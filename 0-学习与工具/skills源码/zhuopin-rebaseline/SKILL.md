## 执行步骤

### 0. 前置检查（有一项不满足即停，报 Shao Peishen）

1. 移交单存在且 frontmatter `status: 待执行`；局部定稿已定稿；Shao Peishen 裁决已落字（在移交单或定稿内，不接受口头转述——R6：只认文件）。
2. 读 `1-转型规划/0-全景路线图/跨桌任务队列.md`：认领对应行改"在办"+登记触碰区；**§三挂口径冻结标**（域/场景｜重梳原因｜日期｜解除条件）——CC 见标即停该场景在途建造。第 4 例教训：07-06 若有冻结标，FI2 MVP 不会按旧口径建完再改。
3. 判定量级：**轻量**（纯字句级、无场景增删/编号/排期变动）只动涉及段落；**结构级**（场景增删/编号/排期/总数变动）走全量九文档。

### 2. 零残差自检（三件，缺一不收工）

1. **grep 全库**：旧编号/旧术语/旧排期关键词逐个查（如 `SC3|逐行四维|全景 42`）；**历史快照件（体检报告/旧移交单）与登记自述按纪律不改**，在接力里注明余留清单。
2. **场景总数校对**：全景规划/实施计划/甘特/CLAUDE.md 四处总数一致。
3. **编号映射核对**：移交单"原→新编号映射"逐条比对落字结果。

### 3. 回填销号（执行完才算闭环）

1. 移交单与开场 prompt frontmatter 改 `status: 已执行归档`；机制日志该行补 ✅。
2. 队列：任务行改"待验收/完成"+产出路径；**解除 §三冻结标**；本次冒出的下游任务（如 CC 引擎改造评估）当场追加"待领"行写明领取方。
3. 若产生 CC 待办（引擎/代码侧），用 zhuopin-kickoff-prompt 出引用版交接 prompt，并在根 CLAUDE.md 登记。

### 4. 收工段（必含 git 处置）

列出本次全部新产出/修改文件清单 + 建议 commit message（`docs(rebaseline): <域><vN> 全景重排落档+docx重转+日志登记`格式）+ 登记队列 §二"待 commit 批次"一行 + 提示 Shao Peishen 一句话交 CC：commit + push + 收工重跑文档台账。Cowork 不擅自 commit。
