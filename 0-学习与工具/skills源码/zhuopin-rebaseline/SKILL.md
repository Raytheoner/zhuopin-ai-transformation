### 2.0 🔴 写后反查（v1.1 新增，队列 #255；**九文档全改完后、零残差自检之前**）

**为什么本 skill 尤其需要它**：一次动九个文档 ＋ 两份 docx，**是全项目写入面最大的执行清单之一**——任何一处"报成功但没写进去"都会被后面的 grep 零残差误判为"本来就没有残差"。

- 逐文档反查：`powershell -File "0-学习与工具\工具-写后反查.ps1" -Path "<刚写的文件绝对路径>" -Keyword "<该文件里应当出现的一句独有文本>"`，返回非 0 即失败。
- **成因**：`Write` 工具、PowerShell 字符串 `-replace`、"here-string 里嵌 Python 脚本"三条链路都可能**报成功而实际没写进去**，**外观与成功完全一致**。
- 🔑 **交叉验证比重复同一种验证更有效**：每份文档至少配两个互不相关的指标（如"行数/字节数变化"＋"关键词命中数"）——**单一指标失效时另一个会顶出矛盾**。2026-08-08 实测两次反查工具自身静默失效（沙箱 grep 把转义竖线当交替符；PowerShell `Select-String -SimpleMatch -AllMatches` 并用时命中恒为 0），**都是靠"这个结果与另一个已知事实矛盾"才发现的**。**已验证可用写法**：`(Select-String -Path $f -Pattern $k -SimpleMatch).Count`（不要加 `-AllMatches`）。
- **docx 重转后须实际核对文件 mtime 与大小已变**——只跑命令不核对，等于没转。

### 2. 零残差自检（三件，缺一不收工）

1. **grep 全库**：旧编号/旧术语/旧排期关键词逐个查（如 `SC3｜逐行四维｜全景 42`）；**历史快照件（体检报告/旧移交单）与登记自述按纪律不改**，在接力里注明余留清单。
2. **场景总数校对**：全景规划/实施计划/甘特/CLAUDE.md 四处总数一致。
3. **编号映射核对**：移交单"原→新编号映射"逐条比对落字结果。

### 3. 回填销号（执行完才算闭环）

1. 移交单与开场 prompt frontmatter 改 `status: 已执行归档`；机制日志该行补 ✅。
2. 队列：任务行改"待验收/完成"+产出路径；**解除 §三冻结标**；本次冒出的下游任务（如 CC 引擎改造评估）当场追加"待领"行写明领取方。
   🔴 **销行时 ✅ 必须写在状态列开头**（队列靠状态字段驱动；写在行尾等于没完成）；**尚有任一子项未完成一律写 🟡、不得写 ✅**。
   🔴 **追加新行前先做「并入审核」（协议〇.10）**：逐条扫 §一 待领行，能并入既有行的一律并入，确无可并入才 `--reserve` 取号，并写明理由。
3. 若产生 CC 待办（引擎/代码侧），用 zhuopin-kickoff-prompt 出引用版交接 prompt，并在根 CLAUDE.md 登记。

### 4. 收工段（必含 git 处置）

列出本次全部新产出/修改文件清单 + 建议 commit message（`docs(rebaseline): <域><vN> 全景重排落档+docx重转+日志登记` 格式）+ 登记队列 §二"待 commit 批次"一行 + 提示 Shao Peishen 一句话交 CC：commit + push + 收工重跑文档台账。Cowork 不擅自 commit。

🔴 **批次三条写法禁令（全部零报错、外观同成功）**：⑴ 文件清单**必须写完整路径**，不得用"同上"等速记（sweep 取到的片段就是字面那几个字符）；⑵ 清单文本内**不得出现裸竖线**（撑破列数，改用全角 ／）；⑶ 不得出现**裸反引号**，**连三连反引号也会触发**——`release` 会因此读不到清单里的队列路径并**拒绝释放**（这是它该做的：fail-loud、锁保持占用），修正后重试，不要绕过。
🔴 **状态列禁带 ✅**（sweep 用 `"✅" not in status` 判待处理）；**清单必须含队列文件自身**；**登记后立即触发一次 sweep**（协议〇.8 批次即扫）。
⚠️ **「回填进已有批次行」前必须先核那行是否仍为待处理**（2026-08-08 实证）：**已 ✅ 的批次行不能再承载新改动**——sweep 已销行，回填内容不在任何待处理批次里，**当场成为孤儿脏文件**；此种情形须**新登记一条批次**。
