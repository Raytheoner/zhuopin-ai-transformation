## §0 动笔前两道闸（两类信通用，**先过闸再谈内容**）

### 闸一：串行原则 —— **同一收信人同时只能有一封在途跟进信**

（Shao Peishen 2026-08-03 定，全局，**优先于并节制一切触发点规则**——包括"场景发布即起草"这条 CLAUDE.md §5 第 8 步。）

**判据**：查 `6-人才与组织/部门AI专员跟进/README-跟进机制与命名约定.md` 清单里该收信人**最近一封**的「发送状态」列——

| 该列的值 | 能否起草下一封 |
|---|---|
| `📥 已回件并回灌 <日期>` | ✅ 可以 |
| `❌ 已作废` | ✅ 可以（那封不占在途） |
| `⏳ 待你审` ／ `🆕 待发` ／ `⏸ 暂缓` ／ `✅ 已推送 …` | 🔴 **不得起草** |

**不得起草时的正确动作**：在 `跨桌任务队列.md` 登记一行「待前信闭环后发」并写明拟发要点，**不要先写出来放着**（写好的信会被后来的 session 当成"可以发了"）。

### 闸二：信件类型判别（v2 起，最重要）

| 类型 | 判据 | 走哪条 |
|------|------|--------|
| **A. 口径/需求确认类** | 要专员**确认判定规则、取值口径、阈值、判据**——即答案会写进代码或影响引擎行为 | **§2 判例批改表**（强制） |
| **B. 其他** | 进度告知、材料转交、日期确认、时限提醒、催办、试用邀请、结论知会 | §4 三要素信 |

**A 类硬规则：禁止抽象设问。** 不得直接问"这条规则该怎么定""关闭状态应该存哪"——业务专员是实操者不是需求分析师，评抽象规则用错媒介。一律转为真实判例让其批改，**规则条文由专线从判例反推**、回发一行请其确认"我这样理解对吗"。

> 依据：2026-07 采购域 6 轮往返仍有开放点，而 63 案例对照表／线下看真实看板／真实截图三次均在几小时内收敛。#13 需求关闭列首封判例包一次性证伪整个功能设计假设。

## §2 A 类：判例批改表结构（v2 核心）

### 2.1 取材

- **≤10 条真实案例**，取自真实 ERP／看板／历史单据（脱敏但**不得虚构**）。
- ⚠️ 虚构样例会让专员脱离直觉、退回抽象思考——2026-07 命令中心 `:8092` 静态原型的虚构占位数据直接导致 11 条误判反馈。
- 案例要覆盖**分歧面**（含边界、例外），不要只挑好判的。

### 2.2 表结构（四段）

```
【判例批改表】<场景>-<议题>-<日期>
├─ 一、背景 3 行（为什么问 / 影响什么 / 什么时候要）
├─ 二、判例对照表（≤10 行，真复选框 docx）
│    | # | 真实场景（料号/单号/客户已脱敏） | 现状判定 | 拟改判定 | ✅对 | ❌错 | ✏️改判理由 |
├─ 三、规则反推初稿（专线写，1-3 句，供专员一眼看"我批完的判例＝这条规则"）
└─ 四、开放点计数（本场景还剩 N 项待确认；本次收 M 项 → 剩 N-M）
```

### 2.3 专员只做三选一

**✅ 对 ／ ❌ 错 ／ ✏️ 改判＋一句话**。允许口语化回复；拿不准可标"存疑"并写原因，**不必勉强给结论**。

## §3 三条硬约束（A/B 两类均适用）

### 3.1 一信 ≤3 个决策点

超过就拆信或转微会（§7）。多决策点信件是回复延迟的主因。

### 3.2 默认预案分级 —— **判据类永不默认生效**

| 类别 | 可否标"超时默认生效" |
|------|---------------------|
| 纯展示/交互类（列宽、分页、导出、图例、排序、措辞） | ✅ 可标"48h 内未回复按拟改方案先做，后续随时可调" |
| **判据／口径／阈值／计算规则类** | 🔴 **绝对不可**——IATF 16949 要求显式签认；超时一律**升级 Shao Peishen 线下推动**，不得以"未回复＝同意"落地 |

> 这是本 skill 唯一的红线级约束。写信时若某决策点无法明确归类，一律按判据类处理（保守）。

### 3.3 材料格式

- **含勾选项**（判例表／圈选表／确认表）→ 走 md2word **原生真复选框**（识别 `☐`/`- [ ]` 直出 `w14:checkbox`）；**死字符"☐"点不动，专员填不了**。
- **纯文字问答信** → md 正文即可，**不附 docx**。
- 不采纳：PDF 表单／Excel／飞书·钉钉多维表（理由见《需求确认方式升级》§1.2b）。

## §4 B 类：三要素信骨架

- frontmatter：title／created／status（起草态一律 `⏳ 待你审`，见 §5.3）
- 抬头：写明**部门连续编号**（形如 `采购部#12`）——按部门连续、跨收信人共用同一计数器、换人不重置，**未发出/已作废的信不占号**；编号只落 README 表格与信件抬头，**不进文件名**
- 开头：先肯定专员最近一次真实交付（点具体成果，不空夸）
- 逐件事：**做什么／怎么做／什么时候交** 三要素齐备
- 知识资产段：该专员名下资产 + 署名认可提醒
- 结尾：随附一页纸对应域节说明 + "有问题随时找我" + 落款（**OPVP Shao Peishen**）

## §5 落位与登记（两类信通用）

1. 落 `6-人才与组织/部门AI专员跟进/`，命名 `部门-姓名-跟进-YYYY-MM-DD-主要事项.md`（未实名用角色代称；文件名不含会变的数字）
2. 需要 docx 时当场跑 `md-to-word` 出同名 docx（勾选类必须走真复选框路径）
3. **README 清单追加一行**（日期／收信人／主要事项／交期要点／发送状态）
4. **首次向某专员发新机制信时**，随信附《专员协作说明-新版需求确认怎么配合-2026-07-25.md》一页

### 5.3 🔴 发送状态四态语义（起草者只能写第一态）

| 状态 | 含义 | 谁写／怎么变过来 |
|---|---|---|
| `⏳ 待你审` | 草稿态，**内容还没审** | **起草者唯一可写的值**（机器真值，严格等值比对） |
| `🆕 待发` | 已批准，等自动发送 | **只能由 `scripts/approve_followup_letter.py` 转态**（`--quote` 必填批准依据，并有 **10 分钟冷却窗口**：脚本首次"观测"到某行只记录时刻并拒绝，满窗后再跑才放行——堵住"起草→批准"同一人一步做完） |
| `⏸ 暂缓` | **内容已审、主动不发** | 由 `🆕 待发` **手工**改写而来，不经任何脚本（区别于草稿态"内容未审"） |
| `📥 已回件并回灌 <日期>` | 该信闭环，**串行原则据此放行下一封** | 回件消化完后手工改写 |

（发出后先落 `✅ 已推送 <UTC 时刻>`，回件并回灌完再改 `📥`；作废写 `❌ 已作废`。）

🔴 **三条会让你踩空的机制事实**：
- **状态列严格等值比对**，多一个字（如带括注说明）都会被拒——保持字面纯净。
- **`工具-共享文档编辑锁.py` 在 release 时结构性拦截**"本次持锁窗口内新增的行直接写 `🆕 待发`"——起草物理上不能一步到位写终态。
- **每日批处理 `ZhuopinFollowupDispatchDaily`（工作日 09:30）扫 `🆕 待发` 行自动推送**。信中若有 **3 天内的明确硬截止**，在 README 行标 `🔒人工发送`，机器人会结构性跳过、改由人当面发（未标时机器判据会兜底跳过并告警，但**兜底不替代人判**）。

## §6 开放点计数（A 类信）

每封 A 类信末尾写明"**本场景还剩 N 项待确认**"。专员当前体感是"信没完没了"，显式计数把它变成"还剩 3 项就收工"——这是最便宜的推动力。计数同步写进《部门AI专员协同一页纸》对应域节。

---

## §7 微会（配套机制，写信前先判断）

某场景**同时有 ≥2 个开放口径点**时，优先约 15-30 分钟微会（屏幕共享真实看板/报告当场定），**跟进信降级为会前材料+会后纪要**；会中裁决由专线当场记纪要、24h 内回发专员一句"确认无误"即可，专员不需会后写任何文档。

---

## §8 人力分层提醒（写信时顺带用）

- 判例包可请**一线实操者先批量初标**（采购＝解植雅/汤易水、质量＝朱映桦、财务待唐燕萍指定），**专员只裁分歧项**。
- 信中可直接写明这一点，减轻专员负担。

## 禁止

- ❌ **前一封尚未 `📥 已回件并回灌` 就起草下一封**（串行原则，优先于一切触发点规则）
- ❌ 口径确认类信件使用抽象设问（一律转判例批改表）
- ❌ 判例包使用虚构/样例数据（必须真实脱敏）
- ❌ 判据/口径/阈值类标"超时默认生效"（IATF 红线）
- ❌ 一信超过 3 个决策点
- ❌ 勾选类材料用 md2word 死字符"☐"
- ❌ 给专员布置"写文档"式作业（一律三步法批改／判例批改）
- ❌ 跟进信里出现与一页纸/权威排期表不一致的日期或事项
- ❌ 跳过 README 登记（清单是发送状态唯一台账）
- ❌ 起草完直接写 `🆕 待发`，**或手工把 `⏳ 待你审` 改成 `🆕 待发`** —— 转终态**只有** `approve_followup_letter.py` 一条合法路径
- ❌ 起草状态写成 `⏳ 待 Paul 审`／`⏳ 待 Shao Peishen 审` 等变体（**机器真值只有 `⏳ 待你审`**；写错不会当场报错，会卡在他批准那一步）
