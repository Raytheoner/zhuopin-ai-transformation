## §0 动笔前两道闸（两类信通用，**先过闸再谈内容**）

### 闸一：串行原则 —— **同一收信人同时只能有一封在途跟进信**

（Shao Peishen 2026-08-03 定，全局，**优先于并节制一切触发点规则**——包括"场景发布即起草"这条 CLAUDE.md §5 第 8 步。）

**判据**：查 `6-人才与组织/部门AI专员跟进/README-跟进机制与命名约定.md` 清单里该收信人**最近一封**的「发送状态」列——

| 该列的值 | 能否起草下一封 |
|---|---|
| `📥 已回件并回灌 <日期>` | ✅ 可以 |
| **`✅ 无需回复`（2026-08-18 新增，v3.3 补入）** | ✅ **语义上可以**——信件本身明示不要求对方任何动作（正文须含「不用回」类字样），**发出即闭环、从不占串行闸**。🔴 **但只能在起草时判定、不得事后追认**（否则任何没人回的信都能被改成这个来解锁）。⚠️ **机器闸仍只认 `📥` 前缀 ⇒ 须写 `串行豁免：前信〈编号〉为 ✅ 无需回复 形态、发出即闭环`**（2026-08-19 质量部#8 先例） |
| **`📨 已确认闭环 <日期>`（2026-08-18 新增，v3.3 补入）** | ✅ **语义上可以**——对方以其它形态响应（群消息／放文件／口头／线下）**且我方已明确回复确认**，以我方确认那一刻为闭环时点。🔴 **转态须能指出两样东西**：对方响应的落档件（`7-外部文档/…`）＋ 我方确认的原话，缺一不得转。⚠️ **机器闸同样只认 `📥` ⇒ 同样须写 `串行豁免：`** |
| `❌ 已作废` | 🔴 **机器闸会拒绝，须写豁免**——语义上那封确实不占在途，**但 #308 子项 G 的闸只认 `📥 已回件并回灌` 这一个前缀**（`工具-共享文档编辑锁.py:1063`），其余一律拒绝 `release`。**⇒ 起草时必须在新增行任一单元格写 `串行豁免：前一封已作废，不占在途`**，否则登记写不进去 |
| `⏳ 待你审` ／ `🆕 待发` ／ `⏸ 暂缓` ／ `✅ 已推送 …` | 🔴 **不得起草** |

> **v3.1 补记（2026-08-09，承载性核查第四批 §3.7.2）**：`❌ 已作废` 这一行原写「✅ 可以」，与机器闸判据不等价、**照做会在 release 时撞墙**。成因＝本 skill v3 落于 2026-08-08，G 闸 apply 于 2026-08-09，**时间上必然错过**。**⇒ 通用初筛法：核 skill 前先比「规则落地时间」与「skill 末次更新时间」两个日期，晚于后者的规则必然不在里面。**

## §2 A 类：判例批改表结构（v2 核心）

### 2.1 取材

- **≤10 条真实案例**，取自真实 ERP／看板／历史单据（脱敏但**不得虚构**）。
- ⚠️ 虚构样例会让专员脱离直觉、退回抽象思考——2026-07 命令中心 `:8092` 静态原型的虚构占位数据直接导致 11 条误判反馈。
- 案例要覆盖**分歧面**（含边界、例外），不要只挑好判的。

### 2.2 表结构（四段）

```
【判例批改表】<场景>-<议题>-<日期>
├─ 一、背景 3 行（为什么问 / 影响什么 / 什么时候要）
├─ 二、判例对照表（≤10 行，真复选框 docx）
│    ★ 表格正上方必须先放 §2.3 那段「勾选栏怎么读」图例，不得省略（v3.3）
│    | # | 真实场景（料号/单号/客户已脱敏） | 现状判定 | 拟改判定 | ✅这样判对 | ❌这样判不对 | ✏️应改判为 |
├─ 三、规则反推初稿（专线写，1-3 句，供专员一眼看"我批完的判例＝这条规则"）
└─ 四、开放点计数（本场景还剩 N 项待确认；本次收 M 项 → 剩 N-M）
```

### 2.3 专员只做三选一 —— 🔴 **但符号必须带主语（v3.3，2026-08-19）**

**✅ 对 ／ ❌ 错 ／ ✏️ 改判＋一句话**。允许口语化回复；拿不准可标"存疑"并写原因，**不必勉强给结论**。

🔴 **v3.3 硬补：三个符号评的恒定是「拟改判定」那一列，且必须在表上方原样附图例。**

**成因＝这条缺口第一次真实阻塞工作**：2026-08-19 姚祖怡对 采购部#16 回件——「**中请我批改的选项 √ 和 × 分别代表什么含义，请你说明清楚，否则我无法改判**」。**不是他看不懂，是本节写法有结构性歧义**：只写「✅ 对／❌ 错」**没有主语**，而两种布局下含义正好相反——
- **布局甲**（`现状判定` 有值、`拟改判定` 留白）：❌ ＝「**现状判定**是错的、要改」（采购部#13 即此，见队列 #266 逐格核对记录）；
- **布局乙**（`拟改判定` 已填好我方建议判法）：✅ 既可读作「同意拟改」、也可读作「现状本来就对」。

**⇒ 统一定死：评「拟改判定」列。「现状判定」列只作对照、不需专员评价。**

**⇒ 每张判例表的表格正上方必须原样附这段图例（不得省略、不得改写）**：

```
🔑 勾选栏怎么读（三个符号的确切含义，请先看这三行再动手）：
✅ ＝「拟改判定这一格填的结果是对的」—— 引擎以后就该这么判。
❌ ＝「拟改判定这一格填错了」—— 引擎不该这么判，但你不必写正确答案。
✏️ ＝「填错了，而且我知道该怎么判」—— 勾它并在后面写一句你认为的正确判法。
⇒ 三个符号评的都是最右边那列「拟改判定」，不是评「现状判定」。每行只勾一个。
```

**⇒ 表头三列写作**：`✅ 这样判对` ／ `❌ 这样判不对` ／ `✏️ 应改判为（写一句）`，**不再用无主语的「✅ 对／❌ 错／✏️ 改判」**。

🔴 **历史信解读（一次性声明）**：**2026-08-19 之前发出的判例表一律按「布局甲」口径解读（✅／❌ 评「现状判定」）**；**唯一例外＝采购部#16**（布局乙、已发出），其符号语义由 2026-08-19 澄清答复单独说明，按新口径解读。

⚠️ **同批实证的第二个坑（与本条叠加才是那次卡住的完整原因）**：采购部#16 判例 3 用了**虚构数据**（「假设某物料需要 15000…」），违反下方禁止项「判例包使用虚构/样例数据」。**前两条是真实料号、第三条突然变构造题**——**符号歧义 ＋ 题型切换，两个一起来**。⇒ **起草时逐行自检：这一行是真实案例吗？**

## §4 B 类：三要素信骨架

- frontmatter：title／created／status（起草态一律 `⏳ 待你审`，见 §5.3）
- 抬头：写明**部门连续编号**（形如 `采购部#12`）——按部门连续、跨收信人共用同一计数器、换人不重置，**未发出/已作废的信不占号**；编号只落 README 表格与信件抬头，**不进文件名**
  - 🔴 **README 表格里的写法不同于抬头**：信**尚未发出**时，README「编号」列须写成 `采购部#12（待发，暂不占号）` 或 `财务部#12（待你审，暂不占号）`——**带括注**，与既有 4 行一致（IT部#7／财务部#11／采购部#12／财务部#12）；信件抬头本身不带括注。发出后再把括注去掉。（v3.1 补，此前只写了「不占号」这个语义、没写这个写法。）

### 5.3 🔴 发送状态四态语义（起草者只能写第一态）

| 状态 | 含义 | 谁写／怎么变过来 |
|---|---|---|
| `⏳ 待你审` | 草稿态，**内容还没审** | **起草者唯一可写的值**（机器真值，严格等值比对） |
| `🆕 待发` | 已批准，等自动发送 | **只能由 `scripts/approve_followup_letter.py` 转态**（`--quote` 必填批准依据，并有 **10 分钟冷却窗口**：脚本首次"观测"到某行只记录时刻并拒绝，满窗后再跑才放行——堵住"起草→批准"同一人一步做完） |
| `⏸ 暂缓` | **内容已审、主动不发** | 由 `🆕 待发` **手工**改写而来，不经任何脚本（区别于草稿态"内容未审"） |
| `📥 已回件并回灌 <日期>` | 该信闭环，**串行原则据此放行下一封** | 回件消化完后手工改写 |

（发出后先落 `✅ 已推送 <UTC 时刻>`，回件并回灌完再改 `📥`；作废写 `❌ 已作废`。）

🔴 **三条会让你踩空的机制事实**：
- **状态列严格等值比对**，多一个字（如带括注说明）都会被拒——保持字面纯净。
- **`工具-共享文档编辑锁.py` 在 release 时结构性拦截**"本次持锁窗口内新增的行直接写 `🆕 待发`"——起草物理上不能一步到位写终态。
- **每日批处理 `ZhuopinFollowupDispatchDaily`（工作日 09:30）扫 `🆕 待发` 行自动推送**。信中若有 **3 天内的明确硬截止**，在 README 行标 `🔒人工发送`，机器人会结构性跳过、改由人当面发（未标时机器判据会兜底跳过并告警，但**兜底不替代人判**）。

## §6 开放点计数（A 类信）

每封 A 类信末尾写明"**本场景还剩 N 项待确认**"。专员当前体感是"信没完没了"，显式计数把它变成"还剩 3 项就收工"——这是最便宜的推动力。计数同步写进《部门AI专员协同一页纸》对应域节。

## §7 微会（配套机制，写信前先判断）

某场景**同时有 ≥2 个开放口径点**时，优先约 15-30 分钟微会（屏幕共享真实看板/报告当场定），**跟进信降级为会前材料+会后纪要**；会中裁决由专线当场记纪要、24h 内回发专员一句"确认无误"即可，专员不需会后写任何文档。

- 判例包可请**一线实操者先批量初标**，**专员只裁分歧项**。
