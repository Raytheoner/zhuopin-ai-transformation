# 卓品 · 需求收敛第一道把关（zhuopin-需求grill v1.0）

> **定位**：全景规划只是**需求概要**；从概要直接写 openspec propose 之间，此前**没有任何机制**。本 skill 补的就是这一格。
> **溯源**：三条核心机制取自 `mattpocock/skills` 的 `grilling`（MIT），已 fork 为中文并绑上本项目四条接缝。上游 `grill-me` 正文只有一行转调 `grilling`；**本 skill 已内含全部机制，不依赖上游任何 skill**。
> **拍板**：Shao Peishen 2026-08-18 答「全按默认」＝ G1(a) fork 成中文 skill／G2(a) 走规范文件＋拍板不走 openspec／G3(a) 只对新场景开工前强制。方案定稿见 `1-转型规划/0-全景路线图/需求收敛第一道把关-grill机制融合方案-2026-08-18.md`。

## 〇、先判该不该用（G3(a) 边界）

| 情形 | 用不用 |
|---|---|
| **新场景开工前**（要走 openspec propose 的） | ✅ **强制** |
| 已建成场景的深化（如 QD-B 档一档二、SC8 #266/#118） | ❌ **不用**——已有真实反馈通道与判例积累，再插一道是纯增成本 |
| 口径级变更（域重梳、排期重排） | ⚪ 不强制（G3 未选 (b)）；判不准可自愿跑 |
| 纯 bugfix／显示层修复 | ❌ 不用 |

**受访者只有一个：Shao Peishen（或场景发起人）。🔴 绝不能是部门专员**——理由见 §三。

## 一、三条机制（照做，不要简化）

**M1 · 设计树与前沿。** 把待定事项建成一棵**决策树**：每个决策分叉出挂在它下面的决策。**前沿 ＝ 前置条件已经落定、现在就能问的那一批**。

- **一轮问完整个前沿**，不要挤牙膏式一次一问。
- 🔴 **一个问题的答案若取决于本轮另一个尚未答的问题，它属于下一轮、不属于本轮。**
- 每轮答复重塑树 → 重算前沿 → 下一轮。

**M2 · 找事实是你的活，永远不是他的活。** 前沿问题若需要环境里的事实，**派子代理去查，不许问他任何你自己能查到的东西**。**且不阻塞**：只有依赖该子代理结果的那几问等它，其余前沿照问。

> 🔑 **这条是三条里价值最高的，因为它正对着本项目最高频的那类错误**：#82／A2 那份派单件两个前提「唐燕萍每日投放」「我方无定时触发」**双双被实测证伪**——这两件都是环境里能查的事实；2026-08-17 记录的六次同族错误全是「把某处写下的旧陈述当成当下事实复述、没核」。**凡是能 grep／查场景 CLAUDE.md／查队列／读 `.51` 服务／看 git 得到的，一律不进问题清单。**

**M3 · 前沿为空才算完。** 每一枝都走到、没有任何一处被默默假设，才算收敛；**且他确认达成共识前不得开工**。

## 二、提问格式（与本项目「需你定夺」四条格式合流，不另起一套）

每问一律：

```
❓ **Q<n> · <一句话标题>**：<问题正文，可含多个选项>

  (a) …… ——选它会发生什么 ＋ 代价
  (b) …… ——同上
➡️ **推荐**：<哪一个，一句话理由>
⏸️ **默认项**：若不答，我将按 (x) 执行
```

四条硬格式（同 CLAUDE.md §5 会话末清单）：① 可直接作答的选择题或是非题；② 每个选项写清「选它会发生什么」与代价；③ **状态汇报另起「状态同步（无需你答）」，两栏各归各位**；④ 每项标默认项，**使「不答」也成为一种有效且可预期的输入**。

## 三、🔴 接缝 1 · 分流判据（整套融合的核心，每一问都要过）

每问出一个问题，先过这道三选一：

| 判据 | 去向 |
|---|---|
| **能从环境查到** —— 仓库文件／场景 CLAUDE.md／两份队列真身／openspec 与 archive／`.51` 服务／ERP·SRM 真实数据／git 历史／前置总表 | 🔴 **自己查，不问任何人**（M2） |
| **只有 Shao Peishen 能定** —— 范围边界／优先级／风险取舍／做不做／做到哪一档／对客闸门 | **本轮 grill 问他** |
| **只有部门专员知道** —— 实操判据／业务口径／阈值／真实单据长什么样／哪种情形算异常 | **不在 grill 里问**，落「判例包待办」，出 grill 后按判例批改法成包 |

**这条分流同时防两个方向的越界**：grill 不去问专员该答的事；判例包也不再夹带本可内部拍板的事。

### 为什么受访者绝不能是专员

对专员跑 grill 会**同时违反三条已生效纪律**：

1. **禁止抽象设问**（判例批改法硬规则第 1 条）——必须转 ≤10 条真实案例三选一；
2. **一信 ≤3 决策点**——grill 一轮问完前沿可能 8-10 问；
3. **跟进信串行闸**——grill 多轮 ＝ 多封信，而同一收信人同时只能有一封在途。

🔑 **这个分工不是权宜之计**：判例批改法的诊断是「AI 专员是业务实操者、不是需求分析师，让他们评抽象规则是用错媒介」——**这句话反过来同样成立：让需求所有者去批判例也是用错媒介**。两种媒介各配各的人，才都跑得快。

## 四、接缝 2 · 产出直接充当 openspec 的输入

grill 收敛后，需求树的三种状态**直接映射**，不再重写一遍：

| grill 树上的状态 | 去向 |
|---|---|
| 已 settled 的分支 | → `design.md` 的 **Decisions** |
| 仍 open、只有他能定的 | → `design.md` 的 **Open Questions** |
| 落「判例包待办」的 | → **Open Questions 里标注「待专员」**，同时进判例包 |

⇒ **消除一次重复劳动**：现状是 design 的决策点到那一步才现想。

## 五、接缝 3 · 两个受众的量级边界（必须写死）

| | 受访者 | 一轮问多少 | 节奏 |
|---|---|---|---|
| **grill** | Shao Peishen | **一轮问完前沿（8-10 问合理）** | 同步、可连续答 |
| **判例包** | 部门专员 | **≤3 决策点** | 异步、串行闸约束 |

🔴 **不写死这条，早晚会有人把 grill 一轮 10 问直接发给姚祖怡。**

## 六、接缝 4 · 度量与可证伪判据

- 既有指标：**开放口径点从提出到销点的中位天数，目标 ≤1 周**（判例批改法 §三）。
- **本 skill 新增前置指标：`进入判例包的开放点数量`** —— 每次 grill 收工必须记下这个数。

> 🔑 **可证伪判据（照 #315 路数写死，便于将来打脸）**：**本机制的全部价值主张是「把本不该问专员的点拦下来」。若一个场景走完 grill 后，进入判例包的开放点数量相对同类场景没有下降，则本机制无效、应当退休。**

## 七、执行清单

1. **判边界**（§〇）——不是新场景就停，别硬套。
2. **建树**：从场景在全景规划里的那段概要出发，列出所有待定事项，标出彼此依赖。
3. **M2 扫一遍**：把所有「能查的」挑出来，**派子代理去查**（不阻塞，其余前沿照问）。
4. **算前沿**，按 §二 格式一轮问完，等他答。
5. **重算前沿**，重复 4，直到前沿为空。
6. **收工产出四样**：
   - 需求树（三种状态已按 §四 分好）
   - 「判例包待办」清单（交判例批改法成包，**不在本 skill 内发信**）
   - **`进入判例包的开放点数量`**（§六 基线值）
   - 场景目录（若尚未建）
7. **收工纪律**：Cowork 不自行 commit——列文件清单 ＋ 建议 commit message ＋ 登记队列 §二 批次（🔴 **每条路径必须反引号包裹**，否则 sweep 判孤儿、静默漏 commit）；登记后立即触发 sweep；**批次转 ✅ 后还要看 `git status` 是否真干净**。
8. **写后反查**：`powershell -File "0-学习与工具\工具-写后反查.ps1" -Path "<绝对路径>" -Keyword "<该文件独有的一句>"`，返回非 0 即失败。

## 八、边界（如实知悉，别越）

- **只做需求收敛，不写代码、不建 openspec 变更包、不发任何信。**
- **不重开任何域的业务口径**——遇到口径问题一律走分流判据的第三格。
- 🔴 **源码 ↔ 已安装版同步纪律**：改完源码即 `save_skill --overwrite`，改完安装版即回写源码，**不得只改一边**（#45 已实证：只改一边＝对实际运行的 skill 完全无效）。源码在 `0-学习与工具/skills源码/zhuopin-需求grill/SKILL.md`。
