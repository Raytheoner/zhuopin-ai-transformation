## 读取纪律（先背再动手）

沙箱挂载/staged 副本对高频改动文件有**桥缓存滞后与尾截断假象**；队列这类文件的读与写回验证一律走 **Windows-MCP PowerShell 直读真身**（`ReadAllBytes`/`Get-FileHash`，只读用 cmdlet 全名）。读回出现 U+FFFD 先跨通道交叉验证再下结论——**沙箱 bash 输出里的 U+FFFD 多为管道显示假象**，2026-08-01 实证：同一文件 bash `cat` 显示 3 处 U+FFFD、PowerShell 直读 `FFFD存在?False`，须以 PowerShell 直读为准。

🔴 **写完必须反查落盘**（2026-07-31 两次、2026-08-04 两次实证）：`Write` 工具、PowerShell 字符串 `-replace`、以及"PowerShell here-string 里嵌 Python 脚本"这条链路都可能**报成功而实际没写进去**。2026-08-04 两次静默失败的共同根因是**Python 字符串里嵌了直双引号**导致语法错误、脚本零输出——**外观与成功完全一致**。写回后一律用 `Select-String`／`Get-FileHash` 反查一次，并让脚本打印一个哨兵串（如 `SENTINEL ...`），**没看到哨兵就是没跑成**。
🔴 **反查工具本身也会静默失效——2026-08-08 一轮内撞两次**：⑴ 沙箱 grep 把转义竖线当交替符（BRE 语义）；⑵ PowerShell `Select-String -SimpleMatch -AllMatches` 并用时 `$_.Matches` 为空集、**六组关键词全返回 0**，而文件明明已增 42 行。**已验证可用的写法**：`(Select-String -Path $f -Pattern $k -SimpleMatch).Count`（**不要加 `-AllMatches`**）。🔑 **抓住它们靠的不是"怀疑工具"，是"这个结果与另一个已知事实矛盾"** ⇒ **交叉验证比重复同一种验证更有效**：反查时至少配两个互不相关的指标（如"行数变化"＋"关键词命中"），单一指标失效时另一个会顶出矛盾。
🔴 **查主工作区脏文件状态必须用本机 git，不得用沙箱侧 git**（2026-08-08 实证，队列 #305）：本机 `core.autocrlf=true` 而沙箱侧未启用该转换，**实测会把全库 30+ 个未修改文件虚报为已修改**，本机直读同一时刻为"干净"。**这是"工具静默回退"罕见的"虚报坏消息"方向**——采信虚报会错误判定"有人在途"而推迟本该做的登记。

🔴 **时间戳必判 UTC vs Win 本地**（本机 UTC+8）：审计 JSONL 存真 UTC；文件 mtime／计划任务 `LastRunTime`／事件日志是本地。PowerShell `ConvertFrom-Json`／`[datetime]::Parse` 会把 ISO 串按本地时区显示——要真 UTC 须显式 `.ToUniversalTime()`。时长差值一律用 `TotalHours` 或 `d\.hh\:mm\:ss`，**绝不用只含 `hh` 的格式串**（会丢 Days）。判"任务/服务为何没跑"之前，先确认机器这段时间是否在运行（查 `ID=27／42／107`，并对比两次读时钟的真实间隔——**时钟本身就是证据**）。

🔴 **权限检查与实际动作必须是两步，中间查退出码**（2026-08-04 本审计自身违规实证，已登记队列 #200）：把 `acquire` 与写盘脚本用 `;` 串在同一条命令里且不查 `$LASTEXITCODE`，会出现"锁工具已正确拒绝、脚本照跑照写"——**「工具拒绝了」与「动作没有发生」是两件事**。

🔴 **判"某件事是否已做"必须实测，且读状态列开头（2026-08-08 实证，v1.7 补）**：曾据某行**行内叙述**断言"某工作至今未做"，而**该行状态列开头就写着"✅ 全部完成"**——代价是让 Shao Peishen 在一件已完成的事上做了一次选择。**⇒ 不只对"载体有没有"实测，对"这件事是否已做"同样要实测**；判据一律用 `python 0-学习与工具/工具-队列查询.py --row N`（返回状态列全文、不截断，头尾互斥时显式打印冲突警告）。⚠️ **该冲突警告在"✅ 开头 ＋ 合规保留历史原文"这一写法上会常态触发，属可接受噪声、勿据此放宽它**——它拦住的正是上述这类真实误判。

## 二、逐行核对：七类失真

| 类型 | 判据 | 处置 |
|------|------|------|
| ① 已完成未销行 | 产出文件/接力节/commit 在，状态仍"待领/在办" | 补记销行（注明"XX 审计补记"+证据指针） |
| ② 状态字样过时 | 日期性措辞失效（"今日X到期"已过、被新事替代、引用已删文件） | 按现状重写该单元格，登记列加"（MM-DD 刷新）"。**⚠️ 只扫标题会误判**——须同时看正文（2026-07-30 §四#35 判例：标题写"红线 7/31"而正文已正确记为 8/31 顺延） |
| ③ 到期无证据 | 红线日已过而证据夹无产出 | **升级**：标 ⚠️ 已过期+触发预案条款，§四 对应行改"立即" |
| ④ Shao Peishen 动作缺行 | 看板有"待 Shao Peishen 审/拍板"状态但 §四 无行 | §四 补行（会卡执行方的优先） |
| ⑤ 触碰区撞车 | 待领行触碰区与在办行重叠 | 加防撞注：建议并入在办行或改由同一执行方顺带 |
| ⑥ 协调文件跨分支漂移/行号撞号 | 某长期分支的队列文件副本相对 origin/master 有独立编辑历史（§一/§四出现同号不同内容） | **不得**盲目"全取一边"：逐冲突查每行引用的 commit hash 是否真实存在于 master；改动一律在 master 真实最大号之后续排；push 前用 `git merge-base --is-ancestor origin/master <sha>` 核验可快进 |
| ⑦ 行内遗留未升格（2026-07-30 新增，队列 #97①） | 某行**正文里**藏着 `⚠️`／"未做"／"待确认"／"下次顺带"等**新的待办**，但该行状态已是"✅ 完成"、或该待办从未变成独立的待领行——**没有任何人会去认领一段藏在长行正文里的话** | 抽出为**独立 §一 待领行**（编号用预留取号），原行保留原文并加"（已升格为 #N）"指针；已归档行里的遗留同样升格。**扫法**：`grep -n '⚠️\|未做\|待确认\|留待\|下次顺带'` 后逐条判断。**⚠️ 特别注意"一行两半"形态**：某行 CC 侧已完成、行内却另写着"需 Cowork 补"（或反之），整行看似已完结、实则半边未做（#172 判例），**只按"这行归谁"读会漏掉** |

## 三、卫生检查（顺带）

批次 ID 唯一（同日多批加域后缀）；§二表块完整；冻结标挂/解与实际一致；外来文件混入专员夹；看板行序仅记录不重排；**§一/§四行号无重复**；**每行列数＝8**（协议〇.8）。

🔴 **状态头必须以 ✅ 开头（2026-08-03 新增，一次性抓出 6 行）**：扫"状态列**前 60 字**含'待领/在办'、而整格内**另有** `✅ 已完成/已发送/已拍板`"的行。**队列靠状态字段驱动、读者与工具最先看到的是开头**——行尾写了完成、头部仍是待领，等于没完成，会被重复领取。判例：#192/#193/#194/#198/#199/#204 同批六行；**2026-08-04 本审计自己又造了一次**，可见这不是别人的毛病。
🟡 **复合态一律写 🟡、不得写 ✅（2026-08-08 补，队列 #304）**：**首标记只表达行整体状态**——只要还有任一子项未完成就写 🟡。**权威词表**（#304 为唯一定义处）：`待领／仍待／待补／待实现／待审／待你／未做／未实现／另一半／半边`；**刻意不含"缺口"**（本项目里是业务名词：材料缺口／缺口清单，纳入会误报）。**判据只许扫状态列开头片段**——放宽到全列实测命中数由 5 炸到 37、且会误伤"如实留白"这一好习惯。
