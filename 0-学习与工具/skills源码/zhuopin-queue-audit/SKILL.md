# 卓品 · 跨会话对账审计（zhuopin-queue-audit v1.0）

多条专线/CC 并行推进时，《跨桌任务队列》可能与实际脱节（漏回写、字样过时、任务已被替代）。本审计**以文件系统真身为准**（R6：只认文件不认转述）校准队列，是值周巡检的前置质量闸——**先对账、后巡检**，否则《本周计划》会催已完成/已删除的事。首例 2026-07-11 执行（发现 6 处失真，含 7/10 端点到期无回填的红线项）。

## 读取纪律（先背再动手）

沙箱挂载/staged 副本对高频改动文件有**桥缓存滞后与尾截断假象**；队列这类文件的读与写回验证一律走 **Windows-MCP PowerShell 直读真身**（`ReadAllBytes`/`Get-FileHash`，只读用 cmdlet 全名）。读回出现 U+FFFD 先跨通道交叉验证再下结论（见 memory `project-encoding-incidents`）。

## 一、证据采集（六源）

1. **队列真身**：`1-转型规划/0-全景路线图/跨桌任务队列.md`（PS 直读，记 LEN+MD5 作写回基线）。
2. **专员回复落档**：`7-外部文档/<部门>/` 近 7 天新件清单（device_list_dir recursive + mtime 过滤）——有新件必须对应看板行的输入或销行证据。
3. **跟进信发送状态**：`6-人才与组织/部门AI专员跟进/README` 清单 + 已删除记录——核对"发信"类任务行。
4. **四条 session 接力**：Phase1收口/财务域/采购域/质量域 最近日期节——各线自述完成的事是否已回写队列。
5. **在途变更包**：`openspec/changes/` 目录清单——"design 待审/apply 中"是否有对应看板行与 §四 Paul 行。
6. **§二批次 vs git**：批次行的 commit hash、✅ 状态与 CC 备注里"检出但未登记"的改动（后者=漏登记信号）。

## 二、逐行核对：五类失真

| 类型 | 判据 | 处置 |
|------|------|------|
| ① 已完成未销行 | 产出文件/接力节/commit 在，状态仍"待领/在办" | 补记销行（注明"XX 审计补记"+证据指针） |
| ② 状态字样过时 | 日期性措辞失效（"今日X到期"已过、被新事替代、引用已删文件） | 按现状重写该单元格，登记列加"（MM-DD 刷新）" |
| ③ 到期无证据 | 红线日已过而证据夹无产出 | **升级**：标 ⚠️ 已过期+触发预案条款（如 CSV 降级/窗口保卫战），§四 对应行改"立即" |
| ④ Paul 动作缺行 | 看板有"待 Paul 审/拍板"状态但 §四 无行 | §四 补行（会卡执行方的优先） |
| ⑤ 触碰区撞车 | 待领行触碰区与在办行重叠 | 加防撞注：建议并入在办行或改由同一执行方顺带 |

## 三、卫生检查（顺带）

批次 ID 唯一（同日多批加域后缀）；§二表块完整；冻结标挂/解与实际一致；外来文件混入专员夹；看板行序仅记录不重排（改动最小化）。

## 四、修正纪律

- **证据确凿才改**；存疑标"待核实（XX 审计）"，不臆断销行。
- 写回走 PS `WriteAllText`（UTF8 无 BOM，与原文件一致）+ 写后验证（长度/探针/FFFD=False）。
- 全部改动登记 §二 新批次 `B-MMDD总线审计` 交 CC commit。
- 审计**不重开业务口径、不动权威文档**——只校准队列这一张调度表（分工红线）。

## 五、输出简报（聊天）

顺序固定：① 总体结论一句（机制是否在转）；② **最要紧一条置顶**（通常是类型③过期项，写明今天该做什么）；③ 修正清单（每处一句：原状→改后）；④ 观察项（卫生类，不阻塞）；⑤ Paul 动作优先级列表。简报不落文件（队列本身即记录），除非 Paul 要求。

## 与值周巡检的关系

对账审计=**校准队列**（对文件真身），值周巡检=**消费队列**（出《本周计划》）——上下游不重复。标准节奏：周一巡检开跑前先跑本审计；巡检 prompt 首句应为"先用 zhuopin-queue-audit 对账并修正队列，再基于修正后的队列生成本周计划"。
