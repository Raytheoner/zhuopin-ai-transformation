## 读取纪律（先背再动手）

沙箱挂载/staged 副本对高频改动文件有**桥缓存滞后与尾截断假象**；队列这类文件的读与写回验证一律走 **Windows-MCP PowerShell 直读真身**（`ReadAllBytes`/`Get-FileHash`，只读用 cmdlet 全名）。读回出现 U+FFFD 先跨通道交叉验证再下结论（见 memory `project-encoding-incidents`）——**沙箱 bash 输出里的 U+FFFD 多为管道显示假象**，2026-08-01 实证：同一文件 bash `cat` 显示 3 处 U+FFFD、PowerShell 直读 `FFFD存在?False`，须以 PowerShell 直读为准。

🔴 **写完必须反查落盘**（2026-07-31 两次、2026-08-04 两次实证）：`Write` 工具、PowerShell 字符串 `-replace`、以及"PowerShell here-string 里嵌 Python 脚本"这条链路都可能**报成功而实际没写进去**。2026-08-04 两次静默失败的共同根因是**Python 字符串里嵌了直双引号**导致语法错误、脚本零输出——**外观与成功完全一致**。写回后一律用 `Select-String`／`Get-FileHash` 反查一次，并让脚本打印一个哨兵串（如 `SENTINEL ...`），**没看到哨兵就是没跑成**。

🔴 **时间戳必判 UTC vs Win 本地**（本机 UTC+8）：审计 JSONL 存真 UTC；文件 mtime／计划任务 `LastRunTime`／事件日志是本地。PowerShell `ConvertFrom-Json`／`[datetime]::Parse` 会把 ISO 串按本地时区显示——要真 UTC 须显式 `.ToUniversalTime()`。时长差值一律用 `TotalHours` 或 `d\.hh\:mm\:ss`，**绝不用只含 `hh` 的格式串**（会丢 Days）。判"任务/服务为何没跑"之前，先确认机器这段时间是否在运行（查 `ID=27／42／107`，并对比两次读时钟的真实间隔——**时钟本身就是证据**）。

🔴 **权限检查与实际动作必须是两步，中间查退出码**（2026-08-04 本审计自身违规实证，已登记队列 #200）：把 `acquire` 与写盘脚本用 `;` 串在同一条命令里且不查 `$LASTEXITCODE`，会出现"锁工具已正确拒绝、脚本照跑照写"——**「工具拒绝了」与「动作没有发生」是两件事**。同族＝#198(b) 的 `_edit_lock()` 对 `status` 误传 `--who` 致探锁永远返回 False。

## 二、逐行核对：七类失真

| 类型 | 判据 | 处置 |
|------|------|------|
| ① 已完成未销行 | 产出文件/接力节/commit 在，状态仍"待领/在办" | 补记销行（注明"XX 审计补记"+证据指针） |
| ② 状态字样过时 | 日期性措辞失效（"今日X到期"已过、被新事替代、引用已删文件） | 按现状重写该单元格，登记列加"（MM-DD 刷新）"。**⚠️ 只扫标题会误判**——须同时看正文（2026-07-30 §四#35 判例：标题写"红线 7/31"而正文已正确记为 8/31 顺延） |
| ③ 到期无证据 | 红线日已过而证据夹无产出 | **升级**：标 ⚠️ 已过期+触发预案条款，§四 对应行改"立即" |
| ④ Shao Peishen 动作缺行 | 看板有"待 Shao Peishen 审/拍板"状态但 §四 无行 | §四 补行（会卡执行方的优先） |
| ⑤ 触碰区撞车 | 待领行触碰区与在办行重叠 | 加防撞注：建议并入在办行或改由同一执行方顺带 |
| ⑥ 协调文件跨分支漂移/行号撞号 | 某长期分支的队列文件副本相对 origin/master 有独立编辑历史（§一/§四出现同号不同内容） | **不得**盲目"全取一边"：逐冲突查每行引用的 commit hash 是否真实存在于 master；改动一律在 master 真实最大号之后续排；push 前用 `git merge-base --is-ancestor origin/master <sha>` 核验可快进 |
| ⑦ 行内遗留未升格（2026-07-30 新增，队列 #97①） | 某行**正文里**藏着 `⚠️`／"未做"／"待确认"／"下次顺带"等**新的待办**，但该行状态已是"✅ 完成"、或该待办从未变成独立的待领行——**没有任何人会去认领一段藏在长行正文里的话** | 抽出为**独立 §一 待领行**（编号用预留取号），原行保留原文并加"（已升格为 #N）"指针；已归档行里的遗留同样升格。**扫法**：`grep -n '⚠️\|未做\|待确认\|留待\|下次顺带'` 后逐条判断。**⚠️ 特别注意"一行两半"形态**：某行 CC 侧已完成、行内却另写着"需 Cowork 补"（或反之），整行看似已完结、实则半边未做（#172 判例），**只按"这行归谁"读会漏掉** |

## 三、卫生检查（顺带）

批次 ID 唯一（同日多批加域后缀）；§二表块完整；冻结标挂/解与实际一致；外来文件混入专员夹；看板行序仅记录不重排；**§一/§四行号无重复**；**每行列数＝8**（协议〇.8）。

🔴 **状态头必须以 ✅ 开头（2026-08-03 新增，一次性抓出 6 行）**：扫"状态列**前 60 字**含'待领/在办'、而整格内**另有** `✅ 已完成/已发送/已拍板`"的行。**队列靠状态字段驱动、读者与工具最先看到的是开头**——行尾写了完成、头部仍是待领，等于没完成，会被重复领取。判例：#192/#193/#194/#198/#199/#204 同批六行；**2026-08-04 本审计自己又造了一次**（把新段前置到 #200 状态列开头，把 CC 写在行尾的完工状态挤后），可见这不是别人的毛病。

**高水位线回写核对**：核对顶部"编号高水位线"是否 ≥ §一/§四 文内真实最大号。**滞后是常态不是异常**。发现滞后即当场回写，并在简报观察项记一句。**同时，本审计及任何按高水位线划范围的步骤，一律取「文内真实最大号」与「顶部高水位线」的较大者**。

**重复劳动检测**：扫 `6-人才与组织/部门AI专员跟进/` —— **同收件人、同日、多封未发的草稿**即报（2026-07-23 判例：两个并行 session 各写一份价格核实信）。判据只看"收件人+日期+未发状态"，不做语义判重（宁可多报，不可漏）。**同族形态**：同一条 Shao Peishen 拍板被两条线同时接（§四#41 判例）——落字前先读一眼行内真身。

**孤儿 worktree/陈旧分支**：跑证据源⑧脚本，把两类候选各按一条 §一 待领行追加（领取方 CC，触碰区写清路径/分支名 + 建议命令），"观察项"类只在简报提一句。**巡检本身不执行任何删除**。若已有拍板把清理挂到月度环境体检（#98），则**只留痕不另立行**。

## 四、修正纪律

- **写回队列前先 acquire 协议〇.7 编辑锁**（`python 0-学习与工具/工具-共享文档编辑锁.py acquire --who "queue-audit"`），占用中等其释放/陈旧再改，**改完立刻 `release`**。🔴 **acquire 与写盘必须两步、中间查 `$LASTEXITCODE`**（见读取纪律第四条）。
- **要新增行时用预留取号**：同时要 §一 与 §四 两套号 → **`--reserve-multi 一:N 四:M`** 一次 acquire 跨分区预留（#185，2026-08-04 落地）；只要一套 → `--reserve N --section 一|四`。两者**互斥**。预留多了无妨——**编号不复用，留空即可**。⚠️ **拿到号不等于已定**：2026-08-04 实测 `--reserve` 曾分配出已被并行 session 占用的号（返回 #233 而该号已被占），工具现已在回写前核对"文内真实最大号"、命中即拒绝，但并发下仍以**写入后的实测**为准。
- **证据确凿才改**；存疑标"待核实（XX 审计）"，不臆断销行。
- 写回走 PS `WriteAllText`（UTF8 无 BOM）+ 写后验证（长度/探针/FFFD=False/**列数=8**/哨兵串）。**⚠️ 勿用 PowerShell 字符串 `-replace`／`.Replace()` 改 md**——2026-07-31 三次静默失败，一律改用 Edit 工具并反查。
- 🔴 **三条静默失败写法禁令（2026-08-04 逐条实证，全部零报错）**：⑴ **Python 串内不得嵌直双引号**（语法错误、脚本零输出、外观同成功）；⑵ **队列文本内不得出现裸竖线**（会撑破列数；改用全角或"／"）——**连"解释解析器"的示例文本也不行**，2026-08-04 一句带反引号的说明把批次清单的反引号配对整段打乱、其后片段全部错位；⑶ **批次文件清单必须写完整路径**，不得用"同名 `.docx`""同上"等人类速记——sweep 取到的片段就是字面那几个字符，匹配不到任何真实脏路径。
- 全部改动登记 §二 新批次 `B-MMDD总线审计` 交 CC commit；**状态列禁带 "✅"**（sweep 用 `"✅" not in status` 判待处理）；**批次文件清单必须含队列文件自身**（否则 sweep 判"脏文件未被任何批次声明"整轮跳过）；**登记后立即触发一次 sweep**（协议〇.8 批次即扫）。
- 审计**不重开业务口径、不动权威文档**——只校准队列这一张调度表（分工红线）。

## 六、每周清扫尾步（协议〇.8，2026-07-30 补·队列 #97①）

**只在值周巡检那一轮（周一）做，日常临时对账不做。** 顺序不可颠倒：

1. **先完成上面全部对账修正**（清扫前必须先把状态改对——否则会把"其实没完成"的行迁进归档件，等于永久失踪）。**⚠️ 这一步不是形式**：2026-08-03 实测，状态头失真 6 行、风险词过滤命中 33/70，**批量过滤既会误迁也会误留**，唯一可靠办法是逐行判读；若当轮"状态已改对"这一前提不成立，**应当推迟清扫并如实登记**，不要硬做。
2. 将 §一/§二/§三/§四 **全部已完成行整行迁入**同目录《跨桌任务队列-归档-YYYYMM.md》（按月一档，**编号永不复用**）。**⚠️ 刻意保留不迁的行不算漏**：被明确标为"无限期搁置/保留不销行"的已知残余风险行（如 #137/#138 形态），迁走会让风险从视野消失，**须留在看板上**。
3. **迁完立刻回写顶部"编号高水位线"** = 迁移前 §一/§四 各自的真实最大号（**不是迁移后文内可见的最大号**）。
4. 迁移与回写**同处一个编辑锁窗口内**（acquire → 迁 → 回写 → release），不可分两次持锁。
5. 清扫结果在简报观察项里记一句：迁走 N 行、高水位线 §一 #X／§四 #Y。
