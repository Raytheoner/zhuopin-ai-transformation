## 与 `zhuopin-lan-closeout` 如何分工（收敛后的两个 workflow）

| | 管什么 | 触发词 | 遇到需要判断的动作 |
|---|---|---|---|
| **本包**（吸收清池） | 自动判 LAN，做所有**非 `.51`** 的可领活 | 「**开启泳道看护**」（别名「offlan清池」，见下） | **停下等他一个字母，答完续跑**；碰 `.51` 类动作自动转出、不执行。🆕 **2026-09-07 起补一条时序放宽**（`#478`）：转出**之后**，若他此刻在环且 LAN 探针实测 on，该项 MAY 在同一 session 内续做——**管什么那一格不变，`.51` 仍归右列那一包管**，变的只是「必须等下一个收口批」这个时序 |
| `zhuopin-lan-closeout` | **专管 `.51` 部署与 LAN 留步**，四步纪律 | 「我已回Lan」 | 逐项串行，他全程盯着 |

🔑 **收口的独特性不是「他在不在」，是它碰 `.51`**——「快照→部署→冒烟→不过即回滚」那套四步纪律只长在收口里，本包重新实现一遍就是复制护栏，**而复制的护栏必然漂移**（本项目已有实例：`#312` 读侧双文件解析、跟进信状态两处载体）。这正是 D1 新增 ⏭️ 档的成因，见 design.md 同节。

🆕 **2026-09-07 时序放宽（`#478`，design 审已过）——请先分清它改了什么、没改什么**：

- **没改**：`.51` 的归属。那一整套执行纪律的正本仍然、且只在 `zhuopin-lan-closeout`，本包**一步都不实现、一句都不复述**；判据未变，`classify("deploy_51")` 恒返回 ⏭️（有无授权都一样——四档的轴是「可逆性」，放行解的是「执行时序」，两者不同轴）。
- **改了**：时序。此前 ⏭️ 项一律要等下一个收口批；现在**转出仍先发生**，其后若三项前置全过（LAN 探针实测 on ／ 该项已有尚未被绑定的转出记录 ／ 他就该项给出的非空授权原文），该项 MAY 在同一 session 内续做。前置由 `工具-泳道看护状态机.py deploy-authorize` 现查现记，**不由会话自行判断**。
- 🔴 **续做时怎么做**：**须现读 `0-学习与工具/skills源码/zhuopin-lan-closeout/SKILL.md`「执行步骤」第 4 项**并照那份正本办——本文件与该命令的输出都**只给指针**。这条不是客气话：一旦这里出现一份可照做的副本，它就会漂，而漂掉的护栏比没有护栏更危险。反例守卫＝`0-学习与工具/工具-泳道纪律复制lint.py`（已挂 CI，判据词从正本运行时提取）。
- 🔴 **实现限制，如实说**：`deploy-authorize` 是一道**记录闸**——保证「没有授权记录就拒绝放行且非零退出」，**不是**对绕过行为的物理阻断。人不在时真正的兜底在被指向方的纪律里，那条防线归它管。

## 执行步骤

1. **扫池／排波**：LAN 探针结果定候选范围（见上「触发与前置」①）后，🔴 扫池只用 `python 0-学习与工具/工具-队列查询.py --digest`（两份真身各一次），候选行的触碰区列用 `--row N --field all` 取，**不得 `Read`／`grep` 队列真身**（K3 读侧禁通读，rules/队列与落库）；触碰区两两比对，重叠即分波；锁工具族恒最后一波；单批上限见「触发与前置」。触碰区排波沿用清池既有的判据思路（`zhuopin-lane-clearpool/SKILL.md` 步骤 1-2，该文件虽已退休为独立触发入口，判据文本仍是本步骤的参照）——**只读引用，不把那两步的文字复制进本文件**（D2/tasks 4.3）。
2. **落档**：生成看护件，走锁登记 §二 批次；🔴 落档失败即全停。
   🔴 **交付模式默认且唯一 ＝「CC 看护者单粘贴、看护者用 Task/Agent 按 §三 扇出」**（判据正本＝`专线opener模板库.md` §〇.17，看护者开场词照抄 `opener骨架.md` §三bis）：他只粘**一段**，泳道 opener 用【CC · 子任务泳道】骨架、**每条恒三行**。**无头 `工具-opener批处理执行v2.ps1` 只在他明示「无头」时用**；「N 个窗口各贴一段」是**退出选项**，不再是默认。🔴 **一批之内不得中途改交付方式。**
   🔴 **看护件固定五节 §〇～§四 ＋ §三bis**：〇口径／一硬边界继承／二次序与并行矩阵（含硬序与每条触碰区，「LAN 留步」清单同落此处）／三泳道 opener／四收工汇总；§三bis ＝ 看护者开场词，**标题逐字 `## 三bis · …`、不带 `§`**（`工具-opener块lint.py` 形态⑥的结构锚）。**目标 ≤10 KB**——「做什么／不做什么／收工」一律写进**队列行**，不进 opener。
   🔴 **§三 每条泳道必须写成下面这三行结构，缺一即整份解析不到、批处理直接报 `✗ 未解析到任何 opener` 并 exit 12**（2026-09-02 首跑实撞，`OP-0902-A`；本结构在看护档下同样保留，它是切回无头档的唯一逃生口）：
   ```
   ### A<N> · <标题>

   粘贴端：CC ｜ 泳道：<泳道名>

   （紧接三反引号代码块，块内即 opener 正文原文）
   ```
   判据来自 `工具-opener批处理执行v2.ps1` 第 33-56 行的解析器（**只读引用，本包不改该脚本**）：① 标题正则 `^###\s+(A\d+)\s*·?\s*(.*)$`——**必须是 `###` 三级、编号必须是 `A` 加数字**，用 `▶ 泳道：` 起头而无 `### A<N>` 标题的写法**一条都解析不到**；② `粘贴端：\s*(CC|Cowork)` 与 `泳道：\s*(\S+)` 在标题与代码块之间的任意行上取；③ 🔴 **泳道名不能含空格**（正则取 `\S+`，空格即截断）；④ 同一泳道名下多个 `A<N>` 按编号升序**泳道内串行**，不同泳道名之间**并行**（`-MaxParallel` 默认 3、`-StaggerSec` 默认 90 错峰）。
   ✅ **真起泳道前先跑一次 `-DryRun -Yes`**，确认打印出的泳道数与 opener 归属与预期一致——这一步零成本，且是唯一能在起无头 CC 之前发现格式错的手段。
3. **组 opener**：每条泳道的 opener 正文，在清池既有的无头 CC 引导之外，须额外内置四句（三句沿 D1 判据现取与 🟡/🔴 收尾约定，一句新增 ⏭️ 处置）：
   - 一句指向 D1 表现取命令（`... criteria`），**不在 opener 里手抄判据表**；
   - 命中 🟡/🔴 动作时的动作指令：先跑
     ```
     python 0-学习与工具/工具-泳道看护状态机.py pause --batch <批次> --wave <波次> \
       --lane <泳道名> --action-key <D1键名> --waiting-for "<在等什么>" \
       [--option "<候选答案>"]...
     ```
     （落状态 ＋ 推「等人」企微通知一次做完，见工具的 `pause` 子命令），随后**以 `OPENER_PARTIAL: 停在<🟡|🔴>决策点——<在等什么>` 收尾**；
   - 🆕 **命中 ⏭️ 转出档时**（如 `.51` 部署）：跑
     ```
     python 0-学习与工具/工具-泳道看护状态机.py transfer-out --batch <批次> --wave <波次> \
       --lane <泳道名> --action-key <D1键名> --note "<需要走 LAN 收口做什么>"
     ```
     🔴 **不进 `OPENER_PARTIAL`**——转出没有真正要等他裁的判断（答案恒定是「走 `zhuopin-lan-closeout`」），泳道正文应**直接跳过这一项，继续其余不依赖它的任务**；仅当后续项确实依赖被转出的这一项时，才对该后续项走同 🟡/🔴 一样的 `OPENER_PARTIAL` 收尾（同 D3 依赖链例外的处理方式）；
     🆕 **转出之后的条件放行分支（`#478`，2026-09-07 起）**：**转出仍先发生、上面那条一字不改**；其后若他此刻在环、且他就该项给出了明确授权，泳道可跑
     ```
     python 0-学习与工具/工具-泳道看护状态机.py deploy-authorize --batch <批次> --wave <波次> \
       --lane <泳道名> --action-key <D1键名> --item "<被授权的那一项>" \
       --authorized-text "<他的授权原文，逐字>"
     ```
     三项前置（LAN 探针实测 on ／ 该项已有尚未被绑定的转出记录 ／ 授权原文非空）由该命令现查，任一不过即**拒绝 ＋ 非零退出**，泳道照原样把该项留在已转出态往下走。放行时它**只打印一个指针**——🔴 **须现读 `0-学习与工具/skills源码/zhuopin-lan-closeout/SKILL.md`「执行步骤」第 4 项**照办；**本文件、opener 正文、该命令的输出，一律不得写出那份正本里的任何一步**（反例守卫 `0-学习与工具/工具-泳道纪律复制lint.py` 已挂 CI 拦这件事）。逐项粒度：一次授权只管一项，同批下一项须自己先转出、自己再取授权，**没有批次级授权、也没有时间窗**（时间窗是假的安全感——他 30 分钟前授权、现在人已经走了，时间窗照样放行）。执行完按结果跑一次 `deploy-record --lane <泳道名> --authorization-index <N> --outcome done|rolled_back|stopped --evidence-ref <证据落点路径>`（**只记指针，不内联证据内容**）；
   - 判据未覆盖时按 🟡 停、在收尾原因里问「这个动作该进哪一档」——工具的 `classify`/`pause` 对未知 `--action-key` 已自动 fail-safe 并把提示文案带进企微通知，opener 只需照做，**不必自行判断该不该停**。
   - 🔴 **不改 `工具-opener批处理执行v2.ps1`**（tasks 4.1，只读核对结论）：该脚本只认 `OPENER_DONE`/`OPENER_PARTIAL` 两个哨兵；`OPENER_PARTIAL` 退出码 0，**不会**触发该脚本「FAIL/NO-SENTINEL 才停本泳道」的中断逻辑（脚本源码 `if ($status -like 'FAIL*' -or $status -eq 'NO-SENTINEL') { break }`），故同一泳道计划里排在暂停项之后的独立项仍会继续跑——**若后续项依赖被暂停的这一项，opener 正文须让该后续项自己先查状态文件（`... show --lane <泳道名>`），仍是 paused 就立即以同样的 `OPENER_PARTIAL` 收尾，不得盲目往下做**。
4. **起泳道**：默认档由**看护者用 Task/Agent 扇出**（`isolation: "worktree"`）——🔴 **并行上限 4**、同波错峰 **≥90 s**；子任务收工**只 push 自己那条分支**，不碰主仓、不 ff master、不在主仓 commit，**主仓 ff 由看护者收工串行做，或经『已授权待合』登记处由 `工具-待合分支巡检.ps1` 机器做；sweep 不做 ff**（`#553` 2026-09-11 更正）；看护者自己**不 commit**，撞 `.git/index.lock` 不重试、按「登记待补」写队列行。**无头档**（他明示）才经 `工具-opener批处理执行v2.ps1` 起无头 CC（`isolation: worktree`），调用签名/心跳/企微四类事件推送**完全不变**（4.1 只读核对，未改该脚本一行）；🔴 **心跳一律跑命令写，不再自己拼路径**（2026-09-09 起，openspec `lane-watch-heartbeat-visibility`／队列 §一 `#504`）：

   ```
   python 0-学习与工具/工具-泳道看护状态机.py heartbeat --lane <泳道标识> --text "<一句话>"
   python 0-学习与工具/工具-泳道看护状态机.py heartbeat --lane <泳道标识> --done --batch <批次> --text "产出落点：<落点>"
   ```
