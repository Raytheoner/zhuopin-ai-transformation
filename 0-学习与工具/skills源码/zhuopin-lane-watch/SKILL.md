## 执行步骤

1. **扫池／排波**：LAN 探针结果定候选范围（见上「触发与前置」①）后，🔴 扫池只用 `python 0-学习与工具/工具-队列查询.py --digest`（两份真身各一次），候选行的触碰区列用 `--row N --field all` 取，**不得 `Read`／`grep` 队列真身**（K3 读侧禁通读，rules/队列与落库）；触碰区两两比对，重叠即分波；锁工具族恒最后一波；单批上限见「触发与前置」。触碰区排波沿用清池既有的判据思路（`zhuopin-lane-clearpool/SKILL.md` 步骤 1-2，该文件虽已退休为独立触发入口，判据文本仍是本步骤的参照）——**只读引用，不把那两步的文字复制进本文件**（D2/tasks 4.3）。
2. **落档**：生成看护件（格式沿清池样板：〇口径／一硬边界继承／二矩阵／三泳道 opener 正文，「LAN 留步」清单同落此处），走锁登记 §二 批次；🔴 落档失败即全停。
   🔴 **§三 每条泳道必须写成下面这三行结构，缺一即整份解析不到、批处理直接报 `✗ 未解析到任何 opener` 并 exit 12**（2026-09-02 首跑实撞，`OP-0902-A`）：
   ```
   ### A<N> · <标题>

   粘贴端：CC ｜ 泳道：<泳道名>

   （紧接三反引号代码块，块内即 opener 正文原文）
   ```
   判据来自 `工具-opener批处理执行v2.ps1` 第 33-56 行的解析器（**只读引用，本包不改该脚本**）：① 标题正则 `^###\s+(A\d+)\s*·?\s*(.*)$`——**必须是 `###` 三级、编号必须是 `A` 加数字**，用 `▶ 泳道：` 起头而无 `### A<N>` 标题的写法**一条都解析不到**；② `粘贴端：\s*(CC|Cowork)` 与 `泳道：\s*(\S+)` 在标题与代码块之间的任意行上取；③ 🔴 **泳道名不能含空格**（正则取 `\S+`，空格即截断）；④ 同一泳道名下多个 `A<N>` 按编号升序**泳道内串行**，不同泳道名之间**并行**（`-MaxParallel` 默认 3、`-StaggerSec` 默认 90 错峰）。
   ✅ **真起泳道前先跑一次 `-DryRun -Yes`**，确认打印出的泳道数与 opener 归属与预期一致——这一步零成本，且是唯一能在起无头 CC 之前发现格式错的手段。
3. **组 opener**：每条泳道的 opener 正文，在清池既有的无头 CC 引导之外，须额外内置四句（三句沿 D1 判据现取与 🟡/🔴 收尾约定，一句新增 ⏭️ 处置）：
   - 一句指向 D1 表现取命令（`... criteria`），**不在 opener 里手抄判据表**；
   - 命中 🟡/🔴 动作时的动作指令：先跑
     ```
     python 0-学习与工具/工具-泳道看护状态机.py pause --batch <批次> --wave <波次> \
       --lane <泳道名> --action-key <D1键名> --waiting-for "<在等什么>" \
       [--option "<候选答案>"]...
     ```
     （落状态 ＋ 推「等人」企微通知一次做完，见工具的 `pause` 子命令），随后**以 `OPENER_PARTIAL: 停在<🟡|🔴>决策点——<在等什么>` 收尾**；
   - 🆕 **命中 ⏭️ 转出档时**（如 `.51` 部署）：跑
     ```
     python 0-学习与工具/工具-泳道看护状态机.py transfer-out --batch <批次> --wave <波次> \
       --lane <泳道名> --action-key <D1键名> --note "<需要走 LAN 收口做什么>"
     ```
     🔴 **不进 `OPENER_PARTIAL`**——转出没有真正要等他裁的判断（答案恒定是「走 `zhuopin-lan-closeout`」），泳道正文应**直接跳过这一项，继续其余不依赖它的任务**；仅当后续项确实依赖被转出的这一项时，才对该后续项走同 🟡/🔴 一样的 `OPENER_PARTIAL` 收尾（同 D3 依赖链例外的处理方式）；
   - 判据未覆盖时按 🟡 停、在收尾原因里问「这个动作该进哪一档」——工具的 `classify`/`pause` 对未知 `--action-key` 已自动 fail-safe 并把提示文案带进企微通知，opener 只需照做，**不必自行判断该不该停**。
   - 🔴 **不改 `工具-opener批处理执行v2.ps1`**（tasks 4.1，只读核对结论）：该脚本只认 `OPENER_DONE`/`OPENER_PARTIAL` 两个哨兵；`OPENER_PARTIAL` 退出码 0，**不会**触发该脚本「FAIL/NO-SENTINEL 才停本泳道」的中断逻辑（脚本源码 `if ($status -like 'FAIL*' -or $status -eq 'NO-SENTINEL') { break }`），故同一泳道计划里排在暂停项之后的独立项仍会继续跑——**若后续项依赖被暂停的这一项，opener 正文须让该后续项自己先查状态文件（`... show --lane <泳道名>`），仍是 paused 就立即以同样的 `OPENER_PARTIAL` 收尾，不得盲目往下做**。
4. **起泳道**：经 `工具-opener批处理执行v2.ps1` 起无头 CC（`isolation: worktree`），调用签名/心跳/企微四类事件推送**完全不变**（4.1 只读核对，未改该脚本一行）；心跳落 `reports/lane-heartbeat/<批次或泳道标识>.md`（约定：开工 1 分钟内写首行「HH:mm:ss ｜ 已开工」，每里程碑追加一行，收工写「DONE ｜ 产出落点」——沿清池 0829 首跑既例）。🔑 **预计等待超过 10 分钟的步骤**（如一次全量回归），**等待期内须再写一行「仍在等 X，预计还要 N 分钟」**——否则看门狗（步骤 5）的 30 分钟判读线在长回归面前会常态性失效（承接清池 `#382` 行内既有判据，5.6 一并落）。
5. **看护**：
   - 🟢 档：自动做完，继续下一项（同清池）。
   - ⏭️ 档：已由 `transfer-out` 记录，泳道不停，继续其余任务（见步骤 3）。
   - 🟡/🔴 档：泳道以 `OPENER_PARTIAL` 退出，`reports/lane-watch-state.json` 已有该泳道的 `paused` 记录（跨 worktree 共享同一物理文件，见工具模块文档「跨 worktree 可见性」）；Cowork 在会话内以「需你定夺」格式呈现（根 `CLAUDE.md` §5 格式四条：编号 + (a)(b)(c) + 各自代价 + 默认项）；他回一个字母后，Cowork 跑
     ```
     python 0-学习与工具/工具-泳道看护状态机.py resume --lane <泳道名> --answer "<他的答复>"
     ```
     再据答复内容起下一段泳道（新开一次 `工具-opener批处理执行v2.ps1 -Only <该泳道下一段>` 或等价小批调用）。
   - D3：单条泳道停不影响其余；**唯一例外**——失败/暂停/转出项在其他泳道依赖链上（触碰区重叠或产出被下游引用）时整链停。
   - 🔴 **D5 待答超时兜底**：看护轮询期间（或续跑前置检查）跑
     ```
     python 0-学习与工具/工具-泳道看护状态机.py check-timeout
     ```
     （默认 4 小时），命中即把该泳道降回原状态、写明「因超时未获答复而收回」、并入当日收工汇总；他回来仍可重新触发该泳道。
   - 🆕 **5.6 波间无心跳看门狗（承接清池 2.3）**：波间轮询各活跃泳道的心跳文件，跑
     ```
     python 0-学习与工具/工具-泳道看护状态机.py check-heartbeat --batch <批次> --wave <波次> \
       --lane <泳道名> --heartbeat-file reports/lane-heartbeat/<该泳道心跳文件>.md
     ```
     （默认阈值 30 分钟）——超时即暂停后续波＋告警＋等人（与 `pause` 同款落状态/通知机制，`tier` 标 🐕 以区别于 D1 四档）。**与 D3 的关系**：D3 管「单项失败只停该泳道、其余继续」；本条管「无心跳」——那是失联不是失败，分不清它在跑长回归还是真挂了，故一律暂停等人；已在 `paused` 态（正等 D1 决策点）的泳道不重复触发——那种「没心跳」是预期状态。
6. **收工**：汇总（每泳道一行 ＋ 心跳全文 ＋ 🔴 **D6「本批停 N 次｜逐次：<泳道>／<档位>／<停在什么动作>／<他答了什么>／<等了多久>」列**＋ **本批转出 N 项（须走 `zhuopin-lan-closeout`）｜逐项：<泳道>／<动作>／<说明>** ＋ 「待回内网」清单——跑
   ```
   python 0-学习与工具/工具-泳道看护状态机.py summary --batch <批次>
   ```
   现取，不手工数）推企微 ＋ 落档；队列回写走锁。

## 🔴 候选范围：按「活」分，不按「域」分（2026-09-02 Shao Peishen 答 (a) 定，业务总线首次正式跑之前）

🔴 **判据只有一句，就是他 S-1 已经定过的那句**：**做错了能不能靠 git 回滚救回来？**

| 能不能回滚救回来 | 归档 | 例子（业务域与机制域**一视同仁**） |
|---|---|---|
| **能** | 🟢 自动做完 | 只动 `.md`／只写单测／**worktree 内建造（含业务场景代码）**／只读取证／openspec 起草／队列回灌 |
| 边界 | 🟡 停等一个字母 | ff 合入 master／改口径判据阈值／design 审／关他人在办队列行 |
| **救不回来** | ⏭️ 不执行、转出 | `.51` 部署及任何触碰生产服务的动作 |
| 绝不 | 🔴 永不代办 | 对外发送／L2 门禁签字／合规红线变更／ASIL C-D |

⚠️ **本节是对一处继承性冲突的收口，成因写清免得后人再撞**：本包吸收 `zhuopin-lane-clearpool` 时，连同继承了它那句「**业务建造**与一切对外发送永不自动入批」。
**那句是 clearpool 为「周末批量清 off-LAN 机制类杂活」写的**（判据正本＝已归档的 `lane-clearpool-skill` design D1），而本包收敛后的范围是「**做所有非 `.51` 的可领活**」——**两句在业务总线场景下直接打架**：照前者泳道什么都不敢领，照后者它会去动业务生产码。

🔴 **收口后的措辞（此后一律以本节为准）**：**业务*数据*与一切对外发送永不自动入批** —— 把「建造」换成「数据」。
**理由**：worktree 内的业务建造**完全能靠 git 回滚救回来**，与机制类建造没有本质差别；救不回来的是**被改写的真实数据**（同 `§一 #418`「代码级回滚救不回被改写的数据」，非本次新发明）。
