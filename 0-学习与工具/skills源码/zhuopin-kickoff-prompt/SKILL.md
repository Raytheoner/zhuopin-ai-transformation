# 卓品 · 交接/转场 Prompt 生成器（v1.2）

为"企业AI转型"项目生成新 session 的交接 prompt。**铁律：引用版**——prompt 只放权威文件的路径与章节指针，绝不复制其内容（防双份漂移，Shao Peishen 2026-07-06 定为标配）。

> v1.1（2026-07-10）：收工段强制带 git 处置、prompt 呈现一律 fenced 代码块（Shao Peishen 2026-07-08 两纪律）；纪律段加跨桌任务队列（Shao Peishen 2026-07-09 纪律）。
> 2026-07-23（队列 §四#32 backlog 回补）：纪律段补一句"编辑跨桌任务队列.md 前先 acquire 协议〇.7 编辑锁、改完 release"。
> **v1.2（2026-07-30，队列 #97）**：三项硬规则入骨架——① **执行环境标注**（`【Cowork】/【CC】` 进标题、`执行环境：` 进【设置】行，Shao Peishen 2026-07-27 定）；② **开工先按触碰区关键词 grep 队列 + 归档件**（认领先于动手的可执行化）；③ **编号一律在 acquire 之后重算**，取回显高水位线 +1。

## 执行步骤

1. **判定目标线 + 执行环境标注（v1.2 硬规则，Shao Peishen 2026-07-27 定）**：Cowork 域专线（采购/财务/质量/销售）｜Cowork 全景总线（重组循环执行）｜CC 建造（代码/真实库/git）。分工红线：域专线不改全景；总线不重开域口径；CC 不改规划文档。
   - **判别口径**：只产改 `.md`、不写生产码、不自行 commit（收工只登 §二 批次）＝ **Cowork**；写跑代码／连真实库与 `.51`／测试部署／自行 commit+push／一任务一 worktree ＝ **CC**。只读取证（PowerShell 直读接口、git 取证）仍属 Cowork；**一旦要改代码或触发服务动作即转 CC**。
   - **落点（两处冗余，缺一不可）**：**标题**处写 `【Cowork】`/`【CC】`（供 Shao Peishen 扫读挑活）；**`【设置】` 行**写 `执行环境：Cowork/CC`（随 opener 复制进新 session）。
   - **`【设置】` 行标准四字段（v1.2 硬规则，Shao Peishen 2026-07-30 定）**：`执行环境 ｜ 分支 ｜ worktree ｜ **工作区**`。前三个回答"在哪写"，**第四个回答"写完在哪生效"——缺它就会出现『改完不等于生效』**。填法：不触碰常驻服务/已部署场景→`无`；触碰 `.51` 四服务→写明推送脚本+重启计划任务+冒烟三件套+回滚 SOP；🔴 触碰企微机器人→写明**须同步 `ops/wecom-service-home` worktree 后重启 `ZhuopinAibotDevListener` 并确认单实例存活**（服务跑的是那个 checkout、不是 master）；触碰定时任务 prompt→写明改的是仓库外 `Claude\Scheduled\<task>\SKILL.md`、须经 `update_scheduled_task` 改并回归自检原有纪律未丢失。
   - **命名不得与执行环境标注冲突（v1.2 硬规则，Shao Peishen 2026-07-30 定）**：文件名/标题里的 `CC`／`Cowork` 是**执行环境保留标识**，不得用于线名、角色名、服务名；表示执行环境时一律用方括号 `【CC】`／`【Cowork】`。**线名一律不带执行环境词**（本线今后称「环境保障线」而非"CC 环境保障线"），"为谁服务"写进定义段、不写进名字。**历史记录不追改**，规则只约束新产出。**推广**：任何已有专属含义的词（`CC`/`Cowork`/`master`/`live`/`dry-run`/`SC*`/`FI*`/`B-*`/`#编号`）不得在同一文档体系里表达第二种含义——命名前自检"这个词在本项目里已经有专属含义了吗？"。**成因**：`开场prompt-CC环境保障线-…`（线名带 CC、执行环境实为 Cowork）令 Shao Peishen 拿到时产生疑惑、靠读正文才判断出该开 Cowork——标注规则被自己的命名反噬。详见 `专线opener模板库.md` §〇.2。
   - **写 opener 时的自检一问**：*本次改动，有没有任何一份"正在跑的副本"不在我改的这个 checkout 里？* 有→写进「工作区」字段；没有→填 `无`。**成因**：2026-07-30 #168 的 CC opener 初稿漏了这一步，若照初稿执行会在**未改动的旧代码**上"重启验证通过"；该步骤在服务 CLAUDE.md 已两次正确记载（07-22、07-27），却从未进过 opener 模板——一直靠 CC 记得。详见 `专线opener模板库.md` §〇.1。
   - **为什么两处都要**：2026-07-27 的《本周计划》§A 只写"财务/采购/质量专线"，读者须靠 `worktree：☐`／"只编 .md"／"勿自行 commit"等间接特征反推是哪张桌，Shao Peishen 明确反馈有歧义。规则真身见 `专线opener模板库.md` §〇 与 CLAUDE.md §5「执行环境标注」。
2. **收集指针**（只收路径，不抄内容）：本次任务的权威依据（移交单/局部定稿/需求件/执行单）+ 对应接力文件（`1-转型规划/session接力-<域>场景落地.md` 或 `0-全景路线图/session接力-Phase1收口.md`）+ 根 CLAUDE.md。
3. **写 prompt 文件**，命名 `开场prompt-<主题>-<目标线>交接.md`，落位：总线/重组类入 `1-转型规划/0-全景路线图/`，域专线类入 `1-转型规划/`。frontmatter 必含 title/created/执行方/来源/status: 待执行。
4. **正文骨架**（顺序固定）：
   - 用法行 + **「开场词（复制即用）」**：单句、含本文件完整相对路径 + "＋CLAUDE.md 当前进度恢复上下文，按文件执行；开干前问我 2-3 个澄清"
   - 背景一分钟（≤5 行）
   - 权威依据清单（①②③… 路径+章节指针+一句话说明各是什么）
   - 任务分段（A/B/C… 按优先级，每段含验收标准）
   - **开工前置步（v1.2 新增，把"认领先于动手"变成可执行动作）**：prompt 里明写——「开工第一件事：按本任务触碰区关键词（文件路径／场景号／专员姓名）**同时 grep 《跨桌任务队列.md》与《跨桌任务队列-归档-YYYYMM.md》**，确认无他人在办行重叠、且本任务未被别的行覆盖；有重叠不得抢领，报总线裁决。」**归档件必须一起 grep**——每周清扫后历史行已不在队列正文，只搜正文会误判为"没人做过"。
   - 纪律段：引用 CLAUDE.md §5/§7 相关条目名（排期同步/完工即归档/§0.2 登记/对客闸/mock先行/哨兵/**跨桌任务队列——开工必读认领+登记触碰区、收工必写+下游任务当场追加**/**编辑跨桌任务队列.md 前先 `acquire` 协议〇.7 编辑锁、改完立刻 `release`（占用中把待登记内容写进自己域接力文件顶部固定小节「⏳ 队列更新待补」等回补，不硬写）**/**新行编号一律取 `acquire` 回显的持锁瞬间高水位线 +1，不得用 acquire 之前读到的值**——2026-07-29 一天四次撞号皆源于此），不抄全文
   - **收工段（必含 git 处置，v1.1 强制）**：滚动对应接力文件 + 更新台账状态；**Cowork 专线/总线类** prompt 收工段须写明"列出本次全部新产出/修改文件清单 + 建议 commit message + 登记队列 §二待 commit 批次 + 提示 Shao Peishen 一句话交 CC：commit + push + 收工重跑台账"（Cowork 不擅自 commit，但不留未提交悬置）；**CC 类** prompt 本含 commit+push，另加"收工重跑文档台账"。
5. **交付**：present_files 附文件卡片 + 在聊天中给出开场词可复制块。若 Shao Peishen 未说明澄清问题，替目标 session 预置 2-3 个建议澄清问题写进 prompt 用法行。
6. **呈现格式（v1.1 强制）**：聊天中交给 Shao Peishen 的 prompt/口令，**≤500 字直接给完整原文、>500 字落 prompt 文件 + 单句开场词引用**；无论长短一律放 fenced 代码块（```…```，渲染自带复制按钮），不用引号段落。
