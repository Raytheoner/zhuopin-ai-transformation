## 执行步骤

1. **判定目标线 + 执行环境标注（硬规则）**：Cowork 域专线（采购/财务/质量/销售）｜Cowork 全景总线（重组循环执行）｜Cowork 环境保障线｜CC 建造（代码/真实库/git）。分工红线：域专线不改全景；总线不重开域口径；CC 不改规划文档。
   - **判别口径**：只产改 `.md`、不写生产码、不自行 commit（收工只登 §二 批次）＝ **Cowork**；写跑代码／连真实库与 `.51`／测试部署／自行 commit+push／一任务一 worktree ＝ **CC**。只读取证（PowerShell 直读接口、git 取证）仍属 Cowork；**一旦要改代码或触发服务动作即转 CC**。
   - 🔴 **补一类·改本机工具链＝CC（Shao Peishen 2026-08-02 定）**：全局 npm 包/插件/CLI 的**安装与版本升级**、以及 `openspec update` 一类**会重写生成物的命令**，**一律标【CC】——即便产出看上去只是 `.md`**。**成因（队列 #205-A 实证）**：`openspec update` 曾把 `.claude/commands/opsx/propose.md` 里的强制门禁段**整段静默删除**（零提示零报错，混在 10 个文件的上游 diff 里）。**仍归 Cowork**：对工具链只读核实版本与状态、把差异登记成待领行。**破例须其明示授权** + 固化升级前证据 + 逐文件过目 diff（判据推荐"中文行增删计数"）+ 事后登记为破例。
   - **落点（两处冗余，缺一不可）**：**标题**处写 `【Cowork】`/`【CC】`（供 Shao Peishen 扫读挑活）；**`【设置】` 行**写 `执行环境：Cowork/CC`（随 opener 复制进新 session）。
   - **`【设置】` 行标准四字段（Shao Peishen 2026-07-30 定）**：`执行环境 ｜ 分支 ｜ worktree ｜ **工作区**`。前三个回答"在哪写"，**第四个回答"写完在哪生效"——缺它就会出现『改完不等于生效』**。填法：不触碰常驻服务/已部署场景→`无`；触碰 `.51` 四服务→写明推送脚本+重启计划任务+冒烟三件套+回滚 SOP；🔴 触碰企微机器人→写明**须同步 `ops/wecom-service-home` worktree 后重启 `ZhuopinAibotDevListener` 并确认单实例存活**（服务跑的是那个 checkout、不是 master）；触碰定时任务 prompt→写明改的是仓库外 `Claude\Scheduled\<task>\SKILL.md`、**该文件在会话内只读，必须经 `update_scheduled_task` 全量替换 prompt**（2026-08-04 实测：直接 Edit 会被拒），并回归自检原有纪律未丢失。
   - **命名不得与执行环境标注冲突（Shao Peishen 2026-07-30 定）**：文件名/标题里的 `CC`／`Cowork` 是**执行环境保留标识**，不得用于线名、角色名、服务名；表示执行环境时一律用方括号 `【CC】`／`【Cowork】`。**线名一律不带执行环境词**（称「环境保障线」而非"CC 环境保障线"），"为谁服务"写进定义段、不写进名字。**历史记录不追改**。**推广**：任何已有专属含义的词（`CC`/`Cowork`/`master`/`live`/`dry-run`/`SC*`/`FI*`/`B-*`/`#编号`）不得表达第二种含义——命名前自检"这个词在本项目里已经有专属含义了吗？"。详见 `专线opener模板库.md` §〇.2。
   - **写 opener 时的自检一问**：*本次改动，有没有任何一份"正在跑的副本"不在我改的这个 checkout 里？* 有→写进「工作区」字段；没有→填 `无`。**成因**：2026-07-30 #168 的 CC opener 初稿漏了这一步，若照初稿执行会在**未改动的旧代码**上"重启验证通过"。详见 `专线opener模板库.md` §〇.1。

1.1 🔴 **标题行硬规则（v1.6，Shao Peishen 2026-08-04 定；规则真身见 `专线opener模板库.md` §〇.0）**：**每个 opener 代码块前必须有一行标题**，格式 `### A<N> ·【Cowork/CC】<线名>（<优先级/时限>）——队列 #x／#y／#z`，**聊天中重发单个 opener 时同样带上**。
   **成因（他本人反馈）**：改版重发 opener 时只给代码块、没给标题行，他原话「**虽然我可以推断，第一张图是哪个任务的 Opener 不明晰**」——代码块内部只有"按队列 #x 开工"，要反推是哪件任务得先记住本周计划的分配，**而 opener 存在的全部意义就是"复制即用、零判断"**。
   **为什么是硬规则**：opener 会被**多次重发**（撞车改版、范围收窄、前置解除各触发一次），**每次重发都是一次身份丢失的机会**；标题行成本只有一行字。**自检一问**：*把这个代码块单独发给一个没读过本周计划的人，他能一眼说出这是哪件任务吗？*

1.2 🔴 **次序与并行矩阵硬规则（v1.7，Shao Peishen 2026-08-07 定，两桌全局；规则真身见 `专线opener模板库.md` §〇.8）**：**一次给出 ≥2 个 opener／派单件／可开工任务时，必须附一张矩阵**，逐项写明：
   ① **能否立即开工**——零依赖／软序／硬阻塞／定时触发型**四选一**。⚠️ **依赖判断以队列行状态列开头的括注自陈为准，本项目没有独立依赖表**，不要去找。
   ② **能否与其它哪几项并行**——🔑 **并行判据 ＝ 触碰区是否重叠**；重叠即软序，须串行或同车。
   ③ **若必须串行，谁先谁后及其理由**。
   **不得只把 opener 并列列出、让他自己推断先后。** 他的原话：「以后一个会话产生多个任务都请指明秩序和并行」。
   **与 1.1 的关系**：1.1 管「这是哪件任务」，本条管「这几件任务之间是什么关系」——**两者是同一类问题的两个形态，都是在 opener 外层补一个字段使读者不必推断**；让他做推断本身即违背 opener 的设计目的。
   **自检一问**：*把这几个 opener 一起发给一个没读过本次会话的人，他能一眼说出该先开哪个、哪几个可以同时开吗？* 不能→矩阵没写够。
   🔑 **本条的补入本身是一次实证**：该规则 2026-08-07 立法，而 **2026-08-08 实测本 skill 与 `专线opener模板库.md` 对它均 0 命中**——**本项目两个生成 opener 的载体，此前都不知道这条规则存在**。成因是本 skill 末次重打包为 08-04、规则 08-07 才立，**时间上必然错过，不是疏忽**。⇒ **凡新立的 opener 类规则，须同时更新本 skill 与模板库两处。**

1.5 **判定转场类别，决定提问策略（Shao Peishen 2026-07-31 定；规则真身见 `专线opener模板库.md` §〇.3）**：
   - **A · 同线转场**（本线接本线、无新任务）→ opener 内**必须内置「开工自检三查」**（① 接力最新日期节＝上次收工日？② 抽 2 行核 opener 在办清单 vs 队列**实际状态列**，不一致以队列为准 ③ grep 四条接力顶部「⏳ 队列更新待补」有无残留），**三查全通过即直接开工、不提问**；任一不通过才就差异发问。
   - **B · 跨线交接**（Cowork→CC、A 线→B 线、总线派活）→ **必问**（交接方与执行方对边界理解常不同，且 CC 要动生产）。
   - **C · 新任务/新场景**（无既有接力可依）→ **必问**，且 opener 内**预置候选问题**，不让执行方自己想。
   - **D · 定时任务 prompt**（巡逻／巡检／每日提醒等 cron 驱动）→ 🔴 **绝对禁止写入任何需要人当场回答的指令**（含"开干前问我…"）——非交互 session **没人能回答**，写了即空转；该类一律靠「**预案覆盖 + 歧义登 §四**」。
   - **两条形态规则（全类别适用）**：① **禁开放式提问**，一律给**带推荐项的选择题**并写清选项间实际差异与代价；② **数量随差异数量走，不写死 2-3 个**——无歧义就 0 个直接干（"2-3 个"仅作上限提醒，超 3 个说明 opener 没写清，应先补 opener）。
   - **⚠️ 为何 A 类不是简单"不问"**：2026-07-31 实证 07-30 那份接力的在办清单**24 小时内即全面过时**（#163/#147/#97/#98 均已完成）——**本项目推进速度下接力过时是常态**，故 A 类正解是"先自检、再就差异发问"。

2. **收集指针**（只收路径，不抄内容）：本次任务的权威依据（移交单/局部定稿/需求件/执行单）+ 对应接力文件（`1-转型规划/session接力-<域>场景落地.md` 或 `0-全景路线图/session接力-Phase1收口.md`）+ 根 CLAUDE.md。

3. **写 prompt 文件**，命名 `开场prompt-<主题>-<目标线>交接.md`，落位：总线/重组类入 `1-转型规划/0-全景路线图/`，域专线类入 `1-转型规划/`。frontmatter 必含 title/created/执行方/来源/status: 待执行。

4. **正文骨架**（顺序固定）：
   - **标题行**（见 1.1，含计划编号＋执行环境＋线名＋队列行号）
   - **若本次交付 ≥2 个 opener，先给次序与并行矩阵**（见 1.2），再给各 opener
   - 用法行 + **「开场词（复制即用）」**：单句、含本文件完整相对路径 + "＋CLAUDE.md 当前进度恢复上下文，按文件执行"，**尾句按步骤 1.5 的类别选**——**A 类**＝"先按文件 §〇 自检三查，通过即直接开工、有差异再问我"；**B/C 类**＝"开干前问我 2-3 个澄清"；**D 类**＝**不写任何提问句**。
   - 🔴 **【设置】行必须写在 fenced 代码块内、作为第一行**（Shao Peishen 2026-07-31 当场发现）：**放在块外加粗＝复制按钮只复制开场词、必然漏掉设置行**——这不是人会不会忘的问题，是**渲染机制保证它被漏掉**。**聊天交付时同理**：给 Shao Peishen 的可复制块必须**同块包含【设置】行与开场词**，不得分两块给。
   - 背景一分钟（≤5 行）
   - 权威依据清单（①②③… 路径+章节指针+一句话说明各是什么）
   - 任务分段（A/B/C… 按优先级，每段含验收标准）
   - **开工前置步（把"认领先于动手"变成可执行动作）**：prompt 里明写——「开工第一件事：按本任务触碰区关键词（文件路径／场景号／专员姓名）**同时 grep 《跨桌任务队列.md》与《跨桌任务队列-归档-YYYYMM.md》**，确认无他人在办行重叠、且本任务未被别的行覆盖；有重叠不得抢领，报总线裁决。」**归档件必须一起 grep**——每周清扫后历史行已不在队列正文，只搜正文会误判为"没人做过"。
   - **纪律段**：引用 CLAUDE.md §5/§7 相关条目名（排期同步/完工即归档/§0.2 登记/对客闸/mock先行/哨兵/**跨桌任务队列——开工必读认领+登记触碰区、收工必写+下游任务当场追加**），并**必带以下四条**：
     - **编辑锁**：改队列前 `acquire`、改完立刻 `release`；占用中把待登记内容写进自己域接力文件顶部「⏳ 队列更新待补」等回补，**不硬写**。🔴 **acquire 与写盘必须两步、中间查 `$LASTEXITCODE`**——2026-08-04 实测：用 `;` 串联且不查退出码，锁工具已正确拒绝而脚本照跑照写（已登记 #200）。**「工具拒绝了」与「动作没有发生」是两件事。**
     - **取号**：新行编号一律 `--reserve` 预留，不自己做加法（#162 已证"回显正确、人仍会看错"）；同时要 §一/§四 两套号用 `--reserve-multi 一:N 四:M`（#185，2026-08-04 落地）。**拿到号不等于已定**——并发下以写入后实测为准。
       🔴 **取号前必须先做「并入审核」（协议〇.10，Shao Peishen 2026-08-08 定，v1.7 补入）**：他的原话「以后新建队列任务不管环境端还是业务端，不管 Co/CC，优先审核并入已有待领任务，实在无法并入任何已存在待领任务才追加序号新建」——**追加新号已由默认动作降为例外**。取号前逐条扫 §一 全部"待领"行（编号＋任务列首段即可，池子通常十余条、成本很低），**能并入的一律并入**（在该行内追加子项，不新建行）；无论并入还是新建都要写一句结论：「已逐条过 N 条待领行，无可并入：〈理由〉」或「拟并入 #X，故本次不取号」。**豁免**：企微机器人对来件的自动追行属"收件登记"、不是建任务，走独立取号路径。
       🔴 **机制类还要看「可动 WIP」上限 8（协议〇.9 措施 C，v1.7 补入）**：只约束**机制/环境类**行，业务场景行不受限；**分母是"可动 WIP"而非未收口总数**——减去三类排除：①定时触发型（触发日未到）②依赖外部方（等专员签认／等 IT／等供应商）③永久关闭·仅手动唤醒（状态列以 🛑 起首）。超限期间新立机制行须先关一条。**旧口径的教训**：曾按未收口总数计致 #309 被迫走特批例外，而按可动口径当时仅 3 条本不该撞限——**一个会逼出例外的上限，例外多了规则就废了**。
     - 🔴 **三条静默失败写法禁令（2026-08-04 逐条实证，全部零报错）**：⑴ 批次文件清单**必须写完整路径**，不得用"同名 `.docx`""同上"等速记；⑵ 队列文本内**不得出现裸竖线**（撑破列数）；⑶ 用脚本改 md 时**串内不得嵌直双引号或裸反引号**（前者致语法错误脚本零输出，后者打乱反引号配对使其后片段全部错位）。**三者的失败形态都是"外观同成功"，只能靠写后反查发现。** 💡 **2026-08-08 实测补充**：连**三连反引号**也会触发——编辑锁 `release` 会因此读不到批次清单里的队列路径并拒绝释放（**这是它该做的：fail-loud、锁保持占用**），修正后重试即可，不要绕过。
     - **状态头纪律**：销行/回填时 **✅ 必须写在状态列开头**——队列靠状态字段驱动，行尾写完成、开头留"待领"等于没完成（2026-08-03 一次性校准过 6 行同形态）。**尚有任一子项未完成一律写 🟡、不得写 ✅。**
