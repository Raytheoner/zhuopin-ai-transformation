> **v1.11（2026-08-19，Shao Peishen 定）**：新增 **4.1 收工报告「需你定夺」项的路由硬规则**——路由判据由「谁提的／session 活没活」改为「**这一项答完之后，由谁动手**」；**本 session 接着就做 ⇒ ⟨就地答⟩，正常给 (a)(b)(c)＋默认项；要另起 session／归他线／对外发送／改他人触碰区 ⇒ 🔴 不给选项**，只写一行「已登记 §一 #N（或 §四 #N），待总线派发」＋一句结论摘要。配套：**报告顶部加一行汇总** `▶ 本报告 N 项定夺：X 项⟨就地答⟩，Y 项已登记队列待总线派发`；**判定责任在写报告的一方、不在 Shao Peishen**（写的人知道自己接下来会不会执行，他不知道）。**他的原话**：「如果 CC 已收口，后面又紧跟定夺选项，这样很容易引导我直接 CC 里回复，你却又希望我转场总线回复，有点绕，是否有更直接的做法和更明显的标注说明？」🔑 **问题不在标注不够明显，在于「给了选项」本身就是一份邀请——报告在哪，回复的引力就在哪**；加标注是在跟人的自然行为对抗，**移除选项才是消除引力**。⚠️ **当场可验**：2026-08-19 `material-board-view-df54d1` 收工报告两项——「#334 apply 接着做吗」答完它自己立刻执行 ⇒ ⟨就地答⟩ 标对了；「采购部#16 判例 3 虚构数据怎么处置」**它也标了本 session 答，但处置动作是对外发信／补判例、归 Cowork，它根本不会执行** ⇒ 应为「不给选项、登记待派」。**旧判据判不出这一条。** **连带**：此前拟定的「已收工 CC 的定夺项一律走总线答」**不再单列**——收工 ＝ 不会再执行，它是本判据的一个特例、已被完全覆盖，按规则退休制不另立规则。
