## 两种诊断路径

1. **单次真实链路计时（推荐，另取得具体诊断授权）**：在仓库内忽略的证据目录生成同一源码的诊断副本，仅在已有段落边界插入stderr阶段时间标记。保留硬编码数据根、子进程、原逻辑与stdout契约；记录原源码hash、副本hash和仅标记的差异。不改正式状态卡或测试。此路径能定位真实链路，包含原脚本已有的只读文件/进程/网卡/可能LAN GET，须按该范围审查。
2. **仅合成替身计时**：用合成队列和可控依赖验证标记/编码协议。它可以准备诊断工具，却不能解释真实主仓180秒超时，也不能通过原真实CI节点。不得将其作为替代通过证据。

## 推荐采样边界

| 阶段 | 原脚本边界 | 只留的观测 |
|---|---|---|
| P0 | 进程进入、`$rootOk` 完成 | UTC/单调时钟、PID、实际PowerShell路径/版本、代码checkout与数据根 |
| P1 | 文档源准备至队列解析结束 | start/end/elapsed、退出或异常分类；不打印文档/队列正文 |
| P2 | opener扫描和本地行分类结束 | elapsed、文件/行计数；不打印派单内容 |
| P3 | `工具-可Open池.py` 子进程前后 | 实际Python绝对路径、子PID、起止、exit、是否出现合法 `@@POOL64@@`；不打印池正文 |
| P4 | sweep统计开始/结束 | elapsed、日志字节/行数；不打印日志内容 |
| P5 | git log开始/结束 | elapsed、exit、返回条数；不打印commit正文 |
| P6 | IPv4枚举及原LAN分支前后 | elapsed、LAN三态、是否走原GET；端口与响应状态可留，不增加任何端点 |
| P7 | JSON序列化开始/完成 | elapsed、输出字节、是否出现合法 `@@JSON@@`；原载荷仅留在受控忽略件，不通读队列 |

将 `@@JSON@@` 输出与stderr标记分开保存；诊断脚本不增加第二次调用、不发送通知。每个异常保留原错误，不能改为0或成功。根因结论必须由阶段时间与同次终态支持。

## 生命周期与停止线

- 单次诊断上限仍按原180秒。到时只结束本次创建的PowerShell进程及已确认归属该诊断的子进程，留最后完成阶段；不杀全机Git、服务或其它会话。
- 创建任何进程前记录源码/hash与进程归属；若不能安全确认子进程归属，则不使用全局进程清理，记录未完成状态并停止依赖动作。
- 在诊断副本中插标记前先核diff，拒绝逻辑、数据根、timeout、skip、错误处理或请求的差异。若插入点需改控制流，回到design审，不直接扩大实现范围。
- 真实队列读取由既有状态卡/可Open池接口执行；本会话判行仍只用 `工具-队列查询.py`。不使用副本作为K3直读入口。
- 原CI node只有在实际修复、受批准同HEAD验收并配对复核后才可关闭；一次采样结束只标“取得诊断证据”。
