## 四、两种可审阅路线

| 路线 | 流程 | 权衡 |
|---|---|---|
| A（推荐）影子生成 + 受控维护窗口 + 可恢复配对提交 | 对固定输入生成影子 CSV/ledger；先核验和审阅；暂停相关读写后备份与核验现场基线，提交两文件，失败配对回滚，验证一致后恢复读写 | 保持已有数据路径。两个 replace 本身仍非原子；一致性依赖读写隔离、事务记录、崩溃恢复与未验证时禁止恢复服务。 |
| B 代际目录 + 一个当前代际指针 | 每代完整生成、校验 CSV/ledger，再只切换一个指针；读写者统一读取该代 | 可把可见性切换缩到单个指针，但需要调整各手动/定时写者和读者的接口、锁与恢复策略，范围更大。 |

推荐 A，理由是本项恢复历史证据，不需要为此更改所有读写接口。**A 不是已批准设计，也不声称 Windows 能同时原子替换两个文件**。若现场无法可靠暂停全部相关读写，A 的前置条件不满足；不能省掉隔离窗口继续发布，须重新评估 B。

## 五、A 路线的候选契约（待设计审）

### 1. 固定输入与影子重放

1. 在获准的现场只读核验阶段取得成对基线的文件摘要、输出行数、ledger 总数与分段信息，明确快照时刻；逐份核对导出名称与 SHA。旧备份与当前源文件的存在性均重新检查。
2. 有效源文件按确定顺序重放到新的、未被服务使用的输出目录。初始影子 ledger 和影子 CSV 从空开始；不调用现场 CSV 的 known 集合作为重放排除清单。匹配函数、签认顺序、同一 AP 限制与金额/税额尾差算法原样复用。
3. 为每条源明细保留文件 SHA、原始 row_index、发票号及对应输出行索引；拆行对应多个输出行。同文件合法的重复明细全部保留；跨文件重复按已有规则处理，不能全局对行内容 set 去重。
4. 不能重新取得同一 SHA 的源文件，其**已有有效 CSV 段**从成对基线保留，标为“保留旧证据、未重新解析”；其旧 unresolved 单独列不可重试。已在盘但 SHA 改变的文件不能冒充原条目。基线段归属、文件同名不同 SHA 或跨来源冲突不能证明时中止候选产出，不猜赢家。
5. 保留旧段与重放结果合并前检查同发票号的归属冲突；不能为了恢复新增行重复计入旧有效段，也不能因为原始文件缺失把既有有效行删除。无法验证冲突时不发布。
6. 使用固定 AP 取数结果或可重放的 mock 输入；真实取数时记录观察时间与范围，差异报告明确它不是原始发生日 ERP 状态的重建。真实数据仅留在获准的数据位置，不能进入 Git 或新审计正文。

### 2. 必须同时成立的输出不变量

1. CSV 实际输出行数 = ledger 各条目 row_count 合计 = 各有效 segments 的输出行数合计；每条目的总数等于其 segments 合计。
2. 全局段顺序可唯一切回 CSV，所有输出行恰有来源；混合新旧 segments 或 legacy 迁移若不能证明顺序，不默默补一个顺序。
3. 拆行的来源映射允许一源多输出；按已签认算法分别守住数量、未税金额和税额，不引入新容差或新专业判断。审计只记录分类、差异比率或守恒检查结论，不落原始金额。
4. 同一源文件的合法多行发票不被误删，跨文件重复不增加计数；缺失源文件的既有有效段不会被重放空结果覆盖掉。
5. 可恢复、新增未解、保留旧 unresolved、缺失/变更源不可重试分别统计；不把无来源的未解行说成已恢复。

### 3. 发布与回滚

1. 影子生成与影子核验全部结束后才形成实际影响表；取得针对该候选摘要、现场目标路径、维护窗口与恢复操作的具体批准。定时扫描是否恢复须另有具体授权。
2. 暂停并确认实际写者和相关读者已退出；待处理写入与在途读取处理完毕。获取发布互斥后重新核现场 CSV/ledger 摘要必须仍等于批准基线，否则候选过期、中止。
3. 先创建同一事务标识的**两个**基线备份，验证摘要、可读性和不变量，再登记预提交记录（基线、候选、备份、阶段、摘要）；事务记录不写财务原始金额或凭据。
4. 以预提交记录驱动 CSV/ledger 配对替换。任一异常、两个文件混合或中断后恢复时，只允许恢复到完整基线或完成完整候选；未完成核验不得开放服务。必须有可由维护人员执行的配对恢复入口，不能仅写“需要时回滚”。
5. 两文件写后重新摘要/读取/校验，确定完整候选，记已提交，随后才按批准恢复读写；失败时核验两个文件均恢复到完整基线并记录失败。不能在 finally 无条件重新启用扫描。

### 4. 影响数字的生成方法

必须同一输入快照比较：旧/新 CSV 输出总数、净增、恢复的源明细数、拆行增出的输出行数、跨文件去重数、变化的既有行数、保留缺失源有效行数、各 unresolved 类数；分清“行”和“发票”。

AP 转出清单 = 旧基线在固定 AP 集合内没有发票、而候选在相同 AP 集合内有发票的 AP 集合。还要列反向退化、变更但未转出的 AP，禁止只报好转数。核对范围与 #494 的待决默认展示需求分离。

目前所有新影响数字均**未测量**，不能填 645/206 作为期望输出。两张原始 AP 需按表 2 的发票号逐条复现，并区分“摄取已产出”“面板参与范围”“建议状态”；有发票不等于可以自动过账。
