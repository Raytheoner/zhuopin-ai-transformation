# O4 · 设备类别后定的输入输出合同草案

## 一、已答范围与本件用途

Shao Peishen 已明确允许试点设备类别晚点再定；官方 #509 已记录“类别不阻断设备无关的输入输出合同、数据可得性和 mock 结构准备”。本件补齐这些准备，不预选具体设备，不确认完整 intent，不启动 OpenSpec、产品代码、采集或预测模型。

目标仍是设备预测性维护，包括运行参数、健康/RUL/故障模式、维护/备件建议、异常与误报区分、OEE 改善；本件为这些能力准备可追溯数据边界。共同字段齐全只说明资料可对照，不能代替预测能力或完整 O4 验收。

当前采取类别中性准备路径。另一条路径是先选设备、取得传感器和维修资料再准备专属规则，能更早确定信号含义，但会等待实际盘点。设备类别延后已获允许，后者放到设备专属阶段；没有追加范围审批题。

## 二、输入合同候选

以下为待审字段合同，尚无实现或正式接口兼容保证。所有原始记录保留；推导字段不回写原始资料。发生时间与获取时间分列，缺失与矛盾保留，不补造设备运行事实。

| 输入资料 | 最小共同字段 | 类别未定时的处理 | 设备专属阶段需要补的证据 |
|---|---|---|---|
| 资料包身份 | bundle_id、revision、synthetic、tenant/oem_scope、source_ref、source_version/hash | 本包仅 synthetic=true；没有真实 OEM 原件。来源不明不能视作可用。 | 数据权限、真实来源、版本基准和隔离范围。 |
| 设备资产 | asset_id、来源资产键、设备标签、设备类别、资料归属 | 合成 asset_id 可用；device_category 可空并明确“尚未选择”。仅作共同结构准备。 | 设备类别/型号、具体试点资产、Owner/backup、信号与维修资料关联。 |
| 测量记录 | source_event_id、asset_id、metric_key、raw_value、declared_unit、occurred_at、retrieved_at、source_ref | metric_key 用合成信号；单位保留原声明；原始值可缺失但须标记。不得把合成信号当真实温度/振动。 | 信号物理意义、单位/量程、采样与校准版本、缺测条件、实际时钟/时区。 |
| 状态事件 | source_event_id、asset_id、原始状态/说明、两个时点、来源 | 原始标签可以并排，不能自行合并成“正常/故障”。 | 设备状态定义、停机/运行口径、人工核准与标签充分性。 |
| 维护/故障记录 | record_id、asset_id、原始报告/维护动作、发生时点、附件来源、标签提供者 | 保留原文与提供者；没有专家确认就不作模型真值。 | 故障分类、维修完成/更换部件、真实维护周期、误报与故障黄金集。 |
| 生产/OEE关联 | period_ref、asset_id、原始计划/运行/停机/产量来源 | 当前只有计划资料不能填成设备运行或 OEE 实绩。 | OEE 分母/时间/停机/质量口径与原始采集记录。 |

候选记录关联键为“资料归属范围 + asset_id + 来源对象”，不能只按设备标签跨资产或跨 OEM 关联；其实际字段映射、唯一键和冲突消费由后续 design 审查。设备类别空值不阻断本件编制，但不能通过设备专属建造/真实模型前置。

## 三、输出合同候选

| 输出 | 必须保留的内容 | 当前不能填的内容 |
|---|---|---|
| 数据可得性表 | 每类资料的来源、版本、存在/缺失/冲突、适用资产、是否合成 | 未取得实际源时不得写“接口已接通”或“资料已齐”。 |
| 证据时间线 | 原始发生/获取时点、测量/状态/维护证据引用、错序及重复候选 | 不把获取时点当设备故障发生时点，不自行覆盖更正或合并数量。 |
| 质量与关联问题 | 缺值、单位待核、时间歧义、资产不匹配、来源冲突、跨范围记录分离 | 缺测不等于设备失效；单位差异不等于物理异常；不跨范围拼接。 |
| 健康/故障/RUL证据位 | prediction_status、专业基准引用、模型/数据版本、人工确认位 | 当前 prediction_status=not_evaluated；health/failure_probability/RUL 均空，没有模型输出或准确性声明。 |
| 维护/备件/误报/OEE证据位 | 所需原始资料、专业判据是否已签、人工动作/回执引用 | 无阈值、维护周期、自动工单、自动停机或备件采购建议；不编造 OEE 改善百分比。 |
| 审计 | 输入资料包/事件引用、输出版本、生成角色/时间、实际人工核对记录 | 预期人工对照与运行实测分列；本轮实际运行、人工专业签认均未发生。 |

“资料缺失/冲突”属于数据证据描述；“设备异常/故障、多久维护、寿命剩余、误报”属于专业判断。后者由专业判例签认后进入设计，当前不设默认阈值。
