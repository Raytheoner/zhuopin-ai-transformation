# SC4首期条款证据mock对照目录

日期：2026-10-04；关联 #467、SC4 待确认完整意图。仅文档准备，未生成产品 fixture、未运行产品测试。六项全部为合成供应商采购合同，无真实 OEM 或供应商数据。

## 对照材料合同

后续每项须带 mock 合同 ID、供应商代号、文本版本与原文 hash、显式词表 ID／版本、原文区间、显示文本处理方式、提取状态与人工复核人。当前模型缺少其中部分字段，先在准备材料中列明，运行时如何承载待技术设计审；不能说已有接口已支持。

| 用例 | 合成输入形态 | 对照重点 | 专业边界与当前事实 |
|---|---|---|---|
| SC4-M01 | 纯文本与合成 DOCX 各含四个可靠编号标题，对应价格／交付／质保／违约责任 | 共享 DOCX 取文与既有纯文本对照、每段来源、顺序、词表 ID 与原文位置 | 现有共享 DOCX 门面可供未来适配；SC4 尚未接入。只核 mock 定位，不判条款合法、充分或风险 |
| SC4-M02 | 一段编号条款的标题同时出现两类词 | 保留该段，显示多类证据与未归类状态 | 当前词表实现多命中返回 OTHER；真实归属由专业确认 |
| SC4-M03 | 一段编号条款标题不命中四类 mock 词 | 未归类段不丢失，人工可看到原文 | 不能把未归类当无风险，不能据四类补集判缺失 |
| SC4-M04 | 同一 mock 文本的无标题版与正文含引用“第三条”版 | 结构证据不足与命中位置；不臆造条款 | 现有正则只认行首，无标题返回空；空输出不是已完成审核 |
| SC4-M05 | 可靠标题前有缩进，段尾有空行／空格 | raw 区间与显示文本逐格核对 | 当前 text 调用 strip，截取原文是否等于显示文本需明确契约；源码观察，未跑新断言 |
| SC4-M06 | 同合同 ID／同四类与数量，但两版本条款正文不同 | 两份原文版本与证据必须可分辨；旧结果指向旧资料 | 当前 audit hash 是覆盖概览，不能用它证明原文未变；审计参数也可为空。未来 design 决定必需审计与版本证据承载 |

## 核对方式

人工逐项核“原文资料与版本 → 取文／切段状态 → 原文位置 → 显示文本 → 定位类别 → 未归类理由 → 审计与人工确认”。审核三能力始终保持前置闸。专业 SC4-G-01～05 没有签认前，不加入模拟法务标准、风险级别或必备清单的自动预期。

未来只有完整意图确认、技术 design 审和正式建造闸通过后，才把适用技术合同转成具体 fixture、测试和实现任务，并把已有共享 DOCX 接口接到 SC4。真实 PDF/Word、SRM 文档库、真实审核、自然语言检索、生产路由与 FI2/FI3 联动均需其实际前置与阶段批准；本目录未启用其中任何能力。

旧包 tasks 第 2 组整体前置保持；本目录不据共享解析器已经存在解锁第 3 组。纯 mock DOCX 适配能否拆为独立窄片由实际 design 审裁定。
