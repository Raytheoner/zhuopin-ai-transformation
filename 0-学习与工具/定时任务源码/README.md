# 定时任务 prompt 源码镜像

## 🔴 一句话：**真身不在这里，改这里不生效**

| | 位置 | 性质 |
|---|---|---|
| **真身（Claude 实际执行的）** | `C:\Users\Paul Shao\Claude\Scheduled\<taskId>\SKILL.md` | **仓库外、不入 git**、无版本历史 |
| **本目录** | `0-学习与工具/定时任务源码/<taskId>.SKILL.md` | **单向镜像**（真身 → 仓库），只为版本保护与可 diff |

**方向是单向的：真身 → 镜像。** 编辑本目录里的文件**不会**改变任何定时任务的行为——这与"机器人跑 `ops/wecom-service-home` 而非 master"（见 `专线opener模板库.md` §〇.1）是**同一类陷阱的镜像形态**，请勿踩反方向。

## 为什么需要它

`Claude\Scheduled\*\SKILL.md` 是四条自动化机制中**两条的全部实现**（值周巡检、拆件巡逻），承载着大量来之不易的判据与教训——例如拆件巡逻 prompt 里的「三条硬约束」全部是巡逻自身实践挖出来的、「三.5 写回前重读比对合并」是 2026-07-30 队列 #168 的临时止血。**这些文件此前没有任何版本保护**：改错了无法 diff、无法回滚，误删即永久丢失，且两桌任何 session 都看不到它们的历史。

对比：已安装 skill 早已有同类保护（`0-学习与工具/skills源码/`，2026-07-10 建立，理由同为"防 Cowork 记忆丢失"）——**本目录是把同一个做法补到定时任务上**。

## 改 prompt 的正确流程（四步，勿跳）

1. **改真身**：用 `update_scheduled_task` 工具改（`Claude\Scheduled\` 下的文件对 Claude 的文件工具是只读的，直接 Write 会被拒）。
2. **回归自检**：改完逐条核对**原有关键纪律是否仍在**——`update_scheduled_task` 是**整段替换 prompt**，不是局部编辑，很容易在重写时丢掉旧条款。至少核对：红线段、编号纪律、批次纪律、状态列禁带 ✅、报告要求。
3. **回镜到本目录**：把改后的真身复制成 `<taskId>.SKILL.md`，**核对哈希一致**。
4. **登 §二 批次 + 触发 sweep**（协议〇.8 批次即扫），使改动进入 git 历史。

> **⚠️ 目前第 3 步靠人记得**——自动化已登记为队列待领行（见下）。在自动化落地前，**任何改定时任务 prompt 的 session 都必须自己回镜**。
