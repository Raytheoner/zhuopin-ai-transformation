## 一、Git 日常速查（带本项目实例）

**心智模型（记住这张图就够用）**：
```
工作区(你改的文件) --add--> 暂存区 --commit--> 本地仓库 --push--> GitHub(远端)
分支 = 平行宇宙；PR = "把我这个宇宙合进 master" 的申请
```

**每天用的 8 条**：
| 命令 | 干嘛 | 本项目场景 |
|------|------|-----------|
| `git status` | 看改了啥、在哪个分支 | 动手前先扫一眼 |
| `git branch --show-current` | 我在哪个分支 | 确认在 feat/xxx 不在 master |
| `git checkout feat/xxx` | 切分支 | 切到 SC8 分支 |
| `git diff` | 看具体改了哪几行 | commit 前自检 |
| `git add 文件` / `git add -A` | 放进暂存区 | 只 add 你要提交的（别盲目 -A） |
| `git commit -m "信息"` | 存一个本地存档点 | `feat(SC8): ...` |
| `git push` | 推到 GitHub 备份 | 收工前必做 |
| `git log --oneline -5` | 看最近提交链 | 确认历史对不对 |

**分支工作流（我们一直在用的）**：`feat/xxx 分支 → 改 → commit → push → 开 PR → 合 master`。一个变更一个分支，别在 master 上直接堆。

**看懂 PR diff**：`+绿色`=新增行、`-红色`=删除行；先看"改了哪些文件、几行"，大改动重点看核心文件。

**4 条救命**：
- 改乱了还没 commit → `git checkout -- 文件`（还原到上次提交）。
- 手头活想先放一放切别的 → `git stash`（藏起来）/ `git stash pop`（取回）。
- commit 信息写错 → `git commit --amend`（还没 push 时）。
- 切错/拉错分支 → `git checkout 对的分支`。

> **练习①（纯练手，可丢弃）**：在 `feat/platform-hardening-p2` 分支，改 README 一行 → `git status` 看 → `git diff` 看 → `git add` → `git commit` → `git push` → 在界面点开看 PR diff。做完你对"工作区→暂存→提交→推→PR"这条链就有手感了。

## 二、开发环境避坑（吃过的亏，记下来）

- **代码住纯本地**：放 `C:\dev\` 这类本地路径，**别放 OneDrive/Dropbox**——云同步会动 `.git`、造成状态错乱和文件锁（我们这次踩的就是这个）。
- **备份靠 GitHub，不靠 OneDrive**：git push 上去就安全了，OneDrive 对代码项目是冗余且有害的。
- **文件被锁**：Word/编辑器打开文件会锁它，写入失败先关掉再写。
- **两个"视图"别混**：Cowork 沙箱看到的文件镜像会滞后，**git 一律在真机 / Claude Code 终端跑**，别从 Cowork 沙箱跑。

> **练习②**：在真机 `git status` 看一次当前状态——回想之前 Cowork 沙箱报的"假 68 改动"，体会"凡 git，以真机为准"。

## 三、如何审 AI 产出（最值钱的一节，把你从"批准者"升级成"把关人"）

**审 design（技术方案）**：每个决策问三句——
1. 为什么这样做？
2. 有没有更简单的做法？
3. 漏了什么依赖 / 边界 / 风险？

标 ⭐ 的（影响算法正确性 / 合规）重点盯。你已经在用 OpenSpec 的"审 design 门禁"，这是关键习惯，保持。

**审测试报告**：核心不是看"全绿"，是看**"该测的场景测全了没"**。一张检查法：
- 正常路径测了吗？**边界 / 异常**测了吗？
- **安全 / 合规场景**（拦截、幂等、审计留痕）——每条有**独立**用例吗？
- 确定性逻辑有"**和手工基准零偏差**"的对照吗？

**红旗**（看到要追问）：只测 happy path、没有失败 / 拦截用例、覆盖率数字漂亮但关键场景空、一个用例塞太多断言看不清测了啥。

> **练习③（贴着 SC8）**：打开 SC8 那 20 个测试的用例名，对照《SC8 上线前置门禁》6 条，自己判一遍"覆盖全没、有没有漏的安全场景"——再跟我对答案，看你判断准不准。这个练熟，你就能独立守门禁了。

## 四、给 AI 下指令的小功（你已经很强，锦上添花）

- **好指令三件套**：角色 + 明确任务边界 + 红线 / 验收标准。
- 三句"防跑偏"咒语：**"先读上下文再动手"**、**"先写测试再实现"**、**"完成后停下报结果"**。
- 复杂任务让它**先出方案（design）停下等你审**，再实现——这就是我们一直走的 OpenSpec 节奏。
