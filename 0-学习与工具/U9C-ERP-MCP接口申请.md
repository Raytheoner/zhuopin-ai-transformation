## 一、申请背景与目的

公司 AI 转型已进入数字员工落地阶段。采购部 SC1（供应商风险初筛）已完成并基于携客云 SRM 数据上线。下一批场景需要从 **U9C ERP** 读取采购与财务数据：

| 依赖本接口的场景 | 模块 | 计划上线 | 接口不通的后果 |
|----------------|------|---------|--------------|
| SC2 采购周报自动生成 | 采购 | 9 月试点 | 周报数据为空，场景失效 |
| SC3 供应商绩效看板 | 采购 | 9 月 | 缺采购/质检数据，无法聚合 |
| FI1 供应链自动仓库对账 | 财务/存货 | 9 月 | 无 BOM 用量与出入库数据，无法对账 |
| FI2 智能月结加速 | 财务 | 11 月 | 无凭证/单据数据，差异匹配无从做起 |
| SC6/SC7、FI3-FI6 | 采购/财务 | 10 月起 | 后续连锁依赖 |

**目的**：为 AI 数字员工开通一条**只读、最小权限、可审计**的 U9C 数据通道，封装为内部 MCP（Model Context Protocol）服务，供各场景统一调用。

## 二、申请事项（请 IT 评估并选定接入方式）

申请对 U9C ERP 以下数据对象的**只读**访问。优先采用官方 API，DB 只读账号为备选：

**方式 A（推荐）：用友开放平台 / U9C OpenAPI**
- 由 IT 在用友开放平台为本项目创建应用，授予下列数据对象的只读 API 权限。
- 优点：官方支持、权限粒度可控、不直连生产库、升级兼容性好。

**方式 B（备选）：数据库只读账号**
- 由 DBA 创建一个 **只读（SELECT-only）** 账号，限定到相关视图/表，最好指向**只读副本/镜像库**而非生产主库。
- 优点：上线快；缺点：与底层表结构耦合，需 DBA 维护视图。

> 请 IT 根据 U9C 当前版本与运维现状，在 A / B 中选定一种；两种都需满足第四节的安全要求。

### 所需数据对象（按业务口径，具体表/接口由 IT 映射）

**采购模块（SC2/SC3/SC6/SC7）**
- 供应商主数据（编码、名称、分类、状态）
- 采购订单 PO（下达、价格、数量、交期）
- 到货 / 收货记录
- 采购入库与质检（IQC）关联单据

**财务 / 存货模块（FI1/FI2 及后续）**
- 存货出入库流水、报废记录、BOM 理论用量
- 应付 / 应收明细、采购发票与付款凭证
- 总账凭证与科目余额、月结状态
- 银行流水（如 U9C 内有）

**项目成本模块（FI7，2027-Q1，本次可先登记不开通）**
- 研发项目成本归集（材料 / 人工 / 制造费用）

## 三、接入方式与技术对接

```
U9C ERP ──(只读 API / 只读DB账号)──> U9C-MCP Server(只读封装)
                                          │
                                          └─> 数字员工场景（SC2/FI1/…）按需调用
```

- AIOps 侧将开发 **U9C-MCP Server v0.1**，仅暴露只读查询能力，封装在 `zhuopin_platform/shared_tools/u9c_connector`。
- 所有调用经平台审计层留痕（IATF 可追溯），原始红色数据不在 AI 侧落盘。
- 需要 IT 提供：接口/账号凭证、测试环境连通、数据字典（字段口径说明）。

---

## 四、安全与合规要求（请 IT 一并确认）

1. **只读最小权限**：仅授予本申请列明对象的 SELECT/读取权限，不涉及任何写操作。
2. **数据不出境 / 不出内网**：数据通道限内网；AI 推理侧只接收结构化结果，不外传原始库数据。
3. **审计留痕**：每次数据访问与 AI 决策均写入审计日志（append-only，保留 3 年）。
4. **敏感数据脱敏**：财务红色数据（如具体金额）按需脱敏或仅传聚合结果。
5. **凭证管理**：API Key / DB 账号由 IT 保管并定期轮换，AIOps 通过受控配置使用。
6. **可回收**：接口权限可随时由 IT 单方收回，不影响 U9C 生产系统稳定性。
