## 二、SuperPowers 插件（项目强依赖）

### 为什么是强依赖

本项目"先写测试再实现"的工程纪律来源于 SuperPowers 插件的 `test-driven-development` 技能。SuperPowers 还提供 `writing-plans`、`subagent-driven-development`、`requesting-code-review`、`executing-plans`、`dispatching-parallel-agents` 等技能，是 OpenSpec apply 阶段 CC 高质量交付的执行框架。

**如果没有安装 SuperPowers，"先测试再实现"这条纪律会在换机器/新人 clone 后无声消失。**

### 安装方法

在 Claude Code 交互式 session 中运行：

```
/plugin install superpowers@claude-plugins-official
```

或从 CLI：

```bash
claude plugin install superpowers@claude-plugins-official
```

安装后重启 Claude Code 会话即可。

> **注意**：`superpowers` 在 `claude-plugins-official` 市场（`anthropics/claude-plugins-official`），已在 `.claude/settings.json` 中声明。团队成员 clone 后 Claude Code 会主动提示安装，但**仍需手动确认一次**，不会自动拉起。

### 验证安装

在 Claude Code session 中输入 `/test-driven-development`，能正常展开则安装成功。

### 版本核实方法（2026-07-05 巡检结论）

SuperPowers 的 GitHub Releases 页**不可靠**——v6.x 起作者只打 git tag、不发布 Release 页（Releases 页长期停留在 v5.1.0）。核实最新版本用：

```bash
git ls-remote --tags https://github.com/obra/superpowers.git
```

变更内容看仓库内 `RELEASE-NOTES.md`（对应 tag 版本），不要信搜索引擎摘要。当前已知最新：v6.1.1（2026-07-02）。

### 本项目依赖的具体技能

| 技能 | 用途 |
|------|------|
| `test-driven-development` | 先写测试再实现（核心纪律） |
| `writing-plans` | OpenSpec propose 阶段写 design.md |
| `executing-plans` | OpenSpec apply 阶段按 tasks 逐步执行 |
| `subagent-driven-development` | 复杂任务拆分为并行子代理 |
| `requesting-code-review` | PR 合并前质量审查 |
| `dispatching-parallel-agents` | 多场景并行建造 |

## 三、项目域插件声明（`.claude/settings.json`）

本文件声明了项目域所需的插件市场和插件，使 Claude Code 在信任本工作区后自动提示安装 SuperPowers。

文件路径：`企业AI转型/.claude/settings.json`

**标准内容（禁止 AI 直接写入，由人工创建）**：

```json
{
  "extraKnownMarketplaces": {
    "claude-plugins-official": {
      "source": {
        "source": "github",
        "repo": "anthropics/claude-plugins-official"
      }
    }
  },
  "enabledPlugins": {
    "superpowers@claude-plugins-official": true
  }
}
```

**首次 clone 后手动创建**（PowerShell，在项目根目录执行）：

```powershell
$content = @'
{
  "extraKnownMarketplaces": {
    "claude-plugins-official": {
      "source": {
        "source": "github",
        "repo": "anthropics/claude-plugins-official"
      }
    }
  },
  "enabledPlugins": {
    "superpowers@claude-plugins-official": true
  }
}
'@
$content | Set-Content -Path ".claude\settings.json" -Encoding UTF8
```

> `pretooluse-guard.ps1` 将 `*/.claude/settings.json` 列为受控文件（安全/审计配置禁止 AI 直接修改），因此该文件**不进 git**，依靠本文档说明和手动创建。

## 四、OpenSpec 工作区（已在 git）

OpenSpec 的 CLI（全局 npm 安装）生成项目数据，这些数据**进 git 版本控制**：

```
openspec/
├── changes/          # 活动变更包（开发中或未归档）
│   ├── fix-a-*/      # 安全整改
│   ├── fix-b-*/      # 数据正确性整改
│   ├── fix-c-*/      # SC8 上线前置
│   ├── qd-b-*/       # QD-B 立项门禁（进行中）
│   └── archive/      # 已归档的完工变更包
└── specs/            # 活规格库（已归档变更的 spec delta）
```

常用命令（在项目根目录执行）：

```bash
openspec list          # 查看当前活动变更
openspec status        # 查看指定变更进度
openspec validate      # 校验 specs/ 一致性
```
