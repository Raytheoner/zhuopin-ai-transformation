## 六、Phase 1 修正与补强（2026-06-07 VP 确认）

新一轮"基础设施与智能体构建"指令已并入本计划，架构方向与全景规划一致。确认结论：

1. **Phase 1 范围** = 平台底座 + SC1 正式上线 + 解依赖。指令点名的 SC6/Q1/Q6/FI1/FI2 五场景均被硬依赖阻塞（U9C MCP / 外部 API / 知识库未就绪），Phase 1 先做原型，数据闸门打开再真上线；**Q6 维持 2027-03 后置**（依赖质量 Champion 黄金标准库）。
2. **平台底座** `5-平台底座/zhuopin_platform`：可安装 Python 包，承载 audit / data_isolation_layer / shared_tools / agents，解决 SC1 跨工程引用老痛点。
3. **审计**：JSONL 先行，9 月迁 ClickHouse（同接口可双写灰度切换）。
4. **OEM 隔离**：`data_isolation_layer` 代码闸门，跨客户/未注册访问直接拒绝并审计。
5. **Q6 的"训练"** 实为 RAG 检索 + 规则引擎 + few-shot（可追溯，满足 IATF），非微调。
6. **补强项**：统一 doc_parser 共享服务（7月）、知识库前置任务（提前 6 周派发）、错误处理/回滚 SOP（每场景上线前）、S3 增 NRE 报价子场景、评估新增 APQP 阶段评审助手、11月场景砍至 4-5 个。
7. **定位**：维持 **Tier 1**（直供 OEM）。

## 七、supplychain 收割与场景重排（2026-06-08 VP 确认）

盘点发现 **supplychain 试点已用真实数据验证了采购线大半 + 运营两个场景 + 销售交付通报的核心引擎**，需收割进全景并重排。方针 = **收割，不整体并入**（完整策略与三张映射表见《supplychain收割与全景推进策略.md》）。

**工具分工**：Claude Code Desktop = 建造车间（连真实库、跑数据、写代码，全景开发主战场）；Cowork = 规划治理桌；共用同一 `企业AI转型` git 仓库。

**已验证可收割（supplychain → 全景场景）**：

1. 连接器 → 平台底座 `shared_tools`：`xky_srm_connector`（SRM 承诺交期）、`zp_connector`（真实 ERP，2.4万 PO）、`crm_notifier`+`wecom`（CRM/企微通报）、`u9c_connector`（骨架）、DataConnector 抽象——**替换我先前搭的 stub**。
2. 智能体 → 对应数字员工：`delivery_forecast`→**SC8**、`supplier_tracking`→SC3、`purchase_recommendation`→SC5、`kit_analysis`→O2、`smt_scheduling`→O1、`srm_risk_monitor`→SC1/SC6、`business_rules`→SC5规则。

**重排结论**：
- **SC8 客户订单交期智能承诺：2027-02 → 2026-07/08 MVP**（核心目标、已实现、不依赖 SC6/SC7）。
- SC3/SC5/O1/O2 提前到 9 月（引擎已就绪，收割落位）。
- SC2/SC4/SC6/SC7/SC9 维持原计划（supplychain 未覆盖）。

**收割时必补三块**（supplychain 没有、全景合规要求）：① IATF 统一审计；② OEM 数据隔离；③ 交付预测推客户前的人工确认门禁（L2，置信度阈值）。
