# 质量域 AI 对接人 · 首月任务单 —— 陈忱

> **定位**：陈忱，你是**质量域 AI 对接人 + 前置数据负责人**——从你最懂的质量业务和数据就绪切入，边干边学 Claude Code，不急着写生产代码。你做的这几件正是质量旗舰（8D / 立项门禁）能否按期上线的**真瓶颈**。

## 本月任务（业务为主，都用现成材料）

### 1. 牵头 8D 历史库归集 + 脱敏　🔴 旗舰① 硬前提
- **做什么**：收集近 2-3 年**已结案、根因验证有效**的 8D 报告，按脱敏规则处理后，结构化填入《8D历史库录入表》。
- **材料**：《质量旗舰开工就绪包》§1 + `1-转型规划/质量旗舰-8D历史库录入表.xlsx`（含字段、填写说明、示例）。
- **脱敏**：客户名令牌化（比亚迪/上汽/理想→OEM-A/B/C）+ 技术实体屏蔽（专属芯片/线别/车型代码模糊化）；**OEM 令牌映射表你本地加密保管、不进库**。
- **验收**：首批 30-50 份完成结构化+脱敏，覆盖四类不良（设计/制程/物料/使用不当）、含 ≥1 个安全相关；只收"根因验证有效"的。
- **周期**：约 6-8 周（8 月底前完成，9 月底为最晚）。

### 2. 选黄金基准样本　🟡 上线校验用
- **做什么**：从历史 8D 里挑 5-10 份作"黄金基准"（AI 上线前重跑、与你当年结论对比）。
- **验收**：覆盖四类 + 含安全相关；标注清楚，存入约定目录。
- 这是纯质量判断活，正中你长处。

### 3. 用质量视角校准旗舰方案　🟡 把业务需求讲清
- **做什么**：以质量工程师视角审《质量旗舰PRD-Q2-8D》和《立项门禁机器可核规则表(38条)》，反馈：AI 该核什么、根因分类对不对、门禁阈值合不合质量实操。
- **验收**：一份书面反馈（哪些规则/阈值要改、为什么），交 Paul + AIOps 1 号。
- 你比纯开发更懂"业务上到底要什么"——这步价值最高。

### 4. Claude Code 轻上手　⚪ 慢慢学，不急
- **做什么**：跟 AIOps 1 号学：读 CLAUDE.md（§7 红线）、装环境、用录入表、看懂工作流；**先不写生产代码**。
- **验收**：能独立用录入表、看懂"场景→平台底座"结构；手熟后再接"8D 录入校验脚本"这类小代码活过渡。

## 红线（你经手客户数据，必须守）
- 8D/客诉**先脱敏再进任何环境**；OEM 令牌映射表质量部（你）单独保管、不进库、不外发。
- 涉安全相关（ASIL）的 8D，根因/对策走功能安全工程师额外审核（ISO 26262 规范）。

## 30 天成功标尺
首批 8D 历史库归集脱敏过半、黄金基准样本选定、旗舰方案业务反馈交付、Claude Code 基本上手。

## 本月**不**做（避免踩坑）
写场景生产代码、doc_parser、连真实库——等 Claude Code 熟了 + 数据就绪（8-9 月）再上。
