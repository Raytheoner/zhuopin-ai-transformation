# AIOps 工程师（第 2 名）招聘工具包

> 配套《AIOps工程师（第2名）岗位说明书》。本岗为 P0，目标 7 月到位。下含两部分：**结构化面试打分卡**（外部/内部统一评估）、**内部转岗动员话术**（优先从 IT 内部物色）。

## 第一部分 · 结构化面试打分卡

**评分锚点（每维 1-5 分）**：1=明显不符 / 2=偏弱 / 3=达标 / 4=良好 / 5=优秀。
**建议权重**：核心是"能不能上手把数字员工建出来、稳定跑起来"，故工程能力与集成经验权重最高。

| # | 评估维度 | 权重 | 重点考察 | 1-3 分典型表现 | 4-5 分典型表现 | 得分 |
|---|---------|------|---------|--------------|--------------|------|
| 1 | Python 工程能力 | 20% | 模块化、单测、Git 协作 | 只会写脚本，无测试/版本习惯 | 能独立搭工程、写测试、讲清取舍 | |
| 2 | API/系统集成 | 20% | REST/OpenAPI、ERP/DB 取数、只读最小权限 | 仅调过简单接口，无权限/凭证意识 | 对接过 ERP/数据库，懂只读/脱敏/凭证管理 | |
| 3 | AI/Agent 开发（加分） | 15% | LLM API、RAG、MCP、Prompt | 没接触过，但愿意学 | 做过 RAG/Agent/MCP，能讲清适用边界 | |
| 4 | 运维与可观测 | 15% | 监控/日志/告警、上线后负责 | 只管写完，不管上线后 | 建过看板、处理过线上问题与回滚 | |
| 5 | 业务沟通与对接 | 15% | 跟非技术同事把需求说清 | 只谈技术，不接业务 | 能把模糊需求落成可交付方案 | |
| 6 | 合规与严谨意识 | 10% | 可追溯、数据隔离、IATF/汽车行业 | 不在意留痕与边界 | 主动谈审计/隔离/回滚，理解汽车行业底线 | |
| 7 | 学习力与主动性 | 5% | 自学新栈、独立排障 | 依赖手把手 | 能自学 Claude Code/SuperPowers 并产出 | |

**加权总分 = Σ(维度分 × 权重)**　建议线：≥4.0 强烈推荐 / 3.5-3.9 推荐 / 3.0-3.4 待定（看培养意愿）/ <3.0 不推荐。

### 行为面试题（STAR，按维度问）

1. **工程能力**：讲一个你从零搭起、现在还有人用的 Python 项目——目录怎么分层？测试怎么写的？后来谁来维护？
2. **集成**：你对接过的最复杂的一个外部系统/数据库是什么？怎么保证只读、不影响生产、凭证不泄露？遇到过什么坑？
3. **AI（加分）**：如果让你把"采购周报"做成一个能自动取数、生成、留痕的工具，你会怎么拆？哪些用规则、哪些用大模型、为什么？
4. **运维**：你负责的系统出过线上故障吗？怎么发现、怎么回滚、怎么避免再犯？
5. **业务沟通**：举一个你把业务同事说不清的需求，落成可交付方案的例子。
6. **合规**：汽车行业要求每个 AI 决策可追溯、不同客户数据严格隔离——如果让你设计，你会怎么保证"不串库"和"留痕可查"？
7. **学习力**：上一次你自学一个全新技术栈并真正用起来，是什么？花了多久？

### 现场小任务（可选，30 分钟）
给一段读取某 API 返回 JSON、做简单聚合并写一条带时间戳/来源的日志记录的需求，观察：是否写测试、是否考虑异常/空数据、是否考虑只读与敏感字段、代码可读性。

### 录用红旗 / 加分旗
- 🚩红旗：只谈"调通就行"不谈稳定性；对数据权限/留痕无感；不愿与业务打交道；夸大但讲不出细节。
- ⭐加分：用过 Claude/DeepSeek/RAG/MCP；熟用友 U9C/制造业 ERP；了解 IATF/ISO26262/APQP/PPAP；有 Tier 1/2 经历。

## 第二部分 · 内部转岗动员话术

> 优先从 IT 内部物色——熟悉公司系统和数据、信任成本低、上手快。以下话术供你（VP）或 IT 负责人一对一沟通时参考，按对象调整。

### 一句话定位
"公司在做 AI 转型，要把各部门的重复工作做成‘数字员工’。我们需要一个懂技术、又愿意跟业务打交道的人来牵头建设和运维——这是个能站上 AI 浪潮、对个人发展很值的机会。"

### 对"技术骨干"型（懂开发/集成，犹豫要不要转）
- **成长**：这是公司未来 3 年的战略方向，你会第一批掌握 Claude Code / MCP / RAG 这套 AI 工程能力，稀缺且值钱。
- **价值**：不是打杂，是从 0 建平台底座、定标准，你的代码会被六个部门复用。
- **支持**：有成体系的工作流（OpenSpec/SuperPowers）和已跑通的 SC1 做样板，不是从空白起步；VP 直接关注、资源到位。
- **务实**：专项奖金 + 外部培训预算；按全景规划，AIOps 是晋升与 AI CoE 的核心梯队。

### 对"业务系统运维"型（熟 U9C/数据，开发偏弱）
- 你最懂公司的数据和系统，这正是数字员工落地最难的部分——接口、数据口径、只读权限你比谁都清楚。
- 开发侧有 AI 辅助工作流和同事配合，你的"业务+数据"底子是别人补不上的优势。
- 这条路能让你从"维护系统"升级为"用 AI 重塑流程"，职业天花板完全不同。

### 常见顾虑与回应
| 顾虑 | 回应 |
|------|------|
| "我不懂 AI / 大模型" | 不要求精通。会 Python + 懂系统集成 + 愿意学就够；我们有工作流和样板带你上手，30/60/90 天有清晰路径。 |
| "转岗有风险，做不好怎么办" | 这是公司战略 P0 岗，VP 直接背书；前 90 天目标是‘跟做 + 独立交付 1 个场景’，循序渐进，不是一上来背全部。 |
| "现在的活谁接" | 转岗前会安排交接期；这是组织层面统筹的事，不让你个人扛。 |
| "会不会就是加班建系统" | KPI 不以‘节省工时’压人；按全景规划红线，AI 使用与部门绩效挂钩，不搞形式主义。 |

### 给候选人的"成功画面"（30/60/90）
- 30 天：上手工作流 + 跟做 SC1 上线 + 联调 U9C 只读连接器。
- 60 天：独立交付 1 个数字员工（如 SC2 / FI1），通过真实数据验证。
- 90 天：稳定运行 2-3 个场景、可用率 ≥95%，成为一个新部门的 AI 对接人。
