## 一、命名与编号

- **文件名**：`部门-姓名-跟进-YYYY-MM-DD-主要事项.md`；未实名前用角色代称，实名后新信用真名，**已发旧信不改名**。
- **输出格式**：每封信**同时出 `.md` ＋ `.docx`**（md2word 生成）。🔴 **2026-08-20 起 docx 为必发项，不存在「可不附」的情形**——判据不是「这封信有没有勾选项」，而是「**有没有 docx**」（纯文本信 AI 不好编辑回复）。⚠️ 存量不追补：`IT部#9`／`质量部#6` 缺 docx 是**已拍板的现状、不是漏检的违规**，后续 session 不要顺手补。
- **落款**：一律 `—— OPVP Shao Peishen`，不用 `—— Paul`；已发出的不追改。
- **编号**：每封**已发出**的信在 README 表「编号」列标 `部门#N`，按该部门实际发送时间连续递增、跨收信人共用计数器；**未发出／待发／已作废的不占号**。文件名不追改，编号只进 README 表与正文抬头。
- 🔴 **取号唯一入口＝`python 0-学习与工具/工具-跟进闸查询.py --to <收信人>` 的「下一个可用号」**——它只按表内实际 `#N` 最大值推算、不看是否已发出、不受括注影响。**任何写在自由文本里的「下一个可用号」都只是人读摘要，一律以该工具输出为准**（同族失真已复发 6 次：本段与表列是同一事实的两份副本，会互相印证着一起错）。

## 二、发送状态八态与闭环判据

- **README 表「发送状态」列 ＝ 一封信状态的唯一权威源**（Shao Peishen 2026-08-21 定，两桌全局）。🔴 **跨桌任务队列不是信状态的载体**：队列里「等某某#N 闭环／串行闸锁着」这类复述一律是会过时的快照，**不得作为判据**，队列只允许写指针。
- **八态**：`⏳ 待你审`（草稿态，**唯一合法的起草产物**，不得在新增行的同一次编辑里直接写终态）／`🆕 待发`（终态，**仅能经批准脚本**从 `⏳ 待你审` 转换而来，不得手工改写）／`⏸ 暂缓`（已批准但主动暂缓，**只能从 `🆕 待发` 手工改写**，先占编辑锁；派发班次单独识别记 `dispatch_skipped_paused`）／`✅ 已推送 <UTC 时刻>`／`📥 已回件并回灌 <日期>`／`✅ 无需回复`／`📨 已确认闭环 <日期>`／`❌ 已作废`。
- 🔴 **闭环三态（`❌ 已作废` 另计）**：`📥 已回件并回灌`（对方正式回件、我方已消化）／`✅ 无需回复`（信件本身明示不要求对方任何动作，**发出即闭环、从不占串行闸**）／`📨 已确认闭环`（对方以其它形态响应＋**我方已明确回复确认**，以我方确认那一刻为闭环时点）。🔑 **判据要问的只有一个问题：这封信现在还要不要收信人做事？** 不要，就是闭环。
- 🔴 **防滥用硬约束（缺了它这套就废）**：`✅ 无需回复` **只能在起草时判定并写进信件正文**（正文须含「不用回」类明示字样），**一律不得事后追认**；`📨 已确认闭环` 必须能指出两样东西——对方响应的落档件（`7-外部文档/…`）＋ 我方确认的原话，缺一不得转态。
- ⚠️ **机制侧只跟到一半**：`工具-共享文档编辑锁.py::_validate_followup_readme_release` **仍只认 `📥` 前缀**，新增两态在代码落地前不解锁 release 门禁；过渡期确需起草时走逃生阀 `串行豁免：〈理由〉`。代码同步须走 openspec（改既有模块对外语义）。
- ⚠️ **配套义务**：回件消化完必须**手工**把该行由 `✅ 已推送` 改为 `📥 已回件并回灌 <日期>`（先占编辑锁），否则下一封被无限期挡住。**2026-08-08 之前发出的历史行沿用旧口径、不追改**。

## 三、跟进信串行原则（优先于并节制一切触发规则）

- 🔴 **同一收信人同时只能有一封在途跟进信。** 下一封的起草前提是前一封**已收到回件且回灌消化完毕**。**编号仍按部门连续编号。**
- **判据**：该收信人**最近一封**的发送状态是闭环三态或 `❌ 已作废` ⇒ 放行；其余四态（`⏳ 待你审`／`🆕 待发`／`⏸ 暂缓`／`✅ 已推送`）一律视为在途，**不得起草下一封**。
- 🛡 **已机制化**：编辑锁 `release` 在本次持锁窗口内新增某收信人登记行时自动回查前一封是否闭环，非闭环即拒绝释放；逃生阀 `串行豁免：〈理由〉` 写在新增行内（既有行状态转换不受约束、历史行不追溯）。🔑 **但串行闸永远不会自己开**——机器只写队列、闸只读 README 表，中间那一步一直是人（§一 `#366`）。
- **它节制「场景发布自动起草跟进信」**：发布收口触发起草，但该专员手上仍有未回灌的在途信时**不得发出**，改为在队列登记「待前信闭环后发」并写明拟发要点。
- **第 8 步（先查闸）的裁决**：两条上位规则曾在「起草」这个动作上正面对撞——机器闸站在串行原则一边（闸锁时加新行会被 `release` 拒绝，除非编一条 `串行豁免：`，**那等于拿逃生阀去绕它本来要拦的那件事**）。⚠️ **也不得退到「起草但不登记 README」**——写好的信会被后来的 session 当成「可以发了」。

## 四、起草 → 批准 → 发送

1. **起草前先占本文件所在 README 的编辑锁**（否则结构性拦截不触发；改到／恢复出 `⏸ 暂缓` 同样须先占）：`python 0-学习与工具/工具-共享文档编辑锁.py acquire --file "6-人才与组织/部门AI专员跟进/README-跟进机制与命名约定.md" --who "<身份>" --note "起草跟进信"`，新增行状态列写 `⏳ 待你审`，**改完立刻 release**。
2. 🔴 **起草期代词自检（转 docx 之前）**：全文搜「他／她／他的／她的」，**逐个回 `6-人才与组织/人员名录-称谓与性别-正本.md` 核对**并写明各自指谁、依据名录哪一行；**名录里没有这个人 ⇒ 改中性表述（「该同事／其」），不许二选一**。🔑 **本条不是一条规则，是一个动作**——规则活在「知道」里没用，得活在起草流程里必然执行的检查步骤里。
3. **批准（草稿态转终态的唯一合法路径）**：`python 5-平台底座/wecom-aibot-service/scripts/approve_followup_letter.py --readme <README> --match-topic "<主要事项列唯一定位关键字>" --quote "<Shao Peishen 的放行原话>"`。🔴 `--quote` 必填（写进独立于聊天记录的审计事件 `followup_approved`）；**冷却窗口 10 分钟**——脚本第一次「看到」某行只记录观测时刻并拒绝执行，堵住「起草→release→立刻批准」这种同一 actor 的两步连做。
4. **发送**：每日批处理 `ZhuopinFollowupDispatchDaily`（工作日 09:30，本机、**不可迁 `.51`**——同 BotID 单实例约束）扫全表 `🆕 待发` 行；或人工 `push_followup_letter.py`。🔴 **未经批准脚本转态不得发送。**
5. 🔴 **发送三条硬前置**（涉已建造场景的信）：① 分支已 ff 合入 master；② `.51` 已部署且冒烟通过；③ 已用对方的原始举证端到端复现。**通知已送达而生产未更新** ＝ 同族第三次复发（#204／#221／#228），代价是直接损伤试点反馈 loop 的信任基础。
6. **`🔒人工发送` 标记**：起草时已知有硬性截止、逾期有实质后果的信，**必须**在「交期要点」列内紧跟截止时间之前标注（如 `🔒人工发送 · 2026-07-31（本周五）前`）——批处理对该标记结构性跳过，只走人工触发。🛡 **机器兜底**（不替代人工判断）：批处理扫「交期要点」列，含严格 `YYYY-MM-DD` 且距今 < 3 天而未标该标记者，视为疑似漏标、同样跳过并私信提醒。
7. **目标文件标注**：同日同收信人可能有第二封时（不确定也建议加），在「主要事项」列末尾追加 `… → 目标文件：\`部门-姓名-跟进-YYYY-MM-DD-主要事项.md\``（`readme_table.build_target_file_annotation()` 生成）；未标注的行回落旧的「收信人＋日期」判据。只在既有单元格内追加文本，不新增列。
8. 🔴 **群抄送是惯例**：发送一律带 `--department <部门>`，**不带只在他明说「这封别抄群」时**。⚠️ **该通道 fail-closed 静默跳过**——映射未配置时不报错、不打印失败，**「命令跑通了」不等于「群抄送发生了」**，必须到 `5-平台底座/wecom-aibot-service/reports/wecom_aibot_audit.jsonl` 看见 `followup_group_cc_delivered` 且 `errcode=0` 才算数。📌 另有一条自动抄送 `ShaoPeiShen`（`followup_cc_delivered`），不需传参。
9. **一句话发送路径＝skill `zhuopin-send-followup`**（Cowork 本机 PowerShell 通道跑的就是他那台机器，off-LAN 亦可）。🔴 **第一条铁律「绝不凭一句话直发」**：必须先读回「收信人＋编号＋标题＋要他办的事」等一个「发」字——**纯直通会把一封财务信发给采购部的人，且发信不可撤回**。
