## 勾选栏怎么读（先看这三行再动手）

- **✅ ＝「拟改判定这一格填的结果是对的」** —— 引擎以后就该这么判。
- **❌ ＝「拟改判定这一格填错了」** —— 引擎不该这么判，但你不必写正确答案。
- **✏️ ＝「填错了，而且我知道该怎么判」** —— 勾它并在后面写一句你认为的正确判法。

**⇒ 三个符号评的都是最右边那列「拟改判定」，不是评「现状判定」。每行只勾一个。**

## 请你批改（3 条，判例内容与原信完全一致）

**背景一句话**：我们算齐料日期时，**只看了「最早的那个答交日期」，完全没看那一笔答交了多少数量** —— 哪怕数量是 **0**，也照样拿它当齐料日。

以你举证的瓶颈物料 **`R01I.0622`** 为例，它在供应计划看板上的逐笔答交是：

| 答交日期 | 答交数量 |
|---|---|
| 2026-08-20 | **0** |
| 2026-09-20 | 0 |
| 2026-10-20 | 0 |
| 2026-11-20 | 0 |
| 2026-12-20 | 0 |
| 2027-01-20 | 0 |
| 2027-02-20 | 0 |
| **2027-05-20** | **10000** |
| 2027-06-20 | 0 |

**⇒ 真正有货的只有 2027-05-20 那一笔（10000）。而我们的程序采用的是 2026-08-20 那一笔 —— 数量为 0 的那个。**

| # | 真实场景 | 现状判定 | 拟改判定 | ✅ 这样判对 | ❌ 这样判不对 | ✏️ 应改判为（写一句） |
|---|---|---|---|---|---|---|
| **1** | `R01I.0622`：逐笔答交如上表，只有 2027-05-20 那笔有 10000 | 齐料日 ＝ **2026-08-20**（取最早日期，不问数量） | 齐料日 ＝ **按数量累计到够为止的那一笔的日期**（本例即 2027-05-20） | ☐ | ☐ | ☐ ____________ |
| **2** | 同上，若这个物料需要 6000，而 2027-05-20 那笔有 10000 | —（现状不算数量） | 齐料日 ＝ 2027-05-20（一笔就够，不用再往后累） | ☐ | ☐ | ☐ ____________ |
| **3** | 假设某物料需要 15000，答交是 2026-10-20 给 8000、2027-01-20 给 9000 | —（现状会取 2026-10-20） | 齐料日 ＝ **2027-01-20**（累计到 17000 才够 15000） | ☐ | ☐ | ☐ ____________ |
