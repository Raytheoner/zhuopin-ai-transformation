# 工程研发 AI Champion · 首月任务单 —— [姓名]

## 本月任务（业务为主，都用现成材料）

### 1. 牵头 OEM 需求文档库归集 + 脱敏 + 分客户入库　🔴 R1 硬前提
- **做什么**：选 **1 套** OEM（建议从文档最规整的客户起步）的历史软件需求文档 + 已有 ECU 规格，结构化整理，按客户隔离入库。
- **隔离红线**：不同 OEM 文档**绝不可混库**——比亚迪资料不进上汽检索结果。入库走 IT 部署的 OEM 隔离层（Chroma，见《OEM隔离层-IT推动brief》），每客户独立实例。
- **脱敏**：客户名 / 车型代码 / 专属芯片型号令牌化；映射表你本地加密保管、不进库、不外发。
- **验收**：≥1 套 OEM 需求文档分客户脱敏入库，AIOps 可向量检索到。
- **周期**：约 6-8 周（8-9 月，**9/30 最晚**，与 OEM 隔离层 Chroma 9/30 部署联动）。

### 2. 选 R1 黄金基准样本　🟡 上线校验用
- **做什么**：挑 5-10 份历史需求分析案例作"黄金基准"（R1 上线前重跑、与研发当年结论对比）。
- **验收**：覆盖典型需求类型、含 ≥1 个 ASIL 安全相关需求；标注清楚，存约定目录。

### 3. 用研发视角校准 R1 方案 + ISO 26262 边界　🟡 把业务需求讲清
- **做什么**：以软件工程师视角审 R1 场景设想，反馈：AI 该辅助分析什么、哪些**绝不能让 AI 碰**。
- **安全红线**：**ASIL C/D = AI 绝对禁区**（LLM 过不了 TCL 工具资质，不进安全证据链）；ASIL A/B 可 AI 辅助 + 资质人员签字。详见《ISO26262-AI安全使用规范（草案）》，本条须 FSE（功能安全工程师）会签。
- **验收**：一份书面反馈（R1 辅助边界 + ASIL 分级处理），交 Paul + AIOps 1 号 + FSE。

### 4. Claude Code 轻上手　⚪ 慢慢学，不急
- **做什么**：跟 AIOps 1 号学：读 CLAUDE.md（§7 红线，尤其 OEM 隔离 + ISO 26262）、装环境、看懂"场景→平台底座"结构、用入库脚本；**先不写生产代码**。
- **验收**：能独立用入库脚本、看懂工作流；手熟后接"文档入库校验脚本"这类小代码活过渡。

## 红线（你经手 OEM 技术数据，必须守）
- OEM 技术文档**先脱敏 + 分客户入库**，绝不跨库；令牌映射表你单独加密保管、不进库、不外发。
- 安全相关（ASIL）需求 / 代码：**ASIL C/D 不让 AI 参与**，A/B 须资质人员签字；走 FSE 额外审核。
