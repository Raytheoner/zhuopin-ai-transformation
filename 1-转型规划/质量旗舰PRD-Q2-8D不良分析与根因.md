# QD-A · 8D 不良分析与根因起草助手（PRD / Design）

> 审阅对象：Paul + 质量经理。本文给出问题、范围、数据依赖、合规分级、与底座衔接、成功度量，并在 §6 列出 6 个需拍板的设计决策（D1–D6，⭐ 影响合规/正确性）。沿用 SC8 design 的结构与决策粒度。
>
> **纯规划，先 mock/脱敏**：本 PRD 不写生产码、不连真实库；落地时历史 8D 库须脱敏后进开发环境。

## 1. 问题陈述

8D（8 Disciplines）是卓品响应 OEM 客诉、内部不良、供应商来料不良的标准纠正流程，也是 IATF 16949 第 10.2 条（不合格与纠正措施）的核心交付物。当前一份 8D 报告从客诉/不良立项到提交客户需 1–2 天，资深质量工程师的时间大量消耗在三件低创造性的事上：**翻历史找类似案例、整理 D1–D8 格式与中英双语文字、把零散的鱼骨图/5Why 整理成可读根因链**。高峰期 8D 积压直接拖累客户满意度与项目节点（OEM 对 8D 时效有硬性考核，常要求 24h 临时对策 + 数日内根因）。

更深的痛点是**根因质量参差**：经验依赖个人，新工程师难以复用历史教训，同类失效反复发生。AI 的价值不止是"写得快"，而是把全公司历史 8D/缺陷沉淀成可检索的知识，给出**基于证据的根因候选**，让根因准确率从依赖个人经验变为依赖组织记忆。

## 2. 目标 / 非目标

**Goals（本场景要做的）**
- 接入客诉/不良信息，自动生成 8D 报告初稿（D1 小组 → D8 关闭），D3 临时对策与 D4 根因为重点。
- 基于历史 8D 库 + 缺陷知识库做相似案例检索（RAG），给出**根因候选 + 历史对策 + 关联 FMEA 条目**供工程师参考。
- 生成客户可读的中英双语版本，按目标 OEM 的 8D 模板格式化。
- 全链写平台 `audit`：AI 草稿 → 工程师修订 → 签字定稿，可追溯（IATF 10.2/7.5）。
- 对客提交走 L2 门禁：AI 不自动发客户，质量工程师签字确认后才出（沿用 SC8 门禁）。

**Non-Goals（本期不做）**
- 不做客诉的智能分流（那是 QD-C，本场景假定不良已立项、责任域已定）。
- 不自动判定 D4 根因为"最终根因"——AI 给候选，根因确认权在工程师（L2 红线）。
- 不连真实 MES/QMS 实时数据（来料/制程数据接入随 QD-E/QD-F，本期用客诉文本 + 历史库）。
- 不自动更新 FMEA（那是 QD-H；本期只做"关联提示"，不写回 FMEA）。
- 不建对客发送通道的自动化（沿用 SC8：先内部/草稿，门禁过了才谈外发）。

## 3. 范围内的端到端流程（mock 阶段）

不良立项（客诉/内部/供应商来料）→ AI 解析失效描述、提取关键信息 → RAG 检索历史相似 8D + 缺陷库 → 生成 D1–D8 初稿（D3 临时对策、D4 根因候选含 5Why/鱼骨骨架、D5–D7 纠正与预防建议）→ 关联 FMEA/历史对策附在旁 → 质量工程师在草稿上修订 → **L2 签字定稿** → （若对客）按 OEM 模板出中英双语 → 全链审计留痕。

| 数据/依赖 | 用途 | 来源 | 状态 / 阻塞 |
|----------|------|------|------------|

| 缺陷知识库/知识图谱 | 根因候选、关联 | 待建 | 🔴 随本场景同步沉淀（先轻量，后图谱化） |

## 5. 与平台底座的衔接（复用，不重建）

**审计 `audit/`**：每次 AI 起草、每次工程师修订、最终签字各写一条 append-only 事件，更正/重出关联原记录 ID（沿用 SC8 §1.4 修订规范），满足 IATF 10.2 纠正措施可追溯。

**数据隔离 `data_isolation_layer/`**：客诉若关联具体 OEM 项目，其客诉文本、历史 8D、关联 FMEA 按客户路由检索，跨库抛 `CrossOEMAccessError`。RAG 检索库按 OEM 边界分库——**比亚迪的历史 8D 不进上汽的检索结果**。

**共享件 `shared_tools/`**：复用企微 `wecom`（积压/超时提醒）、`crm_notifier`（对客提交草稿）。新增 **`doc_parser`（8D/客诉文档结构化解析）**——这是质量域共性件，建议在本场景先本地实现，待 QD-B 立项门禁（解析立项文档）成为第 2 真实消费方时，按 **rule-of-three** 提升进 `shared_tools`（提升前查实际代码确认复用，沿用供应链纪律，不提前抽象）。

**L2 门禁（SC8 模板）**：对客 8D 退回/提交照《SC8 上线前置门禁》两道闸——① 黄金基准：取 5–10 份历史已结案 8D，让 AI 重跑，与质量工程师手工根因/对策逐项对比，确定性部分（格式/字段/双语）零偏差、根因候选命中率达约定阈值才算过；② 错误/回滚 SOP + 人工签字：AI 不自动外发，工程师签字担责。

## 6. 设计决策（✅ 2026-06-11 Paul 采纳全部推荐：D1–D6 均取"选 A"）

> **决策状态（2026-06-11）**：Paul 拍板采纳下列各项的推荐方案（选 A）。其中 **D3（ISO 26262 安全相关不良走功能安全工程师额外门禁）= 已定**，是合规硬约束。两处仍需业务输入（非选型，而是落地数据/共识）：D3 需对接卓品现有"安全相关不良"标记方式；其余按选 A 落地。质量经理共识在开发立项前补齐。

### ⭐ D1. 根因输出定位：AI 给"根因候选 + 证据 + 置信度"，不给"唯一根因"｜✅ 选 A（已定）
- **选 A（推荐）**：AI 输出 2–3 个根因候选，每个附历史证据（相似案例 ID）+ 置信度（高=多个历史强匹配 / 低=弱匹配或启发式），工程师选定/改写。对齐 L2 红线与 IATF"根因须验证"。
- 选 B：AI 直接给单一根因。否决——越权、且 8D 根因须经验证（D4→D5），AI 单判风险高。
- **理由**：A 既提效又守住"根因确认权在工程师"，置信度便于工程师分配复核精力。

### ⭐ D2. 置信度模型：二级（高/低），按"历史证据强度"判定（对齐 SC8 二级口径）｜✅ 选 A（已定）
- **选 A（推荐）**：高 = 有 ≥N 条强相似历史案例支撑且根因一致；低 = 弱匹配/无历史/纯 LLM 推断。低置信根因候选醒目标注"需重点验证"。
- 选 B：三级或 0–100 分。否决——无标注数据校准、过度设计（同 SC8 D1 结论）。
- **理由**：与 SC8/全平台置信度口径一致，可解释、可审计。

### ⭐ D3. ISO 26262 安全相关不良的特殊门禁｜✅ 选 A（已定，合规硬约束）
- **选 A（推荐）**：不良若标记为"安全相关"（涉 ASIL 等级功能、安全机制失效），AI 草稿强制走**功能安全工程师**额外审核，根因/对策 AI 产出不得直接落地（CLAUDE.md §7 第 5 条）。在审计与报告上打"安全相关"标。
- 选 B：所有 8D 同一流程。否决——违反 26262 人工审查红线。
- **需确认**：卓品当前如何标记"安全相关不良"？沿用现有 ASIL 分级标签即可挂接。

### D4. 双语与 OEM 模板：先做 1 个客户模板试点，参数化扩展｜✅ 选 A（已定）
- **选 A（推荐）**：MVP 先支持 1 个 OEM（建议客诉量最大者）的 8D 模板 + 中英双语，模板/术语表参数化；其余客户后续按同结构加配置。
- 选 B：一上来支持全部 OEM 模板。否决——差异大、收集慢，阻塞 MVP。

### D5. 知识库冷启动：随本场景从历史 8D 沉淀，先轻量检索后图谱｜✅ 选 A（已定）
- **选 A（推荐）**：MVP 用历史 8D + 缺陷库做向量检索（RAG）即可起步；缺陷知识图谱作为后续增量（QD-C/QD-H 共用时再投入）。
- 选 B：先建完整缺陷知识图谱再上线。否决——重、阻塞、ROI 滞后。

## 7. 自动化分级（L1/L2）逐环节

| 环节 | 等级 | 说明 |
|------|:---:|------|
| 失效信息解析、相似案例检索 | L1 | AI 自动，结果供参考，低风险 |
| D1–D8 初稿、根因候选 | L2 | AI 起草，工程师**必须**审核修订 |
| 安全相关不良根因/对策 | L2+ | 功能安全工程师额外审核，不得直接落地（D3） |
| 对客 8D 提交/退回 | L2 | 工程师签字确认才外发（SC8 门禁） |
| FMEA 关联 | L1（只读提示） | 仅提示关联条目，不写回 FMEA |

## 8. 成功度量

| 指标 | 基准（现状） | MVP 目标 | 长期目标 | 测量方式 |
|------|------------|---------|---------|---------|
| 8D 输出耗时 | 1–2 天/份 | ≤ 4 小时/份 | ≤ 2 小时 | 立项→签字定稿时间戳（audit） |
| 根因候选命中率 | — | 首版命中（工程师采纳）≥ 60% | ≥ 90% | 工程师采纳 AI 候选的比例 |
| 历史案例复用率 | 低/凭记忆 | 每份附 ≥2 条历史参考 | — | 草稿引用历史 8D 数 |
| 格式/双语返工 | 频繁 | 确定性部分零返工 | 零 | 黄金基准偏差 |
| 客户 8D 退回率 | 待基线化 | 下降 | 下降 ≥ 50% | OEM 反馈/QMS |
| 合规 | — | 审计零缺陷、安全相关 100% 走额外门禁 | 同 | 审计抽查 |

> 注（沿用全景 KPI 红线）：不以"AI 节省工时"直接与个人绩效挂钩，避免隐瞒效率提升。

## 9. 风险与缓解

**[根因误导]** AI 根因候选若被低质量历史污染 → 缓解：D1 给候选+证据不给定论、D2 置信度标注、黄金基准校验命中率；安全相关走 D3 额外门禁。
**[OEM 数据串库]** 历史 8D 跨客户检索泄露 → 缓解：RAG 按 OEM 分库 + 隔离层强制路由 + `CrossOEMAccessError`。
**[历史库脏/缺]** 8D 存档不规范、字段缺失 → 缓解：启动前置做归集脱敏 + 结构化模板；MVP 先小批高质量样本。
**[安全相关漏标]** 安全相关不良未被标记走了普通流程 → 缓解：D3 挂接现有 ASIL 标签 + 关键词兜底识别 + 默认偏保守（疑似即升门禁）。
**[mock→真实偏差]** 真实客诉文本噪声大于样本 → 缓解：切真实独立任务，先过黄金基准；连接器/解析先 mock 验证。

## 10. 落地里程碑（建议，与 AIOps 第 2 人到位绑定）

阶段一（off-LAN 现在可做）：历史 8D 结构化模板设计、OEM 8D 模板收集（1 个试点客户）、脱敏方案、黄金基准样本选取标准。阶段二（开发，需 AIOps 第 2 人）：按 OpenSpec+SuperPowers 出 proposal/design/tasks → 先测试后实现 → mock 端到端。阶段三：脱敏历史库进环境跑黄金基准 → 过门禁 → 内部试用 → L2 对客试点。
