## 2. 定稿口径（可实现口径，向 CC 交付）

### C-1　主料 / 替代料 合并判缺料

**① 取数口径【已放行——CC 2026-07-08 验证通过】**
- 替代料关系从 **U9C BOM** 取：同一父件下，**子件项次序号（项次/行序号）相同**的多行子件视为一组（一个"料位"）；组内 **子项类型 = 标准 → 主料**、**子项类型 = 替代 → 替代料**。
- **放行条件（Paul 裁决 1）**：CC 须先验证现有 `BOM/Query` 取数是否返回"子件项次序号"与"子项类型"两字段（现行 `ZpConnector.get_bom_for_products` 不一定带）。
  - 返回 → C-1 排入 openspec 批2 与 C-2 一并实现；
  - 不返回 → CC 与 IT 落取数（补字段/换接口），落定后再排 C-1，**不无条件排期**。
- **验证结果（CC，2026-07-08，生产 `BOM/Query` 只读实测，15 个真实母件/1324 条子件行，样例来自今日净额底稿真实 FO 订单）**：
  - **子件项次序号 = `m_sequence`**；**子项类型 = `m_componentType`**（标准料恒为 `0`，替代料恒为 `2`，1324 条主件 + 56 条替代料样本无例外）——两字段都返回，姚祖怡口径可直接取数，**结论：放行**。
  - **⚠️ 结构提醒（与姚祖怡口径的字面描述不完全一致，CC 实现时须注意）**：替代料**不是与主件同级平铺、序号重复的兄弟行**（顶层 `m_bOMComponents` 里逐一扫描 `m_sequence` 未发现任何重复）；U9C 实际把替代料**嵌套挂在主件行自己的 `m_bOMCompSubstituteDTO4CreateSv` 子列表**里——主件行与其挂的替代料行 `m_sequence` 完全一致（同"项次"语义仍成立），但取数逻辑要写成"逐条主件行 + 读其内嵌替代料列表"，不能靠"顶层扫描重复序号配对"。样本中每个料位最多 1 条替代料（未见 1 组多替代的情况，`m_subSeq` 字段暂未被真实数据用上，留作未来多替代场景的排序备用）。
  - 只读探测，未改任何 ERP 数据；样例数据/脚本为一次性诊断，未入库（如需复核可让 CC 重跑）。

**② 判定口径**
- 毛需求**只算一份**、归主料（**不重复计**替代料需求）。
- 可用现货 = **主料现货 + 组内全部替代料现货 合计**（六仓白名单口径，与净额一致）。
- **组合计现货 ≥ 该组毛需求 → 该料位判齐**；否则计入缺口。
- **等价合并**（无"优先主料、不足才用替代料"的顺序）——专员口径；若采购后续要"优先主料"，属口径修订，另走反馈。

**③ 显示**
- 瓶颈/缺料清单里，主料 + 替代料**合并成一行**，标注"含替代料 Rxx/Rxx"。

**④ 实现边界（交 CC，非口径裁决）**：组内现货被多产品共享时的双计问题由 CC 在净额快照口径内处理；本口径侧只声明"毛需求不重复计、组内现货合计判齐"。

### C-2　部分齐套显示

**① 可齐套套数**
- `可齐套套数 = min over 全部直接子件( floor(子件可用现货 ÷ 单机用量) )`，受限于最紧子件。
- **无例外**（全部直接子件参与齐套判定，专员确认）。

**② 显示格式**
- 成品行加"**可齐套 X / 总需求**"字段（如 1000 / 8139）；
- 悬浮显示"**卡在子件 Rxx、还差 N 件**"。

**③ 与四色关系**
- 仍**按缺口判色**（有缺口 = 🔴/🟠）；在该档内**标注"可先齐 X 套"**，不因"能齐一部分"改判为绿。

### 窗口滚动

- 看板保供窗口**每月自动滚动 3 个月**（非固定日）：口径 = 出货日 ≤（当月起算 + 3 个月）末，随月自动前移。
