## 二、规则就绪（对接人主笔，对标 FI1 收口-1）—— FI4 的"灵魂"

| # | 收口项 | 要拍的 | 建议默认（strawman） |
|:-:|------|-------|------------------|
| R1 | **四维匹配键与容差** | 物料编码（靠映射表）/ 数量 / 金额 / 税额，各维容差多少 | 数量 ±2% 或 ±N；金额 ±0.5 元/行（尾差）；税额随税率 |
| R2 | **分批到货拆分** | 一个 PO 行对多次 GR/INV，按 FIFO 还是指定匹配 | FIFO 默认 + 支持人工指定 |
| R3 | **匹配结果分类边界** | 完全匹配/金额微差/明细错位/数量金额不符/无 GR，各自判定线 | 见下"MVP 口径底稿" |
| R4 | **必填字段清单** | FI4-A 退回供应商的依据（缺哪些字段就退） | 物料编码/数量/单价/金额/税率/发票号 |
| R5 | **L2/L3 门禁阈值** | 差异金额/比例超多少必须人工（分期先 L3 建议） | 金额量级给 Paul；比例按 R1 容差 |
| R6 | 孤儿单据/PO 变更未同步 | 无对应 PO 行的单据、变更后未同步的怎么处置 | 标记 + 推采购跟单员 |

> R1-R3 与《FI2 三单匹配口径 mock 备料》高度重合——那份的匹配键/容差/状态机可直接作 R1-R3 的 strawman，对接人在其上改。

## 三、治理就绪（上线前签，守 §7 红线）

第一，**L3→L4 分期**（D2）：FI4-B/C/D/F 先以 L3 建议/预警跑 1-2 个月、统计查准/查全率，达标再升 L4 自动过账/拦截。第二，**审计**：每笔匹配判定、分类、退回全写平台 `audit`（append-only，IATF 3 年）。第三，**退回 SOP**：标准化退单（退供应商 via SRM + 推采购跟单员），闭环跟踪。第四，**财务红色数据脱敏**：金额按需脱敏/聚合，原始单价不落 AI 侧。第五，**跨职能接口**：PO/GR 口径、退单闭环、（FI4-G）供应商考核联动需**采购侧接口人**配合——主责财务对接人，采购配合。

## 四、MVP 口径底稿（FI4-B 四维匹配 —— 对接人确认边界）

匹配沿 **PO 行**对齐三单，逐行四维比对，结果分五类：

| 类别 | 判定边界（strawman，待确认） | 处置 |
|------|------------------------|------|
| 🟢 完全匹配 | 物料/数量/金额/税额 四维全在容差内 | L3 建议通过 →（升 L4）自动进过账队列 |
| 🟡 金额微差 | 仅金额差 ≤ 尾差容差（±0.5 元/行） | 标"待确认"，推财务 |
| 🔴 明细错位 | 总额对但明细行金额错位（物料 A 多、B 少，总额一样） | 拦截，高亮错位行（**杜绝成本失真的关键**） |
| 🔴 数量/金额不符 | 超容差 | 拦截，推差异清单 |
| 🔴 无 GR 支撑 | 发票无对应入库 | 拦截，标"无入库发票" |

> "明细错位"是 FI4-B 相对人工"只对总额"的最大增量——总额对、明细错会让按行核算的产品成本严重失真。MVP 必须把这条做准。

**对接人 5 个决策**（成 propose 输入）：① 四维容差量级（R1）；② 分批 FIFO/指定（R2）；③ 五类边界（本表）；④ 必填字段清单（R4）；⑤ L3 阶段哪些结果推人工。
