# EQQR10011 模板改进建议书（A2 → A3 草案）

> **为什么不用程序直接改**：这两份表单的复选框是旧式表单控件（存于 vmlDrawing），程序改写保存会丢控件。**正确做法 = 文档控制人在 Excel 里按本规格手工修订，保留所有控件，再走修订/会签转正。** 本书精确到 sheet / 单元格 / 取值，配套《改进字段草样.xlsx》给出可复制的结构。
>
> 每项标注对应《立项门禁机器可核规则表》规则 ID，改完即可让 AI 门禁自动核。

## 改动 1 · 研发类标题与类型修正（规则 M-02，🔴 必改·低风险）

研发类文件前后不一致：正文大标题已是「研发类」，但封面和 sheet 名仍是「开发」。三处统一为「研发类」：

| # | 位置 | 现状 | 改为 | Excel 操作 |
|---|------|------|------|-----------|
| 1 | 研发类·「表单封面」sheet·文件名称单元格 | 立项申请书（**开发类**） | 立项申请书（**研发类**） | 直接改文字 |
| 2 | 研发类·「表单封面」sheet·顶部标题 | 立项申请书（**开发类**） | 立项申请书（**研发类**） | 直接改文字 |
| 3 | 研发类·正文 sheet 标签名 | 立项申请书（**开发**） | 立项申请书（**研发**） | 右键标签→重命名 |

> 正文行1大标题已是「研发类」，无需改。
> **文档控制确认项**：开发类与研发类**共用同一文件编号 EQQR10011 + 版本 A2**。若按体系应区分，建议给研发类单列子编号（如 EQQR10011-R），或在封面「适用范围」明确为同一编号下的两个变体。此项由质量体系/文控决定。

## 改动 2 · 风险表增「闭环状态」列（规则 R-04，🟡 重要）

红线要求"风险规避闭环"，但当前风险表只有「计划关闭日期」、无闭环结果。在风险表「计划关闭日期」列右侧插入 1 列：

- **表头**：闭环状态
- **数据有效性下拉（序列）**：`未闭环,验证中,已闭环`
- **位置**：开发类风险表（正文 ~行49-50 表头区）、研发类（~行76-77），均在「计划关闭日期」右侧
- **建议配套**：再加 1 列「闭环验证证据/记录」（自由文本，可选）
- **Excel 操作**：选中「计划关闭日期」整列 → 右键插入列 → 填表头「闭环状态」→ 数据 → 数据验证 → 允许「序列」→ 来源填 `未闭环,验证中,已闭环` → 确定
- ⚠️ 风险表处在合并区，手工插列后检查该行合并/边框对齐

## 改动 3 · 新增「项目退出/止损机制」子节（规则 X-01，🔴 必改·改动最大）

当前缺独立退出/止损机制（决议里"未签回停止支出"只是付款止损）。新增一个子节，**放在「项目风险分析」章节之后**（退出/止损与风险同源，且避免大改后续章节编号）：

- **标题**：开发类「五（二）项目退出/止损机制」；研发类「六（二）项目退出/止损机制」
- **引导语**：明确项目在何种情况下应止损或退出，避免沉没成本继续扩大，形成风险闭环的最后一道闸。
- **表格结构**（详见草样）：

| 退出/止损触发条件 | 判定阈值 | 止损/退出措施 | 决策审批人 |
|-------------------|---------|--------------|-----------|
| 关键技术攻关失败 | （示例）2 个里程碑未达 | 暂停支出 / 转研发储备 | 事业部总经理 |
| 质量阀（G1-G4）连续不达标 | （示例）连续 2 阀 | 范围收敛 / 退出评审 | 立项评审委员会 |
| 成本/进度超阈 | （示例）超预算 30% | 重新立项评估 | 财务+事业部 |
| 客户取消/需求重大变更（开发类） | — | 终止 / 转研发 | 事业部+销售 |

- **附**：退出后处置说明（已投入资产、IP 归属）。
- **Excel 操作**：在风险章节末尾手工插入若干行 → 重设该区合并单元格 → 套用与其他章节一致的表格样式。⚠️ 这是改动最大、最需校样的一处，插行后务必检查后续章节（资源/成本效益…）未错位、合并未断、公式引用未失效。

## 改动 4 · ROI 达标显性判定位 + 枚举下拉（规则 F-03/F-04、D-02，🟡 重要）

### 4a. ROI 达标判定位（让 ≥1.5 / ≥5 的结论一眼可见、可机器核）

在「盈利测算依据」区（开发类 ~行91「技术服务类≥1.5」、~行92「产品类≥5」）每行右侧加 1 格「判定」，用公式自动出结论：

| 测算项 | 阈值 | 判定（新增格·公式） |
|--------|------|---------------------|
| 技术服务类：项目收入/项目投入 | ≥ 1.5 | `=IF(收入/投入>=1.5,"达标","不达标")` |
| 产品类：(收入+全周期产品利润)/投入 | ≥ 5 | `=IF((收入+产品利润)/投入>=5,"达标","不达标")` |

> 把"收入""投入"换成模板里对应的实际单元格引用（如成本效益表的合计单元格）。这样 AI 门禁直接读"达标/不达标"，无需再算；人审也一眼看到。

### 4b. 枚举字段加下拉校验（提升可机器核性，下拉值见草样「下拉值清单」页）

| 字段 | 建议下拉值 |
|------|-----------|
| 项目所属事业部 | （公司事业部清单，PMO 填） |
| 功能安全目标 ASIL | 无 / A / B / C / D |
| 资源获取方式 | 采购 / 借用 / 外包 / 自研 / 其他 |
| 风险等级 | 低 / 中 / 高 |
| 当前成熟度 | 成熟量产 / 在研 / 预研 / 不涉及 |
| 知识产权 | 内部开发 / 委外开发 / 自研 / 授权 / 开源 / 不涉及 |

> **取舍**：单选项的自由文本字段改下拉；已是复选框的多选体系（适用法规）保留。**项目等级/立项决议这类单选复选框组**，若想更好被 AI 解析，可评估改为下拉（D-01 机器可读），但这会动控件，是否改由文控权衡。

> ⚠️ **复选框可解析的硬技术前提（吸收外部评审，规则 D-01）**：旧式 VML 复选框的"勾选状态"存在底层绘图对象里，`openpyxl`/`pandas` 读不到——**除非在 Excel 里把每个控件右键→设置控件格式→"单元格链接"绑定到一个单元格**（勾选时该格显 `TRUE`）。若现有模板的复选框**未绑定 linked cell**，AI 读到的就是空/恒 `False`，会把"已选项目等级/已选法规"误判为"未填"，触发 T-02/T-03 阻断 → 100% 误判退回。
> **两条出路（A3 二选一）**：① 推荐——**废除 VML 复选框，全部改 Excel 数据有效性下拉/普通单元格 TRUE-FALSE**，openpyxl 解析难度直降、最稳；② 若坚持保留复选框，**必须逐个绑定隐藏 linked cell**，否则开发环境无法解析。

## 改完后的收益（对接门禁）

四处改完，《机器可核规则表》里这些规则即可自动核：R-04 风险闭环、X-01 退出机制（阻断项补齐）、F-03/F-04 ROI 红线（达标位直读）、D-02 枚举可核、M-02 类型分流正确。门禁的"阻断项"缺口从此清零。

4. 转正后把规则表里标★的缺口规则置为"已就绪"。
