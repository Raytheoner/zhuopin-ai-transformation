##### 场景 FI1：供应链自动仓库对账（2026-08 启动 / 09 试点）

```yaml
痛点: SMT 非精准发料致库存消耗与 BOM 理论用量偏差，加委外加工商库存需人工盘点，
     每月财务与供应链投入大量人力核差异，耗时易错
AI 做什么:
  - 自动采集 SMT 实际投料 vs BOM 理论用量做差异分析（毛理论口径，标准损耗率显性拆分）
  - 差异自动分类（损耗溢短/超损/来料短缺/管理差异），标记需人工的异常项
  - 生成库存对账差异报告；委外加工商库存二期接入
数据依赖: SMT 投料数据、BOM 表、ERP 出入库记录、（二期）委外库存
自动化等级: L2（AI 自动对账 + 差异报告，财务+供应链经理审核异常项）
预期价值: 仓库对账从月度多人天缩至当天自动化；差异定位从逐笔翻查变系统自动标注
状态: 内部对账 MVP 已合 master（mock 30 测试绿、审计链通），停在真实验证前
```

##### 场景 FI2：三单匹配自动对账（2026-09 启动，采购/付款提前重点）

```yaml
痛点: 应付会计用 Excel 逐笔核对 PO/GR/INV，每天 2-3 小时，是最大效率黑洞：
     - 总额对但明细行错位（A 多开、B 少开），后续按行核算的产品成本严重失真
     - 每月 15-20% 单据数据缺失/格式问题，先"凑齐数据"才能匹配
     - 供应商编码≠我方编码、分批到货分批开票、税率错、重复发票
AI 做什么（子场景，按最优子序）:
  - FI2-1 三单数据准备与完整性校验：OCR 解析 SRM 发票、校验必填字段（物料码/数量/
    单价/金额/税率/发票号）、缺失退回、检测 PO 变更未同步、建 PO↔GR↔INV 行级映射、数据质量日报
  - FI2-2 明细行级四维匹配：按「物料码+数量+金额+税额」逐行匹配，物料编码映射自学习，
    分批到货 FIFO/指定拆分，结果五分类（完全/金额微差/明细错位/数量金额不符/无 GR）
  - FI2-3 税率合规校验：INV 税率 vs 供应商约定税率，混合经营按物料取税率，小规模特殊规则
  - FI2-4 重复发票检测：完全/实质/作废重开/跨期重复；并查 INV↔已付款防重复付款
  - FI2-5 容差管控与差异处理：尾差自动判定（±阈值/行），差异原因分类，累积超阈值预警
  - FI2-6 异常拦截与退单清单：标准化退单、SRM 推供应商+采购跟单员、退单跟踪闭环
  - FI2-7 供应商退单率考核联动：退单率标红、Top3 根因、季度排名入采购考核
  - FI2-8 异常模式学习与预防：异常聚类、趋势预警、预防规则建议、异常知识库
数据依赖: U9C PO/GR 明细行、应付；SRM 发票原件+明细行+OCR；物料编码映射表；
         供应商主数据（约定税率/资质）；历史发票/退单
         【卡口】U9C CommonEntity/Query 外网 404（端点时间表或 CSV 桥接）；SRM 900401；OCR 选型
自动化等级: L3→L4 分期（FI2-1~4、FI2-6 先 L3 建议跑准确率，达标升 L4 自动过账/拦截；
         FI2-5/7/8 保持 L3；L4 晋级门=查准/查全达标 + 误判可控）
预期价值: 数据准备 30-40 分/天→5 分/天；明细匹配 2-3h/天→15-20 分/天、审核量压缩~95%；
         单据完整率 80-85%→98%+；匹配成功率 85-90%；杜绝"总额对明细错"的成本失真；
         重复检出>99%；税率错退单减 90%+
最优子序: M1 FI2-1+FI2-2（数据通即起）→ M2 FI2-3+FI2-4 → M3 FI2-5+FI2-6 →
         M4（2027-Q1）FI2-7+FI2-8
```

##### 场景 FI3：付款申请自动校验（2026-11 启动，两段起；采购/付款提前重点）

```yaml
痛点: 付款环节是资金安全高风险区，当前靠人工经验与记忆：
     - 付款申请提交后才发现三单未配齐，反复退回反复提交
     - 打错收款账户（户名/账号/开户行）资金损失风险；供应商换账户仅邮件通知
     - 重复/超额付款人工查重靠记忆与 Excel；跨期几乎发现不了
     - 超合同/框架/暂估价累计付款人工难实时掌握
     - 预付款无合同无单据先打款、长期未核销、勾稽混乱
     - 付款日期靠人工按账期条款算，标准不一
     - 各项校验分散多界面，审批需反复切换
AI 做什么（子场景）:
  - FI3-1 三单匹配状态前置校验：提交时查配票状态，未配齐拦截，紧急付款走 CFO 特批+
    限期补齐+《未匹配付款跟踪清单》（消费 FI2 三单匹配结果）
  - FI3-2 收款账户与合同比对：户名/账号/开户行三字段比对，账户变更走主数据审批流+
    新账户首次使用提醒，关联供应商账户高亮
  - FI3-3 重复付款检测：发票级累计（已付+本次≤发票额）、PO 级累计、疑似重复（同供应商+
    同额+相近日期）、跨期比对、预付款扣回
  - FI3-4 累计付款超合同/订单拦截：实时累计 vs 合同上限、合同变更联动、框架合同汇总、暂估价预警
  - FI3-5 预付款管控与核销校验：付款前单据支撑分级（无单据/仅申请/有 PO/有合同→分级审批+
    CFO 例外通道）、预付款→正式发票全生命周期勾稽、催票机制、账龄监控、核销 FIFO
  - FI3-6 付款日期自动计算：解析账期条款（验收后/月结/到货后/票到后 N 天）、节假日顺延、
    付款日历、到期未申请预警
  - FI3-7 付款申请综合校验仪表盘：一屏汇总各校验通过/拦截、一键穿透、审批效率统计、移动端
数据依赖: FI2 三单匹配结果；U9C 已付款凭证/应付/采购合同（变更/框架/暂估）/供应商主数据
         （收款账户）/预付款台账；法定节假日日历；CFO 审批流
自动化等级: L3→L4 分期（FI3-1~4 先 L3 建议、达标升 L4 自动拦截；FI3-5/6/7 保持 L3；
         涉资金安全，L4 晋级需 Paul + CFO 会签）
预期价值: 付款退回率↓80%+；打错账户→系统拦截趋零；重复/超额检出>99%；
         长账龄预付款↓50%+；审批效率↑60%+
最优子序: 不依赖三单可 2026-10 并行 FI3-2/FI3-4/FI3-5/FI3-6；依赖 FI2 的 FI3-1/FI3-3
         随 FI2 MVP 跟上；FI3-7 仪表盘 2026-11 收口
```

##### 场景 FI4：智能月结加速（银行流水/科目余额/月结仪表板）（2027-Q1 启动）

```yaml
痛点: 月结 T+5，财务需手动核对银行流水、科目余额、总账勾稽，加班严重
     （注：原月结的三单匹配核心已独立为 FI2 提前落地）
AI 做什么:
  - 基于 U9C 月结数据 + 银行流水 API，自动完成银行流水与账面凭证核对
  - 科目余额/总账勾稽差异识别与根因分类（单据缺失/时间性差异/重复入账）
  - 输出月结进度仪表板，实时显示卡点位置与责任人（消费 FI2 三单匹配结果）
数据依赖: U9C 财务模块、银行流水 API、（联动）FI2 三单匹配结果
自动化等级: L2（AI 完成差异分类 + 卡点定位，财务经理审核确认）
预期价值: 月结 T+5→T+3（-40%）→T+1；财务加班减少 70%
```

##### 场景 FI5：费用报销智能审核（2027-Q1 启动）

```yaml
痛点: 费用报销 3 天/批，财务逐张审核发票合规性、报销标准、预算余额，审批链长
AI 做什么:
  - 在 U9C 报销流程基础上，OCR 识别发票、校验真伪与合规性
  - 对照公司报销政策（差旅标准/招待限额）自动审核；实时查预算余额、超预算拦截并通知上级
  - 异常报销（超标/频繁/关联交易）标风险等级；生成部门级费用分析报告
数据依赖: U9C 报销模块、发票 OCR、预算管理系统、公司政策文档
自动化等级: L2（AI 初审 + 风险标记，财务经理抽审）
预期价值: 报销处理 3 天→4 小时，合规率提升至 99%+
```

##### 场景 FI6：异常交易实时检测（应收异常/关联方/频率/内控）（2027-Q2 启动）

```yaml
痛点: 异常交易检出仅约 60%，应收异常、金额突增、频率异常、关联方交易靠人工经验
     （注：付款环节的重复/超额/账户风险已独立为 FI3 提前落地）
AI 做什么:
  - 实时监控 U9C 每笔应付/应收交易，与历史模式对比
  - 异常检测模型：金额突增、频率异常、关联方交易识别
  - 高风险交易触发审批并推送财务主管；维护可疑交易案例库持续学习
  - 生成月度异常交易分析报告，识别系统性内控漏洞
数据依赖: U9C 交易流水、供应商/客户主数据、历史异常案例库、（联动）FI3 付款校验结果
自动化等级: L2（AI 标记异常并推送，财务主管确认处理）
预期价值: 异常交易检出率 60%→>95%，减少资金损失风险
```

##### 场景 FI7：预算执行监控（2027-Q2 启动）

```yaml
痛点: 预算执行靠月底手工汇总实际 vs 预算，超预算事后才发现，缺过程预警
AI 做什么:
  - 基于 U9C 预算模块，实时采集各部门支出、对比预算自动算执行率
  - 异常支出（超预算/预算不足/异常波动）自动预警通知部门负责人
  - 预测月底/季末执行趋势，提前预警超支；支持追加预算 what-if 模拟；月度偏差分析报告
数据依赖: U9C 预算模块、各部门实际支出数据
自动化等级: L2（AI 实时预警 + 趋势预测，CFO 决策审批）
预期价值: 预算监控从事后回顾变实时预警，超预算事件减少 60%
```

##### 场景 FI8：现金流预测与智能预警（2027-Q2 启动）

```yaml
痛点: 现金流预测靠财务总监经验，缺数据支撑，突发大额支出/回款延迟致资金链紧张
AI 做什么:
  - 整合 U9C 应收/应付计划、历史回款周期、在手订单，建分客户/供应商现金流预测模型
  - 预测未来 4/8/12 周现金流，高亮资金缺口窗口；大额逾期应收触发催收 escalation
  - 支持"某客户延迟付款 30 天"的 what-if 影响分析
数据依赖: U9C 应收/应付模块、销售订单、采购合同、银行账户余额
自动化等级: L2（AI 预测预警，CFO 决策调度）
预期价值: 现金流预测从靠经验变靠数据，资金缺口提前 4 周预警
```

##### 场景 FI9：研发费用归集与高新认定助手（2027-Q2 启动）

```yaml
痛点: 研发费用散落材料/人工/工装/测试多科目，人工按项目归集、判资本化/费用化；
     高新认定与政府申报前突击整理辅助账 2 周以上，常被审计退回
AI 做什么:
  - 自动从 U9C 项目成本模块采集各研发项目材料/人工/制造费用
  - 基于会计准则+企业政策规则引擎判资本化/费用化；按高新要求生成研发费用辅助账
  - 计算研发费用占比等核心指标；生成加计扣除备查资料包；政府专项核算；研发项目投入产出分析
数据依赖: U9C 项目成本模块、工时系统、高新认定政策库、企业会计政策文档
自动化等级: L2（AI 归集 + 分类建议，财务/研发总监审核确认）
预期价值: 高新认定准备 2 周→3 天，资本化判断一致性 95%+
```

##### 场景 FI10：存货跌价智能分析（2027-Q2 启动）

```yaml
痛点: ECU 电子元器件迭代快、价格波动大、呆滞风险高；财务年末才手工跌价测试、覆盖不全；
     芯片降价/项目取消时账面价值已失真数月；IATF 追溯致专用物料难处置
AI 做什么:
  - 自动采集 U9C 库存账龄、在途采购、BOM 用量；对接芯片价格 API 取核心器件趋势
  - 结合 OEM 项目生命周期（APQP/EOP）识别呆滞；按准则执行 NRV vs Cost 自动测试
  - 库龄超期/芯片降价超阈值/项目终止未耗物料自动预警；生成跌价准备计提建议表；what-if 模拟
数据依赖: U9C 库存模块、芯片市场价格 API、OEM 项目计划（PLM）、历史呆滞处置记录
自动化等级: L2（AI 测算 + 预警，财务/供应链经理确认）
预期价值: 跌价测试年末 1 次→月度实时，呆滞风险预警提前 3 个月
```
