# 质量旗舰 8D 前置 · 周五里程碑支持包

> 旗舰①（8D 不良分析与根因）2026-10 入轨的**硬前提**是历史 8D 库归集 + 脱敏，全程 6-8 周、全程 off-LAN。本周五的阶段性里程碑是把"能跑通"证明出来：首批 5-10 份脱敏样例 + 录入表填顺 + 黄金基准候选初选 + 归集范围/owner 对齐。
>
> 本包四个部分对应周五四件交付，**陈忱边干边用**：第一部分边脱敏边自查，第二部分边录入边核字段，第三部分挑黄金基准时打分，第四部分开归集对齐会时发出去。术语与《开工就绪包》《录入表》完全对齐（`OEM-A/B/C` 令牌、四类不良、安全相关）。

## 第一部分 · 脱敏样例 Review 要点清单

> 用途：每份样例脱敏完，自己先按这张表过一遍；陈忱抽检时也用这张表。**目标是切断"靠任何细节反推 OEM 身份"的链路，同时不把"失效机理/根因知识"误删。** 一份样例每条都打 ✓ 才算合格。

### A. 客户身份令牌化（最高优先级，漏一处即不合格）

- [ ] **客户名全部令牌化**：比亚迪/上汽/理想等 → `OEM-A/B/C`；跨客户通用机理标 `通用`。正文、标题、表格、附件名里**一处不漏**。
- [ ] **令牌稳定一致**：同一家客户在所有文档里映射到**同一个**令牌（如比亚迪恒等于 `OEM-A`）——这是后续 RAG 按客户分库检索的前提，不能这份叫 A、那份叫 B。
- [ ] **映射表不进包**：`OEM-A=哪家` 的对照表**只存质量部本地加密文件**，绝不写进录入表 / 样例 / 任何会进开发环境的文件。
- [ ] **车型/平台代码已脱敏**：OEM 专属车型名、平台代码、项目代号（能一键对到某家客户的）→ 通用占位（如 `某车型平台`）。

### B. 技术实体屏蔽（Entity Scrubbing，反推链路第二道）

仅令牌化客户名**不够**——D2 现象描述和 D4 根因里常藏着能反推客户的技术指纹。逐类核查：

- [ ] **专属芯片/器件命名**：OEM 定制的芯片型号、引脚/信号专属命名 → 通用化（如 `BYD-DiLink-MCU1` → `Generic-MCU`、专属信号名 → `信号X`）。
- [ ] **专属接口/协议名**：客户专属的通讯接口、私有协议名 → `某私有接口`。
- [ ] **具体产线/工位别**：`SMT-Line 3`、专属工位编号 → `产线X` / `工位X`。
- [ ] **专属软硬件版本号**：能对到客户项目的版本号 → 模糊化或去除。
- [ ] **唯一可识别的量产数据**：专属批次号规则、客户专属料号前缀 → 令牌化或去除。

### C. 个人信息去标识

- [ ] **经办人姓名/联系方式**去除或角色化：`张三` → `质量工程师A`、`李四` → `SQE-B`。
- [ ] **签批人、供应商对接人**同样处理；保留"角色"，去除"个人"。

### D. 保留可学信息（防过度脱敏 —— 这是 AI 价值所在）

> 屏蔽的是"身份指纹"，**不是"失效知识"**。下面这些**必须保留**，删了样例就没学习价值了：

- [ ] **失效机理**完整保留（如"焊膏印刷厚度超规→虚焊"——这是通用知识，不指向任何客户）。
- [ ] **根因逻辑链**（5Why / 鱼骨）保留，只替换其中的客户专属技术实体，逻辑骨架不动。
- [ ] **对策类型**保留（如"纳入 SPC 监控""加严 IQC 参数"）。
- [ ] 自检：脱敏后这份 8D **还能不能看懂"为什么坏、怎么修"**？能 → 合格；看不懂了 → 脱过头了，回退。

### E. 安全相关标记复核

- [ ] **"安全相关"字段独立判定**：涉 ASIL 功能的 8D → 标"是"，触发 ISO 26262 额外门禁（功能安全工程师额外审核）。脱敏不改变安全属性，别把安全相关样例脱敏成看不出安全属性。

> **一份样例的合格门槛**：A 全 ✓（漏一处客户身份即退回）+ B 逐类已核 + C 已去标识 + D 自检"还看得懂失效与根因" + E 安全标记正确。

## 第二部分 · 录入表字段级校验清单

> 配套 `质量旗舰-8D历史库录入表.xlsx`（12 字段）。每录一行按此核；批量录完用"批次自检"段过一遍。口径与录入表"填写说明"页一致。

### 入库门槛（先过门槛，再谈录入）

- [ ] **只收"已结案 且 根因经验证有效"**的 8D（`根因验证有效=是` 且 `结案日期` 非空）。未结案、根因未验证、被否决的整改 → **不入库**（防止 AI 学到未采纳的误判）。
- [ ] 首批控量保质：**30-50 份**，覆盖四类不良；先小批高质量再扩。

### 逐字段校验规则

| 字段 | 校验规则 | 常见错 |
|------|---------|--------|
| 案例ID | 必填、唯一、按统一流水规则（如 `8D-2025-001`）；不得含客户真名 | 用了含客户名的原始编号 |
| 客户(脱敏) | 必填、**只能是 `OEM-A/B/C…` 或 `通用`**；不得出现真实客户名 | 漏脱敏 / 令牌不一致 |
| 失效现象描述(D2) | 必填、保留机理、已过技术实体屏蔽；一句话讲清"什么场景下什么坏了" | 含专属车型/芯片名 |
| 不良分类 | 必填、**四选一枚举**：设计 / 制程 / 物料 / 使用不当；按"根因归属"分，不是按"现象" | 按现象误分；自创类别 |
| 安全相关 | 必填、**是/否** 二选一；涉 ASIL 功能填"是" | 拿不准时漏填 |
| 临时对策(D3) | 必填、围堵/隔离措施 | 与 D5 混填 |
| 根本原因(D4) | 必填、**含 5Why 或鱼骨逻辑链**；这是学习核心，不能只写一句结论 | 只写结论无推导 |
| 纠正与预防(D5-D7) | 必填、措施 + 验证结果；体现"永久对策" | 缺验证结果 |
| 关联FMEA条目 | 选填、有则填 DFMEA/PFMEA 条目号（如 `PFMEA-12`） | 格式不统一 |
| 关联物料/供应商 | 选填、料号/供应商（与 SC1 联动）；供应商名按需脱敏 | 供应商真名未脱敏 |
| 结案日期 | 必填、`YYYY-MM-DD`；入库门槛字段 | 格式乱 / 用未结案件 |
| 根因验证有效 | 必填、**是/否**；只有"是"才入库 | 填了"否"还录进来 |

### 不良分类口径（最易错，统一这一条）

- **设计**：根因在设计裕量/选型/架构（如"时钟裕量不足，温漂下超容差"）。
- **制程**：根因在本厂制造工艺（如"焊膏印刷厚度超规→虚焊"）。
- **物料**：根因在来料/供应商（如"供应商烧结工艺波动致容值偏移"）。
- **使用不当**：根因在客户端使用/装配/环境超规。
- 判定准则：**问"根因落在谁的工序"**，不是"现象在哪暴露"。一份多因的取"主根因"，备注里记次因。

### 批次自检（录完首批后过一遍）

- [ ] 必填列**零空格**（除选填两列）。
- [ ] `客户(脱敏)` 列**无任何真实客户名**（可全列扫一遍）。
- [ ] `不良分类` 仅四枚举值；`安全相关`/`根因验证有效` 仅是/否。
- [ ] 四类不良**都有样本**（设计/制程/物料/使用不当各 ≥1）。
- [ ] 至少 **1 条 `安全相关=是`**（给黄金基准用）。
- [ ] 全部 `根因验证有效=是`、`结案日期` 非空。

## 第三部分 · 黄金基准初选标准

> 黄金基准 = 旗舰上线前用来验"AI 重跑 vs 工程师当年结论"的回归样本（仿 SC8 门禁）。从已入库样例里**挑 5-10 份够格的**。本部分把《开工就绪包》1.4 操作化成一张打分判定。

### 数量与覆盖（硬性配比）

- **总量** 5-10 份。
- **四类不良各 ≥1**（设计 / 制程 / 物料 / 使用不当）。
- **安全相关 ≥1**（专门验证 ISO 26262 额外门禁会触发）。
- **OEM 分布**尽量覆盖主要客户（让分库检索也被验到）。

### 单份"够格当黄金基准"判定（每条都满足才入选）

- [ ] **根因清晰且唯一指向**：D4 有明确、经验证的单一主根因，不是"可能 A 也可能 B"的悬案——AI 重跑要有确定答案可比。
- [ ] **纠正预防可验证**：D5-D7 有具体措施 + **明确的验证结果**（"已验证有效"白纸黑字），不是"待观察"。
- [ ] **现象描述自足**：D2 脱敏后仍能让人/AI 看懂失效场景，不依赖图纸/附件才能理解。
- [ ] **逻辑链完整**：5Why/鱼骨从现象到根因推得通，中间不跳步。
- [ ] **脱敏不影响可判**：第一部分脱敏后，这份仍保留完整失效机理（没被脱过头）。
- [ ] **结论无争议**：当年是质量/工程共识结案的"标准答案"，不是有分歧勉强结的案。

### 标注与沉淀

- [ ] 每份黄金基准在录入表/单独清单里**标注 `黄金基准=是` + 该份对应的不良类别 + 是否安全相关**，方便回归时按维度核。
- [ ] 形成一张"黄金基准候选清单"（案例ID / 不良分类 / 安全相关 / 入选理由一句话），交付时一并给——后续 CC 在 LAN 把它落到 `data/golden/`。
- [ ] **通过标准（上线时验，先记着）**：确定性部分（格式/字段/双语）零偏差；根因候选命中率（工程师采纳）≥ MVP 阈值 60%；安全相关 100% 走功能安全工程师额外门禁。

> 本周只做**初选候选**（挑出 5-10 份、标好维度、写入选理由），不做 AI 重跑（那是上线前的事）。
