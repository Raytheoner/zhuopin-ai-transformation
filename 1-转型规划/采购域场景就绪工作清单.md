# 采购域 AI 场景 · 就绪工作清单

> 采购域引擎已跑在真实数据上，就绪工作的重心是**校准（让已上线的准）+ 部署前置（让待部署的稳）**，不是从零归集。**P0 是缺料预警误判**——它直接动摇采购 AI 的可信度，必须先解。

## P0 · 缺料预警误判校准　🔴 最高优先

**现象**（专员手工核对发现）：跑出的物料瓶颈子件里，部分**卓品库存充足、既无订单也无请购**，却被判缺料、成了追料对象。不需要的料变成追料目标，预警失真。

**根因方向**（架构师初判，已对 kit_engine 代码，待 CC 在真实数据上确认）：

`kit_engine.calc_shortage` 的逻辑是——
```
可用量 = 当前库存 − 安全库存 + 在途未到货
缺口   = max(毛需求 − 可用量, 0)
B6 特例：物料【不在库存快照】时，可用量 = 在途（缺快照不再忽略）
```
问题就出在 B6 特例：**若一个子件没进引擎读到的库存快照、又无在途订单（无 PO），可用量被算成 0，毛需求一减就报假缺口**——哪怕仓里实物一大堆。所以这**大概率不是算法错，是喂给引擎的库存快照覆盖不全 / 料号口径不匹配**。

**排查步骤**（专员牵头定口径，CC 在 LAN 跑数据落实）：

| 步 | 查什么 | 谁 |
|:-:|--------|----|
| 1 | 把误判的瓶颈子件清单 vs 引擎的 `missing_snapshot`（不在库存快照的料）对一遍——大概率全落在里面 | CC |
| 2 | 这些子件的库存口径：是**仓库范围漏**（某些仓未纳入快照）？**料号映射不一致**（SRM/BOM 料号 vs ERP 库存料号编码不一致）？还是**快照状态过滤**把可用库存排掉了？ | 专员 + CC + IT |
| 3 | 毛需求是否挂**真实订单**：这些子件有没有真实 FO/SO 生产需求驱动？若无（无订单无请购正说明不需要），则连毛需求都不该 > 0 | 专员牵头 |
| 4 | 定义"真缺料"业务口径（见下），交 CC 改判定 | **专员主笔** |

**"真缺料"业务口径（专员定稿，CC 据此改）**：净需求 = 毛需求 − 现有可用库存（现货 + 在途 − 安全库存）；**净需求 > 0 才算缺料**；现有库存充足、或无真实订单驱动的子件，**不进缺料/追料集合**，无论有无在途订单。库存快照必须覆盖全仓、料号口径与 BOM/SRM 对齐。

> **截止**：口径草案专员到位首周出 → CC 排查 + 修 → 真实数据回归（误判清零）。这是采购 AI 信任的根，优先于一切新部署。
