⑤ 全盘审计与差距分析报告 §2.5（B6：物料不在库存快照时 available=在途 的由来）

== 现象（采购专员手工核对发现）==
跑出的物料瓶颈子件里，部分**卓品库存充足、既无订单也无请购**，却被判缺料、成追料对象。
不需要的料变成追料目标 → 预警失真，动摇 SC8 保供看板可信度。

== 根因假设（架构师对代码初判，待你在真实数据上确认）==
calc_shortage：可用量 = 当前库存 − 安全库存 + 在途；缺口 = max(毛需求 − 可用量, 0)。
B6 特例：物料【不在库存快照】时 available = 在途。
→ 子件若没进引擎读到的库存快照、又无在途(无 PO)，available=0，毛需求一减报假缺口。
→ 据此**大概率是喂给引擎的库存快照覆盖不全 / 料号口径不匹配，不是算法错**。请验证、勿先入为主。

== 排障步骤（先复现定位，别急着改）==
1. 真实数据**复现**：跑出当前误判的瓶颈子件清单，确认现象。
2. **隔离**：把误判子件 vs 引擎的 missing_snapshot（不在库存快照的料）对照——是否全落其中？
3. **区分根因（关键）**：
   - 数据侧？库存快照漏了这些料——仓库范围漏？SRM/BOM 料号 vs ERP 库存料号编码不一致？快照状态过滤把可用库存排掉？
   - 逻辑侧？毛需求是否挂真实订单驱动（无 FO/SO 需求的子件根本不该有毛需求）？B6 分支在"无在途"时是否该判缺？
   - 大概率是数据侧（库存快照/料号口径），但用真实数据证实，别假设。
4. **★停下，报我**：把复现结果 + 根因（数据侧/逻辑侧/两者）+ 建议修法写出来，等我和采购专员确认"真缺料"业务口径后再改。

== 真缺料业务口径（采购专员定稿，走采购域 Cowork 专线；你据此改）==
净需求 = 毛需求 − 现有可用库存（现货 + 在途 − 安全库存）；**净需求 > 0 才算缺料**；
库存充足、或无真实订单驱动的子件，**不进缺料/追料集合**，无论有无在途订单。
库存快照须覆盖全仓、料号口径与 BOM/SRM 对齐。
（口径草案专员到位首周出；定稿前可先在 mock/脱敏样本上验证修法。）
