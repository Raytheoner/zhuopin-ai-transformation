# FI2 三单匹配自动对账 · 就绪清单 + MVP 细化

> **编号说明（2026-07-09 正名）**：自 2026-07-03 全景重编号起，"三单匹配自动对账"= **FI2**（子场景 FI2-1..8）；此前材料沿用专员草拟期旧号"FI4/FI4-A..H"，对应关系：FI4-A→FI2-1 数据准备、FI4-B→FI2-2 归集匹配、FI4-C→FI2-3 税率、FI4-D→FI2-4 查重、FI4-E→FI2-5 容差、FI4-F→FI2-6 退单、FI4-G→FI2-7 考核、FI4-H→FI2-8 学习。**本版为唯一现行版**，旧号文件已降为指针。
>
> **核心判断**：FI2 能否按期上线，瓶颈不在引擎，在**①三单数据（PO/GR/AP+发票附件）通不通 + OCR 准不准（数据就绪）②匹配的键与容差有没有人定清（规则就绪）**。本清单已融入 **v3 口径修正**（2026-07-09 应付会计实操输入 + Paul 三裁决，权威见《财务域场景v3-局部定稿》§1）：核对对象=**AP 单 vs INV**（PO 前置参照）、按**料品汇总归集比合计**、发票源=**U9C 应付附件+OCR**、新增 **AP-PO 单价强制比对**。
>
> **底座复用**：FI1 已验证的 feed-source 三源抽象（mock/csv/u9c）+ audit + ZpConnector 直接搬；mock MVP 已入库（CC `feat/fi2-recon-mvp`，32 tests），引擎按 v3 调整见《开场prompt-FI2口径修正-CC引擎调整交接》。

## 二、规则定稿（唐燕萍团队 2026-07-10 回复 + Paul 拍板，R1-R7）—— FI2 的"灵魂"

| # | 收口项 | **定稿（2026-07-10）** | 来源 |
|:-:|------|------------------|------|
| R1 | **匹配键与容差** | 料品/数量/未税金额/税额，按料品**汇总归集后比合计**。**数量合计 ±0**；**未税金额合计 ±0.5 元/料品**（尾差）；税额随税率。比例口径备用：数量 0%、未税金额 ≤0.5% | 唐团队圈定 |
| R2 | **分批到货拆分** | FIFO 默认 + 支持人工指定 | 唐团队认可 strawman |
| R3 | **匹配结果分类边界** | 按 §四"MVP 口径底稿"五分类 | 唐团队认可 |
| R4 | **必填字段清单** | **项目名称/单位/数量/单价/金额/税率/税额/发票号/开票日期**（较 strawman 增"数量"） | 唐团队圈定 |
| R5 | **L2/L3 门禁阈值** | **比例分母=整单（PO 行）合计未税金额**（比例=差异总金额÷整单合计未税）；**差异总额 ≤1 元 AP 自行消化（L2）、超出走人工（L3）**；比例线按 R1 容差 | 唐团队建议 + **Paul 2026-07-10 拍板同意** |
| R6 | 孤儿单据/PO 变更未同步 | 标记 + 推采购跟单员 | 唐团队认可 strawman |
| R7 | **AP-PO 单价比对容差** | **人民币口径统一 ±2%，超差拦截（方案二起步，零改造）**+ **过渡管控**：三家外币供应商（PO=下单日汇率/AP=发货日汇率）加规则——容差内但**连续 2 次同向偏移 → 推人工抽查**（防"汇率+涨价叠加被容差吞掉"）；**升级路径**：IT 评估 PO 增"原始外币单价+下单日汇率"字段排期，字段就绪后升级方案一（自动拆分汇率差/价格差，价格差一律拦截） | 唐团队 ±2% + **Paul 2026-07-10 拍板：方案二起步+过渡管控** |

## 四、MVP 口径底稿（FI2-2 归集匹配 —— 唐燕萍团队确认边界）

以 **AP 单 vs INV** 为核对主对象（PO 前置参照），按**同一料品汇总归集**后四维比合计，结果分五类：

| 类别 | 判定边界（strawman，待确认） | 处置 |
|------|------------------------|------|
| 🟢 完全匹配 | 料品/数量/未税金额/税额 四维合计全在容差内 | L3 建议通过 →（升 L4）自动进过账队列 |
| 🟡 金额微差 | 仅未税金额合计差 ≤ 尾差容差（±0.5 元/料品） | 标"待确认"，推财务 |
| 🔴 归集错位 | 发票总额与 AP 总额一致、但**分料品汇总互异**（料品 A 合计多、B 合计少） | 拦截，高亮错位料品（**杜绝成本失真的关键**） |
| 🔴 数量/金额不符 | 超容差 | 拦截，推差异清单 |
| 🔴 无 GR 支撑 | 发票无对应入库 | 拦截，标"无入库发票" |

> 汇总归集天然吸收同料品内 AP↔INV 行级多对多，错位检测聚焦**料品间**。另有**第六项独立校验：AP 单价 vs PO 单价 超 R7 容差 → 拦截**（堵配票手动改金额漏洞）。

**唐燕萍团队 6 个决策——✅ 全部落定（2026-07-10）**：① R1 容差 ✅；② FIFO ✅；③ 五类边界 ✅（唐团队"同意以上边界的设置"）；④ R4 字段 ✅；⑤ R5 门禁 ✅（Paul 拍板）；⑥ R7 容差与汇率 ✅（Paul 拍板方案二起步）。
