# 开场 Prompt —— 采购域场景落地专线

> 用法：新开 Cowork Session，**让它读本文件**（不必整段复制粘贴）。短开场词：
> 「读 `1-转型规划/开场prompt-采购域场景落地专线.md` + CLAUDE.md 当前进度恢复上下文，按文件继续。」
> 仅采购域，独立接力，不碰全景路线图那条 Task。下方代码块是任务全文。

```
【新 Cowork Task·采购域场景落地专线】

先读上下文恢复（按序）：
① CLAUDE.md 当前进度（§4 底座/kit_engine、§5 工作分工、§7 红线）
② 1-转型规划/采购域工作任务书.md（采购域现状 + 专员职责）
③ 1-转型规划/采购域场景就绪工作清单.md（P0 缺料预警校准 + 待部署前置）
④ 6-人才与组织/采购部AI专员-首月工作信.md（采购专员 2026-06-29 到位）
⑤ supplychain收割与全景推进策略.md（SC3/SC5/O2 引擎来历）

【本 Task 定位】采购域场景落地专线，独立于"全景规划路线图跟踪"那条 Task。
本 Task 只管采购域（SC1-SC9 + 共用 kit_engine 的 O2）的：缺料预警口径校准、待部署场景
业务对接材料、价值验收设计、治理/汇报——全部 .md。不回填全景排期表、不动 Phase1 接力文件。

【首件事·缺料预警误判口径校准（业务侧）】
采购专员手工核对发现：瓶颈子件里有些卓品库存充足、无订单无请购，却被判缺料/追料。
架构师初判根因＝kit_engine 算可用量时，子件不在库存快照、又无在途，可用量被当 0 → 假缺口
（库存快照覆盖不全/料号口径不匹配，非算法错）。本 Task 要：
  ① 协助专员把"真缺料"业务口径写清（净需求=毛需求−现有可用库存(现货+在途−安全)>0 才算；
     库存够或无真实订单驱动的子件不进追料集合）；
  ② 把口径 + 排查步骤整理成《缺料预警校准需求》交 CC 修（CC 在 LAN 改 kit_engine、跑真实回归）；
  ③ 不在本 Task 改代码/连真实库——那是 CC 的活。

【其余范围】SC3/SC5/O2 部署业务规则确认材料；SC1/SC8 价值验收指标设计；SC2 周报业务需求。

【边界 —— 不做这些】
- 不写生产代码、不连真实库、不发企微（CC 在 LAN 干；本 Task 写口径/需求交接）。
- 不改全景规划/实施计划/前置总表/Phase1 接力文件。
- docx 默认不转，除非我明确要。

【进度记录】本 Task 自建接力文件 1-转型规划/session接力-采购域场景落地.md
（首次创建；收工滚动更新、标日期），与 Phase1 / 质量域 / 财务域接力分开，互不串。
```
