# Paul 标准工作周

> 一句话：**周一批计划，平时只做"发动、签收、拍板"三个动词，其余交给系统。**

## 一、周一早 · 批阅（约 20-30 分钟，唯一固定动作）

8:37 值周巡检自动产出《本周计划-日期.md》。Paul 只做三件事：

1. 调整 A 节任务优先级（砍不急的、提急的）；
2. 回答 B 节决策清单（每条一句话）；
3. 扫 C 节临期红线 + D 节异常警示。

批完即"计划先行"成立，本周不再需要 Paul 编排任务。

## 二、周中 · 三类碰触（每天累计 10-30 分钟，事件驱动）

**发动**：从《本周计划》A 节复制开场词开 session（一天一两条）。session 自行读队列认领、登记触碰区——Paul 不交代内容。
**签收与拍板**：专员回复到件 → 放 `7-外部文档/<部门>/`，说一句"已归位"（R6）；session 抛出的裁决点（每次 ≤5 个）一句话定；重大交付回"验"字触发收货验证。
**放行**：session 报"待 commit 批次"后，一句话交 CC 取活销行。

## 三、周中 · 线下（AI 不可替，VP 本职）

发专员跟进信、开批改会/校准会、对 IT/CFO/CEO 推前置与对齐、签字项（黄金重核/L2/晋档）。

## 四、月度与季度叠加

- **月初**：协同一页纸刷新（对总线说一句）。
- **月底**：价值记分牌 + 收专员一句话进展。
- **季度**：归档批量搬运（R3）、CLAUDE.md 进度段迁编年（R5）。
- **节点**：S 阶段收口前外部对抗性评审（S1≈2026-11 中旬）。

## 五、Paul 不再做的（出现即流程跑偏，值周巡检 D 节告警）

| 跑偏信号 | 应由谁承接 |
|---------|-----------|
| 转述 A 线结论给 B 线 / 截图搬运 CC 报告 | 队列（收工写、开工读） |
| 脑内防撞排程 / 追问"这个谁在做" | 队列触碰区 + 在办状态 |
| 拼开场词 / 写长交接 prompt | 《本周计划》A 节 + kickoff-prompt skill |
| 盯 commit 归属 / 同一 merge 多处发起 | 队列 §二 待 commit 批次（CC 独取） |
| 口径重梳期还有人在建旧口径 | 队列 §三 冻结标 |

## 六、值周巡检自检口径（每周执行）

巡检生成《本周计划》时，对照本文件检查上一周：① Paul 是否被迫做过 §五 表中任何一项（从队列/接力/会话痕迹判断）；② 固定动作是否漏拍（上周计划 B 节决策是否有未回答项遗留）；③ 有偏差 → 写入 D 节并给出机制修补建议；④ **§七 六步循环上周各步有无空转**（哪一步本周零产出、卡在哪个「以人的速度运行的环节」）。本文件内容变更须 Shao Peishen 拍板。
