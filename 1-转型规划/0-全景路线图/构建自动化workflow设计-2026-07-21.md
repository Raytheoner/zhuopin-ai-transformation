# 构建自动化 workflow 设计

> 一句话：**队列是总线,session 是工人,Paul 只做发动/签收/拍板;自动化的目标是把"传声筒"环节(发动、转场)逐步交给系统,把"卫生"环节(worktree/对账)内置进 loop,而决策闸永远留人。**

## 一、六环 loop(实战验证于 2026-07-19~21,A1–A4 全部走通)

```
┌─→ ①计划(值周巡检,自动) ─→ ②发动(Paul 复制开场词) ─→ ③消化(session 自读上下文干活)
│                                                              │
│   ⑥派生(收工自追下游待领行,自动) ←─ ⑤落地(CC commit+push+台账) ←─ ④转场(Co→CC 一句话)
│        │
└────────┘(新待领行回到队列,下轮循环)

侧环(自动): 专员回复 → 企微机器人归档 7-外部文档/ → 自动追加队列待领行
出口(必须留人): 例外/裁决 → §四 → Paul/孙涛 → 销行
```

## 二、每环自动化现状(2026-07-21 打分)

| 环节 | 现状 | 执行者 | 备注 |
|---|---|---|---|
| ①计划 | ✅ 已自动 | 值周巡检定时任务 | 周一出《本周计划》,开场词+【设置】齐备 |
| ②发动 | 🔴 纯手工 | Paul | 逐条复制开场词开 session——两大堵点之一 |
| ③消化 | 🟢 半自动 | session | 自读 CLAUDE.md/队列/接力;【设置】行已免 Paul 判断 |
| ④转场 | 🔴 纯手工 | Paul | 把"交CC一句话"从 Cowork 搬到 CC——两大堵点之二 |
| ⑤落地 | 🟢 半自动 | CC | commit+push+台账,机械可 sweep 化 |
| ⑥派生 | ✅ 已自动 | session | 协议第3条,收工自追待领行 |
| 侧环 | ✅ 已自动 | 企微机器人 | 归档+追行+群通报,07-20 出站(场景①)亦验证 |

**结论:堵点=②发动+④转场,恰是《Paul标准工作周》§五要消灭的"传声筒"信号。**

## 三、三个自动化杠杆(按安全度排序)

1. **塌缩 Co→CC 两步(灭④)**——.md 回灌类任务(轻回灌、无 prod 风险)改为**一条 CC session 读+回灌+commit 一把过**;"两桌分离"只保留给建造/碰真库类。规则:值周巡检出计划时,凡"只编 .md+登批次"的行,开场词直接按 CC 单session 版生成。
2. **落库 sweep 定时任务(灭④残余)**——定时(如每日一次)读队列 §二,把所有"待commit批次"批量 commit+push+台账重跑。Cowork/专线只管登 §二,Paul 不再逐条放行。前提:批次登记规范(文件清单+message 齐备)。
3. **Dispatch 自动派单(灭②,第二阶段)**——队列待领行已含"领取方+开场词+【设置】",由 Dispatch 直接 spawn 对应 session,Paul 从"逐条复制"变"批一下派单队列"。需先小样验证 Dispatch 实际能力与权限边界。

## 四、永不自动化的闸(留人)

design 审(架构拍板)、L2 人工确认门禁(§7)、对客外发开闸、合规红线变更、例外裁决(如 #61 转 IT)。loop 到闸必须停下等 Paul/孙涛;门禁 fail-closed、不因带括注等灰色输入放宽(07-20 机器人发信被门禁正确拒绝一次即范例)。

## 五、卫生前置(不做,越自动越乱)

- **☑ 收工自删 worktree(2026-07-21 定为标准)**:凡 worktree ☑ 的建造 opener,收工段必须写死——推送确认 ahead=0 后 cd 回主工作区 `git worktree remove <本worktree>` + `git branch -d <本分支>`;删不掉则收工报告显式列"待清 worktree"交兜底。
- **值周巡检兜底**:每周扫 ahead=0 孤儿 worktree/陈旧分支,生成清理任务交 CC(巡检只读不删)。
- **开工三查+第四查、对账审计前置**照旧(协议〇.5/〇.6)。

## 六、两阶段落地路线

| 阶段 | 内容 | 状态 |
|---|---|---|
| **第一阶段(安全、机械)** | ①"☑ 收工自删"写入协议〇.5 + kickoff skill 源码(skill 重打包由 Paul 在 Settings 重装生效);②轻回灌任务塌缩为 CC 单session;③落库 sweep 定时任务建立;④巡检加孤儿 worktree 扫描 | 队列 #68 待领 |
| **第二阶段(验稳再上)** | Dispatch 自动派单小样验证→逐步接管"发动" | 第一阶段稳定后启动 |

**验收标准**:Paul 的周中手工动作收敛到《标准工作周》三动词(发动/签收拍板/放行),其中"放行"由 sweep 吸收、"发动"最终由 Dispatch 吸收;连续两周巡检 D 节零"传声筒/git 卫生"偏差告警即达标。
