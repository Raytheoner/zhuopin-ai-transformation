### 〇.0 标题行 ＋ 编号 ＋ 会话名（硬规则；原「补充／补充二／补充三／补充三之三／根治」合并）

- **全称 `OP-MMDD-X` 三处必带**：① opener 代码块**正上方的标题行**（`[OP-MMDD-X]【CC／Cowork】<短名>`，紧挨代码块，**重发时同样带**）；② 本库与派单件的**节标题**；③ **次序与并行矩阵首列**。编号是跨会话世界里的唯一身份，队列行／§二 批次行／收工报告／CC transcript 目录靠它对齐。
- **会话名用短形 `[Win]MMDDX-<主题短名>`**（例 `[Win]0827A-波次收口-解master分叉与四分支合入`）。🔴 **短形只给人眼、只用于 session 名**，其余一律全称，两者不得互换。
- 🔴 **CC 与 Cowork 设定手段不同，不得混用**：CC 侧靠代码块第 3 行调 `mcp__ccd_session_mgmt__set_session_title`（`session_id` 传字面量 `"self"`）——**没有替代品，标题行以 `[…]` 开头不会自动变成 session 名**；**Cowork 侧无此工具**，其 session 名取自**开场词首行** ⇒ **Cowork 开场词首行必须自带编号**，通式「语义在前、编号在后」，写错**无补救路径**（只能由 Shao Peishen 手工改）。⚠️ Cowork 侧「总字节长度限制」未验证，不据以立规则。
- 🔴 **子任务例外句是那一行的一部分，不得删、不得简写**：`🔴 例外：你若是被 Task/Agent 起的子任务，跳过本行不要执行——子任务没有自己的 session，"self" 会解析到父 session、把调度你的那条会话改名`（子任务跑在父 session 上下文里，**调用成功、无报错**）。🔑 **判据：被复制的单位是「那一行」，不是「那条规则」**——指令带隐含前提就把前提写进指令本身，写进规则不会跟着走。
- **开工第二件事：查同题 session**（凡 CC opener 必含）：`git worktree list` 看有无同主题 worktree，并核 `git -C <该 worktree> status --porcelain`；**有即停下回报，不另起一份**。**发起方判据**：同一 opener 重发前先问「上一次粘出去的那个还在跑吗」。**处置**：两个都已开工则保留产出多的、停零产出的，半成品先 commit 到其特性分支、不合 master。
- **补救**：对已在跑的 CC session 说一句「请调 `mcp__ccd_session_mgmt__set_session_title`（`session_id` 传字面量 `"self"`），标题：`[Win]MMDDX-<主题短名>`」，不必重开。

### 〇.1 【设置】行「工作区」字段（硬规则）

- 前三字段答「在哪写」，**工作区答「写完在哪生效」**——缺它就会出现「改完不等于生效」。
- **四种填法**：⑴ 不触碰常驻服务／已部署场景 → `无`；⑵ 触碰 `.51`（8091 保供看板／8092 命令中心／8093 QD-B／8094 FI2）→ 写明「须 `sync-to-server.ps1` 推送 ＋ 重启对应计划任务 ＋ 冒烟三件套（`/api/ping`·关键页 200·一次全量重算）＋ 回滚 SOP 在位」；⑶ 触碰企微机器人 → 写明「须同步 `ops/wecom-service-home` worktree 后重启 `ZhuopinAibotDevListener`，并确认单实例存活」；⑷ 触碰定时任务 prompt → 改的是 `C:\Users\Paul Shao\Claude\Scheduled\<task>\SKILL.md`（**仓库外、不入 git**）四步走：① `update_scheduled_task` 改真身 → ② **回归自检原有纪律未丢失**（整段替换、极易丢旧条款）→ ③ 跑 `0-学习与工具/工具-定时任务源码备份.py` 回镜（**判据＝规范化逐行比对，不得用裸文件哈希**）→ ④ 登 §二 批次。
- ⚠️ **方向单向：真身 → 镜像，改镜像不生效。** 🛡 回镜一致性由 sweep 每小时兜底；改真身仍只有手工一条路径。
- **自检一问**：*本次改动，有没有任何一份「正在跑的副本」不在我改的这个 checkout 里？* 有 → 写进字段；没有 → 填 `无`。

### 〇.2 命名不得与执行环境标注冲突（硬规则）

- 文件名与标题里 `CC`／`Cowork` **一律且只能表示执行环境**，用方括号 `【】`；**线名一律不带执行环境词**（本线统称「环境保障线／环境总线」），「为谁服务」写进定义段、不写进名字。
- **历史记录不追改**；存量 7 份无 `执行环境` 字段的 opener **自然收口**（谁认领谁顺手补）。⚠️ **季度清扫勿把这 7 份当命名不合规批量改名**——刻意决定，不是遗漏。
- **推广**：已有固定含义的词（`CC`／`Cowork`／`master`／`live`／`dry-run`／`P0-P3`／`SC*`／`FI*`／`QD-*`／`B-*`／`#编号`）不得在同一文档体系里表达第二种含义。命名前问：*这个词在本项目里已经有专属含义了吗？* 有 → 换词。

### 〇.3 开场澄清分四类 ＋ 两条形态规则（硬规则）

- **形态规则（全类适用）**：① **禁开放式提问**，一律给带推荐项的选择题，写清选项差异与各自代价；② **数量随差异数量走**——全通过、无歧义 ⇒ **0 个直接干**；有 N 处需拍板 ⇒ 问 N 个。「2-3 个」只作上限提醒（超 3 个说明 opener 本身没写清，应先补 opener）。
- **四类**：**A 同线转场** ⇒ 先跑「开工自检三查」，全通过即直接干、不问，有差异只就差异出选择题（三查写在 opener 文件里，便于按线定制）；**B 跨线交接** ⇒ 必问；**C 新任务／新场景** ⇒ 必问，且 opener 内预置候选问题；**D 定时任务 prompt** ⇒ 🔴 **绝对禁止任何需要人当场回答的指令**（非交互 session 没人能答，写了即空转），靠「预案覆盖 ＋ 歧义登 §四」。
- **A 类开工自检三查**（A 类 opener 须内置）：① **接力新鲜度**——接力件最新日期节是否等于上一次收工日，不等则先读差异；② **清单一致性**——从 §四 在办清单抽 2 行与队列**实际状态列**逐字比对，不一致**以队列为准**并列出差异；③ **降级残留**——四条接力件顶部「⏳ 队列更新待补」有内容则先回补。全通过 ⇒ 一句「自检三查通过，按 §四 优先级从 X 开始」；任一不通过 ⇒ 就差异出选择题。
- **落点**：本库 §一~§五 各范例、`zhuopin-kickoff-prompt` skill 步骤 1 与骨架、各 A 类 opener 正文。

### 〇.9 建行前先做「并入审核」；机制类还要看「可动 WIP」（协议〇.9／〇.10）

### 〇.11 【设置】行「session」字段（硬规则）

- **新开**（默认）＝独立队列行／独立触碰区／不依赖现存对话上下文；**续用〈名〉**＝是某个**仍开着**的 session 的收尾、勘误，或依赖它才知道的中间结论；**皆可**＝罕见，**必须写明为何无所谓**，不得用它回避判断。

### 〇.15 CC 复命取件算法与「线 vs session」术语

> 规则本体与三条边界见 `.claude/rules/两桌同步与取证.md`；本节是执行时才需要的手册层。

- **算法**：⑴ **时间窗全取，不取「最新一条」**——圈定 `C--Users-Paul-Shao-OneDrive-Projects---AI--*` 下自上次取件以来有新写入的全部 `*.jsonl`；⑵ **逐条归属**——读首条 `type=user` 消息（＝他粘的开场词，必含【设置】行与派单件完整路径），正则提出派单件路径；⑶ 读该派单件 frontmatter 的 **`派出线:`**，只收与本线匹配的；⑷ **回报读到哪几条、各自归属**，使漏读与误收当场可见。
- 🔴 **字段是 `派出线:`，不是 `来源:`**（后者已被占用为「任务从哪来」，不得一词二义）。**存量件回落两级**：查 `来源`／`派发方` 是否恰好写了线名，否则 `git log --diff-filter=A` 取建档 commit → 批次名，或编辑锁 `history.who` 前缀（即线名）。
- **三类兜底一律明说、禁止静默**：提不出派单件路径／派单件无该字段 ⇒ 按上句回落、再不确定就问一句；匹配到 0 条 ⇒ 明说「本线名下无新完工 CC」。

### 〇.16 变更包这次不归档，理由必须写在机器认得的地方

- 三个入口择一：**`暂不归档`**（写在 `proposal.md`／`design.md`／`tasks.md` 任一处＝作者对未来的永久声明，明知长期不会归档时用）／**`预期观察窗口：N 天`**（命中即报「🔭 观察中」、**不计异常**，超窗才升级；在等一件会自然发生的事时用）／**`工具-落库sweep.py --ack-stale-change <包名> --note <依据>`**（复核者对过去某一刻的确认，带 `done/total` 指纹，**tasks 一有新勾选即自动失效**）。🔴 **`--note` 不可省**——它就是这条声明的依据本身。
- ⚠️ 写在 tasks 未勾项行内的自然语言**机器读不到**，不要指望写得更清楚就能绕过；**要求一个特定字符串正是它有价值的地方**。🛡 判定器＝`0-学习与工具/工具-变更包自动归档.py`（**只判定、不归档**），sweep 分三类：真遗忘／已写理由但没用机器入口／尚有真未完项。⚠️ **`archive` 行照旧写进 tasks**（曾被要求禁掉，该前提已被实测推翻两次）。

### 〇.18 命令块「执行端」标签（硬规则）

- **`▶ 执行端：CC`（默认）**——凡不需提权的动作（建造、测试、只读取证、跑脚本、git、批量改档）；🔴 **他可 remote-control 接管**。
- **`▶ 执行端：管理员 PowerShell`**——只有真需提权时（计划任务 `Register`／`Enable`／`Disable` 需 SeTcbPrivilege、`robocopy /COPYALL` 需 SeSecurityPrivilege、改系统级配置）；🔴 **必附一句写清是哪个特权**。
- **`▶ 执行端：我来跑，你不用管`**——只读取证，我自己经本机通道跑完给结论。
- 🔴 **「普通 PowerShell」此后基本不该出现**：正要写它时先问「这件事为什么不能交给 CC？」答不上来就改 `▶ 执行端：CC`。**自检**：*跑到一半他离开电脑还能接管吗？* 不能且并不需要提权 ⇒ 档位选错了。

### 〇.19 opener 是一次性动作，不是状态（人守 1/3，已提前机制化）

- 🔴 **一个 opener 只贴一次。** 后续要提它**只许写一行状态**（「`OP-0901-G` 已派出、等其回报」），**不得再出现代码块**。🔑 **状态可反复陈述而无害，动作重述一次就是重派一次**——他对每个 opener 的默认前提是「给我的就是要我做的」，破坏一次，此后派工成本永久上升。
- 🔴 **代码块正上方必写状态标记，四选一**（三式正本见 `opener骨架.md`）。**判据的参照物是「他执行了没有」，不是「这个编号出现过没有」**：新任务 ⇒ `▶ 首次派出` ＋ 新编号 ＋ 完整块；**已给出、他还没发出而需改内容** ⇒ `▶ 更新版` ＋ **沿用老编号**（编号是「这件活」的身份，活变了才换号）；**他已执行且一字未改** ⇒ 🔴 **禁止**，只写一行状态；他已执行但确需重跑 ⇒ `▶ 重发` ＋ 正文首句「若你已跑过这条，忽略本次」；**判不准** ⇒ **先问一句、不发块**（不确定时发块＝赌他没执行）。
- 🔴 **边界：本条只管「同一个 opener 的第二次」，完全不管「新任务的第一次」**——新任务、新编号 ⇒ 照常给完整块（标题行 ＋ `【设置】` 六字段 ＋ `set_session_title` 整行 ＋ 正文），**一个字都不许省**。
- 📌 **可 lint 化落点**：同一会话内已出现过的 `[OP-MMDD-X]` 再次出现在代码块里**且块前无状态标记** ⇒ 告警；**不能一见重复编号就报**，否则会连正当的「更新版」一起拦掉。
- 🔑 **判据（比本条更耐用）**：**为纠正一次违规而立的规则，最容易在下一次被过度适用** ⇒ **写下一条禁令时必须同时写清「它不管什么」**；只写「不许做 X」而不写「但 Y 照旧」，下一次就会连 Y 一起停掉。
