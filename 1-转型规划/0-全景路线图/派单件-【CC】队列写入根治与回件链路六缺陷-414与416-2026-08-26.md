# A 组 · 队列写入根治（#414）

## A1 · 病灶复述（一句话）

**队列单元格的文本经 bash argv 传入，而本项目行文规范要求大量使用反引号与竖线；调用方还必须自己数 `split` 后的列下标。三条都靠人记，实测 2026-08-25／26 两天内犯了 5 次。**

| # | 形态 | 内容变成了什么 |
|:-:|---|---|
| 1 | 裸竖线撑列 | Markdown 表格的**分隔符** |
| 2 | 反引号被 bash 执行 | **命令**（曾把 25 行 `git worktree list` 输出注入进单元格） |
| 3 | 列位错置 → 触碰区格 | 落进**相邻格** |
| 4 | 列位错置 → **编号格** | **行头断裂**，`grep` 与队列查询双双找不到该行 |
| 5 | 裸竖线撑列（再犯） | 🔴 **发生在「解释这个 bug」的那一行正文里** |

## A2 · 三条修复面（🔴 A 与 B 已在 #414 行内，C 是 2026-08-26 新增且最关键）

### A · 反引号侧 —— 让正文不再经过 shell
给 `工具-共享文档编辑锁.py append-row` 增加 `--cells-json <文件>` 或 `--stdin-json` 入口，单元格内容以 JSON 传入，**argv 里不再出现正文**。反引号、`$()`、引号一律失去特殊性。

### B · 绕过侧 —— 守卫要守住所有入口
现状实测：**竖线守卫已存在且有效**（`append-row` 会当场拒绝含竖线的 `--cell`），但**直接改队列文件的路径（python 插行、整文件重写）完全绕过它**。
⇒ 把单元格校验抽成可被两边调用的函数；**凡写盘前一律复用同一套校验**。
🔑 这一条的价值：**一道已经存在且有效的守卫，因为存在一条绕过它的常用路径而形同虚设**——同族＝「机制建成 9 天却从没真正发出过一条消息」（OP-0819-F）。

### 🔴 C · 列位侧 —— 让调用方永远不必数下标（2026-08-26 新增）
A 与 B **都挡不住列位数错**（第 3、4 次事故正是如此）。
⇒ 提供**按列名写入**的接口，例如：
```
append-row --section 一 --number 416 --set 任务="..." --set 状态="..." --set 触碰区="..."
edit-row   --section 一 --number 416 --append 状态="..."
```
**内部按 §一/§二/§四 各自的列序映射，调用方只写列名。**

## A3 · 顺带修的两处

- **lint 列数盲区**：实测 `#414` 一度为 **13 列**（`awk -F'|'` 数得出），而 `工具-队列结构lint.py` **报通过**。请复现并修。
