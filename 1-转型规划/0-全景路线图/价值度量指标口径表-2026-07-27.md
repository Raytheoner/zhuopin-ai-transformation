# 价值度量指标口径表 · 起步版

## 〇、为什么现在做（一句话）

现有指标全是**过程**指标（测试数、零回归、批次落库），上线场景的**结果**指标至今零个真实数字。**SC8 已上线两周，现在补"上线前后对比"的基线还来得及，再拖一个月就说不清了**——这是本表唯一的时效性理由。

**本版交付的是口径与方法，不是数字。** 数字由业务专线按 §二/§三 的方法采集。

## 〇bis、统计起算日：开发排错期数据一律排除（Shao Peishen 2026-07-29 定，**优先于本表其余所有条款**）

**背景**：2026-07-29 现状是——保供看板的业务数据本身**还没对准**（#139 中 #19「只取核准状态」经真实探测证实现有接口无行级状态字段、做不了，44/116 行逾期噪声仍在；#18-c 的 365 天回溯窗口是折衷非根治）。此阶段专员**每一次打开看板都是在排错、不是在做业务**。

**若把这段时间的访问计入"周活跃"、把这段时间的误判率当基线，指标从第一天就是脏的**——既高估了使用（排错访问≠业务使用），也污染了改善幅度的对照基准。

### 三条硬规则

1. **各场景各自设「统计起算日」**：＝该场景**业务数据对准、正式转入真实业务试用**之日。起算日之前的所有访问、误判标注、工时记录**一律排除**，不进任何指标、不进记分牌。
2. **起算日由业务侧认定，不由技术侧宣布**：以该域专员**书面确认"数据可以用了"**为准（同判据类口径的显式签认原则），不以"部署完成""测试通过"为准。技术上线 ≠ 业务可用。
3. **起算日必须记录在案**：写入本表对应场景节 + 场景 CLAUDE.md「部署状态」段；年底举证时一并出示，说明统计区间为何从该日起算。

## 一、可复用模板（新场景上线时照此补一行）

| 字段 | 填写要求 |
|---|---|
| **场景** | 场景号 + 名称 + 当前上线档位（档1 mock／档2 真实跑通／档3 内部服务／档4 对客交付） |
| **指标名** | 1-2 个，**必须是结果指标**（业务侧可感知的变化），不得填过程指标（测试数、上线数、代码量一律不算） |
| **类型** | 价值型（工时节省／延期挽回／风险拦截）｜ 使用型（周活跃，对应年度达标线"使用线"） |
| **定义（算式）** | 写成可执行的算式，含分子分母口径；有歧义处显式约定 |
| **采集方式** | 谁、多久一次、从哪个系统／日志／表单取；**优先自动采集**，人工标注要写清抽样规则 |
| **基线取值方法** | 上线前的值怎么来。**抽样估算可接受**，但必须写清抽样口径（样本量、抽样对象、时间窗、由谁判定） |
| **基线时点** | 基线代表的是哪个时间点的现状（上线前哪一天／哪个版本） |
| **前后可比性** | ⚠️ 必填。基线与上线后是否同口径；不同口径的，写明如何对齐，或明确"只作趋势参考不作结论" |
| **责任人 / 首次交付日** | 谁采、什么时候给第一个数 |

> **三条硬约定**
> 1. **每个上线场景 ≥1 个价值型指标**，否则该场景在年度达标线"价值线"上不计数。
> 2. **基线必须在场景上线后 4 周内锁定**，逾期该场景只能报"上线后绝对值"、不能报"改善幅度"（说不清就不硬说）。
> 3. **指标不得由建造方自评**——判定权在业务侧（采购口径归姚祖怡、质量归陈忱），同判据类口径的权威单点原则。

## 二、SC8 保供看板（档3 内部服务，2026-07-16 上线试用，07-23 功能批1）

### 指标 1 · 缺料预警误判率（价值型 · 风险拦截）★优先

| 字段 | 内容 |
|---|---|
| **定义** | 抽样成品行／子件行中「系统判定 ≠ 采购实判」的条数 ÷ 抽样条数。误判含两向：**假缺料**（系统报缺、实际有货或已有确定答交）与 **假齐套**（系统报按期、实际缺）。两向分开统计，**假齐套权重更高**（它才会真造成停线）。 |
| **采集方式** | **首选**＝队列 #110 看板行内 `✅正确／❌误判＋原因` 按钮 → 写 JSONL → 每周机器人汇总（P2，08 月排期）。**按钮上线前的过渡方案**＝每周由一线（解植雅／汤易水）对**随机 20 行**做标注、姚祖怡只裁分歧项（同判例批改法的一线标注层分工）。 |
| **基线取值方法** | **已有现成真实素材，不需另跑**：`1-转型规划/缺料预警校准-误判案例对照表与批改会材料-2026-07-07.md` 用真实四源（FO 116 行／BOM 1937 行／Stock 六仓／近 90 天 2810 笔 PO）跑**未改造的现状引擎**，得：判"缺料"总数 **223**、其中疑似误判候选 **63**（＝缺库存快照 ∩ 判缺料），**疑似误判率 63/223 ＝ 28.3%**。 |
| **⚠️ 前后可比性（关键，勿跳过）** | 上述 28.3% 是**自动近似口径**（"缺快照∩判缺料"），而上线后采集的是**人工标注口径**——**两者不能直接相减**。要得到真正可比的基线，需补一步：**对那 63 条做一次人工确认**，得出其中真误判占比 p，则可比基线 ＝ `63 × p ÷ 223`。这一步是本指标唯一的额外工作量。 |
| **建议做法** | 那 63 条本就是给姚祖怡的批改会材料（三步法第 1 步），**不必全量确认**——抽其中 20 条请一线标注、姚裁分歧，即可得 p 的估计值。**≈45 分钟一次性投入，锁死一个能用一整年的基线。** |
| **基线时点** | 2026-07-07（多层 BOM 展开 B1、净额开关翻 ON、PO 在途接入**均在此之后**——即基线代表的是"这些改造之前"的现状，正是我们想对照的起点）。 |
| **责任人 / 首次交付** | 采购专线组织标注 → 姚祖怡判定；**建议 8 月上旬前锁定基线**（离 07-16 上线满 4 周，卡在硬约定 2 的边界上）。 |

### 指标 2 · 追料工时（价值型 · 工时节省）

| 字段 | 内容 |
|---|---|
| **定义** | 采购员每周花在**「确认某成品/子件到底缺不缺、缺多少、该催谁」**上的小时数。**只计"查状态＋确认要不要催"**；**不含**与供应商的谈判、下单、议价、催货沟通本身（那部分 AI 不替代，混进来会虚增收益）。 |
| **采集方式** | 每月一次、连续一周的**自记录**：参与者每天下班前记一个数（当天花在上述动作上的小时数），一周求和。参与者＝姚祖怡 + 解植雅 + 汤易水（3 人）。取 3 人**中位数**而非平均（防单人异常值）。 |
| **基线取值方法** | **抽样估算可接受**（Paul 07-27 认可）。两步：① **回忆式估算**——3 人各答一句"看板上线前，你一周大概花多少小时在查缺料状态上"，取中位数作**初值**；② **一周实测**——用上面的自记录法测一周**上线后**值。⚠️ 回忆值有系统性高估倾向（人倾向高估痛苦时间），故**结论只报改善区间、不报单点**，并在记分牌上明确标注"基线为回忆估算"。 |
| **更可靠的交叉验证（可选）** | 看板 `/api/baoguan` 访问日志（#112 埋点后）＋ 每次访问替代掉的手工动作数（查 ERP 库存 → 查 SRM 答交 → 展 BOM 三步），可反推节省量级，与自记录互相印证。 |
| **基线时点** | 采集当日现状（回忆值指向 2026-07-16 上线前）。 |
| **责任人 / 首次交付** | 采购专线发起、姚祖怡组织；**建议随指标 1 的标注会同场做**（同一批人、同一次会，边际成本近零）。 |

## 三、QD-B 立项审核门禁（试用版，2026-07-23 发布 + 灰度陈忱/朱映桦）

> **🔴 价值叙事重心已定（Shao Peishen 2026-07-31 拍板，§四 #41，选项 (c)）：记分牌两个指标都留、但年度达标线「价值线」只用「风险拦截」举证，工时降为附注。**
>
> **触发事实**——陈忱 2026-07-31 给出两个真实数字（回件 `7-外部文档/质量部/...de8d3b20...md`，#181）：① **人工评审一份立项书约 0.5 小时**；② **AI 判定结论与人工一致，且 AI 抓到了人工过一遍时漏掉的扣分项**（他举的实例＝"数据的一致性是否满足"）。
>
> **为什么改重心**：0.5h/份 是**工时节省的上限**，而上线后的口径本就含"人工复核 AI 报告"的时间（见指标 1 定义），扣掉之后**净节省可能接近零、甚至为负**——拿它当主叙事，年底举证会自己把最弱的一面推到台前，反而稀释真正价值。真正被数据支持的价值是**拦住了人会漏的项**：那是人工评审在 0.5 小时里做不到的事，不是做得慢的事。
>
> **选 (c) 而非 (b) 的理由**：(b) 要改口径表并请陈忱把记法从"计时"换成"逐份记多抓了哪几项"，等于返工采集口径、且工时数据从此断流；(c) **两个都继续采、只改举证时用哪条**，不丢数据、不返工，代价仅是记分牌上多一行。

### 指标 1 · 单份立项书评审工时（价值型 · 工时节省）｜**附注型，不作年度达标线举证**

|---|---|
| **定义** | 从拿到立项申请书到出具《立项审核报告》的耗时（小时/份）。**上线后＝上传耗时 + 人工复核 AI 报告的耗时**（不是只算机器跑的几秒——那会把收益吹成 100%，不诚实）。 |
| **采集方式** | 每份走门禁的立项书记录一次（陈忱/朱映桦在灰度期顺手记：上传时间、复核完成时间）。样本累积到 **≥5 份**再出结论。 |
| **基线取值方法** | **抽样估算**：请陈忱对**最近 3-5 份已人工评审过的真实立项书**回忆估算"当时按 80 条规则逐条过一份要多久（含填表、核对财务数据、写报告）"，取中位数。⚠️ 同样标注"回忆估算"。 |

| **前后可比性** | 口径一致（都是"一份立项书从收到到出报告"的端到端工时），可比性较好——比 SC8 那个指标干净。 |
| **基线时点** | 2026-07-23 上线前（20260717 权威表已定版，规则条数一致，无口径漂移干扰）。 |
| **责任人 / 首次交付** | 质量专线向陈忱要；**建议随 #116（Excel 导出）交付后的第二轮灰度反馈一并问**，不单独发信。 |

### 指标 2 · 风险拦截（价值型）｜**★ QD-B 年度达标线「价值线」唯一举证指标**

> 本指标含**两个子项**：2a 判定一致率（说明"AI 判得准、可以少复核"）、**2b AI 多抓项数（说明"AI 抓住了人会漏的"）——2b 是举证主口径**，2a 退为其前提条件。

#### 2b · AI 抓到而人工漏掉的扣分项数（★主口径，2026-07-31 升格）

| 字段 | 内容 |
|---|---|
| **定义** | 每份立项书中，AI 报告标出扣分、而人工评审同一份时未标出的扣分项**条数**（按项计，不按分值）。 |
| **为什么是主口径** | 它测的是**人工评审在 0.5 小时里做不到的事**，而非做得慢的事——这是 QD-B 真正不可替代的价值，也是唯一不会被"人工复核 AI 报告也要花时间"抵消的收益。 |
| **已有真实证据** | 陈忱 2026-07-31 明确举出实例：**"数据的一致性是否满足"这一扣分项，AI 抓到、人工过一遍时漏掉**（#181 回件原文）。 |
| **采集方式** | 灰度期每份立项书，陈忱在给人工结论时**顺带记一句"AI 多抓了哪几项"**（记项名即可，不必记分值、不必计时）。**注意本指标无分母**，只能报绝对条数与出现频次（每 N 份中有多少份出现 ≥1 项），不要写成百分比。 |
| **基线** | **不适用**——人工评审本来就不产出这个数（漏掉的项人工自己不知道），故**无"改造前基线"可比**，直接从上线后累计。这是与工时类指标的本质差别，举证时须写明，否则会被追问基线。 |
| **责任人 / 首次交付** | 质量专线；**≥10 份时出第一次结论**，与 2a 同批。 |

#### 2a · 判定一致率（代理指标，退为 2b 的前提条件）

| 字段 | 内容 |
|---|---|
| **定义** | AI 判定结论（合格/不合格＋驱动规则）与人工评审结论一致的比例。 |
| **为什么用它当代理** | 真正想测的是"门禁拦住了多少本不该立项的项目"，但该指标需要**事后回溯**（项目做砸了才知道当初不该立），2026 年内拿不到闭环数据。一致率是当下可测、且直接支撑"能不能减少人工复核"的决策依据。 |
| **采集方式** | 灰度期每份立项书由陈忱同时给人工结论，与 AI 报告比对。 |
| **基线取值方法** | **已有现成基线**：黄金三样本（EQ17 合格 98.80 分／邦奇、华丰不合格一票否决，driving rule 74/11）**AI 与人工判定 100% 一致**（`data/golden/manifest.md`，2026-07-23 部署冒烟已复验）。基线＝**3/3**，样本量小需扩到 ≥10 份才有统计意义。 |

## 五、本表没做什么（边界说明，防误用）

1. **不覆盖未上线场景**（Paul 07-27 定）——40 个场景里 38 个未上线，给它们预写指标是纸面工作；上线时按 §一 模板补一行即可，模板已写成可复用形态。
2. **不填数字**——本版只定口径与方法。任何人看到本表里出现具体改善幅度，那一定是后续回填的，且应带采集日期与责任人。
3. **不替代 #112 埋点**——使用型指标全部依赖埋点，本表只定义"埋点埋好后怎么算"。**#112 不做，使用线就是无源之水。**
4. **不做归因**——本表只测"变了多少"，不论证"是不是 AI 导致的"。真要做归因需对照组，当前规模不值得。改善数字对外呈述时应如实说明这一点。
