## 🔴 开工前必须先读懂的一件事：**这三步里只有一步能真正隔离**

原方案 §八 写的是「用一份复制副本走一遍 S3 第 10／12／13 步」。**取证后发现这句话有问题**，因为后两步作用的对象是**全机唯一**的：

| S3 步 | 对象 | 能否在副本上隔离演练 | 本派单件的处置 |
|:--:|---|:--:|---|
| **10** worktree repair | 副本自己的 `.git` | ✅ **完全隔离** | **照演练**，测耗时 |
| **12** editable 重装 | **全机唯一** site-packages | ❌ **装不进副本，一装就改生产** | 🔴 **改判：这不是演练，这是直接修 §一 #406**——见下方 T2 |
| **13** 计划任务重注册 | **全机唯一** 任务计划库 | ❌ 重注册即覆盖生产任务 | 🔴 **改判：跑影子任务**（改名 + 禁用），验通后删除——见下方 T3 |

**⇒ 判据：「在副本上演练」只对"随目录走的东西"成立；对"全机单例"（site-packages、任务计划库、注册表、端口）不成立。**
把全机单例的操作叫作"演练"，等于在生产上做了一次真操作却以为自己在沙盘里。

**本派单件据此把范围重排为 T1/T2/T3 三件，逐件独立可停。**

## T2 · editable 幽灵 import 修复（**这是修 §一 #406，不是演练**）

### 🔴 T2 开跑前的独占自检（**硬前置，不通过即停下问 Shao Peishen**）

**理由**：T2 有一段窗口——`pip uninstall` 之后、`pip install -e` 之前——**10 个包全部 import 失败**。任何并行的 CC 会话若在这段时间跑 `pytest`，测试会莫名其妙地红，**而那个会话不会知道原因，只会去查自己的代码**。

⇒ **开跑 T2 前必须确认自己是唯一在跑的 claude 会话**：

```powershell
# 应只剩本会话自己；出现任何其它 claude 进程即停下回报，不得自行判断"那个应该没在跑测试"
Get-Process claude -ErrorAction SilentlyContinue | Select-Object Id,StartTime,@{n='CPUmin';e={[math]::Round($_.CPU/60,1)}}

# opener 批处理 runner 必须为空
Get-CimInstance Win32_Process -Filter "Name='powershell.exe'" | Where-Object { $_.CommandLine -like '*opener批处理执行*' }
```

⚠️ **已知复杂情况（2026-08-25 实测）**：本机有 **16 个 claude 进程自 08-21 存活至今**，它们**未必在跑测试**，但**也无法从进程信息判断在不在跑**。⇒ **本自检的正确姿势不是"自己判断哪些无害"，而是把清单原样回报给 Shao Peishen，由他确认后再动。**（同 §一 #170 的「逐个核对再清、宁可不清不可错清」判据。）

**T1 与 T3 不受本自检约束**——它们只碰副本目录与影子任务，可与他人并行。
