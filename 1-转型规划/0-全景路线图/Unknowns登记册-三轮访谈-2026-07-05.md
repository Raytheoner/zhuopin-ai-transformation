# Unknowns 登记册（2026-07-05）

## 一、被击落的假设（Paul 比文档显示的更稳，记录在案防止重复怀疑）

法务对 LLM API 使用有明确意见（口径=构建期脱敏数据可用 API，运行期敏感数据本地化）；CEO 已给六部门全员 mandate；Paul 缺席有代理人能拍板；IT 有专人且项目进其绩效；项目级止损有腹案（收缩深耕）。——这五项访谈前在全部项目文档里**零证据**，是"文档盲区"而非"认知盲区"。教训本身值得记：**Paul 脑中的项目 ≠ 文档中的项目**，下面 8 项 unknowns 大半也源于此。

## 二、坐实的 Unknowns（按严重度排序）

### U1 🔴 本地 LLM 迁移是公司级技术路线，但项目文档零记载

**事实**：切换 Gemma 级开源模型 LAN 部署的计划真实存在——有预算、IT 正式评估搭建中、可外请专业部署团队；运行期财务数据/客户实名订单不出局域网。但全景规划技术架构章、实施计划、前置总表、预算章**均无一字记载**。
**为什么重**：LLM 运行时场景（QD-B B 类语义判据、Q2 8D 根因、Q1 客诉分流、R 系列、SC8 case_draft）恰是 2026-10 起的主力，它们的档 3/档 4 隐性依赖这次切换；开源模型与 Claude 的能力差距意味着**所有 LLM 判据换模型必须回归**——而现在的黄金基准只覆盖确定性引擎（kit_engine/对账/规则评分），**LLM 判断类任务没有黄金集**，切换那天将无从验证"变笨了多少"。
**行动**（三件）：① 全景规划架构章补"运行时模型策略"一节（构建期 API+脱敏 / 运行期本地化，切换时点与场景档位的耦合关系）——Cowork，随 D-A 落档一并做；② **建立 LLM 判据黄金集机制**：每个 LLM 运行时判断（QD-B B 类 10 条、8D 预填 12 字段等）冻结"输入+专家认可输出"样本集，作为换模型回归的验收基准——CC，随各场景建设累积，QD-B 先行；③ 数据分级路由表成文（哪类数据可出 API/哪类必须 LAN，把法务口径从"Paul 知道"变成"团队可查"）——Cowork 起草、法务确认签发。

### U2 🔴 U9C 实时库存 OpenAPI bug 不在任何依赖追踪表，且与缺料误判 P0 大概率同源

**事实**：实时库存 OpenAPI 有 bug、**原厂（用友）未回复**、当前库存数据是错的、采购组因此零使用——等接口通了才会全员用。此项不在《U9C接入与连接器收敛-待办追踪》，不在 §七.2 外部依赖红线表。
**为什么重**：① 它是 SC1"已上线"与一线使用之间的真实闸门；② 库存数据错 ≈ 缺料误判 P0 的数据侧根因（kit_engine 假缺口），但两条线在文档里互不相认——采购域专线在修口径，没人在跟原厂 bug；③ O2/SC5 八月 CSV 试用的数据可信度同样受它牵连（CSV 直接从 ERP 导出可绕开 OpenAPI bug，但须显式确认导出数据对）。
**行动**：① 入 §七.2 外部依赖表新行（owner=IT 专人，设原厂跟催红线日，逾期升级 Paul→用友客户经理）——Cowork 落档；② 缺料校准需求 §4-B 与此项建立交叉引用，CC 排查步骤 2 增加"OpenAPI bug 影响面核对"——随 fix 走；③ CSV 试用启动前做一次"导出数据 vs 实物抽盘"的 10 料抽验——采购专员，8 月初。

### U3 🟠 风险型价值没有反事实基线（你自己选的主战场，弹药未备）

**事实**：你拍的价值兑现策略=靠拦截延期/呆滞/停线，但历史基线"只能事后估"。年底说"拦截 30 次缺料"，CFO 一句"以前一年才停几次线？"就能让价值叙事失血。
**行动**：财务+PMC 回溯整理 **2025-2026H1 错配成本基线**——停线次数、客户延期罚款/索赔、呆滞跌价计提、加急运费四项（全部在财务凭证和生产日报里，整理成本约 2-3 人天）——8 月底前成文，作为 D-4 价值验收和年底汇报的对照组。**这是本登记册性价比最高的一项。**

### U4 🟠 一线使用率没有测量管道

**事实**："部门全员使用"是预期状态，但保供看板/SC1 无访问日志，周活跃用户数无从报出。使用率 KPI 在全景 §6.2 定了，测量手段没建。
**行动**：价值记分牌加"周活跃用户"必备列；保供看板补访问日志（与待办 #10 外网鉴权同一次改动，CC 顺带）；采购组用起来的第一周即有数。

### U5 🟡 对客 AI 沟通有计划、无落点

**事实**：你计划 SC8 开闸前与客户沟通，但开闸前置条件（SRM 接通+L2 签字）里没有这一条。
**行动**：SC8 场景 CLAUDE.md 与 SOP 的开闸条件加第三项"主要客户 SQE/采购已沟通知悉"——Cowork 一行字，防将来任何人以为两条件齐了就能开。

### U6 🟡 代理人机制未系统化

**事实**：有代理人能拍板，但 B3 审批配置（VP_APPROVERS）和治理文档未见此人；代理规则（哪些能代、哪些必须等你）未成文。
**行动**：代理人实名入 VP_APPROVERS 配置与治理文档，代理边界写三行（可代=design 审/批间 Triage；不可代=对客开闸/预算/红线变更）——CC 配置 + Cowork 文档。

### U7 🟡 冷备架构师从未演练

**事实**：公司有同级架构师可顶上、也备了向其他 Agent 迁移的路——但那位架构师没读过这套代码，是"未验证的冷备"。
**行动**：S1 收口前（11 月中旬外部评审同期）安排一次 1 天接手演练：读根/场景 CLAUDE.md → 跑全量测试 → 独立修一个 P3 小项。演练即验证，顺带产出"接手指南"缺口清单。

### U8 🟡 项目级止损预案未成文、"达标"定义未与 CEO 对齐

**事实**：你有腹案（收缩深耕，保 2-3 条高价值链），但没写下来，且"年底达标"的定义（几个场景/多少价值算过关）未与管理层显式对齐——届时容易被别人替你定义成败。
**行动**：半页《年度达标定义与收缩预案》——达标线（建议：链 D 先手两联动点通 + ≥5 场景档 3 且周活跃达标 + 风险型价值有基线对照）+ 不达标动作（收缩深耕的具体保留清单）——Cowork 起草，你与 CEO 十分钟对齐。
