# `#627` 根治 A · 批处理侧（`工具-opener批处理执行v2.ps1` ＋ `工具-opener派出前校验.ps1`）

## 一、本件只做四件，别扩面

### ⑴ 🔴 150k／250k 上下文闸：给它装一个**有消费者**的硬闸（本件核心）

**现状**：`0-学习与工具/hooks/hooks-posttooluse-context-meter.ps1` 已经在每次工具调用后把当前上下文写进 `reports/context-meter/<session_id>.json` 的 `lastContext` 字段（＝`input_tokens ＋ cache_creation_input_tokens ＋ cache_read_input_tokens`），并在 150k 分档与 250k 硬线各发一条 `additionalContext` 提醒。**但它只提醒泳道自己，没有任何消费者**——2026-09-20 实测七条泳道上下文峰值 244,434／228,308／213,218／194,282／163,826／155,660／151,036，**无一例外 ≥151k，`CLAUDE.md` §3 的转场线零条执行**。

**要做的**：`工具-opener批处理执行v2.ps1` 已经为每条 opener 生成 `session_id`（GUID，写在该泳道日志首行 `session=<id>`），**它就是那个天然的消费者**。在等待该泳道 claude 子进程期间周期性读 `reports/context-meter/<session_id>.json`：
- `lastContext ≥ 250000`（硬线，Shao Peishen 2026-09-16 答 `1a` 既定）⇒ **终止该泳道整棵进程树**，按 `OPENER_PARTIAL: 上下文转场（≈Nk）` 记账，并**自动排一条续棒**；
- `lastContext ≥ 150000` ⇒ 只记录峰值，不终止（软线语义不变）；
- 🔴 **续棒必须新开 session，禁止 `claude --resume`**——2026-09-20 实测：看护者用 `--resume` 续了三段，三段压在同一 session 里上下文累积到 **238,175**、111 次请求、`cache_read` **16,020,384**，成为当日最贵的一条泳道，**比不续还贵**。续棒 prompt ＝ 一份薄续尾件（现取事实／本段只做什么／收工判据），不继承前段上下文。
- 🔴 **`summary.txt` 增报一列「上下文峰值」**，并在批次汇总里单列「本批越 150k 的泳道 N 条」——没有这一列，这个数字就又回到「没人知道」的状态。

**验收**：单测覆盖三档（<150k 不动／≥150k 只记峰值／≥250k 终止并记 `OPENER_PARTIAL: 上下文转场`）；`summary.txt` 新列有断言。

### ⑵ ⑶b worktree `reports/` 兜底回收改成覆盖每条泳道
现状只对走 NO-SENTINEL 补问路径的泳道跑过；2026-09-20 实测四条正常 OK 收工的泳道一条都没跑，`#601` 的首轮基线 `reports/carrier-consistency-scan.md` 差点随 worktree 删除丢失。改成**不论结局每条泳道收工都跑一次**，并加单测覆盖「OK 收工且 worktree 未自删」这条路径。

### ⑶ `-DryRun` 增一道【设置】行校验
现状 `-DryRun` 只解析泳道分组，不看【设置】行。2026-09-20 实撞：`worktree：☑ 建`（无括号名）三道闸全过，到派出时 L245 正则才判 `FAIL(worktree-name)`，**一整批七条泳道白起一次**。给 `-DryRun` 加一道：逐条校验【设置】行六字段齐全、`worktree：☑` 必须带非空括号名、`分支：` 能解出反引号包裹的 `claude/` 分支名。带两向单测。

### ⑷ `工具-opener派出前校验.ps1` 补「产出物实证」判据
现状只认队列状态字段。2026-09-20 实撞：`#328` 状态字段还是 `open`，泳道开工后才发现核心交付早在 08-17／08-26 已落地，**白烧 5.02M token／47 次请求**。补一道：派单件若在「期望产出」里点名了文件或函数，派出前先核它们在不在；已存在则打印告警并要求人工确认，不静默派出。
