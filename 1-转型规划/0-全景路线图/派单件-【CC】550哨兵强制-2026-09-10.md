## 一、做什么

### 1. `NO-SENTINEL` 时补问一次，仍无才判 FAIL（本棒实质）

现状（`工具-opener批处理执行v2.ps1` 第 107–113 行）：

```
$done = [bool]($tail | Where-Object { $_ -match '^OPENER_DONE\s*$' })
$partial = [bool]($tail | Where-Object { $_ -match '^OPENER_PARTIAL' })
$status = if ($code -eq 0 -and $done) { 'OK' } elseif ($code -eq 0 -and $partial) { 'PARTIAL' } elseif ($code -eq 0) { 'NO-SENTINEL' } else { 'FAIL(' + $code + ')' }
if ($status -like 'FAIL*' -or $status -eq 'NO-SENTINEL') { break }
```

改为：判出 `NO-SENTINEL` 时，**先用 `claude --resume <sessionId>` 补问一次**——`#549` 已把 session id 写进日志首行与 `summary.txt`／`summary.json`，`--resume` 现已在 master 可用（本棒的前置就是它）。

补问的 prompt 要极窄，只要一行，例如：

> 你上一轮没有按收工协议输出哨兵行。**现在只输出一行**，不要解释、不要复述：全部完成输出 `OPENER_DONE`；有留步/未尽项输出 `OPENER_PARTIAL: <一句原因>`。

补问后重新判：拿到哨兵 ⇒ 按 `OK`／`PARTIAL` 记，并在 `summary` 里**标注「补问后取得」**（🔴 不得与首轮自觉输出混为一谈——那会掩盖遵守率）；仍无 ⇒ 判 `FAIL`／`NO-SENTINEL` 并按原纪律中断本泳道。

🔴 **必须带超时与单次上限**：补问自身也是一次 `claude` 调用，会挂死。给它一个明显短于正常泳道的超时（建议 ≤3 分钟），**每条泳道只补问一次，不循环**。补问超时本身即判 `NO-SENTINEL`，不吞。
