## 五、新判据建议（未应用，仅建议）

### 5.1 通用原则（建议写成一条独立小节，供三项日核共用）

> **`Get-ScheduledTaskInfo` 的 `LastTaskResult` 落在 `0x00041300`–`0x00041308`（十进制 267008–267016）区间时，一律是 `SCHED_S_TASK_*` 成功语义码族（`READY`／`RUNNING`／`DISABLED`／`HAS_NOT_RUN`／`NO_MORE_RUNS`／`NOT_SCHEDULED`／`TERMINATED`／`NO_VALID_TRIGGERS`／`EVENT_TRIGGER`），不是失败码。真正的执行失败是完全不同的数值族（典型是 `0x8004xxxx` 一类的负值 HRESULT，或具体命令自身返回的非零退出码）。任何判据都不应把这个区间内的值直接当"异常"分支，应先落到"运行状态"分支，再用 `State`／业务日志等独立信号判断是否真异常。**

### 5.2 第 1 项（sweep）—— 加"运行中豁免"

**现判据**：
```
判据：State=Ready、LastTaskResult=0、LastRunTime 距今 < 2 小时（每小时 :17 跑）。
```

**建议改法（diff 示意）**：
```diff
- 判据：State=Ready、LastTaskResult=0、LastRunTime 距今 < 2 小时（每小时 :17 跑）。
+ 判据：
+   - 若 State=Running（或 LastTaskResult 落在 5.1 通用原则的成功语义码族区间）⇒ **先不判异常**，
+     改查 git -C C:\Dev\zhuopin-ai log -1 --format='%cd' --date=format:'%H:%M' 与当前时刻的差值，
+     若 < 5 分钟视为"正常执行中"，若 >= 5 分钟（sweep 单次不应跑这么久）才升级为 🔴 真异常。
+   - 否则维持原判据：State=Ready、LastTaskResult=0、LastRunTime 距今 < 2 小时。
```

### 5.3 第 2 项（企微机器人）—— 加审计日志新鲜度做双判

**现判据（已改过一次，单源）**：
```
判据 State=Running。
```

**建议改法（diff 示意）**：
```diff
- 判据 State=Running。
+ 判据：State=Running **且** 审计日志 wecom_aibot_audit.jsonl 最新一条 timestamp（真 UTC，转本地后）
+   距离"第 0 步取到的当前时刻"< 30 分钟（正常轮询/心跳间隔的宽松上界，具体阈值待与
+   Listener 真实心跳周期核对后收紧）。
+   - 两者都满足 ⇒ ✅ 在线且在产出。
+   - State=Running 但审计日志超过 30 分钟无新记录 ⇒ 🔴 疑似挂死空转，需人工查僵尸进程
+     （此时才是 #460 原报告里那个"需人工查僵尸进程"的建议动作该出现的场合——用日志新鲜度
+     替代原来的 LastTaskResult 猜测，把误报率换成了漏报率更低的双信号判据）。
+   - State≠Running ⇒ 🔴 真离线（不变）。
```

## 六、单测设计要点

本任务是 prompt 驱动的日核（非编译代码），"单测"落地建议以**判据函数抽出为可测的小工具脚本**（例如 `0-学习与工具/工具-计划任务状态判读.py`，输入 `State`/`LastTaskResult`/上次日志时间戳，输出判定结果），再对该函数写表驱动用例；若暂不落地成独立工具，至少应在下一次人工跑日核时，把以下场景当"人工验收清单"过一遍：

| 场景 | State | LastTaskResult | 审计日志新鲜度 | 期望判定 |
|---|---|---|---|---|
| 1 | Running | 267009 | 2 分钟内 | ✅ 在线（回归 #460 本次实测这一行） |
| 2 | Running | 267009 | 超 30 分钟无记录 | 🔴 疑似挂死（新判据要新增覆盖的分支，现判据会漏判） |
| 3 | Ready | 0 | — | ✅ 正常（不变） |
| 4 | Stopped/Disabled | 267009 或其他 | — | 🔴 真离线（不变） |
| 5（sweep） | Running | 267009（撞上执行瞬间） | git 最近提交 < 5 分钟 | ✅ 正常执行中（新判据要新增覆盖的分支，现判据会误判为异常——即 #460 同族假阳性尚未实测撞上但判据上存在的缺口） |
| 6（sweep） | Running | 267009 | git 最近提交 ≥ 5 分钟仍未出现 | 🔴 真异常（新增分支，替代"State≠Ready 就是坏"的粗判） |
| 7 | 任意 | 落在 267008–267016 区间之外的真错误码（如 HRESULT 负值） | — | 🔴 真失败（5.1 通用原则要求：只有区间外的码才直接判失败） |

场景 1/3/4 是"回归测试"（确保新判据不破坏现有已验证正确的分支）；场景 2/5/6/7 是"新增覆盖"（现判据目前没有对应分支，是本次建议要补的缺口）。
