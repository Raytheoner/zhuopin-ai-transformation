# 派单件 · 【CC】`#240` 档位核实（榜首第二条陈旧行）

## 〇、由来

`#240` 是陈旧度榜首第二条（现取 7.9 天）。行内写明：外部阻塞已于 2026-08-12 由陈承交付四项企微凭据而解除，**剩余范围＝拿这套凭据做 `#162` 统一门户的 OAuth 真实验证**。它久挂的原因**未经核实**——可能是真需要 LAN／真实外部服务，也可能只是没人派棒。**本棒就是去把这个未知变成已知。**

## 一、做什么（按顺序，任一步得出结论即可停）

1. 读 队列 §一 `#240` 与 `#162` 全文（`工具-队列查询.py --row N --field all`），列出 OAuth 真实验证到底要哪几步、每步需要什么。
2. **核凭据在哪**：🔴 凭据一律在 config 文件里，**不得把任何凭据值写进报告、日志、commit 或队列**——只写「在/不在、哪个文件、哪几项齐/缺」。
3. **核可达性**：判 OAuth 端点是否可从当前网络到达。🔴 **`Test-NetConnection` 本机恒为真（TUN fake-ip），不可作可达性判据**；用真实 HTTP 请求的返回码/错误类型判，并把命令与原始返回写进报告。
4. **分诊出结论，三选一**：
   - **(甲) 能 off-LAN 做** ⇒ 就把 OAuth 真实验证做完，`#240` 追 ✅ 建成段；
   - **(乙) 必须 LAN／必须真实外部服务** ⇒ **不做**，把 `#240` 改判 `[S:blocked]` 或 `[S:timed=<日期>]`，状态列写清**卡在哪一步、缺什么、谁能解**，并标注去向（`zhuopin-lan-closeout` 的 LAN 留步清单）；
   - **(丙) 缺凭据或凭据失效** ⇒ 同样改判 `blocked`，写清缺哪几项、该找谁（陈承，**男**——人的属性查名录正本，禁从名字推断）。
5. 无论走哪一支，收工都现取一次 `STALE(7)` 与机制类可动 WIP（`release` 回显即可），与开工时对比。

- 🔴 **凭据值绝不外写**（见 §一.2）。
