# 派单件 · 【CC】文档台账重跑改条件触发

## 〇、由来

**实测（2026-09-12，`OP-0912-E` 现取）**：当日 master 54 个 commit 中，「`docs(队列): 收工重跑文档台账（sweep 自动）`」**14 条（26%）**，加上 sweep 补销 7 条，**21 条（39%）是 sweep 自己的例行产物**。台账是**纯派生产物**——它由仓库文件集算出来，文件集没变时重跑必然产出同样内容，那一条 commit 只是噪音，还会挤占 `git log` 的可读性与编辑锁的争用窗口。

## 一、做什么

1. 定位 `工具-落库sweep.py` 里重跑文档台账的那一段（产出 `1-转型规划/0-全景路线图/文档台账-自动生成.md`），读清它现在的触发条件与写盘方式。
2. 改成**条件触发**：只有当台账的**输入集**发生变化时才重跑并提交。🔴 **判据要可证伪、且 fail-open**：
   - 取输入集的指纹（如纳入统计的文件路径＋mtime／size，或直接对生成结果算 hash）；指纹与上次一致 ⇒ **跳过重跑、不产生 commit**；不一致 ⇒ 照跑。
   - 🔴 **指纹取不到／读失败 ⇒ 按「变了」处理照跑**（fail-open），**绝不静默跳过**——漏跑一次台账没人会发现，是本项目反复吃亏的形态。
   - 指纹落 `reports/` 下（🔴 **新文件名形态必须同批补 `.gitignore` 并用 `git check-ignore -v` 实测取证**，`#328` 那族教训：凭空造的文件名最后被判孤儿、企微群连响 17.1 小时）。
3. **可观测**：跳过时在 sweep 日志留一行「台账未变、跳过（指纹 <前 8 位>）」，让「没产生 commit」与「机制坏了」可区分。
4. 单测：覆盖「输入未变⇒跳过」「输入变了⇒重跑」「指纹读失败⇒照跑」三条。
5. 队列回写＋§二 登记。

## 二、不做什么

- 🔴 **不改台账的生成逻辑与内容格式**，只改「跑不跑」。
- 🔴 **不动 sweep 的其它任何一类**（14 类常驻告警、落库主流程一律不碰）。
- 🔴 **不 ff master**；收工只 push 本泳道分支。
- 🔴 不碰 `.51`／企微机器人／定时任务；不做任何对外发送。
- 🔴 **不立新机制行**（WIP 超上限）；确需时 🛑 起首。

## 三、收工报告按此产出

1. 改动落点与指纹口径；2. 三条单测读数（现跑）；3. `git check-ignore -v` 的实测输出；4. 零回归差集（已知常红两条不算本棒引入）；5. 顶格 `OPENER_DONE` 或 `OPENER_PARTIAL: …`。
