🔴 **本行原前提已被自己证伪，全文改写；原判据作废，勿再引用（2026-08-22 OP-0821-B）** —— **原登记称「118 份文件永久显示已修改、`git status` 干净这条判据失效已 34 天」，该结论错误。** **真相：他本机的 `git status` 一直是干净的**（实测 `git diff --name-only` ＝ 0、`git status --porcelain` 空）；**那 967 份「已修改」只存在于 Cowork 沙箱的 Linux git 里**。 ━━━ **根因** ━━━ Git for Windows 安装器默认在 **system 级**设了 `core.autocrlf=true`（实测 `git config --system --get core.autocrlf` ＝ true），而**仓库级与全局级均为空**；沙箱 git 只读得到挂载进来的 `.git/config`（local）与它自己的 global，**读不到 Windows 的 system 级配置** ⇒ **同一个工作区、同一条命令，两个 git 给出相反答案**：本机 git 认为磁盘 CRLF 正常、干净；沙箱 git 认为磁盘 CRLF ≠ 索引 LF、967 份全改了。 ━━━ ✅ **已修（低风险、可一条命令回退）** ━━━ 在仓库级把该值显式写死：`git config --local core.autocrlf true`。**对本机 git 零行为变化**（本来就是 true，只是来源从 system 变成 local），**只是让沙箱 git 读得到同一条规则**。**实测生效**：沙箱侧同一批路径由 119 份「已修改」降为 **0**。⚠️ `.git/config` 不入库 ⇒ **这是本机环境修复，不是项目口径变更**；**其它 clone（含 CI runner）不受影响**，CI 跑 `windows-latest`、system 默认本就是 true。 ━━━ 🔑 **该记住的那条（比这次的具体故障更要紧）** ━━━ **沙箱 bash 的 git 与本机 git 不是同一个
