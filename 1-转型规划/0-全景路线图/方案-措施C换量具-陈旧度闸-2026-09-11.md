# 方案 · 措施 C 换量具（行数闸 → 陈旧度闸）

## 〇、一句话

措施 C 要防的是「**只开新战线、不关行**」；它用「**开着的行有几条**」当代理变量。这个代理在串行时代成立，在泳道并行时代失效 —— 本件把判据换成直接测目标变量（**有多少条开着的行已经不动了**），并顺手修掉一处已实证 13 天未修的误拦。

## 一、初衷与立据（原文出处，不复述正文）

| 时点 | 事实 | 出处 |
|---|---|---|
| 2026-08-10 | 上限 16，超限 20/16；他选 (c) 仅提示不阻断 | `队列行日志/#58.md` |
| 2026-08-17 | 复评实测：观察周新立 6 条机制行、**无一伴随关行**；提示响 6 次被无视 6 次 ⇒ 改为阻断 | 同上 |
| 2026-08-17 | 定下自我证伪判据：「`WIP豁免：` **若开始批量出现，说明上限本身定错了，应回本条重议上限，而不是继续加豁免**」，并记「当前真实豁免次数 ＝ **0**」 | 同上 |
| 2026-08-29 | 实证缺陷 ⑸：🛑 起首行本不计入 WIP，却仍触发阻断 ⇒ 「逼着每条 🛑 新行写一条名不副实的豁免，久了豁免退化成例行噪音」 | §四 `#58` 行内 |
| 至今 | 缺陷 ⑸ **未修**；上限已被现实抬过两次（8 → 16 → 22），而 `#58` 自书「第三次为迁就现状改口径即等于废掉措施 C」 | 本件现取 |

## 二、实测（2026-09-10 / 09-11 现取，手段随数写）

1. **豁免从 0 → 15**（手段＝按 §一 状态列逐格取 `WIP豁免：`，非全文 grep —— `#58` 记过「全文 grep 得 10、按结构位取得 1」的计数陷阱）。15 条按理由分三类：

   | 类别 | 条数 | 行号 |
   |---|---|---|
   | 真例外（出血／硬前置／当日拍板） | 8 | `#416` `#422` `#433` `#443` `#521` `#545` `#553` `#554` |

   | 无独立理由，纯「立行时已超限」 | 4 | `#529` `#531` `#534` `#544` |

2. **闸没有压住吞吐**：§二 批次数／日（活件＋`归档-202609` 去重 639 个批次名）—— 08-25 `37`／08-31 `24`／09-02 `52`／09-07 `50`／09-09 `56`／09-10 `57`。**全程 WIP 超限，吞吐单调上行。**
3. **闸的直接成本可数**：🛑「排队中·暂非可动」行 **9 条**（`#122` `#138` `#170` `#220` `#284` `#464` `#522` `#529` `#531`），全部是已识别、已值得做、因闸而 park 的机制工作。
4. **积压未复发**：27 条计入行的状态列最新日期**全部落在近 7 天内**，无一条超 7 天未被碰。（口径限制：取格内最大日期，会被行内写的未来截止日污染，只能证「都在动」，不能精确证「几天前动的」——这也正是 D2 要改用 commit 时间的理由。）
5. 🔴 **分诊全量落地后仍不达标**：`#455`／`#482`／`#487`／`#505` 四条改判 `blocked` 后 **27 → 23/22，仍超 1**（`#531` 以 🛑 起首本就不计入，改判对计数零影响）。**一次彻底的人工分诊都压不回上限**，本身就是「阈值与量具不匹配」的证据。

## 三、诊断：三条可证伪的失效判据，条条已触发

- **判据①（`#58` 自书）**：豁免批量出现 ⇒ 上限定错。**实测 0 → 15，已触发。**
- **判据②**：闸应压住在制品。**实测吞吐逆势上行 37 → 57，未压住。** 因为真实在制品载体已变成「同时在飞的泳道数」（`工具-泳道看护状态机.py` 的 `running`），§一 机制行数已退化为**一张待办清单的长度**。
- **判据③**：闸应阻止行被立。**实测 15 条豁免 ＋ 9 条 🛑 ＝ 24 条全部立进队列**，一条未被真正拦住 —— 它改变的不是结果，只是在 `release` 那一刻加了一段仪式（现取 WIP → 写豁免理由 → 加 `--force`）。

**但保留一条**：它是目前唯一一台**强制回头看「这些行还该不该开着」**的机器。2026-09-10 那次分诊正是它逼出来的（5 条挂 `open|partial` 实为等他一字母）。**换量具，不拆刹车。**

## 四、改法

### D1 · 新判据（替换 `_count_mechanism_wip` 的闸面，不动其计数函数本体）

```
阻断条件（仅在本次持锁真正新增 [D:机] §一 行时判，与现行触发条件一致）：
  STALE = 计入 WIP 的行中，末次真实活动距今 > N 天 的条数
  若 STALE > K  ⇒ 拒绝 release（逃生阀仍为 --force-mechanism-wip ＋ 行内 WIP豁免：<理由>）
  行数本身不再设上限
```

- **「末次真实活动」取 commit 时间，不取行内文本日期** —— 行内日期会被未来截止日污染（§二.4 已实测），且可被人手写。取法：该行所在物理文件的 `git log -L` 或按行号定位末次改动 commit 的 `%ad`；实现细节留 design。
- **为什么这样对准初衷**：`#58` 要治的原话是「新立 6 条、无一关行」。`STALE` 直接就是这句话的机器形态；行数多少与这个病无关。

### D2 · N／K 初值（**已用真实 commit 时间实测定死，非推荐值**）

**手段**：`git blame --incremental` 取每条计入 WIP 行所在行的末次 commit `author-time`（增量模式只出行号区间与提交头，不带正文，避开大文件与长行），再按行首 `|<编号>|` 映射回行号。23 条计入行**全部解析成功，无遗漏**。

| 行龄 | 条数 | 行号 |
|---|---|---|
| 0 天 | 4 | `#534` `#552` `#553` `#554` |
| 1 天 | 6 | `#416` `#504` `#507` `#521` `#544` `#545` |
| 2 天 | 4 | `#440` `#459` `#462` `#481` |
| 3 天 | 2 | `#439` `#503` |
| 4–5 天 | 3 | `#479` `#448` `#492` |
| **7 天（最老）** | 4 | `#240` `#312` `#381` `#382` |

`STALE(N)` 实测：`N=2 → 9`／`N=3 → 7`／`N=5 → 4`／**`N=7 → 0`**／`N=10 → 0`／`N=14 → 0`。

**⇒ 定死 `N = 7`、`K = 3`。** 理由三条：⑴ 7 天 ＝ 跨过一整轮值周巡检仍没动，语义干净；⑵ 今天 `STALE(7) = 0`，留 3 条真实余量，**不会上线即阻断**（对照：行数闸上线当天就 24/16）；⑶ 方案里原推荐的 `N=10/K=5` 经实测**永不触发**（`STALE(10)=0` 且最老行才 7 天），等于悄悄废闸——**推荐值若不实测就写死，这次就会错**，此即 D2 要求先实测的原因，已自证一次。

🔴 **量具本身的已知偏差，必须随判据一起落纸**：`blame` 记的是「这一行的**任何**改动」，K2 外置、每周清扫、称呼订正这类**机械改动也会刷新时间** ⇒ **实测 `STALE` 系统性偏低，是乐观估计**。缓解：观察期内值周巡检对行龄榜首 3 条**人工抽查一次**，核该行末次改动是不是实质推进；若抽查发现机械改动污染严重，回本件重定 N（而不是调 K）。

### D3 · 同族两处判据缺陷一并修（一处旧账、一处本次新发现）

**⑴ 缺陷 ⑸（`#58` 2026-08-29 实证，未修）**：新增行不计入 WIP 时仍触发阻断 ⇒ 改为只回显存量、不拦。消除三条假豁免的来源。

**⑵ 🔴 本次新发现 —— 🛑 排除只认「状态列」，而实际写法有两列**：`_count_mechanism_wip` 判的是状态列去掉 `[S:][D:]` 之后是否以 🛑 起首；但队列里有 **5 行把 🛑 写在「任务」列**（`#381` `#382` `#447` `#448` `#505`），其中 **3 行（`#381` `#382` `#448`）因此被计入 WIP**——它们的正文白纸黑字写着「排队中·暂非可动」。

> **实测影响**：把 🛑 判据改为**两列任一命中即排除**，当前 WIP **23 → 20/22，立即合规**。也就是说，今天这道闸之所以判超限，**有一半原因是它自己的排除规则只看一列、而人写在另一列**。

修法二选一（留 design 定）：**(甲)** 判据认两列（改动小、向后兼容存量写法）；**(乙)** 判据不动，改为在 `append-row`／`edit-row` 写侧强制 🛑 必须落状态列（口径更干净，但要一次性订正存量 5 行）。**本件推荐 (甲)＋写侧告警**，理由是存量订正属"为了让机器好读而改历史行"，与「历史记录不追改」相冲。

### D4 · 迁移期

- 新闸**先以告警上线 7 天**，与旧行数闸并行回显两个数；7 天后复评再切阻断。
- 🔴 **复评必须先答一个问题**（照抄 `#58` 的手法）：「这 7 天里新闸的告警有没有被任何人当回事？」答否则不得默认续期。
- 存量 15 条 `WIP豁免：` 标记**不追改**（历史记录不追改），但值周巡检须逐条核一句：**豁免进来的行有没有被真的领走**？`#58` 原话——「若豁免进来的行长期躺着，逃生阀就从例外通道变成上限的旁路，那时该限的不是行数而是豁免本身」。

### D5 · 本版自己的退休判据（先写死，免得三个月后重演）

**若 `STALE` 连续两周为 0 且期间无任何 `WIP豁免：` 新增 ⇒ 说明病已不存在，本闸转为纯告警并登记退休候选**；反之**若 `WIP豁免：` 在新闸下 30 天内再破 5 条 ⇒ 回本件重议 N/K，而不是加豁免**。

## 四bis、两条结论的先后（🔴 别搞反）

`D3⑵` 单独就能把 WIP 从 23 打到 20/22 合规，**成本是一行判据**；`D1` 换量具则要走完整 openspec。两者**不是替代关系**：前者修的是「闸算错了」，后者修的是「闸算的东西不对」。**先做 D3⑵ 立刻止血、再做 D1 换量具**，但 🔴 **D3⑵ 属改口径判据（🟡 档），须 Shao Peishen 一字母才能动**。

## 五、不做什么

- **不第三次抬行数上限** —— `#58` 自书「第三次为迁就现状改口径即等于废掉措施 C」，此路已被封死。
- **不退休措施 C** —— 会失去唯一一台强制回头看的机器（`#58` 记的病：6 次新立、0 次关行，届时没有信号）。
- **不在本件改任何闸** —— 本件是 design 审前置件；落地须走 openspec 变更包，由 CC 领 apply。
- **不动业务域** —— 措施 C 只管 `[D:机]`，业务行不受 WIP 约束，本件维持原样。
