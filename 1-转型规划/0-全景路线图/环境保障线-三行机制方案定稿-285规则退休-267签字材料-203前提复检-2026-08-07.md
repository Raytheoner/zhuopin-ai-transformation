## 一、#285 ·「因果断言前先问有没有没核的变量」达 3/3，处置

### 1.1 先把三次实例的**共同结构**看准（这决定了修法长什么样）

| 次 | 断言 | 断言依据 | 证伪它的 | 谁发现 |
|---|---|---|---|---|
| 1（08-03，#222） | "它确实补推了" | 日志文本 | `schannel` 计数 | 自查 |
| 2（08-03，#221） | "3 个提交至今未并入 master"，据此定 **P1** | 分支/提交计数 | `git patch-id --stable` | **值周巡检线** |
| 3（08-06） | "reset 导致文件被退掉" | reflog 文本 | `git ls-tree` | **CC `aibot-webhook-retire`** |

**#284 已记下的共同点**：证伪它们的都恰好是**一条命令**，且后两次**不是断言者自己跑的**。

**本线补一条更可操作的共同点**：**三次都是从「过程痕迹」推断「当前状态」，而当前状态本可直接查。** reflog 说 "reset moving to…"（过程）→ 文件在不在是 `ls-tree`（状态）；分支有 3 个提交不在 master（过程）→ 改动在不在 master 是 `patch-id`（状态）；日志说"补推了"（过程）→ 推没推是计数器（状态）。
**⇒ 修法的抓手不该是"多想一步"（不可检查），而该是"状态可直查时不得用过程痕迹代替"（可检查）。**

> **证伪本节**：`grep -n "第 1 次\|第 2 次\|第 3 次" 跨桌任务队列.md`（#284 第 ③ 条原文）——若三次实例的依据不是过程痕迹类，本节结论不成立。

### 1.2 三个待答问题的答案

**① 适用边界** —— **不是"所有因果断言"，收窄为「驱动了 P0/P1 定级、或据以立修法行的因果断言」**。
理由：三次里真正有代价的只有第 2 次（错误 P1 定级驱动了后续动作）；第 1、3 次自查/他查后即时更正，代价接近零。**若对所有断言都要求，恰好落进 #285 自己警告的形式主义**，且每周适用面从约 2-4 行膨胀到几十行。

**② 强制点** —— 三个候选逐一评估，结论是**只有一个可用**：

| 候选 | 评估 | 结论 |
|---|---|---|
| 写进 opener §六防线 | **它已经在那里了**（防线 4，含"高危：结论对自己有利时"），仍 3/3 | ❌ **正是退休制要终结的模式** |
| 收工自检项 | 力度弱于 opener，且无人检查自检 | ❌ |
| **编辑锁 `release` 校验④ 的延伸** | 校验④ **已经**在扫"状态列 P0/P1 定级 + 未核实共现"，扫描域、引号剔除（#248）、只查状态列（#225 dogfooding 修正）三项基础设施都已就位 | ✅ **唯一可用**——它是既有咽喉，不是新造机制 |

**具体形态（最小改动）**：状态列出现 P0/P1 定级时，要求同一单元格内出现**一个反引号包裹的命令片段**；缺失即 `release` 拒绝并提示。反引号解析能力代码里已有（#241 `extract_target_filename`／#258 决策点③同款判据）。

🔴 **必须写明的边界，否则会被误当成质量保证**：**它只判「有没有」，不判「对不对」。**
- 能防住：**第 1、3 次那种"根本没想过怎么证伪"**（2/3）；
- **防不住**：第 2 次 #221 那种"想过、但用了错的证据"（1/3）——写一条无关命令即可通过。
- ⚠️ **#248 同族风险已排除**：本方案沿用校验④**现有**扫描域（只查状态列）与 #248 的引号剔除逻辑，**不新增任何扫描面**，故不会重演"描述判据的文字触发判据本身"。

**③ 与 #257 的关系** —— **建议不捆绑，各修各的。**
#285 行文写"三次里有两次发生在长 session 后段，可能是同一根因的两个表征"——**本线核不出这一点**：现有任何载体都不记录 session 长度与断言时刻的对应关系，该关联**既未被证据支持、也未被证伪**。**依本行自己要立的那条规矩，此处不下因果断言。** #257 若落地并产出"session 后段"的可测信号，届时再回头比对。

> **证伪本条**：若能指出任一载体记录了 #222/#221 两次断言发生时的 session 长度，本判断作废。

### 1.3 处置建议（**需 Shao Peishen 定夺**）

**(a) 收窄 + 挂校验④（推荐）** —— 按 §1.2 落地；**同批把 opener §六防线 4 正文降为一行指针**（依 #206 先例：机制化后正文可降级为指针、不必删）。
代价：CC 一次小改动（编辑锁 + 单测）；换来 2/3 覆盖率与一条人守条目的退场。

**(b) 判定无法机制化、如实删除** —— 从 opener §六防线清单删掉，#284 第 ③ 条标注"已删除"。
代价：**知识不丢**（三次实例原文留在 #284），但下次同类错误仍只能靠第二双眼睛。
**它不是弃权** —— #284 自己的观察是"现有机制覆盖不了『结构合法但判断错误』，这类目前只能靠第二双眼睛"，(b) 等于承认这一点并停止假装。

**默认项：若不答，按 (a) 执行**（收窄版风险低、复用既有咽喉、不新增人守条目）。

## 二、#267 · 签字材料/交付证据落 gitignore 目录致真实丢失

### 2.1 根因已机制级坐实（不是推断）

`0-学习与工具/工具-孤儿worktree扫描.py::_is_dirty` 第 79 行：

```
result = _run_git(["status", "--porcelain=v1"], Path(worktree_path), check=False)
```

**`git status --porcelain` 默认不列 gitignore 命中的文件。** 而 `.gitignore` 第 25 行是 `**/reports/`。
⇒ 一个 `reports/` 下躺着签字材料的 worktree，`_is_dirty` 返回 **False** → 落进 `orphan_worktrees` 桶 → 报告归类为「**ahead=0，删除不会丢失任何独有内容**」。
**#267 那次真实丢失，正是这条路径。**

> **证伪本节**：`git status --porcelain=v1` 在一个只有 ignored 文件变化的目录里若有输出，则本结论不成立。

### 2.2 #267 原文提的两个修法，本线均**不建议**照做

| #267 原提 | 不建议的理由 |
|---|---|
| ① CLAUDE.md §5／协议〇 明文加一条「签字材料一律落 git 可追踪路径」 | **又一条人守规则**。且 §5 已 29 条、信噪比 7.5%——按规则退休制的逻辑，**新增人守条目从诞生那天起就是惰性的** |
| ② `工具-仓库外载体扫描.py` 加关键词检测（批次声明含"签字/验收依据/黄金基准"但路径落 gitignore） | 三个问题：⑴ 宿主不同构（该脚本扫的是"参数是否过时"，不是"路径是否可追踪"）；⑵ 关键词判据要猜"这算不算签字材料"，**误判两个方向都有代价**；⑶ 🔴 **治不了本案例**——#267 那次改动由 CC 自行 commit，**根本没走 §二 批次**，批次关键词扫描扫不到它 |

### 2.3 建议的修法：一个 flag，落在真正的咽喉上

**咽喉不是"批次声明"，是 `git worktree remove` 这个销毁动作本身。**

**修法**：`工具-孤儿worktree扫描.py` 增加 ignored 内容检测——
1. `_is_dirty` 之外增查一次 `git status --porcelain=v1 --ignored=matching`；
2. 新增第三个桶 `ignored_content_worktrees`：**ahead=0、tracked 干净、但存在 gitignore 命中的非空内容**；
3. 报告中该桶明确标注「**删除将永久销毁以下不在 git 里的文件**」+ 逐个列出路径；
4. **不做任何删除**（该脚本"只读不删"的既有边界不变）。

**为什么这个比关键词方案好**：
- **不需要判断"这是不是签字材料"** —— 只陈述客观事实"这些文件不在 git 里、删了就没了"，交人看；
- **覆盖全部成因**，不只签字材料（`.env`、`real_frozen/`、`*.db` 同样受益）；
- **不依赖批次通道**，故 CC 自行 commit 的路径也被覆盖 —— 正是 §2.2 ② 治不了的那半。

**⚠️ 如实边界**：本修法只覆盖**经由本脚本报告后再删**的路径。**`git worktree remove` 被直接手敲时仍无拦截**（#267 那次正是直接手敲）。要覆盖那条路径需要一个 `remove` 前置包装器——**本线判断不值得**（多一层包装＝多一个可绕过物），**如实登记为未覆盖缺口**，不假装闭环。

### 2.4 处置建议（**需 Shao Peishen 定夺**）

**(a) 只做 §2.3 工具改动，不加任何规则（推荐）** —— 派 CC 改 `工具-孤儿worktree扫描.py`（约 20 行 + 2 个单测）。**不触发 openspec**：不改全项目口径、不涉鉴权、不改既有对外语义，属只读脚本增一类输出（对照 CLAUDE.md §5 机制类三条门槛，三条均不命中）。
**(b) 工具改动 + 同时在协议〇.8 加一句** —— 多一条人守，收益边际，**不建议**。
**(c) 都不做，只留 #267 已完成的即时补救** —— 事故会复发，代价是再丢一次签字材料。

**默认项：若不答，按 (a) 执行。**
