### 1.1 新发现 A —— `status` 21 种取值

`待发`(26)／`⏳ 待你审`(10)／`实名可发`(4)／`待你审`(3)／`待发（实名可发）`(2)／`已执行归档`(2)／
`待发（待 Paul 审）`(1)／`⏳ 待 Paul 审`(1)／…，另有 2 条把整句话写进了 status
（`跟进信（Paul → 唐燕萍）；改写自 2026-07-04《收口-1 批改会+7月三件事》…`）。

🔑 **这条把 ⑴ 的结论又推硬一格**：`决策点` 消亡是**字段缺席**，
`收信人/收件人` 是**字段名分裂**，`status` 是**同一个字段的取值各写各的**——
三者是同一个病（**无 schema、无机器守**）的三种表现。只补一条必写字段治不了其中任何一种。

### 1.2 新发现 B —— `决策点` 覆盖率的**分母**要更正

上一段取证件 §1.1 记「64 封带 frontmatter」。**实测该 64 里含 README 自身**
（`README-跟进机制与命名约定.md` 也以 `---` 开头，被「文件名含跟进」的口径捞了进去）。
按「文件名含 `跟进-`」的口径重跑：**正信 63 封**，除去 1 份派生件（`-推送摘要.md`）＝ **62 封**。

⇒ **`决策点` 覆盖率＝ 18/62（29%），不是 18/64。**
**分子 18 与三个关键比值（`收信人` 28／`收件人` 19／`决策点` 18）全部不受影响**，
上一段的所有结论**照旧成立**；这里更正的只是分母。

### 1.3 新发现 C —— 分裂的**不只是字段名，还有取值格式**

| 字段 | 取值形态 | 例 |
|---|---|---|
| `收信人`(28) | **部门 · 人名** | `IT部 · 陈承`／`财务部 · 唐燕萍（可分担李姣龙）` |

## 二 · schema 正本（S1–S4）

### 🔴 为什么是 schema，不是「只加一条必写 `决策点:`」

**这条理由按 Shao Peishen 2026-09-02 的要求写进产出件**：

> `决策点:` 当初消亡的根因**就是无机器守**（上一段实测：起草侧字段清单
> `zhuopin-followup-letter/SKILL.md:163` 里根本没有这个字段）。
> **只加一条必写而不定 schema、不配可执行校验，等于再造一个没人守的字段**——
> 而 `#447` 行自己写着「本行自身就是它所描述的那个病的第三个实例」，前两次都只落在文档里。
> §1.1 的 `status` 21 种取值是第四个实例正在发生的现场证据：**没有规格的地方各写各的。**

### S1 · 必写字段

`title` ／ `status` ／ `created` ／ `收信人` ／ `编号` ／ `决策点` ／ `配套`

- ⚠️ **`决策点: 0 项` 必须合法**（通报类信的真实形态，实测存在）。判它违规会**逼出假数据**。
- ⚠️ 同理 **`配套: 无` 合法**。把「没有配套」逼成编一个出来，比字段缺失更坏。

### S2 · 非法别名

`收件人` ⇒ 应写 `收信人`。**取 `收信人` 为正的三条依据**：计数更高（28 > 19）、
README 表头列名即 `收信人`、Shao Peishen 2026-09-02 点名的就是这条。
🔴 取值格式须**一并归一**（§1.3），不是单纯改字段名。

### S3 · 取值形态

| 字段 | 判据 |
|---|---|
| `created` | `^\d{4}-\d{2}-\d{2}$` |
| `编号` | `^<部门>#<数字>$` |
| `决策点` | **前缀锚定** `^\d+\s*项` |

🔴 **`决策点` 刻意不做全串锚定** —— 上一段取证件 §三⑴ 建议的 `^\d+ 项(（.+）)?$`
**在真身上会误杀一条真实合法取值**：

```
决策点: 2 项（FO 预测订单接口能否补行级状态字段 / PO 采购订单接口能否补行级关闭状态字段），或告知已有的替代查询方式
```

（`IT部#5`，尾随说明在括号之后。）一条把真实语料判成违规的判据，第一次跑就会被人加豁免绕开，
**等于没有**——同族教训见 `followup_gate.py` 模块文档「拿逃生阀去绕它本来要拦的那件事」。
**该用例已写成回归锁**（`test_决策点_带尾随说明不判违规`）。

### S4 · `status` 取值漂移：**只观测，本批不定枚举**

🔴 **定 status 的合法取值集合 ＝ 定口径（D1 🟡 `change_criteria`），不在本次三条授权范围内。**
且 21 种取值里 `待发`／`⏳ 待你审`／`实名可发` 三派**各有真实来路，不是笔误**。
⇒ 脚本只把漂移量算出来摆着（`--drift`），**不判违规**；枚举作为开放点 O1 交下一批。

### 适用范围：只守新信，历史只测量

- 默认（无 `--since`）＝ 全量**测量**、退出码 0。当前实测：**62 封正信共 148 处历史违规**。
- `--since <日> --enforce` ＝ 只对该日之后 `created` 的信阻断。
  **历史 62 封一律不追改**（根 `CLAUDE.md` §1；同族既例＝ `followup-closure-form-survives-backfill`
  proposal「其余 53 行不追改」）。
- **排除 `-推送摘要.md`**：实测 `采购部-姚祖怡-…-推送摘要.md` 无 `status`、且与正信共用
  `编号: 采购部#19` —— 它是派生件不是信。**这条排除从语料实测来，不是猜的**；
  不排除则 S1 会对一个根本不该守的文件常年报违规，而那正是判据被加豁免绕开的起点。（已写成回归锁。）

### 🔴 首跑当场抓到两封：病**今天仍在发生**

`--since 2026-09-01` 实测，**2026-09-02 两封在办新信全部缺 `决策点:` 与 `配套:`、且缺 `created:`**：

```
IT部-陈承-跟进-2026-09-02-端点A字段清单与一句澄清并撤回端点B.md｜缺 created / 决策点 / 配套
质量部-陈忱-跟进-2026-09-02-补发五条验收口径与M18四条清单.md｜缺 created / 决策点 / 配套
```

⇒ `决策点` 不是「2026-08-10 之后停了」这么静态的一件事，**是到今天为止每封新信都在继续掉**。
⚠️ **这两封属他线在办，本泳道一个字未改**，仅登记。

### 🔴 顺带修掉本脚本自己的一处同族缺陷（实测发现，非推断）

首版 `--since` 用 `letter.created >= args.since` 过滤。而 `created` 缺失时取值为空串，
**空串恒小于任何日期 ⇒ 缺字段的信反而免检**——上面这两封正是缺 `created` 的，
首版跑 `--since 2026-09-01` 得到的是「**共 0 封在判定范围内、通过**」。

**一个用来查「字段缺失」的判据，被「字段缺失」本身绕过去了**，且不产生任何信号
（同族＝「工具静默回退」「判据恒真、零信息量」）。
已改为 fail-safe：`created` **缺失或形态非法者一律留在判定范围内**，并写成两条回归锁。

### 4.2 实测：右峰的 **12/17 是补记伪影**，且伪影值域与右峰完全重合

本泳道逐封复原的 12 封（台账件 §一），其**补记往返**为

而它们的**真实往返**是 `[0,0,1,1,1,1,2,2,3,3]`（另 2 封 `事实日未知`），**没有一封 ≥14 天**。

⇒ **20–27 区间的 14 个样本里，12 个已被逐封证明是 2026-08-23 那次批量补转态的伪影。**

### 4.3 剔除伪影后重算（**供 R1 参考，非本泳道结论**）

| | 原（§4.1，n=35） | 剔 12 伪影＋回填 10 事实日（n=33） |
|---|---|---|
| 中位 | 7 天 | **2 天** |
| P75 | 24 天 | **3.5 天** |
| **P90** | **26.4 天** | **17.2 天** |
| 最大 | 27 天 | **24 天** |

按 §4.3 同样的「上取整到整周」算法：**26.4 → 28 天** 变为 **17.2 → 21 天**。
（2 封 `事实日未知` 已按 R1 spec 单独列出、**未混入**上述分位数。）

### 4.4 🔴 但 R1 **不应直接采用 21 天** —— 三条须先查清

1. **剩余 5 个 ≥14 天样本（`14,16,18,23,24`）本泳道未逐封验证。**
   它们**可能同样是补记伪影**（2026-08-23 那次点名的是 12 封，但补转态未必只发生过那一次）。
   若它们也是伪影，P90 还会继续下降；若确为真实慢回件，则 21 天偏低。**这一条是重算的胜负手。**
2. **样本量本身可能不足**：剔除后真实 ≥14 天的样本最多只剩 5 个，用 5 个点定 P90 极不稳。
3. **并跑期要覆盖的是「最慢的那一类」（§4.3 原话）** —— 若慢回件人群整个是伪影造出来的，
   那么真正该问的不是「P90 是多少」，而是「**新旧双路要并跑多久才能覆盖一次真实的转态滞后**」。
   🔑 **本次实测指向的正是这个**：真实回件 0–3 天，而**转态滞后了 20–27 天**。
   并跑期若按回件速度定，会漏掉滞后的那一段；**按转态滞后定，28 天反而可能仍是对的**——
   **只是理由完全不同了**（不是「专员回得慢」，是「我方转态慢」）。
