## 一、为什么这五件是一车

全部落在**两个咽喉文件**的同一半径内，且有依赖顺序：

| 行 | 内容 | 触碰文件 |
|---|---|---|
| **#225** | 编辑锁 `release` 结构校验（详见 §二） | `工具-共享文档编辑锁.py` |
| **#230-1c** | `acquire` 回显最近 120 分钟在场者 | 同上 |
| **#219** | 决策提醒第二载体（判定复用进每小时 sweep，P1） | `工具-落库sweep.py` + `decision_reminder.py` |
| **#222** | sweep「启动即写日志」首行 + 三次触发根因复核（允许"证据不足留白"） | `工具-落库sweep.py` |

## 二、#225 的四项 release 校验（含 08-03 两次扩容，以队列行为准）

1. **列数**：§一 行 ≠ 8 列、§二/§四 ≠ 4 列即拒绝（含反引号内裸竖线形态；#164 已并入本行）。
2. **批次清单**：新增 `B-` 行清单不含队列文件自身路径即拒绝（或按 #225① 在 sweep 侧把队列文件视为隐式已声明——两处择一实现，**勿两处都做**，写明取舍理由）。
3. **编号**：新增编号不得与现役＋归档件任何既有行重复，且（人工写手路径）必须属于本次持锁期间 --reserve 返回的集合。**⚠️ 原拟「≤ 高水位线即拒绝」语义有缺陷**——reserve 先推高水位线，预留号天然 ≤ 新高水位线，拦不住「用了旧预写编号」这次真实撞号（见 #225 台账⑦，2026-08-03 实例）。
4. **断言门槛（咽喉4甲案，2026-08-03 拍板）**：P0/P1 定级行内含「未核／未做的核实」字样即拒绝——逼二选一：补核实，或改标「待核实」。**成因＝#221**（关键变量已识别、已写入行内、仍按最坏情形定 P1，后被 `git patch-id` 证伪降 P3）。⚠️ 注意误拦：只对**新增/修改的 P0/P1 行**生效，历史行不追溯。

**另两条实现要求**（#225 计数台账 ⑥ 与 #230-1c）：
- 写盘类操作**执行前**回显目标行号与该行编号列（治"格式对、对象错"——台账⑥实例：计数段误落 #222）。
- `acquire` 成功时打出锁文件历史中最近 120 分钟内的其它 acquire 身份（纯回显，零新增状态文件）。
