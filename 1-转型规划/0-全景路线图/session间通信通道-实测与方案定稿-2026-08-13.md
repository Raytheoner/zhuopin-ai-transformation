# session 间通信通道 · 本机实测与方案定稿（2026-08-13）

## §一 先说实测结论（本机 Windows，非照搬 Mac 结论）

> 🔑 **本节每一条都是本机当场跑出来的，不是从 Mac 那侧推断的。** 上一次「照摘要下结论」的代价见 opener §七 08-13 节。

| 能力 | 实测结果 | 证据 |
|---|---|---|
| `list_sessions` 能否列出会话 | ✅ **能，且不是空壳** | 本机返回 **102 个会话**，最近 20 个含 `Cowork 环境总线 12`／`企业AI转型业务总线10`／`回件拆件巡逻 patrol`×7／`Weekly status update` |

**⇒ 一句话**：**Cowork↔Cowork 通了，CC 仍是单向黑盒。** 与 Mac 端结论一致，但本机的价值分布不同（见 §二）。

## §二 为什么本项目的收益比 Mac 那侧更大（且在另一处）

Mac 那侧关注的是 **Cowork→CC 传令**。本项目不同——**本项目的协作面主要是 Cowork↔Cowork**：

- 环境总线 / 业务总线 / **拆件巡逻（定时、非交互）** / **值周巡检（定时、非交互）** / 各域专线 —— **全部是 Cowork**。
- 而这五条线此前**唯一**的互相可见方式，是队列文件（`acquire`→写→`release`→`§二` 批次→sweep）。

🔴 **由此暴露的那个真正缺口**：**定时任务班次是非交互的，它的发现若没写进队列，就永久消失，而且没有任何机制会发现它没写。**

**本次实测当场撞到一个活例**：今日 `回件拆件巡逻 patrol` 班次在其 transcript 里报了一条机制发现——「本巡逻 prompt 一.1 指向的 `跨桌任务队列.md` 已于 2026-08-11 转为纯指针文件（16 行、无表格），**严格照 prompt 读会解析到零行 → 静默输出「空巡」**，属工具静默回退家族的假阴性；今日恰好确为空巡，但下一个有待拆件行的班次即会漏拆」。**该发现在队列里查不到独立行**（该班判为已有 #315 6.4 承接、未另立）。

⇒ **`read_transcript` 提供了一条此前不存在的事后追回通道**：定时班次说过什么，可以在事后被读回，不再只能寄望它自己记得写队列。**这正是 opener §一bis 那族问题在「非交互班次」这一段上的机制答案。**

## §三 🔴 采纳它的最大风险：它天然就是「第二份副本」

opener §一bis 那 13 例的共因是**同一事实存在两份副本、改了一处漏了另一处**。**新建一条通信通道，若不划边界，等于按下量产键**——尤其：

1. **handoff 目录按设计要进 `.gitignore`** ⇒ 它对 sweep、`工具-队列结构lint.py`、对账审计、文档台账**全部不可见**，是一个**构造性盲区**；
2. `read_transcript` 读到的是**当时的话**，不是**当前的事实**——一条 4 天前的 transcript 与今天的队列若冲突，**队列是权威**；
3. 通道越顺手，越会诱使人「在通道里说清楚就算交代了」，而**不落队列**。

**⇒ 故方案的第一条不是怎么建，而是划死边界（见 §四.0）。**

## §四 方案

### §四.0 🔴 边界（先于一切实现）

> **通道只是传输层，不是记录层。唯一可信源仍是队列。**
> **判据（可机械化）：任何只存在于 session transcript 或 handoff 文件里的结论，视为不存在。**
> 凡要被别人当依据的判断 —— 结论、口径、状态、待办 —— **必须落队列行**；通道只用来**省掉复制粘贴**与**事后追回**，不用来**承载事实**。

### §四.1 Cowork↔Cowork（零成本，今天就能生效）

**不需要任何脚本，只需一条纪律**：在本线 opener §〇 开工自检**新增第 5 查**：

> **查 5 · 同线近期班次扫**：`list_sessions` 取最近 10 个，挑出**与本次任务同域**的班次（尤其 `回件拆件巡逻 patrol` / `Weekly status update` 两个**非交互**班次），`read_transcript --limit 1` 读其结论段；**凡其中出现「机制发现／缺口／未落队列的判断」而队列查不到对应行的，先补登记再开工。**

**为什么值得单列一查**：其余四查查的是「**已写下来的东西是否还准**」，**第 5 查查的是「有没有东西根本没被写下来」**——这是此前四查全部覆盖不到的一类失真，也正是 §二 那个活例的形态。

### §四.2 CC↔Cowork（须 CC 写脚本，本线只出规格）

CC 会话不可见 ⇒ 只能走文件系统握手。**照 Mac 侧协议，但按本机三处差异改写**：

| 方向 | 载体 | 触发语 |
|---|---|---|
| Cowork → CC | `.claude/handoff/_next.md` | 在 CC 里说「执行 `.claude/handoff/_next.md`」 |
| CC → Cowork | `.claude/handoff/<步骤名>.log` | 回 Cowork 说「跑完了」 |

**三处本机差异，须由 CC 实测后落定，本线不猜**：

1. 🔴 **`scripts/hoff` 是 bash 写法，本机是 Windows。** Mac 侧用 `PIPESTATUS` 取回被 `tee` 吃掉的管道退出码；**PowerShell 无 `PIPESTATUS`**，`Tee-Object` 之后 `$LASTEXITCODE` 的行为**须实测**，不得照抄。⇒ 需要一份 `hoff.ps1`，且**「失败不被伪装成成功」这条必须有测试用例**（本项目已有先例：`工具-共享文档编辑锁.py` 的 `acquire` 就因「不查退出码」出过事，见协议〇.7 与 #333）。
2. **本仓库没有 `scripts/` 目录**（实测），工具一律在 `0-学习与工具/`。⇒ 落点应为 `0-学习与工具/工具-握手留痕.ps1`，与既有命名一致，**且会被文档台账扫到**——不新造一个台账看不见的目录。
3. **`.gitignore` 需新增一条** `.claude/handoff/`（现有 `**/reports/` 与 `**/*.jsonl` 覆盖不到它）。

**收益锚在哪（不是泛泛的"省粘贴"）**：**#221／#228／#310／#335／#162 是同一族反复复发的事故——「说部署了但没合入 master／说跑完了但生产没更新」**，其共因是**收口最后一段全靠执行方转述**。`hoff` 把**时间／cwd／原命令／退出码**落盘，Cowork 可直接读盘核对，**不必信转述**。⇒ 建议其首个强制适用面就是**发布收口四关**（见 CLAUDE.md §5「发布即收口纪律」），而不是所有命令。

## §四bis.1 官方口径：原生 Windows 不提供跨会话消息

**Shao Peishen 提供的参考文章**（`myNotesVault\笔记同步助手\2026-08-13\Claude Code的重大更新.md`，头条转载）称该功能「内置在 v2.1.224，2026-08-07 发布，**macOS 和 Linux 同步支持**」。**该文准确，但它没提 Windows 不是疏漏。**

**回原始载体核实**（`https://code.claude.com/docs/en/cross-session-messaging` → Availability 段原文）：

> **"available on macOS and Linux, including Linux inside WSL 2. Claude Code doesn't offer cross-session messaging on native Windows."**

**本机实测比对**：`claude --version` ＝ **2.1.226**（版本够）；安装路径 `C:\Users\Paul Shao\.local\bin\claude.exe` ＝ **原生 Windows 安装，非 WSL**；命名管道枚举只有 `\\.\pipe\claude-mcp-browser-bridge-Paul Shao`（Chrome 桥），**无任何 messaging socket**。 **⇒ 不适用，且不是配置问题。**

📌 **顺带记一条别被带偏的**：GitHub Issue #86069 报「Windows/MSIX 上消息进了输入框但从不提交」并标 `platform:windows`＋`regression`——**那是在官方本就不支持的平台上的残留行为，不构成「Windows 其实能用」的证据，不得依赖。**

## §四bis.2 更要紧的一点：**就算能用，它也不解决本项目的痛点**

Shao Peishen 的原话痛点是「**Opener 开出新 Session，结果都需要我手动粘贴回原 Session 复命**」——**这一棒是 Cowork↔CC**。
而该功能是 **CC↔CC**（官方文档全篇讲的都是 Claude Code 会话之间）。**⇒ 射程不覆盖。**

## §四bis.3 ✅ 真正的解法：CC 的会话原文就在磁盘上，Cowork 可直读

**实测（决定性）**：CC 会话记录以 JSONL 落在 `C:\Users\Paul Shao\.claude\projects\<路径编码>\*.jsonl`。当场打开今日 CC worktree 会话 `queue-lint-bare-pipe-312efa`（`7299b55b-….jsonl`，2026-08-13 16:59 本地，765 行），**取到其整段收工小结原文**——含它自陈的 `git worktree remove` 非原子事故（删了 `commondir` 与 5 个 `.claude/commands/opsx/*.md`，已自行修复）。**当日改写协议〇.5 的依据，源头正是这段话。**

**⇒ 入法为「CC 复命零粘贴」**（Shao Peishen 2026-08-14 拍板 (a)，**正本已写入根 `CLAUDE.md` §5「会话接力」条下**）：他只说一句「CC 跑完了」，Cowork 自行按**三条独立信源**取件 —— ① transcript 原话全文 ② 队列行 ③ `git log` ＋ `git rev-list --count origin/master..master`；**不一致时以队列与 git 为准，transcript 只作补全与追因。**

**为何是三条而非一条**：①②③ 恰好分别覆盖「**它说了什么／它登记了什么／它真做成了什么**」——正是 #221／#228／#310／#335／#162 那族事故（说部署了但没合入 master）反复漏掉的那一层。
**① 的独有价值**：**CC 中途失败或没走到收工时，队列行还没写，但 transcript 已经有了。**

## §四bis.4 🔴 因此 §四.2 的 `.claude/handoff/` 与 `hoff.ps1` **明确不做**（拍板 2(a)〔2026-08-14〕）

**理由**：其收益已被磁盘直读拿走大半，剩下的只有「CC 说跑完了但根本没跑」一种情形，**而那种情形读 transcript 同样看得出来**。**建它等于在 `.gitignore` 里新增一份 sweep／lint／对账审计都看不见的第二份副本**——正是 §三 与 opener §一bis 要根治的东西。**§四.0 的边界条保留不变。**
**§四.1（Cowork↔Cowork 第 5 查）照做**（拍板 2(a)〔2026-08-14〕）——它管的是另一个面，本次发现覆盖不到；已入本线 opener §〇 查 5。

## §四bis.5 三条边界（与正本同步，缺一不可）

1. **非公开契约**：这是 Claude Code 的内部存储格式，**版本升级可能变；一旦解析不出，立即退回粘贴，不得猜**。
2. **只读、不能反向发**：Cowork→CC 方向仍由他粘一句开场词（CLAUDE.md §5「开场词与 prompt 纪律」已保证那只是一句）。
3. **目录名编码吃掉中文**：`企业AI转型` → `---AI--`，任何「2 汉字＋AI＋2 汉字」的路径都会撞同名，**必须 mtime ＋ 内容二次确认，不得只认目录名**。
