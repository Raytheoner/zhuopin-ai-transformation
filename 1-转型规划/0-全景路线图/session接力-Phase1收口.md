## 四、🔴 血教训（新增两条，跨项目遵守）

1. **我们自己写错的结论会被外部报告当证据引回来。** Antigravity 复盘的 Phase 8（拆 534 KB 巨石）整段建立在本方 09-21 写进接力卡的错误「真结论」之上。**外部意见必须逐条回到第一手实测核验，不得因为它引用了我们自己的话就当已核。**
2. **`.claude/settings.json` 是 git 跟踪文件，泳道 worktree「新建自 master」** ⇒ 任何钩子注册**必须先进 master，泳道才带得上**；主工作区装好但未提交的窗口内，所有泳道不受新钩子约束。**起批前必须机器核 `git show master:.claude/settings.json` 含该钩子。**（实证：B 面首跑 08:03:34 建 worktree，守 08:17:53 才进 master，整棒作废。）
3. **CRLF 第四次骗人——这次骗的是机器守本身。** `工具-落库sweep.py` 三道尺寸闸全用 `stat().st_size`（磁盘字节），阈值却按 blob 字节写下 ⇒ **每道闸的余量被「行数」悄悄吃掉**：`lane-watch/SKILL.md` 190 行，磁盘 30,516 vs blob 30,326＝阈值本身，被这道 **reject 型**闸判「超 190 B」，于是任何触碰这份正本的批次被永久拒绝落库——**所谓棘轮破线，是尺子读错，基线一字没破**。已修为 `_git_bytes()`（CRLF 归一后再量）。判词：**尺子和刻度必须同一套单位，否则越守越紧，紧到守住的是尺子的毛病。** 量体量仍一律 `git cat-file -s`／归一后字节，不用磁盘 `.Length`；跨行锚点比对前先按目标文件行尾重铺。
4. **泳道自陈不可信**（本周第五次）：`OPENER_DONE` 与产出面机器核对不上、派单件要求的自陈三行漏填。产出面一律 `git diff --name-only master...HEAD` 机器核。
