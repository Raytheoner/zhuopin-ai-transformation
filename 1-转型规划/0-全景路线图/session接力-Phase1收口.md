## 五、常备纪律（血换的）

- 🔴 **凡触碰 git 的队列／锁工具一律 Windows 侧跑**（`Windows-MCP PowerShell` ＋ `C:\Dev\zhuopin-ai`）：同一条 `git status --porcelain` **挂载侧 33.9 秒／Windows 侧 0.6 秒，56 倍**，而编辑锁每次 acquire／release 都跑它；且挂载侧 `rm` 被沙箱拒，release 一被拒锁就清不掉。只读的 `工具-队列查询.py` 不碰 git，两侧都行（0.2 秒）。
- 🔴 **多行回写不要连发 `commit-edit`**（release 被拒时锁保持占用 ⇒ 第 2 行起必撞「占用中」）。正确形态：一次 `acquire` → 多次 `edit-row --who` → `append-row --section 二` → 一次 `release`。状态格超 4096 B 先 `工具-队列行K2外置.py --apply` 再 `edit-row --changes-json`。以上两条已落 `.claude/rules/队列与落库.md`。
- 🔴 **分诊闸会扫到自己的排泄物**：本棒实测强档 9 条里 7 条假阳，命中的正是上一轮分诊自己写的留痕。已加两级降档（段级／行级），9→3；**剩余 3 条属「命中点在引文里」，design 明记字符串判据解决不了，仍须读全文复核，不得凭强档直接改判。**
- 🔴 **「关键词在 master 有 N 处命中」不是「同一功能已在 master」的证据。** 判据按强度：① `git log master --grep=<行号>` 找同标题提交；② 取该提交新增的函数／常量名逐个 `git grep master`，**全命中才算**；③ `git cherry`（rebase 后假阳，需与 ①② 互证）。**禁用 `git diff --shortstat`。**
- 🔴 **超 60 秒的命令必须写哨兵**：`Windows-MCP PowerShell` 单次调用约 60 秒即断（本棒实撞一次，跑全份编辑锁单测时）。`Start-Process` 另起、重定向日志、尾巴落 `<log>.done` 写退出码，只探哨兵、大间隔，不逐分钟 tail。
- 🔴 **回归闸 narrow 到受影响的测试类**：`-Tests "<测试文件>::<类名>"`（node-id）；**不得写 `-k`**（脚本把整串当一个 argv，`exit=9`）。**ff 排序一次只在飞一条。**
