## 五、常备纪律（血换的）

- 🔴 **worktree 是 git 的视图，不是仓库的视图。** 泳道在 worktree 里做的「全库检索零命中」，对任何被 `.gitignore` 忽略的路径**一律是假阴性**——`7-外部文档/`（`.gitignore:66-67`，跟踪数 0）里有 30+ 份专员真实回件与全套 U9API 接口清单，两条泳道据「它不存在」下了错结论。凡「全库检索」类自查，涉及被忽略路径时必须回主仓跑。（承接行 `#616`）
- **相关不是因果。** 断言前先问「有没有一个反例能推翻它」。
- **只会报成功的守卫等于没有守卫**；**会报成功却什么都没检到的绿灯是同一回事**。看绿字前先确认它检到了东西。
- **只读命令「太干净」先怀疑没读到对象**——当天 `worktree prune --dry-run` 的空输出、和 `git worktree list` 的满屏 `prunable`，是同一个陷阱的两面。
- **单测证明代码对，第一轮真跑才证明环境对。**
- **事件溯源的表，行数不是实体数。**
- **旧记忆不能冒充实测**：写「本会话实测 66 行」而真身是 83，就是这条。凡「已复核」类自陈，须同时写出用什么核的。
- opener **一律用 `工具-opener生成.py` 出**；看护件须有 `## 三bis` 标题。
- 队列真身禁裸 `Read`/`grep`，只走 `工具-队列查询.py --row/--digest`；状态格超 4096 B 走 `工具-队列行K2外置.py`（先出 plan、再 `--apply`、落格后 `--verify-json` 反查）。
