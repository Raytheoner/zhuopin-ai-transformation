# opener 骨架

🔴 **本件是格式的唯一可照抄物。** 模板库 §〇 全是「为什么」、不是「长什么样」，读它重建格式必然漂。
🔴 **一个标识只出现一次，且批次号与 OP 号必须脱形**（Shao Peishen 2026-09-08 定，两桌全局，见文末「编号脱形」节）——**标题栏里只放 OP 短号，不放批次号**。
🔴 **六字段，一个都不能少，顺序固定**：`执行环境 ｜ 分支 ｜ worktree ｜ 工作区 ｜ session ｜ 派出线`
🔴 **「派出线」＝线名＋派出会话 OP 号（有批次再加「批 B-…」）**，如 `Cowork 环境总线 OP-0906-W（批 B-0907_Q）`——追溯认 OP 号，不认 `[Win]` 标题（标题可改、OP 号才是全库唯一身份）；新会话自己的名字不写进 opener（它开工自设）。（Shao Peishen 2026-09-07 答 ① 选 (a)）
🔴 **代码块正上方必写一行状态标记**（见文末三式）；标题里 `CC`／`Cowork` 只能表示执行环境、且用 `【】`。

## 【CC】骨架

🔴 **worktree 字段的唯一执行者是会话自己，不是 Claude 桌面端的「worktree」勾选框（Shao Peishen 2026-09-10 定）**：桌面端新开 CC 时那个勾选框**一律留空**——它勾上会由 app 另起一个 `<短名>-work` 分支＋worktree（实测 `origin/op0908j-work`…`op0908m-work` 四条即此来源），与 opener 里「从 master 起 `claude/…`」的分支字段**双轨并存**，人守越仔细越会选错。**口径**：⑴ 本字段写 ☑ 时，含义是「**会话开工第一步自己起隔离面**」——单棒一律按 §三bis 看护者形态起：会话本体不建分支不改代码，用 Task/Agent（`isolation: "worktree"`）起**一条**子泳道做正文（子泳道 opener 用【CC · 子任务泳道】变体三行），机器建、机器删；⑵ 写 ☐ 时会话在主 checkout 上做（只产 `.md`、只读取证、ff 入 master、收口批这类**必须在 master 上**的活）；⑶ 无论 ☑／☐，桌面端勾选框都不勾——它不再承载任何语义。生成器 `--worktree` 默认值改 ☐、☑ 时自动切 guardian 变体，机器守落 `#522`。

```
[OP-MMDD-X]【CC】<短名，≤12字>
【设置】执行环境：CC ｜ 分支：master（从 master 起 `claude/opMMDDx-<短横线名>`）｜ worktree：☑（<worktree名>，会话自起子泳道隔离、收工自删；桌面端勾选框留空）｜ 工作区：<无（纯库内，不触碰 `.51`／企微机器人／定时任务）｜ 或按 §〇.1 四种情形之一写全> ｜ session：新开 ｜ 派出线：<线名 OP-MMDD-X，有批次再加「批 B-MMDD_X」>
开工第一件事：调 mcp__ccd_session_mgmt__set_session_title（session_id 传字面量 "self"），标题：[Win]MMDDX-<短名>。🔴 例外：你若是被 Task/Agent 起的子任务，跳过本行不要执行——子任务没有自己的 session，"self" 会解析到父 session、把调度你的那条会话改名（2026-08-28 实撞）。
读 ① `<派单件或首要输入的完整仓库根相对路径>` → ② `CLAUDE.md` §<相关节> 恢复上下文，按<派单件/下述>执行。本件为 <A 类（口径已定、判据已写死），无需再问澄清，直接开工 ／ B 类，开工前问我 2-3 个澄清>。

做什么：
1. …
2. …

不做什么：
- …
```

## 【CC · 子任务泳道】骨架（看护者用 Task/Agent 派发，2026-09-05 队列 §一 `#487`／(甲)）

🔴 **本变体专用于「CC 看护者单粘贴、Task/Agent 内部扇出」批次的 §三各 `### A<N>` 泳道 opener**——
它会被看护者原样当作 Task/Agent 子任务的 prompt 使用，**从未**被单独粘贴进一个新 CC 会话。
判据锚点：**文件内出现 `## 三bis、看护opener` 小节**（看护者自己的开场词另起一节，见下）。

🔴 **本变体正文恒为三行，不多写一行**：`做什么／不做什么／收工` 一律写进**队列行**（任务正本本来就在那），
opener 只负责「你是谁、去哪读」。看护件目标 ≤10 KB。
🔴 **正文三行之后固定追加三条机器口径**——P4 两条默认口径（并行上限／只 push 本泳道分支）＋ **收工哨兵一条**——
它们由 `工具-opener生成.py` **自动写入、不由起草者手打**，故计在「不多写一行」之外；下方块即
成品的**逐字全貌**（占位符除外）。**除这三条外一个字都不许多**（2026-09-09 队列 §一
`#487` apply：此前正本写「恒为三行」、生成器却实际输出五行且另塞两段占位，两处口径
各自演进无人比对——现由单测 `test_工具-opener生成.py::骨架与生成器契约` 读本节比对，
正本改了而生成器没跟、或生成器多塞一行，当场红）。

🔴 **第三条（收工哨兵）是 2026-09-10 有意扩入的，不是漏删（队列 §一 `#550`）**——**下一个人不要按「P4 两条」的旧纪律把它删掉**。
成因：`工具-opener批处理执行v2.ps1` 判成败靠**两个指标**——`claude` 退出码 ＋ 顶格一行 `OPENER_DONE`／`OPENER_PARTIAL` 哨兵；
缺哨兵即判 `NO-SENTINEL` 并中断本泳道。2026-09-10 当日四条泳道（`507-sweep-apply`／`529-timeout-semantics`／`544-heartbeat-batch`／`k2-externalize`）
**活全做了、无一 `OPENER_DONE`**——因为本变体此前一个字没提哨兵，子任务不知道要输出它。
**一个把成功报成失败的判据比没有判据更糟，它会训练下一个人忽略 summary。** 修法落在**生成器强制注入**（不依赖起草人记得写），
`工具-opener块lint.py` 形态⑨机器守（子任务泳道块缺哨兵行即报）。

```
[OP-MMDD-X]【CC】<短名，≤12字>
【设置】执行环境：CC ｜ 分支：master（从 master 起 `claude/opMMDDx-<短横线名>`）｜ worktree：☑（<worktree名>，新 worktree，收工自删）｜ 工作区：<无（纯库内，不触碰 `.51`／企微机器人／定时任务）｜ 或按 §〇.1 四种情形之一写全> ｜ session：新开 ｜ 派出线：<线名 OP-MMDD-X，有批次再加「批 B-MMDD_X」>
读 ① 队列 §一 `#N`（`python 0-学习与工具/工具-队列查询.py --row N --field all`，做什么/不做什么/收工全在该行）→ ② `CLAUDE.md` 恢复上下文，按该行执行。本件为 A 类，直接开工。
🔴 并行上限 4，超出排下一波，错峰 ≥90 秒（构建环境瘦身第三轮方案 P4）。
🔴 收工只 push 本泳道分支，不碰主仓、不 ff master——主仓 ff 由看护者收工时串行做，或经『已授权待合』登记处由 `工具-待合分支巡检.ps1` 机器做；sweep 不做 ff（构建环境瘦身第三轮方案 P4，`#553` 更正）。
🔴 收工以顶格一行 `OPENER_DONE` 收尾；命中 🟡/🔴 决策点则以 `OPENER_PARTIAL: 停在<档位>决策点——<在等什么>` 收尾（`工具-opener批处理执行v2.ps1` 判成败双指标之一，缺它做完的活也会被判 NO-SENTINEL；队列 §一 `#550`）。
```

🔴 **不放 `开工第一件事：调 set_session_title…` 那一行**——2026-08-28／2026-09-05 两次实撞证明
「文本例外句」拦不住子 agent 真的执行它（"self" 解析到父 session、把看护者的标题顶掉）；
源头不放比指望子任务读懂例外句更可靠。若某条 opener 有可能被人**脱离看护者、单独粘贴**进
一个新 CC 会话执行，就不该用本变体——改用上面的标准【CC】骨架。

🔴 **「收工自删」此前只是一句承诺、没有任何机器守它（队列 §一 `#560`，2026-09-11 补）**：
Task/Agent `isolation: "worktree"` 只在子任务**零改动**时自动清，一旦真的建了分支、后续
并入 master 后原 worktree 就没人删——`工具-待合分支巡检.ps1`「动作二」补了这个空：判「已
并入 master 且干净」（同它判分支 ff 前置的同一把 `merge-base --is-ancestor` 尺子）即自动
`git worktree remove`（永不 `--force`，脏的只告警点名），常驻执行体与近期刚动过的 worktree
自动豁免。该脚本已挂在 `poll-opener-batch` skill 的轮询里，无需另起机制。

## §三bis · 看护者自己的开场词（唯一真正的顶层会话，仍需要 title）

🔴 **看护件里这一节的标题必须逐字写成 `## 三bis · <随便什么>`（不带 `§`）**——`工具-opener块lint.py`
形态⑥的结构锚是 `^##\s*三bis\b`，带 `§` 就锚不上，整份 §三 泳道块失去保护且不会报错。

你是本批的**看护者**，不是执行者。用 Task/Agent 工具为各条泳道各起一个子任务，
`isolation: "worktree"`，把对应【CC · 子任务泳道】opener 的正文原样作为子任务 prompt。

扇出与 git（硬口径，逐条照做）：

5. 每泳道一行 ＋ 心跳全文 ＋ D6 停点列 ＋ 转出项 ＋「待回内网」清单。

## 四处最常丢的结构（每次出 opener 前逐条对一遍）

| 易丢处 | 判据 |
|---|---|
| **`worktree：☑／☐`** | **必须是勾选符号**、不是裸名字。☑ 后括号写 worktree 名与是否自删，☐ 后括号写为什么不建 |
| **`session：新开`** | **字面必须出现**，否则读者不知道该在当前窗口继续还是新开一个 |
| **`set_session_title` 整行 ＋ 子任务例外** | 🔴 写真实工具名与 `"self"` 字面量，不得简写成伪代码；**仅【CC】标准骨架与 §三bis 看护者开场词需要这一行**——【CC · 子任务泳道】变体（看护者用 Task/Agent 派发）**不放这一行**，源头不放比指望子任务读懂例外句更可靠（2026-09-05 队列 §一 `#487`／(甲)） |
| **「不做什么」段** | 🔴 **块内一旦有「做什么：」独立行，就必须配一条「不做什么：」独立行**——【CC】【CC · 子任务泳道】【Cowork】三种骨架同受此约束（2026-09-06 起【Cowork】也有此段）。硬约束写进这里，不要塞进「做什么」的某一条尾巴；无硬约束写 `- …` 占位。`工具-opener块lint.py` 形态⑦机器守（2026-09-06 队列 §一 `#487` 子项；起草 `OP-0906-I`、落地 `OP-0906-M`）。§三bis 看护者开场词不在此列——它正文不拼这两段，由生成器 fail-loud 报错，见【Cowork】骨架下方说明 |

## 状态标记三式（代码块正上方，四选一）

```
▶ 首次派出：[OP-MMDD-X]
▶ 更新版（你尚未执行）：[OP-MMDD-X] —— 以这一份为准，上一版作废
▶ 重发（你已执行过）：[OP-MMDD-X]（原因：…）
```

第四态不写标记：**判不准他执行了没有 ⇒ 先问一句、不发块。** 已执行且一字未改 ⇒ 禁重贴，只写一行状态。

🔴 **聊天里给他的开场词 ＝ `工具-opener生成.py --variant reference` 的输出原样贴入，禁手抄；>500 字且已有派单件的，一律引用版。**（Shao Peishen 2026-09-08 答 1a，队列 §一 `#489` 步骤 5 ／ `#284` 退休制第三犯）引用版只四行：标题行 ＋ `【设置】` 六字段 ＋ `set_session_title` 行（**Cowork 变体无此行**）＋ 一句「读 `<派单件仓库根相对路径>` 全文＋ `CLAUDE.md` 恢复上下文，按该件执行。本件为 A／B 类」。**正文（做什么／不做什么）写进派单件，不写进开场词**——手抄这四行最常漏的是 `【设置】` 某一字段与标题占位符，而生成器拼装后会自己过一遍 `工具-opener块lint.py::check_block`，漏不掉。

## 取号

`grep -rhoE "OP-?[0-9]{4}-?[A-Za-z0-9]+" 1-转型规划 | sort -u` 看当日已用，取下一个字母；🔴 日期用本机 `Get-Date` 当场重取。**短形 `MMDDX` 只用于 session 名，其余一律全称 `OP-MMDD-X`。**
🔴 **取号一律经 `工具-opener生成.py`（撞号即拒并给下一个空号），不裸 grep 后手抄**——grep 只看得见已落档的号，生成器还看得见**未落档的占位**（下条）。

🔴 **OP 号的占用语义（openspec `opener-id-claim-semantics`，Shao Peishen 2026-09-08 答 `1(a)` design 放行、2026-09-10 回填；两桌全局）**：
1. **永久占用只认「已落进仓库某份 `.md`」**（design ①(a)，`#487` 裁定 ⑵）。取到号但当次 opener 从未派出 ⇒ **该号当场作废、不预留**，他人当日可再取到同一个号；🔴 **不得**为「等下可能会用」把号手写进任何文件占位。
2. **取号→落档之间的真空由机器占位补（队列 §一 `#549` ⑶，2026-09-10 追加授权）**：`工具-opener生成.py` 出件即在 `<主工作区>/reports/op-id-claims.jsonl` 写一条**有时效**（`CLAIM_TTL_MINUTES`，Shao Peishen 2026-09-10 答 `1a` 定为 120 分钟）的占位；查重同时扫已落档文件与未过期占位；落档后或到期自动清理。到期未落档即作废＝第 1 条「未派出即作废」的机器实现，**不是**第 1 条禁止的手写占位。同一份草稿（短名相同）重生成不撞自己；同一条线起两份不同的件传同一个号照样撞。**成因**：2026-09-10 `OP-0910-I`／`OP-0910-J` 两次撞号都在起草期、都没落档，旧查重两边都看不见；同日 `OP-0910-H` 被拦只因对方已落档。
3. **例外写明（design ②(a)）**：接力卡「⏳ 本线在跑会话」表在 `1-转型规划/` 树内，登进去的号**会**被查重扫到、**会**挡号——这是可见性的副作用，接受它、不跳过（不为让措辞干净再造一条会漂的结构判据）。
4. **队列 §一／§四 的行编号（`#503` 这类）不适用本节**：按协议〇.8 永不复用、预留即烧号（design ③(a)），两套语义不得互相援引。
🔴 **残余如实写明**：占位只覆盖同一台机器上的两桌（台账按 `git rev-parse --git-common-dir` 落主工作区、各 worktree 共享，但不进 git、跨机器不可见）；同一秒内两条线各自取号仍可能撞——**收口时不得表述为「撞号已根治」**。

## 编号脱形（2026-09-08 定，两桌全局）

🔴 **批次号的尾段必须是语义词，不得是单字母** —— 写 `B-0908_看护五泳道`，**不写 `B-0908_B`**。

**成因（实撞，不是洁癖）**：2026-09-08 当天同时存在 `OP-0908-B`（【Cowork】FI6 需求 grill 会话）与 `B-0908_B`（泳道看护批），而看护者标题按旧模板拼成 `[Win]0908C-看护B-0908_B` ⇒ **一个标题里两个编号、库里还躺着第三个同形的 `OP-0908-B`，三个「0908 加一个字母」指三件事**。Shao Peishen 当场指出「这个 session 有两个编号很容易搞混」。

**两条改法，同批生效**：
1. **标题只放 OP 短号**：`标题：[Win]MMDDX-看护<语义短名>`（如 `[Win]0908C-看护五泳道`）。**删掉批次名不丢任何追溯能力**——本件开篇即写「追溯认 OP 号，不认 `[Win]` 标题」，标题里的批次号本来就是冗余；批次仍由【设置】行的 `派出线：…（批 B-…）` 与看护件路径承载。
2. **批次名尾段用语义词**：`工具-共享文档编辑锁.py` 的 `BATCH_NUMBER_PREFIX_RE = ^(B-\d{4}_[^_\s]+)` 只要求「非下划线非空白」，**语义词照过，无需改任何工具**。

⚠️ **历史批次名不追改**（`B-0908_B1`…`B9` 等保持原样）——同「历史记录不追改」；新旧会并存一段时间，这是已知代价。

🔑 **判据一句**：**同一份东西的标识只出现一次；两套编号如果长得一样，迟早会被当成同一个。**

🔴 **开新会话先登本线接力卡的「⏳ 本线在跑会话」清单**（编号／会话名／触碰区／起止），**收工划掉**——
**这张表只为可见性（让别人看得见谁在跑、碰什么），不构成占号**（design ①(a)，2026-09-10 改写）：号算不算被占只看「取号」节的语义；
