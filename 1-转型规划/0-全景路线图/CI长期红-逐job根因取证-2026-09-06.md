## 五、附：本次顺带实测坐实的另一处「机制内部静默」——登记为 `#398` 第 ⑹ 处

**不是推演，是本次自己踩到的。** 本会话在 §二 登记批次 `B-0906_SC7env` 后，sweep 如常落库，但生成的 commit 信息**只有字面量 `.env` 五个字符**（master 上的 `1d234dd`，可复核）。原意的信息是：

> `docs(队列#354): 判据二 ` **`` `.env` ``** ` 锚定存量清零回写 —— SC7 …`

**根因**（`0-学习与工具/工具-落库sweep.py:2437-2439`）：

```python
def _extract_commit_message(message_cell: str) -> str:
    match = re.search(r"`([^`]+)`", message_cell)
    return match.group(1) if match else message_cell.strip()
```

它取 §二「建议 message」格里**第一个反引号跨度**当作整条提交信息。约定是「整条信息用反引号包起来」，但该约定**没有任何校验**：只要信息正文里先出现了别的反引号（本例是 `` `.env` ``），提取到的就是那一小段。

🔴 **失败形态**：`git commit` 成功、退出码 0、sweep 不打任何告警、批次照常销行标 ✅。**唯一的受害者是 git log 的可追溯性**（IATF 16949 要求），而那正是没人会当场去看的地方 ⇒ 与本行 ⑴⑵⑶⑷ 完全同族，与 ⑸（`_strike_off_rows()` 不检查 `release` 返回码）同为 `工具-落库sweep.py` 内部静默。

⚠️ **它比 ⑸ 更容易复发**：⑸ 需要一轮里有 2+ 个待提交批次才现症状；本条**只要 message 正文里出现任何一个反引号就必然触发**，而本项目的 message 正文几乎必然带反引号（路径、文件名、commit 号）。
