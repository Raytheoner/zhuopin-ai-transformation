## 二、为什么 sweep 自己解不开（别指望再等一轮）

sweep `main()` 顺序是：`_push_any_unpushed_commits` → **`_sync_master_if_behind_origin`** → `_verify_fast_forward` → **批次处理**。

`_sync_master_if_behind_origin` 跑 `git merge --ff-only origin/master`；**本地队列文件是脏的，而 origin 侧 `080b544` 改的正是队列文件** → git 必然拒绝 → 抛 `SweepAbort("跳过本轮，不强推、不 rebase")` → **批次处理排在其后、根本走不到**。

**⇒ 每小时空跑一次，且本地脏只会越积越多。今日已两次手工介入。** 结构性成因与三个候选修法见队列 **#288**（由派单件 B 建造，本会话不做）。

## 三、要做的事

1. **先复核现状**（`git status --porcelain`、`git rev-list --count HEAD..origin/master`），与 §一 不符就先停下报告，别照着旧快照做。

3. **commit**（建议 message 见 §五）。
4. **`git pull --rebase`** —— 队列文件两边都改过，**有冲突概率**。
   - 冲突处理原则：**队列是追加型文件，两边内容通常都要保留**，逐段合并、不要整块取一边；
   - 合并后**必须复核**：§一 编号无重复无丢失、各行列数为 8、§二 各行列数为 4；
   - 拿不准就 `git rebase --abort` 回干净态并报告，**不要硬合**。
5. **push**，确认 `git rev-list --count origin/master..HEAD` ＝ 0。
6. **销 §二 三个批次的行**（状态列改 ✅ 并注明"本次由 CC 手工解卡提交，非 sweep 落库"）——改队列前先取协议〇.7 编辑锁，改完立刻 release。
