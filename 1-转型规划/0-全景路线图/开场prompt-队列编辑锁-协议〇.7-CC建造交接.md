【任务】建一把"文件锁 + 协议"（advisory lock，靠两桌都遵守）：

1. **锁工具** `0-学习与工具/工具-队列编辑锁.py`（纯标准库）：
   - `acquire(who, note="")`：锁文件＝队列同目录 `.queue-editing.lock`。
     · 无锁 / 锁陈旧（mtime > 30 分钟，视为持有者已挂）→ 写锁（内容＝who+ISO时间戳+note），返回 0（拿到）。
     · 有新鲜锁且非本人 → 返回非 0（占用中）+ 打印当前持有者与年龄。
   - `release(who)`：锁属本人则删除；不属本人不删（打印告警）。
   - `status()`：打印当前持有者/年龄/是否陈旧。
   - fail-safe：任何异常显式报错（不静默放行）。
2. **协议〇.7**（写进 `跨桌任务队列.md §〇`，四条之后加第 5 条）：
   「改本文件前先 `python 0-学习与工具/工具-队列编辑锁.py acquire --who "<身份>"`；
   占用中（返回非0）则**不改本文件**、把要登记的内容先记进自己的域接力文件待回补，
   锁清后（或下次开工）再回补；改完立刻 `release`。两桌（Cowork/CC）均遵守；
   锁文件本地、30 分钟陈旧自动可接管。」
   ⚠ 编辑 §〇 时若队列正被热写，走 acquire 拿锁后再改（本工具的第一个真实用户＝dogfood）。
3. **CLAUDE.md §5** 加一句指针：跨桌任务队列纪律下补「改队列前先 acquire 队列编辑锁
   （协议〇.7 / `工具-队列编辑锁.py`），占用改写域接力待回补」。
4. **`.gitignore`** 加 `.queue-editing.lock`（锁文件不入库）。
5. **单测**：acquire 空锁成功 / 新鲜锁被占返回非0 / 陈旧锁可接管 / release 只删本人 /
   并发两 who 只一个拿到。
6. **skill 登记（不阻塞）**：zhuopin-kickoff-prompt / zhuopin-queue-audit 下次重打包时，
   在"开工"段补"先 acquire 队列锁"、"收工"段补"release"——本次仅在队列登记该 backlog，
   skill 本体在 Cowork 只读、CC 侧若可改则同改。

【验收】工具 + 协议〇.7 + CLAUDE.md 指针 + gitignore + 单测全绿；真实跑一遍
acquire→（模拟第二会话 acquire 返回非0）→release 演示锁生效。

【红线/边界】advisory 锁（靠协议遵守，非 OS 强制）——够用即可，别过度工程成分布式锁；
锁只保护"编辑期"、不改队列内容语义；不碰其他域在办任务。
