## 任务分段

### A 段 · 开工核实（**必须先做完，不要跳到升级**）

**A1 实测当前版本**（不信登记值——A 阶段的第一条教训）

- **验收**：写明实测版本；**若与登记的 v6.1.1 不符，这本身就是有价值的结论**，须回填 `环境依赖清单.md` 并在队列留痕（同 A 阶段对 OpenSpec 的处置）。

**A2 核实"独立 worktree 内升级"是否技术可行**
- 判断 SuperPowers 的安装作用域（全局用户级 vs 项目级 `.claude/settings.json` 的 `enabledPlugins`），确认能否在不改主工作区全局配置的前提下，只让某个 worktree 用 6.2.0。
- **验收**：给出"可行／不可行／可行但有副作用"的明确结论 + 依据。**不可行也是合格结论**，转 §五 问题 1 的备选路径。

**A3 全库 grep 三处 breaking 引用**（队列 #205-B 已列，勿重复推导）
- `review-package` 调用签名、`.superpowers/sdd/` 路径、`testing-anti-patterns.md` 文件名。
- ⚠️ **grep 范围须含五个 `.claude/worktrees/*`**——它们最深的落后 master 338 提交（#207），很可能仍在用旧签名。
- **验收**：逐处列出命中位置与是否需要跟改；**零命中也要写"已扫、零命中"**，不要留空。

### B 段 · 升级与试跑（A 段结论支持才做）

**B1** 按 A2 的结论在**独立 worktree** 升级；升级前后各固化一次证据（版本、受影响目录/文件基线）。
**B2** 跑通一次完整 SDD 流程（写测试 → 实现 → review），确认既有工作方式未被 breaking 面打断。
**B3** 🔴 **逐文件过目 diff，判据用「中文行增删计数」**——A 阶段正是靠它抓到 `openspec update` 删掉了 13 行中文定制段（删 13 增 0、且仅一个文件）。**SuperPowers 同样可能覆盖本地定制，不要假设它只动自己的文件。**
- **验收**：SDD 全流程跑通记录 + diff 过目结论（**"无本地定制被覆盖"也须明写，不能只说"diff 属预期"**）。

### C 段 · 两条定性风险的处置（**勿当理由直接吞**）

**C1** 队列 #205-B 记的"worktree 清理静默 no-op ↔ #98 九个空壳残壳"**只是假设**——**#125 已有另一个已知成因**（`git worktree remove` 非原子失败先清空目录），Shao Peishen 拍板时明确说过"**未必需要靠升级来解释**"。
- **验收**：给出"成立／不成立／无法判定"三选一的结论 + 依据；**新假设不得替换旧成因**，两者可能并存。**参考 A 阶段对 #196 的处置——那次结论是"证伪"，而证伪同样是有价值的结论。**

**C2** "Windows SessionStart hook 修复命中本机形态（路径含中文与空格）"一说**环境保障线未采信**——其 bug 描述是路径含 `(` 等**元字符**致命令截断，**空格/中文与 `(` 不是一回事**。
- **验收**：判据＝**当前 bootstrap 是否正常加载**，须实测后才算数；若一直正常，则本机未命中该 bug，**该条不构成升级理由**，如实写。
