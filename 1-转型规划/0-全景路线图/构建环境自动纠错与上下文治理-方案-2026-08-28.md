# 构建环境自动纠错与上下文治理 · 方案（决策稿）

> **一页结论**：⑴ Claude.exe 安装位置**正常**（MSIX 打包应用的标准位置，实测坐实，不需要也不应搬动）；⑵ memory 双目录的根因＝MSIX AppData 虚拟化（写容器、查真路径），「memory 层停用」的**结论不变、根因需勘误一行**；⑶ CLAUDE.md 57.4 KB 与 session 后半段规则失守是**真问题**，治理路径＝「瘦身下沉」＋「把高频人守规则转成项目级 hooks 机制守」。外部文章理念方向对、配置细节多处失真，**只取理念、全部配置以本机 P0 探针实测为准**。

## 一、三个问题的裁定

### 1.1 Claude.exe 安装位置 —— 正常，不动

本机实测（`Get-AppxPackage`，2026-08-28）：

```
Name            : Claude
Version         : 1.37937.3.0
InstallLocation : C:\Program Files\WindowsApps\Claude_1.37937.3.0_x64__pzs8sxrjxfjjc
```

`C:\Program Files\WindowsApps\` 就是 Windows 对 **MSIX 打包应用**的标准安装根（与商店分发同机制），不是装错了位置。该目录受系统 ACL 保护，**不可、也不应手工迁移**。它带来的唯一副作用是 **AppData 虚拟化**：应用自己写 `%APPDATA%\Claude` 时被 Windows 静默重定向到包容器（`...\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Roaming\Claude\`），而外部工具（含 Claude 会话内的 Write/Read）看到的是真路径——同一"地址"下两棵树。这正是「OneDrive 仓库迁出方案」session 实证的结构，**与仓库迁移无关**（探针文件 7/4 即已在容器）。

### 1.2 memory 双目录 —— 结论不变，根因勘误一行

- **维持**：CLAUDE.md 顶部「memory 层已收割并停用」的处置结论**不变**——读写两侧对不上，该层依然不可信；「不读、不写、不引用」「不得新建第四份载体」照旧。
- **勘误**：判死记录里"无写入口、Write 报 success 不落盘 fail-silent"的**根因归因是错的**——实为"写进真路径、注入读容器"。现象与结论都对，根因换成 MSIX 虚拟化。建议在 CLAUDE.md 顶部 memory 段**加一行勘误指针**（不改写原文，符合"历史记录不追改"；勘误正本＝本文件 §1.1-1.2）。
- **容器内文件不动**：容器那份是应用真正在用的、内容更全；删或合并真路径侧文件只会丢东西（沿用该 session 结论）。
- **边界提醒**：Claude Code CLI 近期版本传闻的 auto-memory（`~/.claude` 侧、与 Desktop memory 目录**不是同一物**）若 P0 探针证实存在，需单独裁定是否启用，**不自动继承判死结论，也不自动豁免**。

### 1.3 CLAUDE.md 过大与后半段失守 —— 真问题

实测：根 CLAUDE.md **57,433 B**（sweep 阈值 90 KB 未触发，但主观失守已现）；`5-平台底座` 4,030 B、`4-数字员工` 3,213 B（下沉健康）；全局 `~/.claude/CLAUDE.md` 10,716 B。57 KB 的根文件每 session 全量注入，长会话后半段注意力被摊薄——**这不是纪律写得不好，是纪律的"常驻成本"超了预算**。治理见 §四支柱一/二：能下沉的下沉（少注入），能机器拦的交给 hooks（不依赖注意力）。

## 四、方案主体：三支柱

### 支柱一 · 上下文预算治理（CLAUDE.md 瘦身下沉）

**目标：根 CLAUDE.md 57.4 KB → ≤30 KB**，每条迁出守 J1（先有承接载体）。

| 手段 | 内容 | 预估减量 |
|---|---|---|
| A. 人员名录下沉 | §1 人员名录与性别（约 6 KB）迁独立正本（建议 `6-人才与组织/人员名录-称谓与性别-正本.md`，跟进信 README 与 zhuopin-followup-letter skill 已各有承接），根文件留 3 行硬指针：「提到任何人名，先读名录正本；名录外人物用中性称谓并当场问」 | ~5 KB |
| B. §5 长论证再压缩 | 逐条把"判据＋一行成因指针"之外的论证性文字迁 CHANGELOG 附录（多数已迁，剩余如串行闸/决策路由段仍有压缩空间） | ~8-12 KB |
| C. 子目录 CLAUDE.md 扩容 | 新增 `6-人才与组织/CLAUDE.md`（跟进信纪律＋名录指针＋串行闸判据），跟进信相关规则从根文件降为指针——只在动该目录时注入 | ~6-8 KB |
| D. `.claude/rules/` 路径作用域规则（**待 P0 证实**） | 若当前版本支持 paths frontmatter 按需加载，则 C 的内容可再前移一层：编辑命中 glob 才注入 | 视探针结果 |

⚠️ **两个不做**：① `@import` 不用于瘦身——import 展开后同样占预算，只是组织手段；② 不迁"红线/称呼纪律/时间戳"这类**任何 session 都可能踩**的全局硬规则——它们留在根文件，但按支柱二转成机器拦截后，正文可压成一行。

### 支柱二 · 机制守扩容（项目级 hooks，六个哨兵）

配置落**项目 `.claude/settings.json`**（入 git、两桌共享），脚本落 `0-学习与工具/hooks/`（`$CLAUDE_PROJECT_DIR` 相对引用）。全部沿用现有 pretooluse-guard 范式：**stdin JSON → 判定 → exit 2 拦截／exit 0 放行，异常一律 fail-open（catch{exit 0}）＋ timeout 10s**——哨兵故障绝不阻塞正常工作。

| # | 哨兵 | 事件 | 判据（承接的人守规则） | 拦截方式 |
|---|---|---|---|---|
| H1 | 日期哨兵 | PreToolUse Edit\|Write | 目标∈{队列/接力/跟进 README/CLAUDE.md} 且新写入内容含与本机 `Get-Date` 不符的"当前日期位"日期（承接：时间戳写侧硬规则，历史 ≥2 轮事故） | 先 warn 两周→block（启发式有误拦风险，白名单"历史记录不追改"类编辑） |
| H2 | 队列锁哨兵 | PreToolUse Edit\|Write | 目标命中 `跨桌任务队列*.md` 且未按协议〇.7 持锁（判据以协议〇为正本） | block |
| H3 | 乱码哨兵 | PostToolUse Edit\|Write | 写入的 md 路径或内容出现 U+FFFD／BEL 类控制字符（承接：乱码文件夹哨兵＋UTF-8 回读抽验，07-04 与 08-19 两例） | exit 2 反馈模型当场修复 |
| H4 | 代词哨兵 | PostToolUse Edit\|Write | 目标命中 `6-人才与组织/部门AI专员跟进/*.md` → 全文第三人称代词逐个对名录正本核对（承接：称谓纪律，历史 ≥6 次翻车、244 处写错） | exit 2 列出违例行 |
| H5 | 收工哨兵 | Stop | 本 session 改过队列触碰文件但状态列/批次疑似未回写 → 提示（须校验 stop_hook_active 防循环） | advisory，不 block |
| H6 | 开工注入 | SessionStart | 注入当日 `Get-Date` ＋ 接力卡路径 ＋ 开工三读一句提醒（把开场纪律从"人记得"变"系统给"） | 纯注入 |

**优先级**：H1/H3/H4 是历史复发最贵的三类错（日期、乱码、代词），P1 先做；H2/H5/H6 进 P2。
**与全局层的关系**：全局 protected-paths 现会拦 AI 改 `.claude/settings.json`——这是正确的自我保护；部署时临时切 warn 或人工改，改完切回 block，并把 `0-学习与工具/hooks/*` 纳入 protected-paths。

### 支柱三 · 错误复盘升格路径（补一环，不另立体系）

现有链条"错误→CHANGELOG/取证知识库→队列行→（3 次违反）规则退休制机制化"已是文章理念的强化版，只补两环：① opener 模板库 §〇 增设**有限重试标准段**（≤3 次、每次换方案、超限如实报告并禁复用同方案）；② 收工自检增一问：「本次有没有新判据只活在报告文本、还没落承接载体」。

## 七、风险与收益

**风险**（均有对策）：① 哨兵 bug 阻塞工作 → fail-open＋timeout＋warn 先行＋protected-paths 保护脚本自身；② H1 启发式误拦 → warn 两周实测误拦率再转 block；③ Cowork 不吃 hooks → 收益缩至 CC（写码/写队列的高危面本就在 CC），Cowork 侧维持 sweep 兜底，不算方案失败；④ 规则载体再+1 处（settings.json＋hooks 脚本）→ 纳入 protected-paths 与文档台账，hooks 清单以本文件 §四为正本；⑤ 二手资料失真 → P0 闸死。

**收益**：① 三类历史最贵复发错（日期/乱码/代词）从"事后发现、有的撤不回"变**当场拦截**；② 根 CLAUDE.md 每 session 少注入 ~27 KB，直接缓解后半段失守；③ 人守条目净减 ≥4 条（守规则退休制方向：机制化优于人记）；④ 开场纪律自动注入，降低新 session 冷启动漂移。
