## Phase 0 · 零 Token 度量基线

**目标**：本机脚本只读解析 `%USERPROFILE%\.claude\projects\**\*.jsonl`，不调用任何模型，产出周报。

**交付**：`0-学习与工具/工具-Token用量度量.py` ＋ 单测；输出 `reports/token-usage-<起>-<止>.md`。

**指标口径（写死）**：
1. 按日、按模型统计 input / cache_creation / cache_read / output 与请求数
2. 按会话统计：请求数、工具调用数、上下文峰值（单条请求 input+cache 之和的最大值）、累计 cache_read；Top20 附会话首条用户消息前 60 字作为标题
3. 开场底噪：每个会话首次请求的 input+cache 总量（P50/P95）
4. 机制税：Bash 命令命中机制工具白名单的占比
5. 看护会话识别：Bash 中 `check-heartbeat|check-timeout|summary` 调用占比 > 30% 的会话

**验收**：跑出 09-06 ~ 09-13 基线，与 Antigravity 报告的 26,166 次请求、45.8 亿 cache read 对账，差异写明原因。

## Phase 1 · 模型路由默认 sonnet

**改动**：
1. `工具-opener批处理执行v2.ps1`：把 `-Model` 默认值由 `''` 改为 `'sonnet'`；显式传 `-Model opus` 时照常生效
2. `patrol_dispatch.py`：argv 加上 `--model`，默认值为 `sonnet`，从模块常量读取；`test_patrol_dispatch.py` 增加 argv 断言
3. opener【设置】行增加「模型：sonnet｜opus」字段；`工具-opener生成.py` 与 `工具-opener块lint.py` 同步（缺省视为 sonnet）
4. 根 CLAUDE.md §5 加一行路由纪律：无头/看护/巡检/批量跑测默认 sonnet；design 起草、需求 grill、ASIL/合规建造可在 opener 里显式写 opus

**不做**：不限制交互式 Cowork/总线会话的模型（由 Shao Peishen 在 app 内自选）。

**验收**：全局 grep 找出所有 `claude -p` 调用点，确认每一处都带 `--model`；P0 周报里无头会话的 Opus 请求占比 < 10%。

## Phase 2 · 看护脚本化 + 长会话切段（主战场）

**2A 看护脚本化**
- 新增 `0-学习与工具/工具-泳道看护等待.py`（Python，复用 `工具-泳道看护状态机.py` 的函数，不再另写一套 PowerShell）
- 用法：`wait --batch <批次> --max-wait 540`。脚本内部每 15 秒轮询心跳、状态文件、进程和锁，**只在出现事件时退出**，退出码区分 DONE/PAUSED/NO-HEARTBEAT/TIMEOUT/MAX-WAIT，并输出 ≤20 行摘要
- `--max-wait 540`：CC 的 Bash 工具单次上限 10 分钟，所以 LLM 每 9 分钟最多被唤醒一次，而不是每轮都自己查
- 改 `zhuopin-lane-watch` SKILL §5：看护循环改为「调用 wait → 按退出码处置」，删掉逐项手动轮询的步骤

**2B 长会话切段**
- 硬线：单会话工具调用 ≥150 次或上下文 ≥150k 时，当前里程碑完成后必须出接力卡并换新会话（先按 150 次执行，P3 完成后收紧到 100 次）
- 落点：`zhuopin-kickoff-prompt` 转场判据 ＋ 根 CLAUDE.md §3 一行
- 机器护栏：PostToolUse 挂一个计数 hook，写 `reports/session-steps/<sid>`，达到阈值时注入一次提醒（仅提醒，不拦截）
- 跑全量回归、大范围 grep 这类重输出步骤，交给子代理执行，主会话只接收结论

**验收**：P0 周报里 ≥300 次调用的会话数从 11 降到 0；看护类会话的请求数下降 ≥80%。

## Phase 3 · 机制税削减（新增）

**问题**：一次常规的「改一份共享文档」要经过取锁 → 编辑 → lint → 放锁 → 登记，通常要 4–6 次 Bash，每次都是一轮 LLM 往返。

**改动**：
1. 取 P0 统计出的前 5 个高频机制调用序列，各合成一个复合子命令（例如 `工具-共享文档编辑锁.py commit-edit --file X --patch <patch>`：取锁、应用补丁、lint、放锁、登记一次完成）
2. 所有机制工具默认 `--quiet`：成功只输出一行，失败才输出详情
3. opener 骨架里的收工段改为调用复合命令

**不做**：不放宽任何锁/lint/登记判据，只合并调用次数。

**验收**：Top 会话中机制类 Bash 占比从 30%–48% 降到 <15%；现有机制单测全部通过。

## Phase 4 · 输出截流

1. 仓库级约定：`pytest -q --tb=short`，并加 `-x` 或 `--maxfail=5`；opener 骨架统一替换
2. sweep、lint、扫描器默认输出摘要，全文写入 `reports/`，只回显路径
3. 在 CLAUDE.md §5 增加一句：单条命令预计输出超过 200 行时，必须先重定向到文件再用 head/grep 读取

**验收**：抽 P0 Top20 会话，单条工具结果 >10KB 的次数下降 ≥80%。

## Phase 5 · 开场底噪瘦身（以 P0 实测为准）

1. 根 CLAUDE.md 从 18.5KB 降到约 10KB：叙事性成因迁入 CHANGELOG，只留指针；常驻纪律、路由表不删；跑 `工具-CLAUDE进度段lint.py`
2. 项目 skill 的 description 压到每条 ≤200 字，详细触发词移入 SKILL.md 正文（listing 每次请求都带，正文只在调用时加载）
3. 评估无头泳道是否需要 `superpowers` 插件：若 P0 显示它的开场注入明显，泳道会话里停用（通过泳道专用 settings 或启动参数），交互会话保留
4. 全局 `~/.claude/CLAUDE.md`（报告称 9.6KB）另起一件审阅，与项目 CLAUDE.md 去重

**验收**：P0 周报里开场底噪 P50 下降 ≥20%，具体数值以实测为准；不追求 25k。

## Phase 6 · 巡逻无状态化 ＋ Stop hook 复核（收尾）

1. `patrol_dispatch.py`：删掉 preamble 中「回到 §一 再走一轮」的指令；由调度层在子进程退出后复查 `patrol_signal.json`，有信号就另起一个新会话。必须补一个单测：锁占用期间到达的信号不能丢
2. Stop hook：保持硬拦截，不改为 Warn。只在 P0 显示 violation 率 >15% 时，才考虑把「答复模板」判据放宽
3. `hooks-pretooluse-queue-read-guard` 每次 Read/Grep/Bash 都会启动一次 pwsh（8 天 1.16 万次）：这不耗 token，但影响速度，记为另一件（环境线）
