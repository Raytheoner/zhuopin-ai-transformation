## Q3｜错误的方法与思路（应避免清单，全部有实证）

1. **把挂载副本当真身**（错了 4+ 次）：一切"文件变旧/截断"恐慌均源于此。已立直读原则+排查顺序（git branch/reflog → 桌面直读 → 才疑真损）。
2. **大内容过上下文手抄**（base64 28KB 手抄即损坏）：跨环境传文件一律走"文件中转 + 哈希校验"，永不手抄。
3. **真机写操作的命名/别名雷区**（RD→Remove-Item 险案）：用户真机脚本一律显式 cmdlet 全名 + 只读约束 + 先排雷。
4. **长 prompt 复制正文导致双份漂移**：已被引用版 prompt 取代——权威内容只在移交单/定稿里，prompt 只放指针。
5. **"布置写作业"式就绪单**（FI1 卡壳一个月的根因）：已被三步法取代，永不回退。
6. **在他人活动分支上改 git 跟踪文件**：CC 亲历一次（docx 转在 FI2 分支上）并自纠；规则=动权威文档前先 `git branch --show-current`。
7. **平均值指标掩盖分字段真相**（8D 校准 37.9% 的教训）：任何 AI 能力评估按"分字段/分档位"呈现，拒绝单一均值。
8. **文件名里带会变的数字**（甘特图 40→42→40 三次改名）：命名去数字化已执行，命名规范入 Q6 治理文件。
9. **误判他人已完成的工作为漏洞**（fix-a/b/c 归档误报、"陈嵚"typo 误报）：审计结论必须先核证据再落纸——triage 驳回机制已在用，保持。
10. **空转的定时任务**（Morning briefing 连接器未授权、零项目联动，纯耗费）：对照 U9C reminder（强联动、有产出、还会自建议降频）——**定时任务的标准=必须读项目文件、产出可执行项**。建议：停掉 Morning briefing（或授权日历/邮箱后再开），保留 U9C reminder 并按其自身建议降频，新增一个"值周巡检"（见 Q5）。
