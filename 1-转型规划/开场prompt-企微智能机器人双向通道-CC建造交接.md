## 任务分段

**A. openspec propose + design（先做，停下等 Paul 审）**
按 §5 场景流程走 openspec；定位建议=平台底座共享件（`shared_tools/notifiers/` 新增 aibot 连接器 + 独立常驻监听服务目录），归属由 design 给方案、Paul 拍板。design 须覆盖：单连接约束（同 BotID 新连接踢旧连接→主备/看门狗策略）、心跳保活（约 30s）与断线重连、凭据管理（BotID/Secret 只入 `.env`，gitignore）、与现有 webhook 通道的关系。
✅ 验收：design.md 过 Paul 审。

**B. 连接层 MVP（mock 先行）**
装 SDK 或直连 WebSocket，实现订阅（aibot_subscribe）/心跳/重连/收发骨架；先用测试群 echo 验证（收到 @消息原样回），不接业务。注意订阅请求有频率保护，勿反复重连触发限制。
✅ 验收：测试群 @机器人 → 服务收到回调并回声；断网重连自愈；全程 audit 留痕。

**C. 场景①：推送跟进信**
`aibot_send_msg` 推 markdown 正文；docx 附件走上传临时素材（初始化/分片/结束三步）。发送成功后**回填落档**：README 清单该行标"已推送+时间"（跟进信本体仍按纪律先落 `6-人才与组织/部门AI专员跟进/`，机器人只是送达通道）。
✅ 验收：一封既有跟进信 md+docx 推送到测试群成功，README 回填自动完成。

**D. 场景②：收专员反馈自动归档（R6 自动化）**
收到专员消息/文件（文件走多媒体资源解密）→ 自动存 `7-外部文档/<部门>/` 按 R6 命名规范落档（该目录 gitignore，注意别误入库）→ 登记 → 向 `跨桌任务队列.md` §一追加"待领"行（领取方=对应域专线）。部门归属按发送人映射四域专员（依据 4）。
✅ 验收：测试群传一份 xlsx → 正确落 `7-外部文档/<部门>/` + 队列出现追加行；中文文件名完整（写后读回抽验，防 U+FFFD——§5 哨兵纪律）。

**E. 两条门禁（写死进代码 + design 落字，Paul 拍板项，不得放宽）**
① 收消息只做**归档/登记/通知**，不自动执行任何业务动作（不改口径文档、不回业务承诺、不触 ERP/SRM）；② 发送侧仅限**已定稿**跟进信（README 已登记为准），草稿不外发。对客外发闸（CUSTOMER_OUTBOUND_ENABLED）不涉及本服务，专员均为内部人员。
✅ 验收：门禁有单测覆盖。
