## 【最近一次会话：2026-06-29 · 专线首次建立】

### 主攻：P0 缺料预警误判口径校准（业务侧）

**做了什么**
1. 按开场 prompt 读全上下文（CLAUDE.md §4/§5/§7、采购域工作任务书、就绪清单 §P0、采购专员首月工作信、supplychain 收割策略）。
2. **对真实代码确认了根因**（只读、未改）：`kit_engine.calc_shortage()` 的 B6 特例——子件不在库存快照、又无在途 PO 时，可用量被算成 0，毛需求一减报假缺口；且该子件**同时进了 `missing_snapshot` 告警清单和 `shortages` 缺料集合**，下游当确定缺料追了。源码注释明确 `get_inventory` 真实切换后该路径"必踩"，佐证这是**库存快照覆盖/料号口径数据问题**，非算法错。
3. 产出 **《缺料预警校准需求.md》**（1-转型规划/，v0.1，交 CC）：现象 → 根因（带代码定位）→ "真缺料"业务口径定稿 → 改判定要求（数据补全 + fail-loud 双手）→ 排查步骤(谁干什么) → 验收标准 → 红线 → 待确认决策点。
4. 建本专线接力文件（首次）。

**Paul 3 项裁定（2026-06-29）**
- **本次范围**＝**仅 P0 缺料校准需求** + 专线接力文件；SC3/SC5/O2 部署规则、SC1/SC8 价值验收下次做。
- **快照缺失处理**＝**数据补全 + fail-loud**：补快照覆盖/料号映射，且子件快照缺失时引擎**显式告警"覆盖不全"、不静默判缺料**（移出确定缺料集合、单列"待核实"清单）。
- **可用库存口径**＝**现货 + 在途 − 安全库存**（在途=已下 PO 未到货；已批请购暂不计入；安全库存扣减）。净需求 = 毛需求 − 可用库存 > 0 才算真缺料、才追料。

**核心发现（供下次会话快速恢复）**
- 误判**大概率纯数据问题**：毛需求由 `explode_bom` 按生产计划(FO/SO)展开，无订单驱动的子件毛需求本就为 0、不会进判定——所以"有货却被追"的料是**真有 BOM 需求 + 真有库存，但库存没喂进引擎**（快照漏仓 / 料号 SRM·BOM↔ERP 编码对不上 / 状态过滤误排）。
- 修法分两手并行：**A 逻辑护栏**（缺快照→待核实+告警，不进追料，先止血）+ **B 数据补全**（全仓覆盖+料号映射，治本让缺快照清零）。
- 验收硬指标：误判清零 + 缺快照子件不混入追料清单 + 黄金基准不漂移（SC5 35850/640000/675850）+ 回归全绿。
