# 企微智能机器人双向通道服务 — 部署到长开服务器（192.168.100.51）

> 与 supplychain / SalesMarketing / SC8 保供看板**同一套机制**：笔记本 `sync-to-server.ps1`（SSH/scp 推送 + 重启任务）
> ＋ 服务器 `deploy-server.ps1`（建 venv + 装包 + 开机自启计划任务）。**与那几个项目的关键差异**：
> 本服务是纯出站 WebSocket 客户端，**不监听任何端口、不开任何入站防火墙规则**。

## 与同机其他项目共存

| 项目 | 服务器目录 | 端口/连接方式 | 计划任务 |
|---|---|---|---|
| supplychain | `C:\supplychain` | 8080（入站） | SupplyChainWebServer |
| SalesMarketing | `C:\salesmarketing` | 8090（入站） | （销售看板任务） |
| SC8 保供看板 | `C:\baoguan` | 8091（入站） | BaoguanWebServer |
| **企微智能机器人（本项目）** | `C:\wecom-aibot` | **纯出站 wss://openws.work.weixin.qq.com**（无入站端口） | **WecomAibotService** |

四者不同目录/任务名，**同机共存不冲突**；本服务不占用任何端口，与前三者天然无冲突。

## 出站可行性（已核实前提，仍需 F 段真实联调二次确认）

.51 对企微 webhook（公网 HTTPS）出站已验证正常（见 SC8 `部署到长开服务器-保供看板.md`："三源全走公网 HTTPS→.51 只需出网"）；本服务走 WSS（同属 TLS+443 协议族），大概率可行，**但握手协议不同，design.md Risks 明确列为 B 段第一步待实测项**。若首次连接测试失败，回退方案：改部署到 Paul 本机（已知可行，`0-学习与工具/发企微.py` 先例验证过"有互联网即可"），架构不变，只是 `deploy-server.ps1` 换成本机计划任务。

## 服务器布局

```
C:\wecom-aibot\zhuopin_platform\   ← 平台底座（sync 推送，含 [aibot] extra 依赖）
C:\wecom-aibot\app\                ← 本工程（sync 推送，含 deploy-server.ps1）
C:\wecom-aibot\.env\               ← 凭据（手工放，不入库；两套凭据并存见下）
```

`.env` 需要两套凭据（design.md D1：webhook 通道并存不改）：
- `WECOM_AIBOT_BOTID`/`WECOM_AIBOT_SECRET`——智能机器人长连接凭据（企微后台"智能机器人"→长连接模式获取，队列 §四#10，**待 Paul 完成前置动作**）。
- `WECOM_WEBHOOK_URL`——既有项目群 webhook（供本服务自身故障告警用，见下"三级重启退避"）。

## 部署顺序（首次）

1. **笔记本（普通 PowerShell）** 推代码：
   ```powershell
   cd "5-平台底座\wecom-aibot-service"
   powershell -ExecutionPolicy Bypass -File sync-to-server.ps1
   ```
   （首次任务还没建，最后一步"重启"会提示失败——正常，继续第 2 步。）

2. **手动把 `.env` 复制到服务器** `C:\wecom-aibot\.env`（含上述两套凭据；`sync` 故意不推 `.env`，凭据不走网络）。
   **`WECOM_AIBOT_BOTID`/`SECRET` 需等 Paul 完成队列 §四#10 前置动作后才有真实值**——前置动作未完成时可先留空部署（服务会 fail-loud 报凭据缺失退出，这是预期行为，不是 bug）。

3. **RDP 登录服务器（管理员 PowerShell）** 跑部署：
   ```powershell
   cd C:\wecom-aibot\app
   powershell -ExecutionPolicy Bypass -File deploy-server.ps1
   ```
   建 venv → `pip install -e` 平台`[aibot]`+本工程 → 生成 `start-aibot-service.ps1`（三级重启退避包装）→
   注册开机自启任务 `WecomAibotService`（SYSTEM、`-MultipleInstances IgnoreNew` 防双实例）→ 启动。

4. **确认**：计划任务状态为 Running；`.env` 凭据填好后，`app\reports\wecom_aibot_audit.jsonl` 会持续追加连接生命周期事件（`connection_established`/`authenticated`/心跳异常/断线等）——这是本服务唯一的"健康检查"信号源（无 HTTP 端口可探活）。

## 之后每次改动（热更新）

笔记本跑 `sync-to-server.ps1` 即可——推代码 + 自动 `schtasks /End`+`/Run` 重启任务。
（依赖有变更时，去服务器再跑一次 `deploy-server.ps1` 重装。）

## 运维速查（在 .51 上）

| 操作 | 命令 |
|---|---|
| 重启 | `schtasks /End /TN WecomAibotService ; schtasks /Run /TN WecomAibotService` |
| 前台看报错 | `powershell -File C:\wecom-aibot\app\start-aibot-service.ps1` |
| 是否在跑 | `Get-ScheduledTask -TaskName WecomAibotService \| Get-ScheduledTaskInfo` |
| 查审计 | `Get-Content C:\wecom-aibot\app\reports\wecom_aibot_audit.jsonl -Tail 20` |
| 手动杀残留进程 | `wmic process where "CommandLine like '%run_aibot_service.py%'" call terminate` |

## 三级重启退避（design.md D2 第三道防线）

`start-aibot-service.ps1` 包装脚本自行实现——服务崩溃退出后依次等待 1 分钟 / 5 分钟 / 15 分钟重启，三次后仍失败则**停止重启**并经 `WECOM_WEBHOOK_URL`（既有 webhook 通道，非本服务自身）发一条告警到项目群。这不是 Windows 计划任务原生的 RestartCount/RestartInterval（只支持单一固定间隔），是本服务自己在包装脚本里实现的图层。

## 红线 / 注意

- **门禁①②写死代码结构，非配置开关**（见根 CLAUDE.md §7 / design.md D8）：归档服务不依赖任何 ERP/SRM/CRM 连接器；推送前强制断言 README 状态列。
- **纯出站，无需任何入站防火墙/端口映射**——与 supplychain/SalesMarketing/SC8 那类需要 LAN 开放的入站服务性质不同，不适用它们的"仅 LAN 无鉴权"红线。
- `app/reports/wecom_aibot_audit.jsonl` 含收发内容摘要/发送人信息 → 已 gitignore，留服务器本地，`sync` 不回传。
- `7-外部文档/<部门>/` 归档产物可能含真实业务数据 → 该目录项目级已 gitignore，本服务只写入 .51 本地（若部署到 Paul 本机同理）。
