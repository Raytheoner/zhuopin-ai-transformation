# zhuopinAI 模型消费者切换 Spec

2026-09-24。状态：现状取证完成，生产切换未完成；不得用本 Spec 代替验收。

## 目标与边界

继承原业务章程及机器判据，将模型进程从 Claude Code 迁移到 Codex；保留 Windows 脚本调度、无信号零模型调用、互斥、审计和人工业务闸。不新建一套固定频率唤醒模型的机制替换现有信号过滤器。

## 前置闭合顺序

1. 保存本地唯一提交与未提交资产；分开审查迁移资产和既有业务改动。禁止全分支 force-push 或把 settings 备份直接入库。
2. 将经过审查的 AGENTS、项目技能、原生 hooks、消费者适配代码纳入版本控制。用 `git show <基线提交>:<路径>` 检查，再建新工作树验证实际继承；主树文件存在不能替代此项。
3. 统一 provider 配置、可执行文件解析、退出码和审计格式。保留原 Claude 配置用于有依据的回退，但当前订阅被禁用时不能宣称回退可用。
4. 显式配置 Codex 模型策略；Claude 的 sonnet/opus 不得透传给 Codex，也不臆造价格或等价关系。先继承已验证的本机 Codex 配置，再根据真实调用数制定分层路由。
5. 先隔离夹具，再原生 CLI 最小任务，再单条真实机制任务；验收后才改现有 Windows 任务入口。五个暂停的 Codex 自动化不得与 Windows 轮询守双跑。
6. 检查任务 Action→VBS→PowerShell/Python→模型进程整条退出码。CommitSweep VBS 当前未透传子进程返回值，需独立修复并做非零反例。
7. 核实 Cowork 仍在云端/桌面生效的任务。目录为空或读取失败不能视为任务不存在。缺少这部分证据时不宣称全量消除了双跑。

## 验收输出

每次运行记录 provider、实际模型（能获取时）、原生会话 ID、源业务 ID、工作树、版本、起止时间、超时原因、进程退出码、工具事件、hook 事件、产物验证结果、调度器最终判断。OPENER_DONE 和 exit=0 只是输入证据，不单独构成成功。

每个消费者必须给出：静默/成功/失败/超时/重复触发反例，以及安装前后清单、备份、回退步骤。凭据不进入可同步配置与报告。

## 测试隔离

原轮询测试硬编码使用生产 Global\\ZhuopinPollGuard。接力测试必须在独立副本替换为测试专用 Local mutex，注入假探针、假巡检及假模型；不能让测试占用生产轮询锁。真实探针可能通知、合入、清理工作树，不得当成无副作用 smoke test 运行。
