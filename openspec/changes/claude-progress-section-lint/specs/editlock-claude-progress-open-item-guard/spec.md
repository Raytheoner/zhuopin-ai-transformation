## ADDED Requirements

### Requirement: J4 未闭合项写入侧拦截
`--file` 指向仓库根 `CLAUDE.md` 时，`release` SHALL 对**本次持锁窗口内新增的**顶部进度条目做未闭合项校验：条目正文命中未闭合措辞词表、且**未点名任何 `#N` 形式的队列行号**时，MUST 拒绝 release（锁保持占用）。

历史条目 MUST NOT 被追溯——新增判定以 acquire 快照为基准。

新增判定 MUST 按**条目正文**比对，MUST NOT 按行号比对：在顶部插入新条目会使既有条目行号整体下移，按行号比对会把整段历史条目误判为新增。

未闭合词表 SHALL 被视为**筛子而非判官**：命中即要求补承接载体；**未命中 MUST NOT 被表述为「该条目已闭合」**。词表 MUST 至少包含「未结」与「未接线」两个说法。

`--file` 指向其它目标时，本校验 MUST NOT 生效。目标识别 MUST 对绝对路径与相对路径给出一致结果，MUST NOT 只做字符串字面量比较。

#### Scenario: 新增条目含未闭合措辞且未点名队列行时拒绝
- **WHEN** 本次持锁窗口内新增一条顶部进度条目，正文含「未结」但不含任何 `#N`
- **THEN** release 被拒绝，锁保持占用

#### Scenario: 新增条目点名队列行即放行
- **WHEN** 本次持锁窗口内新增的条目含「未结」且正文点名了 `#361`
- **THEN** release 正常完成

#### Scenario: 历史条目含未闭合措辞不追溯
- **WHEN** acquire 快照中已存在一条含「尚未」的条目，本次未改动它
- **THEN** release 正常完成

#### Scenario: 在顶部插入新条目不误判既有条目
- **WHEN** 本次持锁窗口内在既有条目**上方**插入一条不含未闭合措辞的新条目
- **THEN** release 正常完成（既有条目未因行号下移被误判为新增）

#### Scenario: 非 CLAUDE.md 目标不受本校验约束
- **WHEN** `--file` 指向其它共享文件，其内容恰好含未闭合措辞
- **THEN** 本校验不生效，release 正常完成

### Requirement: J4 逃生阀 SHALL 要求写明理由并留痕
条目正文含 `进度豁免：<理由>` 时，本校验 SHALL 放行该条目，并 MUST 打印放行留痕（不静默）。

理由为空（标记之后无内容）时 MUST 仍判违规——空豁免 MUST NOT 被接受。

放行时，该理由 MUST 同时被追加进本次 release 写回的锁 `history`，使「刚才谁在这把锁上放行过」在下一次 acquire 时可见。

#### Scenario: 带理由的豁免放行且理由进 history
- **WHEN** 新增条目含「暂不做」与 `进度豁免：属产品侧，本项目无承接对象。`
- **THEN** release 完成，且释放标记的 `history` 中含该理由

#### Scenario: 空豁免仍被拒绝
- **WHEN** 新增条目含未闭合措辞与 `进度豁免：` 但其后无理由文本
- **THEN** release 被拒绝
