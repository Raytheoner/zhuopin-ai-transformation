## Why

`.51` 上四个跨部门服务（保供看板8091/命令中心8092/QD-B8093/FI2 8094）零鉴权代码、全部绑 `0.0.0.0`，公司任一联网终端可无凭据看到真实客户名、立项书财务指标、供应商单价（决策件 §三）；且各场景各自新起端口的惯性若不止住，采购域待上的 SC1/SC2/SC4/SC7/SC10/SC11、质量域待上的 8D/IQC/SPC 会让收编成本随场景数线性增长。#160 已上线的共享口令门禁（`simple_gate.py`）是半天内完成的临时止血，不区分人员、不留访问痕迹、口令 LAN 内明文传输——`统一门户架构决策件-SSO与权限-2026-07-29.md` 已经 Shao Peishen design 审通过，本变更包是其"地基线"（决策件 §六线②）的正式落地：网关 + 企微 OAuth SSO + 三层权限 + 访问日志，网关只是"在现有四服务前面加一层"，不改后端代码，可与业务开发真并行。

## What Changes

- 新增反向代理网关，统一路由规范 `/{域}/{场景}`（如 `/procurement/baoguan`→8091、`/quality/qd-b`→8093、`/finance/fi2`→8094），**四个后端服务代码零改动**。
- 新增企微 OAuth2 网页授权登录：员工企微内点开链接自动带 code 换取 userid，与现有 `wecom-aibot-service/aibot_service/whitelist.py` 的 userid 体系同源（`YaoZuYi`/`tangyanping`/`ChenChen`/`2023458`/`ShaoPeiShen`），不自建账号密码、不引入 Keycloak/LDAP。
- 新增三层权限判定（公开只读／域成员／域管理员），部门映射用手工映射表（6 行，不取企微通讯录 `contact` 权限）；敏感字段按判据（"泄露后会让外部第三方受损，或让内部产生不当信息优势"）判定，不维护穷举清单。
- 新增访问日志，与队列 #112（使用率埋点）同处一次落地，避免两次改造。
- 网关须配进程守护 + 健康检查 + 保留后端直连作运维应急通道（不对外宣传）；程序化访问（每小时全量重算、`deploy-server.ps1` 健康检查、`/api/ping`、同步脚本等）须逐项重新验证不中断。
- **本变更包不做**：① 把新场景注册进路由的"增量线"规范（决策件线①，已单独生效，非代码交付）；② 把现有四服务实际收编进网关路由的"存量线"（决策件线③，条件触发、财务→质量→采购顺序、8091 最后动，另行择期启动）——本次只交付网关能力本身。
- 网关与四个后端服务**不合并进程**，保留故障隔离（决策件 §五决策2 已收回早期"合并单进程"建议）。

## Capabilities

### New Capabilities
- `portal-gateway-routing`：反向代理 + 统一路由表（`/{域}/{场景}` → 后端服务），后端服务零改动；含网关进程守护、健康检查、应急直连通道。
- `portal-wecom-sso`：企微 OAuth2 网页授权登录，userid 换取与既有白名单体系同源，会话签发与校验。
- `portal-permission-model`：三层权限判定（公开只读／域成员／域管理员）+ 手工部门映射表 + 敏感字段判据应用。
- `portal-access-log`：网关侧统一访问日志，承接队列 #112 使用率埋点。

### Modified Capabilities
（无——现有 `platform-service-auth-gate`（#160 共享口令门禁）不在本次修改：其 spec 已自述"是替代关系而非功能扩展"，本变更包新增独立能力，止血口令通道的下线时机在 design.md 的 Migration Plan 中说明，不在本次改动其既有 spec 行为。）

## Impact

- **新增代码**：网关模块（技术选型待 design 决策——是否延续 `serve.py` 的"零三方依赖"路线，或引入轻量反向代理/OAuth 库），预期落点 `5-平台底座/` 或 `1-转型规划/AI运营指挥中心/` 下新增子模块（具体路径由 design.md 定）。
- **不改动**：保供看板（8091）/命令中心（8092）/QD-B（8093）/FI2（8094）四个后端服务的业务代码；`simple_gate.py` 门禁逻辑本身（并存至废止条件满足）。
- **依赖新增**：企微 OAuth2 网页授权（外部依赖，服务不可用时无法登录，需应急本地口令通道兜底）。
- **关联既有资产**：`wecom-aibot-service/aibot_service/whitelist.py`（userid 同源）、队列 #112（访问日志与埋点合并落地）、队列 #10（原"加登录/Token 再开外网"任务，由本变更包承接正式方案）。
- **合规**：涉及员工身份与权限分层，属 CLAUDE.md §5「机制/工具类模块 openspec 触发门槛」第②类"涉鉴权与数据可见性"，故走完整 openspec propose+design（非快速通道）。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

1. **本流程哪些判断是人脑默会经验？**
   - 敏感字段判据（"泄露后会让外部第三方受损，或让内部产生不当信息优势"）已由决策件给出文字判据，但**具体某个新字段是否落在判据范围内**仍需人工逐字段过一遍再确认，属经验判断，目前只在 Shao Peishen（拍板人）与业务总线（起草判据、逐场景核对）脑子里。
   - **谁算某域"域管理员"**（决策件 §五决策3 示例了姚祖怡/唐燕萍/陈忱等，但新场景/新人员加入时如何认定）、**各域何时满足"业务数据对准"从而可进入存量线收编**（决策件 §六线③的触发条件），目前只有业务总线掌握判断尺度。
   - 网关应急直连通道**何时该启用**（网关本身故障 vs 后端服务本身故障的鉴别）、健康检查失败阈值，目前只在 CC 环境保障线的运维经验里，尚未显性化为具体数值/流程。
2. **由谁显性化？**
   - 权限判据与域成员/管理员认定：持有人 **Shao Peishen**（OPVP，决策拍板），backup **孙涛**（既有决策代理人，CLAUDE.md §5 已登记其可代理"日常审批"类判断，不可代"合规红线变更"）。
   - 网关运维判断（应急直连启用时机、健康检查阈值）：持有人 **CC 环境保障线**（本变更包实现与部署方），backup 待 design.md 落实具体数值后转为**可机械判定的规则**（不再需要人工经验），届时不再需要 backup 人选。
3. **用什么方法提取？**
   - 权限判据：**AI 起草·专家批改**——本变更包 design.md 起草具体的域成员映射表与敏感字段判据落地方式，交 Shao Peishen 批改确认（不做工作坊，判据已在决策件拍板，只需落地校验）。
   - 网关运维阈值：**AI 起草·专家批改 + 历史案例反推**——参考 SC8/QD-B/FI2 三服务既有的 `deploy-server.ps1` 健康检查判据反推合理阈值，写入 design.md 由 Shao Peishen 确认。

## 验收与晋档条件（强制，四档口径）

- **本变更包交付后场景所处档位**：**档 3 内部服务**——网关本身不是独立业务场景，而是承载已上线四个内部业务服务的基础设施层；交付后供内部员工经企微 SSO 登录访问，不涉及新增对客交付面，四个后端业务场景各自的档位不受本变更包影响。
- **晋下一档的条件**（从"止血口令与 SSO 并存"晋级到"SSO 为唯一入口、止血口令通道下线"）：
  1. 企微 OAuth 真实生产环境验证通过（真实员工登录 + userid 换取成功，非 mock）；
  2. 四服务程序化访问（每小时重算、`deploy-server.ps1` 健康检查、`/api/ping`、同步脚本、只读取证）逐项重新验证不中断；
  3. 网关进程守护 + 健康检查 + 应急直连通道均已部署验证；
  4. Shao Peishen 明确确认废止 `simple_gate.py` 止血口令通道（决策件 §八风险2 已定复审死线：最迟 **2026-10-31** 前须重新评估，若 SSO 未就绪则口令通道继续沿用并按期复审，不得无限期搁置）。
- **价值指标（风险型，基线由 Shao Peishen 已在决策件中确认）**：
  - **基线**：现状 4 个服务、0 个具备身份鉴权（止血口令不区分人员、不算身份鉴权）。
  - **目标**：SSO 上线后，经网关访问的服务 100% 落在"已登录 userid + 权限分层"之下，指标可用**"零身份鉴权可访问的服务数"从 4 降至 0** 衡量；同时消除决策件 §三点名的三类具体暴露（QD-B 立项书财务数据 / 保供看板客户与交期 / FI2 应付单与供应商单价）不再无凭据可见。
