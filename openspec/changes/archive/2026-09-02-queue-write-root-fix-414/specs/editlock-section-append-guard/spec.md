## ADDED Requirements

### Requirement: 单元格内容可经不途经 shell 的入口传入
`append-row` 子命令 SHALL 提供至少一条**单元格正文不进入命令行 argv** 的输入入口（JSON 文件与标准输入两种形态），使反引号、`$()`、引号、竖线等 shell 元字符在传输过程中不具备任何特殊性。该入口 SHALL 接受两种 JSON 顶层形态：数组（按目标分区列序的内容格）与对象（列名→值）。`--cell`／`--set`／JSON 文件／标准输入四类入口 MUST 四选一，同时提供多个时 MUST 拒绝执行而不得静默择一。

#### Scenario: 含反引号与命令替换语法的正文原样落地
- **WHEN** 调用方通过 JSON 文件提供的字段值中含反引号包裹的路径、`$(...)` 形式的文本
- **THEN** 该字段值逐字原样写入对应单元格，其中的反引号与 `$(...)` 未被求值、未被替换、未被清空

#### Scenario: 标准输入入口与文件入口行为等价
- **WHEN** 调用方以标准输入提供与文件入口相同的 JSON 载荷
- **THEN** 写入结果与文件入口完全一致

#### Scenario: 同时提供多个字段值入口时拒绝
- **WHEN** 调用方同时提供按列序入口与按列名入口
- **THEN** 工具拒绝执行、说明只能用其中一个，不写入任何内容

### Requirement: 按列名提供字段值
`append-row` 子命令 SHALL 支持调用方以**列名**（而非列下标或列序位置）提供字段值，工具按目标分区各自的列序映射落位。未知列名 MUST fail-loud 并列出该分区的合法列名；缺少任一列的值 MUST 拒绝执行，MUST NOT 以空串静默补齐；编号列 MUST 只经专用的编号参数提供，在按列名入口中重复提供编号列 MUST 拒绝。

#### Scenario: 乱序提供列名仍精确落位
- **WHEN** 调用方以任意顺序提供某分区全部内容列的"列名=值"
- **THEN** 各值落入其列名对应的列，行列数符合该分区标准列数

#### Scenario: 未知列名 fail-loud
- **WHEN** 调用方提供的列名不属于该分区且不是已登记的别名
- **THEN** 工具拒绝执行并列出该分区的合法列名，不写入任何内容

#### Scenario: 缺列不被静默补空
- **WHEN** 调用方按列名只提供了该分区部分列的值
- **THEN** 工具拒绝执行并列出缺少的列名，不写入任何内容

### Requirement: 按列名修改已存在的队列行
系统 SHALL 提供一条**走同一套单元格校验**的路径，用于按行编号定位并修改队列中已存在的行的指定列（整格替换与在格尾追加两种形态），使"改一行某一列"不必再经由手工编辑整行文本或直接改写队列文件。定位不到该编号、或同一编号命中多行时 MUST fail-loud，MUST NOT 静默选取其中一行。

#### Scenario: 在指定列尾追加内容而不动其它列
- **WHEN** 调用方对某已存在行的某一列执行追加
- **THEN** 该列内容在原值之后追加新内容，该行其余各列逐字不变，行列数不变

#### Scenario: 行编号不存在时 fail-loud
- **WHEN** 调用方指定的行编号在目标分区内不存在
- **THEN** 工具拒绝执行并说明未找到该编号，不修改目标文件

### Requirement: 关键格哨兵——校验内容与格位的对应关系
写盘前的单元格校验 SHALL 不止校验列数，还 MUST 校验**关键格的内容形态是否与其格位相符**，以捕获"列数正确但内容落进相邻格"这一类失效（该类失效不改变列数，是列位错置唯一会留下的痕迹）。至少 MUST 覆盖：编号格非纯数字（行头断裂）、§一 状态格未以机器可读字段前缀开头、完成标记落入期望产出格、任一单元格内含换行。

#### Scenario: 状态格缺少机器可读字段时拒绝写入
- **WHEN** 调用方提供的 §一 状态格内容未以机器可读状态字段前缀开头
- **THEN** 工具拒绝写入并指出该格是列位错置最常见的落点，不写入任何内容

#### Scenario: 完成标记落入期望产出格时拒绝写入
- **WHEN** §一 期望产出格以完成标记开头、而状态格仍为未完成态
- **THEN** 工具拒绝写入并说明这极可能是把收工叙述写进了产出格（机器读状态列，会一直认为该任务没做完）

#### Scenario: 编号格非纯数字时拒绝写入
- **WHEN** 调用方提供的行编号不是纯数字
- **THEN** 工具拒绝写入并指出该行将行头断裂、grep 与队列查询都将找不到它

#### Scenario: 单元格含换行时拒绝写入
- **WHEN** 任一单元格内容含换行符
- **THEN** 工具拒绝写入，不写入任何内容

### Requirement: 队列结构 lint 须能发现行头断裂的行
队列结构 lint SHALL 能报出**因行头损坏而无法被表格解析器识别为数据行**的行——包括首格为空但其余格有内容、以及行首竖线丢失两种形态。此类行 MUST NOT 因解析器将其跳过而被计为"通过"。判据 MUST 对分隔行与正文中偶然出现竖线的普通文本行不产生误报。

#### Scenario: 编号格被清空的行被报出
- **WHEN** 某数据行首格为空、其余格仍有内容
- **THEN** lint 报出该行行头断裂，指出它会被当成表头/分隔行静默跳过

#### Scenario: 行首竖线丢失的行被报出
- **WHEN** 某行不以竖线开头但以竖线结尾且含多个竖线
- **THEN** lint 报出该行行首竖线丢失

#### Scenario: 分隔行与含竖线的正文行不误报
- **WHEN** 扫描面内存在标准的表格分隔行，或正文中含被反引号包裹的竖线但不以竖线结尾的说明性文字
- **THEN** lint 不报出任何违规
