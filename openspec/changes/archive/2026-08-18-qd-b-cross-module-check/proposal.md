# 变更提案：QD-B C01–C10 跨模块校验（档一止损 ＋ 档二七条实现）

## Why

QD-B 报告第④段目前**恒定输出一句谎话**：

```
C01–C10 跨模块校验尚未实现（openspec 任务 4，扩容期补齐），本报告不含跨模块判定结果
```

而实测（队列 #340 评估件，2026-08-17）证明：**陈忱 2026-08-15 点名的那组「模块一人月数 ↔ 模块八至十」，
引擎今天已经在核**——对应 **规则 14「人月数与人员安排合计」＋ 规则 68「人月数与节点表一致性」**，
两条均已实现且已计入扣分，三份真实黄金样本（华丰／EQ17／邦奇）偏差均 **0.0%** 全部通过。
**缺陷不在判据、在呈现**：把已经核过的部分也说成了没核。陈忱正是看到这一句，才把它当作"待补的能力"点名。

**⇒ 第一优先是修掉这句假话，不是补功能。** 这与队列 #204／#221／#228 那一族同源——
「问题已解决但载体未更正」，只是这一次载体是给评审委员会看的报告正文。

同时，C01–C10 与既有 82 条规则的重叠盘点显示，**真新增只有 C02/C03/C05/C06/C07 五条**：

| 校验 | 既有规则对应 | 处置 |
|---|---|---|
| C01 人员一致性 | 规则 14 ＋ 68 传递等价 | 档二实现（按 §三 口径独立取数） |
| C08 预算工时与里程碑 | 规则 68 近等价 | 档二实现 |
| C09 收益计算自洽 | **规则 59 公式逐字相同** | **不重复实现**，复用规则 59 判定结果 |
| C10 全生命周期毛利率 | **规则 60 公式逐字相同** | **不重复实现**，复用规则 60 判定结果 |
| C04 时间一致性 | 规则 66 覆盖"止"半边且更严（阻断级） | 档二实现（"起"半边为真新增） |
| C02 / C03 | 无 | 档二实现 |
| C05 / C06 / C07 | 无 | **档三挂起**，等陈忱口径（见下） |

## What Changes

**档一 · 止损（本变更包）**
- `report.py` ④段由"恒定说未实现"改为**如实呈现**：逐条列出 C01–C10 的实现状态、比对值与判定；
  未实现的三条明确写出**未实现的原因**（不是笼统"扩容期"）。
- `webapp.py` / `xlsx_report.py` ④段同步呈现（网页新增跨模块校验表，Excel 新增"跨模块校验"sheet）。

**档二 · 七条数值/日期校验（本变更包）**
- 新建 `qd_b_gate/rules/cross_module.py`，实现 C01/C02/C03/C04/C08 五条 ＋ C09/C10 两条复用视图。
- **零新增解析**：七条两侧取数 100% 就位（`预算表` 每行已抽 人月／小计⑩／收入⑪／开始／结束；
  `人员安排合计`、`成本效益` 合计行、`收入依据合计` 均在册；`_cb_income_scale()` 已解决元 vs 万元量纲）。
- **零分数漂移（可证）**：`scoring.py::score()` 只遍历 `registry.rules`（82 条），C01–C10 不在注册表内；
  跨模块结果走独立的 `cross_module_items` 列表、**不并进 `results`**，总分与档位不可能变。

**档三 · C05/C06/C07（本变更包不做，明确挂起）**
- **C05**：按 §三 字面实现会把**评审报告判合格的 EQ17 判成阻断错误**——风险表「所属里程碑」填的是
  `需求确认与资料交付`／`软硬件开发设计` 类自定义描述，与模块九 `立项评审`／`G1–G4质量阀`／`结项评审`
  **严格相等与包含匹配均 0 命中**（华丰 `项目立项`、邦奇 `立项` 亦仅前缀沾边）。
- **C06**：需 ASIL「不适用」同义词表（三份样本出现 `/`、`无`、`A` 三种写法；若把 `无` 当作 ≠NA，
  EQ17 模块四功能安全目标填 `不涉及` 将判错误、**从合格翻成不合格**）。
- **C06/C07**：需新增模块四（`四、项目目标`）三列表解析，当前**完全未解析**。
- ⇒ **不先写代码等口径**——C05 的匹配语义直接决定实现形态，猜错即返工。

**一处刻意不消解的冲突（Q1，须陈忱裁定，本包如实并列呈现、不替他选）**
同一组比对，「立项门禁」82 条表判 **精确相等 ＋ 重要级扣分**（规则 14/68 容差 0.05 人月；规则 66 更是阻断级），
而「规则说明（开发）」§三 判 **10% 容差 ＋ 警告**。一个 6% 的人月偏差，按规则 68 是"不合格·扣分"、按 C08 是"通过"。
**本包按 §三 口径实现跨模块段（这是 C01–C10 的定义出处），但对与既有规则等价的条目同时标注该规则的判定结果**，
使冲突在报告上**可见**而不是被静默压掉一边；扣分仍只由 82 条规则决定，不受本段影响。

## Impact

- **受影响能力**：`qd-b-rule-engine`（C01–C10 校验的分档实现口径）、`qd-b-review-gate`（报告 ④ 段契约）
- **受影响代码**：`qd_b_gate/rules/cross_module.py`（新建）、`qd_b_gate/report.py`、`qd_b_gate/webapp.py`、
  `qd_b_gate/xlsx_report.py`、`qd_b_gate/evaluate.py`（贯通 `cross_module_items`）
- **不受影响**：`scoring.py`、`data/rules/registry.json`、82 条规则判定逻辑、三份黄金样本的档位与驱动规则
- **伴生文件的 .gitignore 覆盖**：本变更**不新增任何自动生成的文件名形态**——不产生锁文件/快照/暂存/
  状态文件/日志/重命名退路产物/备份副本；Excel 报告沿用既有 `xlsx_report.py` 的下载流（内存 BytesIO，
  不落盘），网页报告不落盘。故本项不适用。
- **守卫退休（one-in-one-out）**：本包属**部门业务场景**变更包（`4-数字员工/质量部/QD-B-*`），
  不属机制/环境类，按 `openspec/config.yaml` 该条规则的适用范围不受其约束。
  即便如此，本包实际上**退休了一处**：`report.py::CROSS_MODULE_NOTE` 这条恒定文案连同它所代表的
  "整段留白"分支被删除，改为按实际实现状态生成——**一条恒真的假话被移除，而不是新增一条守卫**。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

**本流程哪些判断是人脑默会经验？**
1. **跨模块比对的"允许偏差"尺度**——评审人心里对"人月数对不上多少算问题"有尺度，而两份权威件给出
   两个不同答案（精确相等 vs 10%），说明该尺度此前从未被显性化过（＝Q1）。
2. **风险"所属里程碑"与模块九阶段名的对应关系**——填报人写"需求确认与资料交付"、模块九写"G1–G4 质量阀"，
   评审人一眼知道说的是同一段，机器不知道（＝Q2/C05）。
3. **ASIL 字段填 `/`、`无`、`不涉及` 是否等同 NA**——同一含义三种写法，人默认懂（＝Q3/C06）。
4. **C09/C10 与规则 59/60 是同一件事**——公式逐字相同却分列两处，此前无人显式记录过它们是一回事。

**由谁显性化？** 陈忱（质量部 AI 专员，口径持有人，实名）；backup：朱映桦（质量部，灰度试用人）。

**用什么方法提取？** **AI 起草·专家批改**——本包已把 1/2/3 三项转成 Q1/Q2/Q3 三道具体选择题
（各附真实样本上的实测后果，如"EQ17 会从合格翻成不合格"），随质量部#7 一次问齐，由陈忱裁定；
第 4 项无需问他，属实现侧盘点结论，已在本包内直接落为"不重复实现、复用规则 59/60"。

## 验收与晋档条件（强制，四档口径）

**本变更包交付后场景所处档位**：**档 3 · 内部服务**（QD-B 自 2026-07-23 起已部署 `.51:8093`，
陈忱＋朱映桦灰度试用中；本包为其增量功能，随包重部署，档位不变）。

**晋下一档（档 4 · 对客交付）的条件**（逐条）：
1. 档三 C05/C06/C07 的三个口径（Q1/Q2/Q3）经陈忱书面裁定并实现，C01–C10 十条全部落地；
2. B 类 10 条语义判定由占位转真实（当前统一转人工）；
3. 评审委员会/PMO 书面确认 AI 预审报告可作为评审输入件（当前定位仍是"预审建议非终局"）；
4. 统一门户 SSO 落地，替换当前的共享口令临时门禁（队列 #160）。
   —— QD-B 是**内部立项评审**场景，"对客"在本场景语境下指对 PMO/评审委员会正式交付，不涉 OEM 外发。

**价值指标**（业务 Champion＝陈忱确认基线）：
- **质量型**：报告④段的**事实正确率**——基线＝当前 0%（恒定输出"未实现"，而实际 4 条在核，属错误陈述）；
  目标＝100%（每条的实现状态与实际一致）。**这是本包最主要的价值，且可当场证伪。**
- **风险型**：跨模块不一致的**独立检出路径数**——基线＝1（仅 82 条规则内的 14/68/59/60/66），
  目标＝2（新增 C02/C03/C04 起半边三条独立路径）。实测已兑现两条真实命中：邦奇 C02 成本差 46.662 万
  （与已知 rule 74/69 缺口同源的第二条检出路径）、EQ17 C04 起始日期差 3 天（v5.0 评审报告未提，人工漏检）。
- **⚠️ 如实登记一条减分项**：C01/C08（即陈忱点名的那一组）在三份样本上偏差**全为 0.0%**，
  实现后**不会改变任何已知样本的判定**。其价值在"拦未来的错填"与"修掉④段的谎话"，
  **不是"立竿见影揪出新问题"**——这一点须原样告诉陈忱，不得包装。
