## Goals / Non-Goals

**Goals**
- 已完成的 opener 不再被派出；每次跳过都留下**可读的判定依据**（行号／命中载体／理由）。
- 判据只有**一份实现**，v1 与 v2 共用；两个 runner 的行为差异只体现在"跳过之后怎么走"，不体现在"怎么判"。
- 无法判定时**一律照常派出**（fail-open），并计数告警。
- 不改变现有 `OK`/`PARTIAL`/`NO-SENTINEL`/`FAIL` 四态的任何既有语义。

**Non-Goals**
- **不改计划文件格式**——不要求写计划的人新增任何字段（决策点 2 论证为何沿用标题）。
- **不做「这行到底该不该做」的语义判断**——只做"载体在哪"的机械判定，不引入 LLM、不读 opener 正文推断意图。
- **不修归档件既有数据**（取证二的状态列矛盾）——判据设计成不依赖它。
- **不在本包内实现 `#396` 的治标**（9 份派单件逐份核实）——那是 #396 自己的活，本包只定义此后的**义务归属**（决策点 6）。
- **不动 `queue-row-status-field` spec 本身**——本包不改状态字段规范，只是**不把它当归档侧判据**。

### 决策点 1 · 「这个 opener 对应的队列行已完成」用什么判据判？（A27 指定项①）🔴 本项无默认

- **(a) 四态判定、归档命中即完成、模糊地带一律 fail-open〔推荐〕**
  判定表与行定位三条件如下（原文不动）：

  | 态 | 条件 | 动作 |
  |---|------|------|
  | **A** | 在 live 两份任一命中 §一 行，且状态字段**非** `done` | **派出**（正常路径） |
  | **B** | 在 live 两份任一命中 §一 行，且 `cells[5]` 以 `[S:done]` 开头 | **跳过 ＋ 告警**（理由：live-done） |
  | **C** | live 未命中，在任一归档件命中 §一 行 | **跳过 ＋ 告警**（理由：archived@`<文件名>`） |
  | **D** | live 与 archive 均未命中 | 🔴 **照常派出 ＋ 告警**（理由：unresolved） |

  行定位三条件全部满足才算命中：① 行位于一个 §一 章节内（章节匹配 `^#{2,3}\s*§?\s*一[、\s·]`，兼容 live／archive 三种写法、H2/H3、单文件多表）；② 用 `queue_table.split_row_cells()` 切分（**必须复用**——反引号游程屏蔽，`#314` 教训）；③ `cells[0]` 去空白后与目标行号**数值相等**（`int` 比较）。多载体**逐份解析后合并，绝不拼接文本再解析**（`#312` 教训）。
  **选它会发生什么**：`#368` 这类「已归档但状态列仍写 `[S:open]`」的行会被正确跳过（取证二）；`#395` 这类「live 且 `[S:done]` 未清扫」的行也会被跳过（B 态补上最长 7 天的清扫窗口）；一切查不到的行照常派出、只多一条告警。
  **代价**：① 归档侧完全不读状态列 ⇒ 若将来值周清扫误迁了一条未完成的行，本判据会跟着把它跳掉——代价由「迁移动作本身是人工复核过的完成判定」兜底，不由本包兜；② D 态 fail-open 意味着「写了行号但查不到」的 opener 会带着告警照跑，告警若无人看即等于没拦（次风险＝告警疲劳，决策点 2 给出区分文案）。
- **(b) 只读机器状态字段 `[S:done]`，live 与归档同一套判据**
  **选它会发生什么**：实现最简单、与 `queue-row-status-field` spec 的规范位置一致。
  **代价**：🔴 **在真实数据上会原样重演白跑**——归档 `#368` 的 `cells[5]` 实测为 `[S:open][D:业] 🆕 2026-08-21 立行，未开工`（取证二），按 (b) 判为 open ⇒ A4 照常派出。一个"正确实现了规范"的校验器在真实数据上完全失效。
- **(c) 只查归档、不查 live**
  **选它会发生什么**：少一半查询、不碰 live 状态字段。
  **代价**：漏掉整个「已完成但尚未清扫」窗口——值周清扫每周一次，窗口最长 7 天；`#395` 在 2026-08-25 出件时恰在此窗口内（live 且 `[S:done]`，从未进归档），按 (c) 会被派出。

**推荐 (a)。🔴 本项无默认**——它定义「什么算已完成」，属口径判据类；且出件 session 收工即结束，第一问「他不答谁去执行」答不出执行者（根 `CLAUDE.md` §5 默认项两个前提）。**须 Shao Peishen 明确答复后方可 apply。**
**推荐理由的手段**：① 取证二＝读 `跨桌任务队列-归档-202608.md` L583 `#368` 行 `cells[5]` 原文（2026-08-25 出件时取；2026-09-12 复核用 `工具-队列查询.py --row 368 --section 一` 确认 live 仍未找到、exit=1）；② 取证一＝按「§一 表格内首列纯数字」全量扫描 live 2 份＋归档件，live ∩ archive 冲突 0、archive 内重复 0（2026-08-25 实测 392 行）；③ 2026-09-12 `ls 1-转型规划/0-全景路线图/跨桌任务队列-归档-*.md` 现取 3 份、`grep -n "^##.*一"` 现取三种 §一 标题写法；④ `#314`／`#312` 教训出处＝`queue_table.py::split_row_cells` docstring 与 `工具-队列查询.py` L20／L90 注释（2026-09-12 读）。

### 决策点 2 · 行号从哪里取（锚点）？新增字段还是沿用 opener 标题？🔴 本项无默认

- **(a) 沿用 opener 标题，不新增字段；抽取正则 `(?:队列|§一)\s*#(\d+)`，先剥 `§四 #N(x)` 与 `§二 …`；多行号取合取〔推荐〕**
  现行两版计划文件的标题**已稳定携带行号**，且两 runner 的解析正则 `^###\s+(A\d+)\s*·?\s*(.*)$` 早已把它捕进 `$title`——不改任何解析代码就拿到锚点：
  ```
  ### A4  ·【Cowork·业务新 session（质量域）】质量域场景清单重审——队列 #368
  ### A27 ·【CC】#397 批处理派出前查归档（#396 治本）——…——队列 #397／#396
  ### A22 ·【CC】#353 apply：…——队列 #353／§四 #108(a)
  ### A2  ·【Cowork】队列每周清扫迁归档（本轮巡检移交件）——协议〇.8／§四 #44
  ```
  🔴 **必须显式排除 `§四 #N` 与 `§二 <批次>`**——§一 与 §四 是两套独立编号（archive 中 `§四 #88` 与 `§一 #368` 并存且无关）；A22 同时含 `#353`（§一）与 `§四 #108`，只有前者是输入。实现上先剥 `§四\s*#\d+(?:\([a-z]\))?` 与 `§二[^／/]*`，再在剩余串上取 `#(\d+)`。
  **多行号（`#397／#396`）合取语义**：🔴 全部引用行都已完成才跳过；任一行仍在办即派出（A27 自身即反例——若 #396 先完成而 #397 未完，析取会把 #397 的活跳掉）。
