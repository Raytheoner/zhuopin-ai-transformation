# portal-qd-b-ui Proposal

## Why

QD-B 的现有审核页已具备正式报告数据，但桌面布局密集，窄屏下浏览 13 个模块、逐项依据和转人工待办不够清楚。按已批准的门户实施顺序补齐只读展示层，让质量人员更容易查看预审结果，同时保持判定和审核责任不变。

## What Changes

- 为 QD-B 的报告页整理桌面与移动展示契约，覆盖 P13 上传入口、P14 预审报告和 P15 规则与证据。
- 只消费 `EvaluationResult` 与现有报告数据；保留六段报告、13 模块、82 条明细、C01–C10、转人工待办、下载入口及审计元数据。
- 明确区分评估时间与原始资料时间。可用时显示审计事件时间；当前结果不含原始资料更新时间时明确写“未提供”，不将评估时间冒充资料新鲜度。
- 使用合成或脱敏展示对象验证排版、状态和长文本转义；不上传文件、不调用 `evaluate()`，不改评分、规则、审计写入或服务接口。
- 本变更只准备仓内子计划与后续展示实施，不包含实现、合入、部署、启用或外发授权。

## Capabilities

### New Capabilities

- `qd-b-portal-display`: QD-B 预审报告只读展示契约，规定响应式布局、现有结果字段和状态的如实呈现，以及来源时间缺失时的表达。

### Modified Capabilities

无。既有审核、判定、评分、解析和审计要求不变。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

1. **本流程哪些判断是人脑默会经验？** 质量人员如何区分预审建议与正式结论、如何理解转人工与未实现状态，以及哪些依据足以支持后续复核；此包只呈现已有结果，不重新定义这些判断。
2. **由谁显性化？** 质量域 AI 专员陈忱持有业务口径；朱映桦作为一线标注层备份整理案例与展示疑问，不代替陈忱作专业签认。Shao Peishen 审核本 UI 子计划与设计边界。
3. **用什么方法提取？** 以历史案例反推页面信息结构，并由 AI 起草展示映射、质量专家批改；本轮不累积或改写规则判据。

## 验收与晋档条件（强制，四档口径）

- **本变更包交付后场景所处档位**：档1 mock 验证。即使展示代码完成，也不代表真实资料评估、业务验收或生产发布完成。
- **晋下一档的条件**：① 本设计获 Shao Peishen 审核后才扩大代码触碰范围；② 展示契约定向检查通过，所有旧结果字段与状态保持一致；③ 另行取得真实样本验证授权并由质量人员复核；④ 生产合入、部署与灰度按独立授权执行。
- **价值指标**：质量型——预审状态、依据、缺失资料和人工责任能否在页面中定位；风险型——不得把未实现/转人工呈现成通过、不得把评估时间呈现为资料时间。基线由业务 Champion 后续确认，本计划不虚构改善比例。
- **LLM 判据黄金集**：本变更不新增 LLM 运行时判断，不建立新的黄金判据集。

## Impact

- **Specs**：新增 `qd-b-portal-display`；不修改既有 `qd-b-review-gate`、`qd-b-rule-engine` 或 `qd-b-intake-parser` 的业务要求。
- **后续代码候选**：`4-数字员工/质量部/QD-B-立项审核门禁/qd_b_gate/webapp.py` 的展示模板及 `tests/test_webapp_ui_contract.py`。`evaluate.py`、评分/规则/解析、报告数据结构、审计、上传限制、认证门禁、下载 API 和部署脚本不在本设计改动范围。
- **系统与数据边界**：复用现有 Flask 服务和身份门禁；不新增依赖、接口、服务端口、数据源或自动生成文件形态。只用合成/脱敏对象，不触碰 OEM 技术资料；不改变 L2 人工复核责任，ASIL C/D 仍不参与 AI 自动判定。
