## Context

见 `proposal.md` 的 Why；行为边界见 `specs/qd-b-portal-display/spec.md`。

当前 `qd_b_gate.webapp` 通过 Flask 返回一份完整 HTML 报告，并使用 `EvaluationResult`、`GateReport`、`ScoredItem` 与 `ModuleRateRow` 渲染结果。评估结果已经包含模板/规则版本和审计事件；审计事件时间代表评估时间，结果对象没有原始立项资料的来源更新时间。上传、认证、下载、评分、审计和规则判定都已存在，均不需要为页面重排而变更。

门户审核把 QD-B 页面映射为 P13 上传、P14 预审报告、P15 规则与证据。QD-B 是独立 Flask 服务；公共门户壳层和后端不能合并。本次把 P14/P15 作为现有报告页面中的信息分组，不增加独立服务端路由。

## Goals / Non-Goals

**Goals:**

- 用与已批准门户 UI 变量一致的轻量 CSS 整理现有 QD-B 上传页与结果页层级，并保留其 Flask 单页和现有路由。
- 对照现有返回字段形成可追溯的展示映射：数据字段、页面位置、状态文字、缺失时显示、依据与版本来源。
- 在桌面 1440×1024、移动 390×844 及全局窄屏 320px 下检查层级、长中文、表格、键盘和状态标识。
- 以人工构造的 `EvaluationResult` 展示对象编写新的窄范围展示契约测试，不调用上传/评估入口。

**Non-Goals:**

- 不更改 `evaluate()`、parser、规则/评分、报告数据结构、C05/C06/C07 业务口径、黄金基准或审计事件。
- 不复制原型的模拟上传/模拟提交行为到真实 Flask 服务；P13 保持当前 `.xlsx` 上传、20 MB 上限和既有处理路径。
- 不新增结果 API、P15 独立路由、持久化字段、统一待办、认证/角色、身份头、复核提交、签发、服务端口或生产部署动作。
- 不用真实立项书、OEM 技术方案或客户资料做视觉/契约验证；不运行历史矩阵、业务 fixture 或真实 `evaluate()`。

## Decisions

### 1. 保持服务端单页与现有数据对象

在 `webapp.py` 现有 HTML 渲染路径内重排上传页和结果页；P14/P15 是同页区块或定位锚点，不增 Flask route。结果继续从 `EvaluationResult` 与现有报告呈现 helper 取得，不从 mock JSON 或 DOM 重新计算。

**理由：** QD-B 独立服务现有页面、下载与认证边界已运行；重用现有数据对象能使八个可见结果区与报告源保持一致，并避免模拟原型的提交控件暗示系统新增能力。

**备选方案：** 将 QD-B 报告迁入公共门户或新增 JSON API。两者都会扩大服务边界并牵涉鉴权、部署及数据所有权，超出已批准的展示层范围。

### 2. 仅调整 `webapp.py` 的展示，不改报告计算模块

后续代码候选仅含 `qd_b_gate/webapp.py` 的 HTML/CSS 展示 helper，以及新增 `tests/test_webapp_ui_contract.py`。沿用现有 `build_scored_items()`、`build_module_rates()`、`deduction_items()`、`build_basic_info()`、`build_financial_summary()` 输出；不改 `report_items.py` 或 `report.py`。所有现有可见栏位继续显示，不能为视觉简化删除 13 模块、全量明细、建议、跨模块结果、转人工待办或审计元数据。

**理由：** 逐项分数和状态的唯一展示换算已集中在 `report_items.py`；再造一套会增加数字漂移风险。纯呈现需求可限定在 Flask HTML/CSS。

**备选方案：** 在前端重算分数或建立第二份模板数据模型。拒绝，因会分叉既有规则语义并改变后续维护面。

### 3. 明示时间含义与缺失值

展示字段包括样本标识、项目基本信息、`template_version`、`rule_version`、评估审计事件时间、哈希摘要，以及现有判定/证据/建议。时间标签写明“本次评估时间”；原始资料时间固定显示“未提供”或等效缺失状态，直至业务数据模型未来另行获批添加来源字段。

**理由：** `AuditEvent.timestamp` 是评估事件时间，不证明立项书何时从来源系统导出或更新。

**备选方案：** 用上传文件名、文件修改时间或页面访问时间替代来源时间。拒绝，因为这些值不能证明业务数据新鲜度。

### 4. 复用批准变量，保持轻量并安全输出

内联 CSS 使用审核通过的颜色、字阶、间距和卡片层级；CSS 只负责布局，不改变服务端返回内容。结果文本继续经现有 `html.escape` 路径；长内容自然换行，表格在窄屏切换为可读的堆叠布局或局部横向滚动，不隐藏必读状态。操作仍用现有链接与过滤器。

**理由：** QD-B 独立运行，不宜依赖门户静态文件或引入构建工具；局部内联样式保持独立部署与现有依赖闭包。

**备选方案：** 新增 React/Vite bundle 或共享门户 CSS 运行时。拒绝，因为会增加依赖、部署文件与服务耦合。

### 5. 只验证展示合同，不执行业务评估

新增测试通过手工构造现有 dataclass 结构，覆盖各 Verdict、缺失原始资料时间、长中文/HTML 字符、13 模块及跨模块/人工待办。测试调用渲染 helper，不调用 `/evaluate`、`evaluate()`、上传解析器、平台 audit writer 或历史 fixture。实施后只运行本测试和目标子项目原定的窄范围静态检查；不重跑全量矩阵/fixture。

**理由：** 本阶段要证实呈现完整、安全和不失真，而非重复证明已运行的规则引擎。

## Risks / Trade-offs

- [长证据导致移动表格难读] → 保留状态、规则编号和证据；小屏采用逐行堆叠/局部滚动，并在 320/390px 检查，不截断必需文本。
- [视觉重排误改状态含义] → 契约测试逐态核文字与状态；不从颜色推断，也不改既有转换 helper。
- [评估时间被误认为资料新鲜度] → 固定标签“本次评估时间”；原始资料时间缺失明确显示“未提供”。
- [门户主题与独立服务样式漂移] → 将使用的批准变量值在 `webapp.py` 集中声明并注明来源文件，后续由独立场景计划维护，不引入跨服务动态依赖。
- [原型包含未接入提交动作] → 仅复用视觉层级；不复制复核提交、签发、统一待办或模拟写回控件。
