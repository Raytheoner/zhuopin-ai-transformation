## Context

QD-B 立项审核门禁是质量旗舰（全景 Q6），Paul 第二管辖域（质量）首批落地场景之一。陈忱团队已交付强 design 输入：**82 条机器可核规则（工作汇总.xlsx「立项门禁」页 A1:K83）+ 字段级规则说明（「规则说明（开发）」231 行）+ 合格分级/严重度（「封面」）+ 真实立项书逐条试评（华丰 EPA 技术服务类）**。本设计据此把人工评审转译为数字人预审，L2 决策权保留在评审委员会/PMO。

**当前状态/约束**：
- 落位 `4-数字员工/质量部/QD-B-立项审核门禁/`，`pip install -e` 平台底座（CLAUDE.md §4/§6）。
- **MVP 仅开发类 `EQQR8082` A2.1**；研发类 `EQQR8106` A3 二期。
- 唯一真实试评样本是技术服务类（华丰）；产品类规则写了未跑真实数据。
- 立项书是合并单元格 Excel 表单（A1:Z145、大量 merge），模板一月内改了 A0→A1→A2→A2.1 四版。
- **QD-A（8D）尚未建**——`doc_parser` 当前**只有 QD-B 一个真实消费方**（交接包 §7 假设 QD-A 先建、QD-B 第 2，与现状不符）。
- 红线（CLAUDE.md §7）：先 mock/脱敏再切真实；所有判定写 audit；L2 决策在委员会；含 OEM 技术方案附件走隔离层；AI 结论永远是"预审建议"非终局。

**stakeholders**：Paul（VP，拍板）、陈忱（质量业务判据/补样本）、PMO/评审委员会（L2 复核）、AIOps 第 2 人（建造）。

## Goals / Non-Goals

**Goals:**
- 把 68 条 A 类确定性规则 + C01–C10 跨模块校验转译为纯函数 + 夹具单测，零语义歧义、可解释、可回归。
- 用解析探针先验合并单元格表单的字段抽取准确率，把"解析可靠性"这个最大工程未知数前置暴露。
- 10 条 B 类语义规则走 LLM，二级置信度、低置信转人工，判定准则业务确认后接入。
- 出三档立项审核报告（MVP 两档起步）+ L2 门禁 + 全链审计，对齐 IATF 8.3 可追溯。
- 黄金基准回归（仿 SC8）：确定性部分零偏差、半自动部分人工一致率达阈值。

**Non-Goals:**
- 研发类 `EQQR8106` A3 规则（二期）。
- 评分制权重表的具体分值（业务方定，本期只留可插拔接口）。
- 签字真伪鉴定、立项决议判定（转人工）。
- doc_parser 提升进 `shared_tools`（无第 2 真实消费方，暂留场景本地）。
- 对客/对外自动放行——AI 不做终局决策。

## Decisions

### D1：四能力分层（解析 / 确定性规则 / 语义判定 / 聚合门禁）
- 选 `qd-b-intake-parser` + `qd-b-rule-engine` + `qd-b-semantic-judge` + `qd-b-review-gate` 四层，沿用 SC5 的"解析/纯算法引擎/agent 聚合"分层纪律。
- 理由：确定性规则（68 条）与 LLM 语义（10 条）失败模式、可测性、置信度模型完全不同，分层使确定性部分可纯单测、语义部分可独立换提示词，互不污染。聚合层统一严重度映射/三档判定/报告/audit/L2。
- 备选：单体 agent 直接吃 82 条——否决，语义与确定性混在一起无法单测、无法回归。

### D2：规则单一可信源 = 工作汇总.xlsx，规则即数据
- 68 条 A 类每条一个纯函数，但规则元数据（规则ID/章节/检查项/适用类型/严重度/阈值/取数锚点）以表格为单一可信源，代码侧维护规则注册表（rule registry），函数实现判定逻辑、注册表挂元数据。规则版本号随表更新登记。
- 理由：IATF 单一可信源；82 条会随业务演进，数据驱动比硬编码易审计、易回归。
- 备选：把判定标准写死代码注释——否决，表一改代码即漂移。

### D3：取数锚"章节标题文本"而非绝对单元格坐标
- 解析器按章节标题/字段标题文本定位，合并单元格按左上锚点展开。记录适配模板版本号；非 A2.1 版本告警不静默。
- 理由：模板一月四版，坐标锚必然脆裂；标题文本相对稳定。交接包 §7 明确要求。

### D4：解析探针先行（第一刀），抽取准确率作规则判定前置门槛
- 实现顺序：先做解析器 + 对 A2.1 模板 + ≥几份真实填写件验证字段抽取准确率，达阈值再写 82 条规则判定。字段标"已抽取/缺失/低置信"，规则判定区分"字段真为空（不合格）"与"解析未抽到（待人工核）"。
- 理由：交接包 §7 点名"doc_parser 解析可靠性 = 最大工程未知数"。若解析不稳，82 条规则全是空中楼阁。先证伪再建造。

### D5：doc_parser 暂留场景本地（rule-of-three 未触发）
- QD-A/8D 尚未建，doc_parser 只有 QD-B 一个真实消费方。按 supplychain 纪律（第 2 真实消费方出现才提升），doc_parser 留 `QD-B-立项审核门禁/` 场景本地，预留干净接口，待 QD-A 落地且真复用时再提升进 `shared_tools`（提升前查实际代码确认真复用，非臆测）。
- 理由：rule-of-three，避免过早抽象；与交接包 §7 的"真复用才提升"一致（仅纠正其"QD-A 第 1 消费方"的现状假设）。

### D6：二级置信度对齐 SC8，低置信默认转人工
- B 类语义判定用高/低二级置信度（不引中间档），低置信一律走人工复核路径，不擅断。判定准则（提示词 + 业务判据）业务确认前，semantic-judge 默认全部转人工。
- 理由：与 SC8 口径统一、可审计；避免 LLM 在业务判据未定时产出不可信终局。

### D7：MVP 两档起步，评分制可插拔
- 总判定先用"错误项一票否决"（有错误→不合格 / 无错误→合格）。评分制（82 条各占几分）作可插拔模块，业务方给权重表后接入，启用后"有条件合格"档（60≤分<80）才生效。
- 理由：评分细则未定（收口-1），但无分值无法算"得分"维度，三档会塌成两档。两档先跑通、不阻塞首版，是诚实且可上线的退路。

### D8：严重度双表映射显式化
- 「立项门禁」J 列（阻断/重要/一般/提示）→「封面」三级（错误/警告/提示）的映射作为规则元数据显式定义、可审计。阻断→错误（一票否决）；提示→提示；重要/一般按规则配置（默认重要→错误候选、一般→警告，最终随收口-1 业务确认）。
- 理由：两套严重度词表必须有确定映射，否则"错误项一票否决"无法落地。

### D9：审计与隔离复用底座，不重建
- 审核结论写 `zhuopin_platform.audit`（scenario=QD-B，关联立项文档版本ID）。立项文档默认内部库；附件含特定 OEM 技术方案/报价时标记走 `data_isolation_layer`。
- 理由：CLAUDE.md §4，单一可信源审计载体，勿重建。

### D10：黄金基准仿 SC8，存 data/golden/，脱敏自包含
- 取历史已结案立项书，AI 重跑 vs 当年评审结论逐项对比。覆盖技术服务类（华丰 1 份）+ 产品类 ≥1 份（待补，收口-3），含"有条件合格""不合格"各 ≥1。通过标准：A 类 68 条零偏差；B 类命中与人工一致率 ≥80%（MVP）。样本脱敏后入 `data/golden/`，含 OEM 报价附件需脱敏。

## Risks / Trade-offs

- **[解析不稳，82 条规则失效]** → D4 解析探针先行，抽取准确率不达阈值不进规则全量判定；字段缺失与"真为空"区分，避免误判阻断。
- **[模板继续改版]** → D3 标题文本锚 + 版本识别告警；非适配版本不静默处理。
- **[产品类规则未经真实验证]** → 收口-3 补产品类样本；MVP 报告对产品类专属规则（量产数据/全生命周期毛利率/收益指标≥5/部分 C01–C03）标"未经真实样本验证"，不给高置信终局。
- **[评分细则缺失 → "有条件合格"档产不出]** → D7 两档起步 + 可插拔评分；交接包 §6-1 已明示。
- **[LLM 语义判定不一致/幻觉]** → D6 低置信转人工 + 证据片段引用原文 + 黄金基准人工一致率门槛；判据未定前全部转人工。
- **[AI 越权下终局结论]** → L2 门禁（review-gate spec），AI 永远"预审建议"，委员会确认才生效；规则调整走回归。
- **[OEM 数据交叉]** → 附件隔离例外走 data_isolation_layer，跨库抛 CrossOEMAccessError。

## Migration Plan

1. 解析探针：解析器 + 字段抽取准确率报告（A2.1 模板 + 真实件），达阈值放行。
2. 确定性规则引擎：68 条 A 类先测后实现（SuperPowers 纪律），mock 夹具单测，华丰样本逐条比对试评结果。
3. C01–C10 跨模块校验。
4. 语义判定（收口-2 判据接入后）：10 条 B 类，二级置信度，低置信转人工。
5. 聚合门禁：严重度映射 + 两档判定 + 报告契约 + L2 + audit。
6. 黄金基准回归：技术服务类（华丰）+ 产品类（收口-3 补样本）。
7. `/opsx:archive` → git push。
- **回滚**：场景独立工程，不动底座 spec、不动其他场景；mock 阶段无真实库副作用；上线前 CUSTOMER/对外无外发面，回滚=停用场景入口。
