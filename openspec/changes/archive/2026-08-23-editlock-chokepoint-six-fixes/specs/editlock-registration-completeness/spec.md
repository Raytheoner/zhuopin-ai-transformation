## Purpose

把「你改完东西有没有登记，好让落库机制来提交」这件事，从人守变成机器守——在 `release` 这个「session 还活着、且必然会被调用」的时点，拦住工作区里不属于任何待处理提交批次的脏文件，使它们不会静默掉在地上。

**为什么挂在 release 而不是别处**：本项目已认定两道咽喉——「队列写入＝编辑锁」与「提交＝落库 sweep」。sweep 的孤儿告警只进日志与运维群、**没有阻断力**（2026-08-22 那六个孤儿从 12:20 UTC 一直报到当日 22:22 落库，约 10 小时，没有任何东西拦住）；而 `release` 是唯一一个 session 尚未结束、且必然会被调用的时点。

**立项实证**：`OP-0822-E` 于 2026-08-22 12:26:16 UTC 占锁，备注原文写着「三份接力件定长化 分三批登记」，随后正常释放——**而那三条批次行从未出现在任何一个提交里**。⇒ **它不是「忘了登记」，是「以为自己登记了」；`acquire` 的备注是意图、不是事实，而 `release` 此前把意图当成了事实。**

### 关于被本能力退休的旧校验（不写成 REMOVED delta，理由见下）

本变更同批退休 `_validate_release_structure` 校验 ②「§二 新增批次行的文件清单列须含队列文件自身路径」。

🔴 **它不以 `## REMOVED Requirements` 形式出现在本变更包里，因为它从来没有被写进任何 spec** —— 全库 `openspec/specs/*/spec.md` 实测零命中（判据：`grep -rn "自身\|declares_self\|批次清单"`，命中的全是无关语句）。**它是一道只活在代码里、从未进过 spec 的守卫**，退休它无 delta 可写。

**这件事本身值得记一笔**：协议〇.9 措施 B 问「本次退休哪一个既有守卫」，默认前提是守卫都在 spec 里可数；实测并非如此。**下一次做机制类变更包时，别只翻 spec 找退休候选，代码里还有一批没上过户的。**

退休理由、代价与被否掉的另一个候选，见 `proposal.md`「本次退休哪一个既有守卫」节与 `design.md` §5。


## ADDED Requirements

### Requirement: acquire 记录工作区脏文件快照
`acquire` 成功占锁时，SHALL 记录当刻工作区的脏文件路径集合，与既有的目标文件内容快照、预留编号、域声明一同存入锁记录本身，MUST NOT 另建新的文件名形态。

取数 MUST 使用**本机 git**、MUST 显式关闭路径转义（`core.quotepath=false`）、MUST 包含未跟踪文件、重命名 MUST 取新路径。

> 路径转义这一条不是可选优化：本项目全部路径含中文，git 默认会把它们转义成八进制形式，届时脏路径与 §二 清单里的字面**永远对不上**，而命令退出码正常、输出看起来完全正常——这是「工具静默回退」的典型形态。

取数失败时 `acquire` SHALL NOT 因此失败——占锁本身仍成立，只是本次未记录快照；此时 release 侧的完整性校验按「无快照」处理（见下）。

#### Scenario: 占锁时记录脏文件集合
- **WHEN** `acquire` 成功占锁，工作区存在若干未提交改动与未跟踪文件
- **THEN** 这些路径被记入锁记录，供 release 时归因使用

#### Scenario: 中文路径不被转义
- **WHEN** 工作区脏文件路径含中文字符
- **THEN** 记录下来的是可读的原始路径，不是八进制转义形式

#### Scenario: 取数失败不阻断占锁
- **WHEN** 工作区状态取数失败（非 git 仓库／git 不可用／超时）
- **THEN** `acquire` 仍成功占锁，锁记录中不含脏文件快照

### Requirement: release 校验脏文件已被待处理批次覆盖
锁定目标为跨桌任务队列系统本体时，`release` SHALL 在放行前重新取得工作区脏文件集合，并逐一判定每个脏路径是否被**某个待处理 §二 批次行的文件清单**覆盖；存在未被覆盖的脏路径时，工具 MUST 拒绝释放、锁保持占用，并**逐个列出**未覆盖路径。

**覆盖判定** SHALL 复用落库 sweep 既有的后缀匹配口径：脏路径 `p` 被清单片段 `f` 覆盖，当且仅当 `p` 等于 `f`，或 `p` 以 `/` ＋ `f` 结尾。工具 MUST NOT 实现 sweep 那套「一个片段命中多个候选即判歧义」的判定——⑹ 只需回答「这个脏文件有没有归属」，一个片段同时覆盖多个脏文件对该问题无害。

**待处理批次** SHALL 指状态列开头片段不以完成标记开头的批次行，涵盖「待处理」与「在办（预登记，收工时精确化）」两态；判定 MUST 复用既有的状态列开头片段函数，MUST NOT 新造判据。

判定 SHALL 覆盖**两份物理队列文件**中的全部 §二 批次行。

由本工具自身产生的锁伴生文件 MUST 被排除在待覆盖范围之外。

> **本 Requirement 的判据刻意不是「本次持锁窗口内新增的脏文件」。** 取证（`reports/sweep-commit.log`，2026-08-22 12:20 UTC）证明：立项实证 `OP-0822-E` 的六个孤儿文件在其 12:26:16 UTC 占锁**之前 6 分钟**就已全部脏——按差集口径，它们在占锁那一刻已进基线，release 时差集为空、照样放行，缺陷原样复发。**差集口径抓不住它自己的立项实证。** 本判据逐字等同 sweep 孤儿检测已在用的那一条，本 Requirement 只是把它从「只进日志的事后告警」前移到「有阻断力、且 session 还活着」的时点。

#### Scenario: 存在未被任何待处理批次覆盖的脏文件，拒绝释放
- **WHEN** release 时工作区存在脏文件，且该路径不被任何待处理 §二 批次行的文件清单片段覆盖
- **THEN** 工具拒绝释放，锁保持占用，逐个列出未覆盖路径

#### Scenario: 全部脏文件均被覆盖，正常释放
- **WHEN** release 时全部脏文件均被某个待处理 §二 批次行的文件清单覆盖
- **THEN** 本项检查放行

#### Scenario: 已完成批次不算覆盖
- **WHEN** 某脏路径只出现在状态列已标记完成的批次行的文件清单里
- **THEN** 该路径判为未覆盖——已完成批次不会再被 sweep 取活，其清单不构成归属

#### Scenario: 预登记批次的目录前缀构成覆盖
- **WHEN** 某脏路径被一条预登记批次行的文件清单片段按后缀匹配覆盖
- **THEN** 该路径判为已覆盖（预登记批次属待处理态）

#### Scenario: 锁伴生文件不计入
- **WHEN** 工作区中存在本工具产生的锁文件、快照、互斥标记等伴生文件
- **THEN** 它们不被要求登记，不因其存在而拒绝释放

#### Scenario: 非队列系统目标不触发本项
- **WHEN** `--file` 指向队列系统以外的目标（如跟进信 README）
- **THEN** 本项检查不生效

### Requirement: 落库 sweep 身份豁免本项校验
持锁者为落库 sweep（`who` 等于 sweep 使用的固定身份标识）时，本项校验 SHALL NOT 触发。

> **豁免的道理，不是开后门**：本项问的是「你改完东西有没有登记，好让 sweep 来提交」；**而 sweep 就是那个来提交的人**。它在一次持锁窗口内做的是「`git add` 本批文件 → 把该批次行改成完成态 → release → commit」——release 那一刻工作区必然是脏的，且它刚把那条批次行标成完成、该清单已不再属「待处理批次」⇒ 本项**必然**判为未覆盖。要求它先给自己登记一条批次，是让消费者去写自己的待办清单；**判据的适用对象从来不包括它。**
>
> 🔴 **不豁免的后果不是多一条告警，是全项目停摆**：sweep 在 `finally` 里调 release 且**不看返回码**，被拒 ⇒ 锁保持占用 ⇒ 下一轮 sweep 起跑探锁判定「有人正在编辑」直接跳过 ⇒ 此后每一轮都跳过，而 sweep 是唯一会 commit 队列改动的机制。本条由 apply 期跑**邻居工具的测试套**当场撞出（本变更包自己的 239 条单测全绿），未进生产。
>
> 同族先例：企微机器人收件登记豁免预留归属校验（队列 #333②）——同样是「让校验认得一条既有的、结构性的例外」。

本豁免 MUST 仅作用于本项校验，MUST NOT 削弱 sweep 仍须通过的其它 release 校验。

#### Scenario: sweep 身份放行
- **WHEN** 持锁者为落库 sweep，release 时存在未被任何待处理批次覆盖的脏文件
- **THEN** 本项校验不触发，release 不因本项被拒

#### Scenario: 非 sweep 身份在同样状态下仍被拒
- **WHEN** 持锁者为普通 session，release 时存在同样的未覆盖脏文件
- **THEN** 本项校验正常拒绝

### Requirement: 未覆盖路径按占锁时刻归因
拒绝提示 SHALL 把未覆盖路径分为两组——本次持锁期间**新出现**的，与**占锁之前就已经脏**的——并对后者附一句说明：该改动可能来自并发 session，若确非本次持锁人所为，可用逃生阀放行。

锁记录中不含脏文件快照（`acquire` 时取数失败）时，工具 SHALL 把全部未覆盖路径按「无法判定出现时刻」呈现，MUST NOT 静默按某一组处理。

> 这条替代了原设想的「用快照差集过滤」。差集过滤是让机器**替人做一个它做不了的判断**（这脏文件是谁造的），并且默默判成「不是你」；归因提示是把判断交还给人，同时把机器确实知道的那点信息（时间先后）如实给出。

#### Scenario: 区分两类未覆盖路径
- **WHEN** 未覆盖路径中既有本次持锁期间新出现的，也有占锁前就已脏的
- **THEN** 提示分两组呈现，后一组附「可能来自并发 session」的说明与逃生阀走法

#### Scenario: 无快照时不臆断
- **WHEN** 锁记录中不含脏文件快照
- **THEN** 全部未覆盖路径按「无法判定出现时刻」呈现

### Requirement: 工作区状态取数失败时 fail-closed
`release` 时工作区脏文件取数失败（非 git 仓库／git 不可用／超时）SHALL 使本项检查判定为**拒绝释放**，并说明是取数失败而非检出未覆盖路径；工具 MUST NOT 静默放行。

> 本变更同批退休了「§二 新增批次行须声明队列文件自身」这道旧校验（协议〇.9 措施 B，one-in-one-out）。取数失败时若静默放行，这道咽喉上将什么都不剩。

逃生阀 SHALL 同样适用于本情形。

#### Scenario: git 不可用时拒绝释放
- **WHEN** release 时工作区状态取数失败
- **THEN** 工具拒绝释放，提示取数失败与逃生阀走法，不静默放行

### Requirement: 逃生阀——未登记而放行必须写下理由
工具 SHALL 提供逃生阀 `登记豁免：<理由>`，使确不该登记的改动不被堵死。

逃生阀的**取材面** SHALL 限于本次持锁的备注与本次持锁期间被触碰过的队列行，MUST NOT 扫描队列文件全文。

> 取材面这一条与既有 `转态豁免：` 同一收敛方向，理由也相同：豁免标记一旦写进两份 1.9 MB 的队列文件任何一处，全文匹配就等于把这道门禁**永久关掉，且此后没有任何人会发现**。逃生阀必须一次一用，不能变成一个写一次就长期生效的开关。

命中逃生阀时，工具 SHALL 打印被放行的未覆盖路径数量与理由摘要，使这次放行在标准输出上仍然可见。

#### Scenario: 备注中声明豁免，放行
- **WHEN** 存在未覆盖脏路径，且本次持锁的备注中含 `登记豁免：` 与理由
- **THEN** 本项检查放行，并打印被放行的路径数量与理由摘要

#### Scenario: 本次触碰的队列行中声明豁免，放行
- **WHEN** 存在未覆盖脏路径，且本次持锁期间新增／修改的某条队列行内含 `登记豁免：` 与理由
- **THEN** 本项检查放行

#### Scenario: 豁免标记只存在于未被触碰的历史行，不放行
- **WHEN** `登记豁免：` 只出现在队列文件中本次未被触碰的历史行里
- **THEN** 本项检查不放行——取材面不含队列全文
