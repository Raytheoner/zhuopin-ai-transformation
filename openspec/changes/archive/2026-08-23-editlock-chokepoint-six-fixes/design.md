## 1. 判据全部由实测定标（原始数据）

### ⑶ §二 文件清单路径格式

| 项 | 实测 |
|---|---|
| §二 现存批次行中「形如路径」的反引号片段 | 1371 个 |
| 格式违规 | **220 个（16.0%）** ＝ 裸文件名 210 ＋ 绝对路径 9 ＋ 反斜杠 1 |
| 格式合规但当前磁盘上不存在 | 98 个（**若加存在性校验，这就是误报量**） |

**两条设计结论**：

1. **不做存在性校验（含斜杠的片段）**。98 个不存在者里大量是合法的范围性速记（`openspec/changes/.../{proposal,design,tasks}.md`、`X/tests/test_*.py`、`0-学习与工具/skills源码/<name>/SKILL.md`）与「当时存在、后来移走」的历史件。7% 的误报会把逃生阀变成常规操作，而逃生阀一旦常规化，这道门禁就废了（同 #351 ⑷ 那条 10% 误报的教训）。
2. **裸文件名例外要靠存在性判**：`CLAUDE.md`／`.gitignore` 这类**根文件**的裸文件名**就是**正确的仓库根相对路径。故规则写成：片段不含 `/` 时，**仓库根下存在同名文件即放行，否则拒绝**。这样既放过根 `CLAUDE.md`，又拦住 `工具-落库sweep.py`（真身在 `0-学习与工具/` 下）。

**⚠️ 与 sweep 的关系必须写清楚（否则下一位读者会以为两边判据打架）**：`工具-落库sweep.py::_resolve_batch_fragments` 的 docstring 明文「不去猜测…这类约定——直接拿片段去匹配当前真实脏路径的**后缀**」，即 **sweep 这个读者是刻意宽容的**。⑶ 收紧的是**写者**，不是读者。这是 Postel 原则的正用，且**恰好消灭 sweep 那条宽容路径上的 `ambiguous` 失效形态**（#234(1)：根 `CLAUDE.md` 与 SC8 目录下同名文件同时脏，片段 `` `CLAUDE.md` `` 命中两个候选被判歧义，连带跳过一个本已声明齐全的批次）。**写者精确 ⇒ 读者的 `ambiguous` 分支不再被触发**，而不是两套判据互相矛盾。

**预登记批次豁免**：`queue-claim-time-preregistration` 的 Requirement「预登记批次的内容与状态标识」明文允许其文件清单为「目录前缀或范围性描述」。⑶ 对状态列含「预登记」的行**不生效**；该行走到「收工时精确化」那一步会被重新触碰，届时不再是预登记态，⑶ 自然接管。**这不是给它开后门，是让两条 spec 各自守住自己那一段生命周期。**

### ⑷ 性别代词判据的收窄（这一项偏离 #351 原文最多，逐步给数据）

#351 ⑷ 的原文判据是「**同一行内**出现男性名且出现『她』／出现女性名且出现独立的『他』」。实测：

| 判据 | 命中行数 |
|---|---|
| 整行（#351 原文） | **65** |
| 人名后 40 字窗口内 | 19 |
| **人名后 25 字窗口内** | **18** |
| 人名后 15 字窗口内 | 13 |

**整行判据的误报来源是队列行的体量**：§一 单行常达数千字、跨多个话题；一行里提到「唐燕萍」（在讲财务口径），同一行别处出现「他」（指 Shao Peishen），整行判据必然配对成功。这与 #324 给校验 ⑥ 做的收窄是**同一个病**（「4062 字符／11 段的单元格里，四个暂缓关键词全在历史段」），故采用同族的解法。

**为什么用「邻近窗口」而不是 #324 的「首段收窄」**：⑥ 要判的是「这一格当前的结论是什么」，首段就是结论所在；⑷ 要判的是「这个代词在指谁」，**指代关系是局部的，与段落位置无关**——一个写在第 7 段的「姚祖怡…她」同样是错的。窗口直接对应指代距离，首段不对应。

**窗口取 25**：40 与 25 只差 1 行（19 vs 18），15 会掉到 13、开始漏掉正常语序（「姚祖怡在 8 月 12 日的回件里说她…」）。取 25 是「已到平台期、且尚未开始漏」的那个点。

**附加收窄：中间隔着异性名字即跳过**。`姚祖怡…唐燕萍…她` 里的「她」指唐燕萍，不是误用。这条复刻既有实践——2026-08-21 那次 244 处追改的脚本判据本身就是「含姚祖怡、含她、**且同行不含陈忱／唐燕萍**」。

**残余 18 行的性质（已逐条看过样本）**：绝大多数是**引用规则条文本身**的行——`#351` 自己那一行、`§四 #75` 那一行，正文里逐字写着「出现 `陈忱`／`唐燕萍`（女）且出现独立的 `他`」。这类**必然**命中，且**必然**是合法的。⇒ `性别豁免：` 不是异常出口，是这条 lint 的**常态配套**，实现方与文档都按常态写。

**名录来源（Shao Peishen 2026-08-23 答，选 (b)）**：抽成单一常量 ＋ 一条与根 `CLAUDE.md` §1 对表的单测。**否掉「运行时解析 CLAUDE.md」的理由**：CLAUDE.md §1 是每周都在变的散文，措辞一变解析就抽不到人名，判据变成**恒真、零信息量**，而**没有任何东西会报错**——用一个失效不产生信号的实现，去做一条专为根治「错误不产生信号」而立的校验，是原地打转。

**单测的方向必须是「⊆」而不是「＝」**：从 CLAUDE.md §1 抽出的每个带性别标注的人名，**都必须在常量里且性别一致**；常量里多出的条目允许（`邵培申` 在 CLAUDE.md 里写作「`邵培申` ＝ Shao Peishen 本人」，没有 `（男）` 标注，抽不出来）。这样既抓住真正的失效形态（**名录扩了而常量没跟**），又不要求 CLAUDE.md 写成机器可解析的格式。

## 2. ⑹ 的判据：为什么偏离 #351 原文

**完整取证与结论见 proposal.md「与 #351 原文的一处偏离」节，此处只补两点实现层面的推论。**

### 2.1 acquire 快照保留，但改变用途

原设计里快照用于**过滤**（差集）。改判后快照用于**归因**：拒绝提示里把未覆盖路径分成两组——「本次持锁期间新出现的」与「acquire 之前就已经脏的」。后者附一句「若确非你的改动，用 `登记豁免：` 放行」。

**这比差集过滤更诚实**：差集过滤是让机器**替人做一个它做不了的判断**（这脏文件是谁造的），并且默默地判成「不是你」。归因提示是把判断交还给人，同时把机器知道的那点信息（时间先后）如实给出。

### 2.2 git 取数的两个坑

1. **必须本机 git，不得用沙箱 git**（§四 #98）：本机 `core.autocrlf` 来自 Windows system 级配置，沙箱 git 读不到，同一工作区两个 git 给出相反答案（967 份「已修改」vs 干净）。本工具由 CC 在本机执行，`subprocess` 起的就是本机 git，天然满足；**但仍显式记在代码注释里**，因为下一位读者可能想把这段挪到沙箱侧跑。
2. 🔴 **必须 `-c core.quotepath=false`**：git 默认把非 ASCII 路径转义成 `"1-\350\275\254\345\236\213..."`。本项目**全部路径都是中文**，不加这个参数，⑹ 拿到的路径与 §二 清单里的字面永远对不上——**结果是「所有脏文件都未被覆盖」这种整体性误报，或反过来被误当成「没有脏文件」**。这是一个典型的「工具静默回退」形态：命令成功、退出码 0、输出看起来完全正常。

### 2.3 git 不可用时 fail-closed

`git status` 执行失败（非仓库／git 缺失／超时）时**拒绝 release** 并说明原因，不静默放行。理由：⑹ 上线后 ② 已退休，静默放行等于这道咽喉上什么都没有。逃生阀 `登记豁免：` 仍可越过。

### 2.4 覆盖判定复用 sweep 的口径，不新造

脏路径 `p` 被片段 `f` 覆盖 ⟺ `p == f` 或 `p.endswith("/" + f)`——**逐字复刻 `工具-落库sweep.py::_resolve_batch_fragments` 的后缀匹配**。**刻意不实现 sweep 那套 `ambiguous` 判定**：sweep 需要它是因为它要决定 `git add` 哪个文件（选错会 add 错东西）；⑹ 只需要回答「这个脏文件有没有归属」，一个片段同时覆盖两个脏文件对这个问题是无害的。**能不抄的复杂度就不抄。**

### 2.5 「待处理」批次的口径

批次行状态列**开头片段**（`_leading_status_segment`，既有函数）不以 `✅` 开头者即算待处理——涵盖 `待处理` 与 `在办（预登记，收工时精确化）` 两态。**复用既有函数，不新造判据。**

## 3. ⑴ 的两个取舍

### 3.1 无有效锁时不阻断

`append-row` 在**没有有效锁**时只打印告警、照常写入。理由：opener §〇.7 明文「本条只新增结构化插入通道，**不强制**所有新行都必须走它——直接在编辑器里手写整行仍是允许的」；把 `append-row` 变成「必须先持锁」等于**改变全项目口径**（CLAUDE.md §5 机制类门槛第①条），须另走 openspec。**⑴ 要修的是「锁归属不校验」，不是「无锁写入」**，两件事不混做。

### 3.2 `--who` 缺失时拒绝（而不是告警）——这条有真实生产影响

2026-08-18 事故的形态是：`acquire`（**已被正确拒绝**）／`append-row`／`release` 打包成一条命令、不查退出码，`append-row` 在他人持锁期间照写两次。**该次调用没有 `--who` 可用**——所以「只在 `--who` 不符时拒绝」拦不住它，必须「`--who` 缺失也拒绝」。

**代价已实测，不是假设**：`0-学习与工具/定时任务源码/{huijian-chaijian-patrol,weekly-status-update}.SKILL.md` 两份都是「先 `acquire --who X`、再 `append-row`（**不带 `--who`**）」，且**已安装副本存在于** `C:\Users\Paul Shao\Claude\Scheduled\` 下、是两个计划任务的实际执行体（拆件巡逻每工作日两班、值周巡检每周一）。⑴ 上线后它们会被拒绝。

⇒ **本变更包必须同批更新源码副本与已安装副本**，否则就是「修好一道守卫、打断两个每日在跑的机制」。这一条列进 tasks.md 的验收项，`diff` 为空才算过。

## 4. ⑵ 的诊断合并与「修正后的命令行」怎么生成

arity 失败时（`len(cells) != expected`）：

1. 扫全部 cell，记录含裸竖线者的序号。
2. **若无裸竖线** → 维持原错误信息（纯数数问题，不添噪音）。
3. **若有裸竖线** → 合并诊断，并尝试**恢复意图**：把所有 cell 按 `|` 拆开、去空白后重新计数。
   - 恢复后**恰好等于** `expected` → 高置信，打印一条**完整可复制的命令行**（`--section`／`--number`／逐个 `--cell`），并写明「这是按『你漏写了 --cell 分隔符』推断出的原意，请核对后再跑」。
   - 恢复后**不等于** `expected` → 只给合并诊断，**不猜命令行**。宁可少给，不给一条错的。

**🔴 边界：恢复出的命令行只打印，绝不自动执行。** 这是 Shao Peishen 否决 `--row-md` 那条理由的直接推论——不新增第二条写入路径。打印一条待人核对的建议，与新增一条工具自己走的通道，是两件事。

## 5. 退休 ② 的实现

删除 `_validate_release_structure` 中 `declares_self` 那一段与其 violation。相关既有单测**不是删掉，是改判**——改为断言「新增 §二 行不含队列文件自身路径时**不再**因该项被拒」，并在用例 docstring 里写明退休依据（协议〇.9 措施 B ＋ 被 ⑹ 覆盖）。**留下一条会跑的用例，比删掉它更能让下一位读者知道这里发生过什么。**

## 6. Non-Goals（明写，防下一位扩范围）

- **不做 ⑵-b `--row-md`**（已否决，理由见 proposal）。
- **不把 `append-row` 提升为强制通道**（改全项目口径，须另走 openspec）。
- **不解决「完全不 acquire 的 session」**——那类改动由 sweep 孤儿告警兜住，属另一层（#351 ⑹ 边界二明文划出）。
- **不追改存量**：220 个路径格式违规、27 个撞号、65 行代词命中，全部只对**此后新写入／被触碰**的行生效（「历史记录不追改」）。
- **不把 ⑷ 扩到跟进信正文**。真实损失最大的那次（采购部#14 把李姣龙写成「他」，信已发出撤不回）发生在跟进信里，不在队列里；但 #351 ⑷ 的范围是队列 lint，扩范围须另立行。**这一条留在这里，是因为它是本变更包已知覆盖不到的地方，下一位不该以为 ⑷ 上线后跟进信就安全了。**
