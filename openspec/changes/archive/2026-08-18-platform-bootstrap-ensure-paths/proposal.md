# platform-bootstrap-ensure-paths Proposal

> 队列 #345 第二步。第一步（17 处入口的扁平布局回退，纯 bugfix）已于 2026-08-18 单独完成并部署验证；**本提案只做 propose，不 apply**，等 Shao Peishen 审 design 后再排期。

## Why（为什么做）

**一段手抄了 35 遍的 `sys.path` 引导，已经漂成 4 种彼此不等价的语义，且其中一种在 2026-08-18 打挂过生产。**

队列 #300（2026-08-08）为解决"多 worktree 共用一套全局 site-packages、谁装的 editable 指针谁说了算"，在每个入口文件顶部内联了一段向上查找 `5-平台底座/zhuopin_platform` 标记的引导。该做法本身有效，但**以复制粘贴为唯一分发方式**，于是：

| 形态 | 找不到 monorepo 标记时的行为 | 文件数 | 风险 |
|---|---|---|---|
| A | 无条件 `raise RuntimeError` | 12 | 🔴 在扁平布局下把入口钉死 |
| B | 插自身包路径 → `find_spec` 兜底 → 才 raise | 18 | 当前认为正确 |
| C | 显式探测扁平布局兄弟目录 `../../../zhuopin_platform` | 2 | 与 B 等价但实现不同 |
| D | 无 `else`，静默跳过 | 3 | 平台底座真缺失时报错点被推迟 |

（实测数据，2026-08-18，判据＝`grep -rl 'for _p in (_HERE, \*_HERE.parents)' --include=*.py`，共 35 个文件。）

**A 形态的代价已经兑现过两次**：`.51` 的部署布局是扁平的 `C:/<svc>/{app,zhuopin_platform}`，**本就没有 `5-平台底座/` 这层目录**，A 形态在那里必然 `raise`。2026-08-18 同一天内两条互不知情的 session 各自撞上：SC8（8091）发布收口时把保供看板打挂（`OLD_CLEAR`+`RESTART_FAILED_NO_INSTANCE`、计划任务 `LastResult=0` 而进程秒退、`/api/ping` 502），QD-B（8093）部署时复现同一现象、中断约 4 分钟。**两处各自修了一遍、改法雷同却互不知情**——这正是本提案要消灭的形态。

🔑 **它还在继续繁殖，不是存量问题**：`4-数字员工/采购部/SC2-采购周报自动生成/`（2026-08-18 新建，晚于 #300 修复共识）**出生就带 A 形态**——`run_sc2.py` 与 `tests/conftest.py` 各一份。**只要分发方式还是复制粘贴，每个新场景都会再抄一份，且抄到的是哪一种取决于作者当时看的是哪个文件。**

## What Changes（改什么）

**新增**：`zhuopin_platform.bootstrap.ensure_paths()` —— 一个函数，两条分支（monorepo 开发机 / 扁平部署机），一处修全体受益。

- 找到 `5-平台底座/zhuopin_platform` 标记 → 按 #300 原语义前插（开发机，确定性优先，压过全局 editable 指针）
- 找不到 → 只插调用方自身包路径，平台底座交由环境解析（生产机，venv 内唯一一份、无歧义）
- 两条分支都走完仍无法 `find_spec("zhuopin_platform")` → **明确 raise，不引入静默失败**
- 提供 `strict=True` 供 `tests/conftest.py` 保留 fail-loud 语义（见下）

**改**：35 处内联块逐步收敛为一次调用。**分两批**，因为两类文件的正确语义并不相同：

- **批一（18 个非测试入口，B 形态）**：换成 `ensure_paths()` 调用，行为等价。
- **批二（12 个 `tests/conftest.py`，A 形态）**：换成 `ensure_paths(strict=True)`，**保留 fail-loud**——🔴 **在 monorepo 内 fail-loud 是有价值的**：测试就该跑在仓库里，找不到标记说明环境真错了，此时静默回退才是隐患。**这一条是队列 #345 行内已写明的判断，不得顺手"统一"掉。** 收拢的收益在于「语义由一个具名参数显式声明」，而不是「12 份各自碰巧写成了 raise」。
- **C/D 形态 5 个**：并入批一，语义对齐到 B。

**鸡生蛋问题**：引导的目的就是让 `zhuopin_platform` 可导入，而函数本身在 `zhuopin_platform` 里。解法与取舍见 design.md 决策点 1（推荐：保留一个 3-5 行的极小 stub 负责找到并导入 bootstrap，其余逻辑集中）。

## 本次退休哪一个既有守卫（强制，协议〇.9 措施 B）

**退休对象＝「新场景 scaffold 时照抄既有场景引导代码片段」这条人守约定**（根 CLAUDE.md §5 场景固定流程第 1 步："新场景 scaffold 时在其 `tests/conftest.py` 顶部与服务入口脚本顶部照抄既有场景（如 SC8）同款引导代码片段"）。

**它已达退休阈值且证据充分**：① 它是**人守**规则，靠作者记得去抄、且抄对文件；② SC2（2026-08-18 新建）**照抄到了 A 形态**——规则被遵守了，结果仍是错的，**说明这条规则即使被执行也不产生正确结果**；③ 35 份副本漂成 4 种语义，本身就是"照抄"这个分发机制的失败记录。

**退休方式＝机制化**（规则退休制二选一的①）：改为 `from zhuopin_platform.bootstrap import ensure_paths; ensure_paths()` 一行调用，**抄错的可能性从"抄了哪一种"收敛为"抄没抄"**——后者是 import 失败、当场可见，不是静默的语义分叉。CLAUDE.md §5 该步正文相应改为指针（依据 #206 惯例：可降级为一行指针、不必删）。

## 伴生文件的 .gitignore 覆盖（强制，队列 #328②）

**不适用**：本变更不新增任何自动生成的文件形态——不产生锁文件、快照、暂存、状态文件、日志、重命名退路产物或备份副本。新增物仅为 `zhuopin_platform/bootstrap.py` 一个源文件及其单测，均为正常入库的跟踪文件。`__pycache__/` 属既有形态、已被 `.gitignore` 覆盖（`git check-ignore -v` 实测命中 `.gitignore:__pycache__/`，非推断）。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

1. **本流程哪些判断是人脑默会经验？**
   - 「哪些文件该 fail-loud、哪些该回退」——当前只在写过 #300／#345 的几条 session 的上下文里，**没有任何代码或文档把它固化成可判定的规则**；SC2 抄错正是这条默会知识没传下去。
   - 「`.51` 是扁平布局」——散落在各 deploy 脚本与 `_find_env()` docstring 里，**同一文件里两处对同一部署形态的认知不一致**（#345 行内已记）。
   - 「引导必须在任何 `zhuopin_platform` import 之前」——靠注释口口相传，无机制保证。
2. **由谁显性化？** 持有人＝Shao Peishen（分管，最终判定）；backup＝承接本变更包的 CC session。**本变更包自身即为显性化载体**——上述三条判断落进 `ensure_paths()` 的参数语义与 spec 的 Requirement，不再依赖记忆。
3. **用什么方法提取？** **历史案例反推**——依据已发生的三次真实事故（#82 FI2 2026-08-10、#345 SC8 与 QD-B 2026-08-18）与 35 份副本的实测形态分布反推规则，不做抽象设问。

## 验收与晋档条件（强制，四档口径）

- **本变更包交付后场景所处档位**：**不适用四档口径**——本变更是平台底座机制/工具类变更，非业务场景，不产出业务价值档位。按 §5 机制类门槛③（改变既有模块在相同输入下的行为）走 openspec + design 审。
- **晋档/收口条件**（逐条，代替档位）：
  1. `ensure_paths()` 单测覆盖四种情形：monorepo 命中 / 扁平命中 / 两者皆无但环境可导入 / 全无（须 raise）；
  2. 批一 18 处替换后，**每个受影响场景全量测试零漂移**；
  3. 批二 12 处 `conftest.py` 替换后，`strict=True` 的 fail-loud 行为经**真实构造缺标记环境**验证仍然报错；
  4. 🔴 **三个 `.51` 常驻服务（8091／8093／8094）真部署并冒烟**（`/api/ping` + 关键页 200），**不能只在本地判"应该好了"——这个 bug 的全部特征就是本地看不出来**；
  5. 全库复扫：`grep -rl 'for _p in (_HERE, \*_HERE.parents)'` 命中数由 35 降至 0（stub 除外，其形态唯一且集中）。
- **价值指标**（风险型）：**基线**＝2026-08-18 前后 10 天内因该引导导致的生产中断 3 次（#82／SC8／QD-B），平均定位耗时长（现象为"计划任务 LastResult=0 但进程秒退"，极难归因）；**目标**＝收口后该类中断归零，且新场景不再可能引入 A 形态。基线由 Shao Peishen 确认。
- **LLM 判据黄金集**：不适用（本变更不含任何 LLM 运行时判断）。

## Impact（影响面）

- **新增 specs**：`platform-path-bootstrap`（本变更包 `specs/` 下）
- **新增代码**：`5-平台底座/zhuopin_platform/zhuopin_platform/bootstrap.py` + 单测
- **受影响文件**：35 个（18 非测试入口 + 12 `conftest.py` + 5 C/D 形态），跨 FI1/FI2/SC1/SC2/SC7/SC8/QD-B/O1/O2 九个场景 + `wecom-aibot-service` + `zhuopin_platform` 自身
- **触碰区冲突**：SC2 正在由另一条 session 建造（opener A2）、O1 亦然（opener B）——**本变更包 apply 时须重新核对这两个场景的在办状态**，不可与其并发改同一批文件
- **红线核对**：mock 先行（不适用，纯路径解析，不碰数据）· audit 留痕（不适用，无业务决策）· OEM 隔离（不适用）· L2 门禁（不适用）· ISO 26262（不适用）
- **回滚**：批一/批二可独立回滚；stub 与 `ensure_paths()` 向后兼容内联块，允许两种形态在过渡期共存，**不要求一次性全切**
