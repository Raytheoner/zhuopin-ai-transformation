## Why

### 一句话

`#136` 的防护本身是对的，**错在它把「不脏」当成了「没到」**。现网 113 条被判缺项的路径里，**只有 8 条是真的没到**；其余 105 条是「已经到了、且此后永远不会再脏」——批次因此永远等不到放行的那一刻。

### 自锁是怎么形成的

覆盖校验现行判据（`_manifest_coverage_gap`）＝ **`resolved` 非空时，清单里形状合格却对不到任何脏路径的片段即判缺项 ⇒ 整批跳过**。

判据背后的隐含假设是：**「现在不脏」＝「内容还在别的分支上，等它合入 master 就会脏」**。这个假设在 2026-08-29 那一次成立（代码确实还在 worktree 分支上），但它对下面三类路径**永远不成立**：

| 类 | 形态 | 会不会再脏 | 现网条数 |
|---|---|---|---|
| **A** | 路径被 `.gitignore` 覆盖（`**/reports/`，`.gitignore:50`） | **永远不会**——它连 `git status` 都不会出现 | **16** |
| **B** | 路径已在 `HEAD`、且工作区对它无改动（内容早已落库；含两份队列真身、接力卡这类每批都写的高频共享件） | **不会**——除非有人再改它一次，而那与本批无关 | **89** |
| **C** | 既不在 `HEAD`、也未被忽略 | 会（这才是 `#136` 要防的形态） | **8** |

A 类是**绝对自锁**（登记方写了一个物理上不可能变脏的路径）；B 类是**相对自锁**（批次 X 把共享件提交走 ⇒ 批次 Y 的同一条清单项从此对不上；队列真身随后又被别的写入弄脏，但那时轮到别的批次先落 ⇒ Y 再次跳过。**Y 永远等不到「它清单里所有文件同时脏」的那一刻**）。

### 现网实测（2026-09-10 现取，`reports/sweep-commit.log` 全量解析）

- **760 条**「整批跳过——文件清单覆盖校验未过」记录，涉及 **48 个批次**。
- 连续跳过轮数 TOP5：`B-0903_51_…两链合master_采购三包链_SC8_ATP批2收口链` **111 轮**、`B-0902_48_…采购提前期中位数统计` **78 轮**、`B-0902_49_…Chroma归属重判` **78 轮**、`B-0902_62_…Chroma五点裁决收口` **77 轮**、`B-0902_64_…判例包依赖未解除` **77 轮**。sweep 每 27 分钟一轮 ⇒ 111 轮 ≈ **50 小时以上**的连续重复告警。
- 去重后 **113 条**被判缺项的路径，按上表归类 ＝ **A 16 ／ B 89 ／ C 8**。
- 缺项路径出现频次 TOP2 ＝ `1-转型规划/0-全景路线图/跨桌任务队列-业务场景.md`（**600 次**）与 `…跨桌任务队列-机制环境.md`（**454 次**）——**两份队列真身自己就是最大的自锁源**。

### 真实损失不是「批次没销号」

队列 `#507` 行内原文：本次抢救出的十件里，`1-转型规划/0-全景路线图/队列行日志/#502.md` 是 SC2 冒烟八段的**原始留痕**，而 `reports/` 被 `.gitignore` 覆盖、换机即失 ⇒ **它是唯一副本**。同批还有摘标全部证据、FI6 `intent.md`、两份派单件。**独有产出进不了 git，才是这条自锁的代价**；批次账面不销号只是它的表征。

### 为什么队列行给的候选 ⑴ 不够——本包最重要的一条否定结论

队列 `#507` 立行时写的候选 ⑴ ＝「高频共享件（两份队列、接力卡、文档台账）命中即视为已覆盖」。**实测该白名单只能放行 760 条中的 42 条（5.5%）**，救活 15 个批次；111 轮的头号卡死批次 `B-0903_51` **不在其中**（它的缺项是 `design审读件-…-2026-09-03.md`、两份看护件、一个 `reports/lane-heartbeat/…md`，全都不是共享高频件）。

⇒ **`#507` 行内那句「错在把共享高频件和本批独有产出一视同仁」只描述了 5.5% 的病灶**。本包据实测把病因改述为：**判据把「不脏」等同于「没到」，而「不脏」的绝大多数情形其实是「已经到了」。**

### 本次退休哪一个既有守卫（协议〇.9 措施 B，队列 `#308`）

**退休对象 ＝ `_manifest_coverage_gap()` 现行判据本身**（「形状合格 ＋ 不脏 ⇒ 缺项」），由更窄的判据原地取代，**不新增第二道守卫、不新增独立检查函数**。同时退休两条既有行为：

1. **「`reports/` 下的路径参与覆盖校验」整类**——被 `.gitignore` 覆盖的路径此后一律不计入缺项（它本就不可能通过校验，参与校验只产生噪音）。
2. **「同一批次每轮重刷同一条跳过日志」**——降频为「首轮 ＋ 每次升格时」各一条（详见 §What Changes ④）。760 条记录里的绝大多数是同一句话的重复。

**没有守卫被整条删除**，因为本包治的是判据过宽而非守卫多余；`#136` 要防的形态仍须有人守。这一取舍已如实写明，不以「无」搪塞。

## What Changes

### ① 判据换锚：缺项 ＝ 形状合格 ＋ 不脏 ＋ **不在 HEAD** ＋ **未被 `.gitignore` 覆盖**

`_manifest_coverage_gap()` 增两条排除：片段若能在 `HEAD` 里找到对应文件（复用 `_resolve_batch_files` 同一套「精确相等 或 `/` 后缀」匹配规则，不另起一套），或该片段被 `git check-ignore` 命中，则**视为已覆盖**，不计入缺项。

判据的语义由「**这次提交装不装得进去**」修正为「**这条声明的内容在不在本仓库里**」——后者才是「空壳提交」真正要问的问题。

### ② 部分装入时，提交信息必须自陈实际装入范围

`#136` 的伤害本体是**那条谎**（标题说整批、内容只有 N 个）。①放宽判据后，「清单 M 条、本次装入 N 条（N<M）」将成为常态，故须让提交自己说实话：提交信息正文追加一段，写明 `本批清单 M 条，本次实际装入 N 条`，并逐条列出未装入的路径及其归类（`已在 HEAD` ／ `被忽略` ／ `缺项`）。**标题一字不改**（保持与 §二 登记一致、便于追溯）。

### ③ 形状判据补三条 reject

现网 8 条 C 类里有 2 条是形状误认：`hooks.PreToolUse`（JSON 键名，正文强调）、`C:\Dev\zhuopin-ai\.claude\worktrees\wecom-service-home\5-平台底座\.env`（仓库外的 Windows 绝对路径；末尾 `\.env` 里的 `\` 落进 `[^/.\s]` 而被现行正则放行）。补：① 含反斜杠即拒；② 形如 `^[A-Za-z]:` 的盘符绝对路径即拒；③ 不含任何 `/` **且不是 `HEAD` 里的仓库根文件**即拒。

🔴 **第③条的例外不是保险起见，是实测撞出来的**：对现网两份队列 §二 全量跑形状判据（**69 行 / 84 个整行反引号片段 / 42 个唯一片段**），「无斜杠即拒」会新拒掉 1 条，而那一条是 **`CLAUDE.md`**——仓库根下的真实文件，且确实以裸名出现在现存清单里。

### ④ 连续跳过 ≥K 轮 ⇒ 升格 §四（队列 `#507` 期望产出③）

**复用既有 `_escalate_long_lived_orphans_to_section_four()` 的整套范式，不另起一套机制**：状态文件计数 → 达阈值 → 编辑锁 `acquire --reserve 1 --section 四` → `append-row` → 当日去重 → 失败只留日志不改退出码。升格文案须点名批次号、连续跳过轮数、缺项清单与其归类，并给可直接作答的选择题。同时把「每轮重刷同一条日志」降频（见 §Why 退休项 2）。

### ⑤ 历史回扫（队列 `#507` 期望产出④）

**不写一次性回扫脚本**。①落地后，42 个批次的缺项将全部落进「已在 HEAD／被忽略」⇒ 下一轮 sweep 自动按既有两条路径消化：仍有脏改动的走正常落库、已无脏改动的走既有「遗留尾巴补销」（`#328`）。apply 阶段只需在 tasks 里**现取核对残余**并逐条登记。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

1. **本流程哪些判断是人脑默会经验？**
   - **「这条清单项现在对不上，是『还没到』还是『早就到了』」**——此前 100% 在人脑里。人一眼能分辨「代码还在别的 worktree 分支上」与「这文件昨天就已经 commit 进 master 了」，机器只看得见 `git status` 那一个切面。本包把这个判断显性化为两条可执行的判据（`HEAD` 存在性 ＋ `.gitignore` 命中）。
   - **「清单里写了一个被 gitignore 的路径」这件事本身是登记错误**——此前无人表述过，因为无人预见登记方会把 `reports/` 下的运行产物写进文件清单（现网 16 条）。
   - **阈值「连续跳过几轮才算没人接」**——现取自队列 `#507` 行内写的 ≥3 轮，非独立论证，故列为 design 决策点 D4 请他拍。
2. **由谁显性化？** 持有人 ＝ 本次 propose 的 CC 泳道 `507-sweep-selflock`（`OP-0910-E`），全部判据均由现网全量实测反推、非凭经验；**backup ＝ Shao Peishen**（design 审拍板判据松紧与残余风险接受度）。
3. **用什么方法提取？** **历史真实案例反推 ＋ 现网全量实测**：⑴ 对 `reports/sweep-commit.log` 全量 760 条跳过记录做结构化解析，去重出 113 条缺项路径，逐条跑 `git ls-tree -r HEAD` 与 `git check-ignore --no-index` 定性；⑵ 对 2026-08-29 事故提交 `6557047` 的 8 条声明路径，用 `git ls-tree -r 6557047^` 复原当时的 HEAD 状态，验证新判据是否仍能拦住。**不涉及 LLM 判断**（纯集合运算与 git 只读查询）。

- **价值指标**（风险型 ＋ 工时型，基线为本次现网实测、非估计）：
  - **风险型**：「独有产出滞留在工作区、不进 git 的最长时长」。基线 ＝ **111 轮 ≈ 50 小时以上**（`B-0903_51`，且期间 `reports/` 下的唯一副本无任何备份）；目标 ＝ 卡死批次数由 48 降至 ≤6（即只剩 C 类真缺项），且真缺项 ≥K 轮必进 §四 有人排期。

## 已知残余风险（如实登记，不淡化）

1. 🔴 **纯修改类批次的漏过面被扩大**——若一个批次声明的文件**全部已在 HEAD**、而本批的改动**全都还在别的分支上**，新判据会放行，产出一个「清单 M 条、实际装入 N 条」的提交。这是本包对 `#136` 唯一实质性的放宽。缓解 ＝ ② 的提交信息自陈（提交自己写明装入了哪 N 条、其余 M−N 条为何没装），使该提交**不再是一条谎**，可被事后追溯。**缓解不等于消除**：读者若只看标题仍会误解。这是决策点 D2 要他拍的取舍。
2. **`HEAD` 存在性是「文件在不在」，不是「内容对不对」**——本能力的观察面仍如既有 spec 所限定，MUST NOT 被表述为「知道声明的内容是否已合入」。
3. **形状判据仍是启发式**，`#136` 登记的两个方向的失手原样成立；③ 只消除两条已实测的误认，不声称穷尽。
4. **④ 的升格依赖编辑锁可用**——锁被占时本轮跳过（同既有孤儿升格惯例），故「升格」是尽力而为、不是保证。
