## Purpose

跟进信 README 中单行体积异常增长时 SHALL 被限制并外置到独立行日志文件，防止个别行的历史回写把整表重新撑大，重演二期治理前的体积问题。

## ADDED Requirements

### Requirement: 超长发送状态外置行日志
主表或归档件中一行的「发送状态」列内容超过阈值时，SHALL 将该列历史内容外置到 `跟进信行日志/<部门#N>.md`（原文原样），行内只保留首段与末段及指向该日志文件的指针。**阈值复用跨桌任务队列同一套判据常量（4 KB，UTF-8 字节，即 `ROW_LENGTH_CAP_BYTES`），不另立数值**（Shao Peishen 2026-09-06 经环境总线拍板，D3-1）。

#### Scenario: 发送状态列超限触发外置
- **WHEN** 一行的「发送状态」列内容达到或超过 4 KB
- **THEN** 该列历史内容原文原样写入对应的行日志文件，主表该行只保留首段＋末段＋指针

### Requirement: 超长主要事项压缩为摘要
主表或归档件中一行的「主要事项」列内容超过 600 字节时，SHALL 将该列压缩为摘要，原文原样写入同一行日志文件。**摘要生成规则（Shao Peishen 2026-09-06 经环境总线拍板，D3-2）**：取首句（按「。／！／？／换行」切分）或前 200 字（两者取其一，以不超过 600 B 上限为准），追加指向行日志文件的指针；不做语义压缩／不调用模型摘要。

#### Scenario: 主要事项列超限触发外置
- **WHEN** 一行的「主要事项」列内容超过 600 字节
- **THEN** 该列在主表中被替换为「首句或前 200 字＋指针」的确定性摘要（非智能摘要），原文写入对应行日志文件

### Requirement: 编辑锁行长判据分级生效
`工具-共享文档编辑锁.py` 的 release 校验族 SHALL 对 README 应用与队列行长判据同族的分级生效策略：本能力上线后第一周内检出超长行 SHALL 仅告警、不阻断 release；满一周后检出超长行 SHALL 阻断 release，除非该行已显式标注逃生阀 `行长豁免：`。

#### Scenario: 首周内超长行只告警
- **WHEN** 本能力上线未满 7 天，release 时检出某行超过行长阈值
- **THEN** release 正常放行，但输出告警信息

#### Scenario: 满一周后超长行阻断 release
- **WHEN** 本能力上线已满 7 天，release 时检出某行超过行长阈值且未标注 `行长豁免：`
- **THEN** release 被拒绝，提示该行超限及外置建议

#### Scenario: 已标注豁免的行不被阻断
- **WHEN** release 时检出某行超过行长阈值，但该行已包含 `行长豁免：` 标注
- **THEN** release 正常放行，不因该行的长度被阻断
