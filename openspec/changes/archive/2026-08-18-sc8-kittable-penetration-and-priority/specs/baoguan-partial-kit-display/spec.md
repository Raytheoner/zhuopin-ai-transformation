## MODIFIED Requirements

### Requirement: 可齐套套数计算
SC8 SHALL 对每条成品保供预警行计算"可齐套套数" = **沿主料路径穿透到叶子件（采购件）层后**，
全部叶子件中 `floor(该叶子件可用现货 ÷ 单台用量)` 的最小值（无例外，全部叶子件均参与该计算，
不排除任何叶子件）。**单台用量为逐层累乘所得**（成品→半成品→…→叶子件），**不计损耗率**
（与本能力既有口径一致；毛需求计损耗，两者差异属既有不一致，本次原样保留）。

该计算依赖子件现货数据；现货数据不可用时（如 `SC8_NET_INVENTORY` 关闭）可齐套套数 MUST 为空
（不显示，不得以 0 或其他默认值冒充）。穿透路径上任一层单台用量非正（数据异常）时，
可齐套套数 MUST 为空，不得以 0 冒充。

**穿透的必要性**：半成品是自制件，不进真实库存 Stock API（该 API 只覆盖采购/外购叶子件），
其现货查询结果恒为无记录。若只扫描第一层直接子件，则「第一层子件即半成品」的成品
（真实数据中 F 开头这一批）可齐套套数恒为 0、瓶颈恒锁定在半成品、缺口恒等于整单订货量——
这两个字段对该批成品从未产出过有意义的数字。

#### Scenario: 第一层子件为半成品时穿透到采购件层
- **WHEN** 某成品的第一层直接子件本身是半成品（该子件自己还有 BOM 子件）
- **THEN** 系统 MUST 继续沿主料路径下钻，直至叶子件（采购件）层，用叶子件的真实现货与
  逐层累乘所得的单台用量计算可齐套套数；MUST NOT 把半成品当作可查现货的对象

#### Scenario: 第一层子件已是采购件时行为不变
- **WHEN** 某成品的第一层直接子件均已是叶子件（采购件）
- **THEN** 计算结果 MUST 与穿透改造前逐值完全相同（零漂移）

#### Scenario: 有现货数据时计算可齐套套数
- **WHEN** 某成品行的全部叶子件均有可用现货数据
- **THEN** 可齐套套数 = 全部叶子件 `floor(现货÷单台用量)` 中的最小值

#### Scenario: 无现货数据时不计算
- **WHEN** 现货数据未接入（如净额开关关闭）
- **THEN** 可齐套套数字段为空，不显示具体数值，不以 0 冒充

#### Scenario: 最紧子件决定可齐套数
- **WHEN** 某成品行多个叶子件的 `floor(现货÷单台用量)` 结果不同
- **THEN** 可齐套套数取其中最小值，并记录该叶子件为"可齐套瓶颈子件"

## ADDED Requirements

### Requirement: 需求日可齐套数量
SC8 SHALL 对每条成品保供预警行计算"需求日当日可齐套最大数量" = 与可齐套套数**同口径穿透到
叶子件层**，区别在可用量除现货外还叠加"计划出货日（需求日）前能到货的在途 PO 量"
（该叶子件的到货日 ≤ 出货日才计入）。

#### Scenario: 穿透后在途 PO 可被正确计入
- **WHEN** 某成品的第一层子件是半成品，其下叶子件有在途 PO 且到货日不晚于出货日
- **THEN** 该在途量 MUST 计入需求日可齐套数量（改造前因只看第一层、半成品查不到到货日，
  在途量永远无法计入）
