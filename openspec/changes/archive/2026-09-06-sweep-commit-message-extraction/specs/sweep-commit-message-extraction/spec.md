## ADDED Requirements

### Requirement: §二 批次提交信息提取不得丢弃单元格内任何文字
`工具-落库sweep.py::_extract_commit_message` SHALL 把 §二「建议 message」单元格视为**整格即提交信息**，除「整格被恰好一对反引号完全包裹」这一种情形外 MUST NOT 丢弃单元格内的任何字符。

单元格内出现的反引号在不满足完全包裹判据时 MUST 被当作普通字面量保留，MUST NOT 被解释为提取边界。

#### Scenario: 整格被一对反引号完全包裹
- **WHEN** 单元格 trim 后首尾均为反引号，且全格反引号总数恰好为 2
- **THEN** 剥去该层反引号，其内部文本 trim 后即为提交信息

#### Scenario: 整格不含反引号
- **WHEN** 单元格 trim 后不含任何反引号
- **THEN** 整格文本即为提交信息，与现行行为一致

#### Scenario: 反引号出现在正文中间（本次事故形态）
- **WHEN** 单元格形如 `docs(队列#354): 判据二 ` 加上一段反引号包裹的 `.env` 再加上后续正文
- **THEN** 提交信息为整格原文（含字面反引号），MUST NOT 被截断为 `.env`

#### Scenario: 首尾是反引号但内部另有反引号
- **WHEN** 单元格 trim 后首尾均为反引号，但全格反引号总数大于 2
- **THEN** 不剥离任何一层，整格原文即为提交信息

#### Scenario: 单元格内含多段行内代码
- **WHEN** 单元格含两段及以上反引号跨度且不满足完全包裹判据
- **THEN** 提交信息包含全部跨度及跨度之间、之外的所有文字

### Requirement: 提取结果为空时拒绝落库而非提交空信息
当 `_extract_commit_message` 的返回值 trim 后为空字符串时，sweep SHALL 拒绝提交该批次，保留该 §二 行的待处理状态，并在本轮日志中写明批次号与拒绝原因；MUST NOT 以空信息或任何自动编造的兜底信息执行 `git commit`。

#### Scenario: 空单元格
- **WHEN** 某待处理 §二 行的 message 单元格为空或仅含空白
- **THEN** 该批次本轮不被提交、状态保持待处理，日志出现该批次号与"提交信息为空"字样

#### Scenario: 仅含一对空反引号
- **WHEN** message 单元格 trim 后恰为一对反引号且其间无内容
- **THEN** 视同为空，按上一场景处理

#### Scenario: 空信息不阻断同轮其它批次
- **WHEN** 同一轮中存在一个 message 为空的批次与另一个 message 合法的批次
- **THEN** 合法批次照常落库，空信息批次单独留待处理，两者互不影响

### Requirement: 文件清单列的反引号语义不受本变更影响
`_resolve_batch_files` 对「文件清单」列反引号片段的逐段提取语义 SHALL 保持不变；本变更 MUST NOT 让两列共用同一套反引号解析实现。

#### Scenario: 文件清单仍按逐段提取
- **WHEN** 某批次的文件清单列含多个反引号包裹的路径片段
- **THEN** 每个片段各自被解析为一个待匹配路径，行为与本变更前逐字一致
