## Why（为什么做）

SC10 的权威排期是 2027-03，前置窗口 2027-01～02 **尚未到来**（⚪ 新增行，非逾期）。
按 Shao Peishen 2026-09-02 判据「不管规划时间表、能开尽开，唯一门槛是前置依赖」，
本包交付前置**不涉及**的那一层：BOM 展开、跨机型共用料识别、物料主数据对齐，
以及一张**数据完备度体检表**。

体检表是本包真正的价值所在：SC10 的三项产出全是「建议」，而建议需要口径与外部数据。
在 2027-01 前置窗口开启之前，最该被回答的问题不是"建议怎么算"，而是
**"我们离能算还差多少数据"** —— 这个问题现在就能用现有 ERP 主数据回答，
且它的答案直接决定 2027-01 那轮数据整备该整备什么。

## What Changes（改什么）

**新增能力**
- BOM 展开与共用料识别：复用底座 `kit_engine.explode_bom`，逐成品单独展开再合并，保住 `explode_bom` 合计口径丢掉的「需求来自哪个成品」。
- 物料主数据对齐：`MaterialRecord`（`lifecycle` 缺省 `UNKNOWN`、`unit_price` 可为 `None`）。
- **数据完备度体检** `BomReviewFacts.data_readiness`：BOM 内物料数／生命周期未知数／无价数／主数据缺失数。
- 外部行情源 `ExternalCatalogSource` Protocol ＋ `UnselectedCatalogSource` 占位实现（调用即抛）。
- **前置闸 `pending.py`** 三项：外部 API 选型／物料属性数据整备／**选用级别口径**。
- 审计留痕：`scenario="SC10"`、`action="bom_review_facts"`、L2、`review_status="待前置到位"`。

**明确不做**
- 不实现 BOM 评审建议、物料优先选用级别建议、优先选用与淘汰建议（三项全在闸后）。
- 不挑选任何一家第三方贸易网站 API（选型是姚祖怡 + IT 的前置，选型结果会改字段口径/配额/缓存策略）。
- 不改排期（2027-03 不动；立行与排期是两件事）、不改规划文档。

**补总表行属规划文档改动（全景路线图线），本泳道不擅改**，已登记待定夺。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

1. **本流程哪些判断是人脑默会经验？**
   - **物料优先选用级别的排序规则**：四个生命周期属性 ＋ 价格 ＋ 通用性（共用机型数）如何合成一个「优先级」，各因素谁压谁、边界在哪。当前只在采购经理脑子里。
   - **淘汰判据**：一个物料满足什么条件才建议从物料库淘汰（近 N 个月零用量？被更优料完全替代？原厂 Obsolete？三者的与/或关系与阈值均未定）。
   - **BOM 评审的合格线**：一份 BOM 里出现多少比例的 NRND/Obsolete 料算「评审不通过」。
   - **「就近/以量换价」的取舍**：规划预期写「以量换价、快速中标支持」，而合并采购与单机型最优往往冲突。
2. **由谁显性化？**
   - 数据型两项：**姚祖怡 + IT**（前置总表 §一 `SC10` 行，Owner 已明确）。
   - 知识型第三项：**采购经理 —— 🔴 待点名，双人制未成立**；前置总表无此行，本包据实拆出。
3. **用什么方法提取？**
   - 建议 **AI 起草·专家批改工作坊**（同 SC11 调拨原则口径的做法：先由本包的 `data_readiness` 体检表 ＋ 候选规则草案打底，再由姚祖怡/采购经理批改），配合 **历史案例反推**（调阅既往 BOM 评审记录）。
   - 知识型按「启动前 8 周」倒排 ⇒ 若 SC10 维持 2027-03 启动，该工作坊最迟 2027-01 开。**与数据型前置同窗口，须并行安排、不可串行**（这是本包拆出第三项前置的实际用途）。

## 验收与晋档条件（强制，四档口径）

- **本变更包交付后场景所处档位**：**档1（mock 验证）**，且只覆盖事实层。三项建议未交付 ⇒ **不构成场景上线**，不进覆盖轨计数。
- **晋下一档（档2 真实数据跑通）的条件**（逐条）：
  1. 真实 ERP 物料主数据只读接入（可先于 2027-01 窗口做，不依赖外部 API）；
  2. 原厂/第三方贸易网站 API 选型完成并签约（姚祖怡 + IT）；
  3. 我司价格库/物料属性数据整备完成，`lifecycle`/`unit_price`/`package` 可回填；
  4. **物料优先选用级别口径经采购经理签认**，backup 实名点名；
  5. 三项 `suggest_*` 的实现须另立 openspec 变更包并过 design 审，不得在本包内顺手补上。
- **价值指标**（三类模板取 2）：
  - **工时型**：单份 BOM 评审耗时（规划基线「~80% 供应商反馈、~5 天」→ 目标「~1 天（-70%）」）。
  - **质量型**：BOM 中 NRND/Obsolete 料的漏检数/百份 BOM。
  - 🔴 两项基线**均未采集**；第二项的采集前提是物料属性数据先存在。本包不代填。
- **LLM 判据黄金集**：本包**不含任何 LLM 运行时判断**（BOM 展开与主数据对齐是确定性计算）。
  建议层实现后是否引入 LLM 判断（如"参数等价的替代料识别"），待 design 审时判定；若引入，
  **无黄金集不晋档 3**。
