## ADDED Requirements

### Requirement: 拆件完成 SHALL 由机器代写闭环态
`工具-共享文档编辑锁.py` 在**队列系统**目标的 `release` 时，对每一条已确定配对到某封跟进信、且状态字段已 `[S:done]` 的 §一 入信行，SHALL 把该信在 README 的发送状态**自动改写为闭环态**，一次走完「转态 → 闭环 → 开闸」。

MUST NOT 要求持锁人手工去 README 改那一格；MUST NOT 新增任何需要人记住的声明语法——`[S:done]` 本身即「已回灌」这句声明。

写入的状态值 MUST 为「新前缀在前、原状态原样接在后」的追加形态，MUST NOT 覆盖原状态；MUST 写明依据的入信行编号与命中的配对通道；日期 MUST 取本机本地日期。

本 Requirement 取代前序变更包中的「拆件完成 SHALL 强制 README 转闭环态」（由拦人手改改为机器代写）。

#### Scenario: 已拆件即自动转闭环态
- **WHEN** §一 某入信行为 `[S:done]` 且确定配对到某封信，该信 README 状态为 `✅ 已推送 …`
- **THEN** release 通过，该信状态列以闭环前缀开头，含入信行编号与原状态原文

#### Scenario: 第九态同样被转为闭环态
- **WHEN** 该信当前为第九态 `📨 回件已到，待拆件 <UTC>`，而入信行已 `[S:done]`
- **THEN** 状态列被改写为闭环态

#### Scenario: 重跑幂等
- **WHEN** 对同一批入信行连续两次 acquire/release
- **THEN** 第二次 README 内容逐字未变

### Requirement: 桥二配对 SHALL 只走两条确定通道
入信行与跟进信的配对 MUST 仅按以下两条判定，MUST NOT 使用包含匹配、编辑距离或最相似匹配：

1. 归一化后的原信文件名 stem 逐字相等；
2. **第九态溯源回指** —— 该信当前为第九态，且其状态单元格中记录的入信归档文件名与本行逐字相同。

🔴 本校验 MUST NOT 采用「该收信人最新一封已发出的信」这条通道。桥二在每次 release 时扫全部历史入信行，**没有时间上下文**：一条陈年 `[S:done]` 入信行会被配到当天刚发出、尚未收到任何回复的信上并将其自动闭环。日粒度的日期护栏不足以挡住这一情形（实测存在同日发出与同日回件的真实反例）。

配对不上时 MUST NOT 写入、MUST NOT 拦截，也 MUST NOT 猜测。

#### Scenario: 纯文字回件靠溯源回指被纳入覆盖面
- **WHEN** 入信归档件主题段为 `文本反馈`、README 行无 `目标文件：` 标注，但该行为第九态且溯源写的正是这份归档件
- **THEN** 该信被自动转为闭环态，状态列写明命中的是回指通道

#### Scenario: 溯源写的是另一份归档件则不认
- **WHEN** 该行为第九态但溯源文件名与本入信行不同
- **THEN** 不配对、不写入，release 不因此被拦

#### Scenario: 陈年入信行不得闭环当天刚发出的信
- **WHEN** 某部门存在一条已 `[S:done]` 的历史文字入信行，且该部门当天新发出一封尚未收到回复的信
- **THEN** 新发出那封的状态列逐字未变

### Requirement: 写入 SHALL 走 README 自己的编辑锁，写不成 SHALL 拦
自动写入 MUST 经跟进信 README 目标自身的协议〇.7 编辑锁，MUST NOT 借队列那把锁裸写。「读锁判定 → 写锁」整段 MUST 在互斥保护下执行，写后 MUST 回读校验，并 MUST 同步该目标的 `lastknown` 基准（否则下一次 `acquire` 会把这次合法写入误报为绕锁改写）。

README 锁被他人占用、或写盘失败时 MUST NOT 静默：MUST 返回违规、拒绝 release（锁保持占用），并指名道姓说明是哪封信未转成、被谁占着。

#### Scenario: 锁被占用时拒绝且不改文件
- **WHEN** 另一身份正持有 README 编辑锁
- **THEN** release 返回非 0，README 逐字未变，输出含占用者身份与该信编号

#### Scenario: 合法写入不被后续 acquire 误报为绕锁
- **WHEN** 机器完成一次自动转态后，另一身份 acquire 该 README
- **THEN** 不出现绕锁改写告警

### Requirement: 逃生阀 SHALL 一次一用，且 SHALL 阻止机器代写
本校验 SHALL 保留逃生阀标记 `转态豁免：〈理由〉`。命中时机器 MUST NOT 写入、MUST NOT 拦截，且 MUST 打印留痕。

取材面 MUST 限于**本次持锁的 note** 与**本次持锁期间触碰过的队列行**，MUST NOT 匹配队列文件全文。

#### Scenario: 本次触碰行内写豁免则机器不代写
- **WHEN** 持锁期间修改的那一行内含 `转态豁免：…`
- **THEN** release 通过、输出含「转态豁免」字样，README 状态列逐字未变

#### Scenario: 陈年豁免字样不得叫停机器
- **WHEN** `转态豁免：` 只出现在本次未触碰的历史行中
- **THEN** 机器照常自动转态

### Requirement: 判出来却定位不到行 SHALL 拦
若某封信被判定为「已拆件但未转闭环」，却无法在 README 表格中定位到对应行，MUST 返回违规、MUST NOT 静默跳过——两处解析共用同一套表头判定，走到这一步说明另有异常（如编号列重复）。

#### Scenario: 定位不到即拦
- **WHEN** 判定结果中的信编号在 README 表格中找不到对应行
- **THEN** release 返回非 0，输出含该信编号
