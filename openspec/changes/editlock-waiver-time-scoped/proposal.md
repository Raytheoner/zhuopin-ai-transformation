> 🔴 **本变更包按派单件 `派单件-【CC】登记豁免时间维收窄与孤儿升格-2026-09-07.md` 执行：propose ＋ design 出件即停，未实现任何代码。** 命中 CLAUDE.md §5 openspec 门槛第③条（改变既有模块对外语义：同一接口、同一输入，`release` 的返回结果由**放行**变为**拒绝**——方向与 `editlock-aibot-registration-completeness-exemption` 恰好相反）。

## Why

**病灶**（队列 §一 `#416` ⑶，`OP-0904-E` 于 2026-09-04 只读核实，至今未修）：`release` 校验⑹「登记完整性」的逃生阀判据是**裸子串** `REGISTRATION_WAIVER_MARKER in s`，取材面 ＝ 本次 `acquire` 的 note ＋ **本次持锁期间被触碰过的队列行整行文本**。于是：

1. **一句泛豁免放行全部脏文件**。写一句「登记豁免：他线脏文件由其作者线自登」，`uncovered` 里**全部**未登记脏文件当场放行——不论它们是谁的、有几个、是不是真的会有人去登。
2. **躺在队列行里的旧豁免会被重新激活**。真实残留：`#382` 的**任务列**里至今躺着一句
   `登记豁免：`.claude/settings.local.json`（并发 session 遗留的本机个人配置，不属本线改动、不入库，留待其属主处置）`。
   只要某次持锁碰了 `#382` 那一行（改状态、追一句回写都算），这句 2026-09 之前写下的豁免就成为**本次**的豁免来源，把当刻工作区里**任何**未登记脏文件一并放行。
3. **两种放行在标准输出上长得完全一样**——`✓ 检测到登记豁免声明，已放行 N 个未登记脏文件：…`，看不出被放行的是不是豁免作者真正想放行的那些。

🔑 **判据（`#416` 行内原话）**：**「一次一用」的逃生阀必须用时间维判据，不能用空间维判据。** 现实现取的是空间维——「这段文本在不在我这次碰过的范围里」；而只要那段文本**落了盘**，它就会被后来的、与它无关的持锁窗口反复取到。

**今日实证（2026-09-07）**：16:21 一轮 sweep 报 **21 个孤儿脏文件、来自 ≥5 个会话、最老 18 小时，无一自登**。逐条回看 release 记录，每一次都是以「他线脏文件由其作者线自登」这类泛豁免放行的——**那句话在每一次 release 上都成立，也在每一次之后都没有兑现**。环境总线当日人工代登 15 件（`B-0907_W19`）。

**止血已做（人守，2026-09-07 生效）**：`.claude/rules/队列与落库.md` 新增「`登记豁免：` 止血口径」——只认逐文件点名豁免（路径＋作者＋到期），禁泛豁免。**本变更包 ＝ 把这条人守变成机器守，并补上孤儿升格通路。**

**为什么止血句不够、必须机器守**：这条纪律的违反者是**每一个正在赶收工的会话**，而违反的收益（马上能 release）当场兑现、代价（明天多 21 个孤儿）落在别人身上。CLAUDE.md §5「规则退休制」判据在这里已经满足——它一天之内被 ≥5 个会话违反。

## What Changes

（拟议，**本次不实现**；D1–D4 编号与派单件 §三 一致）

- **D1 取材面收窄到时间维**：⑹ 的豁免只从**本持锁窗口的 `acquire` note** 取。队列行文本、上一次的 note、任何落盘文本一律不再构成豁免来源。
  - ⚠️ 只收窄 ⑹ 这一项的取材面。同一个 `waiver_sources` 列表还喂着 `转态豁免：`（`_auto_sync_followup_reply_state`）与 `opener豁免：`（`_opener_guard_violations`）——**那两项的取材面本次一个字不动**。
- **D2 豁免解析为结构化条目**：`登记豁免：<路径>[；<路径>…]（作者 <OP 号>，到期 MM-DD）`。**只放行被点名的文件**，其余脏文件照常阻断。解析失败 ＝ 无豁免（fail-closed）。
- **D3 泛豁免拒绝**：note 里有 `登记豁免：` 却点不出任何有效路径 ⇒ `release` 拒绝，并打印**两条**出路（登 §二 批次／逐文件点名），不设第三条。
- **D4 孤儿升格**：`工具-落库sweep.py` 的孤儿告警旁增一条通路——孤儿存续 ≥6 小时 ⇒ 自动 `append-row` 一行 §四（当日同文件去重），列出文件、首见时间与 (a) 代登 / (b) 丢弃两个选项，交人一字母。**不自动声明入库、不自动 commit 任何未声明文件。**

**BREAKING**：`release` 在「写了泛豁免 ＋ 存在未登记脏文件」时，返回由**放行**变为**拒绝**；在「豁免只写在本次触碰的队列行里」时，同样由放行变为拒绝。这正是本变更的目的，但它确实改变了既有对外行为，故走本流程。

**受影响的既有 spec 断言**：`editlock-registration-completeness` 的 Requirement「逃生阀——未登记而放行必须写下理由」及其 Scenario「本次触碰的队列行中声明豁免，放行」——后者本次**被反转**，以 MODIFIED delta 如实写出，不静默改掉。

## 本次退休哪一个既有守卫；若不能退，写明为何不能

**不退休任何既有守卫，理由是本次改动的方向与 one-in-one-out 想防的事情相同、不是相反。**

协议〇.9 措施 B 要防的是「规则只增不减、守卫代码只涨不落」。本次**没有新增任何一道守卫**——⑹ 仍然是那一道，判定对象、触发时点、拒绝文案骨架全不变；变的是它的**逃生阀口径由宽收窄**。⇒ 本包让门禁的可绕过面**净减少**，与该措施同向。强行退一道不相干的守卫来配平，等于用一次真实的精度提升去换一次记账上的好看。

**候选过一遍、登记在此，避免「止了血就没人再想」**：

- **候选一：退休 `ORPHAN_ALERT_THRESHOLD_HOURS = 3` 的企微推送告警**（D4 落地后 6 小时会有 §四 行，3 小时那条推送似可退）。**不取**——两者受众不同：企微推送打给**在场的人**（还来得及自己登），§四 行打给**总线的排期**（人已经不在场了）。退掉前者等于把「还来得及自救」的窗口一并退掉。
- **候选二：退休 `dirty_at_acquire` 快照**（D1 之后归因分组仍在用它）。**不取**——归因分组是拒绝文案的可用性来源，与豁免取材面无关，退它属于另一件事。

## 伴生文件的 .gitignore 覆盖

**本变更不新增任何此前不存在的文件名形态。**

- D1–D3 只改判据，不落盘任何东西；豁免理由沿用既有去处（`release` 的标准输出 ＋ 锁文件 `history`，后者本就随 `*.editlock` 忽略规则处置）。
- D4 的「当日去重」状态**复用既有** `reports/sweep-orphan-state.json`（在既有条目上加一个字段），**不新建状态文件**。
- **核实方式（实测，非推断）**：
  ```
  $ git check-ignore -v reports/sweep-orphan-state.json
  .gitignore:41:**/reports/	reports/sweep-orphan-state.json
  exit=0
  ```
  ⇒ 已被 `.gitignore:41` 的 `**/reports/` 覆盖。
- D4 唯一的落盘产物是**队列机制环境文件里的一行 §四**——它是既有文件、既有形态，由既有的 `_commit_uncovered_queue_changes`（队列 #398 ⓘ2）按既有口径落库。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

1. **本流程哪些判断是人脑默会经验？**
   - 「这句豁免是**这一次**写的，还是躺在那儿被顺手捡到的」——人读得出（看行的上下文、看日期），机器此前只会 `in`。这是本次要显性化的**主判据**。
   - 「这句豁免点名了谁」——人读得出「他线脏文件由其作者线自登」等于没点名，机器此前一视同仁。**阈值**＝至少一个有效路径；**例外**＝取数失败时的 fail-closed 分支另有口径。
   - 「多久算没人管」——`≥6 小时` 这个尺度此前只在人的直觉里（今日 21 个孤儿最老 18 小时才被发现）。
2. **由谁显性化？** 持有人 ＝ 环境保障线（本 session `OP-0907-AM`）；backup ＝ Cowork 环境总线 `OP-0906-W`；仲裁人 ＝ Shao Peishen。
3. **用什么方法提取？** **历史案例反推**——`#416` 行内 `OP-0904-E` 的只读核实（判据是裸子串、取材面含整行文本）＋ 2026-09-07 16:21 sweep 的 21 个孤儿实测 ＋ `#382` 任务列那句真实残留（它同时是 D1 的单测用例）。apply 阶段补**受控复现**（真 git 仓库 ＋ 真 CLI，见 tasks §2）。
