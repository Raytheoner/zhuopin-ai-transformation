## 必须证明的业务入口

| 入口/机制 | 验收判据 | 当前证据口径 |
|---|---|---|
| 开启泳道看护 | 从自然语言技能入口选择获准业务任务，实际启动 Codex 构建，遵守依赖、阶段批准和并发限制 | 候选存在 guardian；主仓技能仍写未迁移；真实新链未完成 |
| 看看泳道 | 返回当前真实进展、停点、失败原因和下一动作，能定位任务与证据 | 待逐入口实测，不能以源码存在判通过 |
| 机器人监听 | 已注册服务/事件消费者能接收信号，单消费者、暂停/恢复与故障可定位 | 历史规定范围证据需重新核对本次版本和实际启停 |
| 跟进信回灌 | 脱敏回件从接收、匹配到自动归档、拆件、入队形成可追溯链；重复回件不重复消费 | 既有确定性接缝测试不能替代新引擎实际回件链 |
| 值周计划 | 从现时队列形成可执行计划，任务有主、有截止、有派发/承接，不调用旧引擎 | 待查适配与实测证据 |
| 回 LAN 收口 | off/unknown LAN 留步；回 LAN 后依正式检查、具体授权及原收口纪律承接实际对象 | 本次不自动取得生产部署/ff/外发授权 |

单任务实施→CI→独立 review→release-prep只是以上闭环的一部分，不得单独标为完整 MVP 通过。旧消费者验收、mock/脱敏组件测试、现时本机/服务证据和最终候选原生闭环须分别标注。
