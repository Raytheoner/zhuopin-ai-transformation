## Why

### 病灶：三个读取实现，三种不同的盲区，且盲区都不产生任何信号

`#133` 已把成因钉死，原文的判据比修法更值得复述：

> 🔑 **「逐格实读」这四个字本身不构成证据，要问的是「读的是哪一层」** —— 同族＝ CLAUDE.md §5「工具静默回退」与 §一 #416 那条「答案 60 毫秒就到了、只是打在没人看的 WARN 里」，**共同点是错误不产生任何信号**。

本次 propose 期把「三个实现各自的盲区」实测清楚了（手段、命令与全部数字见 `tasks.md` §1，下同）：

| 实现 | 位置 | 覆盖 | 🔴 实测盲区 |
|---|---|---|---|
| `read_checkboxes()` | `0-学习与工具/md转Word工具/md2word.py:85` | `w14:checkbox` 控件（`doc.element.body` 内） | **裸勾选字符一个都看不见**——对 `质量部#11` 回件（专员真的勾了 **22** 个 ☑）返回 **「0 个控件、勾 0」**；返回值是 `list`，调用方 `len()==0` 与"一条都没勾"**在类型上无法区分** |
| `analyze_docx()` | `5-平台底座/wecom-aibot-service/aibot_service/reply_form_detection.py`（`#446` 产出） | 控件 ＋ 裸字符 ＋ 高亮 ＋ 批注 ＋ 修订，五类一次性 | 只读 `word/document.xml`（页眉/页脚/脚注不覆盖）；**装在 aibot 服务包里，`4-数字员工/` 各场景 import 不到**——这正是重复实现长期并存的结构性原因 |
| `_read_docx()` | `4-数字员工/质量部/QD-A-8D不良分析/qda_prefill/doc_reader.py:93` | `python-docx` 的 `doc.paragraphs` | **表格与 `w:sdt` 内容整块丢失且不报错**：同一份 08-26 回件 XML 全文 5216 字、它只拿到 3872 字（丢 **26%**）；`质量部#11` 全文 1897 字、它只拿到 543 字（丢 **71%**），☑ 计数由 22 变 3 |

### 「python-docx 恒空串」这条路径今天仍然会静默给出错误答案

`#133` 的事实链 ⑴ 说「`docx.Document(...).tables[1]` 逐格 `cell.text` 全为空串」。**本次已逐字复现，并把它读得更准**（`tasks.md` 1.3）：

- `tables[1]` 共 **24 格**，其中 **9 格**为空串（38%）；同表 XML 真相 ＝ **9 个 `w14:checkbox` 控件，勾 3 个（☒3/☐6）**。
- ⇒ **那 9 个空串格，一格不多一格不少，正是那 9 个复选框格。** `#133` 原文的「全为空串」指的是**勾选列**全空，其余 15 格有字——如实写明这一处更准的措辞，不改 `#133` 原文（历史记录不追改）。

🔴 **关键在于这个空串不是错误、是合法返回值**：`python-docx` 的 `Paragraph.text` 只拼 `w:p` 的**直接** `w:r` 子节点，嵌在 `w:sdt/w:sdtContent` 里的 run 被整段跳过，于是控件格返回 `""`、程序继续往下跑。调用方拿到的是「9 个空字符串」，与「9 个真的没填的格」**逐字节相同**。⇒ 这不可能靠"下次记得读对层"防住，只能靠**让这两种情况在类型上不再相同**。

### 现网语料实测：13/68 份会被读成假阴性

对 `7-外部文档/` 全部 **68 份 docx**（含各部门专员真实回件）跑一次只读对照——「naive `python-docx` 文本视角」对「XML 直读视角」：

- **19 份**携带勾选形态（控件或裸字符）；
- 其中 **13 份**在 naive 视角下 **勾选数为 0，而 XML 里确实有勾**——即**今天再走一遍 `#133` 那条路，13 份回件会被读成「一条都没勾」**；
- 另有 **1 份**（`用友OpenAPI完整文档/创建盘点差异单.docx`）**根本不是合法 zip**（`BadZipFile`）⇒ 「读不了」这条路径在现网语料里是**真实存在**的，不是构造出来的假设。

### 已连栽三次，rule-of-three 早已触发，且代价是不实指摘

`#481` 行原文：**已连栽三次**——`采购部#16`／`#17`（勾选找错地方）、`#18`（假阴性）、Cowork 侧漏段落内勾。🔴 **代价是对专员做出不实指摘**（说人家没勾、其实勾了）；`采购部#19` 原句「我们把 Word 文件逐格读过，9 个格子确实都没有内容」已发出、撤不回；他 08-28 回件原话「**你是没有看到吗？**」。

⚠️ **本包**不**主张"现在很紧急"**——`#481` 行明写「更正信已于 2026-08-28 随 `采购部#20` 发出，**本项不在出血** ⇒ 可以等」，本次是趁 WIP 有余量顺手推进 design，**非抢进度**。

### 为什么必须机守（元判据复用，不新造）

Shao Peishen 2026-09-02 的元判据：**「如果能做，就不要指派手工——会带入失误。」**

- **有咽喉**：`#446` 已把「每次拆件都必须跑一遍形态探测」这一步机器化，挂载模式是现成的；缺的只是**这一步调用的那个函数只有一份、且它不会把"读不到"说成"没有"**。
- **人守已实证失效三次**，且第三次（`#446` 之后的 Cowork 漏段落内勾）发生在已经有一份好实现之后 ⇒ **"有一个正确工具"不等于"人会去用那个正确工具"**，只有"错的那几份不存在了"才管用。

### 本次退休哪一个既有守卫（协议〇.9 措施 B，机制类变更包强制回答）

🔴 **本包确有一条可退的实现，且这是它区别于"规则只增不减"的地方**：

- **`md2word.read_checkboxes()`（`md2word.py:85`）拟退休**——它**没有任何生产调用点**（全仓 grep：唯二引用在自己的 `test_md2word.py:99/116`，另两处是 `reply_form_detection.py` 的注释指路）。它今天的实际作用是「**一个看起来可以直接用、实际只覆盖三分之一形态的入口**」，`质量部#11` 上它给出的「0 个控件、勾 0」就是这类入口的典型危害。**具体退法（删除 / 改薄壳 / 只加警示）是 design 决策点⑤，本包不代拍板。**
- **`reply_form_detection.detect_checkboxes()` 等五个探测器拟改为委托**——判据正本移入统一件，`aibot_service` 侧只保留薄封装。⚠️ **如实标注：这是"搬家＋合并"，不是"删掉一段代码"的退休**，不宜包装成 one-in-one-out 已履行。
- **`qda_prefill/doc_reader._read_docx()` 的 `paragraphs`-only 取文拟退休**——它丢 26%–71% 正文且不报错，是三份实现里唯一**连正文都读不全**的一份。
- **不能退的**：`check_reply_form_signals.py` CLI（它是拆件班次的执行位置，`#446` 的价值一半在这里）；`#446` 章程里"每次都跑一遍"这条流程约束（本包只换它调用的引擎，不动这条约束）。

### 伴生文件的 `.gitignore` 覆盖（强制段）

**不适用——本变更不新增任何自动生成文件。** 统一件是**纯只读解析器**：不写锁、不写快照、不写缓存、不写日志、不做重命名退路。单测所需的 docx 夹具由 `md2word` 在 `pytest` 的 `tmp_path` 内当场生成（沿用 `test_md2word.py::_build` 既有做法），落在 pytest 临时目录、不落仓库。
**核实方式（apply 期须实跑，不是推断）**：`tasks.md` 4.4 要求跑完全部单测后用 `git status --porcelain` 确认工作区不出现任何新文件名形态；若 design 决策点④ 选了"落一份现网语料回归基线文件"，则该基线文件须当场用 `git check-ignore -v` 判定并把**实际输出**写进 tasks，不得写"应该被覆盖"。

## What Changes

- **① 新增统一 docx 读取入口**（落点由 design 决策点① 拍板，起草方推荐 `zhuopin_platform/shared_tools/doc_parser/`）：一次调用覆盖 `#481` 点名的三种形态——**勾选控件**（`w14:checkbox`）、**段落内勾**（正文裸 ☐/☑/☒ 字符）、**表格格内勾**（同上两种落在 `w:tc` 内，并带同行其余单元格上下文）。判据与实现以 `#446` 的 `reply_form_detection` 为底本迁移，**不重写第二份**。
- **② 「读不到」与「没有勾」在类型上不可混同**（本包的核心，对应 `#481` 期望产出 ②）：读取结果不再以裸 `list`／裸 `int` 表达。至少三种状态各有其表示——`读取失败`（非法 zip／缺 `word/document.xml`）、`无勾选载体`（这份 docx 里根本没有可勾的东西）、`有 N 个载体、勾了 M 个`。**调用方不可能把前两者写成 `if not result:` 而得到"一条都没勾"。**
- **③ 交叉校验：高层文本视图漏读即报**——统一件在解析时同时算出「XML 视图的载体数」与「`python-docx` 高层文本视图能看见的勾选字符数」，两者不一致即在结果里挂一条**必须被处理的诊断**（`text_view_incomplete`）。这是把 `#133` 那条"错误不产生任何信号"的病根直接反转成信号。
- **④ 反例单测（`#481` 期望产出 ②）**：以 `md2word` 当场生成的真实含控件 docx 为夹具，断言 `python-docx` 的 `cell.text` 路径**确实返回空串**，且统一件对同一文件**必须**判为"有载体、勾了 M 个"而非"零勾"；再加一条**非恒真自证**——把统一件的控件探测器换成返回空的桩，同一断言必须失败。
- **⑤ 迁移既有调用点**（`#481` 期望产出 ③，**apply 期任务，本次不做**）：`reply_form_detection` 五个探测器改委托、`check_reply_form_signals.py` CLI 行为不变、`qda_prefill/doc_reader._read_docx()` 改走统一件取文、`md2word.read_checkboxes()` 按决策点⑤ 处置。
- **不改动**：`#446` 定的拆件流程约束与 CLI 的输出格式（拆件班次看到的东西不变）；`sc4_contract/text_source.py`（它**刻意拒收** `.docx` 并注明"等平台底座 doc_parser 落地后接入"——本包正是那个 doc_parser，但**接入 SC4 不在本包范围**，另立行）；`qd_b_gate/parser.py`（实测为 **xlsx/openpyxl** 解析，与 docx 无关，不在触碰区）。

## Capabilities

### New Capabilities

- `unified-docx-checkbox-reader`：单一 docx 勾选读取入口，三形态一次覆盖；结果类型使 `读取失败`／`无载体`／`有载体且勾了 M 个` 三态互不可混；高层文本视图漏读时挂出诊断。

### Modified Capabilities

- `md2word.read_checkboxes()` 的对外语义：由「返回控件列表（空列表既表示无控件、也被调用方读成没勾）」改为 **design 决策点⑤ 拍板的形态**（删除／薄壳委托／保留并加警示三选一）。**BREAKING**，但按 §Impact 的消费者核实，**现网无生产调用点**。
- `reply_form_detection.detect_checkboxes()` 等五个探测器：判据正本迁出，本地改为委托。对 `check_reply_form_signals.py` 的输出**不构成 BREAKING**（CLI 打印格式不变，见 §Impact）。
- `qda_prefill/doc_reader._read_docx()` 的取文完整度：由「只 `doc.paragraphs`（实测丢 26%–71%）」改为覆盖表格与 `w:sdt` 内容。**这是行为变化，且会改变 QD-A 的 D1–D8 分段结果**——apply 期须对 QD-A 既有测试与黄金基准做回归，见 `tasks.md` 3.3。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

1. **本流程哪些判断是人脑默会经验？**
   - **「这份回件里，对方到底勾了没有」**——此前完全靠拆件的人挑一个库、写一段代码、看一眼结果。`#133`／`#446` 合计四次实证该判断会失败，且失败的方向**恒定偏向"对方没答"**（漏读永远表现为少，不会表现为多）⇒ 这不是随机误差，是**有方向的系统性偏差**，而这个方向恰好指向"指摘对方"。
   - **「什么算读到了」**——「逐格实读过」这句话此前被当作证据本身。`#133` 已把它显性化为一条判据（「要问的是读的是哪一层」），但**这条判据今天只存在于 `#133` 的行文里，没有任何一处会在你读错的那一刻告诉你**。本包把它显性化进**返回值的类型**与**诊断字段**（③），不要求任何人事先记住。
   - **「裸 ☒ 算不算勾了」**——`#446` 刻意判定"裸字符没有 checked 这个布尔状态"，但现网语料里 `质量部#11`（22 个 ☑）／`#12`（7 个 ☑）**就是用裸字符作答的真实回件**。这条尺度目前只在 `reply_form_detection` 的 docstring 里，**从未由 Shao Peishen 拍过板** ⇒ 本包把它抬为 design 决策点②，请他定。
2. **由谁显性化？** 决策人 **Shao Peishen**（design 审拍板五个决策点，本包止步于起草、不代拍板）；起草方 ＝ 本 session（`OP-0907-H`【CC】）；backup ＝ 下一位领取 `#481` 的 session 可凭本包与 `design.md` 独立复核——**全部实测脚本与命令写在 `tasks.md` §1，任何人可现取重跑比对**，不依赖本 session 的口述。
3. **用什么方法提取？** **历史真实案例反推**（`#133` 四次真实误读，非构造假设）＋ **现网全量只读取证**（68 份 docx 语料，见 §Why 与 `tasks.md` §1）。不涉及 LLM 判断，纯 XML 结构规则。
   - 🔴 **propose 期已完成的取证（实跑，不是推断）**：① 68 份语料对照跑，19 份携带勾选形态、**13 份在 naive 视角下假阴性**、1 份非合法 zip；② `#133` 的 `tables[1]` 全空串已逐字复现（24 格/9 空，对应 9 控件/勾 3）；③ 三份既有实现在同两份真实回件上的读数差异已逐条录得。
   - ⚠️ **边界如实写明**：该取证只覆盖**当前 `7-外部文档/` 目录下的 68 份 docx**，不覆盖已被删除/未归档的回件，更不覆盖**未来**会收到的形态（如别的 Office 软件另存出的 `w:checkBox` 旧式表单域——见 §已知残余风险 2）。「今天 13/68」只能支持「这条路径今天仍然在错」，**不能**支持「这就是全部的错法」。

## 验收与晋档条件（强制，四档口径）

- **本变更包交付后场景所处档位**：跨场景共享工具，非独立业务场景，套用最接近的描述 ＝ **档2 真实数据跑通**（判据以现网 68 份真实回件语料实测过，非 mock 构造；但尚未在一次真实拆件里被依赖着做出过对外结论）。
  - ⚠️ **本包 propose 交付后仍在档1**——design 审未过、代码未写；上面说的档2 是**apply 完成后**的目标档位。
- **晋下一档（档3 内部服务）的条件**：
  1. 三份既有实现的调用点全部迁完，且**旧入口在仓库里不再是可调用的诱饵**（决策点⑤ 落地）。
  2. 真实发生一次「对方其实勾了、旧路径会读成没勾」的回件，由统一件读对，且拆件回执里**引用的是统一件的输出**。
  3. 🔴 **零假阴性不得读成"规则已生效"**——若交付后长期无差异命中，正确表述是「**未被检验**」。判据同 `editlock-write-side-date-guard` 与 `editlock-credential-shape-guard` 已确立的口径，本项目已有同形教训（根 `CLAUDE.md` §四 #58／#122）。
- **价值指标**（**风险型**）：**「把对方答过的读成没答」这一失效的可能路径数**——基线 ＝ 三条独立读取路径，其中两条实测会给出假阴性（`md2word` 对裸字符形态、`qda_prefill` 对表格/控件形态），且**假阴性与真阴性在返回值上不可区分**；目标 ＝ 路径收敛为一条，且该条在返回值类型上使二者不可混同。
  - 辅助（**质量型**）：现网 68 份语料回归——统一件在其上的读数与 XML 直读逐份一致，差异为 0 份（apply 期须实跑并把份数写进 tasks，不得引用本 propose 的数字）。
- **LLM 判据黄金集**：不适用（纯 XML 结构规则，无 LLM 运行时判断）。

## 已知残余风险（如实写明，不粉饰）

1. **统一件治不了"根本没去读"**——`#446` 的模块 docstring 已把这条说透：「根因不是工具缺失……根因是**读形态这一步在拆件流程里压根没有必然会被执行的位置**」。本包治的是**另一半**：这一步被执行时，选到的可能是错层的那个实现。⇒ 交付后的措辞只能是「**凡走统一件读的，读不到会说读不到**」，**不得**写成「此后不会再误判专员没勾」。
2. **形态覆盖仍是枚举，不是穷尽**——本包覆盖 `w14:checkbox` ＋ 裸 ☐/☑/☒ 两族。**旧式表单域 `w:fldChar`/`w:checkBox`（Word 97-2003 表单、部分 WPS 另存路径）不在覆盖内**，现网 68 份语料里今天为 0 命中，但这只支持"今天不漏"。⇒ 新形态出现时须回到本包补一族，**本包的价值之一正是"补一处、三个调用点同时受益"，但这也意味着漏一处会同时漏三边**。
3. **决策点② 若选"给裸字符 checked 语义"，会引入一个方向相反的新错**——正文里把 ☒/☑ 当装饰或图例印刷（如"☒＝不适用"这类说明行）会被读成"对方勾了"。
   🔴 **如实标注证据强度：这一条今天是理论风险，不是实测风险。** propose 期已把现网语料里全部裸字符逐段打出上下文核对（`tasks.md` 1.4），结果是两种形态、**均无图例/装饰**：`质量部#11` 的 22 个裸 ☑ **每一个后面都紧跟真实作答文字**（「☑ 认可」「☑ (b) 改为两档。」「☑ 按 V3.2（扣分＋红线）」等），**语义毫不含糊就是勾了**；`采购部` 07-28 回件的 8 个裸 ☐ 则是**各自独占一段、段内只有一个 ☐**，即一份**未填的作答格**（全未勾，此时"读成 0 勾"是**正确**答案）。⇒ 现网证据**偏向支持**给语义，反例尚未出现——但"尚未出现"不等于"不会出现"，且一旦出现，错误方向就反转为"诬赖对方勾了他没勾的选项"。两个选项的错误方向相反，**这正是决策点② 无默认的原因**。
4. **`qda_prefill` 的取文变化会改结果**——它今天丢 26%–71% 的正文；补全之后 D1–D8 分段的输入变了，**既有黄金基准很可能漂移**。⚠️ 漂移**不等于变坏**（原本就少读了七成），但 apply 期**必须逐条人工确认新基准，不得直接覆盖旧基准了事**。
5. **落点若选平台底座，`md2word` 会多一条跨仓依赖**——`md2word.py` 是 `0-学习与工具/` 下的独立 CLI（`依赖：pip install python-docx`），今天不 import 任何平台包。决策点⑤ 若选"薄壳委托"，等于要求跑 md2word 的环境也装 `zhuopin_platform`。⚠️ **`wecom-aibot-service` 无此问题**（实测 `pyproject.toml` 已声明 `dependencies = ["zhuopin_platform[aibot]", ...]`），且 `zhuopin_platform` **不依赖 python-docx**、统一件按 `#446` 的做法是**纯 stdlib（`zipfile`＋`ElementTree`）** ⇒ 落进平台底座**不新增任何第三方依赖**。这条风险只对 `md2word` 一方成立。
