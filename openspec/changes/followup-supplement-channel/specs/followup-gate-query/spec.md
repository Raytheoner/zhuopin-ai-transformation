## ADDED Requirements

### Requirement: README 表格定位 SHALL 显式指名，MUST NOT 依赖文档顺序

跟进信 README 的表格解析 SHALL 按**所属章节标题**定位目标表；MUST NOT 以「文件里第一个以 `|` 开头且含『发送状态』的行」作为表头判据。

本要求 SHALL 同时约束本仓库两份独立的 README 解析实现（`aibot_service.readme_table` 与 `工具-共享文档编辑锁.py::_followup_readme_rows`）。只改其中一份即视为未满足——**未改的那一份会让人以为整件事已经修完了。**

章节标题匹配不到目标表时 MUST 报错中止，MUST NOT 回退到任何「取第一个表」的行为。

**依据（实测）**：改判前两份实现同时依赖一条从未被声明的判据——补件表恰好排在主表后面。把补件表挪到主表之前（一次纯排版编辑），两份会同时把补件表读成主表，**且都不报错**。

#### Scenario: 按章节标题定位主表
- **WHEN** 消费者请求《现有跟进信清单》表
- **THEN** 返回该章节标题下的表，无论它在文件中排第几

#### Scenario: 补件表排在主表之前不影响主表消费者
- **WHEN** README 中《补件登记》表被移动到《现有跟进信清单》表之前，随后运行闸查询／入信配对桥／起草缺口检测／编辑锁串行原则闸
- **THEN** 四者读到的仍是主表，输出与移动前逐字相同

#### Scenario: 章节标题缺失时 fail-loud
- **WHEN** 目标章节标题在 README 中不存在
- **THEN** 解析报错中止，MUST NOT 返回另一张表的数据、MUST NOT 返回空列表当作「没有数据」

### Requirement: 顺序无关性 SHALL 有反例测试与写侧守卫

「两表次序不影响任何判定」SHALL 由一条**反例测试**锁定：构造补件表在前的文本，断言主表消费者的输出不变、或在章节标题缺失时 fail-loud。

该测试 SHALL 经**变异验证**——把改判前的原实现喂给它 MUST 变红；不能对原实现变红的测试是空转，不计入本要求的满足。

跟进信 README 的编辑锁 `release` 校验 SHALL 断言两张表的章节标题均存在。

#### Scenario: 反例测试对原实现变红
- **WHEN** 把「取第一个含发送状态的表」的原实现代入反例测试
- **THEN** 测试失败

#### Scenario: 反例测试对新实现变绿
- **WHEN** 把按章节标题定位的新实现代入同一测试
- **THEN** 测试通过

#### Scenario: 章节标题被删则拒绝 release
- **WHEN** 持锁窗口内某张表的章节标题被删除或改名，release 被调用
- **THEN** release 被拒绝并指明缺失的标题，锁保持占用
