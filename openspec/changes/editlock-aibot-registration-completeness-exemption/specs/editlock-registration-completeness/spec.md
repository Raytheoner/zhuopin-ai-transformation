## ADDED Requirements

### Requirement: 自行提交自身改动的持锁者不适用登记完整性校验
release 时的登记完整性校验（"全部脏文件须被某个待处理 §二 批次覆盖"）SHALL NOT 适用于**自行提交并推送自身改动**的自动化持锁者——该校验的前提是"持锁者的改动要靠他人（落库 sweep）提交"，对自提交者不成立。企微机器人 SHALL 与落库 sweep 一样属于该类：它经自身的队列 git 同步路径 commit 并 push 自己追加的行，失败时另有降级与补录路径。

本豁免 SHALL 仅作用于登记完整性这一项校验，MUST NOT 削弱该持锁者仍需通过的其余 release 校验（列数、关键格、组内编号重复、已归档编号重复、称呼判据等）。本豁免 MUST NOT 覆盖"工作区状态取数失败"那条 fail-closed 分支——校验**无法执行**与校验**不适用**是两回事。

#### Scenario: 机器人释放锁时不因他人的脏文件被拒
- **WHEN** 持锁者为企微机器人，工作区存在不属于任何待处理 §二 批次的脏文件（含由其它并发会话产生、与机器人本次动作无关的文件）
- **THEN** release 不因登记完整性被拒绝，锁正常释放

#### Scenario: 人类会话仍受登记完整性校验约束
- **WHEN** 持锁者为普通人类会话，工作区存在不属于任何待处理 §二 批次的脏文件，且未写登记豁免标记
- **THEN** release 仍因登记完整性被拒绝

#### Scenario: 机器人违反其它校验时仍被拒绝
- **WHEN** 持锁者为企微机器人，其新增行违反列数、关键格或编号重复等任一其它校验
- **THEN** release 仍被拒绝——豁免只作用于登记完整性这一项

#### Scenario: 取数失败时对机器人同样 fail-closed
- **WHEN** 持锁者为企微机器人，但工作区脏文件状态取数失败（git 不可用/超时），且无登记豁免声明
- **THEN** release 仍被拒绝，不静默放行
