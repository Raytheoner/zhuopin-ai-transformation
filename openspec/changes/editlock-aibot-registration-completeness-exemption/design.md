## 取证：受控复现（不是相关性推断）

派单件对 ⑶ 的要求是「**先用 ⑵ 修好的 stderr 复核一次真因再动手**」。⑵ 的落点在另一 CC 会话的触碰区内（`connection.py` ＋ 机器人调 release 处），本会话拿不到那条 stderr；改用**更强的一种验证**——直接受控复现。

**复现方法**：玩具 git 仓库，`who=企微机器人` acquire → 只追加一行以「企微反馈自动归档：」开头的 §一 行 → 工作区另存在一个**属于别的会话**的脏文件 → release。

**结果**：当场被拒，拒绝项为校验⑹ 登记完整性，未覆盖脏文件 2 个：机器人自己写的 `queue.md`，以及**别人正在改的那个文件**（被明确归入"acquire 之前就已经脏（可能来自并发 session）"一栏）。

**对照**：同一场景把 `who` 换成 `SWEEP_LOCK_WHO`，校验⑹ 不触发（改由③预留归属校验拦下，属另一回事）——证实⑹ 确实只认 sweep 这一个身份。

**与线上三次事故的一致性**：13:19:39 被拒时 Cowork 正在改队列与方案件（工作区必脏）；13:55:38 同一条链路工作区已干净、**未**被拒；08-26 08:16 那次 M1 的 CC 正在跑。三次全部吻合。

## 决策点 1：豁免的判据取"是否自行提交自身改动"，而非"是不是机器人"

**问题**：最省事的写法是 `who in (SWEEP_LOCK_WHO, AIBOT_LOCK_WHO)`。但这样写下去，下一个自动化持锁者出现时会**第三次**重演同一疏漏（#333② 是第一次，本条是第二次）。

**决策**：判据表述为**"持锁者是否自行提交自身改动"**，代码上仍以身份常量集合实现（本项目一贯做法：判据独立实现、不引入注册表），但**常量集合旁必须写清它表达的是哪条判据**，使下一个自动化路径接入时有明确的挂靠点。

**证据（机器人确实自行提交）**：`queue_git_sync.py::append_task_and_sync_to_git` 成功即记 `queue_sync_pushed`；失败走 `queue_sync_degraded` ＋ `_route_pending_failure` 落 pending ＋ `_mark_row_unsynced_safely`，并向运维告警。⇒ 它的改动不依赖 sweep，校验⑹「你的脏文件没人管」这一前提对它不成立。

## 决策点 2：本次取窄修法（身份豁免），把宽修法登记为独立候选

**宽修法**：把校验⑹ 的度量范围从"仓库全部脏文件"收窄为"本次持锁者实际改动的文件"。

**它更治本**——本缺陷的深层形态是：**一个把全局状态当作本次动作的责任范围来度量的校验，必然在并发环境里错怪无辜者**。校验⑹ 想问"你改的东西有没有人管"，实现成的却是"仓库里还有没有没人管的东西"。人类会话同样会被别人的脏文件挡住，只是人类看得懂拒绝文案、会去登记或写豁免，所以从没被记成缺陷。

**为何本次不做**：
1. 影响面覆盖**全部**持锁者的判定口径，属改变全项目口径（门槛①），应单独立项、单独取证；
2. `dirty_at_acquire` 快照当初被明确记为「**不再用于过滤**（原设想的差集判据已被取证推翻），只用于 release 拒绝时的归因」——直接拿它做过滤等于重走一条已被推翻的路，须先弄清当初为何推翻；
3. #416 ⑶ 正在出血（每次回件锁死 30 分钟），窄修法能立刻止血，宽修法需要一轮完整取证。

**⇒ 建议**：本包只做身份豁免；宽修法另立队列行，**并在代码注释里指向它**，避免"止了血就没人再想根治"。

## 决策点 3：豁免范围严格收窄

- **仅豁免校验⑹**。机器人仍须通过：列数、关键格哨兵、组内编号重复、归档号重复、称呼判据、§二 状态列格式等全部其余校验。
- **不豁免"取数失败"那条 fail-closed 分支**——`dirty_now is None`（git 不可用/超时）时的拒绝对机器人同样保留：那条分支防的是"校验无法执行"，与"校验不适用"是两回事，不可混为一谈。
- 配套**反例**单测必须包含"人类会话 ＋ 未覆盖脏文件 → 仍拒绝"，否则无法区分"豁免生效"与"校验⑹ 被改废"。
