### 取证一：队列行号在 live ∪ archive 内是全局唯一键（判据可以按号查）

按「§一 表格内首列纯数字」扫描全部载体：

| `跨桌任务队列-业务场景.md`（在办） | 22 |

- **live ∩ archive 冲突编号：0 个**
- **archive 内部重复编号：0 个**

⇒ 迁归档是**移动**而非复制，编号不复用。**按行号查是可靠的**，不需要引入 (文件, 行号) 复合键。`#368` 只在归档、`#397`/`#395` 只在 live，均已实测。

### 取证二：🔴 归档行的「状态列」不可信——按状态字段判会原样重演白跑

这条推翻了最自然的实现（"读 `[S:done]` 机器字段"）。归档件里 `#368` 那一行**按竖线切分恰 8 段**，逐格如下：

| 格位 | 列名 | 实际内容（截断） |
|-----|------|----------------|
| `cells[0]` | # | `368` |
| `cells[1]` | 任务 | `✅ **[S:done] 整行销号（2026-08-22，② 由 Cowork 全景路线图线经 OP-0821-M 完成）** …` |
| `cells[5]` | **状态** | **`[S:open][D:业] 🆕 2026-08-21 立行，未开工` …** |

**销号信息被写进了任务列，状态列原封不动停留在 `[S:open] 未开工`。**

⇒ 若按 `queue-row-status-field` spec 的规范位置（`cells[5]`）读机器字段，对 `#368` 得到的答案是 **open** ⇒ **A4 会被照常派出 ⇒ 白跑一字不差地重演。** 一个"正确实现了规范"的校验器，在真实数据上会完全失效。

🔑 **判据：归档件里的「行在哪」比「行说自己是什么」可信。** 值周清扫只迁它判定为已完成的行，**迁移这个动作本身就是完成判定**，且它是人工复核过的；而状态列是否被同步更新，无任何机制保证（本行即反例）。故**归档命中即已完成，不解析归档行的任何状态内容**。

> **附带发现（不在本包范围）**：归档 `#368` 的状态列与任务列自相矛盾，属数据质量缺陷。**不在本包内修**——本包的判据刻意设计成不依赖它，修不修都不影响正确性。建议登记 §四 提请值周清扫在迁移时同步状态列，另行处置。

### 取证三：`#368` 在归档件里出现 7 次，其中**没有一次**是它自己那一行

`grep "#368"` 命中 `跨桌任务队列-归档-202608.md` 的 533/535/902/904/906/912/1028 行——**全部是别的行在正文里提到它**（如 `§一 #363` 正文写「结论同去向 §一 #368」，`§四 #88` 正文亦提及）。而 `#368` 自己那一行在**第 583 行**，首列写作裸 `368`、**不带 `#`**。

⇒ **子串检索必然同时产生假阳性与假阴性**：搜 `#368` 搜到 7 条无关行、搜不到目标行本身。判据必须是**「§一 表格内首格数值相等」**，且必须先做章节归属判定。

## Goals / Non-Goals

**Goals**
- 已完成的 opener 不再被派出；每次跳过都留下**可读的判定依据**（行号／命中载体／理由）。
- 判据只有**一份实现**，v1 与 v2 共用；两个 runner 的行为差异只体现在"跳过之后怎么走"，不体现在"怎么判"。
- 无法判定时**一律照常派出**（fail-open），并计数告警。
- 不改变现有 `OK`/`PARTIAL`/`NO-SENTINEL`/`FAIL` 四态的任何既有语义。

**Non-Goals**
- **不改计划文件格式**——不要求写计划的人新增任何字段（决策点 2 论证为何沿用标题）。
- **不做「这行到底该不该做」的语义判断**——只做"载体在哪"的机械判定，不引入 LLM、不读 opener 正文推断意图。
- **不修归档件既有数据**（取证二的状态列矛盾）——判据设计成不依赖它。
- **不在本包内实现 `#396` 的治标**（9 份派单件逐份核实）——那是 #396 自己的活，本包只定义此后的**义务归属**（决策点 6）。
- **不动 `queue-row-status-field` spec 本身**——本包不改状态字段规范，只是**不把它当归档侧判据**。

## Decisions

### 决策点 1 · 行号→归档件检索判据（A27 指定项①）🔴 需签认

**四态判定，按序短路：**

| 态 | 条件 | 动作 |
|---|------|------|
| **A** | 在 live 两份任一命中 §一 行，且状态字段**非** `done` | **派出**（正常路径） |
| **B** | 在 live 两份任一命中 §一 行，且 `cells[5]` 以 `[S:done]` 开头 | **跳过 ＋ 告警**（理由：live-done） |
| **C** | live 未命中，在任一归档件命中 §一 行 | **跳过 ＋ 告警**（理由：archived@`<文件名>`） |
| **D** | live 与 archive 均未命中 | 🔴 **照常派出 ＋ 告警**（理由：unresolved） |

**逐条依据：**

- **B 态是必要的，不能只查归档。** 反例 ＝ `#395`：它 `[S:done]`（已并入 #397）却**仍在 live 机制环境第 73 行**，从未进归档。只查归档会漏掉整个"已完成但尚未清扫"窗口——而值周清扫是**每周一次**，这个窗口最长有 7 天。
- **C 态只判"在不在"，不读内容**（取证二）。归档命中即已完成。
- **D 态必须 fail-open。** 派出一个不该派的，有人会发现；跳过一个该做的，**无人在场**。二者不对称，故一切模糊地带向"派出"倾斜。
- **B 态的状态字段只读 `cells[5]` 开头**，且**只在 live 侧使用**（live 侧由编辑锁写侧咽喉守着，字段可信；归档侧无人守，见取证二）。

**行定位判据（防取证三的假阳/假阴）——三个条件全部满足才算命中：**
1. 该行位于一个**§一 章节**内（章节匹配 `^#{2,3}\s*§?\s*一[、\s·]`，兼容 live 与 archive 两种写法，且支持单文件多个 §一 表）；
2. 用 `queue_table.split_row_cells()` 切分（**必须复用**——它按 CommonMark 反引号游程规则屏蔽单元格内的裸竖线，这是队列 #314 apply 阶段真实踩坑后升级来的；自己写 `split('|')` 会在含反引号路径的行上切错格数）；
3. `cells[0]` 去空白后**与目标行号数值相等**（`int` 比较，不是字符串 `in`）。

**多载体解析纪律**：逐份文件独立解析后合并，🔴 **绝不拼接文本再解析一次**——沿用队列 #312 已被单测锁死的教训（拼接后 `_parse_table_rows` 只取第一个 `## 一、`，会静默丢掉第二份的 §一）。归档件同理，且更严重：`归档-202608.md` 单文件内就有 4 个 §一 表。

**不引入 LLM**：全部判据为整数相等与前缀匹配。

### 决策点 2 · 行号从哪里取（锚点）🔴 需签认

**结论：沿用 opener 标题，不新增字段。**

现行两版计划文件的标题格式**已经稳定携带行号**，且两个 runner 的解析正则 `^###\s+(A\d+)\s*·?\s*(.*)$` **早已把它捕获进 `$title`**——不需要改任何解析代码就能拿到锚点：

```
### A4  ·【Cowork·业务新 session（质量域）】质量域场景清单重审——队列 #368
### A27 ·【CC】#397 批处理派出前查归档（#396 治本）——…——队列 #397／#396
### A22 ·【CC】#353 apply：…——队列 #353／§四 #108(a)
### A2  ·【Cowork】队列每周清扫迁归档（本轮巡检移交件）——协议〇.8／§四 #44
```

**抽取正则**：`(?:队列|§一)\s*#(\d+)`，全局匹配取全部。

🔴 **必须显式排除 `§四 #N` 与 `§二 <批次>`**——§一 与 §四 是**两套独立编号**，archive 中 `§四 #88` 与 `§一 #368` 同时存在且毫不相干。A22 的标题同时含 `#353`（§一）与 `§四 #108`，**只有前者是本判据的输入**。实现上：先剥掉 `§四\s*#\d+(?:\([a-z]\))?` 与 `§二[^／/]*`，再在剩余串上取 `#(\d+)`。

**多行号（`#397／#396`）合取语义**：🔴 **全部引用行都已完成，才跳过；任一行仍在办，即派出。** 依据 ＝ A27 自身：它引用 `#397／#396`，若将来 #396 先行完成而 #397 未完，按析取语义就会把 #397 的活跳掉。合取是唯一安全的选择（与 fail-open 同向）。

**无行号（如 A2 的 `协议〇.8／§四 #44`）** ⇒ **D 态**：告警 ＋ 照常派出。这类 opener 本就不绑定 §一 行，**属正常形态、不是错误**，故其告警文案须与"写了行号但查不到"区分开（后者才值得追查）。

**为何不新增独立字段**（如 `▶ 队列行：#397`）：
- (a) 需要修改全部历史计划文件才能回放验证，而回放验证正是本包的验收条件之一；
- (b) 计划文件由人手写，新增一个必填字段等于新增一条**人守**规则——而本包的立意恰是把人守变机制守，自相矛盾；
- (c) 现有标题格式在 v1/v2 两版、`本周计划-*.md` 与 `建造波次-*.md` 两族文件上**已实测一致**，无需再造契约。
- **代价如实记**：标题是自由文本，理论上可能漏写或写错格式 ⇒ 落到 D 态（告警 ＋ 派出），**不会造成误跳过**，代价可接受。

### 决策点 3 · v1/v2 两个 runner 的共同挂点（A27 指定项③）🔴 需签认

**挂点位置 ＝ 解析完成、`-Only` 过滤之后，任何派出/分组动作之前。** 两个 runner 在这一点上结构完全同构：

| runner | 解析循环 | `-Only` 过滤 | **挂点插入处** | 其后紧接 |
|--------|---------|-------------|--------------|---------|
| v1 | L53–72 | L75–76 | **L76 之后** | L78 打印清单 → L103 `foreach` 串行派出 |
| v2 | L37–56 | L59–60 | **L60 之后**（🔴 必须在 L62 泳道分组**之前**） | L62–69 泳道分组与打印 → L128 `Start-Job` |

**为何统一放在"分组之前"而不是"派出瞬间"**：
- v2 若放在 Job 内部（`$laneBlock` 的 `foreach`，L94），则 ⑴ 泳道清单打印（L66–69）会显示一批实际不会跑的 opener，**人看到的计划与实际执行不一致**；⑵ 一个成员全部被跳过的泳道仍会 `Start-Job` 并**白等一次 `-StaggerSec`（默认 90 秒）**；⑶ 判据在 Job 内执行 ⇒ 每泳道各跑一次查询，重复 I/O 且难以统一汇总。
- 放在分组前，`-DryRun`（v1 L81 / v2 L71）**天然就能显示跳过标记**——这正是验收条件之三，无需额外代码。

**共用实现 ＝ `0-学习与工具/工具-opener派出前校验.ps1`**，两 runner 各 `. (Join-Path $PSScriptRoot '工具-opener派出前校验.ps1')` 一次。导出单一函数：

```powershell
# 入参：解析好的 $openers 数组（含 Id/Title/Text/Paste[/Lane]）
# 出参：同一数组，每个元素补两个属性 —— Skip([bool]) 与 SkipReason([string])
Set-OpenerDispatchDecision -Openers $openers -RepoRoot $RepoRoot [-Force]
```

**判据本体走 Python，不在 PowerShell 里重写表格解析**——helper 只负责调用与结果映射：

```
python 0-学习与工具/工具-队列查询.py --row <N> --section 一 --include-archive --format json
```

理由：⑴ 复用 `queue_table.split_row_cells`（反引号游程屏蔽，#314 教训）与 `iter_queue_paths`（#312 教训），**判据只存在一份**；⑵ 在 PowerShell 里另写一个 markdown 表格解析器，就是造第二个会漂移的实现——本项目已在 #312 上付过这个学费。

**跳过后各自怎么走（这是两者唯一的差异）：**

| | v1（串行） | v2（泳道） |
|---|---|---|
| 跳过的 opener | `foreach` 内 `continue`，记 `SKIPPED` | 分组前从泳道成员中滤除，记 `SKIPPED` |
| 🔴 **不得触发** | L128 的 fail-loud `break` | `$laneBlock` L111 的 `break`（停本泳道） |
| 整泳道被跳空 | — | **不 `Start-Job`**，不占并发额、不等 `-StaggerSec` |
| 汇总表 | 新增 `SKIPPED` 行，含理由 | 同左，`summary.txt` 一并写入 |
| 退出码 | 有跳过**不影响**退出码；仅 FAIL/NO-SENTINEL 仍 `exit 1` | 同左 |

🔴 **最容易踩的一个坑，必须显式实现**：跳过的 opener **不会产生 `OPENER_DONE` 哨兵**。若跳过后仍走原状态计算（v1 L124 / v2 L109），`$code -eq 0 且 !$done` ⇒ 判为 **`NO-SENTINEL`** ⇒ v1 **整批中断**、v2 **停掉整条泳道**。**跳过必须在状态计算之前就短路掉，绝不能让它流进哨兵判定分支。** 这一条须有单测锁死。

**逃生阀 `-Force`**：跳过判定全部失效，恢复现状行为。用于"我就是要重跑一遍已完成的活"。使用时在日志显式记录 `[Force] 归档校验已被绕过`——绕过必须留痕。

### 决策点 4 · 查询结果要不要缓存　（建议 (a)，可不签认）

- **(a) 不缓存**，每个 opener 各查一次。一次批处理典型 5–15 个 opener，每次读 4 份 md（合计约 1.4 MB）；相对于一个 CC session 动辄数分钟的开销，**完全可忽略**。
- **(b) 缓存**一份 `<行号> → 状态` 快照到 `reports/opener-batch/<stamp>/`。省下几百毫秒。
  🔴 **选 (b) 的附带义务**：这会造出一种此前不存在的文件名形态 ⇒ 必须回头补 `.gitignore` 并用 `git check-ignore -v` **实测取证**（不是推断），见 proposal 该节。
- **建议 (a)**——收益近乎为零，却要新造一种文件形态并承担 #328 那族的风险（凭空造出的文件名没人回头看忽略规则，最终被 sweep 判为孤儿脏文件、企微群连响 17.1 小时）。**不值得。**

### 决策点 5 · `工具-队列查询.py` 怎么扩（建议 (a)，可不签认）

- **(a) 新增两个可选开关**：`--include-archive`（默认 **关**）与 `--format json`（默认 **text**）。不传时输出、退出码与现状**逐字不变**。
- (b) 直接改默认行为（默认就查归档、"没找到"改为非零退出码）。

**建议 (a)。** 理由：(b) 本身就是一次"改变既有模块对外语义"——`工具-队列查询.py` 有既有调用方（人工命令行、其它脚本），**把 exit 0 改成非零会静默改变它们的成败判定**，等于在修一个静默缺陷的同时引入另一个。(a) 是纯增量，老调用方零感知。

`--format json` 的返回契约（新挂点只认它，**不解析中文文案**，也不依赖退出码——取证四）：

```json
{"row": "368", "section": "一", "found": true, "carrier": "archive",
 "file": "1-转型规划/0-全景路线图/跨桌任务队列-归档-202608.md",
 "line": 583, "status_field": "open", "done": true, "reason": "archived"}
```

- `carrier` ∈ `live` / `archive` / `none`
- `done` ＝ **最终判定**（`carrier=archive` ⇒ 恒 `true`，**不看 `status_field`**；`carrier=live` ⇒ 取决于 `status_field == "done"`）
- ⚠️ 上例中 `status_field` 为 `open` 而 `done` 为 `true` —— 这正是取证二那个矛盾行的真实取值，**契约刻意让两者可以不一致**，消费方只准读 `done`。`status_field` 仅供人排查。

### 决策点 6 · 派单件 frontmatter `status` 回写义务归属（A27 指定项②）🔴 需签认

**问题**：`派单件-*.md` 的 frontmatter `status` 由谁负责改对？现状是**无人负责** ⇒ 21 份里 9 份仍 `待执行`，已坐实 ≥2 份失真（#396）。

**先厘清一件事：本包的队列行校验拦不住这一族。** 派单件与队列行是两个载体——A4 撞上的失真派单件 `派单件-【Cowork】质量域场景清单重审-2026-08-21.md`，其对应队列行 `#368` 确实已归档（本包能拦）；但 #396 普查出的另一份 `派单件-【CC】FI2面板翻倍修复与R5分母对照表-2026-08-23.md` 是**本轮 A1 刚执行完**、队列行状态尚未必同步 ⇒ **本包的判据对它无效**。两者必须分别处置，不能指望一条判据兜住。

**三个选项：**

- **(a) 义务归执行 session（纯人守）**——收工纪律加一条"若本次执行的活有对应派单件，同批把 frontmatter `status` 改为 `已执行`"。
  *代价*：这正是已经失效的那条路。它从未被写成明文，但事实上一直指望执行者自觉；结果是 9/21 失真。**规则退休制的判据在此已达阈值**：错误不产生信号 ⇒ 会被一直重复。单靠 (a) 等于原地打转。
- **(b) 义务归机器（sweep 常驻告警）**——落库 sweep 新增一类：扫全部 `派单件-*.md`，凡 `status: 待执行` 而其标题/正文引用的队列行已 `done` 或已归档者，告警列出。
  *代价*：需改 `工具-落库sweep.py`，本包范围扩大约半天；告警首月可能有噪音（沿用 `_check_claude_md_carrier_size` 的"首月只告警、不调参"惯例可控）。
  *收益*：与本包判据**同源**——sweep 复用同一个 `--include-archive` 查询，不新造判据。
- **(c) 义务归派出前校验（本包挂点顺带查）**——校验器在查队列行的同时，也查是否存在同名派单件且 `status` 失真。
  *代价*：🔴 **判据不可靠**。opener 标题不含派单件路径，只能靠标题文字模糊匹配文件名（A4 标题「质量域场景清单重审」↔ 派单件名「质量域场景清单重审」是巧合式吻合，非契约）。**模糊匹配 ⇒ 误跳过 ⇒ 违反本包 fail-open 底线。**

🔴 **建议 (a) ＋ (b) 并用，明确分工：**
- **(a) 定义义务**——义务人 ＝ **执行该派单件的 session**（谁做完谁改，与队列行回写同批、同一次编辑锁）。**这条必须写下来**，因为机器只能告警、不能代替判断"这份派单件是否真的执行完了"。
- **(b) 兜底**——sweep 常驻告警，**首月只告警不调参**。它不承担改写义务，只保证**失真会产生信号**——这正是本族缺陷唯一缺的东西。
- **(c) 明确排除**，理由如上（模糊匹配触碰误跳过底线）。
