## ADDED Requirements

### Requirement: 待写入新值须通过反引号游程闭合性校验
`edit-row` 在把 `--set`／`--append`／`--changes-json`／`--stdin-json` 解析出的**每一个新值**写入目标行之前，SHALL 对该值做反引号游程闭合性扫描：按 CommonMark 反引号 code span 规则（连续反引号视为一个"游程"，开启游程须找到**同长度**的闭合游程才算配对成功），确认值内**不存在未闭合的反引号游程**。

该扫描 MUST 复用与读侧 `queue_table.split_row_cells`／`_mask_backtick_spans` 相同的游程配对算法，MUST NOT 采用"反引号字符总数是否为偶数"这一更弱的判据——总数为偶数不代表游程两两匹配（例：一个长度 3 的游程与一个长度 1 的游程，总字符数 4 为偶数，但按 CommonMark 规则互不匹配，长度 3 的游程仍未闭合）。

任一新值命中未闭合游程时，工具 MUST 拒绝本次 `edit-row` 调用、不写入任何内容，并在提示中包含：命中未闭合游程的字段名、该值的内容预览（含未闭合游程的具体片段）。

#### Scenario: 新值含未闭合反引号游程，拒绝写入
- **WHEN** `edit-row` 待写入的某个字段新值中存在一个反引号游程，扫描全文找不到与之长度相同的闭合游程
- **THEN** `edit-row` 拒绝写入，不修改目标文件，提示命中字段与未闭合片段

#### Scenario: 简单奇偶计数会漏判的形态必须被本判据拦下
- **WHEN** 某字段新值中同时存在一个长度 3 的反引号游程与一个长度 1 的反引号游程（反引号总字符数为 4，简单奇偶计数会判定为"闭合"）
- **THEN** 本判据 MUST 判定为未闭合（因两个游程长度不同、不构成 CommonMark 意义上的配对），`edit-row` 拒绝写入

#### Scenario: 正确闭合的反引号包裹竖线不被本判据拦下
- **WHEN** 某字段新值中反引号游程全部两两配对闭合，且闭合游程内部含半角竖线 `|`
- **THEN** 本判据判定为闭合，本 Requirement 不拒绝该次写入（是否因竖线本身被拒绝由既有 `has_bare_pipe` 判据决定，与本 Requirement 无关，本 Requirement 只判反引号闭合性）

#### Scenario: 未闭合游程改为正确闭合后放行（非恒真自证）
- **WHEN** 上一版本因反引号未闭合被拒绝的同一字段新值，被修改为反引号游程全部正确闭合，其余内容不变
- **THEN** 本判据判定通过，不再因反引号闭合性拒绝该次写入——证明拒绝确实来自未闭合判定，而非其它恒定原因
