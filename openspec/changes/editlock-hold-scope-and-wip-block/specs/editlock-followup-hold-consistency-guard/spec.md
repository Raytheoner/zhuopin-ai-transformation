## MODIFIED Requirements

### Requirement: 检测队列行的暂缓结论与已点名的跟进信文件
release 锁定目标为默认队列文件时，对本次持锁期间新增/修改的 §一/§四 行，工具 SHALL 检测该行是否同时满足：① 该行的**当前结论段**（§一 状态列 cells[5]／§四 事项列 cells[1] 按 `━━━` 分隔符切分后的**首段**）含有"暂不发"、"暂缓"、"压着"、"不发"中任一字样；② 该行可提取出至少一个反引号包裹、以 `.md` 结尾的文件名引用（§一 检测输入指针列 cells[3] 与触碰区列 cells[6]；§四 检测事项列 cells[1] 的**同一首段**）。

单元格不含 `━━━` 时，首段即整格，行为与收窄前一致。

工具 MUST NOT 把首段之外的历史沉积文本纳入暂缓关键词的扫描面——队列单元格按「历史记录不追改」长期沉积多轮登记，把整格当作"当前结论"会使误报率随沉积单调上升（2026-08-10 §四 #52 真实误报：单元格 4062 字符／11 段，四个暂缓关键词全部落在历史段、首段一个都没有）。

#### Scenario: 暂缓字样只出现在历史段，不触发本校验
- **WHEN** 一个 §四 行的事项列首段是"✅ 本行已完全闭环"类当前结论、不含任何暂缓字样，而 `━━━` 之后的历史段含"压着"字样，且该行点名了一封跟进信
- **THEN** 工具判定本行当前结论不是暂缓，不进入与 README 的交叉核对，release 正常放行

#### Scenario: 暂缓字样出现在当前结论段，正常触发
- **WHEN** 一个 §一 行的状态列首段含"暂不发"字样，且该行输入指针列含反引号包裹的 `.md` 文件名引用
- **THEN** 工具判定该行"点名了一封跟进信且结论为暂缓"，进入下一步与 README 的交叉核对

#### Scenario: 仅含暂缓字样但无文件名引用时不触发本校验
- **WHEN** 一个 §一 行的状态列首段含"暂缓"字样，但该行任何列都不含反引号包裹的 `.md` 文件名引用
- **THEN** 本校验不触发，release 正常放行

## REMOVED Requirements

### Requirement: README 已终态推送而队列行仍称暂缓时告警
**Reason**: 一进一出退休（协议〇.9 措施 B）。该反向告警在现网队列上唯一的命中是 §一 #150，而 #150 正是本能力自己的 Scenario 明文承认为合法的形态——"队列行的文本是在事故发生后新增，用于如实记录『本应暂缓但已被机制误发』这一经过"。一条只会在合法写法上响的规则产出的是噪音而非约束；且它属于 §四 #58（2026-08-17 复评）刚判定"信息量为零"的非阻断提示形态，而本变更包同批正把 `editlock-mechanism-wip-guard` 从该形态中移出。风险侧亦不对称：正向拦的是"照发一封已决定暂缓的信"（对外、不可撤回、有 2026-08-06 01:30 UTC 真实事故），反向管的只是"队列文本滞后于 README"（纯内部、可事后改、无外部后果）。

**Migration**: 无迁移动作。该分支只打印告警、从不阻断 release，删除后 release 的放行/拒绝判定完全不变；"队列文本滞后于 README"这一情形此后由值周巡检对账（既有职责，见 skill `zhuopin-queue-audit`）承接，不新增任何替代守卫。
