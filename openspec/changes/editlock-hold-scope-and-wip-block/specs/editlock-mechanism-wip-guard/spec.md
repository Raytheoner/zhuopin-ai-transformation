## MODIFIED Requirements

### Requirement: 超限时拒绝 release
`release` 释放跨桌任务队列.md 锁时，若本次持锁期间新增了域为 `机` 的 §一 行，SHALL 重新计算全文当前的机制类可动 WIP 计数（按 `queue-row-domain-field` 能力定义的口径）；若该计数超过上限，工具 MUST 拒绝 release、锁保持占用，除非本次调用满足下述「逃生阀」Requirement。

本项检查 MUST 仅在本次持锁期间**真正新增**了 `[D:机]` 的 §一 行时触发——对未新增机制行的 release（含专为关行降 WIP 而进行的编辑）MUST NOT 因存量超限而拒绝。理由：措施 C 要踩的是"新立机制行"这个动作；若改为"任何 release 超限即拒绝"，在存量已超限时（2026-08-17 实测 24／16）会连"来关行降 WIP 的那个 session"一并挡在门外，使规则把自己的解法锁死。

拒绝提示 MUST 含：当前计数与上限、本次新增行的编号、以及两条出路各自的确切走法（先关闭一条既有机制类可动行 ／ 按逃生阀写法放行）。

#### Scenario: 新增机制行导致超限，拒绝 release
- **WHEN** 本次持锁期间新增一条 `[D:机]` 的 §一 行，release 时重新计算得到可动 WIP 计数超过上限，且未满足逃生阀条件
- **THEN** `release` 拒绝释放，锁保持占用，提示当前计数／上限、新增行编号与两条出路

#### Scenario: 计数未超限，正常放行
- **WHEN** 本次持锁期间新增的 `[D:机]` §一 行使可动 WIP 计数保持在上限以内
- **THEN** `release` 正常释放，不打印本项提示

#### Scenario: 新增行域为业务类，不触发本项检查
- **WHEN** 本次持锁期间新增的 §一 行全部域为 `业`
- **THEN** 本项检查不重新计算、不判定（无机制类新增，无需检查）

#### Scenario: 存量已超限但本次未新增机制行，不拒绝
- **WHEN** 当前可动 WIP 已超上限，但本次持锁期间未新增任何 `[D:机]` 的 §一 行（例如本次编辑正是把某条机制行关闭）
- **THEN** 本项检查不触发，release 正常放行

### Requirement: 上限值可配置
可动 WIP 上限默认值 SHALL 为 24（对齐协议〇.9 措施 C 现行定案；沿革 8 → 16（2026-08-09）→ 24（2026-08-19，Shao Peishen 拍板；盘点件 §五 定夺 1 推荐 20，同日实测「A 类四行尚未销号 ⇒ 立四条会到 23」后改定 24）），MUST 支持通过命令行参数覆盖，避免上限值本身未来调整时需要改动代码。

⚠️ 本条曾写「§四 #58 于 2026-08-17 复评明确不再上调」——该判断在 2026-08-19 被推翻：#58 那次不上调的理由是「第三次为迁就现状改口径即等于废掉措施 C」，而 08-19 上调的理由不同——**排队待立的 4 条各自对应一次真实事故或一个已确认的生产不可用缺陷，压着不立 ＝ 让那些事故保持可复发状态**，与措施 C 控风险的目的方向相反（论证见该盘点件 §三）。两者不是同一件事，故不构成「反复迁就」。

#### Scenario: 覆盖默认上限
- **WHEN** 调用 release 时传入自定义上限参数（如 `--mechanism-wip-cap 20`）
- **THEN** 本项检查使用传入的上限值而非默认值进行超限判断

## ADDED Requirements

### Requirement: 逃生阀——越过上限必须在队列行内留下理由
工具 SHALL 提供一个逃生阀，使真正紧急的立行不被上限挡死；该逃生阀 MUST 同时满足两个条件才生效：① 调用 release 时显式传入开关参数（该参数 MUST NOT 携带理由文本）；② 本次新增的那条 `[D:机]` §一 行的状态列内写明约定标记 `WIP豁免：<理由>`。

🔴 理由 MUST 落在队列行内，MUST NOT 仅落在命令行参数、标准输出或任何日志文件中——命令行参数是会话级的，随窗口关闭即消失，而队列行进 git、可被 `工具-队列结构lint.py` 与值周巡检看见。仅落日志的逃生阀等于没有约束。

两个条件缺任一时，工具 MUST 拒绝 release 并指出缺的是哪一个。

#### Scenario: 开关与行内理由齐备，放行并留痕
- **WHEN** release 传入逃生阀开关，且本次新增的机制行状态列含 `WIP豁免：<理由>`
- **THEN** 尽管超限，`release` 正常释放；理由随该行一并落盘、进入版本历史

#### Scenario: 只给开关、行内未写理由，仍拒绝
- **WHEN** release 传入逃生阀开关，但本次新增的机制行状态列不含 `WIP豁免：` 标记
- **THEN** `release` 拒绝，提示理由必须写在队列行内、不能只写在命令行上

#### Scenario: 只写行内理由、未给开关，仍拒绝
- **WHEN** 本次新增的机制行状态列含 `WIP豁免：<理由>`，但 release 未传入逃生阀开关
- **THEN** `release` 拒绝，提示需显式传入开关以表明这是一次有意越过
