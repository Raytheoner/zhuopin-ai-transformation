## Context

- **档位**：本包交付后 ＝ **档 0（骨架）**。本次 design 定的是**从档 0 走向档 1 的开工边界**。
- **判据现状**：`CriteriaRegistry("FI5", …)` 四条 —— `TRAVEL_STANDARD_TABLE`／`ENTERTAINMENT_LIMIT_TABLE`／`L2_BUDGET_BLOCK_PCT`／`RISK_GRADE_BOUNDARIES` —— **全部未签认**，`RULE_VERSION = "fi5-skeleton-unsigned-2026-09-03"`，导入期双向校验。全库 `.signed(` 在 `4-数字员工/**/*.py` 下命中 2 处**全是注释** ⇒ 五场景 18 条一条未签。
- **核心设计约束**：四个引擎的**内容就是那四条未签认判据**。本 design 的中心问题因此是：**有没有一层不依赖任何判据、又有真实业务价值的东西可以先做？**
- **答案（D1）**：有 —— **可比量层**。因为报销的判据**全部是「每单位上限」这一形态**，所以「除以」这一步是纯算术、不含任何标准。与 FI8「名义层」、FI6「度量层」同构（都是「不依赖任何未签认假设的那一层」），与 FI10 相反（FI10 无此层）。🔴 **形态各自找、不照抄。**
- **两处比前三包更硬的缺口**（决定 D6 与 D9）：① `data/mock/` **只有三张表、无往来单位主数据**，`expense_lines` **无 vendor、无招待对象、无费用发生日** ⇒ 关联交易这一类**连字段都没有**；② 数据依赖里的「**预算管理系统**」全库只在三处转述里出现，**连一条 fail-loud 常量都没有**，且 FI7 写的是「U9C 预算模块」、FI5 写的是「预算管理系统」，**可能根本不是同一个东西**。

### 四条实施约束（apply 阶段必须照做，否则 D1／D4／D7／D12 会被悄悄绕过）

1. 🔴 **四列可比量必须全算、并列呈现，不得预选、不得默认排序**——只算其中一列就等于替财务侧预选了口径，而两张表要定的正是「上限是多少」。列头标注与「无默认单列排序视图」两条**属实施约束，不是 UI 偏好**（D1／D15）。
2. 🔴 **任何档位都不写回 U9C**，`.51` 部署时同样成立；超预算「拦截」在本轮及签认前一律只产建议与草稿（D4）。
3. 🔴 **跨期分支必须显式造用例覆盖**：`data/mock/` 三条记录 `period` 与 `submitted_at` 全在同月，**mock 全绿证明不了 D7**，真实数据里跨月报销是常态（D7）。
4. 🔴 **「重复发票」列保持「检出但不判违规」**，且 `AuditFinding.risk_grade` 保持恒空 ＋ 用例守——两者都是**用用例守住一个「没有」**，删掉那条用例不会有任何信号（D12／D14）。
