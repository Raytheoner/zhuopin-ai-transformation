# sc2-autopush-friday Design

> **本包的核心决策（推送形态与 IATF 定性）已由 Shao Peishen 于 2026-08-22 拍板**（队列 §四 `#89`，答 `OP0822A` 定夺 1 选 (a)）。
> 下方 D30-D36 是**据该拍板往下推导出的实现级决策**，逐条列出待 design 审追认；其中 **D33／D36 两条不是纯实现细节**，请重点看。

## 决策表

| # | 决策 | 一句话理由 |
|---|---|---|
| **D30** | **删除 `ensure_publishable()` 与 `UnconfirmedError`，而非留着不调用** | 留着不调用的闸最危险——读代码的人会以为门还在。要装回去时落点只有一处（`notify.push` 里恢复一次判断），刻意让它只有一处，免得下次漏掉旁路 |
| **D31** | **推送幂等与推送范围不随前置一并取消** | 它们防的不是签认，是**重复**与**误投**。⚠️ 幂等在取消前置后比过去更要紧：过去人工确认这一步天然限流，现在到点即发，重跑/重启若不幂等就连发 |
| **D32** | **`autopush` 缺省 `--mode real`**，与 serve/report 缺省 mock 相反 | 唯一调用方是无人值守的计划任务。缺省 mock 的失败模式是「每周往群里发一份假数据」，且**要到姚祖怡在群里看见假数字才会被发现**——没有任何中间环节会报错 |
| **D33** | 🔴 **基准日＝当天（本周），保留 O-7「本周窗口尚未走完」声明** | 他要的就是「周五给出**本周**的」，故周五跑时本周只过 5/7 天是**设计上必然**的偏差，任何阈值都修不掉。唯一补救是每期把话说在明处。**已配单测钉死**，防日后有人嫌它难看而删 |
| **D34** | **群推走 outbox 落盘 ＋ 笔记本侧中继代发**，不在 `.51` 直连 | `#282` 拍板不得新起 webhook；而 aibot 长连接在笔记本、SC2 在 `.51`，同一机器人多处长连接会互相踢线（单实例约束）。形态取自 `fi2-source-inversion` design 决策点 8.2 已批的 ⑵ |
| **D35** | **outbox 只写部门名，chatid 由中继侧解析** | 权威映射是 aibot 侧那张 yaml。抄一份 chatid 进场景代码就立刻产生第二份真相，而那张表的注释里已记着它踩过的坑（键名 `IT` 而非 `IT部`，传错即 fail-closed 静默跳过）。**部门键拼错在入队侧当场上抛**——把一个静默失败换成一次响亮失败 |
| **D36** | 🔴 **一期写两条 outbox 记录（群 ＋ 私信），不合成一条** | 群通报与私信是两次独立投递，中继可能一条成功一条失败。合成一条后「群发了、私信没发」这种半成功状态无法表达，只能整条重发（重复）或整条丢弃（漏发） |
| **D37** | `ZhuopinDeploy.psm1` 加**可选参数**而非另写注册函数 | 该模块存在的理由就是收拢四类计划任务坑（SYSTEM 只认机器级 PATH／电池／重启参数／防双实例）。复制一份逻辑＝把四个坑重踩一遍。**缺省值未变，五个既有调用方行为一行不改** |
| **D38** | 定时任务同时给 `MultipleInstancesIgnoreNew` **和** 2 小时执行时限 | 两者必须一起给。只给前者而不限时，一次挂死会把此后每周的触发**全部静默 IgnoreNew 掉**，表现为「任务还在、再也没跑过」——又一个不产生任何信号的错误 |

## 🔴 请重点看的两条

### D33 —— 这是一个我们主动选择保留的、每期都会出现的难看提示

周五 20:00 出「本周」的报表，意味着本周只过了 5/7 天，而上周与上月同期都是完整 7 天
⇒ **所有「量」类指标的环比/同比会系统性偏低**。2026-08-18 首次部署当天（周二，2/7 天）
21 个指标里 16 个被打上标记，**那不是业务波动**。

**这不是可以靠调阈值解决的问题**，因为它根本不是阈值问题。既然专员要的就是本周的，
唯一诚实的做法是每期把这句话摆在周报顶部。**它会每周出现一次，看起来像噪音，但它不是。**

⚠️ **另一条路存在但未选**：改为「周五出上一个完整周（W-1）」——数字干净、无此偏差，
但那不是他要的东西。**此处不替他改判**；若 design 审认为该改，属 D16-R 的修改，请明示。

### D36／未送达 —— 本包交付后，群里仍然收不到任何东西

中继尚不存在（`fi2-source-inversion` 0/58 任务未开工，全仓 `outbox` 零命中，2026-08-25 实测）。
本包上线后周五 20:00 会准时生成、准时写 outbox，**而消息只会积压**。

**这与 `#82` 是同一个形态**：机制建成 9 天、每天在跑、一条都没真发出去，没有人察觉。
故本包把积压做成三处可见（CLI 打印、页面提示、`outbox.pending()`），
并把「已推送 ＝ 已交付给中继 ≠ 群里已看到」写进 `notify.push` 的 docstring 与本设计。

**中继的建造不在本包范围**（属 FI2 包），已登记队列待派。
