# fi10-inventory-writedown-mvp Proposal

> 🔴 **状态：起草中，未过 design 审。** 由无头泳道 `B-0903_20 / fin-scenarios`（件号 `OP-0903-B3`，队列 §一 `#474`）起草，**只到 proposal ＋ specs 增量 ＋ tasks，不写 `design.md`**（🟡，须 Shao Peishen 拍板）。

## Why（为什么做）

存货跌价测试目前是年末集中做的手工活：库龄靠翻表、哪些料还会被用掉靠问计划、NRV 靠经验估、项目终止后剩的料常常没人回头看。芯片这类价格波动大的器件，降价发生时也没有任何信号。FI10 把账龄、在途、BOM 用量与 OEM 项目生命周期整合起来，按准则跑 **NRV vs Cost** 自动跌价测试，出**跌价准备计提建议**并支持 what-if。自动化等级 **L2**（AI 测算＋预警，财务/供应链经理确认）。

**立项依据**：队列 §一 `#474`（源 `#463`）＋ Shao Peishen 2026-09-02「能开尽开，唯一门槛是前置依赖」。权威排期表原排 **2027-06**（Phase 1 收官月）——本包**不改排期**。

🔗 **链 D 联动点 L9**（`SC7` 呆滞 ↔ FI10 跌价**同口径**）。

## 🔴 缺口一览（三处，性质各不相同，勿混为一谈）

| | 缺什么 | 性质 | 本包怎么处理 |
|---|---|---|---|
| **⑴ 芯片价格 API** | 数据源尚未选型签约 | **前置未满足**（上游 `#475` 独立立行） | 🔴 **依赖它的部分停下登记、不实现**（芯片降价超阈值预警）；不依赖的部分照做 |
| **⑵ L9 呆滞口径** | 要"从 SC7 取"，但 **SC7 那份口径尚未落地** | **判据无源可取**（本泳道实测出的新情况） | 🔴 **不代判、不自行定义**（自行定义 ＝ `#474` 明令禁止的"另立一套"，且属 🟡） |

### ⑴ 芯片价格 API —— 前置未满足，且**标的本身尚待判定**

`#475` 已把该 API 独立立行（跨域基础设施，与 `O2` 芯片预警共用，不挂单一场景名下）。本包据此**停下登记依赖它的部分**。

⚠️ **一处本包不代下结论的待判**（`#475` 明写）：前置总表 `O2` 行写「芯片**供货** API」（服务对象仅 `O2`，11 月底截止，🟡），实施计划依赖表写「芯片**市场价格** API」（服务对象 `O2`／`FI10`，10 月，"待选型"）——**命名／服务对象／时点三项均不同，是否同一项尚未定**。**若是两项，「供货」那项尚未逾期、「价格」那项已逾期，紧迫度完全不同。** 本包**如实沿用「未定」**，已落成 `config.CHIP_PRICE_API_BLOCKED` 常量并由用例守住"未定"这个措辞本身。

📌 **本泳道另实测到一条与 `#475` 判词同向的事实**：该 API 的**另一个消费方 `O2` 芯片预警子功能，目前同样没有工程实体**——`4-数字员工/运营部/O2-物料齐套预警/` 下无任何芯片预警相关代码（仅测试夹具里出现过"芯片 C"这个物料名）。⇒ 这个共用前置**当前两个消费方都还没落地**，`#475` 所说"挂在单域名下会连带失去主人"的风险，在此得到一处旁证。

### ⑵ L9「同口径」当前无源可取 —— 本泳道实测出的新情况

`#474` 写「`SC7` 已有工程实体，呆滞口径应从那里取、不得另立一套」。**本泳道 2026-09-03 逐文件实测，情况与该表述不符**：

- `sc7_inventory/business_rules.py` **只有两条规则**：R1 单次采购金额 ≥ 50 万 → 人工审核；R2 无认证供应商 → 人工审核。**没有任何呆滞口径**。
- `SC7/CLAUDE.md` **三处**明写「呆滞库存处置」属 **②期深化（2027-01）尚未落地**，且「②期深化范围确认……业务口径**待姚祖怡确认**」。

⇒ **L9 要对齐的那个口径当前不存在**。FI10 若自行定义呆滞口径，即等于 `#474` 明令禁止的"另立一套"，且属 🟡 `change_criteria`（泳道无权）。⇒ **本包不代判、停下登记**，落成 `config.L9_SOURCE_ABSENT` 并由用例守住。

**这不是说 `#474` 写错了**——`#474` 说的是"SC7 已有工程实体"（属实），推论"呆滞口径应从那里取"在 SC7 ②期落地后成立。本包只是指出：**在那之前，这条指令没有可执行的对象**。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

**1. 本流程哪些判断是人脑默会经验？**

| 判据 | 现状 | 落点 |
|---|---|---|
| **NRV 估算口径** | 准则给框架，落地全靠经验：售价取哪个（最近成交？在手订单？市场报价？）、扣不扣销售费用与税金 | `NRV_ESTIMATION_BASIS`（`None`） |
| **库龄超期门限** | 无成文口径。多少天算超期、分不分物料类别（芯片与结构件显然不同） | `AGING_ALERT_THRESHOLD`（`None`） |
| **项目终止未耗物料口径** | 无成文口径。终止后多久触发、在途的怎么算（已订未收的还要不要继续收） | `TERMINATED_PROJECT_ALERT_CRITERIA`（`None`） |
| **呆滞口径** | 🔴 **不是"未签认"，是"应从 SC7 取而 SC7 还没有"** | `SLOW_MOVING_CRITERIA`（`None`，理由见 ⑵） |

## 验收与晋档条件（强制，四档口径）

- **本变更包交付后场景所处档位 ＝ 档 0（骨架）**。
  🔴 如实说明：`#474` 写「可开工部分＝NRV vs Cost 测试引擎与三类预警触发条件的 mock 建模」。逐项看——**NRV 测试引擎的算法骨架**（比较、计提额计算）可建，但 **NRV 本身的取值口径未签认**；**三类预警里，一类（芯片降价）前置未满足、一类（库龄）门限未签认、一类（项目终止）口径未签认**。⇒ **本包不宣称档 1**。
- **晋档 1 的条件**：
  1. 财务 ＋ 供应链交付 NRV 口径、库龄门限、项目终止口径并实名签认；
  2. 🔴 **`SC7` ②期呆滞口径落地**（或由 Shao Peishen 明确改由 FI10 先定、SC7 后对齐——**这是口径归属的改动，属 🟡，须他拍**）；
  3. `config` 改实值、`RULE_VERSION` 升版、签认落档；
  4. 引擎按"先测后实现"落地，合成数据全绿（**芯片降价预警除外，前置未满足**）。
- **晋档 2 的额外条件**：
  5. U9C 库存模块（账龄／在途）取数通道核实打通；
  6. 🔴 **OEM 项目计划（PLM）取数须走隔离层**，按客户路由、禁跨库，且须实测跨库确实抛 `CrossOEMAccessError`；
  7. 🔴 **芯片价格 API 选型签约完成**（`#475`）——**且其标的先被判定清楚**（供货 vs 市场价格是一项还是两项）。**在标的判定前不得开始选型，否则可能选错标的**（`#475` 原文）。
- **价值指标（D-4 两级验收）**：
  - **风险型**：跌价迹象的提前发现月数（当前 ≈ 年末集中做一次）；
  - **质量型**：计提建议与最终入账数的偏差率。
- **LLM 判据黄金集**：本场景主体是**规则与数值测算**，若最终实现不含 LLM 运行时判断则不适用；含则须补黄金集，**无黄金集不晋档 3**。留 design 审确认。
