## Why

### 病灶：查重是取号那一刻的快照，不是锁

`#487` 第三子项已把根因钉死，原文：

> `--op-id` 查重扫的是**已落盘的痕迹**（仓库 ＋ 接力卡），而「取号」与「落盘」之间有一段真空 —— **查重是取号那一刻的快照，不是锁**。

**实撞（2026-09-06，同日两条线）**：业务总线取到 `OP-0906-D`、查重判空号、放行；该 opener 经 Shao Peishen 判「不必转场」**从未粘出**，因而没有落进仓库任何文件 ⇒ 环境线随后取号时 grep 不到它，**同日再次取到 `OP-0906-D`**。两条线各自合规、工具各自正确，**结果仍然撞号**。当次是 Shao Peishen 本人发现的，**不是机制**。

### 为什么落到队列编号预留这一侧，而不是 op-id 那一侧

⑵ 在 op-id 那一侧**几乎不需要代码**——`_check_op_id_not_reused` 本来就是 grep 已落盘痕迹，"未落盘即可复用"正是它现在的行为，⑵ 对它只是把这条既成事实**写成一句纪律**（「未派出的号当场作废、不预留」）。

⑵ 在**队列行编号**这一侧则是**真代码改动**，而且方向与现状相反：

| 现状（`工具-共享文档编辑锁.py`） | 出处 |
|---|---|
| 「未使用完的预留号允许留空洞（协议〇.8：编号永不复用），本函数不做任何"释放未用编号"的操作，调用方也不需要」 | `_reserve_ids` docstring（L1683 附近） |
| 「即使本次未写满，编号不复用、留空即可」 | `cmd_acquire` 预留成功后的回显 |
| 「已成功预留的分区其高水位线不回退，允许留空洞」 | `--reserve-multi` 部分失败回滚分支 |
| 单测 `test_reserve_then_release_without_using_leaves_gap_and_keeps_high_water_mark` 明文断言 HWM **不回退** | `test_工具-共享文档编辑锁.py` |
| 单测 `test_reserve_multi_partial_failure_rolls_back_and_keeps_first_section_advance` 明文断言首分区 HWM **不回退** | 同上 |

⇒ 队列行 `#487` 的判断「现有 `_reserve_ids`／`reserved_map` 与 `editlock-queue-number-reservation` spec 均未覆盖『预留后从未落盘』的释放逻辑」**经复核属实**：spec 七条 Requirement 里没有任何一条谈"回收"，代码里则明确写着"不回收"。

### 现网证据（propose 期实跑，非推断）

对 `1-转型规划/0-全景路线图/跨桌任务队列-{业务场景,机制环境,归档-202607,归档-202608,归档-202609}.md` 五份文件，用 `^\|\s*(\d+)\s*\|` 提取全部表格行首编号，与 `1..498`（当前 §一 高水位线 ＝ #498）取差集：

- **命中编号 489 个，缺口 9 个：`187 / 215 / 216 / 303 / 348 / 356 / 367 / 409 / 496`**
- 9 个缺口**全部 > 166**（§四 高水位线 ＝ #166）⇒ 全部落在 §一 编号空间，不存在"§四 有这行、被合并统计掩盖"的可能。

🔴 **如实标注取证边界，不过度归因**：本包**不主张**这 9 个空洞全部由"预留后未落盘"造成——行被删除、行头损坏解析不出编号、历史清扫遗留都可能产生同样的表象，本次**未逐个归因**。这份取证只支持一个较弱但足够的结论：**编号空洞在现网真实存在且仍在产生**（`496` 距当前高水位线仅 2），而"预留后从未落盘"是其中一条**已被 `#487` 子项三实证过的同族成因**。

### 为什么必须机守（元判据复用，不新造）

Shao Peishen 2026-09-02 元判据：**「如果能做，就不要指派手工——会带入失误。」**

- **有咽喉**：`acquire --reserve` 与 `release` 是编号进出的唯一正门，`reserved_map` 已经写在锁文件里、release 已经在读它做校验③ —— **判定"本次预留了哪些、落盘了哪些"所需的两份数据，此刻都已经在手边**，不需要新采集任何东西。
- **人守已实证失效**：`#487` 子项三那次撞号，是在两条线都合规、两个工具都正确的前提下发生的；靠"记得回收"这类人守，形态与它完全同构。
- ⇒ 该做机器动作。

### 本次退休哪一个既有守卫（协议〇.9 措施 B，机制类变更包强制回答）

🔴 **如实答：本包不退休任何守卫，并论证为何不能退——但本包同时不是"再加一道闸"，方向相反。**

1. **没有一道闸被拆**：release 的校验①-⑨（组内重复／归档号重复／预留归属③／断言门槛④／持有一致性⑥／WIP 上限⑨／opener 守卫／登记完整性⑹）**一条不动**。本包新增的是一个**回收动作**（回退高水位线），不是一条拒绝判据；它**不会拒绝任何此前能通过的 release**。
2. **确实退休了一条既有"设计断言"，且如实标注它不是守卫**：`_reserve_ids` docstring 里那句「本函数不做任何『释放未用编号』的操作，调用方也不需要」，以及两条钉死"不回退"的单测断言 —— 这三处是本包**必须反转**的既有结论。它们是**设计说明与回归钉**，不是门禁；把它们包装成 one-in-one-out 已履行是**不诚实的**，故此处如实标注。
3. **为什么反而不能借机加闸**：一种"顺手"的写法是让 release 在发现未落盘预留时**拒绝释放**（逼人当场用掉或说明）。**本包明确不这么做**——回收的价值是"省一个号"，而 release 被卡死的代价是整条线停摆（`#487` 行内已有 K2 阻断闸"不能把来关行的 session 也挡在门外"的同构教训）。为一个号的空洞去换一次停摆，方向反了。这一条已固化为 `design.md` 决策点 ③ 的推荐理由。

### 伴生文件的 `.gitignore` 覆盖（强制段）

**分两种情形，且两种都已用 `git check-ignore -v` 实跑核实，不是推断：**

- **推荐方案（`design.md` 决策点 ② (a) 高水位线尾部回退）＝不新增任何自动生成文件形态。** 回收动作只改写队列文件顶部那一行既有的「编号高水位线」标注（该文件本就在版本库内、本就每次预留都被改写），不写台账、不写快照、不写日志、不做重命名退路。
- **若 design 审改选 ② (b) 空闲号台账**，则会凭空造出一种此前不存在的文件名形态。**实测两个候选落点均已被覆盖**：
  - `git check-ignore -v reports/queue-reserve-freelist.jsonl` ⇒ `.gitignore:41:**/reports/`（退出码 0）
  - `git check-ignore -v reports/x.editlock.freelist` ⇒ `.gitignore:41:**/reports/`（退出码 0）；另 `.gitignore:69` 的 `*.editlock*` 通配（#328② 合并后）本身即覆盖任意 `<目标>.editlock.*` 派生物。
  - ⇒ **若选 (b)，台账落点 MUST 限定在 `reports/` 或 `*.editlock*` 两个已覆盖形态之内**，不得另择路径。此约束已写进 `tasks.md` 0.x 前置闸，不靠人记。

## What Changes

- **① `release` 新增"回收本次未落盘预留编号"动作**：结构校验全部通过之后、写 released 标记之前，比对 `reserved_map`（本次实际预留到的编号）与两份队列文件 §该分区此刻的可见行编号，得出**本次预留但未落盘**的编号集合，并按 design 决策②的机制把它们交还编号空间。
- **② 回收前置等值核对（fail-safe 而非 fail-closed）**：只有当目标文件此刻的 §该分区高水位线**仍恰好等于本次预留到的最大号**时才回收；不等即说明期间另有写入（绕锁写入 `#200`／`#233`、陈旧锁接管、`预留豁免：` 手工抬线 `#493` 均属此列）⇒ **跳过回收并打印一行告警，release 照常通过**（决策点③）。
- **③ 「留待下次落盘」的显式声明通道**：新增 `--keep-reserved` 声明，供"本次取号、下次持锁再落行"的跨桌用法保留编号，不被回收（决策点④）。
- **④ `--reserve-multi` 部分失败回滚路径一并回退已推进的分区**（决策点⑥）——该路径下 acquire 整体已回滚、锁已释放，不可能有任何行落盘，是 ⑵ 下最干净的一例。
- **⑤ 回收留痕**：回显 ＋ 写进锁 `history`（决策点⑦）。高水位线那一行的回退本身在 `git diff` 里长期可见，长期证据无需另建载体。
- **⑥ 口径落点**：协议〇.8「编号永不复用」的措辞按 design 决策①处理（改正文 or 只改代码注释与 spec）。
- **不改动**：release 的既有校验①-⑨与 opener 守卫、登记完整性；`_reserve_ids` 的 fail-loud 原则与碰撞检测；`--reserve`／`--reserve-multi` 的参数校验与互斥规则；`工具-opener生成.py` 的 `--op-id` 查重（op-id 侧的 ⑵ 只需一句纪律，边界见「不做什么」）。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

1. **本流程哪些判断是人脑默会经验？**
   - **「这个预留号到底还会不会被用」**——此刻完全靠取号那个人的意图，机器无处可读。规则/阈值/例外/尺度四项都只在人脑里：**规则**＝正常应在同一次持锁内落行；**例外**＝跨桌取号（Cowork 取号写进 opener、CC 后续持锁才落行），这条例外目前只能靠 `预留豁免：` 逃生阀事后补救，`#493` 已实证它会把高水位线拉到滞后状态；**阈值**＝陈旧锁 30 分钟之后算不算"放弃"；**尺度**＝"落盘"是指落成队列行，还是号出现在任何文件里都算。
   - **「空洞要不要紧」**——协议〇.8 的绝对措辞「编号永不复用」此前从未被追问过它保护的到底是什么。本包把它显性化为一句可判定的话：**它保护的是「曾经存在过的行的编号不被二次分配」，而不是「高水位线只增不减」**（判别见 `design.md` 决策点①）。
2. **由谁显性化？** 决策人 **Shao Peishen**（design 审拍板七个决策点，本包止步起草、不代拍板）；CC 建造车间负责回收接线、单测与两条既有断言的反转；backup ＝ 下一位领取 `#487` 的 session，可凭本包 ＋ `design.md` ＋ `队列行日志/#487.md` 独立复核（判据正本恒在 `工具-共享文档编辑锁.py`，任何人可现取比对）。
3. **用什么方法提取？** **历史真实案例反推**（`#487` 子项三 `OP-0906-D` 同日两取的实撞；`#493` 预留豁免致高水位线滞后的实撞）＋ **现网只读取证**（本次 propose 期已跑：五份队列文件全量行首编号提取，9 个空洞见 §Why）。不涉及 LLM 判断，纯集合运算与整数比较。

## 验收与晋档条件（强制，四档口径）

- **本变更包交付后场景所处档位**：跨项目治理机制，非独立业务场景，套用最接近的描述 ＝ **档1 mock 验证**（design 审通过、回收接线与单测完成、对现网只读回归跑过，但尚未在生产真实回收过一次编号）。
- **晋下一档（档2 真实数据跑通）的条件**：
  1. 真实发生一次回收（**不是单测构造的临时队列**）：某次 `acquire --reserve N` 未写满，`release` 回退了高水位线，且该动作在队列文件的 `git diff` 里可见。
  2. **紧接着的下一次 `--reserve` 真的取到了被回收的那个号**，且该号成功落成一行、release 通过校验③ ⇒ 证明"交还"是真的交还，不是只改了个数字。
  3. **等值核对分支至少被走过一次**：构造或遇到一次"高水位线已被他人推进"的情形，确认 release **跳过回收但照常通过**，且告警文案足以让人知道跳过了什么。
  4. 🔴 **零回收不得读成"机制已生效"**——若交付后长期无回收发生，正确表述是「**未被检验**」。判据同 `editlock-write-side-date-guard` 与 `editlock-credential-shape-guard` 两包已确立的口径，本项目已有同形教训（根 `CLAUDE.md` §四 #58／#122）。
- **价值指标**（风险型 ＋ 质量型）：
  - **风险型**：编号空洞新增速率。**基线 ＝ 现网 `1..498` 中 9 个 §一 空洞（`187/215/216/303/348/356/367/409/496`），其中 `496` 产生于高水位线 `498` 之前不久**（propose 期实测，见 §Why）。目标 ＝ 上岗后新增空洞中"预留未落盘"这一成因归零。
  - **质量型**：`预留豁免：` 逃生阀的使用次数——若回收 ＋ `--keep-reserved` 覆盖到位，跨桌取号不再需要靠事后逃生阀补救（`#493` 那一类），该标记的新增次数应下降。**基线须在 apply 期用 `git log -S` 实测后写死，不得凭印象填。**
  - 基线由 Shao Peishen（本机制的业务 Champion）确认。
- **LLM 判据黄金集**：不适用（纯集合运算与整数比较，无 LLM 运行时判断）。

## 已知残余风险（如实写明，不粉饰）

1. **推荐方案只回收"尾部连续段"，不回收中间空洞**（决策点② (a)）。预留 `303/304/305`、只落 `303/305` 时，`304` 仍然是永久空洞。**如实措辞**：交付后的回显与汇报只能写「**已回收本次预留中未落盘的尾段编号 N 个**」，**不得**写成「预留号不再产生空洞」。真要覆盖中间空洞，只有决策点② (b) 的空闲号台账一条路，而它的代价是引入**第二个编号真相源**——这正是本项目反复付学费的形态（`#312` 判据分叉、`#487` 子项一 `--dont` 两处不同步）。
2. **等值核对是"当下一致"，不是锁**。回收发生在持锁窗口内，但**绕过编辑锁的直接写入本包看不见**（`#200`／`#233` 已实证这类写入真实存在）。若有人在本次持锁期间绕锁抬高了高水位线，等值核对会命中并跳过回收 ⇒ **本包在这种情形下退化为现状（留空洞），不会产生错误结果，但也不会产生正确结果**。这是刻意选的方向（跳过 > 猜），代价如实。
3. **陈旧锁接管路径不回收（决策点⑤推荐 (b)）⇒ 空洞的最大来源可能仍在**。异常退出的 session 从不走 release，它 `reserved_map` 里的号必然未落盘 —— 这恰恰是空洞最典型的来源，而推荐方案**只报告不回收**。理由是"前一位是否真的死了"只有 30 分钟这个时间启发式做依据，**回收错了的代价是撞号（不可逆方向），不回收的代价只是留空洞（＝现状）**。⚠️ 但这意味着**本包上线后空洞仍可能持续产生**，验收时不得把"还有空洞"读成"机制没生效"。
4. **op-id 侧的纪律尚无载体（待派工残项）**。⑵ 在 op-id 那一侧只差一句纪律，但本包按边界不做 ⇒ **在那句纪律落进某个载体之前，`OP-0906-D` 那一类同日撞号仍会发生**。这一条须在 design 审时一并交代给 Shao Peishen，由他决定另立队列行还是并入 `#487` 收尾（本包不代他决定）。
5. **两条既有单测断言反转后，回归网在这一段是空的**。apply 期改这两条测试的那一刻，"不回退"这个行为不再有任何测试守着；若回收逻辑本身有 bug，**表现形式是编号被错误交还然后被二次分配**——即撞号，不可逆方向。⇒ `tasks.md` 要求新增测试必须**先写、先红**，再改既有两条断言（先测后实现，同 `#474` 已确立的做法）。
