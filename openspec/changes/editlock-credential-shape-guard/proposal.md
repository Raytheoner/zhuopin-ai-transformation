## Why

### 病灶不是"谁不小心"，是载体属性

2026-08-24 记录「IT 对应的群 ＝ 运维部AI保障群」这条答复时，一条**真实且当时仍然有效**的企微 webhook（连 `key=` 参数）被逐字粘进队列 §一 `#351` 行内，随后进了 git 历史。§四 `#118` 已把成因钉死，原文：

> **队列文件的本职就是「把对话原样留痕」，而原样留痕与凭据隔离天然冲突 —— 不是谁不小心，是载体属性，所以只能靠机制拦。**

⇒ 这条不可能靠「下次注意别粘 key」这类人守纪律防住：**要留痕的那个动作，和要隔离的那个内容，是同一次粘贴**。

### 现有防线是事后的，而且已实证"没真挡住"

现存唯一覆盖面是 CI job `凭据扫描`（`0-学习与工具/工具-密钥扫描lint.py`）。它的两条硬边界，`#118` 已如实登记：

1. **事后**——扫的是已 commit 的 checkout，凭据要先进版本库才可能被它看见；`#118` 的真实后果正是「原值仍在 git 历史里可完整取回」，而**历史已裁定不清洗**（轮换后旧 key 即失效，清洗＝重写全部 commit hash，代价远大于收益）。⇒ 一旦写进去，就只剩"轮换"这一条昂贵且需 Shao Peishen 本人操作的补救路径。
2. **红了两个多月没人看**——`#118` 原文：「这次是 CI 门禁替人挡下的，但它红了两个多月没人看，所以也没真挡住」。⇒ 一道**需要人去看**的事后门禁，在本项目已有实测的失效数据，不是理论风险。

### 为什么必须机守（元判据复用，不新造）

Shao Peishen 2026-09-02 的元判据：**「如果能做，就不要指派手工——会带入失误。」** 先问有没有咽喉，再问既然能为什么还派给人。

- **有咽喉**：`edit-row`／`append-row` 是队列写入的唯一正门（协议〇.7），`#455` 已在同一处成功挂上三条判据，挂载模式是现成的。
- **人守已实证失效**：`#118` 一次真实泄漏 ＋ 事后门禁两个月无人看，两条都是实测数据而非假设。
- ⇒ 该做机器判据。**这也是本包不采用「给操作者一条 checklist」的原因**——checklist 正是这条元判据要淘汰的形态。

### 本次退休哪一个既有守卫（协议〇.9 措施 B，机制类变更包强制回答）

🔴 **如实答：本包不退休任何守卫，且论证为什么不能退。**

- **`工具-密钥扫描lint.py`（CI `凭据扫描` job）不能退**——它与本包**作用面不重叠**：它扫**全仓库 1465 个已跟踪 `.md` ＋ 全部代码/配置文件**，覆盖大量**不经编辑锁写入**的路径（人直接编辑器改文件、脚本生成、`git add -f` 带进来的 `.env`）；本包只覆盖「走了 `edit-row`／`append-row` 这个正门」的写入。**退掉它 ＝ 把所有不走正门的写入全部裸奔**，与本包的目的相反。二者是「事前正门闸」与「事后全仓兜底」的分工，不是重复。
- **`#99⑶` 值周逐 job 巡检不能退**——它兜的是「CI 红了没人看」这个失效模式本身，作用面是**所有** CI job，不只凭据扫描。
- **确有一条被本包功能性取代的"人守条目"**：`#118` 遗留的「以后记得别把 key 粘进队列」这一条**从未被写成正式规则、只存在于 `#118` 行内的叙述**。本包上岗后它由机器承担 ⇒ 按「规则退休制」精神，apply 期在 `#118` 行内追加一句指针说明该人守面已被机器接管（**不改历史正文，只追加**）。**如实标注：这不是一条"删掉一段代码"的退休，是一条口头纪律的机械化**，不宜包装成 one-in-one-out 已履行。

### 伴生文件的 `.gitignore` 覆盖（强制段）

**不适用——本变更不新增任何自动生成文件。** 本包只在两个既有子命令的既有执行路径上插入一段**纯拒绝逻辑**（命中即 `print` ＋ `return 1`），不写锁、不写快照、不写日志、不写暂存、不做任何重命名退路。核实方式：改动清单见 §Impact「受影响代码」，其中无任何 `write_text`／`open(..., "w")`／`rename` 新增调用点；apply 期须在 tasks 2.x 完成后用 `git status --porcelain` 实跑一次单测与一次真实拒绝，确认工作区不出现任何新文件名形态（**不是推断，是实跑**）。

## What Changes

- **① 写入侧新增「凭据形状即拒」闸**：`cmd_append_row`／`cmd_edit_row` 在写盘前，对**本次新写入的每一个单元格值**跑一遍凭据形状判据；命中即**拒绝本次写入、不修改目标文件**，并**点名具体命中了哪条规则**（规则名 ＋ 命中所在的列名）。
- **② 判据来源＝复用 `工具-密钥扫描lint.py`，不重写第二份**：按 `#455` 已确立的 `_load_opener_lint_module()` 同款动态加载模式（文件名含中文/连字符，不能直接 `import`），从 lint 本体读取 `CREDENTIAL_PATTERNS`（AWS Access Key／私钥文件头／Anthropic API Key／企微 webhook 真实 key 参数）**及（若 design 审拍板扩面）`GENERIC_ASSIGNMENT_RE` 那一族**。🔴 **不复制正则字面量到编辑锁里**——判据正本恒在 lint 本体，取不到即 **fail-loud**（同 `_load_opener_lint_module` 惯例，不回退成本地简化版）。
- **③ 拒绝文案给出路**：固定包含「**凭据请落 `.env`，队列只写指针**」，并给出可照做的替代写法（例：写 `见 .env 的 WECOM_WEBHOOK_URL_OPS`，不写 URL 本体）。
- **④ 回显做减法**：拒绝文案**不回显完整命中串**（拒绝提示会进终端 scrollback、可能被粘进别处），只回显规则名 ＋ 列名 ＋ 命中串的前若干字符（具体位数见 design 决策点③）。
- **不改动**：`0-学习与工具/工具-密钥扫描lint.py` **本体一行不动**（派单件「不做什么」第一条）；`cmd_edit_row`／`cmd_append_row` 内 `#455` 三条判据与其余校验；release 结构门禁；`acquire`／`release` 的 `--note` 通道（边界理由见 design 决策点④）。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

1. **本流程哪些判断是人脑默会经验？**
   - **「这串东西是凭据还是指针」**——此前完全靠写队列的人当场用眼判断。`#118` 实证该判断在真实场景下会失败，且失败一次的代价是不可逆的（进了 git 历史、已裁定不清洗）。本包把它显性化为**一组可执行的形状规则**，且规则正本与 CI 用的是同一份。
   - **「凭据的正确落点是哪儿」**——「落 `.env`、队列只写指针」这条口径此前只在 `#118` 与 `.env` 相关讨论里零散存在，**没有任何一处会在你写错的那一刻告诉你**。本包把它显性化进**拒绝文案本身**（出路随拒绝一起给出，不要求任何人事先记住）。
2. **由谁显性化？** 决策人 **Shao Peishen**（design 审拍板五个决策点，本包止步于起草、不代拍板）；CC 建造车间负责判据接线、单测与现网只读回归；backup ＝ 下一位领取 `#480` 的 session 可凭本包与 `design.md` 独立复核（判据正本在 `工具-密钥扫描lint.py`，任何人可现取比对）。
3. **用什么方法提取？** **历史真实案例反推**（`#118` 一次真实泄漏，非构造假设）＋ **现网全量只读取证**（本次 propose 期已跑，见下）。不涉及 LLM 判断，纯正则/字符串规则。
   - 🔴 **propose 期已完成的取证（实跑，不是推断）**：对 `git ls-files` 列出的**全部 1465 个已跟踪 `.md`** 各跑两遍——`CREDENTIAL_PATTERNS` 四条结构化规则 **命中 0 处**；`GENERIC_ASSIGNMENT_RE` 通用启发式（含 lint 同款占位符/标识符/长度过滤）**命中 0 处**。⇒ **两种判据范围今天的假阳性面都是零**，决策点① 的选择不会在上线当天误伤任何现网内容。⚠️ **边界如实写明**：该取证只覆盖**当前 checkout 的已跟踪 `.md`**，不覆盖 git 历史、不覆盖归档件之外的其它文件类型、更不覆盖**未来**会被写入的内容——「今天零命中」只能支持「今天不会误伤」，**不能**支持「这个判据范围永远不会误伤」。

## 验收与晋档条件（强制，四档口径）

- **本变更包交付后场景所处档位**：跨项目治理机制，非独立业务场景，套用最接近的描述 ＝ **档1 mock 验证**（design 审通过、判据接线与单测完成、对现网全量 `.md` 只读回归跑过，但尚未在生产真实拦下过一次凭据写入）。
- **晋下一档（档2 真实数据跑通）的条件**：
  1. 真实发生一次凭据形状写入被本闸拒绝（**不是单测构造的假 key**），且拒绝文案足以让操作者当场知道命中了哪条规则、该改成什么写法。
  2. 该次拒绝之后，同一内容以「指针写法」成功写入队列 ⇒ 证明出路是**真的可走**，不是一句话。
  3. 🔴 **零命中不得读成"规则已生效"**——若交付后长期无命中，正确表述是「**未被检验**」。判据同 `editlock-write-side-date-guard` proposal 已确立的口径，本项目已有同形教训（根 `CLAUDE.md` §四 #58／#122）。
- **价值指标**（风险型）：凭据进入版本库的**可能路径数**——基线 ＝ 走正门写队列这条路完全无闸（`#118` 实证可通行）；目标 ＝ 该路径被机器闸拦住，且拦截理由与 CI 事后扫描同源（判据不分叉）。
- **LLM 判据黄金集**：不适用（纯正则/字符串规则，无 LLM 运行时判断）。

## 已知残余风险（如实写明，不粉饰）

1. **覆盖边界必须如实措辞**：本闸只覆盖「走 `edit-row`／`append-row` 正门」的写入。**任何绕过正门的写法（编辑器直接改文件、脚本整文件重写、`--file` 指向别处）本闸看不见**。⇒ 交付后的回显与汇报措辞只能是「**已校验本次经正门写入的 N 个单元格值**」，**不得**写成「队列已不可能进凭据」。（同 `_opener_guard_violations` 的 D2 覆盖边界声明范式。）
2. **形状判据的本质是形状**：它拦的是**长得像凭据的字符串**，拦不住「一段自然语言把 key 拆成四段中文描述」这类改写，也拦不住形状不在四条规则内的新型凭据（如未来引入某第三方服务的自有 token 格式）。⇒ 新增外部凭据类型时须回到 `工具-密钥扫描lint.py` 补形状规则——**本包的价值之一正是让"补一处"同时惠及 CI 与写入闸**，但这也意味着**漏一处会同时漏两边**。
3. **判据正本取不到时 fail-loud 会让写入整体不可用**：若 `工具-密钥扫描lint.py` 被移动/重命名/语法错误，本闸按惯例 fail-loud ⇒ `edit-row`／`append-row` 直接报错退出，**队列写入在修好之前不可用**。这是刻意选的（fail-closed 优于静默放行），但代价真实：apply 期须确保错误文案直接点名"判据正本文件路径 + 该怎么修"，不能只抛一个 traceback。
4. **本包不覆盖 `--note` 与锁文件**：`acquire`／`release` 的 `--note` 会进 `*.editlock` 锁文件。**已实测该文件被 `.gitignore` 覆盖**（`git check-ignore -v` 实跑：`.gitignore:69:*.editlock*`）⇒ note 内容不进 git，风险面低一档。但 note 会被回显、可能被人再粘进队列行 ⇒ **本包不隐含"note 已安全"**，如需覆盖须另立行（见 design 决策点④）。
