## Why

**一句话根因**：**串行闸想问的是「他手上还有没有一封没了结的信」，而它实际比的是「收信人这一格的字符串长不长得一样」。**

`#124` 已经点破了这一条，并给出了本包最该被记住的判据——**「本次是误拦所以被看见了；误放不会有人看见」**。本轮做的事很简单：**把没人看见的那几次数出来。**

### 实测二：`#124` 未预见的更宽形态——「最近一封」也有两把尺子，且**此刻正在给出相反答案**

`#124` 只说了「收信人匹配口径不一致」。实测发现还有第二层分岔：**「哪一封是最近一封」这个定义本身，生产里也有两份不一样的实现。**

- **闸侧（release 闸 ＋ 闸查询）**：按 README **物理行序**取该收信人最后一行。
- **`followup_gate._letter_sort_key`（配对侧）**：按 **（日期 → 编号序号 → 行序）** 排序取最大，其 docstring 明写「⚠️ **不能只按表内行序**：实测 `采购部#4`（07-21）排在 `采购部#17`（08-20）之后——README 的物理行序不是时间序」，且 `latest_dispatched_letter` 的 docstring 自称「**与跟进闸同一把尺子**」。

**实测：这句自称不成立，而且现在就不成立。**

| 收信人 | 按物理行序最后一行 | 按排序键最新一封 | 一致？ |

🔴 **如实登记：这一例的结论碰巧是对的。** `质量部#13` 交期要点写「知会性质，不用回复」，它本应是 `✅ 无需回复`（闭环态），只是被发送脚本回填成 `✅ 已推送` 覆盖掉了——**正是 `质量部#7` 行内已记着的那个已知漏洞**（「起草时判定了、发送时被机器抹掉了」）。**但闸的开合建立在一把它自己都说了不该用的尺子上这件事，不因这次侥幸而改变**（同 `followup-closure-evidence-gate` 里那次「碰巧是对的」）。

### 实测三：豁免正在被机器批量制造，且单调增长（`#482` ④ 的真正对象）

`#482` ④ 写的是「删掉 `质量部#10` 行内那段名不副实的豁免」。**本轮实测发现它已经不是一行，也不是人写的：**

`0-学习与工具/工具-跟进信README行长外置.py:282` 有一个常量：

```
SERIAL_WAIVER_REASON = "D3 行长外置压缩摘要，非新起草跟进信"
```

它在压缩「主要事项」列时**自动往「交期要点」列写入** `串行豁免：D3 行长外置压缩摘要，非新起草跟进信`。

- **成因**：行身份 `_followup_row_identity` ＝「除状态列外的全部单元格」。压缩正文即改变身份 ⇒ 一次**纯历史内容压缩**被串行闸判成「新起草的跟进信」⇒ 工具只能写一条豁免把自己放过去。该工具自己的 docstring 已如实记下这是「D3 外置动作与既有串行闸机制的一处真实交互缺口（design.md 撰写时未预见）」。
- **现网存量 5 行**：`采购部#12`／`IT部#8`／`质量部#7`／`质量部#10`／`质量部#12`，五行的豁免理由**逐字相同**。
- **它会长**：每压缩一行长行就多一条，无上限、无到期。

🔴 **而豁免的判据是 `任一单元格含「串行豁免：」即放行`——不问理由说的是什么。** 那句理由讲的是「本行是压缩摘要、不是新起草跟进信」，**语义上根本不是一次串行豁免**；但它在机器眼里是一个**永久、无条件、可被后续任何编辑复用**的开闸口令。

⇒ **`#482` ④ 若只删 `质量部#10` 那一格，等于什么都没做**：下一次行长外置会原样写回来，而另外 4 行原封不动。

### 本次退休了哪一个既有守卫（协议〇.9 措施 B，机制类变更包强制回答）

**退休三处实现 ＋ 一条自动写豁免的路径 ＋ 一条人守，净减。**

1. **退休：`工具-跟进信README行长外置.py::_find_serial_gate_conflicts` 这份复刻实现**（上表 #4）。它复刻的是 #1 的逻辑，因此**逐字继承了 #1 的匹配缺陷**，而它的产物是往生产 README 里写开闸口令。退休后改为调用权威判据。
2. **退休：`SERIAL_WAIVER_REASON` 这条自动写豁免的路径。** 🔴 这是本包唯一一处**净减逃生阀**，而且减掉的是一个**会自我增殖**的逃生阀——同族里最该先退的一个。
3. **退休：`_validate_followup_readme_release` 里那段整格逐字的收信人比对**（上表 #1 的匹配半边）。改判方向由 `#124` 已裁决（统一到归一化），**本包不重新提问**。
4. **退休（人守）：`#124` 截止段那条**「在裁定前，凡新增跟进信行务必让收信人列与该收信人前一封**逐字一致**」。本包让它成为多余 ⇒ 直接删，不留。**这是净减一条人守，符合「把人守挂到咽喉上，而不是再加一条人守」。**

**降级不退休**：`串行豁免：` 逃生阀本身**保留**。它服务的是真实场景（并行跟进两条线）；本包只掐掉「机器自动写它」这一条产出路径，不动人写的那条。

### ③ `❌ 已作废` 补防滥用判据（`#482` ⑶，`#90` 裁决的遗留项）

`❌ 已作废` 目前是一条「不想等回件就把前信标作废、闸即打开」的捷径。补**按风险分档**的判据（design **D4**）：

| 转态前（取自 acquire 快照） | 风险 | 要求 |
|---|---|---|
| 未发出（`⏳ 待你审`／`🆕 待发`／`⏸ 暂缓`）→ `❌ 已作废` | 低（信从没占过闸） | 写明理由即可 |
| **已发出且未闭环** → `❌ 已作废` | 🔴 **高——正是那条捷径本身** | 理由 ＋ **可核凭据**（队列行号／§四 决策号）＋ 不得命中开闸措辞 |

🔴 **诚实登记**：现网主表 `❌ 已作废` **零行**，归档件里 1 行（`销售部（未发，不编号）`，2026-08-04，属低风险档且理由充分）。**本项是预防性加固，不是在修一次已发生的滥用**——加固的理由是「捷径存在且使用成本为零」，不是「已被滥用」。

### ④ 停止机器制造豁免 ＋ 清理存量（`#482` ④，实测三）

- **停产**：行长外置不再写 `串行豁免：`。根治方案两选一，**须 design 审拍板**（design **D5**）——(a) 行身份改用**编号列主键**（根治整类「改了任一非状态列就被判成新增行」的误报）；(b) 新增**专用**标记 `行长外置：`，只对「本次只压缩了主要事项列、其余列逐字不变」这一可机器验证的形态放行。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

**1. 本流程哪些判断是人脑默会经验？**

1. **「这两行是不是写给同一个人的」** —— 人一眼就知道 `质量部 · 陈忱` 与 `质量部 · 陈忱（可请朱映桦先初标）` 是同一个人，而机器不知道。**规则**：`·` 之前是部门、之后到第一个括号为止是姓名，括注一律不参与身份。**例外**：括注若写的是**另一个真实姓名**（`（可分担朱映桦）`／`（转汤易水第④项）`），仍**不**改变收信人——信是写给 `·` 之后那个人的。**尺度**：括注表达的是「谁可以分担／转办了哪一项」，不是「这封信改发给谁」。
2. **「哪一封才是他最近的一封」** —— 熟手知道要看日期，不是看行在表里的位置；机器现在看的是位置。**规则**：日期为主、同日多封按编号、都相同才按行序。**这条已经被显性化过一次**（写在 `_letter_sort_key` 的 docstring 里），**但只显性化给了配对侧，闸侧没拿到** —— 本包做的是把它接上。
3. **「这次作废是真的失效，还是不想等回件」** —— 人读一眼理由就知道；机器读不懂。**规则**：作废的正当理由必须指向**信的内容为什么失效**（哪几件事、被什么取代），而不是指向**流程需要**。**阈值**：已发出未闭环的信作废须给出可核凭据行号。**例外**：未发出的信作废属低风险，写明理由即可。
4. **「这条豁免是不是真豁免」** —— `质量部#10` 的起草者当场就知道并写进了行里（「本行不是真的豁免」），而机器把它和一次真豁免同等对待。**规则**：豁免理由必须指向**串行原则本身**（为什么这封可以与前一封并行），指向别的东西（如「本行是压缩摘要」）的不是豁免。

**2. 由谁显性化？** 持有人 **Shao Peishen**（口径来源：2026-09-03 `OP-0903-D` 对 §四 `#124`／`#90` 的两条裁决）；backup **孙涛**（决策代理，可代 design 审，范围见 `.claude/rules/场景建造与合规.md`）。

**3. 用什么方法提取？** **历史案例反推 ＋ L2 改判判例累积**：⑴⑵ 由 2026-08-26 起草 `质量部#10` 时 release 被拒那一次实撞反推（`#124`）；⑶ 由 2026-08-21 判据分裂追认时暴露的捷径反推（`#90`）；④ 与实测二、实测三由本轮对生产真身的结构化复算得到——**四条全部来自撞上，没有一条是设问得来的**。

## 已知边界（必须随交付一起说出去）

1. 🔴 **本包只统一「谁是同一个人」，不改「什么算闭环」。** 闭环四态口径（`#90` 已追认）原样不动；`❌ 已作废` 那一档只加**写入时**的理由要求，**不回溯任何既有行**。
2. 🔴 **`❌ 已作废` 的黑名单判据防手滑、不防蓄意。** 想绕过它的人换个措辞即可。这就是为什么高风险档还要求**可核凭据**——伪造一个队列行号会在值周巡检对账时被查出来，而伪造一句措辞不会。**如实说：本包不能杜绝滥用，只能让滥用留下可查的痕迹。**
3. **实测二那把尺子换掉后，陈忱的闸会立刻从 ✅ 开变成 🔒 锁**（依据 `质量部#13`）。这是**正确的后果**（该行状态列确实不是闭环态），但它会立刻影响质量线起草。真正的修法在另一条线（发送脚本回填不得覆盖闭环态判定），**本包不做**，见 design D3 的处置建议。
4. **归一化会把 `（转汤易水第④项）` 这类括注一并剥掉。** 若哪天有人用括注表达「本封改由某某回复」，归一化会把它仍归到 `·` 之后那个人名下。**这是有意的**（既有口径：括注不改变收信人），但须在 README 里写死「变更收信人 ＝ 改 `·` 之后的那个名字，MUST NOT 用括注表达」，否则本包给了一个新的静默误判面。
5. **本包不解决「行长外置改变行身份」以外的身份误判。** 若 design 审选了 D5(b)（专用标记）而非 D5(a)（编号列主键），则「人手工改了某行的日期列」仍会被判成新增行，仍会撞闸——**那一类没有承接方，须另立队列行**。
