## ADDED Requirements

### Requirement: `❌ 已作废` SHALL 按转态前状态分档校验
把跟进信 README「发送状态」列写为 `❌ 已作废` 时，release 结构校验 MUST 按**转态前的状态**（取自 acquire 快照中同一行）分档：

| 快照中的状态 | 档 | 要求 |
|---|---|---|
| 已是 `❌ 已作废`（本次未变） | — | 不校验（不回溯既有行） |
| 属「尚未发出」三态（`⏳ 待你审`／`🆕 待发`／`⏸ 暂缓`） | 低 | 仅 R1 |
| 其余（已发出，含未知写法） | 🔴 高 | R1 ＋ R2 ＋ R3 |
| 本次持锁窗口内新增、直接写 `❌ 已作废` | 🔴 高 | R1 ＋ R2 ＋ R3 |

判据源 MUST 是 acquire 快照，MUST NOT 依赖 git 历史——回灌与转态发生在同一个未提交窗口内，判定时刻这些改动尚未进入任何 commit。

未知状态写法 MUST 归入高风险档（保守方向，同 `classify_status` 对 `"unknown"` 的既有处理）。

#### Scenario: 未发出的信作废只需写明理由
- **WHEN** 快照中状态为 `⏳ 待你审` 的行改为 `❌ 已作废（该批需求已随销售域推迟整体失效）`
- **THEN** release 放行

#### Scenario: 已发出未闭环的信作废走高风险档
- **WHEN** 快照中状态为 `✅ 已推送 2026-09-01 …` 的行改为 `❌ 已作废`
- **THEN** release 被拒绝，且拒绝文案说明本行走的是高风险档及缺了哪几条

#### Scenario: 既有作废行不被回溯
- **WHEN** 快照中状态已是 `❌ 已作废 …`，本次未改动该单元格
- **THEN** 不做任何校验

### Requirement: 作废理由 SHALL 写明、SHALL NOT 是「为了开闸」、高风险档 SHALL 附可核凭据
- **R1 · 写明理由**：`❌ 已作废` 之后 MUST 有正文。判法 ＝ 归一化状态文本去掉前缀后剥净装饰字符与括号符号，剩余实义字符 **≥ 8 个全角字**。
- **R2 · 不得命中开闸措辞**：理由文本命中 `为了开闸`／`为开闸`／`开闸`／`解闸`／`打开串行闸`／`绕过串行`／`不想等回件`／`不等回件`／`腾闸`／`让闸开` 任一者，MUST 拒绝，且拒绝文案 MUST 指名命中的是哪一个词。
- **R3 · 可核凭据**：高风险档的理由中 MUST 含至少一个可核引用——队列行引用（`§一 #N` 或 `§四 #N`）或 `Shao Peishen <ISO 日期> 答` 形态之一。校验 MUST 只判引用的**存在与形态**，MUST NOT 试图判断该引用说的对不对。

🔴 R2 防手滑、不防蓄意：换个措辞即可绕过，成本近乎为零。有约束力的是 R3——它要求作废理由指向仓库里查得到的东西；伪造一句措辞不留痕迹，伪造一个队列行号会在值周巡检对账时被查出来。本要求的目标不是让机器判断动机，是让动机留下可查的痕迹。

#### Scenario: 理由直书为了开闸被拒
- **WHEN** 已发出未闭环的信改为 `❌ 已作废（为了开闸，先把这封作废）`
- **THEN** release 被拒绝，拒绝文案指出命中的词是 `为了开闸`

#### Scenario: 理由过短且无凭据被拒
- **WHEN** 已发出未闭环的信改为 `❌ 已作废（不需要了）`
- **THEN** release 被拒绝，拒绝文案同时指出 R1 与 R3 未满足

#### Scenario: 真实的合法作废不被拦死
- **WHEN** 某未发出的信改为 `❌ 已作废 · 9 月重写（2026-08-04，队列 #137，Shao Peishen 选 (a) 线下当面说）——信中三件事已全部随销售域推迟失效`
- **THEN** release 放行

#### Scenario: 高风险档带可核凭据放行
- **WHEN** 已发出未闭环的信改为 `❌ 已作废（§四 #137 已改判：该口径整体撤回，本信三件事全部失效）`
- **THEN** release 放行

### Requirement: 高风险档 SHALL 提供留痕式逃生阀
高风险档 MUST 提供与既有 `串行豁免：` 同范式的逃生阀：行内写 `作废豁免：〈理由〉` 即放行，但 MUST 打印留痕提示，MUST NOT 静默通过。

该逃生阀 MUST NOT 自动到期——设自动到期需要一个承接方，而本变更未为它建立承接方；「写下需要动作、却没有承接方」是本项目已被点破的一类形态，不再新增一例。

#### Scenario: 逃生阀放行但留痕
- **WHEN** 高风险档的行内含 `作废豁免：该信涉及的供应商已终止合作，无回件可能`
- **THEN** release 放行，且输出中打印该豁免声明

#### Scenario: 空理由的作废豁免不被接受
- **WHEN** 行内含 `作废豁免：` 且其后无任何文本
- **THEN** release 被拒绝

### Requirement: 本判据 SHALL NOT 回溯既有行，且上线命中数为零 SHALL 被如实说明
本判据只作用于**本次持锁窗口内发生的写入**，MUST NOT 扫描或阻断任何未被本次改动触碰的历史行。

实测（2026-09-07）：生产主表 `❌ 已作废` 为 **0 行**，归档件 `README-归档-202609.md` 中 1 行（属低风险档、R1 与 R3 均满足）。⇒ 本判据上线当天命中数为 0，它是**预防性加固**，不是在修一次已发生的滥用。该事实 MUST 随交付一起说出去，MUST NOT 被表述为「修复了一处滥用」。

#### Scenario: 未触碰的历史作废行不产生任何输出
- **WHEN** 本次持锁窗口只改动了别的行
- **THEN** 既有 `❌ 已作废` 行不产生 violation、不产生告警
