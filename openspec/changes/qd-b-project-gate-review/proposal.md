## Why

质量部项目立项评审目前全靠评审委员/PMO 人工逐项核对 82 项规则——耗时、口径不一、跨模块勾稽（人月/成本/收入/毛利率/ASIL）易漏。陈忱团队已把开发类立项门禁沉淀为 **82 条机器可核规则 + C01–C10 跨模块校验 + 真实立项书逐条试评（华丰 EPA 项目）**，这是可直接落地的强 design 输入。本场景（QD-B，质量旗舰 Q6）把这套规则交给数字人做**逐项预审**，出立项审核报告供评审委员会/PMO 复核，是质量域 off-LAN 友好、风险可控的旗舰之一。

权威规格：`7-外部文档/质量部/AI质量智能建设就绪工作汇总.xlsx`（「立项门禁」82 条 + 「规则说明（开发）」字段级 + 「封面」合格分级/严重度）；取数锚点：`7-外部文档/质量部/EQQR8082立项申请书（开发类）-A2.1.xlsx`。

## What Changes

- 新建场景工程 `4-数字员工/质量部/QD-B-立项审核门禁/`，`pip install -e` 平台底座（CLAUDE.md §4/§6）。
- **解析探针先行**：从合并单元格 Excel 表单（A1:Z145、大量 merge）按**章节标题文本锚点**（非绝对单元格坐标，抗模板改版——一月内已 A0→A2.1 四版）抽取 13 模块字段为结构化模型；先验字段抽取准确率，再谈规则判定。
- **确定性规则引擎**：把「立项门禁」页 68 条 A 类「可机器核」规则（必填/格式/日期逻辑/数值勾稽/一致性/合规阈值）+ C01–C10 跨模块一致性校验转译为纯函数，每条一夹具单测（先测后实现）。
- **半自动语义判定**：10 条 B 类规则（立项依据"是什么/什么用途"、目的/意义、目标分类/指标量化、交付物-指标对应、职责对应、技术/商务总结）走 LLM，输出命中/未命中 + 证据片段 + **二级置信度**（对齐 SC8 高/低口径），**低置信默认标"需人工复核"不擅断**。
- **转人工 4 条**（C 类：应对措施有效性、双签字、立项决议）AI 只验"在/不在"，不下结论。
- **三档立项审核报告**：合格 / 有条件合格 / 不合格 + 阻断项清单 + 警告/提示逐条（规则ID/章节/检查项/判定/证据/修改建议）+ 跨模块校验结果 + 转人工待办 + 审计元数据（模板版本/规则版本/时间戳）。报告标注 **"AI 预审建议，立项决策在评审委员会"**。
- **L2 门禁**：AI 结论非终局，评审委员会/PMO 复核确认才生效（PRD D1 红线）；规则重大调整走黄金基准回归。
- **全链审计**：每份审核报告（AI 预审 + 复核 + 最终判定）写平台 `audit`（append-only / 3 年），关联立项文档版本 ID（IATF 8.3 可追溯）。

**MVP 范围（Paul 2026-06-27 定）**：只做**开发类 `EQQR8082` A2.1**（有真实试评闭环）；研发类 `EQQR8106` A3 规则书已备好但**二期再做**，本期不实现。

## Capabilities

### New Capabilities
- `qd-b-intake-parser`: 立项书解析——合并单元格 Excel 表单 → 13 模块结构化字段模型，章节标题锚点取数 + 模板版本识别 + 字段抽取置信/缺失标记；含"解析探针"先验环节。（doc_parser 当前**仅 QD-B 一个真实消费方**——QD-A/8D 尚未建——按 rule-of-three **暂留场景本地**，第 2 真实消费方出现再提升进 `shared_tools`。）
- `qd-b-rule-engine`: 确定性规则引擎——「立项门禁」68 条 A 类规则（完整性/合规性/计算准确性/一致性/逻辑合理性）+ C01–C10 跨模块校验，纯函数 + 夹具单测，每条产出 {规则ID, 判定, 证据, 严重度, 修改建议}。
- `qd-b-semantic-judge`: 半自动语义判定——10 条 B 类规则的 LLM 判定，命中/未命中 + 证据片段 + 二级置信度 schema，低置信转人工。（判定准则为 design 收口项-2，业务方确认后接入。）
- `qd-b-review-gate`: 立项审核聚合与门禁——三档判定逻辑（MVP 起步"错误项一票否决"两档，评分制为可插拔模块）+ 审核报告输出契约 + C 类 4 条转人工 + L2 复核确认 + audit 写入。

## design 阶段停审点（apply 前必须收口，交 Paul + 陈忱/PMO）

- **收口-1 评分扣分细则**：82 条各占几分、扣分/加分制由质量部/PMO 定，非 AI 预设。MVP 先"错误项一票否决"两档（不合格/合格），评分制作可插拔模块后增量接入——否则"有条件合格"档（60≤分<80）产不出来。
- **收口-2 10 条半自动规则判定准则**：每条 LLM 提示词 + 输出 schema + 置信度 + 低置信转人工策略，需陈忱给业务判据（"什么程度算说清了产品是什么"）。
- **收口-3 产品类真实样本**：现唯一试评样本为技术服务类（华丰），产品类专属规则（量产数据 G/H/I/J/K、全生命周期毛利率 P/(D+J)、收益指标 ≥5、C01–C03 部分）写了未跑真实数据，需陈忱补 ≥1 份产品类立项书做试评/黄金基准。
