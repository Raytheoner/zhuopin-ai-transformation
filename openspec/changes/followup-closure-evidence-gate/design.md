## D1. 不新造 `🤖 已归档待拆件`，把既有第九态抬为「机器天花板」

**决策**：opener 提议的新中间态 **不引入**。改为：**第九态 `📨 回件已到，待拆件 <UTC>` 就是机器能写到的最高状态**，桥二的天花板从 `📥` 降到它。

**为什么**：

1. 第九态**逐字表达的就是同一件事**（回件物理到达、已归档、尚未拆件）。它 2026-08-23 已上线、已有 `is_reply_arrived_status` 判据、已有桥一幂等分支、已有 `reply_arrived_cites` 溯源回指契约。
2. 再造一个同义态 ＝ 让人和机器**多记一条规则去说一件已经说过的事** —— 这正是本项目否掉 `回灌完成：` 标记时用过的同一条判断。
3. 一个词只表达一个含义（《专线opener模板库》§〇.2）。两个同义态共存，早晚会出现「有的地方写 A、有的地方写 B」的第二份副本 —— 而「同一事实的两份副本会互相印证着一起错」在本项目 README 的取号段上已经发生过**六次**。

**代价（如实登记）**：opener 里「机器可写／只能由拆件写」这条分界**在字面上不如两个新词直白**。缓解 ＝ 在 README 状态语义正本里把这条分界写成一张表（谁有资格写哪一态），并在 `followup_gate` 的常量段用注释锁死。

**⚠️ 这一条与 opener 原文不同，属本 design 的主动改判，须在 design 审时被明确同意或推翻。**

## D2. 「那些行确实被改过」怎么判 —— 🔴 行内锚点做闸，git 只做事后审计

### 结论

| 用途 | 判据 | 为什么 |
|---|---|---|
| **release 时的同步闸**（决定 `📥` 认不认） | **行内锚点**（`[R:…]` ＋ 被引用行的内容判据） | **那一刻 git 里什么都还没有**（见下） |
| **事后审计**（值周巡检／sweep 常驻告警） | **git pickaxe `-S<锚点>`** | 回答「这条锚点何时、由哪个提交带进来」 |

### 🔴 为什么 git 不能做闸：回灌与转态发生在同一个未提交窗口内

拆件班的动作次序是（拆件巡逻章程 §三）：`acquire` → 改队列行 → `release`（桥二在此刻跑）→ 登 §二 批次 → **落库 sweep 之后某一轮才 commit**。

⇒ **桥二判「那些行改过没有」的那一刻，改动还在工作区、没有进任何 commit。** 用 `git log` 判，结论恒为「没改过」——**一个看起来完全正常的错误结论**，且它会把**正确的**流程全部拦死。sweep 每小时一轮，这个窗口最长可达一小时以上。

**⇒ 时序决定了闸只能用内容判据，不能用历史判据。** 这不是「git 不够好」，是它回答的问题（这件事何时进入历史）与闸要问的问题（这件事现在在不在）根本不同。

### 行内锚点的判据（可机器执行，无需 git）

`📥` 被认可，须同时满足：

1. 状态列以 `📥 已回件并回灌` 开头；
2. 括注中可解析出 **≥1 个队列行引用**（形如 `§一 #427`，可多值）与**≥1 个归档件路径**；
3. 每个被引用行**确实存在**于两份队列真身之一（🔴 逐份解析后合并，**不拼接文本再解析** —— `_split_live_sections` 同名 label 后写覆盖先写，拼接会静默丢掉第二份的 §一，#312 缺口一踩过）；
4. 🔴 **每个被引用行的状态列，剥掉全部机器字段（`[S:…]`／`[D:…]`／`[R:…]`）与空白后，仍非空。**

**第 4 条是唯一让判据非平凡的那一条**，它成立的前提是一条实测事实：**入信行由企微机器人按固定模板建立，模板在状态列只写机器字段、没有正文。** ⇒ 「这一格有正文」＝「机器人之外的某个主体往这里写过东西」。

**⇒ 机器想让终态通过，就得先真的往那些行里写出内容 —— 而它写不出。**

### ⚠️ 第 4 条的两个已知弱点，如实登记

- **它不检验内容质量。** 写一个字也算「写过」。**本判据防的是「机器凭空写终态」，不是「人敷衍」**；后者由拆件报告与值周巡检承接。
- **入信行是自引用的。** 拆件结论写回入信行本身（`§一 #427` 的实际形态）时，被引用行 ＝ 入信行。这**合法且是常态**，第 4 条照样成立（模板态不含正文）。⚠️ 但它意味着**引用去向不构成「结论落到了业务载体」的证明** —— 想要那个，得另立判据，**本包不做**。

### git 侧：能用什么、不能用什么（事后审计）

| 手法 | 可用性 | 失效场景 |
|---|---|---|
| `git log -S"<锚点文本>" -- <队列文件>`（pickaxe） | ✅ **推荐** | 内容判据，**不受行号漂移影响**；锚点被后续编辑改写则查不到，故锚点须取**不会被改写的片段**（归档件文件名，含 32 位 disambiguator） |
| `git log -L<n>,<n>:<file>` ／ `git blame` | 🔴 **禁用** | 队列行号随上方增删漂移，两者会**静默给出另一行的历史**（根 CLAUDE.md §5 已记，`#312` 修法处原文） |
| commit hash 作长期引用 | 🔴 **禁用** | rebase／ff 重放后 hash 全变（落库 sweep 每轮 `_reconcile_with_origin_and_push` 会 rebase） |
| `CommitDate` 判「什么时候做的」 | ⚠️ **不可信** | rebase 会把 CommitDate 全部重写为重放时刻；须用 `AuthorDate`（`%ad`），且**它同样可被 `--date` 覆盖**，只是无人这么做 |
| `git cherry` 判「这个改动不在里面」 | 🔴 **禁用** | 判「不在」不可信（已记于本项目既有结论） |
| 在 worktree 副本里跑 | 🔴 **禁用** | ① `git -C` 会向上找到**祖先仓库**并给出另一个答案且不报错；② worktree 签出可落后 master —— 2026-08-23 实测同一相对路径下 CC 读副本、Cowork 读真身，对 `财务部#15` 给出**相反的事实**，两边都不报错。⇒ 一律经 `git rev-parse --git-common-dir` 解到主工作区（`工具-共享文档编辑锁.py::REPO_ROOT` 已如此），并在路径含 `.claude/worktrees` 时**明确警告读的是副本** |
| 时间比较 | ⚠️ | git 默认输出**本地时刻带 offset**；文件 mtime **本地**；企微审计 jsonl 与第九态里的时刻是**真 UTC**。🔴 任何「回件到达之后」的比较，两侧必须先标基准再比（根 CLAUDE.md §5 硬规则） |

### 🔴 一条一定要写进实现的护栏

**「git 查不到」必须与「git 没查成」严格区分。** pickaxe 返回空有两种含义：真的没有这条锚点，或**仓库路径解错了／文件名写错了／在副本里跑**。前者是结论，后者是故障。⇒ 审计侧一律 fail-loud：查询失败返回 `(None, 原因)`，**绝不返回空列表**（同 sweep `_query_scheduled_task_actions` 的既定手法）。

## D3. 存量：截止日期之前不追改；🔴 但机器代写的四行**不享受**这条豁免

### 三类存量，处置各不相同

| 类别 | 现网实测 | 处置 |
|---|---|---|
| **A. 人手写的历史 `📥`**（桥二上线之前） | 5 行无日期 ＋ 2 行 `2026-08-24` 等 | **不追改**，按旧口径视为已闭环 |
| **B. 🔴 机器代写、状态列含「未经人工逐字确认」** | **4 行**：`IT部#9`／`IT部#10`／`质量部#10`／`采购部#19` | **不豁免**，逐条处置（见下） |
| **C. 20 → 18 封历史未闭环信**（停在 `✅ 已推送`） | 取证清单 `1-转型规划/0-全景路线图/取证清单-README历史未闭环信20封-2026-08-23.md` | **本包不动**，仍挂原线 |

### A 类：不追改的含义（必须明写，不能含糊过去）

判据对截止日期之前的 `📥` 行**降级为「按旧口径视为已闭环」**，并在闸查询输出里**显式标注** `依据：旧口径（无回灌引用）`。

🔴 **这意味着什么，说清楚**：

1. **我们永远不会知道 A 类里有没有第二个 `质量部#10`。** 本机制的保证**从截止日期起算**，对它之前的行**零保证**。
2. 因此**不得**在任何汇报里说「跟进信闭环状态已全部可核」—— 正确说法是「**截止日期之后新增的闭环可核**」。
3. 标注必须出现在**输出里**，不能只写在文档里 —— 否则读输出的人看到的仍是一个不带保留的 `✅ 开`。

**截止日期怎么判（无需 git）**：`📥 已回件并回灌 <日期>` 的状态串**自带日期**，直接用它。**已知弱点**：该日期是写入方填的，可能填错；5 行**根本没有日期**。⇒ 规则 ＝ **无日期一律按 A 类**（保守方向：这些必然是早期人手写的，桥二写入恒带日期）。

**截止日期取值建议**：**`2026-08-28`（本包实撞当日）**，而非桥二上线日 `2026-08-23` —— 因为 08-23~08-28 之间正是 B 类产生的窗口，而 B 类被单独拎出来处置，不需要靠截止日期去覆盖。

### B 类：为什么不能一并豁免

**opener 的建议是「历史行不追改」，若照字面执行，会把本次事故的四个产物一起洗白。** 它们不是历史遗留，它们**就是这次事故本身**，且它们**自带一句机器留下的自白**（「未经人工逐字确认」）。**放过它们，等于本包上线的第一个动作就是给它要修的那件事背书。**

**建议处置（逐条，本包只定口径不执行）**：

- `质量部#10`／`采购部#19` —— **Cowork 已于 2026-08-28 实拆**（拆件件在案）⇒ **补写引用即可转正**，不需要重新判断。
- `IT部#9`／`IT部#10` —— **无人核过**，一律**降回第九态 `📨 回件已到，待拆件`**，进 `🔴 待拆件` 队列等拆。🔴 **降回不是惩罚，是把状态改回它当时真实的样子。**

⚠️ **降回会重新锁上陈承的串行闸** —— 这是正确的后果（回件确实没人拆），但它会**立刻影响 IT 线**。⇒ 列为**需 Shao Peishen 定夺项**（见 tasks §0.2）。

## D4. sweep 常驻告警：🔴 触发与解除一并设计

**复用既有框架，不新造机制**：`工具-落库sweep.py::_track_and_alert_standing_state`（第 4／5 类常驻告警已在用）。

### 判据（key 集合）

`key = 信编号`（如 `质量部#10`）。命中条件 ＝ README 该行状态为 `📥`，**且**满足以下任一：

- 状态列含「未经人工逐字确认」字样（B 类）；
- 或 D2 的四条锚点判据任一不满足，**且**该行日期在截止日期**之后**（A 类不进 key 集）。

### 🔴 key 里绝不放会变的量

**key ＝ 信编号，不含日期、不含小时数、不含行号。** 把会变的数放进 key，每变一次就是一个新 key、天天被当成新问题重新告警，且旧 key 会被判为「已解除」—— **常驻状态与事件的分界线就在这里**（第 4 类告警的注释原文已记）。

### 怎么被关掉（三条，缺一即成噪音灯）

1. **自动解除（主路径）**：该行补齐合格引用 ⇒ key 从集合里消失 ⇒ 框架自动播报 `render_resolved`「已回落」。**不需要任何人去关它。**
2. **降回第九态同样解除**：状态不再是 `📥` ⇒ 不命中 ⇒ 解除。**⇒「我不确认它，我把它退回去」也是一条合法出路** —— 只有一条出路的告警会逼人乱确认。
3. **🔴 到期退休（本包必须写死的一条）**：本告警是**存量清算型**。B 类清零 ＋ 新机制上线后，它在设计上**恒为零命中**。⇒ tasks 里挂一条**退休检查项**：上线后连续 30 天零命中即评估退休或降为纯回显。**否则它就成了一个永远绿着、没人再看的检查** —— 与「永远红着的灯」是同一个病的两面。

### 抑制窗口 N 的取值

**N ≥ 落库周期的 2 倍。** 拆件与 release 在同一个持锁窗口内完成，`📥` 与引用**同时写入**，正常路径根本不会经过「有 `📥` 无引用」的中间态；会经过它的只有**异常**。取 N 小（如 1h）会在 sweep 与拆件班并发时误报。**建议 N ＝ 6 小时**，首月只告警不调参（同第 4 类上线纪律）。

### 回显纪律

🔴 **每轮回显，零命中亦不省略**（同第 4 类）：逐条打印「当前 `📥` 行数／其中带合格引用 N／不带 M／A 类豁免 K」。**否则这个守卫与「建成 9 天从未发出过一条消息」那个反面教材无法区分。**

## D5. `[R:…]` 字段的形态与解析

**取值形态**：`[R:一#427]`，多值 `[R:一#427,一#334]`；`一`／`四` 为分区，与既有 `--section` 取值一致。

**为什么放在状态列的机器字段族里**：

- 与 `[S:…]`／`[D:…]` 同位同族，解析器 `_parse_status_domain_fields` 已在那里，**扩一个字段的成本远低于新造一个位置**；
- 它承载的内容（「派生去向」）**本来就是拆件巡逻章程 §三.4 已经要求写的东西**，本包只是把它从自由文本挪到机器读得到的位置 —— 同 `采购部#9`／`#11` 那条实证：**结论白纸黑字写着，只是写在了机器读不到的地方**。

**缺 `[R:…]` 怎么办**：桥二**不写 `📥`、不拦 release**，只在 notes 里低噪提示一行「§一 #N 已 `[S:done]` 但未写 `[R:…]`，README 保持第九态」。

🔴 **刻意不拦**：拦 release 会把「拆件班忘了写一个字段」升级成「队列锁放不掉」，而队列锁放不掉会阻塞所有人。**代价不对称：漏写的后果是闸多锁一会儿（可恢复），拦死的后果是全线停摆。**
