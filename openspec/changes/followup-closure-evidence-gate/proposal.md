# 闸的开合系统性根治：终态自带可核引用 ＋ 闸由两态改四态

> 承接队列 §一 `#366`（2026-08-28 追加段：「闸的开合须系统性根治」）；实撞现场
> `1-转型规划/0-全景路线图/拆件-质量部10与采购部19回件-2026-08-28.md` §〇。
> 本包**只出 propose ＋ design**，不含实现（`OP-0828-X`，2026-08-28）。

## Why

**一句话根因**：**闸判的是「状态字段长什么样」，而它想判的是「上一封的往返真的闭环了没有」。中间那一步——有人真的读了回件、并把结论回灌进队列行——没有任何机器可验证的痕迹**，于是机器只能用一个**它自己写的字段**去冒充它。

⇒ **闸依赖的判据，正是它要守护的那件事的自陈。** A 说自己做完了，B 读 A 的自陈来决定放不放行。

### 实撞（2026-08-28，非构造）

`质量部#10` 与 `采购部#19` 的 README 发送状态**都已是** `📥 已回件并回灌`，括注写着「**S4 桥二自动转态 …… 本次由机器代写，未经人工逐字确认**」，`§一 #427`／`#428` 也已被标 `[S:done]` —— 而当日真正的拆件是 Cowork 事后手工补做的。**且那次机器转态恰好把最要紧的一件盖住了**：陈忱 09:22 那条 281 B「文本反馈」才是 `质量部#10` 的正式答复，14:04 的 23 KB xlsx 是额外交付。

**两个闸当时显示 ✅ 开，依据正是那个不可信字段。结果碰巧是对的**（Cowork 当天确实拆完了）——**但闸的开合建立在一个不保证名副其实的字段上这件事，不因这次侥幸而改变。**

### 它属于哪一族，以及为什么这一族里它最危险

同族＝「判据恒真、零信息量」「守卫看的不是那个对象」「工具静默回退」——共同点是**错误不产生任何信号**。但本条比同族更危险一档：

- 同族前几种是「**该报的没报**」（漏警）；
- 本条是「**没做的被记成做了**」（伪证）。**它会让后续所有人都不再去看那份原件。**

### 三个此前没被点破的结构缺陷

1. **`[S:done]` 是一句自陈，不是一件证据。** 写它的是拆件巡逻（一个 LLM 定时班），机器把它当硬事实向上游传导，一路传到闸。
2. **机器留下的那句「未经人工逐字确认」没有任何消费方。** 这是好设计（机器没有伪装成人工确认），但**又一次「写下需要动作、却没有承接方」** —— 现网 4 行带着这句话，无一被任何机制读过。
3. **闸只有开/关两态**，于是「回件到了没人拆」与「信还没发」被压成同一态（都显示 🔒）。**本次发生的恰恰是前者，而它在闸上完全不可见。**

### 本次退休了哪一个既有守卫（协议〇.9 措施 B，机制类变更包强制回答）

**退休两条，一条降级，净减一条人守：**

1. **退休：桥二「`[S:done]` ⇒ 直接写 `📥 已回件并回灌`」这条授权**（`工具-共享文档编辑锁.py::_build_reply_closed_status`）。这是本次事故的直接产出方。**退的是它写终态的资格，不是它这个人** —— 它继续在 release 上跑，天花板降到第九态（见 What Changes）。
2. **退休：`工具-跟进闸查询.py` 的 `gate_open: bool` 作为唯一对外结论**。布尔量是三缺陷之三的成因；改为四值 `gate_state`，`gate_open` 保留为派生字段供既有 JSON 消费方兼容（见 design D6）。
3. **降级（不退休）：README 状态列「人不得乱写终态」这条人守。** 它不可能靠人守住（人守必失守），**但也不该删** —— 本包让它从「靠人记住」变成「写终态时必须交出引用，交不出机器就不认」。**这正是协议〇.9 要的形态：把人守挂到咽喉上，而不是再加一条人守。**

🔴 **本包不新增任何需要人另外记住的自然语言标记。** 新增的 `[R:…]` 回灌去向字段是**既有机器字段族**（`[S:…]`／`[D:…]`）的一员，且它承载的内容（「派生去向」）本来就是拆件巡逻章程 §三.4 已经要求写的东西 —— **本包只是把它从自由文本挪到机器读得到的位置**（同「`采购部#9`／`#11` 的结论写在了机器读不到的地方」那条实证）。

### 伴生文件的 .gitignore 覆盖（队列 #328 子项②，强制回答）

**本变更不新增任何此前不存在的文件名形态。** 唯一的新文件是 sweep 常驻告警的状态文件，它属既有形态：现有第 4／5 类常驻告警各有一份同类状态文件（如 `CLAUDE_MD_SIZE_STATE_REL`），落在同一目录、同一命名族、由同一个 `_track_and_alert_standing_state` 读写。

**核实方式（实现期强制补做，不得以推断代替）**：实现时须对新状态文件的实际路径跑 `git check-ignore -v` 并把**实测输出原样贴进 tasks 验收项**（tasks 3.4）。🔴 **本 propose 阶段刻意不写「应该被覆盖」** —— #322 那次 17.1 小时连响的成因正是「没有人回头看一眼忽略规则」，而**一句未经实测的「应该被覆盖」比不写更糟**。

## What Changes

### ① 拆字段：把「到了」与「拆了」交给不同主体写

| 状态 | 谁有资格写 | 语义 |
|---|---|---|
| `📨 回件已到，待拆件 <UTC>`（**既有第九态，不新造同义词**） | **机器**（桥一到达时写；桥二在桥一没跑成时补写） | 文件到了、已归档。**这是机器有资格断言的全部。** |
| `📥 已回件并回灌 <日期>` | **只能由拆件动作写**，且**必须携带引用** | 有人读了回件并把结论落进了具体的队列行 |

🔴 **刻意不引入 opener 提议的 `🤖 已归档待拆件` 这个新字符串**：第九态 `📨 回件已到，待拆件` 已经**逐字表达同一件事**，且已在生产、已有判据、已有幂等分支、已有溯源回指契约。再造一个同义态，等于让人和机器都多记一条规则去说一件已经说过的事（同本项目否掉 `回灌完成：` 标记的那条判断）。**辨析与代价见 design D1。**

### ② 🔴 终态自带机器可核的引用（本包核心，唯一能消掉条件的一步）

- **队列侧**：拆件在 §一 入信行的状态列写机器字段 **`[R:一#427]`**（回灌去向，可多值），与既有 `[S:…]`／`[D:…]` 同族同位。
- **README 侧**：`📥` 的括注必须写出**同一组行号**与**依据的归档件**。
- **闸判据**由「状态 ＝ `📥`」改为 **「状态 ＝ `📥` **且** 它声明的那些行确实存在、且那些行里确实有人写过东西」**。
- **「有人写过东西」的判法（非平凡、可机器判、无需 git）**：被引用行的状态列**剥掉全部机器字段后仍非空** —— 因为**入信行是机器人按固定模板建的，模板在这一格只有机器字段**。⇒ **机器想伪造终态，就得先真的往那些行里写出内容。**

🔴 **这不是「要求人别乱写终态」**（那是人守、必失守），**是让终态自己带上证据**。

### ③ 闸增第四态：`🔴 待拆件` 从隐形变成会被抓到的状态

`工具-跟进闸查询.py` 的对外结论由 `gate_open: bool` 改为四值：

| `gate_state` | 含义 | 放行？ |
|---|---|---|
| `🔒 在途` | 已发出、未收到回件 | 否 |
| **`🔴 待拆件`** | **回件已到、无人拆** | **否 —— 但与「在途」原因完全不同，须分别催办** |
| `✅ 开` | 已拆且回灌有证据 | 是 |
| `⏸ 暂缓` | 主动压着 | 否 |

**这一态本身就是本次事故的可见化**：如果它当时存在，「回件躺着没人拆」会被值周巡检抓到，而不是被一次自动转态盖过去。

### ④ 配套：让那句「未经人工逐字确认」第一次有承接方

落库 sweep 新增一类**常驻状态告警**（复用既有 `_track_and_alert_standing_state` 框架，不新造机制）：README 中处于 `📥` 但**拿不出合格引用**的信，超过 N 小时未补齐即告警；**补齐即自动解除并播报解除**。🔴 **告警的关掉方式与触发方式一并设计**，详见 design D4。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

**本流程哪些判断是人脑默会经验？**

1. **「这封信到底闭没闭环」** —— 拆件的人知道自己有没有读过原件、有没有把结论落到某处；机器此前只能读一个字段。**规则**：闭环 ＝ 读过原件 ＋ 结论落进了具体载体（队列行或接力文件）。**阈值**：至少一个可指名的落点。**例外**：`✅ 无需回复`（通知型信，发出即闭环，从设计上没有回件）与 `❌ 已作废`。
2. **「一条回件该回灌到哪里」** —— 熟手一眼就知道该落进入信行本身（属已有裁决的确认）还是另起／改写业务行（属新事实）。`§一 #427` 的拆件结论明写「回灌去向＝本行即唯一载体」，正是这条默会经验的一次显性化。
3. **「哪些历史 `📥` 是可信的」** —— 人凭记忆知道 8 月 23 日桥二上线前的转态都是人手写的；机器完全没有这条时间线。**本包把它显性化为一个明写的截止日期，而不是留在人脑里。**
4. **尺度／例外**：机器代写留下的「未经人工逐字确认」四行，**不属于「历史行」**，不享受历史豁免 —— 见 design D3。

**由谁显性化？** 持有人 **Shao Peishen**（口径来源：2026-08-28「需要系统性根治」及三层修法）；backup **孙涛**（决策代理，可代 design 审）。

**用什么方法提取？** **历史案例反推 ＋ L2 改判判例累积**：三层修法全部由 2026-08-28 那一次实撞反推而来（README 4 行带「未经人工逐字确认」、`#427`／`#428` 已 `[S:done]` 而回灌未做、第九态与终态之间没有人参与的门），不是设问得来的。

## 验收与晋档条件（强制，四档口径）

**本变更包交付后场景所处档位**：**档 3（内部服务）** —— 本包为**机制/环境类**，服务对象是本项目自身的协同流程，运行在开发机与常驻服务上。🔴 **本包 propose 阶段交付物只有 proposal ＋ design ＋ delta specs，档位指的是实现落地后的目标态，不是本次提交的状态。**

**晋下一档（档 4 对客交付）的条件**：不适用 —— 本机制永不对客。

**实现落地后「本机制真实生效」的前置条件（逐条，缺一不算生效）**：

1. 判据模块新函数全量单测绿，且含**「机器无法在不写内容的情况下让终态通过」**这条反例断言；
2. `工具-跟进闸查询.py --all` 在**生产真身**上跑通，四态各自至少出现过一次真实取值（`⏸ 暂缓` 可用构造样本）；
3. 桥二在一次真实 release 上被观测到**没有**再写 `📥`（只写／保持第九态）；
4. 存量 4 行「未经人工逐字确认」处置完毕（逐条人工确认或降回第九态），sweep 该类告警**从有到无并播报过一次解除**；
5. 🔴 **一次真实的完整往返**：回件到达 → 第九态 → 拆件写 `[R:…]` → release → `📥` 带引用 → `--to <收信人>` 显示 `✅ 开`。**这一条不发生，前四条全绿也不算生效**（同「探针通了 ≠ 机制通了」）。

**价值指标**：

- **风险型（主）**：「**闸开而其依据不可核**的信数」。基线 ＝ **4**（2026-08-28 实测 README 带「未经人工逐字确认」的行数：`IT部#9`／`IT部#10`／`质量部#10`／`采购部#19`）；目标 ＝ **0**，且此后新增恒为 0（机制上不再产生）。
- **质量型**：「回件到达 → 拆件」的中位时长。基线 **待测**（本包之前该量在数据上不可得 —— 这正是缺陷之三；`🔴 待拆件` 态上线后首月即产生第一批基线数据）。🔴 **不编造基线值。**
- **风险型（副）**：`串行豁免：`／`转态豁免：` 两个逃生阀的使用次数。基线待 Cowork 从 git 历史统计；目标 ＝ 不上升（**若本包让它们上升，说明新判据卡住了正常路径，须回头改判据而不是改人**）。
- **基线由业务 Champion 确认**：Shao Peishen。

## 已知边界（必须随交付一起说出去）

1. 🔴 **本包只能保证「终态不是凭空写的」，不能保证「回灌是对的」。** 引用锚点证明有人往那些行里写过东西，**证明不了他读懂了**。`采购部#19` 那次的真实错误是**读法覆盖不全**（docx 复选框假阴性、段落里的勾被漏掉），本包对这一类**零帮助** —— 它属另一条线（读取器覆盖面），不得因本包上线就以为那类问题也被解决了。
2. **历史行永远不可核。** 见 design D3：截止日期之前的 `📥` 一律按旧口径视为闭环，**这意味着我们永远不会知道它们当中有没有第二个 `质量部#10`**。
3. **git 只能事后审计，不能做 release 时的判据** —— 见 design D2：回灌与转态发生在**同一个未提交窗口**内，那一刻 git 里什么都还没有。
4. **本包不解决「拆件班读得浅」**。`[S:done]` 仍是一句自陈；本包只是不再让这句自陈**独自**把闸推开。
