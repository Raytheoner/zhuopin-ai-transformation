# single-guarded-copy Proposal

> **状态：propose 出件，等 design 审。** 本包**不得** apply，直到 Shao Peishen 完成 design 审。
> **来源**：队列 §一 **#503**（2026-09-08 立行，Cowork `OP-0908-A`，Shao Peishen 当日直令，原话「同一个内容存在两份，只留一份有机器守、人只看有守的那份」）。本包由泳道 `503-opener-single`（`OP-0908-P`，批 `B-0908_四泳道机制根治`）起草。
> **openspec 门槛核对**（`.claude/rules/场景建造与合规.md` §二）：命中 **①「改变全项目口径」**——本包改的是「会话怎么把 opener 交给他」这条**两桌全局流程**，触及所有 `zhuopin-*` skill 的出件段与根 `CLAUDE.md` §3；同时命中 **③「改变既有模块对外语义」**（`工具-opener生成.py` 的默认出件方式由「打到 stdout」改为「落文件」）。⇒ **必须走 openspec 且必须含 design 审**（`#503` 行内亦已写明「须 design 审须 Shao Peishen 本人过，因为解法会改他自己复制 opener 的习惯动作」）。

## Why

### 一句话

**能被机器守住的那一份，必须是唯一被消费的那一份；若人消费的是另一份，守卫的存在只提供虚假安全感。**

### 实撞，不是推演（2026-09-08 当日两次，第二次就发生在起草本包的这条泳道上）

**第一次（`#503` 立行成因）**：业务总线把 `OP-0908-I` 的 opener 手工削成一行发进 Cowork 聊天，**六字段【设置】行整行丢失**（`session：新开`／worktree 从哪条分支起／`.51` 只读边界全没了），被 Shao Peishen 当场退回。而**落进仓库的那一份**（派单件里的 `[OP-0908-I]` 块）六字段齐全、`工具-opener块lint.py --enforce` 实跑零违规。**两份内容、只有一份有守，而他复制的是没守的那份。**

**第二次（本包起草时第一人称实测，见 `同族普查-两份内容清单.md` 清单 2）**：本泳道收到的 Task prompt 顶部有一整段「环境适配（看护者补充）」七条硬约束，对落库件 `看护件-泳道看护批B-0908_四泳道机制根治-2026-09-08.md` 实测 `grep -c 环境适配` ＝ **0**。其中一条**与落库块正面冲突**：落库块写 `worktree：☑（503-opener-single-503，新 worktree，收工自删）`，实际执行的 prompt 写「你已经在隔离 worktree 里，不要再建 worktree」。**落库的那一份通过了全部七个形态检查，而它是错的那一份。**

### 为什么加守救不了（`#503` 行内已预先钉死，起草不得滑向此处）

`#503` 给了三条候选：⒜ 会话自检（人守）／⒝ lint 产出可粘贴块、会话逐字转贴并比对校验和／⒞ 改流程让第二份根本不存在——并明写「**只有 ⒞ 是真正的消灭，⒜⒝ 都是再加一道会漏的守**」。

普查佐证了这句话：本项目已经解决过同族问题两次，用的都不是加守，而是**指向唯一那份**——
- `0-学习与工具/hooks/README-安装步骤.md:31`：哨兵 hook 的 `settings.json` 直接写仓库内绝对路径 ⇒ 只有一份，「注册之后改脚本、调判据、加哨兵都不再需要你动手」；
- `工具-泳道纪律复制lint.py`：看护侧只允许给出指向收口正本的指针，**不得存在那套纪律的任何一份可执行副本**，且该脚本刻意不写死词表（词表运行时从正本提取），理由原文「**用一份手抄去守『不许手抄』会让整件事变成笑话**」。

而加守的两次（计划任务单向回镜、仓库外载体扫描的假零检测）都只做到「副本追真身」或「知道自己扫不到」，**没有一次消灭第二份**。

### 🔴 但纯 ⒞ 与他 2026-09-08 的当场裁定正面冲突——这是本包最硬的一处，必须由 design 审拍板

⒞ 最直观的读法是「对话里不再出现完整块，只给他文件路径＋块编号」。**这条读法当天已经被他退回过一次**：`OP-0908-I` 被退回的理由恰恰是**块被削短了**，接力卡 §五 当日回写的原话是——

> 🔴 **引用版省的是「做什么／不做什么」，不是六字段**——【设置】行（含 `session：新开`）＋ CC 的 `set_session_title` 行必须留在他要粘的块里，因为**那几行的受众是粘贴的人，做什么的受众是读文件的会话**。

⇒ 本包据此把 ⒞ 收窄成一句**不与他的裁定冲突**的形态：

> **要消灭的不是「第二份字节」，是「第二次创作」。**
> 块可以在对话里出现（他要粘的就是它），但**它的每一个字节必须来自同一次工具调用**——会话不得手打、不得手改、不得凭记忆重建、不得「按需削短」。落库那份与他粘的那份是**同一次生成的两个出口**，不是两次创作的两个产物。

`OP-0908-I` 之所以能被削成一行，正是因为**当前流程允许会话手打块正文**：`工具-opener生成.py` 今天只把成品 `print()` 到 stdout（`工具-opener生成.py:559`），**不落任何文件**；`zhuopin-kickoff-prompt/SKILL.md` 步骤 10 的 lint 自检跑在一个**用完即弃的临时 `.md`** 上。于是「落库件」与「他粘的那份」在今天的流程里本来就是**两次独立创作**，中间只隔着会话的手。

### 本次退休哪一个既有守卫（协议〇.9 措施 B，机制类强制回答）

**退休一条人守 ＋ 废掉一处假自检**：

1. **退休（人守 → 机器守）**：`1-转型规划/session接力-业务总线.md` §五 第一条「opener 一律 Read `opener骨架.md` → `工具-opener生成.py` → 过 `opener块lint.py --enforce`」——`#503` 期望产出 ③ 明写「落地后把接力卡 §五 那条人守降为一行指针」。本包落地后该条的三步全部由生成器的单一出口强制，正文降为一行指针（规则退休制，根 `CLAUDE.md` §5）。
2. **废掉（同层判据升级，非人守退休）**：`zhuopin-kickoff-prompt/SKILL.md` 步骤 10 末条「把块写入**临时** `.md` 跑 `--enforce`」——这道自检检查的是一个**不会被任何人消费的临时文件**，是本题的教科书式反例（守在没人读的那份上）。本包落地后它被生成器内置的 `check_block` 自检 ＋ 落库件上的 release 守卫替代，条目删除而非改写。

🔴 **`工具-opener块lint.py` 形态①–⑦ 一条都不退**——它们守的是落库件，落库件仍然要守。本包只是让「落库件」与「他粘的那份」重合，从而让这七个形态第一次真的覆盖到他消费的内容。

## What Changes

**① 生成器改为「先落文件，再出块」的单一出口（核心，`工具-opener生成.py`）**
新增 `--out <仓库根相对路径>`（落点文件）与 `--anchor <块标题或锚>`（写进文件的哪一节）。生成器在**同一次调用内**：拼装 → 跑 `check_block` 自检 → **写入落点文件** → 回读落点文件中刚写入的那个块 → 把**回读到的字节**打到 stdout。stdout 与文件内容因此在构造上同源同批，不存在「会话在中间改一手」的窗口。未传 `--out` 时的行为改由决策点 ① 拍板（候选：fail-loud 报错退出／保留但打印显式警告）。

**② 生成器为每个块盖一个可核对的出件指纹（`工具-opener生成.py` ＋ `工具-opener块lint.py`）**
块内新增**一行**指纹（形态与位置由决策点 ② 拍板）。指纹 ＝ 块正文（不含指纹行本身）的 SHA-256 前 8 位十六进制。它有两个用途，**都不是「再加一道会漏的守」**：
- 对**他**：粘进 CC 的块与仓库里那份指纹一致 ⇒ 一眼可核，无需比对全文；
- 对**机器**：`工具-opener块lint.py` 新增形态⑧——落库件里的 opener 块若**指纹行缺失或与块正文对不上**，即判违规（＝这个块被手打或被手改过）。这道守卫仍然只守落库件，**但它守的是「这份是不是生成器出的」，而不是「这份格式对不对」**，是形态①–⑦ 射程之外的第一道内容来源守卫。

**③ 会话侧规则改成一句可判定的禁令（根 `CLAUDE.md` §3 ＋ 各 `zhuopin-*` skill 出件段）**
现行文字是「先 Read 骨架逐字套用」（**过程性**，无法事后判定是否照做）；改为**结果性**禁令：

> 🔴 **会话不得手打、手改、削短任何 opener 块的正文。** 块的每一个字节只能来自 `工具-opener生成.py` 的**同一次调用**；需要改内容 ⇒ 改参数重跑生成器（同号块重铸由生成器撞号查重拦），**不得在输出里改一个字**。

**④ 泳道 opener 的「即时补充」必须回落库（`zhuopin-lane-watch` 出件段）**
针对普查清单 2 那个第一人称实撞：看护者若需要给某条泳道追加执行环境约束（如「已在隔离 worktree，不要再建」），**必须先写进看护件对应泳道块**（走生成器重铸或走 §一 硬边界追加），再交 Task/Agent；**不得只在 prompt 参数里追加**。判据同 ③：Task prompt 的正文也只能是落库块的逐字副本。

**⑤ 覆盖边界必须有承接载体（`#503` 行内「更值得记的一层」）**
编辑锁 release 的 opener 守卫每次都打印「只覆盖走了队列锁流程的 opener，非本流程直接粘出去的会话看不见，不代表全部覆盖」——**本日至少打印 8 次，没有任何载体承接这句话**。本包把这句从 stdout 一次性回显，改为落进一处常驻载体（落点由决策点 ③ 拍板）。

**不改**：`工具-opener块lint.py` 形态①–⑦ 的判据一个字不动；`opener骨架.md` 的六字段与三种骨架形状不动（除非决策点 ② 选了「指纹行进骨架」，那时只加一行）；编辑锁的 `OPENER_EXEMPT_MARK` 逃生阀语义不动。

## 本次新造了哪种自动生成文件形态（`.gitignore` 覆盖，强制回答）

- **推荐形态（决策点 ② 选 (a)／(b) 时）：不新增任何自动生成文件形态。** `--out` 写的是**已有类别的 `.md`**（派单件／看护件／`开场prompt-*.md`），本来就该进 git；指纹是块内的一行文本，不是文件。
- **若决策点 ② 选 (c)「指纹落 sidecar 台账」**：那会新造 `reports/opener-fingerprints.jsonl` 这一形态。**实测**（`git check-ignore -v`，2026-09-08 本 worktree 内跑）：

  ```
  .gitignore:50:**/reports/	reports/opener-fingerprints.jsonl
  ```

  ⇒ **已被 `.gitignore` 第 50 行的 `**/reports/` 覆盖**，不会变成孤儿脏文件。但**这同时意味着它不进 git、不进 CI、跨 worktree 不可见**——与 `#504` 正在修的心跳件是同一个坑（心跳件也在 `reports/` 下）。⇒ (c) 案若被选中，必须连带回答「这份台账既然不进 git，谁来读它」，否则它自己就变成本包要消灭的那种「没人消费的守」。

## Capabilities

### New Capabilities

- `single-guarded-copy`：opener 块的**单一创作源**——生成器同一次调用同时落文件与出块，块内盖出件指纹，lint 新增形态⑧核对指纹，会话侧禁止手打／手改／削短块正文。

### Modified Capabilities

- `工具-opener生成.py` 的出件语义：由「拼装后 `print()` 到 stdout、不落盘」改为「落盘 → 回读 → 出块」；未传 `--out` 的行为按决策点 ① 变更。
- `工具-opener块lint.py` 的守护面：由「只守格式（字段在不在）」扩展到「守内容来源（这份是不是生成器出的）」。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

1. **本流程哪些判断是人脑默会经验？**
   ⑴ **「这个块能不能削短、削掉哪几行」**——`OP-0908-I` 那次削掉的正是六字段行，而会话当时**自认为在做一件合理的事**（把长块缩成一行方便他看）。这条判断此前完全靠会话临场把握，无判据、不留痕。本包把它显性化为一条**结果性禁令**（一个字都不能改），并用指纹让「改没改过」可机器判定。
   ⑵ **「哪些执行环境约束需要补给泳道」**——普查清单 2 那七条环境适配约束是看护者临场想到的，正确但没落盘。本包把它显性化为「补充必须先回落库块再派出」。
   ⑶ **「lint 报告的射程之外还有什么」**——release 守卫每次都在打印这句话，靠人每次读一遍并记住。本包把它显性化为一处常驻载体。
2. **由谁显性化？** 持有人 ＝ **Shao Peishen**（design 审拍板三个决策点，尤其决策点 ①／② 会改他自己复制 opener 的习惯动作，`#503` 行内已点明这一点）；backup ＝ **孙涛**（缺席时代理，范围见 `.claude/rules/场景建造与合规.md`）。实现与取证由 CC 建造车间承担；下一位领 `#503` 的 session 可凭本包 ＋ `design.md` ＋ `同族普查-两份内容清单.md` 独立复核。
3. **用什么方法提取？** **历史案例反推**（2026-09-08 `OP-0908-I` 削块实撞 ＋ 本泳道第一人称实撞，两例均为真实生产事件，非构造）＋ **全库普查**（按 `#503` 判据扫出 10 条同族条目，逐条标注有守的那份与被消费的那份，含 2 条对照组以证明判据非恒真）。不涉及 LLM 判断，纯流程与字符串规则。

## 验收与晋档条件（强制，四档口径）

- **本变更包交付后场景所处档位**：跨项目治理机制，非独立业务场景，套用最接近的描述 ＝ **档1 mock 验证**（design 审通过、生成器与 lint 改动完成、单测覆盖、对全库现存 opener 块跑过一次只读回归，但**尚未在真实派件中拦下一次手改**）。
- **晋下一档（档2 真实数据跑通）的条件**（逐条，缺一不晋）：
  1. 真实出过 ≥3 份 opener（含至少一份看护件 §三 多泳道件）走完 `--out` 单一出口，且他粘进 CC 的块与落库块**指纹一致**（核对手段 ＝ 他粘的块回读跑 lint 形态⑧，不是会话自陈）。
  2. 真实发生一次**手改被拦**——形态⑧ 在落库件上报出「指纹对不上」，且提示足以让人知道该重跑生成器而不是继续手改。⚠️ 若长期零命中，正确表述是「**未被检验**」，**不得表述为「手改已消除」**（同 `editlock-write-side-date-guard` 已确立的判据；根 `CLAUDE.md` §5 已有同形教训）。
  3. 真实发生一次「看护者要给泳道补环境约束」并走了 ④ 的回落库路径（本泳道这次就是反例，正好可作对照）。
- **价值指标**（风险型）：**他粘进 CC 的块与落库件不一致的次数**——基线 ＝ 2026-09-08 单日 2 次（`OP-0908-I` 削块 ＋ 本泳道环境适配段），且**两次都不是被机制发现的**（一次他当场退回、一次起草本包时才发现）；目标 ＝ 不一致仍可能发生，但**必须由机器先发现**（形态⑧ 报出），不得再由他先开口。
- **LLM 判据黄金集**：不适用（纯流程与字符串规则，无 LLM 运行时判断）。

## 已知残余风险（如实写明，不粉饰）

1. 🔴 **对话面永远没有咽喉。** 即便 ①②③④ 全部落地，会话**在物理上仍然能**手打一个块进聊天——没有任何机器能拦。本包能做到的是：⑴ 让手打**没有动机**（生成器一次调用就同时给出文件与块，比手打更省事）；⑵ 让手打**留下可发现的痕迹**（无指纹或指纹对不上）；⑶ 让**他**有一个成本极低的核对动作（对 8 位十六进制，不是比全文）。**这是缓解，不是消灭**，不得在收口时表述为「已根治对话面」。
2. **指纹本身可以被手打。** 会话若手改块后重算指纹再盖上，形态⑧ 照过。判据只能拦「无意识的手改」，拦不住「有意识的伪造」——但后者已不属于本题（本题的两次实撞都是前者）。
3. **`--out` 让会话多写一个文件**，对「他其实只想要一个块、不想多一份文件」的轻量场景是净增负担。决策点 ① 若选 fail-loud，这个负担变成强制。**这一项的代价由他判，不由起草方判。**
4. **形态⑧ 上岗会让 release 守卫自动变严**（编辑锁逐字复用 `check_block`，同 `#487`／`OP-0906-M` 已实测过的连带效应）。存量件若不豁免，可能出现「谁下次编辑某份老件就被拦一次」——与 `#487` 遗留的那一份 `开场prompt-构建环境瘦身第二轮A2A3-…md:13` 同形。apply 期必须先取基线数。
