# sweep-startup-nonblocking Proposal（队列 #328 子项①＋通则）

## Why（为什么做）

`工具-落库sweep.py` 起跑段的 `_fetch()` 一遇网络失败就 `SweepAbort` 整轮跳过，而**本轮真正需要网络的只有收尾段的 push，且收尾段 `_reconcile_with_origin_and_push` 本来就会自己再 fetch 一次**——起跑段那次 fetch 对本轮的本地工作（提交待处理批次／重跑台账／flush 锁忙暂存／孤儿告警／openspec 覆盖检测）**全部不必要**，却把它们一并挡掉。

这是**「起跑段阻断整轮」同族第三例**：#288（`_sync_master_if_behind_origin` 排在批次处理前）→ #309 子项 F（`_push_any_unpushed_commits` 对非快进硬 return）→ 本行。**#309-F 行内已自陈识别出「起跑段不得整轮 return」这条通则，却只写在一行队列正文里，没有任何机制拿它去扫剩下的起跑段检查，于是第三例原地不动。** 本变更包因此不只修这一处，而是把通则做成**可扫描判据**，使第四例无法静默出现。

### 本次退休哪一个既有守卫（协议〇.9 措施 B，机制类强制）

**退休 `_fetch()` 抛 `SweepAbort` 这一守卫本身——整体删除，不是加一条降级分支。**

`_fetch()` 现有唯一职责是「fetch 失败即中止整轮」（`工具-落库sweep.py:632-635`，全文件仅此一处 `raise`）。本次改为**返回 `bool` 且永不抛异常**，由两处调用点各自决定后续：

- **起跑段**（`_push_any_unpushed_commits`，L664）：失败即记录后继续，补推推迟到收尾段。
- **收尾段**（`_reconcile_with_origin_and_push`，L725）：失败即记录后**跳过本轮对齐与推送、但继续执行其后的本地检查**（#198(c) 部署提示／#229 部署留痕／#298 openspec 覆盖与滞留检测——这些全是纯本地读，不需要网络，今天却被这次 abort 一并挡掉）。

⇒ **守卫位点由 1 处减为 0 处，净减，无新增运行时守卫。**

本包另新增的两项均**不是运行时守卫**，如实区分、不含混：
- 通则一（起跑段中止位点白名单）＝**一条单测**，它不拦任何生产行为，只在有人新增/删除起跑段 abort 位点时让 CI 失败，强制作者显式分类；
- 通则二（伴生文件 `.gitignore` 覆盖）＝**一条 `openspec/config.yaml` 撰写期问询**，与 #206 迁 propose 门禁段、#308 措施 B one-in-one-out 同类，注入 propose 提示词，不产生任何运行时代码。

## What Changes（改什么）

1. **`_fetch()` 去异常化**：改签名为 `_fetch(repo_root, log, phase) -> bool`，失败记录一行含阶段名与 stderr 的日志后返回 `False`，不再 `raise`。
2. **起跑段两处降级**（通则一的直接产物，见 design §2 逐位点判定表）：
   - `_fetch` 失败 → 记录后继续本轮（**本行主体**）；
   - `_push_any_unpushed_commits` 补推失败（L683，现 `exit_code=2` 整轮中止）→ 同样降级为记录后继续。**这一处是通则扫出来的「第四例」**，不在原派单件字面范围内，但正是交付条件⑵要求逐位点判定后必然落到的结论——本地提交不会被撤销，推送交收尾段重试，收尾段推送失败仍以 `exit_code=2` 收尾，对外语义不丢。
3. **收尾段 `_fetch` 失败降级**：记录后跳过对齐与推送、继续其后的本地检测，退出码维持 0（与今日 `SweepAbort` 默认退出码一致，不改变对外语义）。
4. **通则一落进 spec ＋ 可扫描判据**：`sweep-startup-resilience` 新增「起跑段中止位点须显式登记且默认降级」要求；配套单测以 AST 静态扫描起跑段六个函数的全部 `raise SweepAbort` 位点，与冻结清单逐项比对，不一致即失败。
5. **通则二落进 `openspec/config.yaml`**：新增 proposal 撰写期问询——凡新增/修改「工具会自动生成的伴生文件」，须同批确认 `.gitignore` 覆盖情况。
6. **子项②（`.gitignore` `*.editlock*`）经核实已于 2026-08-13 完工**，本包不重复改动，只做验收复核（详见 design §4）。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

1. **本流程哪些判断是人脑默会经验？**
   「起跑段某处检查该拦还是该降级」这一判断当前**完全是默会的**——判据（"它挡住的本地工作，是否真的依赖它检查的那个前提"）从未被写下来，三次事故（#288／#309-F／本行）都是**撞上了才逐处补**，每次只修自己撞见的那一处。阈值/例外/尺度：无网络时哪些动作仍安全、退出码 0／2／`FORK_EXIT_CODE` 各自的语义边界、哪些前提属"仓库物理状态不可用"（必须拦）而哪些属"外部依赖暂时不可用"（应降级）。
2. **由谁显性化？**
   持有人＝**Shao Peishen**（机制口径拍板人）；backup＝**环境总线**（本机制的日常维护线）。本次由 CC 起草判定表、Shao Peishen design 审拍板定案，结论写入 `sweep-startup-resilience` spec 与队列 #328 行。
3. **用什么方法提取？**
   **历史案例反推**——以 `reports/sweep-commit.log` 全量 715 轮真实运行记录为样本，反推每一处起跑段 abort 的实际代价；再由作者对现存九个位点逐一给出该拦/该降级的结论与理由，交 design 审批改（AI 起草·专家批改）。

## 验收与晋档条件（强制，四档口径）

- **本变更包交付后场景所处档位**：**档 3（内部服务）**——`工具-落库sweep.py` 是每小时无人值守定时任务、且是本项目唯一落库通道，本变更直接改其生产行为，非 mock。
- **晋下一档的条件**：本包**不涉及对客交付，不适用晋档 4**。维持档 3 的条件：① 全量回归绿（`test_工具-落库sweep.py` 现 138＋本次新增）；② 通则一的扫描单测对**真实生产源码**（非夹具）通过；③ 上线后至少观察到一次真实网络失败轮次，日志显示"记录后继续"且本地工作照常完成（**本次交付时无法人为构造，如实登记为待自然发生的观察项，不假称已验证**）。
- **价值指标**（风险型）：
  - 基线（实测，见 design §1）：起跑段 `_fetch` 失败致整轮跳过 **20 轮／715（2.8%）**，分布 **11 个不同日期**，其中 **3 轮**的批次在紧邻下一轮立刻落库＝被白推迟一个完整周期；2026-08-11 当日曾卡住 #315 apply 的开工前提，由值周巡检手工重触发才通过。
  - 目标：该类整轮跳过归零（网络失败不再影响本地工作）；**同族第四例不得再以"没人拿通则去扫"的方式发生**——由扫描单测承担，非人守。
  - 基线由 Shao Peishen（本机制业务 Champion）确认。
- **LLM 判据黄金集**：**不适用**——本变更不含任何 LLM 运行时判断，全部为确定性 git 状态判定。

## Impact（影响面）

- **受影响 specs**：`sweep-startup-resilience`（MODIFIED 两条既有 Requirement ＋ ADDED 一条通则 Requirement）。`sweep-sync-reconciliation` 的收尾段职责边界不变，但其 fetch 失败分支行为改变——delta 一并登记。
- **受影响代码**：`0-学习与工具/工具-落库sweep.py`（`_fetch`／`_push_any_unpushed_commits`／`_reconcile_with_origin_and_push`）、`0-学习与工具/test_工具-落库sweep.py`（新增回归与扫描单测）、`openspec/config.yaml`（通则二）。
- **不受影响**：`.gitignore`（子项②已完工，本包不动）；队列 #328 子项③④⑤（不在本次派单范围，如实留置，见 design §5）。
- **合规红线核对**：
  - **mock 先行**：不适用——被改对象即生产工具本身，回归测试全部走临时仓库夹具（`_run_git` 真实调用、临时目录，不碰主工作区），已是既有惯例。
  - **audit 留痕**：本变更**增加**留痕（原本 abort 后 `_reconcile` 之后的检测全部无日志，现在会有）；`sweep-commit.log` 为 append-only。
  - **OEM 隔离**：不涉及任何 OEM 技术数据。
  - **L2 门禁**：不涉及采购金额／新供应商／对客推送。
  - **ISO 26262**：不涉及安全相关代码。
