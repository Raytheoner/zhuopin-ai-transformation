# lane-watch-deploy-extension Proposal

> 归属：队列 §一 `#478`（2026-09-03 立行，`OP-0903-D`，立行依据＝Shao Peishen 答 **L-1 ＝ (a)**；2026-09-07 由 Cowork 业务总线 `B-0907_E` 激活，`OP-0907-G` 派 CC 起草）。
> 类别：**机制/环境类变更包**（守护本仓库泳道看护工具自身），受 `openspec/config.yaml` 两条 MANDATORY 约束，见下文。
> 🔴 **本轮范围＝propose ＋ design 起草，不 apply**：`工具-泳道看护状态机.py`／`zhuopin-lane-watch/SKILL.md`／`lane-watch-mode/design.md` 三处载体本轮**一行未动**——那是 design 审过之后 apply 阶段的事（`tasks.md` §1–§4）。
> ⚠️ **过渡期口径（本包落地前一律照此）**：各批 opener 维持现行「🔴 不部署」写法，不得因本包已起草就提前放开（`#478` 行内原文）。

## Why（为什么做）

**一句话**：D1 ⏭️ 档现行语义是「碰 `.51` 一律转出、本包永不执行」，其代价是——**即便 Shao Peishen 此刻就在环、笔记本也实测 on-LAN，泳道里那一项部署仍然必须等到下一次「我已回Lan」收口批**；本变更在**不改「`.51` 归 `zhuopin-lan-closeout` 管」这条根边界**的前提下，只解开这一层多余的**时序**约束。

**他的原话诉求**（2026-09-03，`#478` 行内逐字保留）：「只要笔记本 on-LAN，到时提醒我授权，我在环授权通过后可以部署」。

**为什么这是时序问题而不是边界问题**：`.51` 部署之所以单独设一档，理由写在 `lane-watch-mode/design.md`「为什么 `.51` 部署要单独设一档」节——**不是因为「他在不在」，是因为它碰 `.51`**，而 `.51` 部署所需的那套纪律**只长在 `zhuopin-lan-closeout` 里**。这条理由约束的是「谁的纪律说了算」，**不约束「在哪个 session 里执行」**。现行实现把两件事捆在一起，于是产生了一个没有依据的等待：纪律明明可以被指向，却因为它写在另一个 skill 里，就要求另开一次 session。

### 🔴 核心设计约束：指向而非复制（本包最要紧的一句）

`zhuopin-lane-watch/SKILL.md` 现行原文自己已经写下了本包的失败模式：

> 收口的独特性不是「他在不在」，是**它碰 `.51`**；那套纪律**只长在收口里**，本包重新实现一遍就是复制护栏，**而复制的护栏必然漂移**。

⇒ **本次扩展若在 lane-watch 侧抄一份那套纪律，等于亲手制造该文自己警告过的那个缺陷。** 故本包的实现形态被**先验地**限定为：lane-watch 侧只留**指针 ＋ 前置闸 ＋ 留痕**，纪律正文一个字都不进来，执行时现读 `0-学习与工具/skills源码/zhuopin-lan-closeout/SKILL.md`（被指向方，本包**不改它一行**）。

**📌 同族第三次，不是第一次**：本项目 2026-09-03 当天另有两次同形——业务总线把 opener 正文同时放进看护件与新建 prompt 文件（当日撤）、`#345` 35 份路径引导手抄；更早的两例已被 `lane-watch-mode/design.md` 点名（`#312` 读侧双文件解析、跟进信状态两处载体）。**前三次都是「写的时候两处一致，改的时候只改了一处」**，故本包把「不许抄」从散文警告升级为可执行判据（见 What Changes ④）。

### 守卫退休问答（MANDATORY · 协议〇.9 措施 B / one-in-one-out）

🔴 **先如实说明本包的特殊处境**：本包是一次**放宽**（把「永不执行」改为「有条件可执行」），放宽天然是加风险而不是减风险，因此 one-in-one-out 在这里**不能靠"顺手删一条"敷衍**——必须回答「放宽之后，原先靠什么挡住的，现在靠什么挡住」。

**本次退休两条既有的「人守」，各以一道机器闸取代，无一条是空退。**

**退休对象一**：「⏭️ 档不执行」这条边界**今天完全是人守**——`工具-泳道看护状态机.py::transfer_out_lane` 只做「记录去向＋推 FYI」，它**不阻止任何人接着去部署**；真正拦住部署的是每批 opener 正文里手写的那句「🔴 不部署」。这与队列 `#284` 计数⑦⑧⑨ 同族（批次清单／暂存区核对／`--no-notify`），全部属于**「靠起草者每次记得写一句」**这一已被反复证伪的防线。
**取代物**：新增 `deploy-authorize` 前置闸——**无 on-LAN 实测记录、无当次授权留痕，即拒绝放行并以非零退出码收尾**；「不部署」不再依赖 opener 起草者的记性。

**退休对象二**：「别把那套纪律抄进 lane-watch 侧」这条约定，今天只以**散文警告**存在于 `zhuopin-lane-watch/SKILL.md` 与 `lane-watch-mode/design.md` 两处（「复制的护栏必然漂移」），**没有任何东西在检查它有没有被遵守**——而本包正是最有动机违反它的那一次改动。
**取代物**：新增反例守卫（判据形态见 design 决策点 6），**lane-watch 侧四处载体中该纪律的可执行文本出现次数 ＝ 0**，违反即 CI 报错。取自 `0-学习与工具/工具-引导样板lint.py` 的同款手法（`#345`／`#354` 两族手抄形态的门禁，是本项目已验证有效的"退休一条手抄人守"实现范式）。

**为什么不是"新增两道守卫、没退任何东西"**：两道新闸各自**对准一条现存的人守**，闸生效之日那两条人守即失去存在理由（同 `#492` 对 `--no-notify` 的处理手法：默认值改安全之后，那条"无一例外"的约定不但不再必要，继续留着还会误导读者）。原文一律保留、标注取代关系，**不删一字**（历史记录不追改）。

### 伴生文件的 .gitignore 覆盖问答（MANDATORY · 队列 #328 子项②）

**不适用：本变更不新增任何自动生成的文件名形态。**

本变更的留痕全部落在**既有**状态文件 `reports/lane-watch-state.json` 的既有 lane 记录结构下，新增两个 append-only 字段（`deploy_authorizations`／`deploy_attempts`，见 design §二），**不新增锁文件、快照文件、独立日志、备份副本或重命名退路产物**。

**核实方式（实测，非推断）**：

```
$ git check-ignore -v reports/lane-watch-state.json
.gitignore:41:**/reports/	reports/lane-watch-state.json
```

命中 `.gitignore:41` 的 `**/reports/`，字段级新增不改变文件名形态，忽略规则沿用现状、不受影响。

⚠️ **一处须在 design 审时确认的边界**：`zhuopin-lan-closeout` 的纪律含一个"快照"环节，该环节**可能**产出文件。**本包不改它、也不代它产出**——快照由被指向方按其自身既有实现完成，其文件形态的忽略规则归属 `lan-closeout-skill` 变更包，不在本包范围内（design 决策点 2 明确本包只做指向，不接管任何执行步骤）。若 apply 期发现该环节实际会由 lane-watch 侧代跑，则本条须回退重答，不得含糊放行。

## What Changes（改什么）

**① `0-学习与工具/工具-泳道看护状态机.py`**（本轮不动，apply 阶段做）

- `TRANSFER_ACTIONS` 处注释扩写：`deploy_51` 仍属 ⏭️ 档、**分类不变**，但补充「授权后可在同一 session 内续做」的条件分支说明与指针（不复述纪律正文）。
- 新增 `deploy-authorize` 子命令 ＋ `authorize_deploy()`：**前置三查全过才返回放行**——⑴ LAN 探针 `effective == "on"`（复用既有 `lan_status()`，不新写探针）；⑵ 该泳道该项已有 `transfer-out` 记录（转出仍先发生，泳道不停这条不变）；⑶ 当次授权文本非空。任一不过即拒绝并非零退出。
- 放行输出**只打印指针**：被指向方的仓库根相对路径 ＋ 「MUST 现读该文件按其纪律执行」一句，**不打印纪律正文**（同 `criteria` 子命令"现取而非手抄"的既有手法）。
- 新增 append-only 留痕字段 `deploy_authorizations`／`deploy_attempts`（schema 见 design §二），并接入 `summary` 现取一行。

**② `0-学习与工具/skills源码/zhuopin-lane-watch/SKILL.md`**（本轮不动）

- 顶部「与 `zhuopin-lan-closeout` 如何分工」表：**不改根边界那一格**（`.51` 仍归收口管），只在「遇到需要判断的动作」列补一句时序说明——他在环且 on-LAN 时可在本 session 内续做，**纪律仍取自收口正本**。
- ⏭️ 档段（步骤 3 与步骤 5）：在现行「转出、不进 `OPENER_PARTIAL`、继续其余」之后追加条件续做分支；🔑 该段**必须写成指针**，不得展开纪律。
- 红线节「D1 ⏭️ 档本包永不执行」一句改判为一行指针，**旧版原文原样保留**（同「推送目标」节 2026-09-06 改判的既有手法）。

**③ `openspec/changes/lane-watch-mode/design.md` D1**（本轮不动）

**④ 反例守卫（本包新增的唯一"检查器"）**（本轮不动）

- 判据：**lane-watch 侧载体中，那套纪律的可执行文本出现次数 ＝ 0**；载体清单、关键词集来源、豁免形态（指针句不算复制）三者的具体判据见 design 决策点 6。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

1. **本流程哪些判断是人脑默会经验？**
   - **「他在环」这件事怎么算数**：现行体系里没有任何字段记录"他此刻在场"——`pause`/`resume` 只记「他答了什么」。本包第一次要求把"在场"落成可核的证据，而**「在场」本身不可机器观测**（design 决策点 5 即处理这一点：用"他的一次新鲜授权"作为在场的**唯一**代理证据，不另造探针）。
   - **「授权一次管多大范围」这个尺度**：今天只存在于 `zhuopin-lan-closeout` 的口头惯例里（「一次一项、带伤不推进」）。本包须把它显性化为字段级判据（design 决策点 4）。
   - **阈值/尺度类新增**：授权的时效窗口（若设）与授权粒度——两者均在 design 决策点 4 列为待裁，**不由起草方自行拍**。
2. **由谁显性化？** 持有人 **Shao Peishen**（`#478` 立行依据与拟改语义四条 MUST 均出自其 2026-09-03 答 L-1=(a) 及原话）；backup **孙涛**（其缺席时的代理人，范围见 `.claude/rules/场景建造与合规.md`）。
3. **用什么方法提取？** **历史案例反推 ＋ AI起草·专家批改**——反推依据＝`lane-watch-mode/design.md` 记录的 ⏭️ 档设立成因（初稿把 `.51` 放 🟡 的那处真矛盾）与三例"复制护栏"实事（`#312`／跟进信状态两处载体／`#345`）；起草由 CC 出 design 决策点，**由 Shao Peishen 逐条批改后方可 apply**（本包命中 🟡 档 ③ openspec design 审）。

## 验收与晋档条件（强制，四档口径）

- **本变更包交付后场景所处档位**：**档 1（mock 验证）**。本包全部单测走注入替身（LAN 探针注入、状态文件指向临时夹具），**不发真实网络请求、不连 `.51`、不做任何真实部署**；真实链路验证属晋档 2 的前提，不在本包范围内。
- **晋下一档的条件**：
  1. 🔴 **一次真实触发**：某批泳道产出**确实需要上 `.51`**时，走完整链（转出 → 提醒 → 他授权 → 放行 → 按收口正本纪律执行 → 留痕），且 `summary` 现取能报出该次授权与执行结果。
     ⚠️ **验收样例的硬约束（`#478` 行内点名）**：**不得拿 2026-09-03 `B-0903_70`（FI9）那批当样例**——FI9 只有 `config.py`／`models.py`／测试，**无服务入口、无部署对象**，排期 2027；拿它验收等于用一个没有部署对象的批次证明部署链路可用。
  2. 反例守卫在 CI 上真实拦下一次人为注入的复制文本（负例验证，不是"跑绿了就算"）。
  3. `openspec validate --strict` 全绿（本包自身）；`工具-泳道看护状态机.py` 既有 70 例单测零漂移。
- **价值指标**（**工时型 ＋ 风险型**双指标）：
  - **工时型 · 基线**：一项 `.51` 部署从"泳道产出就绪"到"真正部署完"的等待时长 ＝ 等到下一次「我已回Lan」收口批（以 `reports/lane-watch-state.json` 的 `transfers.recorded_at` 到对应收口批完工时刻的实测差值为准，**不许会话自算**）。**目标值**：他在环且 on-LAN 的场合下降至同 session 内完成。
  - **风险型 · 基线**：现行「不部署」防线 ＝ opener 起草者每批手写一句（人守，同族已实测失效 3 次：`#284` ⑦⑧⑨）。**目标值**：无授权留痕时放行次数 ＝ 0（结构上不可能——闸拒绝并非零退出）。
  - **基线确认人**：Shao Peishen。
- **LLM 判据黄金集**：**不适用**。本包不含任何 LLM 运行时判断，全部为确定性的探针读值、字段存在性检查与文本匹配。

## Impact（影响面）

**受影响 specs**：新增能力 `lane-watch-deploy-authorization`（本包 delta spec）；**修改** `lane-watch`（其 ⏭️ 档 requirement 的处置语义由"一律转出、本包不执行"变为"转出仍先发生 ＋ 授权后可条件续做"，属既有 requirement 的真实改写，不能只靠新增一份 spec 绕过——具体 MODIFIED 块见本包 `specs/`）。

**受影响代码/文档**（全部在 apply 阶段动，本轮零改动）：`0-学习与工具/工具-泳道看护状态机.py`、`0-学习与工具/test_工具-泳道看护状态机.py`、`0-学习与工具/skills源码/zhuopin-lane-watch/SKILL.md`、`openspec/changes/lane-watch-mode/design.md`、反例守卫落点（design 决策点 6 裁定后确定）。

**明确不受影响、且刻意不动的**：

- 🔴 `0-学习与工具/skills源码/zhuopin-lan-closeout/SKILL.md` —— **被指向方，本包一行不改**。它是那套纪律的唯一正本；本包若改它，"指向而非复制"就退化成"两处都能改"。
- 🔴 **「`.51` 归 `zhuopin-lan-closeout` 管」这条根边界不改**（`#478` 行内明确）——本包只解时序约束。
- `0-学习与工具/工具-opener批处理执行v2.ps1` —— 解析器与哨兵语义不变，本包不新增哨兵。
- `transfer_out_lane` 的「不进 pause/resume 问答循环」语义不变——转出仍先发生、泳道仍不停；授权是转出**之后**的一个独立分支，不是把转出改回问答。

**红线核对**：

- **mock 先行**：单测层注入假探针与临时状态文件，**不触碰 `.51`、不发真实请求**；真实验证留待他在场时另做，如实登记不假装闭合。
- **audit 留痕**：授权与执行结果写入 `reports/lane-watch-state.json`（既有留痕载体），`summary` 现取报出——IATF 可追溯口径下，"谁在什么时候授权了哪一项部署"必须可回溯到具体记录，这正是本包新增字段的存在理由。
- **OEM 隔离**：不涉及——不含任何 OEM 技术数据。
- **L2 门禁**：不涉及——`.51` 部署属 ⏭️ 档，与 L2 门禁（>50 万／新供应商／交付预测推客户）不同族；🔴 档四项（对外发送／L2 签字／合规红线／ASIL C-D）本包**一项不放宽**。
- **ISO 26262 / ASIL**：不涉及——非安全相关代码；ASIL C/D 绝对禁区不动。
- **凭据纪律**：本包全部产出**不含任何口令、URL 值或凭据**；`.51` 的门禁口令读取属已知禁区（不重试 SSH 读 `.env`），本包不涉及也不绕过。
