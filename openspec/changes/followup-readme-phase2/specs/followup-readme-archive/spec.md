## Purpose

跟进信 README 主表中已进入终态且长期不再变化的行 SHALL 定期迁出到按月归档件，在不丢失任何读取方既有语义的前提下把主表体积控制在可人工阅读的规模。

## ADDED Requirements

### Requirement: 归档判据
一行 SHALL 被判定为可归档，当且仅当其「发送状态」列以 `📥 已回件并回灌` 或 `❌ 已作废` 开头，且该状态最后一次变更距归档执行时刻已超过 30 天。不满足任一条件的行 MUST NOT 被迁移。

#### Scenario: 满足归档判据的行被迁移
- **WHEN** 一行「发送状态」以 `📥 已回件并回灌` 开头，且该状态写入距今已超过 30 天
- **THEN** 该行被整行迁移到对应月份的归档件

#### Scenario: 未满 30 天的终态行不迁移
- **WHEN** 一行「发送状态」已是终态标记，但状态写入距今不足 30 天
- **THEN** 该行保留在主表，不被迁移

#### Scenario: 非终态行不迁移
- **WHEN** 一行「发送状态」不以任一终态标记开头（如仍是 `⏳ 待你审`／`✅ 已推送…`）
- **THEN** 该行保留在主表，不被迁移，无论其时间跨度多长

### Requirement: 归档件表头与内容原文原样
归档目标文件 `README-归档-YYYYMM.md` SHALL 使用与主表相同的表头与列序；被迁移行的内容 MUST 原文原样写入归档件，不得在迁移过程中改写、压缩或省略任何字段。

#### Scenario: 迁移后内容与迁移前逐字节一致
- **WHEN** 一行被迁移到归档件
- **THEN** 归档件中该行的六个字段值与迁移前主表中的值逐字节一致

### Requirement: 归档编号不复用
一个编号（如 `财务部#3`）一旦被写入主表，无论该行后续是否被迁移到归档件，该编号 MUST NOT 被后续任何新增行复用。

#### Scenario: 已归档编号不被复用
- **WHEN** `财务部#3` 已被迁移到归档件，此后为财务部新增一封跟进信
- **THEN** 新行编号为该部门计数器下一个未使用过的编号，不为 `财务部#3`

### Requirement: 活行读取方语义不变
仅依赖「该收信人最新一封信」判定结果的读取方（如跟进闸查询）SHALL 在归档实施后得到与实施前一致的判定结果，无论该收信人的历史信件是否已被归档——判定范围恒定为主表当前存在的行。

#### Scenario: 最新一封已归档，闸判定仍正确
- **WHEN** 某收信人当前在主表中最新的一封信已满足归档条件并已被迁移，但主表仍保留其更早的非终态历史行（若存在）或该收信人当前无主表在途行
- **THEN** 跟进闸查询对该收信人的判定结果（闸开/闸锁）与归档前的既有语义一致，不因归档动作本身产生误判

### Requirement: 全量读取方改为主表未命中再查归档
需要跨历史匹配的读取方（如按编号回填历史统计）SHALL 改造为「先查主表，主表未命中该编号时再查归档件」的两段式查找，且该改造后的输出结果 MUST 与改造前对相同输入的输出结果一致。

#### Scenario: 编号仍在主表，改造后行为不变
- **WHEN** 全量读取方查询一个仍存在于主表的编号
- **THEN** 查找在主表阶段命中并返回，不触发对归档件的查询

#### Scenario: 编号已归档，改造后仍可查到
- **WHEN** 全量读取方查询一个已被迁移到归档件的编号
- **THEN** 主表未命中后自动查询归档件并返回该编号对应的行内容，结果与归档前直接从主表查得的结果一致
