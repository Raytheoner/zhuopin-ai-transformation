## Why

### ⑴ 病灶：stage 是按清单的，**commit 不是**

`工具-落库sweep.py` 文件头「五条硬要求」第 ① 条自陈：

> ① 只 `git add` 各批次行列出的文件，绝不 `git add -A`——见 `_resolve_batch_files()`，仅对已在批次"文件清单"列中以反引号标出的路径做 add，其余任何脏文件一律不碰。

🔴 **这句话对 `git add` 成立，对 `git commit` 不成立——而决定 commit 内容的是后者。**

**取证（本次 propose 期实跑 AST 扫描，非阅读印象）**：全文 6636 行里共 **6 处 `git add`、5 处 `git commit`**，落点如下（行号为 propose 期快照）：

| # | 函数 | `git add` 落点 | `git commit` 落点 | commit 是否带 pathspec |
|---|---|---|---|---|
| 1 | `_run_scheduled_task_mirror_sync` | L1936（`--` 镜像目录） | L1938 | ❌ 无 |
| 2 | `_commit_uncovered_queue_changes` | L2685（`--` 队列文件） | L2686 | ❌ 无 |
| 3 | `_process_normal_batch`（**主路径**） | L5067（`--` 清单 resolved）＋ L5072（`--` 队列文件） | L5075 | ❌ 无 |
| 4 | `main()` 补销遗留尾巴 | L6306（`--` 队列文件） | L6307 | ❌ 无 |
| 5 | `_rerun_ledger` | L6488（`--` 台账文件） | L6489 | ❌ 无 |

**六处 add 全部带 `--` pathspec、确实没有一处 `git add -A`；五处 commit 全部是裸 `git commit -m <msg>`。** 而 `git commit` 不带 pathspec 时提交的是**整个 index**，不是"本进程刚 add 的那些"。index 是**工作区级的共享状态**——任何一个并发 session、任何一个中断在半路的流程、任何一次人工 `git add` 留下的暂存内容，都会在 sweep 的下一次 commit 里被**套上别人的批次标题**一起提交。

### ⑴ 的出血形态是实撞的，不是纸面推断（`OP-0827-A`，2026-08-27）

§四 `#127` 原文记录：该 session 实测到两份文件（`1-转型规划/0-全景路线图/专线opener模板库.md`、`1-转型规划/0-全景路线图/波次收口-2026-08-26泳道版-2026-08-27.md`）正被**另一条 Cowork session 实时改写**（mtime 落在本 session 运行区间内），遂**刻意不提交**，并按编辑锁给出的出路在三个批次行内写明「登记豁免：<理由>」。**release 三次都据此放行**（工具回显「✓ 检测到登记豁免声明，已放行 2 个未登记脏文件」）。

**然而 sweep 照样把它们提交了，一次不落。** 本次 propose 期已用 `git show --stat` 复核那三个提交（**手段：在本 worktree 内逐个跑 `git show --stat --oneline <sha>`**）：

| commit | 标题 | 实际含的文件 |
|---|---|---|
| `6ec17c5` | `（本批已自行 commit，无待生成 message）` | 专线opener模板库.md（+42）／波次收口-…-2026-08-27.md（+186 新建）／跨桌任务队列-机制环境.md（±2） |

| `f20bd5a` | （§二 批次标题） | 同上两份（+7／±4）＋ 队列文件 |

⇒ **`登记豁免` 的实际语义是「豁免登记完整性校验」，不是「豁免提交」**；而工具给出这条出路时的措辞读起来像是「这些文件本次不处理」。

🔑 **为什么这条比它看起来严重**（`#127` 原文三点，本包如实承接）：
1. **它让一条正确执行了纪律的 session 反而制造出被禁止的结果**——每一步都按工具指引做，得到的却正是纪律要防的那个结局（两条 session 的收工混进同一个提交，此后再也分不开）。
2. **失败无声**：release 打 ✓、sweep 也打 ✓，**两边都报成功而结果是错的**，只有事后 `git show --stat` 才看得出夹带。
3. 它与 §四 `#126` 同族但更靠前——`#126` 是「信号被埋在输出里」，本条是**「信号本身就是错的」**。

### ⑴ 的受控复现（propose 期实跑，一分钟可重放）

🔴 **不靠"读代码觉得是这样"，用 `git commit --dry-run --short` 当场坐实**（在本 worktree 内跑，未产生任何 commit，收尾已 `git restore --staged` ＋删文件还原）：

```
# 造一个"别人暂存进 index 的孤儿" + 一个"本批清单声明的文件"
printf 'declared\n' > _repro_declared.md ;  printf 'orphan\n' > _repro_orphan.md
git add -- _repro_orphan.md          # ← 模拟并发 session / 中断流程留下的 index 内容
git add -- _repro_declared.md        # ← sweep 自己按清单 add 的那一步

# A) sweep 现状：commit 不带 pathspec
git commit --dry-run --short
    A  _repro_declared.md
    A  _repro_orphan.md          ← 🔴 孤儿被带进这次提交

# B) 修法候选：commit 带 pathspec
git commit --dry-run --short -- _repro_declared.md
    A  _repro_declared.md
    ?? _repro_orphan.md          ← 孤儿留在工作区，未进提交
```

**追加实测（决定 design 决策点① 的关键差异，同一轮跑出）**：把 `_repro_declared.md` 在 `git add` **之后**再改一次（模拟并发 session 在 sweep 的 add→commit 窗口里动了声明件）：

```
git commit --dry-run --short                       →  AM _repro_declared.md   （取 index 快照＝add 那一刻的内容）
git commit --dry-run --short -- _repro_declared.md →  A  _repro_declared.md   （取工作树当前内容）
```

⇒ **带 pathspec 的 `git commit` 隐含 `--only` 语义，提交的是"这些路径此刻的工作树内容"，不是"add 那一刻的 index 快照"。** 这不是细节，是 design 决策点① 必须拍的那个取舍——见 `design.md`。

### ⑵ 真风险：不是今天在出血，是明天没人拦

§四 `#126` 裁决原文（Shao Peishen 2026-09-03 取 ⒜ 维持现状）另立了这条：

> 「下一次同样的抛落在 `_reconcile_with_origin_and_push` 这类关键路径上而仍被宽 except 接住 ⇒ **sweep 说自己跑完了、实际某一步没做**」。

🔴 **propose 期已白盒核实今天的实际状态（手段：AST 扫描本文件全部 `ExceptHandler`，按函数归属统计，非 grep 印象）**：

- 全文 **66 个 except 分支，其中 31 个是宽捕获**（`except Exception` 29 ＋ `except BaseException` 2）。
- 但按函数看**关键路径今天是干净的**：`_reconcile_with_origin_and_push`／`_push_any_unpushed_commits`／`_pop_reconcile_autostash`／`_commit_uncovered_queue_changes`／`_strike_off_rows`／`_process_normal_batch`／`_rerun_ledger` —— **七个函数体内 except 分支数全部为 0**。
- `_run_scheduled_task_mirror_sync` 内有 3 个宽 except，但**都不罩着它的 `git add`／`git commit`**（L1927 只罩子进程调用且在 except 内 `return`；L1952／L1970 罩 webhook 推送）。
- `main()` 内 5 个：L6427 `except SweepAbort`（专用）、L6438 通用兜底（**已 fail-loud**：日志＋traceback 尾 6 行＋企微推送＋独立退出码 `UNEXPECTED_EXIT_CODE`，来源 #198(a)）、L6463／L6467 在兜底内部（推送失败、日志落盘失败）、L6242 是 **#136 裁定原文明确要的 fail-open**（`_manifest_coverage_gap` 校验自身异常只留痕、按旧判据继续）。

🔑 **⇒ 如实结论：⑵ 今天不是一个正在出血的缺陷，是一条"今天成立、但没有任何东西保证它明天还成立"的性质。** `#126` 那句话本身就是未来时（「下一次……」）。本包对 ⑵ 的正确定位是**回归守卫 ＋ 兜底告警点名**，不是"收窄一堆现存 except"——把 31 处宽 except 全量改写会让本包从"两处同触碰修"膨胀成一次全文件重构，是本项目反复付过学费的形态。

**⑵ 现存的一处真实可改进点（不涉及 except，涉及"点名"）**：`main()` 的通用兜底只喊「未预期异常 `<类型>: <消息>`」＋ traceback 尾 6 行，**不说本轮跑到哪一步**。读者要从 traceback 反推「是批次没提交、还是提交了没推送」。而这两者的人工处置动作完全不同。⇒ 给流水线加一个**步骤指纹（breadcrumb）**，让兜底告警能直接点名"在『收尾段对齐并推送』这一步抛的"。

### 本次退休哪一个既有守卫（协议〇.9 措施 B，机制类变更包强制回答）

🔴 **如实答：本包不退休任何**代码**守卫，且论证为什么不能退；但确有一条"待办的人守修补"被本包功能性取代。**

- **不能退：编辑锁 release 守卫⑹（登记完整性校验）**。裁决原文已把两者定位成互补——「**漏写文件的风险由 release 守卫⑹ 兜住（未覆盖脏文件即拒绝）**」。本包收紧 stage 范围后，**清单漏写的代价从"被顺带提交"变成"根本不落库"**，⑹ 正是那道让人在写队列时就发现漏写的闸。退掉它 ⇒ 漏写变成静默不落库，比现状更糟。
- **不能退：`_manifest_coverage_gap`（#136 覆盖校验）**。它管的方向相反——「**声明了但装不进去**」（空壳提交，6557047 形态）；本包管「**没声明却被装进去**」。两个方向不重叠，退任一个都留一半洞。
- **不能退：`_track_and_alert_orphan_paths`（#238 孤儿告警）**。本包收紧后孤儿脏文件**不再被顺带带走**，它们会留在工作区 ⇒ 孤儿告警的价值**上升而非下降**，它是本包的下游承接方。
- 🔴 **确有一条被功能性取代的"待办人守"**：§四 `#127` 的建议 ⒞「最小改动＝只改措辞，把编辑锁那句出路改成『登记豁免：<理由>（🔴 注意：只免检查，不免提交）』」。本包落地后**那句话不再需要写**——豁免的文件本来就不会被带走了。**如实标注：这不是"删掉一段代码"的退休，是一条尚未落地的人守修补被机制取代**，不宜包装成 one-in-one-out 已履行。apply 期须在 §四 `#127` 行内追加一句指针说明 ⒞ 已无必要（**只追加、不改历史正文**）。

### 伴生文件的 `.gitignore` 覆盖（强制段，队列 #328②）

**答：取决于 design 决策点① 选哪一个，两种情形都已实测、不留推断。**

- **决策点① 若选 ⒜（pathspec commit）／⒝（提交前清扫 index）／⒟（只断言不修）**：本变更**不新增任何自动生成文件**——只改 `git commit` 的调用参数、或新增只读断言，无 `write_text`／`open(..., "w")`／`rename` 新增调用点。
- **决策点① 若选 ⒞（临时 index，`GIT_INDEX_FILE`）**：会新造一个此前不存在的文件名形态（临时 index 文件）。🔴 **实测结果（本 worktree 内实跑）**：`git check-ignore -v .git/sweep-tmp-index` **退出码 1、无输出**（即 `.gitignore` **不**命中），但 `git ls-files .git` 输出为空、`git status` 从不遍历 `.git/` ⇒ **放在 `.git/` 下无需 `.gitignore` 覆盖，因为它压根不在 git 的扫描范围内**。
  🔴 **但这正是 #322／#328② 那条教训的复发点**：若实现时图省事把临时 index 落在**工作树内**（如 `reports/` 或仓库根），它会立刻变成 `git status` 恒报的未跟踪文件、被 sweep 判为孤儿脏文件、企微群连响。⇒ **决策点① 选 ⒞ 时，spec 里必须硬性规定临时 index 只能落在 `.git/` 下**，且 apply 期须用 `git status --porcelain` 实跑一次确认工作区不出现新文件名形态（**不是推断，是实跑**）。

## What Changes

### ⑴ 落库提交只覆盖本批清单声明的路径

- **① 主路径 `_process_normal_batch` 的提交范围收紧为「本批 `resolved` ＋ 该批次所在队列文件」**——清单之外的任何 index 内容（含被 `登记豁免` 放行的脏文件、并发 session 暂存的内容、中断流程的残留）**不得**进入该批提交。
- **② 其余四处 sweep 自动提交（镜像核对／队列孤儿改动／补销遗留尾巴／台账重跑）同样收紧**为「只提交本步骤自己 add 的那些路径」——它们各自的 add 早已是 pathspec 的，收紧只是让 commit 与 add 对齐（作用面由 design 决策点② 拍板）。
- **③ 提交后校验（post-condition）**：提交完成后核对该 commit 实际含的路径集合，与预期集合不一致即**出声告警**（不静默）。这条是本包的"非恒真自证"锚点——没有它，"已收紧"与"碰巧没人暂存过东西"外观相同。
- **④ 撞上清单外 index 内容时的处置**由 design 决策点③ 拍板（静默不带走／点名告警／整批跳过三选一）。
- **不改动**：`_resolve_batch_files` 的清单解析与匹配规则（精确相等优先／后缀匹配／三分类）一行不动；`_manifest_coverage_gap`（#136）一行不动；`_looks_like_declared_path`（#136 形状判据）一行不动；`_partition_pending_rows_by_batch_isolation`（#238 批次隔离）一行不动；`_track_and_alert_orphan_paths` 一行不动；编辑锁 `工具-共享文档编辑锁.py` **本体一行不动**。

### ⑵ 关键路径的异常不得被静默吞掉

- **⑤ 定义一份「关键路径函数清单」常量**（哪些函数进清单由 design 决策点⑤ 拍板），并新增**回归守卫单测**：清单内函数体内**不得**出现 `except Exception`／`except BaseException`／裸 `except`。**逐字沿用本文件已有的同款守卫范式**——`LocalOnlyCommitGuardTests::test_本类不做任何git写动作` 已经在用「按源码文本切片 ＋ `ast.parse` ＋ `ast.walk` 断言」锁执行构件（`0-学习与工具/test_工具-落库sweep.py` L6827）。
- **⑥ 给流水线加步骤指纹**：`main()` 每进入一个关键步骤即更新一个"当前步骤"标记；通用兜底（L6438）与企微告警文案**点名该步骤**，让「跑完了」与「跑到第 N 步没做完」在日志与告警上不再同形。
- **⑦ 现存 31 处宽 except 全量分诊表**（告警类／加载类／#136 fail-open 裁定类／兜底类），**只登记进 `design.md`、本包一处不改**——避免把"两处同触碰修"膨胀成全文件重构。
- **不改动**：🔴 **`_run_git` 的 `encoding=`／`errors=` 一个字节不改**（§四 `#126` 本体已裁 ⒜ 维持现状，本包不复议）；L6242 的 #136 fail-open **不动**（那是裁定原文明确要的取向）；所有告警／推送路径上的宽 except **不动**（"告警失败不应影响本轮退出码"是既有且成立的取向）。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

1. **本流程哪些判断是人脑默会经验？**
   - **「这次提交里应该有哪些文件」**——此前完全依赖"index 里恰好只有该有的东西"这个**从未被任何机制保证过的假设**。`OP-0827-A` 实证该假设在并发场景下不成立，且失败一次的代价不可逆（两条 session 的收工混进同一提交，事后分不开）。本包把它显性化为**一条可执行的等式：提交内容集合 ＝ 清单声明集合**。
   - **「`登记豁免` 到底豁免了什么」**——此前只在写这行代码的人脑子里（豁免的是 ⑹ 校验，不是提交），而**工具的措辞诱导出了相反的预期**。本包让这两者重合：写了豁免的文件，确实不会被提交。
   - **「哪些函数是关键路径、不许在里面加宽 except」**——此前完全没有成文，只靠 code review 时有人恰好想起来。本包把它显性化为**一份具名清单 ＋ 一条机器判据**。
2. **由谁显性化？** 决策人 **Shao Peishen**（design 审拍板六个决策点，本包止步于起草、不代拍板）；CC 建造车间负责实现、单测与现网只读回归；backup ＝ 下一位领取 `#479` 的 session 可凭本包与 `design.md` 独立复核（本 proposal 里每一条取证都写明了手段与可重放命令，任何人可现取比对）。
3. **用什么方法提取？** **历史真实案例反推**（`OP-0827-A` 一次真实夹带，三个提交的 `git show --stat` 已复核）＋ **受控复现**（`git commit --dry-run` 两侧对照，本文 §Why 可一分钟重放）＋ **白盒 AST 全量扫描**（6 处 add／5 处 commit／66 个 except 分支按函数归属统计）。不涉及 LLM 判断，纯静态结构规则。

## 已知残余风险（如实写明，不粉饰）

1. **收紧之后，"漏写清单"的代价从"被顺带提交"变成"根本不落库"。** 承接方是编辑锁 release 守卫⑹（写队列时就拒绝未覆盖脏文件）与 `_track_and_alert_orphan_paths`（孤儿告警）。⚠️ **但守卫⑹ 有两条已成文的身份豁免**——`SWEEP_LOCK_WHO`（sweep 自身）与企微机器人（`#416` ⑶）。这两个身份写队列时**不受 ⑹ 约束** ⇒ 它们造出的清单外脏文件，只剩孤儿告警一道兜底，且那是**告警、不是闸**。这条不是反对收紧的理由（现状是"被静默夹带"，更糟），但**必须如实写进交付措辞**，不得说成"漏写风险已被完全兜住"。
2. **决策点① 若选 ⒜（pathspec commit），提交内容的语义会从"index 快照"变成"工作树当前值"**——受控复现已坐实（`AM` vs `A`）。含义：若并发 session 在 sweep 的 add→commit 窗口里改了**某个被声明的文件**，sweep 会提交它**更新后**的内容，而不是 add 那一刻的内容。窗口极短但非零。⇒ 这是决策点① 的核心取舍，不能当实现细节带过。
3. **⑵ 的守卫锁的是"形状"，不是"语义"。** AST 断言只能看住"清单内函数体里没有宽 except"；它拦不住「把关键逻辑挪进一个不在清单里的小函数、再在那儿宽捕获」这类改写，也拦不住 `except OSError` 这类**窄但同样吞掉真问题**的捕获。⇒ 清单本身需要随代码演进维护，**本包不隐含"此后关键路径永不会被静默吞掉"**。
4. **"关键路径清单"是一份需要人维护的名单**，天然存在漂移。缓解手段（apply 期落地）：清单常量旁写明"新增任何会 `git commit`／`git push` 的函数必须进本清单"，并在同一组单测里加一条**反向检查**——全文中调用了 `commit`／`push` 动词的函数若不在清单里即报出。⚠️ 该反向检查同样是形状判据，不是真值。
5. **本包不改变 sweep 对"非 clean 整轮跳过"的既有门禁**，因此绝大多数情形下清单外脏文件会在更早的门禁处就让整轮跳过。⑴ 真正覆盖的是**门禁放行、但 index 仍含清单外内容**的那个交集（`OP-0827-A` 正落在这个交集里）。⇒ 交付措辞只能是「本批提交内容已限定在清单声明范围内」，**不得**写成「sweep 提交从此不可能含意外文件」。
