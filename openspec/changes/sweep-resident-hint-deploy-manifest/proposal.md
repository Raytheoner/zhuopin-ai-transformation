## Why（为什么做）

**一句话**：`工具-落库sweep.py` 的「常驻服务部署提示」判据只做路径前缀匹配，**改一份 `.md` 文档也会告诉人「需 sync-to-server.ps1 同步并重启 ZhuopinAibotDevListener」**——而那次同步与重启根本不会搬走这份文档，提示说的是一件不存在的事。

**实证（非推断）**：2026-08-22 14:52 运维群收到该告警，触发它的批次 `B-0822_17` 在 `5-平台底座/wecom-aibot-service/` 下**只改了 `CLAUDE.md` 一份文档、零行代码**（批次行见 `1-转型规划/0-全景路线图/跨桌任务队列-机制环境.md` L171）。

**为什么值得修，而不是当噪音留着**：**误报的代价不是噪音，是它会训练人忽略这条告警。** 而这条告警存在的全部意义，正是真改了常驻服务代码时把人拦住（成因＝`#126`／`#193`／`#221`／`#228` 那族「代码已提交但生产未生效」）。**等它被忽略成习惯，真出事那次也不会有人看。**

**为什么现在有条件修准，而 2026-08-04 建它时没有**：`#198(c)` 建这条提示时，「本批改动到底需不需要同步重启」只能靠路径前缀近似。而实测发现**该问题已有一份现成的、机器可读的真值**——`5-平台底座/wecom-aibot-service/sync-to-server.ps1` 的 `-AppFiles @("pyproject.toml", "aibot_service", "scripts", "deploy-server.ps1")`，且 `5-平台底座/deploy-tools/ZhuopinDeploy.psm1` 对该参数的注释写明了设计意图：「**刻意白名单而非整目录同步**：避免带上 reports/（含真实客户名/审计明细）、tests/、.venv 等不该上服务器的内容」。

⇒ **判据不需要猜文件后缀，直接对齐部署脚本自己的清单。** 这一点决定了修得干净还是只修一半：派单件建议的「非 `.md`／非 `docs/` 则报」只能挡住 `CLAUDE.md` 与 `部署到长开服务器-企微智能机器人.md` 两份，而 `tests/`、`register-*.ps1`、`run-*.vbs`、`sync-to-server.ps1` **自己**这四类同样不上服务器，仍会继续误报。Shao Peishen 2026-08-22 据此拍板走部署清单判据。

### 守卫退休问答（MANDATORY · 协议〇.9 措施 B / one-in-one-out）

**本次退休一条既有的失效判据，且不新增任何独立守卫。**

**退休对象**：`openspec/specs/sweep-startup-resilience/spec.md` §「常驻服务改动部署提示」中的**判据半句**——「当本轮 sweep 处理的批次**命中有常驻服务副本的路径**（如 `5-平台底座/wecom-aibot-service/`）时」及其对应 Scenario「本轮落库的批次文件清单中**包含 `5-平台底座/wecom-aibot-service/` 下的路径**」。

**为什么必须退休它，而不是在它之外再加一层**：这半句**本身就是缺陷的成文形态**。它把「有常驻服务副本的**目录**」当成了「有常驻服务副本的**文件**」，而该目录下真正被部署的只有四个条目（见 What Changes ①）。若只在代码里补一层过滤而不动 spec，就会出现「spec 说该报、代码不报」这种**两套判据各自为政**的形态——正是 `#80` 一期刻意避免的那种（「lint 说 7 条、release 说 6 条」）。故本包**改写该 requirement 的判据半句**，其「纯提示、不阻断、不改退出码」的约束半句一字不动。

**为什么不新增守卫代码**：本变更是**收窄一个既有判据**，不是新增一道检查——变更前后 sweep 的告警种类数、调用点数、守卫函数数**全部不变**（`_touches_resident_service` 一进一出，仍是同一个函数、同一个调用点）。新增的单测属反例锁定，不构成需要日后维护的独立守卫。

⚠️ **一处如实说明**：本包确实引入了一份**跨语言副本**（`.ps1` 的 `-AppFiles` 清单在 Python 侧再写一份）。这与本项目反复记录的「同一事实两份副本、改一处漏另一处」（README 编号段三次复发、`#345` 的 35 份手抄副本漂成 4 种语义）同族，**不能假装它不存在**。处置见 `design.md` 决策点 2：副本无法消除（跨语言，sweep 不解析 PowerShell），但配**漂移守卫单测**——该测直接读 `sync-to-server.ps1` 真身、解析其 `-AppFiles` 行、与 Python 常量逐项比对，**两边不一致即红**。⇒ 副本仍在，但「漂移后静默生效」在结构上不再可能。

### 伴生文件的 .gitignore 覆盖问答（MANDATORY · 队列 #328 子项②）

**不适用：本变更不新增任何自动生成的文件名形态。** 本变更只改动 `工具-落库sweep.py` 内的一个常量与一个纯函数、并新增单测，不新增锁文件、快照、暂存、状态文件、日志、重命名退路产物或备份副本。sweep 既有的状态文件（`reports/sweep-fork-state.json`、`reports/sweep-orphan-state.json` 等）与运行日志（`reports/sweep-commit.log`）**文件名形态一字未变**，忽略规则沿用现状、不受影响。

## What Changes（改什么）

**① 判据由「目录前缀」收窄为「目录前缀 ∩ 部署清单」** —— `0-学习与工具/工具-落库sweep.py`：

现状（L484 与 L1177-1178）：

```python
RESIDENT_SERVICE_PATH_PREFIXES = ("5-平台底座/wecom-aibot-service/",)

def _touches_resident_service(paths: set[str]) -> bool:
    return any(p.startswith(RESIDENT_SERVICE_PATH_PREFIXES) for p in paths)
```

改为：前缀命中后，再要求该路径**在前缀之后的第一段**落在该常驻服务的部署清单内。清单取自 `sync-to-server.ps1` 的 `-AppFiles`，即 `pyproject.toml`／`aibot_service`／`scripts`／`deploy-server.ps1` 四项。数据结构由「前缀元组」改为「前缀 → 部署清单」的映射，使日后新增第二个常驻服务时**必须同时给出它的部署清单**，无法只加前缀（结构上堵住本缺陷的复发路径）。

**判定表（实测该目录当前全部 12 个顶层条目，逐条有归属、无一项靠推断）**：

| 顶层条目 | 在 `-AppFiles` 内 | 改它是否需同步 | 改后是否该报 |
|---|---|---|---|
| `aibot_service/`（含 `.py` 与 `.yaml` 配置） | ✅ | 是 | **报** |
| `scripts/` | ✅ | 是 | **报** |
| `pyproject.toml` | ✅ | 是 | **报** |
| `deploy-server.ps1` | ✅ | 是（在服务器上执行） | **报** |
| `CLAUDE.md` | ❌ | 否 | 不报 |
| `部署到长开服务器-企微智能机器人.md` | ❌ | 否 | 不报 |
| `tests/` | ❌（psm1 注释明列为刻意排除） | 否 | 不报 |
| `sync-to-server.ps1` | ❌（同步工具自身，在笔记本跑） | 否 | 不报 |
| `register-decision-reminder-task.ps1` | ❌ | 否（在 `.51` 上手工跑一次注册任务） | 不报 |
| `register-followup-dispatch-task.ps1` | ❌ | 同上 | 不报 |
| `run-hidden.vbs` | ❌ | 否 | 不报 |
| `run-decision-reminder-hidden.vbs`／`run-followup-dispatch-hidden.vbs` | ❌ | 否 | 不报 |

⇒ **收窄后被排除的不止 `.md`**：`tests/`、三个 `.vbs`、两个 `register-*.ps1`、`sync-to-server.ps1` 自身共 7 类同样不再误报，这是部署清单判据相对「非 `.md`」判据多治掉的部分。

**② 混合批次照报（不做多数表决）** —— 本批在该前缀下同时含文档与代码时，**只要有任一路径命中部署清单即发提示**。理由：提示的作用是提醒「有东西需要同步」，一份代码没同步就足以造成失配，不因同批还改了十份文档而稀释。配单测锁定。

**③ 提示文案不分档** —— 仍为单一文案（「需 `sync-to-server.ps1` 同步 `ops/wecom-service-home` 并重启 `ZhuopinAibotDevListener` 后才在生产生效」）。`deploy-server.ps1` 严格说只需同步、不必重启，但它是四项里唯一的这种情形、且极少改动，**为它拆两套文案的收益低于让文案保持单一好记**。见 `design.md` 决策点 3。

**④ 漂移守卫单测** —— 新增一条单测直接读 `5-平台底座/wecom-aibot-service/sync-to-server.ps1` 真身，正则提取其 `-AppFiles @(...)` 行，与 Python 侧常量逐项比对；不一致即失败。⇒ 日后任何一方改了清单而另一方没跟上，**在 CI 当场红**，不会漂到生产。

**⑤ 明确不做（本次范围外，已按 Shao Peishen 2026-08-22 拍板另登记）** —— 同一判据还有**反向缺陷**：`sync-to-server.ps1` 同时同步 `5-平台底座/zhuopin_platform`（`-LocalPlatformDir`），而该路径**不在** `RESIDENT_SERVICE_PATH_PREFIXES` 内 ⇒ **改底座代码会真实影响常驻服务、却一声不吭**。⑶ 治的是「多报」，这是「漏报」，同一判据的两面。本包**不扩范围**（纳入会让几乎每次底座改动都触发告警，属扩大告警面，该单独评估），另立 §四 一行待派。本包的映射结构已为其预留扩展位。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

1. **本流程哪些判断是人脑默会经验？**
   - **「这次改动到底需不需要同步并重启常驻服务」** —— 此前完全是默会的：sweep 用路径前缀近似，人收到告警后各自在心里判断一次「这次好像只是文档吧」。本变更把它显性化为一条可机械执行的判据：**看该路径是否落在部署脚本的 `-AppFiles` 白名单内**。
   - **该白名单本身是既有显性资产、非本次新造** —— 它已成文在 `sync-to-server.ps1` 里，并由 `ZhuopinDeploy.psm1` 的参数注释写明设计意图（刻意白名单、排除 `reports/`／`tests/`／`.venv`）。**本次做的是把一份已显性化、但此前只有部署脚本一个消费者的知识，接到告警判据这第二个消费者上**。
   - **例外**：`deploy-server.ps1` 需同步但不需重启（见 What Changes ③），已成文，不再默会。
   - **阈值/尺度类**：本变更无阈值、无比例、无时间窗。
2. **由谁显性化？** 持有人 **陈承**（IT，`.51` 常驻服务的实际运维方、运维群受众）；backup **Shao Peishen**（本判据的拍板人，2026-08-22 定判据取部署清单）。本变更**不新增**需登记进《跨场景前置数据与知识库任务总表》§一.2 的知识资产条目——该知识已在部署脚本内成文，本包只是把它接到第二个消费者上。
3. **用什么方法提取？** **历史案例反推** —— 依据是 2026-08-22 那次真实误报（批次 `B-0822_17`，运维群 14:52 收到），以及对该目录当前全部 12 个顶层条目逐条对照部署清单的判定（见 What Changes ① 判定表）。

## 验收与晋档条件（强制，四档口径）

- **本变更包交付后场景所处档位**：**档 3（内部服务）**。sweep 是已在生产每小时运行的内部机制，本变更改的是它的告警判据，交付即在生产链路内生效。
- **晋下一档的条件**：**不适用** —— 档 4 为「对客交付」，sweep 是内部机制，永不对客，无晋档路径。
- **本包验收判据（逐条，全过才算收口）**：
  1. **正判据**：构造一个只碰 `5-平台底座/wecom-aibot-service/aibot_service/` 下 `.py` 的批次，提示照发（单测覆盖）。
  2. **负判据（本变更是否真的止住误报的判据）**：构造一个只碰 `5-平台底座/wecom-aibot-service/CLAUDE.md` 的批次——**即 `B-0822_17` 的最小复现**——提示不发、webhook 零投递（单测覆盖）。⚠️ 仅验证 1 不足以收口：它只证明「该报的还报」，不证明「不该报的不报了」，而后者才是本包存在的理由。
  3. **混合批次判据**：同批含 `CLAUDE.md` ＋ 一份 `aibot_service/*.py`，提示照发（单测覆盖）。
  4. **漂移守卫判据**：Python 常量与 `sync-to-server.ps1` 的 `-AppFiles` 逐项一致（单测直读 `.ps1` 真身比对）。
  5. `0-学习与工具` 全量回归零漂移；`openspec validate --all --strict` 全绿；队列结构 lint／引导样板 lint／凭据扫描三道既有门禁未回归。
- **价值指标**（风险型）：
  - **基线（已实测，非估计）**：2026-08-22 单日误报 **1 条**（`B-0822_17`，运维群 14:52）。⚠️ **基线只有这一条是被实证过的**——`reports/sweep-commit.log` 的历史行只记「常驻服务部署提示已推送」，**不记该批次改了哪些文件**，故历史误报率无法从日志回溯统计，**本包不编造一个历史基线数字**。
  - **目标值**：本变更生效后，**纯文档批次触发该提示 = 0 次**。
  - **量法**：此后每次该提示发出时，比对触发批次的文件清单是否含部署清单内条目；出现纯文档批次触发即为回归。
  - **基线确认人**：Shao Peishen（该告警的受众与本判据拍板人）。
- **LLM 判据黄金集**：**不适用**。本变更不含任何 LLM 运行时判断，全部为确定性的路径字符串匹配。
