# queue-write-root-fix-414 Proposal

## Why

队列 §一 #414（2026-08-26 派单件 OP-0826-N A 组）：**队列单元格的内容会落错结构位，而且不报错**——2026-08-25／26 两天内同一族事故连续 5 次，三种外形：

| # | 形态 | 内容变成了什么 |
|:-:|---|---|
| 1 | 裸竖线撑列 | Markdown 表格的**分隔符** |
| 2 | 反引号被 bash 执行 | **命令**（曾把 25 行 `git worktree list` 输出注入进一个单元格） |
| 3 | 列位错置 → 触碰区格 | 落进**相邻格** |
| 4 | 列位错置 → **编号格** | **行头断裂**，`grep` 与队列查询双双找不到该行 |
| 5 | 裸竖线撑列（再犯） | 🔴 **发生在「解释这个 bug」的那一行正文里** |

病灶不在人，在传输层与接口形状：① 单元格文本经 **bash argv** 传入，而本项目行文规范**要求大量使用反引号包路径与命令**（双引号包裹时 bash 把反引号当命令替换执行）；② 调用方必须自己数 `split` 后的列下标；③ 一道**已经存在且有效**的竖线守卫（`append-row` 会当场拒绝），因为存在一条绕过它的常用路径（python 插行、整文件重写）而形同虚设。

第 5 次事故最能说明问题：**它发生在写"解释这个 bug"那一行正文的时候**。按 CLAUDE.md §5「规则退休制」，人守条目违反 3 次即达阈值，必须机制化或删除——本变更是机制化。

🔑 **本变更的一句话判据**：**一道已经存在且有效的守卫，会因为存在一条绕过它的常用路径而形同虚设**——同族＝「告警机制建成 9 天、每天在跑，却从来没有真正发出过一条消息」（OP-0819-F）。故落点不是"再加一道校验"，而是"把入口收敛到同一个函数上"。

## What Changes

**修复面 A · 正文不再经过 shell**
- `append-row` 新增 `--cells-json <文件>` 与 `--stdin-json`：单元格内容以 JSON 传入，**argv 里不再出现正文**，反引号、`$()`、引号、竖线一律失去特殊性。顶层接受数组（按列序）或对象（列名→值）。

**修复面 B · 守卫覆盖所有入口**
- 单元格校验收拢进权威模块 `queue_table.validate_row_cells(section, cells, *, source)`，`append-row` 与新增的 `edit-row` 写盘前一律复用同一函数。
- 新增**关键格哨兵**（此前完全没有）：编号格非纯数字（＝行头断裂）／§一 状态格不以 `[S:` 开头／完成标记 `✅` 落进期望产出格（#412 真实形态）／单元格内含换行（命令输出注入形态）。**这一类正是列位错置唯一会留下的痕迹——格数是对的，错的是内容与格位的对应关系。**
- `source="write"|"parsed"` 区分写侧与读侧口径，**只影响竖线一项**：写侧一律拒绝（沿用既有语义不放宽）；读侧跳过（切列本身已是反引号感知的，格内被反引号正当保护的竖线合法，生产队列 §一 #324／#326 即如此）。

**修复面 C · 调用方永远不必数下标**
- `append-row --set 列名=值`（可重复）；新增子命令 `edit-row --section --number --set/--append 列名=值` —— 改**已存在**的行此前只有两条路：手工编辑器改（易改错格）、或写 python 插行/整文件重写（**完全绕过守卫**，正是 #414 认定的"真正的缺口"）。
- 新增 `SECTION_COLUMN_NAMES`／`resolve_column_index`／`build_row_cells`／`header_mismatch`。缺列 fail-loud，**不静默补空串**。

**A3-1 · lint 行头断裂盲区**
- `工具-队列结构lint.py` 新增 `_broken_row_head_violations`：抓①编号格被清空（旧实现当表头/分隔行**静默跳过**）②行首竖线丢失（`split_row_cells` 返回 None、整条丢弃）。两者共同点是**行根本进不了列数校验**。

**A3-2 · release 对"自愈"的出口**
- `_validate_release_structure` ③预留归属校验新增两条豁免：**HEAD 存在性**（该编号已在 git HEAD 同分区 ⇒ 是修复既有行、非新增）与行内逃生阀 `预留豁免：<理由>`。

- **BREAKING**：`append-row` 对**此前可以写入**的两类内容开始拒绝——① §一 状态格不以 `[S:` 开头；② `✅` 开头的期望产出格。二者在生产队列中**存量为 0**（75 条 §一 活行全部合规），且 `工具-队列结构lint.py` 早已把①作为硬门禁事后拦截，本次只是把拦截点从"事后"提前到"写入那一刻"。仓库内 5 处使用旧格式的**测试夹具**已同步更新（#308 之前的遗留写法）。
