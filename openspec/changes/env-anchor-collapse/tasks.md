## 范围改判（apply 期实测，须留痕）

**`1-转型规划/AI运营指挥中心/serve.py` 不 import 平台底座**，改为**内联同一套解析语义 ＋
等价性测试守**。

- **为什么**：该服务「零三方依赖」是**既定设计原则**（其文件顶部就三处写明，`simple_gate`
  与 `access_log` 已因同一理由各自内联一份）；`.51` 上由 `deploy-server.ps1` 注册的计划任务跑的是
  **裸 `python serve.py`**，实测其部署脚本**既不建 venv、也不 `pip install -e zhuopin_platform`**。
  若在此 import 平台底座，8092 命令中心会在 `.51` 上直接起不来——**而本地测起来永远是绿的**
  （#345 原话：「本地永远能找到仓库根标记，本地全绿与它毫无关系」）。
- **例外不能没有约束**：新增 `1-转型规划/AI运营指挥中心/tests/test_serve_env_anchor_parity.py`
  （8 例），对同一套夹具**逐布局**断言两份实现给出同一答案，含 worktree 场景与变异验证。
  spec 已补一条 Requirement 把这个手段写成契约。
- **其实质缺陷已修**：原 `_find_env` 从 `ROOT` 向上找最近的 `.env`，从 worktree 跑会拿到陈旧
  副本、门禁口令可能是上一代的。

### 🔴 兑现二：`serve.py` 在 `.51` 上会让 8092 的门禁静默失效

**部署根 `C:/command-center/{serve.py, index.html, data}` 里没有 `zhuopin_platform` 目录**
——「零三方依赖、不装平台底座」正是本服务的既定设计（见本文件「范围改判」小节）。于是三段
锚定②（monorepo marker）与③（`<root>/zhuopin_platform/pyproject.toml`）**一段都不命中**，
`_find_env()` 返回 `None`，而 `.env` 就躺在 `serve.py` 旁边 ⇒ `ZP_GATE_PASSWORD` 读不到 ⇒
**服务照起、页面照 200、只有口令没了。**

**实测（重启前，用同目录的 `_serve_probe.py` 副本，生产仍跑旧码）**：
`ROOT=C:/command-center`／`_find_env()=None`／`GATE_PASSWORD` 空／而 `.env` 确实存在。

🔑 **为什么那 8 条等价性测试一条都没红——这一条比 bug 本身更值得记住**：
它们断言的是「两份实现给出**同一个**答案」，而**两边都答 `None` 也叫一致**。
**一致 ≠ 正确。等价性守的是「两份副本不漂」，守不住「两份副本一起答错」**——这是等价性
这种测试形态的**固有盲区**，不是那批用例写得不好。补的三条新用例落在「这个布局下的正确
答案是什么」上，而不是再加一条一致性断言。

**修法**＝用三段锚定的**第①段** `ZP_ENV_FILE` 显式指名（指错文件即 fail-loud，不退回静默）：
新增 `start-command-center.ps1`（由 `deploy-server.ps1` 生成，对齐其余三服务惯例），计划任务
改跑该包装而非裸 `python.exe`——**此前直接调 `python.exe`，没有地方设这个环境变量**。
`serve.py` 另记录并打印本次命中的 `.env`（只打路径不打键值），门禁未启用时打红字。
