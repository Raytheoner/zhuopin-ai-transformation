# cc-hooks-p3 Design

## 决策点 1：ⓐ 不与 `#398` 心跳钩子合并（本 session 内澄清，已获 Shao Peishen 答复）

**背景**：opener 原文要求"ⓐ SessionStart 与 `#398` 合并成一枚脚本"，理由是"省 Shao Peishen 一次注册动作"。

**实测推翻前提**：本 session 开场即观察到 `#398` 的 `health-check-staleness.ps1` 已在生产独立生效（开场横幅内容与其 `Write-HookMessage` 输出格式完全吻合），且 `~/.claude/settings.json` 已核实注册 `SessionStart → health-check-staleness.ps1`。

**结论（已获答复：独立建）**：ⓐ 单独一枚**项目级**脚本，不读取、不复用、不改动 `health-check-staleness.ps1`（该文件继续只属于 `#398` 与全局 `~/.claude/settings.json`）。理由：两者注册在不同文件（项目 `.claude/settings.json` vs 全局 `~/.claude/settings.json`），合并已不产生"少一次人工动作"的收益，只会让 ⓐ 的脚本承担一份不属于自己判据（月度体检心跳）的维护成本。

**代价（已知、接受）**：CC 开场若两个 SessionStart 均命中，会看到两条独立横幅（各自 `hookSpecificOutput.additionalContext`），Claude Code 会将同一事件的多个 hook 输出依次拼接注入，不冲突、只是多一行。

## 决策点 2：ⓓ Stop 钩子——已知"半覆盖"风险下的知情决定（本 session 内澄清，已获 Shao Peishen 答复）

## 决策点 3：ⓒ PreToolUse 门禁——"有效锁"判据用存在性检查，不用身份匹配

**问题**：`PreToolUse` 钩子的 stdin 只有 `tool_name`／`tool_input`／`session_id`／`cwd`，没有"这个 session 此前是否以某个 `--who` 字符串 `acquire` 过"的记忆——钩子进程与本次 `acquire` CLI 调用是两个独立进程，无共享状态。

**已否决方案**：让钩子读某种"本 session 已 acquire"的会话级标记文件。否决理由：需要 `acquire` 命令额外写一份"谁在哪个 session 里持锁"的映射，且 `session_id` 与 `--who` 之间目前没有绑定关系（`--who` 是自由文本，如 `"CC-QD-B"`），强行绑定要改 `cmd_acquire` 签名，代价与收益不成比例。

**采用方案**：**只判"锁文件当前是否存在有效（未陈旧，< `STALE_MINUTES` 分钟）的记录"**，不判"是不是我持的"。这仍能拦住协议〇.7 历史事故的主要形态——"完全忘记 acquire、直接改队列文件"——而"A 持锁、B 也直接改"这种绕锁场景，`acquire`/`release` 既有的 `_detect_shadow_copy` 与决策点5 幽灵副本检测仍然是那道网，ⓒ 不重复造轮子。

**判定目标文件清单**（与 `工具-共享文档编辑锁.py::_is_queue_system_target` 判据对齐，另加两张接力卡）：

- `1-转型规划/0-全景路线图/跨桌任务队列-机制环境.md`
- `1-转型规划/0-全景路线图/跨桌任务队列-业务场景.md`
- `1-转型规划/0-全景路线图/跨桌任务队列.md`（指针文件，一并纳入——历史上曾被误改）
- `1-转型规划/0-全景路线图/session接力-Phase1收口.md`
- `1-转型规划/0-全景路线图/session接力-业务总线.md`

⚠️ **已知失效风险，明写不掩饰**：后两张接力卡按 `#381` 子项⑸ 2026-08-25 并入记录，"收工必写义务已取消、观察至 2026-09-07 无交互式会话消费即退役"——**若届时确认退役，ⓒ 的这两条清单项会变成"守卫一份已经没人写的文件"，不产生危害但也不产生价值**，届时随文件退役一并从清单移除（登记为 tasks §8 收口项，不在本次处理）。

## 决策点 4：ⓔ 路由提示——关键词→规则文件映射表（直接转录根 `CLAUDE.md` §4，不新拟判据）

匹配对象：`--file` 解析后的绝对路径 ＋ `--note` 原文，对下表逐行做子串命中（大小写敏感，中文关键词天然不需要大小写归一）：

| 命中关键词（任一） | 提示读 |
|---|---|
| `6-人才与组织`／`7-外部文档`／`跟进信`／`专员` | `.claude/rules/跟进信与专员.md` |
| `4-数字员工`／`5-平台底座`／`openspec`／`.51`／`OEM`／`ASIL` | `.claude/rules/场景建造与合规.md` |
| `全景规划`／`实施计划`／`排期变更`／`重组循环`／`文档命名归档`／`台账` | `.claude/rules/文档与全景治理.md` |

**刻意不含"队列与落库.md"自身一行**：`acquire` 本身就是队列与落库纪律的一部分，调用者已经在这条路径上，不需要提示"去读你正在执行的这份协议"。

🔴 **同理，"文档与全景治理.md"一行不用目录路径当关键词（建造期实测坐实，单测钉死）**：最初试写成 `1-转型规划/0-全景路线图`，而两份队列真身与接力卡物理上也落在这个目录——用目录做关键词会让"改队列"本身触发一条不相关的路由提示，与"默认队列编辑不自我指向"这条设计意图矛盾。改为只用内容关键词（全景规划／实施计划／排期变更／重组循环／文档命名归档／台账），逐字对应根 CLAUDE.md §4 该行原文。

**命中 0 条时**：不打印任何路由提示行（沉默是合法结果，不是"判定失败"）。

## 决策点 5：ⓓ Stop 判据——只在"小节存在但格式不全"时拦，不在"完全没写"时拦

根 `CLAUDE.md` §5 原文允许"本次无需决策项时明写'本次无需你决策'"——这是合法的、常见的终态。若 `Stop` 钩子对"完全没有需你定夺小节"的回复也一律 `exit 2`，会把这个合法终态变成永远过不去的死循环（且 `Stop` 钩子存在 `stop_hook_active` 场景，需谨防死循环）。

**判据**：最后一条 assistant 文本中若出现「需你定夺」或「需你决策」字样（小节标题级别，非正文提及），则要求同一段落内出现至少一个 `(a)` 或 `(b)` 形态的选项标签；缺则 `exit 2`。**完全不出现该字样 ⇒ 放行**（无论是因为真的无决策项，还是因为回复还没写完——`Stop` 钩子不负责判断"该不该有决策项"，只负责"写了就得写完整"）。

🔴 **防循环**：stdin JSON 的 `stop_hook_active` 字段为 `true` 时（本次 Stop 事件本身就是上一次 Stop 钩子拦截后的重试）一律放行，不重复判定——避免模型改不对格式时陷入无限重试。

## 决策点 6：ⓑ UPS5 标记——为什么显式加锚点而不是纯文本子串匹配

**已否决方案**：脚本内硬编码"称呼纪律"等五条的**判定用**特征子串（如 `"称呼一律"`），靠字符串包含判断"这一行是不是那五条之一"。否决理由：根 `CLAUDE.md` 历次瘦身都在改措辞（P1/P2 已发生两轮），子串一旦失配是**静默**的——脚本会读到 0 条或错误的 N 条而不报错，正是本项目反复强调的"工具静默回退"反面形态。

**采用方案**：在根 `CLAUDE.md` 五处目标行**行尾**追加不可见于渲染、但 grep 可见的锚点注释 `<!-- UPS5:1 -->` … `<!-- UPS5:5 -->`（Markdown HTML 注释，不影响正文渲染）。脚本按 `UPS5:\d` 提取整行正文，**断言恰好命中 5 条**——命中数 ≠5 时钩子仍必须 `exit 0`（fail-open，不阻断正常使用），但把"预期 5、实得 N"写进心跳/审计，使漂移**可见**而非静默消失。

## 已否决方案：ⓕ 新建独立 rules 尺寸巡检脚本

**否决理由**：`sweep-claude-md-size-guard` 已有完整的常驻告警骨架（`_track_and_alert_standing_state`、24 小时防重复轰炸、自动解除）——新建一套会制造"两套判据、两个通知源"，与协议〇.9 措施 B 的精神直接冲突。改为直接扩展 `_claude_md_targets` 返回值与 `CLAUDE_MD_ROOT_BYTE_CAP` 常量。

## 边界（继承自 P0 实测，OP-0903-G/H，全部六枚适用）

hooks 与带 `paths` 的 `.claude/rules/*.md` **只在 CC 生效，Cowork 全不生效**（`根CLAUDE.md彻底瘦身-方案-2026-09-03.md` §五实测结论）。本包 ⓐⓑⓒⓓ 不承诺 Cowork 侧；ⓔⓕ 因为改的是 CLI 工具与 sweep 定时任务本体（不依赖 Claude Code 的 hooks 事件），**两桌都生效**（Cowork 会话若调用 `工具-共享文档编辑锁.py acquire` 同样能看到路由提示；sweep 是独立定时任务，与两桌均无关，天然全局生效）。
