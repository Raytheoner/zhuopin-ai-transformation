## Purpose

定义编辑锁 `release` 对协议〇.9 措施 C"机制类可动 WIP 上限"的非阻断提示行为——在新增 §一 机制类行导致计数超限时提醒，但不阻断释放，因为该上限的用途是"给建行踩刹车，不是精确会计"。

## ADDED Requirements

### Requirement: 超限时提示不阻断
`release` 释放跨桌任务队列.md 锁时，若本次持锁期间新增了域为 `机` 的 §一 行，SHALL 重新计算全文当前的机制类可动 WIP 计数（按 `queue-row-domain-field` 能力定义的口径）；若该计数超过上限（默认 8，可通过命令行参数覆盖），SHALL 打印非阻断提示，release MUST 仍然正常放行。

#### Scenario: 新增机制行导致超限，提示但放行
- **WHEN** 本次持锁期间新增一条 `[D:机]` 的 §一 行，release 时重新计算得到可动 WIP 计数为 9（超过上限 8）
- **THEN** `release` 打印提示"机制类可动 WIP 当前 9／8，已超上限"，并正常释放锁，返回成功

#### Scenario: 计数未超限，无提示
- **WHEN** 本次持锁期间新增的 §一 行使可动 WIP 计数保持在上限以内
- **THEN** `release` 不打印本项提示，其余流程不受影响

#### Scenario: 新增行域为业务类，不触发本项检查
- **WHEN** 本次持锁期间新增的 §一 行全部域为 `业`
- **THEN** 本项检查不重新计算或提示（无机制类新增，无需检查）

### Requirement: 上限值可配置
可动 WIP 上限默认值 SHALL 为 8（对齐协议〇.9 措施 C 现行定案），MUST 支持通过命令行参数覆盖，避免上限值本身未来调整时需要改动代码。

#### Scenario: 覆盖默认上限
- **WHEN** 调用 release 时传入自定义上限参数（如 `--mechanism-wip-cap 10`）
- **THEN** 本项检查使用传入的上限值而非默认的 8 进行超限判断
