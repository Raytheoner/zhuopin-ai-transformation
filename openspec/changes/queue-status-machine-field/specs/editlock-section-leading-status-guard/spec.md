## Purpose

定义编辑锁 `release` 对 §一/§二 状态列"✅ 标记位置"的两项结构性拦截（子项 F）：F1 阻止 §二 新增批次行"新建即终态"；F2 拦截状态列内 `✅` 出现在非开头位置导致的头尾不一致。均只对本次持锁期间新增/修改的行生效，历史行不追溯。

## ADDED Requirements

### Requirement: §二 新增批次行不得以 ✅ 开头
`release` 释放跨桌任务队列.md 锁时，对本次持锁期间**新增**的 §二 批次行（identity＝批次名 cells[0]，不存在于 acquire 快照的 §二 批次名集合内），SHALL 检查其状态列（cells[3]）的开头片段（`_leading_status_segment`）；若以 `✅` 开头，MUST 拒绝 release。既有批次行状态列从其它值合法转为 `✅`（如 sweep 或 CC 收工标记完成）MUST NOT 被本项拦截。

#### Scenario: 新增批次行直接标记已完成，拒绝 release
- **WHEN** 本次持锁期间新增一条 §二 批次行，其状态列开头片段为 `✅ 已完成（本次登记）`
- **THEN** release 被拒绝，提示"§二 新增批次行状态列不得以 ✅ 开头"

#### Scenario: 既有批次行合法转为已完成，正常放行
- **WHEN** 本次持锁期间的变化是某个已存在批次行（其批次名在 acquire 快照中已存在）的状态列从"待处理"改为 `✅ 已完成`
- **THEN** release 正常放行，本项不拦截

### Requirement: 状态列含 ✅ 但不在开头片段即报
`release` 释放跨桌任务队列.md 锁时，对本次持锁期间新增/修改的 §一 行（状态列 cells[5]）与 §二 行（状态列 cells[3]），SHALL 检查其状态列全文是否含 `✅` 字符；若含，且 `✅` 不出现在该状态列的开头片段（`_leading_status_segment` 返回值）内，MUST 拒绝 release。

#### Scenario: ✅ 出现在正文中段，头尾不一致，拒绝 release
- **WHEN** 一个 §一 或 §二 行状态列开头片段为"待处理"，但正文后段包含"...子项已 ✅ 完成..."
- **THEN** release 被拒绝，提示状态列头尾不一致

#### Scenario: ✅ 位于开头片段内，正常放行
- **WHEN** 一个行状态列开头片段本身即以 `✅` 起始
- **THEN** 本项检查通过（不视为头尾不一致）

#### Scenario: 状态列不含 ✅，本项不适用
- **WHEN** 一个行状态列全文不含 `✅` 字符
- **THEN** 本项检查不触发

### Requirement: 仅对本次新增/修改行生效
上述两项检查 SHALL 仅对本次持锁期间新增或内容有变化的行生效（与既有 acquire 快照做逐行比对判定），历史行（快照中已存在且内容未变）MUST NOT 被本能力追溯拦截。

#### Scenario: 历史行不受影响
- **WHEN** 一个历史遗留的 §一/§二 行本身即存在"✅ 不在开头"或类似结构问题，但本次持锁期间未触碰该行
- **THEN** release 不因该历史行而拒绝，仅对本次实际新增/修改的行生效
