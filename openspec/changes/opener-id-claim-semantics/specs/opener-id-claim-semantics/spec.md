## ADDED Requirements

### Requirement: OP 号未落盘即未占用
OP 号（`OP-MMDD-X`）SHALL 仅在**已落进仓库某份 `.md`** 时才视为被占用。取到号但当次 opener 从未派出时，该号 MUST 被当场作废：MUST NOT 预留、MUST NOT 为「日后可能会用」而写进任何文件占位；他人当日 SHALL 可以再次取到同一个号。

本 Requirement **仅适用于 OP 号**。队列 §一／§四 的**行编号**（`#503` 这类）按协议〇.8 永不复用、预留即烧号，两套语义 MUST NOT 互相援引。

#### Scenario: 取号后未派出，该号可被再取
- **WHEN** 某会话取到当日某个 OP 号，但该 opener 从未派出、未落进任何 `.md`
- **THEN** 同日另一条线取号时该号仍为空号，可被再次取到；不视为违规

#### Scenario: 不得为未派出的号做占位登记
- **WHEN** 某会话取到号后，为保住该号而把它写进某份文件（不含真实派件内容）
- **THEN** 违反本 Requirement——占位写入使该号变为"已落盘"，等于绕过 ⑵ 私自把它变成"已占"

#### Scenario: 队列行编号不适用本 Requirement（非恒真自证）
- **WHEN** 某次 `acquire --reserve` 预留了 N 个队列行编号，实际只落盘 M 个（M < N）
- **THEN** 剩余 N−M 个编号 MUST 留作永久空洞、MUST NOT 被回收复用——本 Scenario 用于证明本 Requirement 未被误推广到队列编号空间

### Requirement: 撞号查重须自陈其射程
`工具-opener生成.py` 的撞号查重（`_scan_used_suffixes`／`_check_op_id_not_reused`）SHALL 在其文档字符串中写明：本查重只认**已落盘痕迹**，取号与落盘之间存在一段真空，查重是取号那一刻的快照、不是锁；据 `#487` 裁定 ⑵，该真空不由本工具消除。

报错文案 SHALL **指向**该自陈，MUST NOT 重述其内容（指向而非复制）。

#### Scenario: 撞号报错指向射程说明
- **WHEN** 传入一个当日已落盘的 OP 号
- **THEN** 工具拒绝出件，报错文案中包含指向射程自陈的指引，且仍给出当日下一个空号

#### Scenario: 射程自陈不是一次性回显
- **WHEN** 查阅该工具"这个号算不算被占"的判据
- **THEN** 该判据存在于代码文档字符串这一常驻载体中，而非仅存在于某次命令的 stdout——与 `#503` 所治的「守卫射程只活在一次性回显里、无承接载体」同族

### Requirement: 同一时刻只有一条占用语义生效
「一个 OP 号算不算被占用」SHALL 在任一时刻只有一条判据。系统 MUST NOT 同时存在「未落盘即未占用」与「登进在跑清单即占用」两条相反语义、并让"走哪一条"取决于取号人是否记得执行某个人工动作。

具体形态由 design 决策点 ①／② 拍板：~~或以 ⑵ 为唯一语义并写明"登进在跑清单会被查重扫到"这一例外，或让查重排除在跑清单区，或改以"登表即占"为唯一语义。**本 Requirement 在 design 审回填答案前不完整，不得据此实现。**~~ ✅ **已拍板（2026-09-08 答 `1(a)`，2026-09-10 回填）＝①(a)＋②(a)**：以 ⑵ 为唯一永久占用语义，`_scan_used_suffixes` 不跳过在跑清单、但在 `opener骨架.md`「取号」节写明「登进在跑清单的号会被扫到、会挡号」这一例外；接力卡在跑清单条目改写为「只为可见性，不构成占号」。

#### Scenario: 两条相反语义并存
- **WHEN** 同一机制中，登进接力卡在跑清单的号被查重判为已用，而未登表的同类号被判为空号
- **THEN** 违反本 Requirement——两种结果在语义上相反，而选择哪一条由一条人守决定
- **实证**：`opener骨架.md` 文末要求「开新会话先登本线接力卡的『⏳ 本线在跑会话』清单」，而该接力卡位于 `1-转型规划/` 树内，正是 `_scan_used_suffixes` 的扫描范围

### Requirement: 取号即声明——真空期的有时效机器占位
`工具-opener生成.py` SHALL 在出件成功时于 `<主工作区>/reports/op-id-claims.jsonl` 写一条占位（`op_id`／`mmdd`／`suffix`／`short_name`／`line`／`claimed_at`），并在查重时同时扫「已落档文件」与「未过期占位」；当日同号已被**另一份草稿**（短名不同）声明且未过期时 MUST 拒绝出件并给出避开已落档与已声明后缀的下一个空号。占位 SHALL 在 `CLAIM_TTL_MINUTES` 后自动失效、在该号已落档后自动清理；占位台账读写失败 MUST fail-closed 不出件。台账路径 MUST 按 `git rev-parse --git-common-dir` 解析到主工作区，使各 worktree 共享一份。

本 Requirement **不改变**「永久占用只认已落档」（前一 Requirement）：占位是「取号→落档」真空的有时效可见窗口，到期未落档即作废＝「未派出即作废」的机器实现；它由工具写入与清理，不是人手写进 `.md` 的占位登记。（授权：Shao Peishen 2026-09-10 答 `1a，2a`，队列 §一 `#549` ⑶／`#531` 子项；🔴 `CLAIM_TTL_MINUTES` 初值 120 由建造方定、待其明确答复。）

#### Scenario: 两份起草中的件同号（2026-09-10 `OP-0910-I` 实撞形态）
- **WHEN** 线甲以短名 X 取到 `OP-MMDD-K` 并出件（占位已写），线乙在时效内以短名 Y 再取 `OP-MMDD-K`，两边均未落档
- **THEN** 线乙被拒绝出件，报错指明对方短名／派出线／声明时刻，并给出下一个空号

#### Scenario: 同一草稿重生成不撞自己
- **WHEN** 同一短名的件改一个参数再生成一次
- **THEN** 出件成功，占位时间戳刷新，台账中该号仍只有一条

#### Scenario: 到期作废
- **WHEN** 某占位已超过 `CLAIM_TTL_MINUTES` 且该号未落档
- **THEN** 他人可再取到该号，且该占位被从台账清理——这是「未派出即作废」的机器实现

#### Scenario: 落档后交还给落档查重
- **WHEN** 某号已出现在 `1-转型规划/` 树内任一 `.md`
- **THEN** 其占位被清理；再取该号仍被拒，但拒绝理由来自已落档查重而非占位

#### Scenario: 台账不可写即不出件（fail-closed）
- **WHEN** 占位台账所在目录不可创建或文件不可写
- **THEN** 工具报错退出、不出件——不能证明占到号就不算取到号
