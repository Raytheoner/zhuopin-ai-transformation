## MODIFIED Requirements

### Requirement: 超限时拒绝 release
`release` 释放跨桌任务队列锁时，若本次持锁期间新增了域为 `机` 的 §一 行，SHALL 重新计算全文当前的机制类可动 WIP 计入集（按 `queue-row-domain-field` 能力定义的口径，且 🛑 排除按下述「🛑 排除认两列」Requirement），并对计入集中每一行取其**末次真实活动时间**（该行所在物理行在版本历史中的末次提交时间，工作区未提交的行按「当前时刻」计）；令 `STALE` ＝ 计入集中末次真实活动距今超过 N 天的行数。若 `STALE > K`，工具 MUST 拒绝 release、锁保持占用，除非本次调用满足「逃生阀」Requirement。**计入集的行数本身 MUST NOT 作为拒绝条件**（迁移期例外见「迁移期并行回显」Requirement）。

本项检查 MUST 仅在本次持锁期间**真正新增**了 `[D:机]` 的 §一 行时触发——对未新增机制行的 release（含专为关行、专为推进最老行而进行的编辑）MUST NOT 因存量 `STALE` 超限而拒绝。理由与行数闸时代相同：措施 C 要踩的是「新立机制行」这个动作；若改为「任何 release 超限即拒绝」，会连来关行、来推进陈旧行的那个 session 一并挡在门外，使规则把自己的解法锁死。

「末次真实活动」MUST 取版本历史元数据，MUST NOT 取行内文本日期——行内日期会被写进格内的未来截止日污染、且可手写。

拒绝提示 MUST 含：当前 `STALE`／K 与 N 的取值、本次新增行的编号、**陈旧行清单按行龄降序至少列出最老的 K＋1 条（编号＋行龄天数）**、以及两条出路各自的确切走法（推进或关闭陈旧行使 `STALE` 回到 K 以内 ／ 按逃生阀写法放行）。

#### Scenario: 新增机制行且陈旧行超限，拒绝 release
- **WHEN** 本次持锁期间新增一条计入 WIP 的 `[D:机]` §一 行，release 时计得 `STALE > K`，且未满足逃生阀条件
- **THEN** `release` 拒绝释放，锁保持占用，提示 `STALE`／K、N、新增行编号、最老 K＋1 条陈旧行的编号与行龄、两条出路

#### Scenario: 计入行数很多但没有陈旧行，正常放行
- **WHEN** 本次持锁期间新增一条计入 WIP 的 `[D:机]` §一 行，计入集行数超过旧行数上限（如 25 行）但 `STALE ≤ K`
- **THEN** `release` 正常释放，不因行数拒绝（迁移期内按「迁移期并行回显」Requirement 处理）

#### Scenario: 新增行域为业务类，不触发本项检查
- **WHEN** 本次持锁期间新增的 §一 行全部域为 `业`
- **THEN** 本项检查不取龄、不判定

#### Scenario: 存量已陈旧超限但本次未新增机制行，不拒绝
- **WHEN** 当前 `STALE > K`，但本次持锁期间未新增任何 `[D:机]` 的 §一 行（例如本次编辑正是把最老的一条机制行关闭或推进）
- **THEN** 本项检查不触发，release 正常放行

#### Scenario: 行内写着近期日期但版本历史显示久未改动，仍计陈旧
- **WHEN** 某计入行的状态格内含一个未来截止日或近期日期文本，但该物理行的末次提交距今超过 N 天
- **THEN** 该行计入 `STALE`（取龄只认版本历史，不认行内文本）

## ADDED Requirements

### Requirement: 陈旧阈值可配置，行数上限仅存于迁移期
陈旧天数 N 默认值 SHALL 为 7，允许陈旧条数 K 默认值 SHALL 为 3（2026-09-11 以现网计入行的真实提交时间三次实测定死——23 行与 27 行两个基数下 `STALE(7)=0`、最老行 7 天、`N=10` 永不触发＝悄悄废闸），两者 MUST 支持通过命令行参数覆盖。

行数上限（默认 22，`--mechanism-wip-cap`）SHALL 仅在迁移期（告警模式）内继续作为拒绝条件生效；迁移期满切换为阻断模式的同一批变更 MUST 删除该参数与该判据（协议〇.9 措施 B 一进一出），MUST NOT 以「仅提示」形态保留。

#### Scenario: 覆盖默认阈值
- **WHEN** 调用 release 时传入自定义阈值参数（如 `--stale-days 10 --stale-cap 5`）
- **THEN** 本项检查使用传入的 N／K 而非默认值进行判定

#### Scenario: 切阻断后行数上限参数不再存在
- **WHEN** 迁移期已结束、工具处于阻断模式，调用 release 时传入 `--mechanism-wip-cap`
- **THEN** 参数解析失败（未知参数），提示该判据已退休并指向本能力 spec

### Requirement: 🛑 排除认两列
计算机制类可动 WIP 计入集时，一行若其**状态列**的自然语言正文（去掉 `[S:][D:]` 字段与前导修饰符后）以 🛑 起首，**或**其**任务列**正文（去掉前导修饰符后）以 🛑 起首，SHALL 视为「排队中·暂非可动」而不计入。两列任一命中即排除；已有的只写在任务列的存量写法 MUST NOT 被要求订正（历史记录不追改）。

写侧（`append-row`／`edit-row`）在写入一条域为 `机` 的 §一 行时，若任务列以 🛑 起首而状态列自然语言正文不以 🛑 起首，SHALL 打印一条非阻断告警，提示 🛑 的规范落点是状态列；MUST NOT 因此拒绝写入。

#### Scenario: 🛑 只写在任务列，不计入 WIP
- **WHEN** 某 `[S:open][D:机]` 行的任务列以「🛑 **排队中·暂非可动**」起首，状态列自然语言正文不含 🛑
- **THEN** 该行不计入可动 WIP 计入集、不参与取龄

#### Scenario: 🛑 只写在状态列，不计入 WIP
- **WHEN** 某 `[S:open][D:机]` 行的状态列自然语言正文以 🛑 起首，任务列不含 🛑
- **THEN** 该行不计入可动 WIP 计入集（与改前行为一致）

#### Scenario: 写侧告警引导落状态列
- **WHEN** `append-row` 新增一条 `[D:机]` §一 行，任务列以 🛑 起首、状态列自然语言正文不以 🛑 起首
- **THEN** 写入成功，stdout 打印告警指出 🛑 应落状态列；该次写入不被拒绝

### Requirement: 新增行本身不计入时不阻断
若本次持锁期间新增的 `[D:机]` §一 行**全部**不属于可动 WIP 计入集（状态为 `blocked`／`timed=`／`done`，或按「🛑 排除认两列」被排除），本项检查 SHALL 只回显当前 `STALE`／K（迁移期内并回显行数／上限），MUST NOT 拒绝 release，MUST NOT 要求为这些行写 `WIP豁免：`。

若新增的多行中部分计入、部分不计入，判定与逃生阀 SHALL 只针对计入的那些行；拒绝文案 MUST 只点名计入的新增行编号。

#### Scenario: 新增 🛑 起首行且存量超限，放行并回显
- **WHEN** 本次新增一条以 🛑 起首的 `[S:open][D:机]` §一 行，存量 `STALE > K`
- **THEN** `release` 正常放行，stdout 回显存量 `STALE`／K 并注明「本次新增行 #X 不计入、与超限无关」

#### Scenario: 新增 blocked 行不触发判定
- **WHEN** 本次新增一条 `[S:blocked][D:机]` §一 行
- **THEN** `release` 不因 WIP 判定拒绝，不要求 `WIP豁免：`

#### Scenario: 一次新增计入行与不计入行各一条
- **WHEN** 本次新增 `#A`（`[S:open][D:机]`，计入）与 `#B`（🛑 起首，不计入），且 `STALE > K`、未给逃生阀
- **THEN** `release` 拒绝，文案只点名 `#A`；逃生阀齐备时只要求 `#A` 行内有 `WIP豁免：`

### Requirement: 取龄失败非静默降级
取「末次真实活动时间」依赖版本历史元数据；若该取数失败（版本控制命令不可用、超时、返回不可解析、或某计入行无法映射到物理行），工具 MUST NOT 静默按「无陈旧行」放行，也 MUST NOT 因取数失败而拒绝 release。工具 SHALL 打印一条带失败原因与受影响行号的降级告警，并按「本次无法判陈旧」放行；取数 SHALL 带超时上限（默认 30 秒，可配置）。

部分行取龄失败时，SHALL 对取到的行照常判定，对未取到的行逐条列在降级告警内。

#### Scenario: 版本控制命令不可用
- **WHEN** release 时新增了计入 WIP 的机制行，但取龄子进程启动失败
- **THEN** `release` 放行，stdout 打印降级告警写明失败原因与「本次未判陈旧」

#### Scenario: 取龄超时
- **WHEN** 取龄子进程超过超时上限仍未返回
- **THEN** 子进程被终止，`release` 放行并打印含耗时与超时值的降级告警

#### Scenario: 某计入行映射不到物理行
- **WHEN** 计入集中某行的编号在文件中找不到以 `|<编号>|` 起首的物理行
- **THEN** 该行不参与 `STALE` 计数，降级告警逐条点名该编号；其余行照常判定

### Requirement: 迁移期并行回显与切换前置
本能力 SHALL 先以**告警模式**上线：告警模式下，行数上限判据照旧生效（超限拒绝、逃生阀不变），陈旧度判据只计算不拒绝；每次触发本项检查时 `release` MUST 同时回显两个数（`机制类可动 WIP N／上限` 与 `STALE(N天)＝S／K`）及陈旧行清单（最老 K＋1 条）。

告警模式 SHALL 持续 7 天（一轮值周巡检节拍），期满切换为阻断模式的前置条件 MUST 包含：① 已回答「这 7 天里新闸的告警有没有被任何人当回事」且答案为「有」；② 值周巡检已对行龄榜首 3 条人工抽查一次；③ 至少一次取龄在非主 checkout 环境（沙箱挂载盘或 worktree）真实跑过并记录耗时。三者缺一 MUST NOT 切换，MUST NOT 默认续期，须回 design 重议。

#### Scenario: 告警模式下行数超限仍拒绝
- **WHEN** 工具处于告警模式，本次新增计入行，行数 23／22，`STALE=0`
- **THEN** `release` 按行数判据拒绝（与改前一致），文案同时回显 `STALE(7)=0／3`

#### Scenario: 告警模式下陈旧超限只回显
- **WHEN** 工具处于告警模式，本次新增计入行，行数 20／22，`STALE=5／3`
- **THEN** `release` 放行，stdout 回显两个数并列出最老 4 条陈旧行，明示「告警期，未阻断」

#### Scenario: 阻断模式下只认陈旧度
- **WHEN** 工具处于阻断模式，本次新增计入行，行数 25，`STALE=1／3`
- **THEN** `release` 放行，不回显行数上限

## REMOVED Requirements

### Requirement: 上限值可配置
**Reason**: 行数上限判据测的不是措施 C 要防的目标变量（「只开新战线、不关行」），已被 `#58` 自书的证伪判据（豁免批量出现 0 → 15）判死，且第三次抬上限等于废掉措施 C。其 Requirement 文本（含 8 → 16 → 24 → 22 的沿革记载）由本包「陈旧阈值可配置，行数上限仅存于迁移期」Requirement 承接，行数上限仅在迁移期保留、切阻断时随参数一并删除。
**Migration**: 迁移期内 `--mechanism-wip-cap` 仍可用；切阻断时删除参数，调用方须改用 `--stale-days`／`--stale-cap`。沿革记载迁入协议〇.9 措施 C 正文与 `#58` 行日志，不随 spec 删除而丢失。
