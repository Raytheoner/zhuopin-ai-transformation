> 承接：队列 §四 `#58`（措施 C 正体）＋ §一 `#454`（状态分诊常态化）。首要输入＝`1-转型规划/0-全景路线图/方案-措施C换量具-陈旧度闸-2026-09-11.md`（下称「方案件」），本文只记 propose 期新增的实测与取舍，方案件已写的初衷／诊断不复述。授权：Shao Peishen 2026-09-10 答 `1a`（换量具）＋ 2026-09-11 答 `1a`（先实测定 N/K 再派 propose）。派单：`OP-0911-D`（`派单件-【CC】措施C换量具-openspec-propose-2026-09-11.md`）。

## Why

协议〇.9 措施 C 要防的是「**只开新战线、不关行**」（`#58` 原话：观察周新立 6 条机制行、无一伴随关行）；它一直用「**开着的机制行有几条**」当代理变量。方案件 §三 用三条可证伪判据证明这个代理已经失效——**条条已触发**：

1. `#58` 自书的自我证伪判据「`WIP豁免：` 若开始批量出现，说明上限本身定错了」——豁免数 **0 → 15**（2026-08-17 → 09-10，按 §一 状态列逐格取标记，非全文 grep）。
2. 闸应压住在制品——§二 批次数／日 **37 → 57 单调上行**，全程 WIP 超限；真实在制品载体已变成「同时在飞的泳道数」，§一 机制行数退化为一张待办清单的长度。
3. 闸应阻止行被立——**15 条豁免 ＋ 9 条 🛑 ＝ 24 条全部立进了队列**，一条未被真正拦住；它改变的不是结果，只是在 `release` 那一刻加了一段仪式。

且上限已被现实抬过两次（8 → 16 → 22），`#58` 自书「第三次为迁就现状改口径即等于废掉措施 C」，**抬上限这条路已封死**；2026-09-10 一次彻底的人工分诊（4 行改判 `blocked`）也只把 27 压到 23／22，**仍超 1**——「阈值与量具不匹配」的直接证据。

**但不拆刹车**：它是目前唯一一台强制回头看「这些行还该不该开着」的机器（09-10 那次分诊正是它逼出来的）。本包**换量具**——把判据从「开着几条」换成直接测目标变量「**有几条开着的行已经不动了**」（`STALE`），并顺手修掉同一道闸上两处已实证的判据缺陷（`#58` ⑸ 与本次新发现的 🛑 只认一列）。

## What Changes

- **D1 · 闸面换量具**：`release` 在「本次持锁真正新增 `[D:机]` §一 行」时（触发时机**逐字不变**，`#58` design 决策点 4 防自锁）不再比较「计入行数 vs 上限」，改为计算 **`STALE` ＝ 计入 WIP 的行中，末次 commit 距今 > N 天的条数**，`STALE > K` 才拒绝；**行数本身不再设上限**。初值 **N＝7、K＝3**（实测定死，见上表与方案件 §D2）。
- **D3⑵ · 🛑 排除认两列**（本次新发现）：计入判据由「状态列自然语言以 🛑 起首即排除」改为「**状态列或任务列任一**以 🛑 起首即排除」；写侧（`append-row`／`edit-row`）对「🛑 只落任务列」的新写法打**告警**（不拒），引导落状态列。实测影响：当前 WIP **23 → 20／22 立即合规**。
- **D3⑴ · `#58` ⑸ 修法⑴**：本次新增的机制行若**本身不计入 WIP**（🛑 起首／`blocked`／`timed=`），不触发阻断，只回显存量；消除「逼着每条 🛑 新行写一条名不副实的豁免」（`#448` `#522` `#526` 三条假豁免的来源）。
- **逃生阀不变**：`--force-mechanism-wip` ＋ 行内 `WIP豁免：<理由>`，缺一即拒（`#58` design 决策点 5）。
- **取数失败非静默**：`git blame` 不可用／超时／行号映射失败时，**不拒绝、不静默**——打印带原因的降级告警并按「本次无法判陈旧」放行（理由见 design D-E；「工具静默回退不产生信号」是根 CLAUDE.md 点名的失效形态，故降级必须出声）。
- **迁移期**：新闸**先以告警模式上线 7 天**，与旧行数闸并行、`release` 回显两个数；7 天后复评（须先答「这 7 天里新闸的告警有没有被任何人当回事」）再切阻断，切阻断的同一批**退休行数上限判据**。
- **BREAKING**：是——切阻断后，`release` 对「新增机制行且存量 STALE > K」由放行变拒绝；对「新增机制行且行数 > 22 但 STALE ≤ K」由**拒绝变放行**（这正是换量具的目的）。告警期内行为与现状完全一致，仅多一行回显。

## 本次退休哪一个既有守卫（强制，协议〇.9 措施 B）

**退休：机制类可动 WIP 的「行数上限」判据本身**——即 `editlock-mechanism-wip-guard` 中「上限值可配置」Requirement 及其 `MECHANISM_WIP_CAP_DEFAULT＝22`／`--mechanism-wip-cap` 参数，**在告警期满切阻断的那一批整条删除**，不降级保留、不留「仅提示」半边（`#58` 已实证「非阻断提示在连续 6 次被无视后信息量为零」，留半边＝重演）。三条理由：

1. **它测的不是措施 C 要防的那件事**（方案件 §三 判据②③：吞吐逆势上行、24 条全部立进）；一个与目标变量脱钩的量具，产出的不是约束，是仪式。
2. **它已被自己的证伪判据判死**（判据①：豁免 0 → 15），而按 `#58` 自书，唯一剩下的「第三次抬上限」等于废掉措施 C——**修不了、又不能抬，只剩换**。
3. **同一道闸上两个判据并存超过观察期就是 `#366`「两套判据各自轮询」的教训重演**——故告警期定死 7 天、复评有硬前置（D-D），到期不得默认续期。

**为何不同批退休（留 7 天并行）**：新量具的 `STALE` 是**乐观估计**（机械改动也刷新 blame 时间，见 design D-A），且 `git blame` 在沙箱挂载盘上的耗时未实测（本机主 checkout 6.9–8.0 s）；没有一段真实并行期就切阻断，等于用一个未经现网检验的判据替换一个已知失效的判据。7 天 ＝ 一轮值周巡检节拍。

## 伴生文件的 .gitignore 覆盖（强制）

**不适用——本变更不新增任何自动生成的文件名形态**，且这是一条 design 决策而非顺带结果：`STALE` 取数每次现跑 `git blame --incremental`（只读子进程），**刻意不建缓存文件、不写状态文件、不写日志文件**（design D-E 的备选 (b)「缓存 blame 结果到 `reports/`」被否，理由＝ `#322` `*.editlock.mutex.stale` 教训：凭空造出的文件形态没人回头看忽略规则）。写侧 🛑 告警与陈旧度告警均只走 stdout。核实方式＝apply 后 `git status --porcelain` 不得出现任何新形态未跟踪文件（沿用 `editlock-hold-scope-and-wip-block` 4.3 的验法）。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

1. **本流程哪些判断是人脑默会经验？** 两处：① **「一条开着的机制行算不算『还在动』」**——此前靠值周巡检读状态格里的日期拿捏，而格内日期会被未来截止日污染、也可手写（方案件 §二.4 已实测「只能证都在动、不能证几天前动的」）；本包把它显性化为「该行所在物理行的末次 commit 时间」这一不可手写的机器判据，并把「多久算不动」（N＝7＝跨过一轮值周巡检）与「几条不动才算病」（K＝3）两个尺度写死并附实测依据。② **「🛑 该写在哪一列」**——队列里两种写法并存了至少 5 行，没人意识到闸只认一列；本包把「两列任一即算」显性化为判据，并让写侧当场提醒。
2. **由谁显性化？** 决策人 Shao Peishen（design 审拍板 N/K 与 D-B 修法）＋ CC 建造车间（判据实现、单测、现网只读实测）；backup＝下一位领取 `#58`／`#454` 的 session 可凭本包 design 与探针脚本（`tasks.md` 1.1 指明手段）独立复算 `STALE` 分布，不需重跑取证即可判断 N/K 是否仍成立。
3. **用什么方法提取？** 历史真实案例反推（`#58` 观察周「6 立 0 关」、`#448`／`#522`／`#526` 三条假豁免、`#381`／`#382`／`#448` 三行误计）＋ 现网全量只读实测（23 条计入行的 blame 行龄分布，两次独立取数一致）。不涉及 LLM 判断。

## 验收与晋档条件（强制，四档口径）

- **本变更包交付后场景所处档位**：跨项目治理机制（编辑锁＝全项目唯一队列写入咽喉），非业务场景，不适用「对客交付」口径；套最接近的描述＝**档1 mock 验证**——design 审通过、代码与单测完成、现网只读实测两次一致，但新闸尚未在真实 `release` 上以阻断模式拒绝过任何一次。
- **晋下一档（档2 真实数据跑通）的条件**，逐条：
  1. 告警期 7 天内，`release` 每次新增机制行都真实回显了两个数（行数／上限 ＋ `STALE(7)`／K），且**至少一次 `git blame` 取数在沙箱挂载盘或 worktree 环境下真实跑过**、耗时已记录（本机主 checkout 已测 6.9–8.0 s，别的环境未测——不得拿主 checkout 的数推别处）；
  2. 🔴 **复评硬前置**：切阻断前必须先答「这 7 天里新闸的告警有没有被任何人当回事」（`#58` 手法）；答「否」⇒ 不得默认续期、回本包 design D-D 重议（是判据错了、还是没人看回显）；
  3. 切阻断后真实发生一次「新增机制行 ＋ `STALE > K`」的拒绝，确认文案足以让操作者知道下一步（关哪 3 条最老的行／怎么走逃生阀）；
  4. 值周巡检在告警期内对**行龄榜首 3 条**人工抽查一次，核该行末次改动是不是实质推进（design D-A 的乐观偏差缓解）；若机械改动污染严重 ⇒ 回本包重定 N，不调 K。
- **价值指标**（风险型）：① **假豁免**——基线＝3 条（`#448` `#522` `#526`，理由原文皆为「本行以 🛑 起首、本就不计入」），目标＝0（D3⑴ 结构性消除）；② **误计**——基线＝3 行（🛑 落任务列被计入），目标＝0（D3⑵）；③ **闸与目标变量的对准**——基线＝行数闸下「豁免 15／全部立进」，目标＝切阻断后 30 天内 `WIP豁免：` 新增 ≤5 条（超过即触发方案件 §D5 回议 N/K，**不是加豁免**）。
- **本版自己的退休判据（方案件 §D5，先写死）**：若 `STALE` 连续两周为 0 且期间无 `WIP豁免：` 新增 ⇒ 病已不在，本闸转纯告警并登记退休候选；若新闸下 30 天内豁免再破 5 条 ⇒ 回本包重议 N/K。
- **LLM 判据黄金集**：不适用（纯 git 元数据与结构化匹配，无 LLM 运行时判断）。
