## Goals / Non-Goals

**Goals**：闸的判据直接测「有几条开着的机制行已经不动了」；同一道闸上两处已实证的计数缺陷同批修掉；新判据上线不自锁、不静默、不新造文件形态。

**Non-Goals**：
- 不第三次抬行数上限；不退休措施 C；不动业务域（`[D:业]` 行不受 WIP 约束，维持原样）。
- 不订正存量 5 行的 🛑 写法（D-B 若裁 (乙) 再另派）；不追改存量 15 条 `WIP豁免：`。
- 不改 `_suggest_status_reclassification`／`triage-candidates` 分诊器（`#454` 线），不改 sweep 第 12 类。
- 不为取龄建缓存或状态文件。

## Decisions

### D-A · `STALE` 的「真实活动」定义 ＝ 该行物理行的末次 commit 时间（blame），并如实承认它是乐观估计

**候选**：
- **(甲)【推荐】`git blame --incremental` 取行末次 commit `author-time`**。增量模式只出提交头与行号区间、不带正文，避开 644 KB 文件与 78 KB 长行；按行首 `|<编号>|` 映射行号。两次独立取数（方案件 §D2 与本包复跑）23 行全部解析成功、分布一致。
- (乙) 行内文本日期（状态格内最大日期）。已实测会被未来截止日污染（方案件 §二.4），且可手写——**出局**。
- (丙) `git log -L <line>` 逐行查。每行一次子进程，23 行 × 秒级＝不可接受；且 `-L` 对超长单行的 diff 更慢——出局。
- (丁) 每行日志 `队列行日志/#N.md` 的 mtime。只有 K2 外置过的行才有日志（169 份 vs §一 135 行＋§四），覆盖不全——出局。

🔴 **已知偏差必须落纸（派单件点名）**：`blame` 记的是这一行的**任何**改动。K2 外置、每周清扫、称呼订正、并入审核这类**机械改动也会刷新时间** ⇒ `STALE` **系统性偏低、是乐观估计**；本次两跑 0 天行由 4 涨到 10 再到 14，其中 `#455` `#482` `#487` `#505` 四行的归零**完全来自 `OP-0911-A` 那笔回滚编辑**（内容上只是把状态字段改回原值）——机械触碰刷新行龄的当场实证。这意味着：**新闸漏报的方向是「该拦没拦」，不是「不该拦却拦」**——与行数闸的失效方向相反，对写入咽喉而言是更安全的一侧。
**缓解**：观察期内值周巡检对**行龄榜首 3 条**人工抽查一次，核该行末次改动是不是实质推进；若抽查发现机械改动污染严重（榜首 3 条中 ≥2 条的末次改动是机械触碰），**回本件重定 N，不调 K**（N 是「多久算不动」的语义尺度，K 是余量；污染让「不动」的可观测时长变短，该修的是尺度）。
**不做的缓解**：不尝试在 blame 层区分「机械 commit」与「实质 commit」（如按 commit message 前缀 `docs(队列): 收工重跑文档台账（sweep 自动）` 过滤）——那是给量具再叠一层判据，且 sweep 自动 commit 会把同一批次里人的实质回写一并带走，过滤反而把实质活动也滤掉。留作 Open Question 观察一期后再议。

> **⛳ D-A**：采用 (甲)，偏差与缓解写进 spec「超限时拒绝 release」与 proposal 晋档条件 4。
> **默认项：若不答，按 (甲) 执行。**

### D-B · 🛑 排除只认状态列的缺陷修法 ＝ (甲) 判据认两列 ＋ 写侧告警

**实测影响（派单件点名必写）**：`#381`／`#382`／`#448`／`#505` 四行正文自陈「排队中·暂非可动」（🛑 落在任务列）却被计入。09:39 基数下改判后 **23 → 20／22 立即合规**；09:55 `OP-0911-A` 回滚 4 行误判分诊后基数变为 27，改判后 **27 → 23／22，仍超 1**——**认两列消掉的是误计（4 行），不再单独构成合规**；方案件 §四bis「先做 D3⑵ 立刻止血」的前提已随基数变化失效，本包不再宣称它能单独止血。即便如此，今天这道闸判超限**仍有相当一部分原因是它自己的排除规则只看一列、而人写在另一列**（其余是 `#58` ⑸ 与真实在办行数）。

**候选**：
- **(甲)【推荐】读侧判据认「状态列或任务列任一以 🛑 起首」＋ 写侧对「🛑 只落任务列」的新写法打非阻断告警**。改动＝`_count_mechanism_wip` 加一个 `or`；向后兼容存量 5 行（`#381` `#382` `#447` `#448` `#505`）；写侧告警把口径往「落状态列」收敛但**不追改历史**。
- (乙) 判据不动，写侧**强制** 🛑 必须落状态列，并一次性订正存量 5 行。口径更干净，但订正 5 行属「为了让机器好读而改历史行」，与「历史记录不追改」相冲；且订正动作本身要走锁、走 §二，为一个 `or` 的等价效果付五行历史改写——不值。
- (丙) 只改读侧、不加写侧告警。两种写法会继续并存下去，下一个读队列的工具（如 `--digest`、分诊器）还会再撞一次同一坑——出局。

**写侧告警的边界**：只对 `[D:机]` 且状态可动（open/partial/hold）的行判；🛑 落状态列的既有写法不响；`edit-row` 只在本次写入的值触发时响（不为存量行刷屏——`#143` 噪声化教训）。

> **⛳ D-B**：采用 (甲)＋写侧告警。
> **默认项：若不答，按 (甲) 执行。** 若你更看重口径唯一（愿意付 5 行历史改写），回 (乙)，届时另派订正棒。

### D-C · `#58` ⑸ 修法 ＝ 新增行不计入 WIP 时不触发阻断，只回显存量（`#58` 自给修法⑴）

**现状**：`new_mechanism_rows` 收集本次新增的所有 `[D:机]` 行；只要非空且存量超限就拒绝，并把超限归因到一条它自己没算进去的行（`#435` 实证），逼出 `#448`／`#522`／`#526` 三条「本行以 🛑 起首、本就不计入」的假豁免。

**候选**：
- **(甲)【推荐】`#58` 修法⑴——把 `new_mechanism_rows` 收窄为「本次新增且计入 WIP」的行；收窄后为空 ⇒ 只回显存量（迁移期回显两个数），不进 `violations`、不要求豁免。** 多行混合时判定与逃生阀只针对计入的那几行，文案只点名它们。计入判据**复用 `_count_mechanism_wip` 同一套**（含 D-B 的两列 🛑），不复制第二套。
- (乙) `#58` 修法⑵——仍阻断，但文案改为「存量超限 N／M，与本次新增行 #X 无关，本次放行需 --force」。它保留了「每条 🛑 新行都要写豁免」的仪式，只是把文案写诚实；假豁免继续产生——出局。

**为什么 (甲) 不会打开口子**：🛑／`blocked`／`timed=` 行本来就不占 WIP，立它们不增加「开着的行」；措施 C 要踩的动作是「新立**可动**机制行」。对「先立 🛑 行、事后摘 🛑 转可动」这条绕路：摘 🛑 是 `edit-row` 而非新增，按 `#58` 决策点 4 本就不触发判定——这是决策点 4 的**既有**边界，不是本包新开的；值周巡检核「豁免进来的行有没有被真的领走」（方案件 §D4）同样覆盖「摘 🛑 进来的行」。

> **⛳ D-C**：采用 (甲)。
> **默认项：若不答，按 (甲) 执行。**

### D-D · 迁移期与退休判据

**迁移期**：告警模式 7 天（一轮值周巡检节拍），行数闸照旧、陈旧度只算不拦，`release` 回显两个数＋最老 K＋1 条陈旧行。
**切阻断前置（三者缺一不切、不得默认续期）**：① 照抄 `#58` 手法先答「这 7 天里新闸的告警有没有被任何人当回事」，答否 ⇒ 回本件重议（是判据错了、还是没人看回显）；② 值周巡检已对行龄榜首 3 条人工抽查一次（D-A 缓解）；③ 至少一次取龄在**非主 checkout 环境**（沙箱挂载盘或 worktree）真实跑过并记录耗时（本机主 checkout 6.9–8.0 s 不能推别处，rules/队列与落库已记「沙箱挂载盘上 git 极慢」）。
**切阻断的同一批**：删 `--mechanism-wip-cap` 与 `MECHANISM_WIP_CAP_DEFAULT`（一进一出，见 proposal 退休问答）；改写协议〇.9 措施 C 正文、`专线opener模板库.md` §〇.9 ⑵、docstring。
**本版退休判据（方案件 §D5，先写死）**：`STALE` 连续两周为 0 且期间无 `WIP豁免：` 新增 ⇒ 转纯告警并登记退休候选；新闸下 30 天内豁免再破 5 条 ⇒ 回本件重议 N/K，**不是加豁免**。
**存量 15 条 `WIP豁免：` 不追改**，但值周巡检逐条核「豁免进来的行有没有被真的领走」。

**候选中被否的**：(乙) 直接上阻断、不设告警期——新量具的 `STALE` 是乐观估计且 blame 在别的环境未测，用未经现网检验的判据替换已知失效的判据＝赌；(丙) 告警期 14 天——两套判据并存超过一轮巡检就是 `#366`「两套判据各自轮询」重演，且 7 天已够一次「告警有没有人当回事」的检验。

> **⛳ D-D**：7 天告警期＋三条硬前置＋同批退休行数闸＋方案件 §D5 退休判据。
> **默认项：若不答，按上述执行。** 若你判断 7 天内不会有足够的「新增机制行」样本（告警期内每次新增才回显一次），回 (丙) 14 天。

### D-E · 取龄失败怎么办 ＝ 非静默放行（fail-open 但必须出声）＋ 30 s 超时 ＋ 不建缓存

**这是 propose 期新发现的必答项**：编辑锁此前不依赖 git 子进程；本包让 `release` 在新增机制行时多跑一次 `git blame`，主 checkout 6.9–8.0 s，别处未测。取数可能失败（git 不在 PATH／沙箱挂载盘超时／文件在 worktree 影子副本上无历史／编号映射不到物理行）。

**候选**：
- **(甲)【推荐】fail-open 但必须出声**：取数失败 ⇒ 打印带原因与受影响行号的降级告警，按「本次无法判陈旧」放行；带超时（默认 30 s，`--stale-probe-timeout` 可配）。理由：本项检查是写入咽喉上的一道闸，**闸自身的故障不得变成全项目写不进队列**（`#58` 决策点 4 同一精神）；但「静默回退不产生信号」是根 CLAUDE.md 点名的失效形态，故降级必须打印、且部分失败时逐行点名。
- (乙) fail-closed（取数失败即拒绝）。任何一台机器 git 慢一点，所有会话写不进队列——出局。
- (丙) fail-open 且静默。与 `#523`「缺域行静默跳过 ⇒ 算少 ⇒ 该拦没拦」同形——出局。
- (丁) 把 blame 结果缓存到 `reports/` 下、按文件哈希失效。省时间，但凭空造出一种新文件形态（`#322` `*.editlock.mutex.stale` 教训：没人回头看忽略规则；proposal `.gitignore` 问答已据此写「不适用」）；且 7 s 只在新增机制行时付一次，不值得为它建缓存——**出局，留作 Open Question**。

**超时值 30 s 的依据**：主 checkout 实测 8 s 的 3.75 倍；沙箱挂载盘的倍率未知，故 apply 棒须在 tasks 4.3 记录一次非主 checkout 的实测，若 >30 s 则调大默认值而不是让它每次超时降级（每次降级＝闸永远不生效，与 (丙) 等价）。

> **⛳ D-E**：采用 (甲)。
> **默认项：若不答，按 (甲) 执行。**

### D-F · 告警／阻断模式的切换载体 ＝ 模块级常量 `MECHANISM_WIP_GATE_MODE`，切换＝一次 apply 批次，不做 CLI 开关、不做日期自动切换

**候选**：
- **(甲)【推荐】模块常量 `MECHANISM_WIP_GATE_MODE = "warn"`，切阻断＝改成 `"block"` 并同批删行数闸**（一次有 design 审前置的 apply）。切换是**人拍板的动作**，载体是代码与 §二 批次，可追溯。
- (乙) CLI 开关 `--stale-gate-mode`。每个会话各自决定拦不拦 ⇒ 闸不再是闸——出局。
- (丙) 写死日期，到 2026-09-18 自动切阻断。「写进文本的状态不会自己过期」的镜像——若那天三条前置没满足，机器会替人做一个没人拍板的决定；且它等于把「答不答那个问题」这道人闸拆掉——出局。

> **⛳ D-F**：采用 (甲)。
> **默认项：若不答，按 (甲) 执行。**

## Risks / Trade-offs

- **[`STALE` 乐观偏低 ⇒ 该拦没拦]** → D-A 缓解（榜首 3 条人工抽查）；失效方向是安全侧；Open Question 1。
- **[`git blame` 7–8 s 拖慢每一次新增机制行的 release]** → 只在新增机制行时付；D-E 超时降级出声；tasks 4.3 记非主 checkout 实测。若实测普遍 >30 s，回本件议缓存（D-E 丁）而不是静默调大超时。
- **[告警期内样本不足——只有新增机制行时才回显]** → D-D 备选 (丙) 14 天；且复评问题①「有没有人当回事」若因样本为 0 无法作答，按「答否」处理、回本件，不得默认续期。
- **[两套判据并存 7 天，文案含两个数，操作者可能只看熟的那个]** → 回显把陈旧行清单（编号＋天数）放在行数之前；告警期文案明写「7 天后此项将阻断」。
- **[D-C 收窄后「先立 🛑、再摘 🛑」绕路]** → 是 `#58` 决策点 4 的既有边界，非本包新开；值周巡检核「摘 🛑 进来的行有没有被领走」。
- **[`_count_mechanism_wip` 返回值增列（计入行号清单）影响其它调用方]** → tasks 3.1 先 grep 全部调用方、逐一核对；签名兼容（增返回项不改既有两项）。
- **[新增行不计入时「只回显」会不会退化成 `#58` 说的「信息量为零的提示」]** → 它不是判定输出、是状态回显，不承担拦截职能；真正的拦截在计入行新增那一支，不受影响。

## Migration Plan

1. **apply 批 1（告警模式）**：D-A／D-B／D-C／D-E 实现＋单测（tasks §2–§3），`MECHANISM_WIP_GATE_MODE="warn"`，行数闸照旧；协议〇.9 措施 C 正文追加「2026-09 陈旧度闸告警期」段；回填 `#58`。
2. **告警期 7 天**：值周巡检抽查榜首 3 条；记一次非主 checkout 取龄耗时；`WIP豁免：` 新增计数。
3. **复评（🟡 Shao Peishen 一字母）**：答 D-D 三条前置；全「有／已做」⇒ apply 批 2。
4. **apply 批 2（阻断模式）**：常量改 `"block"`，删 `--mechanism-wip-cap`／`MECHANISM_WIP_CAP_DEFAULT`，改写措施 C 正文／模板库 §〇.9 ⑵／docstring／spec 迁主。
5. **回滚**：批 1 `git revert` 即回到现状（告警期内行为与现状一致，仅多一行回显，回滚零风险）；批 2 回滚＝常量改回 `"warn"` 并恢复行数闸（同一 commit revert）。

## Open Questions

1. **机械 commit 对 `STALE` 的污染程度**（D-A）：观察期榜首 3 条抽查后，若污染显著，是回本件重定 N，还是引入「按 commit message 区分机械／实质」的第二层判据？——可安全推迟：不改本包 spec、approach、任务拆分，只影响 N 的下一个取值。
2. **是否建 blame 缓存**（D-E 丁）：取决于非主 checkout 的实测耗时；可安全推迟：告警期内取到实测再议，不影响本包接口。
