## ADDED Requirements

### Requirement: 数据驱动差异分类规则注册表

系统 SHALL 把差异分类规则维护为数据驱动的规则注册表，每条 `{规则ID, 条件(差异方向/是否在标准损耗内/阈值), 分类档, 严重度, 是否触发 L2}`，分类档覆盖**损耗溢短 / 来料短缺 / 管理差异**。规则元数据 MUST 以注册表为单一可信源、随版本登记；分类引擎按注册表判定，MUST NOT 把分类标准写死在判定代码里。

#### Scenario: 标准损耗内 → 损耗溢短（正常）
- **WHEN** 总差异为正且 ≤ 标准损耗基线
- **THEN** 分类为"损耗溢短·标准内"，严重度低，不触发 L2

#### Scenario: 超出标准损耗 → 超损/管理差异
- **WHEN** 总差异为正且 > 标准损耗基线（超出部分超阈值）
- **THEN** 分类为"超损"或"管理差异"（按注册表阈值），严重度高，触发 L2 标记

#### Scenario: 负向差异 → 来料短缺/盘点疑点
- **WHEN** 总差异为负（实际投料少于理论净用量）
- **THEN** 分类为"来料短缺"或"管理差异（盘点/过账疑点）"，触发 L2 标记

#### Scenario: 临时口径占位，对接人定稿替换
- **WHEN** 财务 AI 对接人尚未交付差异分类规则（7/31 前）
- **THEN** 使用 Paul 临时口径注册表跑 mock，结果标"临时口径·待对接人定稿"；定稿后替换注册表、不改分类引擎代码

### Requirement: 规则版本登记

系统 SHALL 为分类规则注册表登记版本号，每份对账报告与审计记录关联其所用规则版本，规则变更走黄金基准回归。

#### Scenario: 报告标注规则版本
- **WHEN** 生成一份对账分类结果
- **THEN** 结果元数据含分类规则版本号，可追溯到具体规则定义
