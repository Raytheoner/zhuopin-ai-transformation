## Why（一段）

派发链的人工成本曲线已实测三级：2026-08-29 当日从「4 次粘贴＋人为掌握时序」压到「1 粘贴＋1 口令」，Shao Peishen 明示还剩的两个人工动作（粘看护 opener、答"开启泳道"）也应归零。全部组件已存在且经生产验证：看护件样板（0828/0829 两份）、`工具-opener批处理执行v2.ps1`、无头 CC 批处理前例（B-0825 A27）、心跳约定（0828 看护件 §一bis）、企微四类事件推送（OP-0829-J 产出）。缺的只是一个把链条串起来、且带护栏的**触发入口**。

## What Changes

新建**引用式 skill `zhuopin-lane-clearpool`**（学 `zhuopin-kickoff-prompt` v2.0 指针模式：已安装版＝约 2KB 稳定指针，规则正本＝仓内 `0-学习与工具/skills源码/zhuopin-lane-clearpool/SKILL.md`）。触发词＝Shao Peishen 在 Cowork 说「**offlan清池**」（及近义表述）。链条＝扫两份队列真身出 off-LAN 候选 → 按白名单判据选件 → 按触碰区排波次生成**看护件落档** → 经批处理工具起**无头 CC 泳道** → 心跳文件＋企微四类事件推送 → 收工汇总推他。

## Non-Goals

- 不自动派发**业务建造**与一切**对外发送**（信件、群通知、专员触达）——永不入自动白名单；
- 不改 `工具-opener批处理执行v2.ps1` 的既有对外语义（只调用；确需小补另立变更）；
- 不取代值周巡检与拆件巡逻（清池是"他主动喊"的即时形态，巡检仍是兜底节奏）；
- 不在 LAN 内场景使用（触发词即口径：off-LAN 批）。

## Impact

- 受影响：派发口径（全项目）；新增 capability `lane-clearpool`；
- 不受影响：队列协议〇全部纪律（选件、认领、锁、批次照旧机器走）；硬边界十条原样继承。
