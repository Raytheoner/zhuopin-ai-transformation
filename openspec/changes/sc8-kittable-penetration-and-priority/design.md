# Design — 可齐套多层穿透（#266）＋ 优先级判据补全（#118）

## Context

两项口径均已由姚祖怡书面签认（采购部#13 回件，2026-08-12），本设计只解决**怎么落地**，
不重开口径。两项必须同一批次交付且顺序固定（先 #266 后 #118）——她是按单料号逐个核的，
两处若分批变会让她无法归因（同 2026-08-05 #262/#263 先例）。

## Goals / Non-Goals

**Goals**：① 可齐套套数/需求日可齐套数量下钻到采购件层重算；② 优先级判据补齐 ②③ 级。

**Non-Goals**（本次明确不做）：
- 不改齐料日 `kit_date` / 四色判定 / BOM 缺口物料清单；
- 不改 `priority_resolver` 的优先地位（#15 真实 PMC 表上线后仍以其为准）；
- 不动 `_gross_need`（毛需求）既有口径。

## Decisions

### D1：穿透用自建 `_unit_usage`，刻意**不复用** `kit_engine.explode_bom`

`explode_bom` 会逐层乘 `(1 + loss_rate)`，而改造前的 `_kittable_qty`/`_demand_kittable_qty`
用的是**裸 `qty_per_unit`、从不计损耗**。

**实测数据（本次取真实 BOM 4523 行）**：其中 **2 行 `loss_rate=0.003`**，且
`S02Y.0035`→`R01D.0017` 那一行就在**第一层**，而 `S02Y.0035` 是在单成品（真实预测订单里
有 5 行）。⇒ 若改用 `explode_bom`，**判例 3 那一族（第一层即采购件、姚祖怡批改为 ✅「维持
现状不用动」）会发生漂移**——`floor(2600/26)=100` 变成 `floor(2600/26.078)=99`。

**故 `_unit_usage` 沿用不计损耗口径**，保证单层 BOM 场景逐值与改造前完全相同。
实测验证：判例 3 对照组全部行在 #266 单独作用下**逐值零漂移**。

**如实登记的既有不一致**：可齐套口径不计损耗、而毛需求 `_gross_need` 计损耗——这是本次
之前就存在的不一致，**本次原样保留、不顺手改**（属判据类，永不默认生效，须经她确认）。

### D2：叶子件判定与 `explode_bom` 的 `sub_assemblies` 同口径

component_id 本身不再作为任何 BOM 行的 product_id 出现即为叶子件；只沿主料路径下钻
（`not is_substitute`），与 `_gross_need` 的 `main_bom` 过滤、`_bom_subtree_product_ids`
（#263）的闭包口径一致。含循环引用防御（`visited`）。

### D3：数据异常语义原样保留

改造前「任一直接子件 `qty_per_unit <= 0` → 返回 None，不以 0 冒充」。改造后沿传播路径
任一层用量非正即返回 None，语义不变、覆盖面扩大到被穿透的层级。

### D4：②③ 判据同时用作 resolver 分支的二级判据

`priority_resolver` 接口粒度只到 so_id，而真实数据里同一 FO 文档下多个行项**共享同一
so_id**（2026-07-29 真实踩坑）。改造前该分支二级排序仅按原始下标 `i`；本次改为
`(rank, 出货日, -数量, 下标)`，与兜底分支统一口径。

**为何不是把 ②③ 凌驾于 resolver 之上**：她本次未说明这三级是否即 #15「真实 PMC 优先级表」
的最终形态、还是仍需 PMC 侧表格覆盖 ⇒ 不替她推断，resolver 优先地位不动。

**既有测试兼容性**：`test_priority_resolver_same_so_id_multiple_lines_falls_back_to_original_order`
锁定「同 so_id 多行按原始顺序」——该用例三行出货日递增，新键 `(rank, 出货日, -数量, i)`
得出的次序与原断言一致，**该用例未被改动亦未失败**。

## Risks / Trade-offs

**风险 1：#118 判据变更的影响面比 #266 广。** 实测 97/109 行的**有效库存快照**发生变化
（因大量成品共用叶子件，分配次序一动就连锁），最终落到显示字段上是 9 行变化。
⇒ 缓解：交付物含逐行「修复前后数字对照」，并**按 #266/#118 分别归因**。

**风险 2：判例 3 对照组在端到端口径下仍有 1 行变化。** `S02Y.0210` 出货 2026-08-20 那行
瓶颈由 `R01B.0365`/缺口 4200 变为 `R01B.0127`/缺口 2100。**归因分解证明该变化 100% 来自
#118 判据、#266 对该成品逐值零漂移**。这必须在给她的说明里写清楚，否则她会读成
「说好不动的怎么动了」。

## Migration Plan

纯计算口径修正，无数据迁移、无 schema 变更、无开关。`SC8_NET_INVENTORY` 关闭时两个字段
恒为 None（与改造前一致，零漂移）。

## Open Questions

1. **可齐套口径是否也应计损耗率**（见 D1）——现状不计，与毛需求不一致；影响面＝真实 BOM
   4523 行中 2 行。**留待姚祖怡确认，本次不动。**
2. 她给的三级判据是否即 #15 真实 PMC 优先级表的最终形态（见 D4）——本次不推断。
