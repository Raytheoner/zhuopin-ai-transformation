## ADDED Requirements

### Requirement: 信级往返天数度量的分桶与单列口径
往返天数度量 SHALL 把跟进信 README 主表的每一行归入且仅归入四个桶之一：

- `可算`：状态承载事实日期且规范尾标里有具体事实日 ⇒ 往返天数 ＝ 事实日 − 发信日；
- `事实日未知`：尾标里写的是字面量 `事实日未知`（**有人明确记下「查不出来」**）；
- `无标注`：状态承载事实日期但无尾标（**没记**；尾标机制之前写的历史行）；
- `不适用`：该状态本就不承载事实日期。

四桶计数之和 MUST 等于主表行数。

🔴 `事实日未知` 与 `无标注` MUST 各自单列、MUST NOT 混入中位数计算、且 MUST NOT 被合并为同一个「缺失」桶——前者是「记了，结论是不知道」，后者是「没记，真实日期未必丢了」；合并即把「没记」洗成「记了不知道」，是同一类信息销毁的温和版本。

可算样本数低于既定下限时，脚本 MUST NOT 报出中位数：MUST NOT 报 0、MUST NOT 拿另外两个桶凑数，SHALL 改为说明拒算原因。下限取值 MUST 大于 1——实测往返周期分布是双峰的，小样本必然只落一峰，一个「没有样本也照样给数」的度量脚本正是两个都不是真值的历史中位数的制造方式。

脚本 SHALL 同时报出**补记滞后**（补记日 − 事实日）的中位与最大值——该量此前完全不可观测，而 2026-08-23 的 12 封批量补转态在它上面的取值是 20–27 天。

尾标正则、`事实日未知` 字面量与「哪些状态承载事实日期」的判据 MUST 复用写侧（`工具-跟进信README登记.py`），MUST NOT 自持第二份——写侧与读侧各写一份的后果是写进去的标读不出来，而且不报错。

发信日或事实日形态损坏时，该行 SHALL 退回单列桶并说明原因，MUST NOT 按 0 天计入可算桶。

主表解析不到任何数据行时 SHALL 报错，MUST NOT 返回一份空报告——只读结果「太干净」时先怀疑没读到目标文件。

本度量 SHALL 只读，MUST NOT 写入 README 或任何状态文件。

#### Scenario: 有具体事实日的行进可算桶
- **WHEN** 某行状态为 `📥 已回件并回灌 〔事实日 2026-08-04 ／ 补记日 2026-08-05〕`、发信日 `2026-08-01`
- **THEN** 该行归入 `可算` 桶，往返天数 3、补记滞后 1

#### Scenario: 事实日未知的行单列且不进中位数
- **WHEN** 某行尾标为 `〔事实日 事实日未知 ／ 补记日 2026-08-23〕`
- **THEN** 该行归入 `事实日未知` 桶并被单独列出编号，不参与中位数计算

#### Scenario: 无尾标的历史行归无标注桶而非事实日未知桶
- **WHEN** 某行状态为 `📥 已回件并回灌（2026-08-23，拆件巡逻）`（无规范尾标）
- **THEN** 该行归入 `无标注` 桶，`事实日未知` 桶计数不变

#### Scenario: 四桶之和等于主表行数
- **WHEN** 主表含可算、事实日未知、无标注、不适用各若干行
- **THEN** 四桶计数之和等于主表行数

#### Scenario: 可算样本不足时拒报中位数
- **WHEN** 可算样本数低于下限
- **THEN** 报告中的中位数为空，并给出拒算原因，MUST NOT 输出 0

#### Scenario: 单列桶不把中位数拽走
- **WHEN** 可算样本足量，同时存在大量无标注与事实日未知的行
- **THEN** 中位数仅由可算样本算出，与另外两桶的数量无关

#### Scenario: 日期形态损坏时退回单列
- **WHEN** 某行发信日不是合法日期
- **THEN** 该行不进可算桶，改归单列桶并记录解析失败原因

#### Scenario: 主表无数据行时报错
- **WHEN** 目标文件解析不出任何数据行
- **THEN** 脚本报错并以非零退出码结束，MUST NOT 输出一份空报告
