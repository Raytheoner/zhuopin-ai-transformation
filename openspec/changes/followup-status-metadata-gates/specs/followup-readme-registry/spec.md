## ADDED Requirements

### Requirement: set-status 的事实日／补记日两字段
`set-status` SHALL 在把状态改写为承载事实日期的状态（`✅ 已推送`／`📥 已回件并回灌`／`📨 已确认闭环`／`📨 回件已到，待拆件`）时要求调用方给出 `--fact-date`，缺则 MUST 被拒绝（非零退出码），且 MUST NOT 获取编辑锁、MUST NOT 改动 README 主表。

`--fact-date` 取值 SHALL 为严格 `YYYY-MM-DD` 且真实存在的一天，或字面量 `事实日未知`；MUST NOT 晚于本机当天。该字面量 MUST 与点级台账（`zhuopin_platform.coverage_point_ledger.models.FACT_DATE_UNKNOWN`）为同一份常量，CLI MUST NOT 自持第二份字符串——两处各写一个，度量脚本按哪一个筛都会漏掉另一半，而漏掉不报错。

补记日 SHALL 由工具取本机当天，MUST NOT 由命令行传入——一个可传的补记日即可被倒填，而它正是用来量「补记滞后」的那一半。

事实日与补记日 SHALL 以规范尾标 `〔事实日 X ／ 补记日 Y〕` 写在状态单元格末尾，MUST NOT 新增 README 主表列。同一单元格 MUST NOT 出现两枚尾标。

🔴 在**同一状态前缀**下，已写入的具体事实日 MUST NOT 被后续写入改写；命中即拒绝（非零退出码、不取锁、不改动 README）。唯一逃生阀 SHALL 是在 `--status` 文本里显式写 `事实日更正：`——留痕在单元格里、可被检索，MUST NOT 设计成命令行开关（开关跑完就没了，谁也看不出这行被改过）。

**换状态即换事实，不算覆盖**：事实日 SHALL 被视为「当前这个状态」的属性而非「这一行」的属性（回件到达日 ≠ 我方确认闭环日）。转到不承载事实日期的状态时，旧尾标 SHALL 原样带过（连同其原补记日），MUST NOT 被冲掉。

补记滞后（补记日 − 事实日）≥14 天时，CLI SHALL 打印提示——这行字正是 2026-08-23 批量补转态当时**没有**的那个信号。

本要求 MUST NOT 声称能判定事实日是否属实：`--fact-date <今天>` 与「真的就是今天回件」在机器眼里一模一样。它只把该动作由「默认发生」降为「必须主动做一次」。

#### Scenario: 转回件态未给事实日被拒绝
- **WHEN** 以 `--status "📥 已回件并回灌（拆件巡逻）"` 调用 `set-status` 而未给 `--fact-date`
- **THEN** CLI 以非零退出码拒绝、不取锁、不改动 README，并给出「不得拿今天顶替」的出路文案

#### Scenario: 事实日与补记日一并落成规范尾标
- **WHEN** 以 `--status "📥 已回件并回灌（拆件巡逻）" --fact-date 2026-08-10` 调用
- **THEN** 状态单元格末尾写入 `〔事实日 2026-08-10 ／ 补记日 <本机当天>〕`，并打印往返滞后天数

#### Scenario: 事实日不可考时写字面量而不被补记日顶替
- **WHEN** 以 `--fact-date 事实日未知` 调用
- **THEN** 尾标写 `〔事实日 事实日未知 ／ 补记日 <本机当天>〕`，且该样本被标注为度量时单列、不混入中位数

#### Scenario: 同一状态下已有事实日不得被覆盖
- **WHEN** 某行已带 `〔事实日 2026-08-10 ／ 补记日 2026-08-23〕`，再以同一状态前缀与不同的 `--fact-date` 调用
- **THEN** CLI 以非零退出码拒绝、不取锁、不改动 README，并在文案中给出旧值与 `事实日更正：` 逃生阀写法

#### Scenario: 显式写事实日更正标记后允许改写
- **WHEN** `--status` 文本中含 `事实日更正：原记 2026-08-10，依据…` 且给出新的 `--fact-date`
- **THEN** CLI 放行，新事实日与更正理由同时留在单元格里

#### Scenario: 换状态即换事实不算覆盖
- **WHEN** 某行带 `📥 已回件并回灌` 的事实日，转为 `📨 已确认闭环` 并给出新的事实日
- **THEN** CLI 放行——回件到达日与我方确认闭环日本就是两个日期

#### Scenario: 转到不承载事实日的状态时旧尾标原样带过
- **WHEN** 某行带事实日尾标，转为 `❌ 已作废` 且未给 `--fact-date`
- **THEN** 旧尾标（含其原补记日）原样保留，MUST NOT 被冲掉

#### Scenario: 事实日形态不合或晚于本机当天被拒绝
- **WHEN** `--fact-date` 取值不是真实存在的一天（如 `2026-02-30`），或晚于本机当天
- **THEN** CLI 以非零退出码拒绝、不取锁、不改动 README

#### Scenario: 不承载事实日期的状态不要求该参数
- **WHEN** 以 `--status "🆕 待发"` 调用而未给 `--fact-date`
- **THEN** CLI 正常完成写入，且不写入任何尾标

### Requirement: set-status 的状态取值闭集
`set-status --status` 的取值 SHALL 以判据版八态（`⏳ 待你审`／`🆕 待发`／`⏸ 暂缓`／`✅ 已推送`／`📥 已回件并回灌`／`✅ 无需回复`／`📨 已确认闭环`／`❌ 已作废`）或第九态（`📨 回件已到，待拆件`）之一为前缀，其余 MUST 被拒绝（非零退出码、不取锁、不改动 README）。前缀之后的括注内容 MUST NOT 被校验。

第九态 SHALL 纳入闭集：它是 `#366` M1 落地、由 S4 桥一实际写进同一列的权威状态，判据版 §二 只是成文早于它。把它排除在外的后果不是「拦住一种乱写」，而是**唯一合法登记入口写不出一个合法状态**，使用者只会绕开该入口。

历史写法 `✅ 已发` MUST 被拒绝写入，但 MUST NOT 从 `followup_gate` 的已知状态集中移除——历史行仍须被读懂。**「闸认得」与「还能写」是两件事**，拒绝文案 SHALL 显式区分这两种情形（「认得但已退役」vs「完全不认得」）。存量 README 行 MUST NOT 被回改。

#### Scenario: 判据版八态与第九态放行
- **WHEN** `--status` 以八态或第九态之一为前缀（可带任意括注）
- **THEN** CLI 通过状态校验

#### Scenario: 已退役的历史写法被拒绝且文案点名其已退役
- **WHEN** 以 `--status "✅ 已发（2026-07-09）"` 调用
- **THEN** CLI 以非零退出码拒绝、不取锁、不改动 README，且文案说明该写法闸仍认得但已退役

#### Scenario: 闭集之外的自由文本被拒绝
- **WHEN** `--status` 取值不以闭集任一前缀开头
- **THEN** CLI 以非零退出码拒绝，且文案说明该写法连 `followup_gate` 也不认得

### Requirement: append 的收信人取值形态与旧字段停写
`append --recipient-cell` 取值 SHALL 为 `<部门> · <姓名>` 形态；姓名 MUST 在人员名录正本在册；其中的部门 MUST 与 `--department` 一致。任一不满足即拒绝（非零退出码、不取锁、不改动 README）。部门不一致会把编号取到另一个部门的连续序列里，且写完不报错——故它是拒绝项而非告警项。

姓名在册判定 SHALL 复用 `工具-共享文档编辑锁.py::PERSON_GENDER_ROSTER`，MUST NOT 在运行时解析名录正本散文——正本 §一 措辞一变就抽不到人名，判据随即恒真、零信息量，且没有任何东西会报错。取数结果少于既定下限时 SHALL 报错拒判，MUST NOT 据此把每个真实收信人都判成「不在册」。

`append` SHALL 拒收 frontmatter 仍带 `开放点计数:` 或 `开放点:` 的信件（`决策点:` 为唯一正本）。该检查 SHALL 落在登记 CLI 而非全目录 lint：后者会把既有历史件判成永久违规，而「历史件不追改」是既定纪律，一条恒红的校验只会被加豁免绕开。

#### Scenario: 收信人缺分隔符被拒绝
- **WHEN** `--recipient-cell` 取值不含 `·`
- **THEN** CLI 以非零退出码拒绝、不取锁，并给出 `<部门> · <姓名>` 的写法

#### Scenario: 姓名不在名录正本被拒绝
- **WHEN** `--recipient-cell` 的姓名不在人员名录正本在册名单内
- **THEN** CLI 以非零退出码拒绝，并说明须先问一次、补进正本，MUST NOT 允许现编

#### Scenario: 部门与 department 参数不一致被拒绝
- **WHEN** `--department` 为 `采购部` 而 `--recipient-cell` 为 `质量部 · 陈忱`
- **THEN** CLI 以非零退出码拒绝，并说明会把编号取到另一个部门的序列里且不报错

#### Scenario: 名录取数异常时报错而非把每个人判成不在册
- **WHEN** 名录常量被改坏、可读到的姓名少于下限
- **THEN** CLI 以非零退出码报「名录取数异常」，MUST NOT 继续做在册判定

#### Scenario: 信件仍带已停写的旧字段被拒绝
- **WHEN** `--letter-path` 指向的信件 frontmatter 含 `开放点计数:` 或 `开放点:`
- **THEN** CLI 以非零退出码拒绝，并说明以 `决策点:` 为唯一正本、旧字段停写、历史件不追改
