# followup-status-metadata-gates Design

> 🟡 **本件须 Shao Peishen 拍板后方可合入 master。** 每个决策点都给选项、代价与推荐项；**D1／D2／D3 三条是本包真正需要他答的**，D4–D5 是已落定取舍的复核项。

## 决策点

### D1（🔴 须拍）第九态 `📨 回件已到，待拆件` 要不要进 `--status` 闭集

Shao Peishen §10 O1 答 (a) 的原文是「判据版八态＋闭环三态为闭集」。**第九态不在那句话里**——它是 `#366` M1 之后落地的、由 S4 桥一实际写进同一列的权威状态，`跟进机制-判据版.md` §二 成文早于它，所以那份「八态」清单里没有它。

- **(a)〔荐〕纳入闭集（当前实现）**。代价＝闭集实际是九个前缀，与 §10 那句话字面上差一项，须在 `跟进机制-判据版.md` §二 补一行说明（本包已补）。收益＝登记 CLI 写得出所有合法状态。
- **(b) 严格按字面只收八态**。代价＝**唯一合法登记入口写不出一个真实存在的合法状态**；需要手动标第九态的人只能绕开 CLI 裸手 Edit 主表（而门禁会拦，于是他会去改门禁白名单）——这正是本 CLI 存在的理由被绕过。

🔑 判据：**一条把真实合法语料判成违规的判据，第一次跑就会被人加豁免绕开，等于没有**（同 `决策点:` 前缀锚定那条的理由）。

### D2（🔴 须拍）S4 桥自动转态写不写尾标

`followup_readme_bridge.py`（桥一写第九态、桥二写 `📥 已回件并回灌`）**不经过本 CLI**，其写出的状态列没有尾标，会落进度量脚本的「无标注」桶。

- **(a)〔荐〕本包不改桥，另立队列一行交 `#366`／`#446` 的实现方**。代价＝并跑期内桥写的行不进「可算」桶，度量样本增长慢；收益＝不撞 `#366`／`#446` 的触碰区（`#447` 行自己写着「⑵ 须与 `#366`／`#446` 的实现方对齐取数与写入口径」）。
- **(b) 本包顺手改桥**。代价＝跨触碰区改动，两个 session 改同一文件；且桥的「事实日」取数（企微回件时间戳 vs README 日期）本身是一个需要单独定的口径，顺手改必然是猜。

### D3（🔴 须拍）`✅ 无需回复`／`❌ 已作废` 要不要也强制事实日

当前：不强制、给了照记。真实语料里 `✅ 无需回复（2026-08-13 发出即闭环）` 是带日期的。

- **(a)〔荐〕维持不强制**。理由＝这两态是**我方当场做出的判定**，不存在「事实发生在别的一天」；强制会把它们也拖进补记语义，制造一批「事实日＝当天」的无信息样本。代价＝这两态的行永远进不了度量。
- **(b) 一并强制**。代价＝见上；收益＝口径整齐（所有闭环态都有事实日）。

### D4（复核）与 `followup-readme-phase2`／`followup-decision-point-gate` 的排序

同一能力 `followup-readme-registry` 上目前有**三份在途 delta**。本包 apply 前须先确认前两包的收尾次序。**已落定取舍**：本包在实现上**建立在 `followup-decision-point-gate` 之上**（`_assert_no_legacy_decision_fields` 挂在 `_assert_decision_points` 末尾），故合入顺序 MUST 为 `followup-readme-phase2` → `followup-decision-point-gate` → 本包。

### D5（复核）逃生阀形态：单元格留痕 vs 命令行开关

**已落定：留痕在单元格里**（`事实日更正：原记 <旧值>，依据…`）。理由＝命令行开关跑完就没了，**谁也看不出这行被改过**；而单元格里的标记可被 `grep`、可被值周巡检抽验，同 `串行豁免：`／`转态豁免：` 既有房规。

## 已落定的取舍（不再展开，供复核）

- **尾标落状态单元格、不新增表列**：新增列要改主表表头，45 行历史行与四个解析方（`readme_table`／查询／闸／桥）全要跟；而状态列今天已经在写日期。
- **补记日不接受传参**：能传即可倒填，而它正是量「补记滞后」的那一半。
- **事实日是「当前状态」的属性、不是「这一行」的属性**：换状态即换事实，不算覆盖。⚠️ 这一条是被单测撞出来的（先写成「一行一个、转态沿用」，用例当场矛盾：转闭环时要么被逼重填回件日、要么把回件日当成确认日）。
- **`FACT_DATE_UNKNOWN` 与点级台账共用同一个 Python 对象**（单测 `assertIs` 断言）：两处各写一个字符串，度量脚本按哪一个筛都会漏掉另一半，而漏掉不报错。
- **O2 名录取数走编辑锁侧常量、不运行时解析散文正本**：理由是那份常量自己写着的那条（措辞一变就抽不到人名，判据随即恒真、零信息量且没有任何东西会报错）。
- **O3 落点在登记 CLI 而非全目录 lint**：全目录 lint 会把 3 封历史件判成永久违规，而「历史件不追改」是既定纪律 ⇒ 恒红的校验只会被加豁免绕开。
- **度量脚本可算样本 <5 拒报中位数**：一个「没有样本也照样给数」的度量脚本，就是 §4.5 那两个中位数的制造方式。下限取 5 而非 1 的理由＝design §4.1 实测分布是**双峰**的，小样本必然只落一峰。
- **`事实日未知` 与「无标注」不许合并**：前者是「记了，结论是不知道」，后者是「没记，真实日期未必丢了」。合并即把「没记」洗成「记了不知道」。
