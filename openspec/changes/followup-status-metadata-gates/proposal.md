## Why

### 一个日期被写下来的那一刻，另一个日期被销毁了

2026-08-23，README 主表有 **12 封信**被批量「补转态」：`采购部#6/#7/#8/#10`、`质量部#5`、`财务部#7/#8/#9/#10`、`IT部#4/#5/#6`。状态列上留下的日期是 **2026-08-23**，也就是**补记那一天**；这些信的**真实回件日在那一刻被覆盖式销毁、不可复原**（design §4.4 逐封铁证，往返天数实测 20–27 天、全部 ≥14 天）。

后果不是「算不准」，是**度量本身变成了账的伪影**：

- 08-23 度量复盘的样本 17 封 ⇒ 中位 **2 天**（**样本缺失**：慢的那 12 封当时还没转态、不在闭环集里）。
- 09-01 同法重算 35 封 ⇒ 中位 **7 天**（**样本污染**：把补记日当回件日）。
- **底层事实一天没变**。08-24 那次「达标有余（约为目标 1/3）」并据此**摘掉判例批改法回退闸**的结论，建立在一份**没补完的账**上。

🔴 **全程不产生任何信号**——屏幕上只是一个数字从 2 变成了 7。这与本项目已反复吃过亏的「工具静默回退」「`决策点:` 无声消亡」完全同族：**错误不产生任何信号，所以永远不会被察觉。**

### 为什么「以后注意写真实日期」不够

「注意写」是人守，而这个动作的失效**不阻塞、不报错、不产生任何下游信号**，正是 `#447` ⑴ 的死法。⑴ 已经证明过一次：`决策点:` 靠自觉写到 70% 覆盖率，然后归零。⇒ 必须挂咽喉：**一封信要改状态，必须经过 `set-status`**（`hooks-pretooluse-queue-read-guard.ps1` 已把裸手 Edit 主表拦死）。

### 为什么必须同时改度量侧

只在写侧分开两个日期还不够：**读侧若把「事实日未知」和「没标注」合并成一个「缺失」桶，等于把「没记」洗成「记了不知道」**，是同一类信息销毁的温和版本。design §5.3 的 Scenario 已明文要求「度量脚本 SHALL 将 `事实日未知` 的样本单独列出，不混入中位数计算」——本包把这条从**点级台账**（`#439`，已实现于 `coverage_point_ledger`）平移到**信级**。

## What Changes

### ⑵ 事实日／补记日（`set-status`）

- 新增 `--fact-date`：转 `✅ 已推送`／`📥 已回件并回灌`／`📨 已确认闭环`／`📨 回件已到，待拆件` 时**必填**；取值为 `YYYY-MM-DD`（须真实存在且不晚于本机当天）或字面量 `事实日未知`。
- 🔴 **补记日由工具取本机当天，不接受传参**——能传即可倒填，而它正是量「补记滞后」的那一半。
- 两者以**规范尾标** `〔事实日 X ／ 补记日 Y〕` 落在状态单元格。**不新增表列**：新增列要改主表表头，45 行历史行与四个解析方全要跟；而状态列**今天已经在写日期**，问题从来不是没地方写，是写下来的那个日期分不清是哪一个。尾标只把两者**分开**，不动表形态；历史行天然没有尾标 ⇒ 度量脚本据此单列，而它们恰好就是被污染的那批样本。
- 🔴 **同一状态下事实日一经写入不得被改写**（design §5.3 第三条 Requirement）。逃生阀＝在 `--status` 文本里显式写 `事实日更正：原记 <旧值>，依据…`——**留痕在单元格里、可被检索**，同 `串行豁免：`／`转态豁免：` 的既有房规，不做成一个跑完就没了的命令行开关。
- **换状态即换事实，不算覆盖**：回件到达日 ≠ 我方确认闭环日。事实日是「当前这个状态」的属性，不是「这一行」的属性。⚠️ 这一条是被单测撞出来的——先写成「一行一个事实日、转态沿用」，用例当场矛盾：转闭环时要么被逼重填回件日、要么把回件日当成确认日。
- **转到不承载事实日的状态**（`❌ 已作废` 等）时，旧尾标**原样带过**（连同它原来的补记日），不因一次不相干的转态把它冲掉。
- **补记滞后 ≥14 天时打印 `[NOTE]`**：这行字正是 2026-08-23 那次批量补转态**当时没有**的那个信号。

### O1 状态取值闭集（`set-status`）

- `--status` 前缀须属**判据版八态 ＋ 第九态**（`CLI_STATUS_CLOSED_SET`），其余拒写；括注怎么写不校验。
- ⚠️ **第九态 `📨 回件已到，待拆件` 一并纳入，这不是放宽 O1**：它是 `#366` M1 落地、由 S4 桥一实际写进同一列的权威状态，判据版 §二 只是成文早于它。排除它的后果不是「拦住一种乱写」，而是「唯一合法登记入口写不出一个合法状态」——人只会绕开 CLI 裸手 Edit。⇒ **design 决策点 D1。**
- **`✅ 已发` 退役**（主表实测 6 行、全部 2026-07）：`followup_gate` 仍认得它（历史行要能被读懂），但此后不许再写。**「闸认得」与「还能写」是两件事**，拒绝文案显式点名这一点。**历史行不回改。**

### O2 收信人取值形态（`append`）

- `--recipient-cell` 须为 `部门 · 姓名`，姓名须在人员名录正本在册，且部门须与 `--department` 一致（不一致会把号取到另一个部门的序列里，且写完不报错）。
- 🔴 **姓名取数走 `editlock.PERSON_GENDER_ROSTER`，不在运行时解析散文正本**——理由是那份常量自己写着的那条（正本 §一 是每周都在变的散文，措辞一变就抽不到人名，判据随即恒真、零信息量且没有任何东西会报错），且编辑锁侧已有同步用例保证「正本 §一 ⊆ 该常量」。再解析一次＝第二份会漂移的名录。
- **名录规模下限守卫**：读到的姓名少于 15 个即报错拒判，而不是把每个真实收信人都判成「不在册」（🔑「只读结果太干净先怀疑没读到对象」）。
- **实测 45 行主表零误杀**（四位收信人全部在册、格式全部合规）。

### O3 旧字段停写（`append`）

- frontmatter 仍带 `开放点计数:`／`开放点:` 者拒登记，`决策点:` 为唯一正本。
- **落点刻意在登记 CLI 而不在 `工具-跟进信frontmatter校验.py`**：后者扫全目录，会把 3 封历史件判成**永久违规**，而「历史件不追改」是既定纪律 ⇒ 一条恒红的校验只会被人加豁免绕开。登记 CLI 只看本次要登记的那一封，天然只约束新件。

### 度量侧（新工具）

- 新增 `0-学习与工具/工具-跟进信往返度量.py`：四桶分类（`可算`／`事实日未知`／`无标注`／`不适用`），🔴 **`事实日未知` 与「无标注」各自单列、都不混入中位数、两者不许合并**；可算样本 <5 时**拒报中位数**（不报 0、不拿另两桶凑数）；同时报**补记滞后**中位与最大值。
- 尾标正则与「哪些状态承载事实日」**importlib 复用登记 CLI**——写侧与读侧必须是同一份判据，各写一份的后果是写进去的标读不出来，而且不报错。

## 本次退休哪一个既有守卫（强制，协议〇.9 措施 B）

**退休：`6-人才与组织/部门AI专员跟进/跟进机制-判据版.md` §二 末条「⚠️ **配套义务**：回件消化完必须**手工**把该行由 `✅ 已推送` 改为 `📥 已回件并回灌 <日期>`」里的「`<日期>` 写什么」这一段人守语义。**

改前：该条只说「写日期」，**没有任何判据说明写的是哪一天**——12 封信正是从这个空白掉下去的。改后：日期语义由 `--fact-date` 机器守（必填 ＋ 形态 ＋ 不可覆盖），本条降为指向 §二bis 的一行。**一进（`--fact-date` 上岗）一出（「写日期」这条无判据的人守条目消解）。**

🔴 **顺序不可反**：本包 apply 完成 ≠ 可以改那条文字。**先真实验活（至少真实拒绝一次并留痕），后改文字**（沿用 `editlock-write-side-date-guard` 确立的 #381 顺序约束）。⚠️ 「必须手工转态」这半句**不退休**——机器守的是「转态时日期写什么」，**不是「有没有人去转态」**；后者仍是人守（`#366` M1 已点名「闸永远不会自己开」）。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

1. **本流程哪些判断是人脑默会经验？**
   ⑴ **「这个日期是事实发生那天，还是我今天登记的那天」** —— 此前完全隐含在转态者脑子里，写下来的只有一个数字，**两种语义在载体上无法区分**。本包把它显性化为两个并存的字段 ＋ 一个「不可考」的合法取值（`事实日未知`）。**机器守不了「这个日期对不对」，只能守「有没有被迫做出选择」**——而正是「不必做选择」让 12 封信的真实日期消失。
   ⑵ **「哪些样本可以进中位数」** —— 此前无判据，两次度量各自凭直觉取样，得出两个都不是真值的数。本包显性化为四桶分类与 `MIN_SAMPLES_FOR_MEDIAN`。
2. **由谁显性化？** 持有人 ＝ **Shao Peishen**（§10 (a) 拍板人、design 审拍板人）；backup ＝ 下一位领取 `#447` 的 session，可凭本包＋`design审前置-口径点台账三开放点收敛-2026-09-01.md` §4.4–4.5＋`跟进机制-判据版.md` §二bis 独立复核，不依赖任何本会话的口头结论。
3. **用什么方法提取？** **历史事故反推** —— 12 封信的逐封实测（design §4.4 表）即本判据的全部出处；`事实日未知` 字面量与不可覆盖约束**直接沿用点级台账 `coverage_point_ledger` 已实现的同一条**（`FACT_DATE_UNKNOWN` 为同一个 Python 对象，单测断言 `assertIs`），不新立第二份。不涉及 LLM 运行时判断。

  - `test_工具-跟进信README登记.py` **61 passed ＋ 8 subtests**（改前 30）。
  - `test_工具-跟进信往返度量.py` **14 passed**（新建）。
  - 度量脚本对**生产 README 只读实跑**：45 行 ⇒ 可算 0 ／ 事实日未知 0 ／ 无标注 36 ／ 不适用 9，四桶之和 ＝ 45，**拒报中位数并说明原因**。

  2. 真实登记一个具体事实日成功，事后核实尾标**确实进了 git**，且度量脚本能把它算进 `可算` 桶。
  3. 🔴 **观察窗口 ≥5 次真实转态**，逐次核实事实日**不等于当天**的比例——**若出现「为了过闸而一律填当天」**，本判据须**重评而非放宽**：逼出假数据比字段缺失更坏，且这一次的假数据形态**恰好就是 2026-08-23 那次事故本身**。
  4. 🔴 **零命中不得被读成「规则已生效」**（本项目已有 §四 #58／#122／`.51` 假零／skill 假零四个同形教训）。窗口内本闸一次都没拒绝过 ⇒ 正确表述是「未被检验」，**MUST NOT** 表述为「事实日销毁问题已解决」，**且此时不得据此改 `跟进机制-判据版.md` 那条人守文字**。
- **价值指标**（风险型）：新写入状态行的事实日标注覆盖率 —— 基线 ＝ **0%**（45 行主表无一行带尾标，实测）；目标 ＝ **新写入 100%**（存量不追改，守根 `CLAUDE.md` §1「历史记录不追改」）。次级指标 ＝ **补记滞后中位数**（此前无法观测，基线不存在；本包上线后首次可测）。
- **LLM 判据黄金集**：不适用（纯日期形态与集合成员判定，无 LLM 运行时判断）。

## 已知残余风险（如实写明，不粉饰）

1. **本闸拦不住「填了一个假的事实日」。** `--fact-date 2026-09-07`（＝今天）与「真的就是今天回件」在机器眼里一模一样。**这正是 2026-08-23 事故的形态，本包只能把它从「默认发生」降为「必须主动做一次」，并让 `[NOTE]` 与度量脚本把滞后分布摆出来**——不假装覆盖。对策只有观察窗口的人工抽验（验收条第 3 项）。
2. **规范尾标的存在依赖「所有转态都走 CLI」。** S4 桥一／桥二（`followup_readme_bridge.py`）自动转态时**不经过本 CLI**，写出的状态列没有尾标 ⇒ 会落进「无标注」桶。**本包刻意未改桥**（那是 `#366`／`#446` 的触碰区，跨行改动会撞触碰区）。⇒ **design 决策点 D2**：桥的尾标补写要不要另立一行。
3. **`✅ 无需回复` 与 `❌ 已作废` 不要求事实日。** 判据是「判据版 §二 的取值形态里自带不自带日期」，但真实语料里 `✅ 无需回复（2026-08-13 发出即闭环）` 是带日期的。**当前放行但不强制**（给了照记）——硬要求会把「我方当场判定」也拖进补记语义。⇒ **design 决策点 D3。**
4. **O2 的名录取数是一份人工同步的常量。** 名录扩了而常量没跟时，新收信人会被判成「不在册」。这是 **fail-loud 方向**（拒绝而不是放行），且编辑锁侧已有同步用例当场变红，但**第一次撞上的人会被挡住**，须知道出路是先补正本再补常量。
5. **度量脚本的可算样本长期为 0 的可能。** 若所有转态都走桥（见风险 2）或人一律不用 CLI，这个桶永远是空的，而脚本会**如实说「拒报中位数」**——它不会假装有数，但**也不会主动告警**「机制没被用上」。⇒ 观察窗口第 4 项要盯的正是这个。
