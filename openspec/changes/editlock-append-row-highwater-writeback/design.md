## 一、现状取证（只读，可逐条复核）

### 1. 计数器的写入方只有一个

| 路径 | 读高水位线 | 写高水位线 | 代码位置（master ＠ `d987d31`） |
|---|---|---|---|
| `acquire --reserve` / `--reserve-multi` | ✅ | ✅ | `_reserve_ids()`，1880–1955 行 |
| `acquire`（不带预留） | ✅（只回显） | ❌ | `cmd_acquire()`，6010–6016 行 |
| `append-row --section 一\|四 --number N` | ❌ | ❌ | `cmd_append_row()`，2929–3053 行 |
| `edit-row` | ❌ | ❌ | 改既有行，不引入新编号，**不在本包范围** |

`cmd_append_row` 的完整写入尾段（3050–3053 行）：

```python
    target_path.write_text(new_text, encoding="utf-8")
    print(f"✓ 已追加一行到 §{args.section}：{new_line}")
    return 0
```

—— 写完即返回 `0`，中间没有任何一次高水位线读写。

### 2. `_reserve_ids` 的回写逻辑（D1 要复用的那一段）

1. `HIGH_WATER_MARK_LINE_PATTERN.search(text)` 定位声明行 → 取出整行 `line`；
2. `SECTION_NUMBER_PATTERNS[section].search(line)` 取该分区的号（`group(2)` ＝ 数字）；
3. 碰撞前置校验（队列 `#185`）：即将分配的号若已出现在可见行 ⇒ `ReserveFailedError`；
4. `line[:start(2)] + str(new_value) + line[end(2):]` 就地换数字 → 整文件 `write_text`。

其中 **1、2、4** 是纯粹的「定位 ＋ 替换分区片段」，与「分配」无关 —— 这三步就是 D1 要抽出来共用的部分。**3 不复用**：它是分配前的合法性判定，`append-row` 侧那一刻编号已经由调用方给定、行也已经通过了列数与凭据校验，再跑一次碰撞校验只会把「补写空洞号」这种合法动作误拒。

### 3. 计数器写入的目标文件与 `append-row` 的写入目标**不是同一个量**

- 高水位线声明**恒定只存机制环境文件**（决策点 1/2 的既有结论）：`cmd_acquire` 用 `reservation_target = QUEUE_MECHANISM_PATH_REL if is_queue_system else args.file`（5961–5963 行）。
- `cmd_append_row` 则按 `--domain` 把 §一 路由到机制环境文件**或**业务场景文件，并**就地改写 `args.file`**（2945–2957 行）。

⇒ **D1 的实现必须在域路由改写 `args.file` 之前把「计数器目标」定死**，与 `lock_anchor` 的既有做法同源（队列 §一 `#420` 已为「锁锚点」踩过同一个坑，注释原话：「锚点与写入目标是两个量」）。**这里是第三个量。** 写错就会把高水位线写进业务场景文件 —— 而那份文件里根本没有声明行，`append-row --domain 业` 会当场全面失败。

### 4. release ③ 兜不住的原因（proposal「Why」已列表，此处只补一句判据）

③校验（`_validate_release_structure`，4402–4443 行）问的是「**你有没有按规矩取号**」，本包问的是「**计数器和文件一致吗**」。前者有三个合法豁免口（机器人收件登记／修复既有破损行／行内 `预留豁免：`），每开一个，后者就多一条失效路径 —— 这是**两个不同的量**，不能互相代替。

## 二、决策点（四点，各带推荐项）

> ✅ **本节四点已于 2026-09-08 全部拍板为 (a)**（Shao Peishen 答 `1a2a3a4a`）。以下原文保留。

### D1｜口径二选一：自愈 还是 强制

`#505`「期望产出」列原文给了两条路，二选一：

- **(a) 自愈型（推荐）** —— `append-row --number N` 写入成功后同步推线。两个入口对计数器行为一致，`--number` 的既有用法**全部保持可用**。
- (b) 强制型 —— 拒绝 `--number` 走新号，一律逼回 `--reserve`。
- (c) 两者都要 —— 推线 ＋ 对「未预留的新号」打警告但不拒。

**推荐 (a)，理由三条**：

1. **(b) 会当场打断三条既有合法通路**。release ③ 的三个豁免口（机器人收件登记／修复破损行／`预留豁免：`）存在的前提，正是「有些行就是不经 `--reserve` 落盘」。(b) 等于在 `append-row` 这一侧把这三条路全部堵死，而它们各自都有自己的立项与实证（`#333`②／`#414` A3-2）—— 那是三次单独的改判，不是本包能顺手做的。
2. **(b) 解决不了本包的问题**。即便 `append-row` 拒了，破损行修复、机器人写入等路径仍会让编号落盘；线照样滞后。**堵入口治不了状态不一致，只有补写入才治得了。**
3. **(c) 的警告是噪音**。「未预留」这件事 release ③ 已经在拒了（且带三个豁免的精确判定）；在 `append-row` 侧再打一遍警告，等于把一条已有门禁的判据复制到第二处 —— 本文件已有前例（`#399` 的两份 README 解析）证明这类复制的代价是「两份同时漂移、且都不报错」。

> ⚠️ **(a) 的代价，写在这里不藏**：自愈会让「本该走 `--reserve` 却走了 `--number`」这个**用法错误**变得更没有痛感 —— 今天它至少还会让下一个人撞一次。⇒ 纪律仍由 release ③ 守（本包一个字不动它），(a) 只保证**状态**不再被这个用法错误破坏。两道分工写进 spec，避免日后有人以为本包退休了③。

### D2｜次序：先推线还是先写行

- **(a) 先推线、后写行（推荐）** —— 推线失败 ⇒ 拒绝，**零残留**（行未写）。
- (b) 先写行、后推线 —— 推线失败 ⇒ 行已落盘、线未动，正是本包要消灭的那个状态。

**推荐 (a)**。两个动作不在同一次原子写里（两次 `write_text`，且可能是两份不同的物理文件，见 §一.3），**必然存在一个失败会留下不一致的次序** —— 选哪个次序，就是选「哪一种不一致可以接受」：

| 次序 | 失败后的残留 | 协议怎么说 |
|---|---|---|
| (a) 先线后行 | 线已推、行未写 ＝ **一个空洞号** | 协议〇.8 明文允许（「编号永不复用，留空即可」） |
| (b) 先行后线 | 行已写、线未推 ＝ **计数器滞后** | 正是 `#505`／`#200`／`#233` 的病灶 |

⇒ (a) 的失败模式落在协议已经接受的那一类里，(b) 的失败模式落在协议正在治的那一类里。

**另**：(a) 顺带让 `append-row` 的拒绝语义保持一致 —— 该命令现有的每一处校验失败都明说「**未修改目标文件**」；把推线放在写行之前，这句话继续成立。

### D3｜推进口径：单调 还是 严格赋值

- **(a) 单调 `max(当前值, N)`（推荐）** —— `N ≤ 当前值` 时不动线、不报错。
- (b) 严格 `= N`。

**推荐 (a)**。`N ≤ 当前值` 是**合法且常见**的：走 `--reserve` 预留了 303、304 只用了 303（协议〇.8 允许留空洞）；补写一个此前预留未用的空洞号；`is_repair_of_existing` 路径重写一条 HEAD 里已有的行。(b) 在这些情形下会把线**往回拉**，等于亲手制造一次「线滞后于文件」—— 与本包目的相反。

(a) 的另一个性质：**幂等**。同一行重复 `append-row`（重试、脚本重入）不会让线漂移。

### D4｜适用面：是否覆盖非队列系统目标

- **(a) 只对队列系统目标生效（推荐）** —— `--file` 显式覆盖到别的文件时，沿用今日行为：不推线、不报错。
- (b) 一律推线，目标文件没有声明行就报错。

**推荐 (a)**，与 `cmd_acquire` 既有口径同源（`hwm_source = QUEUE_MECHANISM_PATH_REL if is_queue_system else args.file`，6012 行 —— 非队列目标读不到声明行时，`_read_high_water_mark` 返回 `None`，`acquire` 静默略过，不报错）。

(b) 会让**全部**用临时目录假文件跑的既有单测在 `append-row` 上当场失败 —— 那不是发现了缺陷，是本包给自己造了一片回归。

## 三、拟议实现（apply 阶段执行，本次不写码）

1. 从 `_reserve_ids` 抽出 `_advance_high_water_mark(target, section, new_value) -> int | None`：定位声明行 → 取分区号 → `max()` → 就地替换 → 写回；返回写回后的值，`None` 表示「目标无声明行、按 D4 略过」。声明行缺失／格式漂移在队列系统目标下 ⇒ **抛错（fail-loud）**，非队列目标 ⇒ 返回 `None`。
2. `_reserve_ids` 改为调用它（**行为不变**：预留侧的碰撞前置校验仍在 `_reserve_ids` 内、在调用之前）。
3. `cmd_append_row`：在域路由改写 `args.file` **之前**算出 `hwm_target`（同 `lock_anchor` 的取法）；在 §一/§四 且 `args.number` 为数字时，**于 `target_path.write_text` 之前**调用，失败即 `print("✗ …") ; return 1`（不写行）。§二 无编号列 ⇒ 不适用。
4. 单测两组 ＋ 反向对照，见 tasks.md §2。

2. **不改 release ③ 预留归属校验及其三个豁免口** —— 纪律面本包一个字不动（见 D1 的红字）。
3. **不把高水位线写入改成原子写** —— 现行 `_reserve_ids` 就是「读全文 → 替换 → `write_text` 覆写」，非原子；本包复用同一写法，风险面**持平、不放大**。若要治它，那是针对**全部**高水位线写入方的另一件事，应单独立行。

6. **不做两次实证的豁免口归因** —— 列为 apply 阶段取证任务（tasks §0.9），不在本文件下结论。
