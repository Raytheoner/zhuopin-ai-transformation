## 1. 实现 · 编辑锁侧（D1–D4，`0-学习与工具/工具-共享文档编辑锁.py`）

> ✅ **本节已于 2026-09-09 由 CC `OP-0908-X` 全部完成**（分支 `claude/op0908x-505-hwm-apply-a1e02f`）。前置 `#482` 已按他 2026-09-08 答 `1a／2a` 结案：其内容实测早在 master（逐行核验 `missing_in_master ＝ 0`），分支保持原样不 ff ⇒ 「先 `#482`、后本包」的定序按**内容口径**已满足。

- [x] 1.1 抽出 `_advance_high_water_mark(target, section, new_value) -> int`（⚠️ **实际签名无 `| None`**，理由见 1.3）：复用 `_reserve_ids` 的「定位声明行 → 取分区号 → 就地替换分区片段 → `write_text`」三步；**不复用**其碰撞前置校验（那是分配前的合法性判定，`append-row` 侧会把「补写空洞号」误拒 —— 判据见 design.md §一.2）。
- [x] 1.2 D3：`new = max(current, new_value)`；`new == current` 时**不写盘、不报错**，直接返回 `current`（幂等，且避免为一次无变化的写入触发 git 脏文件）。
- [x] 1.3 D4 —— ⚠️ **施工时按实测改判：判定落在调用方，不落在函数内部**（起草时写的是「函数内判队列系统与否、非队列返回 `None`」）。**改判成因（实测，不是推演）**：`_reserve_ids` 的既有单测**恰恰以非队列系统的临时文件跑 `--reserve`**，并断言「声明行缺失 ⇒ 拒绝预留」（`ReserveIdsTests::test_reserve_fails_loud_when_high_water_mark_line_missing`，子进程 `--file <临时路径>`）—— 把「非队列系统 ⇒ 静默返回 `None`」写进共用函数，会让这条既有 fail-loud 当场失效，等于用本包制造一个同族缺陷。⇒ **两个调用方的适用面本就不同**：`_reserve_ids` 恒 fail-loud；`cmd_append_row` 以 `hwm_target = None` 表达 D4（非队列系统目标根本不调用）。判据仍未合并成一个 `try/except`（起草的这一层意图被保住），只是分在两处调用点而非函数内部；理由写进了 `_advance_high_water_mark` 的 docstring 第四条。**副效果更贴 spec**：spec 写的是「`--file` 指向队列系统之外的文件时 MUST NOT **尝试**推进」——调用方拦截才是字面意义上的「不尝试」，函数内拦截在目标恰好含声明行时仍会推进它。
- [x] 1.4 `_reserve_ids` 改为调用 1.1 —— **行为必须一字不变**：碰撞前置校验仍在 `_reserve_ids` 内、位于调用之前；`new_value = reserved[-1]` 在预留侧恒大于 `current`，故 `max()` 对它是恒等变换。以既有单测零改动通过为证。
