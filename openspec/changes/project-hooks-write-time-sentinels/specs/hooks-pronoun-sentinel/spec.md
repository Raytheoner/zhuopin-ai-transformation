## ADDED Requirements

### Requirement: H4 SHALL 按人员名录正本核对跟进信中的第三人称代词
H4 SHALL 在 `PostToolUse`（matcher `Edit|Write`）触发；当写入目标命中
`6-人才与组织/部门AI专员跟进/*.md` 时，MUST 对**本次写入引入的内容**做第三人称代词一致性核对。

名录 MUST 从 `6-人才与组织/人员名录-称谓与性别-正本.md` 读取。
H4 MUST NOT 在脚本内硬编码任何人名或性别——硬编码即等于造出第二份名录。

违规时 MUST `exit 2`，并 MUST 逐条列出：**行号**、**该行里的人名**、**写成的代词**、**名录里的正确代词**。

#### Scenario: 名录内人物代词写反即拦
- **WHEN** 新增内容含「李姣龙……他已确认」，而名录记 `李姣龙（女）`
- **THEN** 退出码为 2，反馈中含该行号、`李姣龙`、`他`、`她`

#### Scenario: 代词正确则放行
- **WHEN** 新增内容含「唐燕萍……她已签认」，名录记 `唐燕萍（女）`
- **THEN** 放行

#### Scenario: 七个高危名字全覆盖
- **WHEN** 分别对 `祖怡`／`燕萍`／`映桦`／`植雅`／`易水`／`姣龙`／`国庆` 各构造一条写反的句子
- **THEN** 七条全部判违规

### Requirement: H4 SHALL 宁可漏报也不误报
指向不明确时 H4 MUST 放行。

判定 MUST 限于「同一段落内出现名录人名，且其后最近的第三人称代词与名录不符」这一形态。
同一段落内出现**多个**不同性别的名录人名时，其后代词的归属 MUST 视为不明确并放行。

段落中出现的非名录人物（客户、OEM 对接人、其他部门同事）MUST NOT 触发判定。

#### Scenario: 一段里两个不同性别的人名则不判
- **WHEN** 同一段落先后出现 `姚祖怡（男）` 与 `陈忱（女）`，其后有一个「他」
- **THEN** 放行（归属不明确）

#### Scenario: 名录外人物不触发
- **WHEN** 新增内容含「客户对接人……他表示」，该人名不在名录内
- **THEN** 放行

### Requirement: H4 SHALL 不触碰历史记录
块引用（`>` 开头）、代码块（``` 围栏内）以及带 `代词豁免：<理由>` 标记的行 MUST NOT 判违规——
根 `CLAUDE.md` 已定「历史记录不追改」，引用旧信原文时里面的旧代词就该保持原样。

#### Scenario: 引用旧信原文不判违规
- **WHEN** 新增内容在块引用里原样贴出一段含错误代词的旧信文字
- **THEN** 放行

#### Scenario: 同样的句子写在正文里仍判违规
- **WHEN** 同一句话不在块引用内、也无豁免标记
- **THEN** 退出码为 2

### Requirement: 名录正本缺失 SHALL 报「无法核验」而非「无违规」
名录正本文件不存在、读取失败或解析出 0 个人物时，H4 MUST 放行，
且 MUST 在心跳与 stderr 中明写「🔴 本类无法核验：<原因>」。

H4 MUST NOT 在该情形下输出「未发现违规」一类结论——**没有名录时它没有任何结论可用**。

#### Scenario: 名录缺失时明说无法核验
- **WHEN** `6-人才与组织/人员名录-称谓与性别-正本.md` 不存在
- **THEN** 退出码为 0，且输出含「本类无法核验」，不含「未发现违规」

#### Scenario: 名录解析出 0 人时同样无法核验
- **WHEN** 名录文件存在但解析出 0 个人物
- **THEN** 输出含「本类无法核验」
