## Why

### 一句话

**现有守卫全部守在「落库时」与「CI 时」，而本项目最贵的三类错误里有两类在「写入时」就已经不可逆或已污染下游——把发现时点从收工提前到当场，是这一包唯一要买的东西。**

### 现状：仓内已有的机器守都在下游

| 既有守卫 | 守在哪个时点 | 漏在哪 |
|---|---|---|
| 落库 sweep（7 项检查） | commit 时 | 一轮之内写进去的东西，本轮之前无人看 |
| `工具-队列结构lint.py` / `工具-CLAUDE进度段lint.py` | CI 时 | 更晚，且 CI 整体长期红（#398 ⑶），信号已被稀释 |
| 编辑锁 `release` 十条结构校验 | release 时 | **只覆盖队列文件**，跟进信、场景 `CLAUDE.md`、报告类产出不经它 |
| 跟进信 skill 起草期自检 | 起草时 | **靠模型记得做**——历史已证明"读到规则 ≠ 执行规则"（根 `CLAUDE.md` §1 原话） |

### 两类错误为什么必须在写入时拦

**H3 乱码**——写入端 UTF-8 损坏时**路径与内容同现 U+FFFD**（2026-07-04 11:42 QD-A 事故：每个汉字变 2 个 U+FFFD，并催生了「乱码文件夹哨兵」这条开工/收工各查一次的人守规则）；2026-08-19 又出现两处 `D:\airead` 被写成 BEL 控制字符。
**污染是即时且向下游扩散的**：坏字节一旦落盘，此后每一次读该文件的会话都拿到坏内容，而 `git status`、测试、CI 全都不会因此变红。收工时才发现，中间所有基于它的产出都要复查。

**H4 代词**——跟进信是**对外发送**物。`财务部#14` 因 `姣龙` 被写成「他」而向专员做出错误称谓，**信发出撤不回**（事故全文存档见 CHANGELOG 附录 F）；涉姚祖怡一行累计写错 244 处。
根 `CLAUDE.md` §1 已写明真正的落点是「**起草完成后扫一遍全文第三人称代词，逐个回名录核对**」——**这句话现在 100% 靠模型自觉**。而它的判别特征正是本项目反复吃亏那一族：**能从字面猜出来、且猜错了不会当场报错**。

### 为什么是 hooks，而不是再加一条 lint

`queue-lint-appellation-guard`（称呼判据）已经证明 CI lint 这条路可行——**但它守的是队列文件，而跟进信的致命时刻在「发出去之前」**。
两者分工，本包不与它重叠：**它拦 `Paul` 这个字面量，本包拦第三人称代词与名录不符**；**它在 CI，本包在写入时**。

## What Changes

### 新增：公共框架（`0-学习与工具/hooks/`）

一个共用的 PowerShell 前置层，所有项目级哨兵复用：

- **stdin JSON → 解析出「本次真正的写入目标路径」与「本次写入的内容」**；
- 🔴 **禁止对原始命令串做正则**（见下方「P0 探针带来的三条硬约束」第 ③ 条）；
- **fail-open**：任何异常一律 `exit 0` 放行（`try{...}catch{exit 0}`），并把异常本身写进 `audit-hooks` 日志——**哨兵故障绝不阻塞正常工作，但也绝不静默**；
- **timeout 10s**（与既有 `pretooluse-guard` 同规格）；
- **拦截留痕**：每次拦截落 `~/.claude/audit-blocks-<date>.log`（复用既有格式，不新造日志形态）；
- 🔴 **自证在岗（`heartbeat`）**：每次运行——**含放行**——落一条心跳；配套一条「最近 N 天零心跳即告警」的检查（承接方见 tasks §5）。**这一条不是锦上添花，是本包的准入条件**，理由见 design 决策点 1。

### 新增：H3 乱码哨兵（PostToolUse `Edit|Write`）

写入目标是 `.md`／`.py`／`.ps1` 且**本次新增内容**含 U+FFFD 或 BEL 类控制字符 ⇒ `exit 2`，把违例行号与坏字节位置反馈给模型当场修。

### 新增：H4 代词哨兵（PostToolUse `Edit|Write`）

写入目标命中 `6-人才与组织/部门AI专员跟进/*.md` ⇒ 对**全文**做第三人称代词与人员名录的一致性核对，违例即 `exit 2` 并逐条列出行号。

### 修改：项目 `.claude/settings.json`

新增 `PostToolUse` 挂接（两个哨兵各一条 matcher）。
🔴 **该文件命中 `~/.claude/protected-paths.json` 的 `*/.claude/settings.json`（`mode: block`）⇒ 这一步必须由 Shao Peishen 人工执行**，与 #398 留步 1 完全同形。**不绕**（绕过一次，这条守卫此后就不再是守卫）。tasks 里已把它列为独立的、带人工前置的一步，并建议与 #398 那份至今未装的心跳钩子**并成一次动作**。

### BREAKING

**是。** `Edit`/`Write` 在两类输入下由必然成功变为被拒：① 写入内容含 U+FFFD/BEL；② 跟进信正文代词与名录不符。存量文件不受影响（只判本次写入）。

## 🔑 P0 探针带来的三条硬约束（不是背景，是必须落进实现的条款）

**①「仅 CC」是如实的收益面，不是失败。**
P0-1 实测坐实：Cowork 的本地代理模式给每个会话一份**独立沙箱 `HOME`**（MSIX 容器内 `local-agent-mode-sessions\...\local_<uuid>\.claude`，实测 295 份，其中含 `settings.json` 的仅 2 份且各 3 字节＝`{}`，容器内 `audit-*.log` 数 ＝ **0**）⇒ **全局 hooks 对 Cowork 一条都不生效**。
**项目级** hooks 对 Cowork 是否生效**本棒未测**（须先部署才能测，属本包红线外）——按 Shao Peishen 答 **3(a)**：**design 按「仅 CC」写**，并把这一问列为 apply 后的第一个验收动作（10 分钟）。**不得因未测就写成"两桌均可"。**

**② 项目 `settings.json` 会因「工作区未信任」被静默忽略——这是本包最大的单点风险。**
实测：`C:\Users\Paul Shao\.claude.json` 里同一目录有**两条斜杠方向不同、结论相反**的信任记录（`C:\Dev\zhuopin-ai` ＝ True，`C:/Dev/zhuopin-ai` ＝ **False**）；命中后者时命令行原样吐出 `Ignoring 7 permissions.allow entries from .claude/settings.json: this workspace has not been trusted.`
⇒ **配置放在这个文件里，就有一条"哨兵不响、不报错、一切正常"的路径。** 这正是 OP-0819-F「机制建成 9 天、每天在跑、却从来没真正发出过一条消息」的复发条件。
**对策已写进 What Changes 的「自证在岗」，并作为 design 决策点 1 单独论证。**

**③ 判据必须作用在「解析出的写入目标 ＋ 内容 diff」上，禁止对原始命令串做正则。**
实测：本班写 P0 探针报告时被 `pretooluse-guard` 拦下——**拦的不是写入目标**（目标是 `1-转型规划/…/构建环境P0探针报告-2026-08-28.md`，与 patterns 毫无关系），**而是 heredoc 正文里出现的 `~/.claude/hooks/` 字样**。
⇒ **把「谈论某事」误判成「做某事」**。三个哨兵一律不得重蹈；本条已写成公共框架的规范条款并配反例场景。

## 本次退休哪一个既有守卫（强制，协议〇.9 措施 B）

**退休：根 `CLAUDE.md` §5「乱码文件夹哨兵」条中的「开工与收工各查一次上级目录」这半条人守动作，降为一行指针。**

- **可退的理由**：那半条要求的是**人（或模型）每次开工/收工记得跑一次目录扫描**，而它要防的根因——「写入端 UTF-8 损坏时路径与内容同现 U+FFFD」——**H3 在写入当刻就拦住了**，且拦得更早、更准（按内容判，不按目录名猜）。
- **不退的部分**：同条里「出现乱码兄弟目录即停手、按既例隔离、不直删」的**处置流程**保留原样——那是事后处置，H3 不覆盖。
- **净变化**：人守条目 **−1**，机制守条目 **+2**（H3／H4）。
- 🔴 **顺序不可反（沿用 #381 硬约束）**：**先机制在生产真实验活（至少真实拦下一次并留痕），后降指针。** 本包 apply 完成 **≠** 可以降指针；降指针是 tasks 里单独的、带前置条件的一步。

**为什么没有为 H4 也配一条退休**：H4 承接的是根 `CLAUDE.md` §1 的代词自检句，而该条同时承载「为什么必须以名录为准」的成因与硬事实名录本身，**按规则退休制「正文可降为一行指针、不必删」处理，不构成一条可退的守卫**。反向核实过一次「有没有别的可退守卫」：`工具-队列结构lint.py` 现有四项判据没有一项能被 H3/H4 覆盖，硬凑一个来退等于为满足格式削掉一道真在用的网（同 `queue-lint-appellation-guard` 的既有论证）。

## 伴生文件的 .gitignore 覆盖（强制）

本变更**会新增一种此前不存在的自动生成文件形态**：公共框架的心跳文件。

- 形态：`reports/hooks-heartbeat.json`（**单文件、定名、覆盖写**，刻意不按日期/会话分片——分片会造出无限增长的文件形态，正是 #322 `*.editlock.mutex.stale` 的坑）。
- 实测（非推断）：

```bash
git check-ignore -v reports/hooks-heartbeat.json
# ⇒ .gitignore:35:**/reports/	reports/hooks-heartbeat.json     退出码 0（已被覆盖）
```

  本仓 `.gitignore` 第 35 行 `**/reports/` 已整目录忽略，故新形态**开箱即被覆盖**，不会被 `git status` 报为未跟踪、不会被 sweep 判为孤儿。
  🔴 **tasks 里仍要求 apply 时把这条 `git check-ignore` 实跑一次并把输出贴进收工报告**——上面这条是本棒基于现行 `.gitignore` 的实测，但 apply 可能发生在若干天后，`.gitignore` 届时可能已变。

- **拦截留痕不新增形态**：复用既有 `~/.claude/audit-blocks-<date>.log`（仓库外，不入 git）。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

**⑴ 本流程哪些判断是人脑默会经验？**

- **代词判定的默会部分**：哪些句子里的「他/她」指的是**收信专员本人**，哪些指的是信里提到的第三方（客户、OEM 对接人、其他部门同事）。名录只能判定「这个人的正确代词是什么」，**判不了「这个代词指的是谁」**——后者是全文语境判断。
  规则/阈值/例外：① 名录内 21 人的性别为硬事实（不可推断）；② 名录外人物一律中性称谓（「该专员／其／对方」）；③ 引用历史记录、已发出的旧信原文时**不追改**（例外）。
- **乱码判定几乎没有默会成分**（U+FFFD 与 BEL 是字节级事实），故 H3 的三问以 H4 为主。

**⑵ 由谁显性化？（持有人 ＋ backup 双人制，实名）**

- 持有人：**Shao Peishen**（人员名录与称谓纪律的唯一权威，硬事实的最终裁定人）。
- Backup：**唐燕萍**（财务总监兼财务域 AI 专员）——财务部六人全部为女性这一条即由她所在域给出；她对本域称谓的圈定即权威签认（根 `CLAUDE.md` §1 已明写此点）。
- 名录正本载体：`6-人才与组织/人员名录-称谓与性别-正本.md`（由并行的 `OP-0828-Q` 棒新建）。🔴 **H4 MUST 从该正本读取，MUST NOT 在脚本里硬编码任何人名与性别**——硬编码会造出第二份名录，与「唯一权威载体」直接冲突。

**⑶ 用什么方法提取？**

**历史案例反推**（三选一）。语料现成且量足：`财务部#14` 的 `姣龙` 事故、涉姚祖怡的 244 处、根 `CLAUDE.md` §1 点名的 7 个「会把语言直觉带偏」的名字（`祖怡`／`燕萍`／`映桦`／`植雅`／`易水`／`姣龙`／`国庆`）。
**这 7 个名字直接构成 H4 的黄金测试集**——判据若对它们全对，就已经覆盖了历史上全部已知翻车形态。

## 验收与晋档条件（强制，四档口径）

**本变更包交付后所处档位：档 3（内部服务）。**
理由：哨兵服务于内部构建流程，不产出对客交付物，也不涉真实业务数据；但它**真实运行在生产工作区**（不是 mock），故不是档 1／档 2。

**晋下一档（档 4 对客交付）的条件**：**不适用，且本包永不晋档 4。** 哨兵是内部构建环境设施，无对客交付形态。此项写「不适用」而非留空。

**本档验收条件（逐条，全部可机器核）**：

1. `openspec validate --strict` 绿；
2. 单测覆盖三个 spec 的全部 Scenario，**含反例**：① 正文提到受保护路径**不得**被误判（对应硬约束③）；② 引用旧信原文里的代词**不得**被 H4 判违规；③ 哨兵脚本抛异常时 **MUST 放行**（fail-open）且心跳仍落盘；
3. **真实拦下一次**：H3 与 H4 各在生产工作区真实拦截一次并留痕（`audit-blocks` 有记录）——🔴 **「测试通过」不算，OP-0819-F 的教训是「探针通了 ≠ 机制通了」**；
4. **自证在岗可验**：手工把 `.claude/settings.json` 的挂接改坏一次，「零心跳告警」必须在约定窗口内响；改回后自动解除；
5. **P0-1 未答那半问已补答**：Shao Peishen 在 Cowork 做一次受控 Edit，书面记录哨兵有无触发，结论回写 design。

**价值指标（业务 Champion ＝ Shao Peishen 确认基线）**：

- **风险型（主）**：H3／H4 对应的两类错误**复发数 ＝ 0**。基线＝乱码 2 起（2026-07-04、2026-08-19）、代词 ≥6 次（其中 1 次已发出不可撤回）。
- **质量型（辅）**：误拦率 **≤1 次/周**（沿用方案 §八 第 5 条口径；H1 正是因为过不了这条而出 scope）。
- **不设工时型指标**：这两类错误的成本是"发出去撤不回"和"下游全部复查"，用工时衡量会低估。
