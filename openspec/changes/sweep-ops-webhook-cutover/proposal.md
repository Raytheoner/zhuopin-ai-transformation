# sweep-ops-webhook-cutover Proposal

> 归属：队列 §一 `#282` 的 **⑴ 包第一个动作**（Shao Peishen 2026-08-19 对 §四 `#73` 答 (c)）。
> **不新取号、不增机制类可动 WIP**（当日 24/24 已满）。派单件＝`1-转型规划/0-全景路线图/开场prompt-CC-282止血并入包一-队列四73-2026-08-19.md`（OP-0819-G）。
> 类别：**机制/环境类变更包**（守护本仓库流程/工具自身），故受 `openspec/config.yaml` 两条 MANDATORY 约束，见下文 §守卫退休问答 与 §伴生文件问答。

## Why（为什么做）

**一句话**：`工具-落库sweep.py` 的机制类告警此刻仍在发进**采购内部工作群**，与 `#282` 拍板「业务部门此后不从任何 webhook 收消息」直接抵触；本变更把它的去向键切到已验通的运维群 `WECOM_WEBHOOK_URL_OPS`，止住一件**每天都在发生**的事。

**这不是潜在风险，是已发生 58 次的既成事实**（`reports/sweep-commit.log` 宽口径统计，08-12 起按日 10／4／1／4／6／2）。其中 2026-08-19 `07:37Z` 那条告警的**正文是一段 Python traceback**（`CalledProcessError: git add … exit 128`）——一段 git 调用栈落在业务同事的工作群里，正是 `#282` 要消灭的那件事的具体形态。

**为什么现在能做、而此前不能**：本项此前唯一的否决理由是「`_OPS` 无效（`93000`），先改 sweep 等于把『发错人』换成『一条都不发』」。该理由已于 2026-08-19 死亡——运维群 webhook URL 第三值不仅通过残缺 payload 探针（`44004`，§四 `#67`），**且已在 `.51` 真发出过一条完整消息**（企微 `errcode=0`，§四 `#72`）。⇒ `_OPS` 不只是「地址合法」，是「真能收到消息」。

**架构依据**：`3-治理与合规/通知通道架构决策件-webhook退役与aibot单一出口-2026-08-06.md` §4.2 已给出可机械化判据——**消息主题是「某个自动化机制自己出问题了」→ 走 webhook 运维群；主题是业务内容 → 走 aibot**。sweep 的 15 类告警（分叉、孤儿脏文件、部署留痕提示、定时任务镜像差异、未预期异常……）**全部属于前者**，本变更即把 sweep 这一行落到 §四 通道矩阵的目标态。

### 守卫退休问答（MANDATORY · 协议〇.9 措施 B / one-in-one-out）

**本次退休一条既有的「人守」约定，且不新增任何守卫代码。**

**退休对象**：`3-治理与合规/通知通道架构决策件-webhook退役与aibot单一出口-2026-08-06.md` §5.1 的处置约定——「新运维群的 webhook URL 填入 `.env` 的 `WECOM_WEBHOOK_URL`，**替换现值**」（该节表格「逃生通道／要什么」格原文）。

**为什么必须退休它，而不是放着不管**：这条约定**今天照做就会造成伤害**。它写于 2026-08-06，当时的隐含前提是「读裸键的都是该搬走的机制告警」；而 2026-08-19 §四 `#73` 的边界核查证伪了这个前提——全库读裸 `WECOM_WEBHOOK_URL` 的还有 `0-学习与工具/发企微.py`，那是「Cowork 写正文、CC 一句话发企微」的**业务内容**通道，收信人本就该是采购内部工作群。**若按 §5.1 原方案替换裸键的值，业务简报会连同机制告警一起被搬进只有两个人的运维群** —— 那是反向错误，比现状更糟。⇒ 现实中已改走「新增 `_OPS` 键、按用途分流」的路线（FI2 `30d1736` 已是先例），§5.1 那条约定已被事实取代但**从未被显式作废**，是一条仍在文档里、仍会被下一个读者照做的失效指令。本变更负责作废它并写明取代关系。

**为什么不新增守卫代码**：本变更的正确形态是**结构性消除**而非**新增检查**——把 12 处硬编码的键名字面量改为从唯一常量 `WECOM_WEBHOOK_ENV_KEY` 派生（详见 What Changes ②）。副本消失之后，「日志说的键名和实际读的键名不一致」这个错误在结构上不再可能发生，**因而不需要一条守卫去检查它**。这与 `#308` 子项 G「把人守动作挪进既有咽喉、不新增守卫」是同一取向。

### 伴生文件的 .gitignore 覆盖问答（MANDATORY · 队列 #328 子项②）

**不适用：本变更不新增任何自动生成的文件名形态。** 本变更只改动 `工具-落库sweep.py` 内的一个常量与若干日志文案字符串，不新增锁文件、快照、状态文件、日志文件、重命名退路产物或备份副本。sweep 既有的状态文件（`reports/sweep-fork-state.json` 等）与运行日志（`reports/sweep-commit.log`）**文件名形态一字未变**，其忽略规则沿用现状、不受影响。

## What Changes（改什么）

**① 功能侧 1 处** —— `0-学习与工具/工具-落库sweep.py` **L437** 常量：

`WECOM_WEBHOOK_ENV_KEY` 由 `"WECOM_WEBHOOK_URL"` 改为 `"WECOM_WEBHOOK_URL_OPS"`。

**10 处调用点一处都不用碰**（L992／L1010／L1112／L1153／L1179／L1772／L1796／L1842／L2057／L2707），全部经同一个 loader `_load_webhook_url(repo_root)`（L1041）取值。**本清单已由本变更包作者独立复核，与 §四 `#73` 记载逐行一致**（复核方式与结果见 `design.md` §零）。

**② 文案侧 12 处**（11 处日志文案 ＋ 1 处 docstring）—— 同一批改掉键名字面量副本：

L994／L1012／L1042(docstring)／L1114／L1155／L1181／L1774／L1798／L1844／L2062／L2073／L2709 把 `WECOM_WEBHOOK_URL` 写成了**字面量**。只改 ① 会让日志说「未在 .env 找到 `WECOM_WEBHOOK_URL`」而实际找的是 `_OPS`——不影响功能，但会误导日后排查。**改法不是把字面量换成另一个字面量**（那只是把 12 份副本换成新的 12 份），而是改为从常量派生（日志文案用 f-string 引用 `WECOM_WEBHOOK_ENV_KEY`；docstring 不能是 f-string——那会使 `__doc__` 变 None——故改为**命名该常量**而非复制其值，同样达成副本归零），使副本数由 12 归零。

🔑 这是本项目反复记录的「同一事实的两份副本，改一处漏另一处」（README 编号段三次复发、`#345` 的 35 份手抄副本）在**日志键名字面量**上的又一例；本次选择根治而非并行维护。

**③ 明确不回退裸键（语义硬约束，配单测）** —— `_OPS` 缺失时 `_load_webhook_url` 返回 `None`，各调用点既有分支即「跳过该条告警、只留痕日志」，**MUST NOT 回退到裸 `WECOM_WEBHOOK_URL`**。静默回退正是把告警发回业务群的那条路径。照 FI2 `resolve_alert_webhook()` 同款语义（`4-数字员工/财务部/FI2-三单匹配自动对账/scripts/scan_tax_export_scheduled.py:81`，commit `30d1736`），并比照其三个单测补齐 sweep 侧对应用例。

**④ 告警取不到去向不得影响 sweep 退出码** —— 沿用既有语义，不改；`specs/sweep-fork-alert` 已有等价 requirement，本变更把它从「分叉告警专属」上升为「sweep 全部机制告警通用」并显式登记（见 delta spec）。

**⑤ 作废架构决策件 §5.1 的替换约定**（见上 §守卫退休问答），在该文件内就地标注取代关系，不删原文（历史记录不追改）。

**⑥ `alert_webhook.py` 的处置** —— 属 `#282` ⑴ 包同范围，本包是否同批做交 design 决策点 4 定，**不擅自扩范围**。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

1. **本流程哪些判断是人脑默会经验？**
   - **「哪些消息该走运维群、哪些该留在业务群」这条分流判据**：现已由架构决策件 §4.2 显性化为可机械执行的一句话——**主题是「某自动化机制自己出问题了」→ 运维群；主题是业务内容 → 业务群**。此前它只存在于 Shao Peishen 与经手 session 的判断里，本变更是它第一次落到代码常量上。
   - **「哪些读裸键的调用点该改、哪些绝不能改」**：仍带默会成分——判据是「该调用点承载的是机制自陈还是业务内容」，而这需要读懂每个调用点在做什么。已在 §四 `#73` 与本包 `design.md` §三 逐个点名固化（sweep 改／`发企微.py` 绝不改／aibot-service 五入口另属一事／SC8 `run_baoguan_web.py` 属 SC8 自有兜底），**例外清单本身即是本次显性化的产物**。
   - **阈值/尺度类**：本变更无阈值。
2. **由谁显性化？** 持有人 **Shao Peishen**（分流判据的决策人，架构决策件 §4.2 出自其 2026-08-06 拍板）；backup **陈承**（IT，运维群另一名成员，是该通道的实际共同受众）。本变更不新增需登记进《跨场景前置数据与知识库任务总表》§一.2 的知识资产条目——判据已在架构决策件内成文，本包只是把它落地到一处代码。
3. **用什么方法提取？** **历史案例反推**——依据是 `reports/sweep-commit.log` 全量 58 条真实已发告警的分类统计（15 种告警类型，最多为孤儿脏文件 12 次、分叉告警合计 21 次、定时任务镜像差异 6 次），逐类比对 §4.2 判据，**结论是 15 类全部落在「机制自陈」一侧、无一条属业务内容**，故本次可整体切换而不需按告警类型分流。

## 验收与晋档条件（强制，四档口径）

- **本变更包交付后场景所处档位**：**档 2（真实数据跑通）**。本变更的验收判据本身就是真实企微投递——mock 层面证明不了「消息到了哪个群」，而这恰是本变更的全部目的。
- **晋下一档的条件**（本包不追求晋档 3，以下为如实登记的前提差距）：
  1. **正判据**：真实触发一条 sweep 机制告警，确认它**进的是运维群**（Shao Peishen ＋ 陈承二人群）。
  2. **负判据（止血是否成功的真正判据）**：确认**采购内部工作群不再收到**同一条告警。⚠️ 仅验证 1 不足以收口——它只证明「多了一个收件人」，不证明「少了一个」。
  3. **前置**：验收 MUST 在**主工作区**执行。本 worktree 的 `.env` 持有的是 `_OPS` **第一版无效值**（详见 `design.md` 决策点 7），在此处跑会得到 `93000` 并误判为代码缺陷。
  4. 全量回归零漂移；`openspec validate --all --strict` 全绿。
- **价值指标**（风险型）：
  - **基线（已实测，非估计）**：业务部门群累计收到机制类告警 **58 条**，其中 2026-08-19 当天 2 条。
  - **目标值**：本变更生效后，业务部门群新增机制类告警 **= 0 条**。
  - **量法**：`reports/sweep-commit.log` 按既有宽口径（行首 ✓ 且含「已推送」）统计，切换日之后的增量。⚠️ **口径须写死为宽口径**——初次统计用只匹配「告警已推送」「通知已推送」两种措辞的 grep 只数到 57，漏掉了「常驻服务部署提示已推送」这一类，**同一份日志两种数法差一条**。
  - **基线确认人**：Shao Peishen（本项目内该通道的业务 Champion 即其本人，非部门专员）。
- **LLM 判据黄金集**：**不适用**。本变更不含任何 LLM 运行时判断，全部为确定性的环境变量读取与字符串输出。

**受影响代码**：`0-学习与工具/工具-落库sweep.py`（1 处常量 ＋ 12 处文案）、`0-学习与工具/test_工具-落库sweep.py`（新增用例）、`3-治理与合规/通知通道架构决策件-webhook退役与aibot单一出口-2026-08-06.md`（§5.1 标注取代关系）。`5-平台底座/wecom-aibot-service/scripts/alert_webhook.py` 是否纳入见 design 决策点 4。

**明确不受影响、且刻意不动的**（防止改动时误伤，逐个点名）：
- `0-学习与工具/发企微.py` —— **业务内容**通道，收信人本就该是采购内部工作群，**改它是反向错误**。

- `5-平台底座/wecom-aibot-service/scripts/` 五个入口 —— 读的是 `5-平台底座/.env` 的裸键，而**该键实测值长为 0**（已复核，见 `design.md` §四），它们本就一条都发不出去，与本项不是同一件事。

**红线核对**：
- **mock 先行**：不适用于「消息发到哪个群」这一判据本身（mock 恒为真），单测层用注入的假 env 覆盖分流逻辑，真实投递按档 2 验收。

- **ISO 26262**：不涉及——非安全相关代码。
- **凭据纪律**：本包全部产出**不含任何 URL 值**，只用 key 参数的 SHA256 前 8 位指纹标识。`.env` 已由 `.gitignore` 覆盖（既有事实，本变更未改动忽略规则）。
