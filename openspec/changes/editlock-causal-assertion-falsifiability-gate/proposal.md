# editlock-causal-assertion-falsifiability-gate Proposal

## Why

CLAUDE.md §5「规则退休制」规定：同一条"人守"规则被违反 3 次即须机制化或删除。"下因果断言前先问有没有一个没核的变量能同样解释"这条人守规则（曾写于环境保障线 opener 的"反面清单·防线 4"）已达 **3/3** 阈值——三次证伪分别靠 `schannel` 计数／`git patch-id --stable`／`git ls-tree` 三条命令，且后两次都不是断言者自己跑的。队列 #285（第 ③ 条计数与三次实例见 #284）记录了完整取证与三选一讨论，**Shao Peishen 2026-08-07 已拍板选 (a)**：收窄适用面 + 挂编辑锁 `release` 校验④延伸，同批把该人守条目正文降为一行指针。本变更只是把已拍板的决定落地为代码，不重开设计讨论。

## What Changes

- **编辑锁 `_validate_release_structure` ④断言门槛延伸**：§一 状态列（cells[5]，剔除「」/『』引号包裹片段后，复用 #248 既有的 `_strip_quoted_spans`）一旦出现 P0/P1 定级 token，MUST 在同一单元格内找到至少一个反引号 `` ` `` 包裹的命令片段（视为"如果我错了，哪一条命令会证明我错"的证伪命令）；缺失即拒绝 release 并提示。**不新增任何扫描面**——沿用既有的"只查状态列"边界与 #248 的引号剔除逻辑。
- **降级"防线4"正文为一行指针**：该人守条目此前的完整段落（换一种系统行为下是否仍成立／不信工具或人说成功／质疑自己刚下的判据／因果断言先问未核变量／凡涉数量先 grep）中，第 4 条（因果断言）改写为指向本机制的一行指针，不再复述判据本身。
- **BREAKING**：无——新增校验只对本次持锁期间新增/修改的 §一 行生效，历史行不追溯（既有校验①-⑨的一贯范式）。

## Capabilities

### Modified Capabilities

- `editlock-assertion-gate-scope`：④断言门槛新增一条独立 Requirement——P0/P1 定级行的状态列须含反引号包裹的证伪命令片段，缺失即拒绝release。既有三条 Requirement（引号剔除、仅状态列边界、历史兼容性）不变，新增校验与它们正交（同一状态列可能同时触发"未核实字样"与"缺证伪命令"两类拒绝，互不影响判定逻辑）。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

1. **本流程哪些判断是人脑默会经验？** "写因果断言前有没有先想过其它解释、能不能证伪"此前完全是执笔者脑内的一个隐性检查步骤——本变更把它从"态度要求"（不可检查）转成"产出物要求"（能否在状态列里指出一条反引号命令，可检查）。
2. **由谁显性化？** 持有人：**Shao Peishen**（三选一拍板人，已选 (a)，理由与代价见队列 #285 与 `环境保障线-三行机制方案定稿-285规则退休-267签字材料-203前提复检-2026-08-07.md` §一）；backup：**Claude Code**（本变更的代码落地与后续任何接手 session，判断依据均已record在案，无需重新论证）。
3. **用什么方法提取？** **历史案例反推**——三次真实事故（详见 #284 第 ③ 条）的共同结构是"从过程痕迹推断当前状态，而当前状态本可直接查一条命令"，判据设计直接来自这一复盘，非预先设计。不涉及 LLM 判断。

## 本次退休哪一个既有守卫；若不能退，写明为何不能

本变更**不退休任何既有守卫**——它是把一条此前完全没有守卫（纯人守、写在某份 opener 的"反面清单"里）的规则**首次机制化**，不存在"替换掉哪个旧守卫"的问题。按 `openspec/config.yaml` 措施 B 的问询要求如实回答：本次新增机制类校验，无可退休对象；判断依据同"档1-4 晋档口径"惯例，由本 proposal 自评、design 审核实（本变更决策已在队列 #285 完成实质性审议，design.md 仅做落地记录，不重开审）。

## 验收与晋档条件（强制，四档口径）

- **本变更包交付后场景所处档位**：跨项目治理机制（编辑锁是全项目共用的写入咽喉），非独立业务场景，不套用四档"对客交付"口径；近似映射＝**档1 mock 验证**（design 记录完成、代码与单测完成，尚未经过至少一次真实生产队列行触发该校验的端到端观察）。
- **晋下一档的条件**（晋档2 真实数据跑通）：① 全部 6 项既有 ①-⑨ 校验回归零漂移；② 至少一次真实 §一 行在 release 时因缺证伪命令被本校验拒绝（真实拦截而非单测模拟）；③ 至少一次真实新增 P0/P1 定级行、含证伪命令、正常通过 release。
- **价值指标**（风险型）：本条只判"有没有"、判不了"对不对"——按拍板文原话覆盖 2/3（防住"根本没想过怎么证伪"），防不住"想过但用了错的证据"（1/3，#221 那种）。基线＝人守规则 3/3 违反率；目标＝此后同族违反因结构性拦截而无法进入 release，人守条目正文降为指针不再重复出现在新 opener 里。
- **LLM 判据黄金集**：不适用（纯字符串/正则匹配，不含 LLM 运行时判断）。
