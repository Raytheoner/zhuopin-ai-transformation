# sweep-commit-message-extraction Proposal

> 起因＝队列 §一 `#398` 第 ⑹ 处（2026-09-06 实测坐实，非推演）。Shao Peishen 2026-09-06 答 (a)：立项修提取逻辑，走 openspec propose + design，design 审后再 apply。

## Why（为什么做）

`0-学习与工具/工具-落库sweep.py::_extract_commit_message`（2437-2439 行）把 §二「建议 message」格里**第一个反引号跨度**当作整条 commit 信息：

```python
def _extract_commit_message(message_cell: str) -> str:
    match = re.search(r"`([^`]+)`", message_cell)
    return match.group(1) if match else message_cell.strip()
```

于是只要 message 正文里先出现了任何一段行内代码（路径、文件名、commit 号——本项目几乎必然会写），提交信息就被**静默截断**到那一小段。

🔴 **失败形态是「成功」**：`git commit` 返回 0、sweep 不打任何告警、批次照常销行标 ✅，唯一的受害者是 git log 的可追溯性（IATF 16949 要求 AI 辅助决策全程可追溯），而那正是没人会当场去看的地方。**2026-09-06 本次亲历**：批次 `B-0906_SC7env` 的信息被截成字面量 `.env`（master 上的 commit `1d234dd`）。

**存量已扫**：`git log --since=2026-06-01` 里至少 **11 条** commit 呈同一指纹（整条信息就是一个孤立的路径/文件名/短标签）：`.env`／`.gitignore`／`CLAUDE.md`／`.51`×2／`采购部#13`／`IT部#7`／`OP-0901-D`／`c6d6274`／`决策点:`／`登记豁免:`。指纹不明显的（首个跨度恰好包着一段像句子的内容）不可肉眼分辨，真实数量只会更多。

🔑 **判据取证（本变更包的设计依据，非推演）**：扫 2026-08-01 以来该队列文件全部 745 个 commit 的历史版本，去重后得 357 个 §二 message 格，形态分布是——

| 形态 | 条数 | 现行提取结果 |
|---|---|---|
| 整格无反引号（整格即信息） | **335（94%）** | ✅ 正确（走 `else` 分支） |
| A：整格恰好被一对反引号包住 | 15（4%） | ✅ 正确 |
| C：反引号出现在正文中间 | **7（2%）** | ❌ **必被截断** |
| B：起首是跨度、其后另有说明文字 | **0** | —— |

⇒ **现行判据把 4% 的写法当成了唯一约定，代价是 2% 被静默损坏，而 94% 只是碰巧走对了 `else` 分支。** 且形态 B 在历史上**一条都不存在**——这一点决定了修法可以安全地"整格即信息"，不会伤到"信息＋尾注"的写法（它不存在）。

## What Changes（改什么）

- **改** `工具-落库sweep.py::_extract_commit_message` 的语义为「**整格即信息，仅剥去一层完全包裹的反引号**」，三条规则、无歧义、**不可能截断**：
  1. 整格 trim 后**恰好**是一个完全包裹的反引号跨度（首尾为反引号且全格仅两个反引号）⇒ 剥去该层，内部文本即信息（保住形态 A 的 15 条）。
  2. 否则 ⇒ **整格 trim 后的原文**即信息，内部反引号原样保留为字面量（修好形态 C，保住形态 335 条无反引号的）。
  3. 结果为空 ⇒ **fail-loud**：拒绝提交该批次、保留其待处理态并写日志，不以空信息落库。
- **加** 单测：形态 A/C/无反引号/空格/纯反引号/空格式各一条，并以本次真实事故 `B-0906_SC7env` 的原始 message 格为回归夹具（钉死"再不会被截成 `.env`"）。
- **不改**：批次取活顺序、销行语义、push/对齐逻辑、`_resolve_batch_files`（文件清单列的反引号语义**完全不同、不动**）。

### 本次退休哪一个既有守卫（协议〇.9 措施 B，强制回答）

**退休**：`0-学习与工具/skills源码/huijian-chaijian-patrol/SKILL.md:75` 三条禁令中的「**不得裸反引号**」——就 §二 message 列而言。

- 它是一条**人守**：要求作者写 message 时要么整条用反引号包住、要么一个反引号都别写。
- 它**已被违反并造成实害**（本次 `B-0906_SC7env`，且历史至少 11 条），符合规则退休制「人守被违反即须二选一：机制化或删除」。
- 本变更采用「机制化」那一支：**改成任何写法都不会截断**，于是这条人守没有任何存在必要 ⇒ 同批把该行改写为一行指针（说明 message 列内反引号已无特殊语义，文件清单列的反引号语义不变、禁令对该列继续有效）。

🔴 **注意不要顺手扩大退休范围**：同一行的另两条禁令（路径不得速记「同上」、清单内不得裸竖线）**继续有效**，它们守的是「文件清单」列，与本变更无关。

### 伴生文件的 .gitignore 覆盖（强制回答）

**不适用**：本变更不新增任何自动生成的文件名形态——不产生锁文件、快照、暂存、状态文件、日志文件、重命名退路产物或备份副本。改动全部落在一个纯函数的返回值语义与其单测上，磁盘上不多出任何新文件。

## 知识资产三问（强制，全景规划 §1.4 第 2 条）

1. **本流程哪些判断是人脑默会经验？**
   - 「§二 message 格该怎么写才能让 sweep 取到完整信息」——这条**规则从未成文**，只以 `re.search` 的实现细节存在，作者只能靠模仿既有行。实测 357 格里三种写法并存（94% / 4% / 2%），正是"无人知道约定是什么"的直接证据。
   - 「一条 commit 信息写到什么程度算可追溯」——尺度只在写 message 的人脑子里，本变更**不触碰**该尺度，只保证写了什么就提交什么。
2. **由谁显性化？**
   - 持有人：**Shao Peishen**（决策人，规则退休与口径拍板）；backup：**孙涛**（缺席代理，可代 design 审）。
   - 显性化产物＝本变更包 spec 的 Requirement 正文 ＋ 退休后改写的 SKILL.md 指针行。
3. **用什么方法提取？**
   - **历史案例反推**：已完成——扫 745 个历史 commit 的队列文件版本，统计出 357 格的真实形态分布（见上表），约定由此从"猜"变成"数出来的事实"。无需另开工作坊。

## 验收与晋档条件（强制，四档口径）

- **本变更包交付后场景所处档位**：**档 3（内部服务）**。`工具-落库sweep.py` 是已在生产常驻的机制件（`ZhuopinCommitSweep` 计划任务，约 27 分钟一轮），本变更是对其既有函数的语义修正，交付即随该常驻服务生效，不经 mock 阶段。
- **晋下一档的条件**：**不适用，且刻意不晋**。档 4 ＝对客交付；本工具是内部构建机制，永不对客，**不存在晋档路径**。
- **价值指标（风险型）**：
  - 基线（已实测）：2026-06-01 以来指纹明显的截断 commit **≥ 11 条**；本次亲历 1 条。
  - 目标：apply 后新增截断 commit **恒为 0**——判据＝spec 的形态 C 场景单测长绿，且 apply 后一个月内 `git log` 抽查无新增孤立路径/短标签型信息。
  - 由 Shao Peishen 作为业务 Champion 确认基线。
- **LLM 判据黄金集**：**不适用**——本变更不含任何 LLM 运行时判断，是一个纯字符串函数。

## Impact（影响面）

- **specs**：新增能力 `sweep-commit-message-extraction`（本包 delta）。与既有 `batch-registration-precheck` 的「文件清单列反引号预检」**互不重叠**（那条守第 2 列，本条守第 3 列）。
- **代码**：`0-学习与工具/工具-落库sweep.py`（仅 `_extract_commit_message` 及其调用点的失败分支）；`0-学习与工具/test_工具-落库sweep.py`（新增用例）；`0-学习与工具/skills源码/huijian-chaijian-patrol/SKILL.md`（退休行改写）。
- **合规红线核对**：
  - **mock 先行**：不适用——纯函数，单测即完整验证面，无外部依赖可 mock/不可 mock 之分。
  - **audit 留痕**：本工具不产生 AI 业务决策，无 `audit` 写入义务；但本变更**正是为了修复 git log 这条留痕通道**，方向与该红线一致。
  - **OEM 数据隔离**：不涉及任何 OEM 数据。
  - **L2 门禁**：不涉及采购金额/新供应商/交付预测，无 L2 触发面。
  - **ISO 26262 / ASIL**：不涉及车载代码，非安全相关。
- **历史存量**：**不追改**。那 11 条 commit 已在 `master` 且已 push，改写历史与本项目 ff-only、不强 push 的既定纪律直接冲突；存量事实登记在队列 `#398` ⑹ 与取证件 `1-转型规划/0-全景路线图/CI长期红-逐job根因取证-2026-09-06.md`，作为可追溯性缺口的书面留痕。
