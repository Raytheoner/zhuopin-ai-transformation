# qd-b-portal-display Specification

## Purpose
为 QD-B 预审结果提供清楚、可读的只读展示，使质量人员在桌面和手机上都能查看现有判定、依据、缺失状态与人工责任，同时不改变任何业务判据。
## Requirements
### Requirement: QD-B 报告内容完整且状态如实

QD-B 报告页面 MUST 展示现有结果中的总判定、预审说明、13 个模块得分率、扣分明细、全量评审明细、改进建议、C01–C10 跨模块结果、转人工待办与审计元数据。页面 MUST 保留每项的判定、依据和建议；不得将 `MANUAL`、`PENDING`、资料缺失或未实现项显示为“通过”，也不得通过界面重新计算分数、修改判定或改变阻断效力。

#### Scenario: 查看完整预审结果
- **WHEN** 页面收到一份现有 QD-B `EvaluationResult`
- **THEN** 页面展示总判定、模块率、扣分与明细、行动项、跨模块结果、转人工待办和审计信息，且逐项内容与输入结果一致

#### Scenario: 保留待人工与未实现状态
- **WHEN** 某项结果为转人工、待核、未实现或缺资料
- **THEN** 页面用文字和状态标记明确呈现该状态及现有原因，不将其归一为通过或不适用

#### Scenario: AI 预审不形成最终决定
- **WHEN** 页面显示合格或不合格预审结果
- **THEN** 页面仍显著说明这是 AI 预审建议，最终立项决定由评审委员会/PMO 复核，不提供新的自动放行或正式签发操作

### Requirement: 报告依据与时间来源可区分

报告页面 MUST 将项目/样本信息、模板版本、规则版本、审计事件时间和内容哈希按现有结果字段展示。原始资料更新时间不在结果对象中时 MUST 标为“未提供”或等效的明确缺失状态；MUST NOT 把评估时间、页面访问时间或文件名当成原始资料更新时间。

#### Scenario: 展示可用版本与评估证据
- **WHEN** 结果对象包含样本标识、模板版本、规则版本、审计事件时间和内容哈希
- **THEN** 页面显示对应值并标明评估时间的含义，哈希按现有报告约定展示

#### Scenario: 原始资料时间缺失
- **WHEN** 结果对象没有来源系统或原始资料更新时间
- **THEN** 页面明确显示该信息未提供，不推断数据新鲜度

### Requirement: 报告在窄屏与长内容下保持可读

报告页面 MUST 在 1440×1024 桌面与 390×844 移动视口呈现全部既有内容；长中文、长证据、建议与表格内容 MUST 可阅读，不得被截断或彼此遮挡。状态识别 MUST 同时依赖文字，不得只依赖颜色。

#### Scenario: 手机查看报告
- **WHEN** 用户在 390×844 视口打开报告
- **THEN** 结果卡片、13 模块汇总、明细、证据、跨模块项目及转人工责任均可滚动查看，页面无横向溢出导致的内容丢失

#### Scenario: 长中文依据
- **WHEN** 证据或建议包含长中文、特殊符号或 HTML 字符
- **THEN** 内容换行且按文本显示，不执行 HTML，不遮挡判定状态或相邻字段

### Requirement: 保持现有操作与安全边界

QD-B 展示 MUST 继续使用现有服务、认证门禁、上传限制、报告下载和 Flask 路由；展示层 MUST NOT 新增 API、数据源、持久化写入、业务提交、规则修改或人工复核签发操作。显示内容 MUST 继续经过安全的文本转义。

#### Scenario: 访问报告与下载
- **WHEN** 用户通过现有 QD-B 路由查看报告或下载评分表
- **THEN** 认证行为、路由和下载行为与改版前一致，页面只呈现既有结果

#### Scenario: 结果文字含 HTML 字符
- **WHEN** 样本字段、证据或建议包含 `<`、`>`、引号等字符
- **THEN** 浏览器将其显示为文本，不解析为可执行标记或脚本
