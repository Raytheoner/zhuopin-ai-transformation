## 一、两桌分工

- **Claude Code Desktop（建造车间）**：写并运行场景代码、连真实 SRM/ERP、跑真实数据；不改规划文档。
- 🔴 **口令「开启Opener OP-MMDD-X」**：他审过的 opener 由 Cowork 代起，不再切 Code tab／粘贴。**【CC】⇒ 无头**：经 `0-学习与工具/工具-opener批处理执行v2.ps1` 起 `claude -p`（`-FullAuto`，**只在隔离 worktree 内**，护栏＝状态机四档＋hooks＋git 可回滚）；起前必重跑前置实测（不认起草时的表），先 `-DryRun -Yes` 核泳道数；🟡 停点由 Cowork 以「需你定夺」端出、答后 `resume`；**接管＝`claude --resume <session-id>`**（无头起时带 `--session-id` 与 `-n "[Win]MMDDX-<短名>"`，写进 §二 与看护件，机器守 `#522`）。**【Cowork】⇒ 就地**：互动型（grill／值周答题／清扫逐行判）前台跑，非互动型派子代理、结果回本会话。**唯一仍需新开会话的＝转场 opener。** 完整步骤见 `1-转型规划/0-全景路线图/opener骨架.md`；🔴 本口令不放松红线：🔴／⏭️／🟡 档处置不变。
- **执行环境判别**：只产改 `.md`、不写生产码、不连真实库 ＝ Cowork；写跑代码／连真实库与 `.51`／部署／一任务一 worktree ＝ CC。🔴 **判别只看「改不改生产码／连不连真实库」，`commit` 不是判别项**（两桌都自行 commit+push），但 **Cowork 提交前仍须走** `工具-共享文档编辑锁.py` 的 `acquire/release`，登记完整性⑹、opener 守卫、称谓核对三道照跑，**§二 登记照登**（sweep 退为兜底而非唯一落库通道）。只读取证属 Cowork，一旦改代码或触发服务动作即转 CC；**改本机工具链（npm/插件/CLI 升级、`openspec update` 类）＝ CC**，Cowork 破例须其明示授权＋固化升级前证据＋逐文件过目 diff＋事后登记。**「已获授权」≠「该照原方案执行」**——取证推翻方案即回报改判。

## 二、git 同步
- 🛡 **机器守（CC，hook ⓐ SessionStart）**：开场横幅给 fsck／ahead-behind／双标时刻／§一摘要；Cowork 侧仍人守。开工 `git fsck --connectivity-only` 再 `git pull`；收工 `git push`；同一文件别两边同时改。**fsck 报错即停**，报 Shao Peishen 走恢复流程（备份未 commit 改动→重 clone→拷回 `.env`/reports 等 gitignore 件）。**OneDrive**：平时全关、每周手动开一次作离线备份。排查「文件像是变旧了」见 `0-学习与工具/取证方法知识库.md` §三.1。
- **合并策略 ff-only**：PR 一律 ff-only，由 `工具-落库sweep.py::_reconcile_with_origin_and_push` 强制对齐；零 diff 的 PR 验证 `git log master..branch` 为空后带说明 CLOSE，不强 push、不 rebase。🔴 **ff 的验收闸 ＝「零回归」，不是「全绿」**（master 长期红且已拍板不修，`#398`⑶）。**判据**：把同一组失败用例在**纯 master（零改动）**上用**同一条命令**复跑一次——逐条复现 ⇒ 判**零回归、可 ff**；有任何一条只在本棒分支上红 ⇒ **不绿即停**，停手报他。🔑 **自陈「零回归」必须同时写出手段**（复跑命令 ＋ 两侧实测数），只有结论没有手段的不算。**仍禁**为了让测试通过而改断言或跳用例。
- 🔴 **乱码文件夹哨兵**：CC 开工／收工各查一次上级目录，`*AI转*` 目录应且仅应 1 个（`Get-ChildItem ..\ -Directory | ? Name -like '*AI转*'`）；出现含 U+FFFD 的兄弟文件夹即停手，整树移入 `_乱码重复文件夹隔离-日期\`、逐文件哈希比对、不直删。**根因指纹**：路径与内容同现 U+FFFD；CC 写含中文路径的关键文件后读回抽验一处中文（PostToolUse 哨兵 `sentinel-mojibake.ps1` 机器守）。
- 🔴 **`Claude outputs/` 不入库**：Cowork 每调一次 `SendUserFile` 交付文件，桌面端会在**仓库根**自动落一份同名副本到 `Claude outputs/`——它是**交付通道的副产物、不是仓库资产**，已入 `.gitignore`，**不必逐次 `release --waiver`**。🔑 **判别一句：凡由交付／预览通道在仓库根自动生成、且库内已有权威件的副本，一律入 `.gitignore`，不进 §二 批次。**

## 三、取证与时间戳
- 🔴 **时间戳必判 UTC vs 本地**（本机＝UTC+8；hook ⓐ 已给双标）：引用任何时刻前先答「这是 UTC 还是本地」并显式标基准（`09:04:31Z (17:04:31 本地)`）；`wecom_aibot_audit.jsonl`／企微告警文案＝真 UTC，文件 mtime／计划任务 `LastRunTime`／事件日志／`LastBootUpTime`＝本地。🔴 **写侧**：向队列行／批次行／`Last Updated`／接力节标题写日期一律用本机 `Get-Date -Format 'yyyy-MM-dd'` 当场重取——不估算、不用 UTC、不写未到日期、不引用早先取值、禁用沙箱 `date`。 ⇒ 陷阱见 `取证方法知识库.md` §一.2／§一.3。
- 🔴 **工具静默回退**：一类工具参数不符预期时不报错而回退到「看起来合理」的默认行为。**判据：只读命令返回「太干净／太正常」的结果，先问它是不是根本没读到我以为的那个对象。** 已知实例见 `取证方法知识库.md` §二；写后反查三件套见 `专线opener模板库.md` §〇.6；判本机是否重启只认 `ID=27 Kernel-Boot 引导类型`（§一.1）；**判据本身也需被质疑一次**（§四.1）。
- 🔴 **退出码只认被执行进程自己那一层**：`%VAR%` 在 cmd **解析期**即被展开——读到的是**执行前**的旧值，不是被调进程的退出码。**写法**：被调命令单独落一层（独立 `.ps1`／调用后立刻读 `$LASTEXITCODE`），或在 cmd 内用 `!VAR!` ＋ `setlocal enabledelayedexpansion`；**管道之后读到的是管道末端的退出码，不是它的**。**判据一句：这个退出码是谁那一层产生的？**
- **直读原则**：对新鲜度敏感的读取一律本机直读（PowerShell 只读 cmdlet 全名，严禁 `rd` 等可变更别名），不用沙箱挂载副本（有文件桥滞后与尾截断假象、git 操作极慢）；沙箱 bash 只做批量 grep 与纯文本处理。状态页 Artifact＝`zhuopin-project-status`。
- **企微推送**：Cowork 写 `.md` → 对 CC 说「把 X.md 发企微」（Cowork 沙箱出网 403）。工具 `0-学习与工具/发企微.py`（读 `.env` 的 `WECOM_WEBHOOK_URL`）；底座另有 `shared_tools/notifiers/wecom.send_markdown`。
- 🔴 **取证件的 `✅ 已修／转绿` 必须可证伪**：同时附当时那条完整命令＋真实回显，缺回显即不得写 ✅，只能写「据称已修·未取证」；**一个门禁工具守 ≥2 族判据时，判「绿」必须复跑整套**，不得只核与当下话题相关的那一族（**判据**：工具的**文件名只说了一半**——`0-学习与工具/工具-引导样板lint.py` 的 docstring 即自陈此事）。（实证见 CHANGELOG 附录 Q）
