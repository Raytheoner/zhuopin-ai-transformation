# 规则 · 两桌同步、git、取证与时间戳

> CC 触碰上述路径自动加载（CC 每次开工都会碰到其中之一）；**Cowork 不自动加载，按根文件路由表显式 Read**。🔴 **本文件只写「触发 → 动作 → 判据／指针」；成因／实证一律在 `1-转型规划/0-全景路线图/进度编年-CHANGELOG.md`【附录 Q】。**

## 一、两桌分工
- **Cowork（规划治理桌）＝项目总架构师**：规划／路线图／治理合规／招聘／汇报；默认只改 `.md`，Word 仅在明确要求时用 md-to-word；不碰真实库、不写生产代码。**文件链接纪律**：为他定位或产出文件一律附可达文件卡片（present_files）。
- **Claude Code Desktop（建造车间）**：写并运行场景代码、连真实 SRM/ERP、跑真实数据；不改规划文档。
- 🔴 **口令「开启Opener OP-MMDD-X」**：他审过的 opener 由 Cowork 代起，不再切 Code tab／粘贴。**【CC】⇒ 无头**：经 `工具-opener批处理执行v2.ps1` 起 `claude -p`（`-FullAuto`，**只在隔离 worktree 内**）；起前必重跑前置实测，先 `-DryRun -Yes` 核泳道数；🟡 停点由 Cowork 端出、答后 `resume`；**接管＝`claude --resume <session-id>`**（写进 §二 与看护件）。**【Cowork】⇒ 就地**：互动型前台跑，非互动型派子代理、结果回本会话。**唯一仍需新开会话的＝转场 opener。** 完整步骤见 `opener骨架.md`；🔴 本口令不放松红线。
- **执行环境判别**：只产改 `.md`、不写生产码、不连真实库 ＝ Cowork；写跑代码／连真实库与 `.51`／部署 ＝ CC。🔴 **`commit` 不是判别项**（两桌都自行 commit+push），但 Cowork 提交前仍须走 `工具-共享文档编辑锁.py` 的 `acquire/release`，登记完整性⑹／opener 守卫／称谓核对三道照跑。只读取证属 Cowork，改代码或触发服务动作即转 CC；**改本机工具链＝ CC**，Cowork 破例须明示授权＋证据＋逐文件过目 diff＋事后登记。**「已获授权」≠「该照原方案执行」**——取证推翻方案即回报改判。

## 二、git 同步
- 🛡 **机器守（CC，hook ⓐ SessionStart）**：开场横幅给 fsck／ahead-behind／双标时刻／§一摘要；Cowork 侧仍人守。开工 `git fsck --connectivity-only` 再 `git pull`；收工 `git push`；同一文件别两边同时改。**fsck 报错即停**，走恢复流程（备份未 commit 改动→重 clone→拷回 gitignore 件）。**OneDrive**：平时全关、每周手动开一次备份。排查「文件像变旧了」见 `取证方法知识库.md` §三.1。
- **合并策略 ff-only**：PR 一律 ff-only，由 `_reconcile_with_origin_and_push` 强制对齐；零 diff 的 PR 验证 `git log master..branch` 为空后带说明 CLOSE。🔴 **ff 的验收闸 ＝「零回归」，不是「全绿」**（master 长期红且已拍板不修，`#398`⑶）。**判据**：同一组失败用例在**纯 master**上用**同一条命令**复跑——逐条复现 ⇒ 判零回归、可 ff；任何一条只在本分支红 ⇒ **不绿即停**。🔑 自陈「零回归」须同时写出复跑命令＋两侧实测数。**仍禁**改断言或跳用例。
- 🔴 **乱码文件夹哨兵**：开工／收工各查一次上级目录，`*AI转*` 应且仅应 1 个；出现 U+FFFD 兄弟文件夹即停手，整树隔离、逐文件哈希比对、不直删（PostToolUse 哨兵 `sentinel-mojibake.ps1` 机器守）。
- 🔴 **`Claude outputs/` 不入库**：`SendUserFile` 交付在仓库根自动落副本，是交付通道副产物、非仓库资产，已入 `.gitignore`，不必逐次 `release --waiver`。判别：凡交付／预览通道在仓库根自动生成且库内已有权威件的副本，一律入 `.gitignore`。

## 三、取证与时间戳
- 🔴 **时间戳必判 UTC vs 本地**（本机＝UTC+8；hook ⓐ 已给双标）：引用任何时刻先答「UTC 还是本地」并显式标基准；`wecom_aibot_audit.jsonl`／企微告警文案＝真 UTC，文件 mtime／计划任务／事件日志＝本地。🔴 **写侧**：队列行／批次行／`Last Updated`／接力节标题写日期一律 `Get-Date -Format 'yyyy-MM-dd'` 当场重取——不估算、不用 UTC、不写未到日期、不引用早先取值、禁用沙箱 `date`。 ⇒ 陷阱见 `取证方法知识库.md` §一.2／§一.3。
- 🔴 **工具静默回退**：判据：只读命令返回「太干净／太正常」，先问是不是没读到对象。已知实例见 `取证方法知识库.md` §二；写后反查三件套见 `专线opener模板库.md` §〇.6；判本机是否重启只认 `ID=27 Kernel-Boot`；**判据本身也需被质疑一次**。
- 🔴 **退出码只认被执行进程自己那一层**：`%VAR%` 在 cmd 解析期即被展开，读到的是执行前旧值。**写法**：被调命令单独落一层（独立 `.ps1`／调用后立刻读 `$LASTEXITCODE`），或用 `!VAR!` ＋ `setlocal enabledelayedexpansion`；管道之后读到的是管道末端的退出码。**判据：这个退出码是谁那一层产生的？**
- **直读原则**：新鲜度敏感的读取一律本机直读（PowerShell 只读 cmdlet 全名），不用沙箱挂载副本；沙箱 bash 只做批量 grep 与纯文本处理。状态页 Artifact＝`zhuopin-project-status`。
- **企微推送**：Cowork 写 `.md` → 对 CC 说「把 X.md 发企微」。工具 `0-学习与工具/发企微.py`（读 `.env` 的 `WECOM_WEBHOOK_URL`）。
- 🔴 **取证件的 `✅ 已修／转绿` 必须可证伪**：同时附完整命令＋真实回显，缺回显只能写「据称已修·未取证」；**一个门禁工具守 ≥2 族判据，判「绿」须复跑整套**，不得只核当下话题相关的那族。（实证见 CHANGELOG 附录 Q）

## 四、memory 层
- Desktop/Cowork 侧**完全忽略**。CC 侧 auto-memory ＝「技巧笔记层」：**只记**工具技巧／环境坑／偏好表述；**纪律口径判据一律不入**——权威载体只有根 `CLAUDE.md`、`.claude/rules/` 与两份队列。🔑 **判别只问「违反了会怎样」**：会做错事 ⇒ 纪律，不入；只是多走弯路 ⇒ 技巧，可入。
