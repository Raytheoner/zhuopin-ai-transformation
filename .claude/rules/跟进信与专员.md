## 二、跟进信纪律
- **归集** `6-人才与组织/部门AI专员跟进/`，命名 `部门-姓名-跟进-YYYY-MM-DD-主要事项.md`，每封含**做什么／怎么做／什么时候交**，发一封在 README 清单追加一行；编号 `部门#N`（跨收信人共用计数器、未发出不占号、已发旧信不改名）。
- **口径／需求确认唯一格式＝判例批改法**：≤10 条真实案例「现状判定 vs 拟改判定」对照，专员只做 ✅/❌/✏️＋一句话；🔴 **判据／口径／阈值类永不默认生效**（纯展示类可标 48h 默认生效）；不加并行专员。生成器＝skill `zhuopin-followup-letter`。 ⇒ 全文见 `6-人才与组织/CLAUDE.md` §一，正本＝该目录 README ＋ `需求确认方式升级-判例批改法与微会机制-2026-07-25.md`。
- 🔴 **串行原则（优先于任何「某动作完成即触发发信」的规则）**：同一收信人同时只能有一封在途；下一封起草前提＝前一封已回件且回灌消化完毕；起草后提交 Shao Peishen 审核后发。**判闸唯一入口＝`python 0-学习与工具/工具-跟进闸查询.py --to <收信人>`**；闸锁即不得起草，改在队列登记「待前信闭环后发」＋要点。
- 🔴 **信状态唯一权威＝跟进信 README「发送状态」列**：队列里「等某某#N 闭环／待回件」类复述是会过时的快照，不得作判据，队列只写指针。 ⇒ 设计正本 `跟进信状态单一可信源-架构设计-2026-08-21.md`。发送器＝skill `zhuopin-send-followup`。
