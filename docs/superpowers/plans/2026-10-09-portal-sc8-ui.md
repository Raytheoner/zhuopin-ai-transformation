# SC8 采购门户展示适配执行计划

> 当前产物仅供审核；本文不授权业务代码实施、真实取数、发布、ff、部署或对外发送。实施需先取得本计划审核和独立范围批准。

**Goal:** 让采购人员在统一门户查看 SC8 现有交期/物料/案例结果及其来源和责任状态，所有业务语义保持原样。

**Architecture:** 在既有 SC8 独立 Flask 页面内改动展示层，复用原只读结果和已有操作/权限入口。SC8 计算、规则、快照、案例写入、审计和服务边界不改；门户不合并后端服务。

**Tech Stack:** 现有 Python/Flask、HTML/CSS；不新增依赖。

**Spec:** `openspec/changes/portal-sc8-ui/{proposal.md,specs/sc8-portal-display/spec.md,design.md,tasks.md}`；总计划 `docs/superpowers/plans/2026-10-08-portal-ui-rollout.md` 阶段4。

## Global Constraints

1. 仅允许改 `4-数字员工/采购部/SC8-客户订单交期智能承诺/sc8/webapp.py` 的展示层及新增 `4-数字员工/采购部/SC8-客户订单交期智能承诺/tests/test_webapp_ui_contract.py`；先重核隔离树 HEAD、dirty 和批准计划，不切换/新建分支。
2. 不改算法、阈值、取数范围、规则版本、真实六键数据、颜色方向、D4专业签认、刷新/重算动作或案例/审计写逻辑。
3. 所有验证使用构造 mock；不跑全量矩阵、业务fixture、真实数据捕获或现网LAN读取。
4. 不覆盖隔离树既有未提交状态；任何范围外变化先停下留证，不回滚他人内容。
5. ff、生产部署、启用、对客信息发送分别需要逐项授权。

## Review Focus

1. 颜色必须有文字且不推断未签认语义；DOS、源时间和规则版本只显示原值。
2. 物料、成品订单与案例保持数据维度独立。
3. 服务超时/陈旧/资料不足/权限不足与规则待签认不能混成“已通过”。
4. 只读渲染不触发数据请求、重算、快照刷新或审计写入。
5. 动态文本转义，长中文/窄屏不破坏页面可读性。

## 文件责任与步骤

| 文件 | 修改责任 |
|---|---|
| `sc8/webapp.py` | 只改HTML/CSS显示，不改路由处理或业务动作 |
| `tests/test_webapp_ui_contract.py` | 新增纯mock展示契约用例 |
| 隔离树现有计划、规则、业务实现 | 只读；不重写、不覆盖 |

1. **确认基线**：在获准隔离树读取 HEAD、dirty、计划批准哈希和目标文件；核对任务所要求的精确范围。若与授权不符，停止代码修改并报告差异。
2. **绘制字段映射**：依据现有模板/数据对象记录源字段、页面区域、缺失状态、来源时间、审计/权限入口。未签认的颜色/D4语义保持待确认，不创建推断值。
3. **先写测试**：构造纯 mock 覆盖完整结果、缺字段、陈旧/超时/待签认、物料维度独立、长文本/HTML转义，以及渲染不调用写动作或外部读取。
4. **展示实现**：最小修改既有页面渲染；保持原控制器、计算与动作语义。页面上的刷新/重算只保留原有明示动作，不由展示/测试隐式触发。
5. **定向验证**：用项目隔离 Python 环境运行 `pytest -q "4-数字员工/采购部/SC8-客户订单交期智能承诺/tests/test_webapp_ui_contract.py"`；记录精确命令、退出码和测试摘要。不运行其它矩阵/fixture。
6. **复核与证据**：检查 diff 限定于批准文件，运行 `git diff --check`，请求独立只读 Luna review；修复范围内发现后重跑定向测试。记录 HEAD、变更文件、测试结果、审阅结论。
7. **停点**：交付 reviewable 候选和文件清单；颜色/D4签认、真实LAN核验、真实取数、发布、ff、部署、启用及对客发送各自保持待授权。
