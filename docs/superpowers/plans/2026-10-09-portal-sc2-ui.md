# SC2 采购门户展示适配执行计划

> 当前产物仅供审核；本文不授权业务代码实施、真实取数、发布、ff、部署或对外发送。

**Goal:** 在统一门户中清楚展示 SC2 周报的统计期、来源、更新时间和资料状态，将未核验的数量语义显式保持待核。

**Architecture:** 在现有 SC2 Flask 页面里改渲染层，保留数据源、周次、计算、路由、身份、审计和服务边界。独立核验现网超时情况后再讨论任何服务状态结论。

**Tech Stack:** 现有 Python/Flask、HTML/CSS；不新增依赖。

**Spec:** `openspec/changes/portal-sc2-ui/{proposal.md,specs/sc2-portal-display/spec.md,design.md,tasks.md}`；总计划 `docs/superpowers/plans/2026-10-08-portal-ui-rollout.md` 阶段4。

## Global Constraints

1. 仅允许改 `4-数字员工/采购部/SC2-采购周报自动生成/sc2/webapp.py` 的展示层及新增 `4-数字员工/采购部/SC2-采购周报自动生成/tests/test_webapp_ui_contract.py`。
2. 不改指标计算、数量语义、统计期、数据源、审计写入或服务架构；所有待核口径保留原值并标记“口径待核”。
3. 不修改或接管 #538；不根据截图推定现网服务可用。实施前先核对已有超时证据与测试入口。
4. 测试仅使用构造 mock，不访问真实数据、不重算、不写业务审计。
5. 不覆盖既有未提交状态；ff、生产部署、启用、对外发送分别逐项授权。

## Review Focus

1. 统计期、来源、更新时间展示源值，缺失分别标记。
2. 待核数量不会被标题、汇总或格式化包装成确认口径。
3. 空周次、真实0、资料不足、陈旧数据和超时状态互不混淆。
4. 长供应商名称和HTML字符安全可读。
5. UI测试不触发服务数据源或写操作。

## 文件责任与步骤

| 文件 | 修改责任 |
|---|---|
| `sc2/webapp.py` | 只改结果页展示 |
| `tests/test_webapp_ui_contract.py` | 新增纯mock展示契约测试 |
| `sc2` 数据源、计算、审计/路由 | 只读，不修改 |

1. **现状与超时核对**：查阅已有超时证据及测试入口；若测试需要连接真实服务/源，则不执行该路径，将限制记录下来。服务可用性需另行授权的当次核验。
2. **字段映射**：从现有模板/数据结构列出统计期、来源、更新时间、数量和供应商字段；数量的单位、归属和比较含义全部标成待核，等待实名持有人与backup签认。
3. **先写测试**：构造 mock 覆盖完整元数据、空周次、真实0、资料不足、待核值、超时/陈旧状态、长供应商名及HTML转义，并断言无真实数据读取/写入。
4. **展示实现**：只改 `webapp.py` 的HTML/CSS渲染，不增加提交、确认、重算控件或API，不改变当前路由和身份/审计处理。
5. **定向验证**：使用项目隔离 Python 环境运行 `pytest -q "4-数字员工/采购部/SC2-采购周报自动生成/tests/test_webapp_ui_contract.py"`，记录命令、退出码和摘要；不执行全量业务矩阵。
6. **复核与证据**：限定diff，运行 `git diff --check`，做独立只读 Luna review；如修复则重跑定向测试，记录 HEAD、文件清单和审阅结论。
7. **停点**：交付候选供审核；口径签认、服务当次核验、真实数据、发布、ff、部署、启用和对外发送仍需各自授权；#538保持原状态与责任。

## 验收证据

- mock展示契约用例通过，断言不读取真实源、不写业务数据。
- diff仅触及批准的展示文件与测试文件。
- 对待核口径及超时限制有明确记录，不把页面可打开表述为业务验收。
