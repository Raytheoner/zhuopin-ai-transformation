# 智能门户统一UI正式实施计划 Implementation Plan

> **For agentic workers:** 实施时使用 `.agents/skills/executing-plans/SKILL.md`；如本人选择分任务实施，则使用 `.agents/skills/subagent-driven-development/SKILL.md`。本件按本人偏好使用纯编号步骤。当前仅提交计划审核，尚未开始业务代码实施。

**Goal:** 将已通过整套审核的明亮企业办公方案逐模块应用到智能门户，保持现有业务能力、规则、身份权限和审计责任。

**Architecture:** 公共门户继续使用静态HTML/CSS/JavaScript，由既有8092服务托管；各场景继续使用独立服务。先更换门户壳层，再分别适配QD-B、Q2和采购界面；业务网关收编及财务需求变更作为独立范围审批，不随UI改版实施。

**Tech Stack:** 现有Python标准库静态托管；原生HTML/CSS/JavaScript；业务页面保持各自Flask实现。React/Vite模拟原型用于视觉与交互参照，不直接覆盖生产工程，不新增运行依赖。

**Spec:** `1-转型规划/AI运营指挥中心/UI设计评审-2026-10-07/智能门户UI-设计基线与执行记录-2026-10-07.md`、`审核说明与统一UI规范.md`、`设计变量.json`、`需求页面映射.json`。整套审核签认见同目录 `智能门户UI-整套审核结论-2026-10-08.md`。

## Review Focus

1. 已有销售同源数据加载失败：清楚显示来源、快照日期和失败状态，不静默当作实时数据；公共框架任务3拥有此检查。
2. 规划或暂停场景被点击：不能进入模拟执行或擅自改变权限，保留现有能力入口与阶段说明；公共框架任务1、2拥有此检查。
3. 手机关闭侧栏后键盘焦点：隐藏侧栏不可聚焦，Escape与遮罩关闭后回到触发按钮；公共框架任务4拥有此检查。
4. 服务正常但规则待签认、数据旧或证据缺失：不得显示业务通过；质量和采购各自契约及定向测试拥有此检查。
5. 长中文、未知hash及来源文本含HTML字符：布局不溢出、未知页可回首页、文本不被解释为HTML；公共框架任务2、4拥有此检查。

4. 执行一次明确Luna只读review；修复范围内问题后复验，形成候选commit与文件清单，另请ff及部署授权。

3. 保留XLSX/20MB、EQQR8082 A2.1、13模块、六段报告、现有扣分明细及下载；C类在否、C05/档三签认缺口继续显式呈现。意见至少6字仅为模拟设计校验，不自动新增正式签认规则。

### 阶段4：采购适配

页面：P18–P22；移动只查看关键结果和依据。

1. SC8先复核获准隔离树HEAD/dirty/授权范围。将新UI任务与R2业务修复区分；不覆盖原SC8源码或擅自新建分支。

3. 定向契约检查放入SC8 `tests/test_webapp_ui_contract.py`；不得借UI复验重跑矩阵、fixture或真实六键。SC8结果表现网核验须确认当次LAN只读范围，再保存结果表截图、数据时间与当次接口状态。

5. 每个场景独立review及发布准备；采购专业口径、阈值与取数范围不由界面改版冻结。

### 阶段5：财务回件后适配
