# 原队列驱动日常构建 routine 实施计划

> 使用 executing-plans 在本主会话串行实施；唯一任务清单为对应 OpenSpec tasks.md。不派子代理，不修改业务代码。

**Goal:** 让“开启泳道看护”“我已回LAN”从原队列自动取回需求、范围、批准及验收上下文，无需人工搬运开场词。

**Architecture:** 在原 handoff 入口增加确定性上下文读取和需求验收检查，原队列为任务状态真源，INDEX/主规格/原件为对应契约真源。复用原事件入档拆件、认领、串行构建和 LAN 留步，不增加执行器、调度器或任务状态库。

**Tech Stack:** Python stdlib、现有队列查询与编辑锁、原 workflow、pytest、OpenSpec。

**Spec:** openspec/changes/queue-driven-daily-routine-1114/design.md。

## 已批准范围

用户已批准四项机制衔接、现有 fixture 闭环验证、SC7 11.12 会话反馈实际消化入队，以及现存全部未关闭任务按新规则整理。周期回件拆件巡逻继续停用；原监听事件驱动消费者保持现状，不启停调度。不改业务代码，不部署/外发/commit/push/ff，不代专业签认，不重索已有有效批准。

## 实施切片

1. 通过专用队列工具获取全池 digest，对所有非 done 行逐行读取；记录原状态、归属、目标、来源、批准指针、验收、下一步及缺口，未知不猜。状态摘要不替代原行；整理不自动解冻、不抢认领、不销旧任务。
2. 原入口提供短指令对应的只读上下文装载；只读取原行及必要指针，核 live 状态、来源漂移、INDEX、外部阻塞与授权证据。普通前台模式不强迫进入旧 headless/commit 阶段。
3. 在原验收接口关联业务要求、spec scenario、对应测试与功能/audit 证据；缺覆盖、失败或候选漂移不能标完整需求验收。保留 mock/真实/专业/发布的不同边界。
4. 原事件拆件章程及泳道/LAN入口接入上述检查；周期巡逻保持停用，原事件消费者不改。SC7原件哈希归档、段落/表格消化、复用#670，保留旧责任方及业务权限，新增口径只记待确认。
5. 原 fixture 覆盖事件入档→队列→短入口→refinement→验收→归档销号，并验证缺信息、冻结、已认领、未授权、离网和重试反例。完整机制子项目 pytest，需求门禁单测及三个 lint/OpenSpec strict。
6. 全部未关闭任务整理覆盖复核，持锁登记原行指针和§二，release/status；形成六项R5及首次试跑入口。本会话不启动业务试跑。

## 文件职责与验证

- codex-handoff/handoff.py 及既有 workflow_requirements/workflow_release：原入口和验收接线。
- codex-handoff 内的窄辅助模块与 tests：上下文与证据校验，禁止包含模型派发/调度/生产动作。
- 原队列行日志、SC7来源归档/消化记录：事实和回链；全部修改经原锁与队列工具登记。
- 原泳道/LAN/拆件技能源码及需求使用说明：短入口调用契约，不复制长规则。
- reports 下本次整理报告与 docs/codex 验收记录：覆盖数、命令/退出码、缺口、候选哈希和测试证据。

先写失败测试再最小实现；完整pytest从codex-handoff子项目运行，禁止根混跑。只缺业务事实的项如实保留，不能用批量标记ready代替审查。未知锁、旧失败和他人改动保全。
