## 战略背景

作为 VP，推进 AI 转型的最大挑战不是技术，而是**让组织动起来**。本路线图的设计原则：

1. **采购部先行** — 这是你分管的核心部门，也是 AI 能最快见效的领域（供应商评估、合同审核、库存优化都有清晰的数据和规则）
2. **一个部门跑通 → 三个部门跟进** — 用采购部的成功案例建立信心和 SOP，再复制到财务、销售、运营
3. **3 个月见成效，6 个月成体系** — 不给画饼的时间表，每阶段都有可量化的产出

## 第 1 阶段：基建与启动（7月）— 采购部

### 目标
打好数字员工落地的数据和技术基础，同时用低风险的快速见效场景建立团队信心。

### 关键任务

#### 任务 1.1：数据就绪度评估（第 1-2 周）

| 数据源 | 状态 | 责任人 | 输出 |
|-------|------|-------|------|
| ERP 采购数据（供应商主数据、PO 历史、交货记录） | ⬜ 待评估 | IT + 采购 | 数据接入方案 |
| 供应商资质文档（合同、审计报告、ISO 证书） | ⬜ 待评估 | 采购 | 文档数字化清单 |
| 外部征信 API 接入评估 | ⬜ 待评估 | IT | API 可行性报告 |
| 历史采购决策案例（过去 12 个月） | ⬜ 待整理 | 采购 | 案例数据集 |

> **产出**：数据就绪度报告，标注哪些数据立即可用、哪些需要 1-2 周清洗、哪些需要长期治理。

#### 任务 1.2：基础设施部署（第 1-2 周）

- [ ] **Claude Code / API 接入**：完成企业级 Anthropic API 开通和账号配置
- [ ] **MCP 工具链搭建**：至少接入 ERP 只读接口、供应商数据库、文档解析工具
- [ ] **日志与审计系统**：部署 AI 决策日志采集管道，确保从第一天起就有审计轨迹
- [ ] **AIOps 角色确认**：指定 1 人负责数字员工的日常运维（可以是 IT 团队中的 AI 负责人）
- [ ] **权限框架初版**：按"只读优先"原则，设置第一批数据访问权限

#### 任务 1.3：第一个数字员工立项 — 供应商风险评估助手（第 3-4 周）

按照[[管理模板]]的 Phase 1，完成：

- [ ] 填写 **岗位定义卡**
- [ ] 完成 **可行性评估**（确认数据就绪、价值明确、失败成本可控）
- [ ] 输出 **ROI 预测卡**（预计节省采购经理每周 5-8 小时的供应商评估时间）
- [ ] 报 VP 审批通过，正式立项

## 第 2 阶段：试点验证（8月）— 采购部

### 目标
跑通第一个数字员工，用实际数据证明 AI 的价值，积累团队经验。

### 关键里程碑

| 周次 | 里程碑 | 验收标准 |
|------|-------|---------|
| **W5** | 供应商风险初筛 Skill 开发完成 | 通过黄金用例测试 |
| **W6** | 灰度上线（内部测试，仅建议模式） | 10 家供应商测试通过，业务方确认质量 |
| **W7** | 人工复核阶段（AI 输出 + 采购经理确认） | 连续 5 个工作日无重大错误 |
| **W8** | 第一阶段复盘 | ROI 预测 vs 实际数据对比报告 |

### W5-W6 具体执行

- **Skill 开发**：基于 Claude Code + SuperPowers + OpenSpec 工作流构建"供应商风险初筛"Skill（SC1 已完成代码，等真实 SRM 数据验证）
  - 输入：供应商名称、注册资本、历史交付准时率（SRM 自动拉取）、IQC 合格率（人工录入）、单源依赖状态
  - 输出：风险评分（1-5 级）+ 风险描述（DeepSeek AI 生成）+ 建议动作
  - 自动化等级：L2（AI 评估，采购经理确认，IATF 审计日志全程记录）
- **知识注入前置任务**（W3-W4 完成，Skill 开发前）：采购部整理过去 12 个月供应商评估案例（约 30-50 份），结构化后作为参考数据集
- **验证 Skill 配套**：自动检查评分是否在合理范围内、必填字段是否完整、审计日志是否正常写入

### W7-W8 具体执行

- **并轨运行**：AI 评估 + 人工评估同时进行，对比结果一致性
- **反馈收集**：采购经理对每次 AI 输出标记"一致 / 部分一致 / 不一致"
- **问题修正**：对偏差案例进行根因分析，更新 Skill 规则

### 阶段 2 输出

- [ ] 第一个数字员工上线并稳定运行
- [ ] 输出《供应商风险初筛试点报告》— 含准确率、人工节省时间、采购经理反馈
- [ ] 沉淀一份《第一批踩坑记录》（5-10 条经验教训）
- [ ] 形成可复制的**数字员工入职 SOP**
