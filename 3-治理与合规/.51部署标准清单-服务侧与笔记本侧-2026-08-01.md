## 〇、适用范围与两条前置红线

**适用**：`.51`（192.168.100.51）上的服务部署/重部署，以及**笔记本侧**常驻计划任务（sweep／机器人监听／决策提醒等）的注册。

**🔴 前置红线一：新场景一律不新起端口**（CLAUDE.md §5，Shao Peishen 2026-07-29 定）。本清单默认服务对象是**存量四服务**（8091 保供看板／8092 命令中心／8093 QD-B／8094 FI2）的重部署与运维。**新场景不得照抄本清单去起第五个端口**——一律注册到统一门户路由 `/{域}/{场景}` 下并预留网关 auth 接入点，设计见《统一门户架构决策件-SSO与权限-2026-07-29.md》。本清单的 §三 各条在门户形态下**仍然适用**（BOM／防火墙／触发器／绝对路径的坑不因换形态而消失），只是端口与防火墙规则由门户统一持有。

## 三、`.51` 服务侧标准清单（七类坑，逐条打勾）

### ① UTF-8 BOM —— 脚本必须带 BOM
- [ ] `deploy-server.ps1` 与其生成的启动包装脚本**文件头为 `EF BB BF`**
- **为什么**：`.51` 内建 Windows PowerShell 5.1 对**无 BOM** 的 UTF-8 文件按系统 ANSI 解码，中文注释/字符串直接变成语法错误。
- **实证**：2026-07-21 命令中心首次部署即因此报错（队列 #65）。
- **现状核对（2026-08-01 逐文件 `head -c 3` 取证）**：保供看板 ✅／命令中心 ✅／QD-B ✅／FI2 ✅／**`5-平台底座/wecom-aibot-service/deploy-server.ps1` ❌ 无 BOM（文件头为 `# =`）——即队列 #167 记录的唯一缺口，至今未修**。

### ② 防火墙入站规则 —— 必须显式创建，且**不得限 LocalSubnet**
- [ ] `New-NetFirewallRule -DisplayName "<服务>-WebServer-<端口>" -Direction Inbound -Protocol TCP -RemoteAddress Any`
- **为什么**：本机 `127.0.0.1` 冒烟 200 **不能证明**外部可访问；缺规则时外部一律超时，且这个假象极具迷惑性。组员笔记本常在不同网段（如 WLAN），`LocalSubnet` 会把他们挡在外面。
- **实证**：2026-07-21 命令中心本机 200、外部全超时，补 `CommandCenter-WebServer-8092` 后恢复（队列 #65）。
- **现状命名惯例**：`Baoguan-WebServer-8091`／`CommandCenter-WebServer-8092`／`QdB-WebServer-8093`／`Fi2-WebServer-8094`。

### ③ 触发器与运行身份 —— `AtStartup` + SYSTEM，**不用 `AtLogOn`**
- [ ] `New-ScheduledTaskTrigger -AtStartup`
- [ ] `New-ScheduledTaskPrincipal -UserId "SYSTEM" -LogonType ServiceAccount -RunLevel Highest`
- **为什么**：`AtLogOn` + 交互式登录在"会话已断开"状态下**无法启动新进程**（`0x80070002`）。
- **实证**：2026-07-23 `CommandCenterWeb` 原按 `AtLogOn` 注册，Administrator 会话断开时服务短暂中断（队列 #79 附带发现）。

### ④ 绝对路径烘焙 —— 不依赖运行时 PATH
- [ ] 注册时用 `Get-Command` 解析出**绝对路径**并烘焙进启动包装脚本，不写裸命令 `python`
- **为什么**：`python` 常是当前用户级安装（`AppData\Local\Programs`），SYSTEM 账户的 PATH 里根本没有该目录，裸命令**连"找不到命令"都不会明确报**。
- **实证**：同 #79；`0-学习与工具/工具-注册落库sweep计划任务.ps1` 头部注释有完整复盘。

### ⑤ 失败自愈参数
- [ ] `-RestartCount 3 -RestartInterval (New-TimeSpan -Minutes 1)`
- **现状**：命令中心／QD-B／FI2／保供看板四服务均已带；`WecomAibotService` 的注册脚本头部明确说明"Windows 计划任务的 RestartCount/RestartInterval 只支持单一固定间隔"，另行处理。

### ⑥ 共享口令门禁（#160，2026-07-30 起）
- [ ] 目标机 `.env` 含 `ZP_GATE_PASSWORD=<与其余服务同值>`
- [ ] 部署脚本对"已存在的老 `.env` 缺这一行"场景**幂等补行、不覆盖已填值**（SC8 已实现，可照抄）
- **注意**：`ZP_GATE_PASSWORD` 未配置时门禁**自动 no-op**——即"忘了填"不会报错、只会静默零鉴权，属静默失效形态，必须显式核对而非依赖报错。
- **程序化访问**：`/api/ping` 已豁免；其余程序化读取一律走 `X-Auth-Token` 请求头。

### ⑦ 凭据不入库
- [ ] 真实凭据只写 `.env`（已 gitignore），不进 commit／日志／audit 明文
- [ ] 口令类**不写进任何会被提交的文件**（含队列与接力）——2026-07-06 销售域 PII 入 git 历史即反例，至今未清

## 四、笔记本侧计划任务标准清单（⑤⑥⑦，**只适用笔记本侧**）

### ⑤ Principal 慎用 SYSTEM —— 改当前账户 + `LogonType S4U`
- [ ] `New-ScheduledTaskPrincipal -UserId "<当前账户>" -LogonType S4U`（不落密码、不要求保持登录会话）
- [ ] 不加 `-RunLevel Highest`（sweep 类任务只需一般用户权限）
- **为什么**：仓库在 OneDrive 个人版路径下，ACL 归当前用户，**SYSTEM 触发的任务静默权限被拒——零执行、零日志，而 `Get-ScheduledTaskInfo` 可能仍显示"已运行"**。
- **⚠️ 但 S4U 也有门槛（2026-07-31 实测新增）**：注册 `LogonType S4U` 需要"以批处理作业登录"权限，**赋予该权限本身要求管理员权限**——本机注册 `ZhuopinDecisionReminderDaily` 时实测 `Access denied`，已隔离验证 S4U 失败／Interactive 成功。**退路 = `LogonType Interactive`**（同 `ZhuopinAibotDevListener` 既有先例），**代价是任务触发时需当前用户已登录本机**。
- **选型口径**：能注册 S4U 就用 S4U；报 `Access denied` 就退 Interactive **并在任务说明里写明"需用户已登录"这一约束**，不要反复试。
- **两个都真实存在的先例（2026-08-01 本机只读核实）**：`ZhuopinCommitSweep` 的 `Principal = Paul Shao / S4U`——**S4U 注册成功且在跑**；而同一台机上注册 `ZhuopinDecisionReminderDaily` 时 S4U 报 `Access denied`，退 Interactive。**即 S4U 不是普遍被禁**，成败随注册时的权限上下文而变，所以口径是"先试 S4U、失败即退"，而不是"S4U 不可用"。

### ⑥ 笔记本电池策略
- [ ] `New-ScheduledTaskSettingsSet ... -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries`
- **为什么**：该 cmdlet **默认** `DisallowStartIfOnBatteries`，拔电后任务直接不触发。

### ⑥bis `StartWhenAvailable = True` —— **错过必须补跑**（2026-08-01 审计新增）
- [ ] `New-ScheduledTaskSettingsSet ... -StartWhenAvailable`
- **为什么**：笔记本会休眠、会关机、会没登录。该项为 `False` 时，**错过的触发时刻直接作废、不补跑**，且**不报错、不留痕**——是标准的静默失效。
- **实证（本机三任务并列核实）**：`ZhuopinCommitSweep` **True**（#189 已修）／`ZhuopinAibotDevListener` **True**／`ZhuopinDecisionReminderDaily` **False ❌**（= 队列 #199）。
- **🔴 这条为什么单列一节**：`ZhuopinDecisionReminderDaily` 是 **2026-07-31 新建**的任务，而 #189 **同日稍早**刚为 sweep 修过同款设置——**新任务原样复发了刚修完的老坑**，因为注册脚本是照抄的、没人核对设置项。**这正是本清单存在的理由的最好例证**：坑修过一次≠不会再犯，得有清单。
- **连带风险**：#192-A 拍板的"机器人锁忙推迟件的兜底 flush"正挂在这个任务上，其关键收益写的是"保证不会跨周末"——载体不可靠时兜底一并不可靠。
- **⚠️ 但危害程度勿夸大（2026-08-01 同日实测更正）**：`ZhuopinDecisionReminderDaily` 的 `LastRunTime = 08-01 09:31:52 本地`、`NumberOfMissedRuns = 0`，而当日休眠恢复是 09:25:52——**机器唤醒后该任务确实跑了**。故"错过即永久不跑"是**推断而非观察**，`StartWhenAvailable` 的实际语义边界比直觉窄，**本条按"设置项应保持一致"这一卫生理由保留，不按"必然漏跑"立论**。真正需要查的是同次实测发现的 `LastTaskResult = 0x800710E0`（执行被拒绝，非成功）——见队列 #199。
- **📌 方法学**：本条初稿的推断在 20 分钟内被同一批实测数据部分推翻。**清单类文档尤其容易把"配置看起来不对"写成"必然出事"**——凡未实际观察到后果的条目，一律写成"应对齐"而非"会漏"。

### ⑥ter 三任务设置一致性核对（注册任何新计划任务后跑一次）
```
foreach($n in @("ZhuopinCommitSweep","ZhuopinAibotDevListener","ZhuopinDecisionReminderDaily")){
  $t=Get-ScheduledTask -TaskName $n
  "{0,-32} MultipleInstances={1} StartWhenAvailable={2} Principal={3}/{4}" -f `
    $n,$t.Settings.MultipleInstances,$t.Settings.StartWhenAvailable,$t.Principal.UserId,$t.Principal.LogonType
}
```
- [ ] 新任务的 `MultipleInstances`／`StartWhenAvailable`／电池两项与既有任务**逐项对齐**，不一致必须有写明的理由
- **现状基线（2026-08-01）**：三者 `MultipleInstances` 均为 `IgnoreNew` ✅（sweep 因此不会双实例并跑）。

### ⑦ 验证标准改"空跑也写日志"
- [ ] `Start-ScheduledTask` 后，目标日志文件**必须出现新时间戳**——哪怕内容只是"本轮无事可做"
- **为什么**：`LastTaskResult=0` **不等于**任务真的跑了。没有新时间戳＝脚本根本没启动（回查 Principal／权限）。
- **⚠️ 判"任务为何没跑"之前，先确认机器这段时间是否在运行**（CLAUDE.md §5，2026-08-01 实证）：查事件日志 `ID=27／42／107`，并对比两次读时钟的真实间隔——**休眠期间任务排队 `Queued`、唤醒即执行，是 Windows 正常行为，不是缺陷**。2026-08-01 曾因漏查此项把一次正常休眠误判为 P1 缺陷。

### 笔记本侧路径纪律
- [ ] 计划任务 Action 指**主工作区稳定路径**，绝不指向任何 `.claude\worktrees\<name>`（建造 worktree 会被删，删了任务就废）

## 六、回滚 SOP（部署前必须已在位，不是出事再想）

**服务侧**：
```
schtasks /End    /TN <TaskName>        # 停止本次运行
schtasks /Delete /TN <TaskName> /F     # 彻底注销（回到未部署态）
```
**门禁回滚（#160）**：清空 `.51` 上对应 `.env` 里 `ZP_GATE_PASSWORD=` 的值 + `schtasks /End` + `/Run`，即恢复零鉴权原状，**无需回滚代码**。

**代码回滚**：`sync-to-server.ps1` 重推上一个已验证 commit 的产物 + 重启任务。

- [ ] 回滚命令已实际写进本次部署的交接记录（不是"照本清单查"，是写下具体 TaskName）
