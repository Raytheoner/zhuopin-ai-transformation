## 四、逐控制测试步骤（由人执行并记录）

### P2P-01 · 三单及紧急例外

1. 从原业务总体追到付款申请、PO、收货、发票及 FI2 匹配结果；核对单号、适用期间、数据版本及结果完整性。
2. 对比 FI3 D1 “完全匹配”口径与人工核对结果；记录缺结果、缺发票和不适用预付。
3. 如有紧急标志，取得实际 CFO 审批凭据、事实日、执行人；核对仅豁免三单未配齐，并取得 7 工作日补齐及《未匹配付款跟踪清单》的真实后续证据。
4. 保存旁路清单、人复核及实际付款记录的关联；未找到原审批或后续证据记“缺证据”，不以 special_approval 角色字段替代。

### P2P-02 · 重复付款

1. 核对已付凭证期间完整性及取数截止时刻；分别列已付、在途/并发申请及核销记录能否取得。
2. 按 R3 逐样本复算同供应商/同金额/±3 天疑似及发票累计；允许分次付款不得仅因相同发票号一律判错。
3. 复核未核销预付及本次扣回，记录 12 个月业务口径与现源码 30×12 日近似的边界差异；交专业复核，不在底稿改规则。
4. 对照财务最终人工判断，记录误报、漏报、原始证据与处理结果；对未有证据的并发去重如实标未覆盖。

### P2P-03 · 主数据及收款账户

1. 取得账户生效版本、变更申请、实际修改人、独立复核/授权人、时刻及原系统变更日志。
2. 按 R2 复核户名/账号/开户行、30 天并行窗口及首用财务主管确认。
3. 检查 first_use_confirmed_by 的实名与原凭据能否绑定；字符串非空不能独立证明授权正确或及时。
4. 底稿和审计材料的账号仅留尾 4 位；原始账户取证保存在受控位置，不在本模板复制全号。

### P2P-04／P2P-UP-PO · 审批及职责分离

1. 取得适用期间的审批矩阵、授权权限与变更记录，确认其专业签认版本。
2. 逐样本串联申请人、PO 审批人、付款审批人、付款执行人、复核人及各自事实时刻/凭据；空字段记缺证据。
3. 对照 R5 单据支撑及应批角色、R7 实际 CFO 特批，区分“应该由谁批”和“谁确已批”。
4. 按专业签认的冲突角色表核对 SoD；冲突关系、代岗/例外处理未签时不自行建立默认判据。
5. 实际付款仍在 U9C/银企系统由人执行；本底稿不产生付款指令。

## 五、证据有效性与逐样本结果

### 证据标准（汉化方法来源）

可支持复核的材料包括：带日期和审批人的签署件；可核验审批人及日期的电子批准记录；能定位执行人与时刻的系统 audit；说明系统控制配置/版本/时刻的截图；可复核的重新计算；带日期、地点、观察人的观察记录。

单独的口头确认、无日期文件、无可识别执行人/审批人的材料、无时刻的泛化系统报表、仅“与某人讨论过”而无佐证，均列为证据不足。电子邮件证据若已合法落档可引用；本件不授权发送或索取新邮件。

| 样本号 | 步骤 | 实际执行人／时刻 | 证据 ID、版本／哈希、路径 | 观察事实 | 结果（通过／不符／缺证据／不适用） | 人工复核结论及依据 |
|---|---|---|---|---|---|---|
| 〔填写〕 |  |  |  |  |  |  |

“缺证据”与“不适用”分别统计，均不填作“通过”。系统生成报告还须复核总体完整性、准确性及版本，不能只签报告结论。

## 六、缺陷三级候选分流与整改

**下表是源方法的汉化说明，供财务选择/签认本地标准；尚未成为卓品的自动判据。** 不移植 SOX 法定适用性、源技能的金额重要性/概率/抽样数字；AI 只归集事实，不代判等级。与 R8“重大漏拦”的对应关系也须专业明确，不能按名称相似自动等同。

| 源方法等级 | 汉化含义 | 本公司专业评估所需字段 |
|---|---|---|
| Deficiency／内部控制缺陷 | 控制设计或执行不足，导致不能及时预防或发现错报 | 事实、受影响控制、发生可能性/影响、补偿控制及依据 |
| Significant Deficiency／重要缺陷 | 严重性低于重大缺陷，但足以需要治理责任人关注的单项或组合问题 | 组合影响、治理关注理由及本地已签分级依据 |
| Material Weakness／重大缺陷 | 存在重大错报不能被及时预防或发现的合理可能性 | 专业重要性/可能性判据、控制/错报影响与签认出处 |

| 发现 ID | 样本／证据 | 设计缺口／执行不符／缺证据 | 单项及组合影响 | 专业等级／签认依据 | 补偿控制及有效性证据 | 整改 Owner／期限 | 复核证据／结论 |
|---|---|---|---|---|---|---|---|
| 〔填写〕 |  |  |  | 未签认时留“未签认” |  |  |  |

原发现与后续整改分别留痕；关闭需重新复核证据，不覆盖原失败记录。Owner 由相应业务管理者指派，模板不代点名。
