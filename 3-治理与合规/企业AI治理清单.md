## 关于这份清单

本清单面向 VP / 数字化转型负责人，对标**供应链数字员工**和**财务数字员工**两大优先落地场景，覆盖 AI 治理的五个核心维度：

| 维度 | 核心问题 |
|------|---------|
| 安全与权限 | 数字员工能做什么、不能做什么？ |
| 合规与审计 | 出事了能不能追溯、能不能解释？ |
| 质量与可靠性 | 输出是否准确？翻车了怎么办？ |
| 成本与效率 | 投入产出比是否清晰？是否可持续？ |
| 组织与流程 | 人机如何协作？谁来负责？ |

> **使用方式**：每个条目可标记 ✅（已就绪）、🔄（进行中）、⬜（待启动），作为季度 AI 治理 maturity review 的检查基线。

---

## 一、安全与权限（Security & Access Control）

### 1.1 数据分级与访问控制

- [ ] **数据分级清单**：梳理供应链和财务数据资产，按敏感度分为 3-4 级（公开/内部/敏感/绝密）
- [ ] **数字员工权限矩阵**：为每个 Agent 定义最小必要权限（Least Privilege），例如：
  - 供应链需求预测 Agent → 可读历史销售数据，不可写 ERP
  - 财务异常检测 Agent → 可读交易流水，不可修改账务
  - 供应商评估 Agent → 可读公开征信数据，不可访问供应商银行账号
- [ ] **RBAC/ABAC 落地**：数字员工的权限与人类员工的角色体系打通，不允许独立于企业 IAM 系统之外的"影子权限"
- [ ] **动态授权机制**：高风险操作（如自动下单、自动付款审批）需要动态 token 或人工二次授权

### 1.2 数据隔离与脱敏

- [ ] **生产 vs 非生产数据隔离**：数字员工的开发、测试、生产环境数据严格分离
- [ ] **敏感字段自动脱敏**：识别并替换 PII（客户姓名、电话、地址）、财务数据（银行账号、交易金额）中的敏感信息，进入 LLM 前完成脱敏
- [ ] **输出反向过滤**：数字员工生成的回答中，防止模型"记住"并输出训练数据中的敏感信息（DPO / 输出过滤器）
- [ ] **跨境数据合规**：涉及海外供应商/客户数据时，确认符合 GDPR、CCPA、《数据安全法》等要求

### 1.3 工具调用白名单

- [ ] **MCP 工具清单**：每个数字员工可调用的外部工具有明确的建立、审查、撤销流程
- [ ] **写操作保护**：所有对生产系统的写操作（ERP 更新、银行接口调用、订单创建）需满足「双人规则」——AI 发起 + 人确认
- [ ] **不可逆操作的熔断机制**：如批量删除、批量修改价格、大额付款等，设置人工强制审批节点

## 二、合规与审计（Compliance & Auditability）

### 2.1 全链路审计日志

- [ ] **每次 AI 决策可追溯**：记录每一次数字员工的输入（prompt + context）、输出、调用工具、所用模型版本、推理耗时
- [ ] **结构化审计存储**：审计日志采用不可篡改存储（如 append-only 数据库或区块链存证），保留周期 ≥ 3 年
- [ ] **审计查询接口**：合规团队可以按时间、Agent、用户、操作类型快速检索审计记录
- [ ] **变更影响记录**：当 AI 配置（Skill 更新、模型切换、权限变更）发生修改时，自动记录变更人、变更内容、生效时间

### 2.2 可解释性要求

- [ ] **决策理由自动附带**：数字员工的每次建议（如"建议增加采购量 30%"）必须附带推理依据
- [ ] **置信度标尺**：输出附带置信度评分（0-100），低于阈值自动标记"需人工复核"
- [ ] **人工复核记录**：人类确认/驳回 AI 建议的操作、原因、时间全部记录在案
- [ ] **定期抽样审查**：按季度抽检数字员工的决策日志，评估是否存在系统性偏差或错误

### 2.3 行业合规对齐

- [ ] **供应链场景**：确认符合 ISO 28000（供应链安全管理）、ISO 20400（可持续采购）的 AI 辅助要求
- [ ] **财务场景**：确认数字员工的账务处理符合 GAAP/IFRS 标准，审计轨迹满足 SOX 法案要求
- [ ] **跨境贸易场景**：数字员工处理的报关、税务数据符合各国海关和税务法规

## 三、质量与可靠性（Quality & Reliability）

### 3.1 输出质量保障

- [ ] **自动化验证技能**：为每个数字员工配备配套的验证 Skill（Validation Skill），每次输出后自动执行断言检查
  - 供应链示例：需求预测值是否在合理范围内（±50% 历史均值）
  - 财务示例：会计分录是否满足借贷平衡、金额是否为有效数字
- [ ] **黄金数据基线**：维护一组"已知正确答案"的测试用例集，每次模型/Skill 更新后自动回归测试
- [ ] **幻觉率监控**：按周统计数字员工的幻觉率（可通过人工复核抽样估算），设定告警阈值（如 > 3% 触发审查）

### 3.2 异常处理与兜底

- [ ] **超时/失败降级策略**：当 LLM 调用超时或返回异常时，数字员工的默认行为是什么？（重试？走备选模型？转人工？）
- [ ] **边界输入保护**：数字员工无法处理的输入（如格式异常、缺失关键字段）应有统一的"我不确定，请补充信息"或"转人工处理"响应
- [ ] **人工接管通道**：任何环节出现异常，业务人员可以一键接管数字员工正在处理的任务
- [ ] **灰度发布机制**：数字员工的 Skill 更新先走 10% 流量 → 观察 24h → 全量发布，发现问题可秒级回滚

### 3.3 持续改进

- [ ] **用户反馈闭环**：每个数字员工的输出附带"有用 / 无用 / 需要修正"反馈按钮，收集数据反哺优化
- [ ] **失败案例库**：记录每次数字员工出错的完整上下文，形成"AI 踩坑日志"，定期 review 并更新 Skill
- [ ] **周期性评估**：每季度对数字员工做一次全面评估（准确性、用户满意度、ROI），输出评估报告

## 四、成本与效率（Cost & Efficiency）

### 4.1 成本可见性

- [ ] **按 Agent / 按部门 / 按任务的 Token 消耗仪表板**：能让 VP 一眼看清"哪个数字员工最烧钱"
- [ ] **模型分级调用策略**：
  - 简单任务（如数据格式转换）→ Haiku / 轻量模型
  - 中等复杂度（如供应商评分）→ Sonnet
  - 高复杂度推理（如合同审核、根因分析）→ Opus
- [ ] **缓存命中率优化**：对高频重复的请求（如企业知识库问答），设计 Prompt 缓存机制，控制在 Anthropic API 的缓存窗口内
- [ ] **预算上限与告警**：每个数字员工设置月度 Token 预算上限，超过 80% 时预警、超过 100% 自动降级

### 4.2 ROI 度量

- [ ] **效率基线**：记录每个流程的人工处理耗时（如"人工审核一份合同平均 45 分钟"），作为 AI 效率提升的基准线
- [ ] **ROI 计算公式**：建立统一框架
  > ROI = (节省的人工时数 × 人力成本单价 + 减少的错误损失) / (API 费用 + 工程维护成本 + 培训成本)
- [ ] **非量化收益记录**：记录"做了以前做不到的事"——如实时风险预警、全天候监控、跨语言沟通等无法直接用时间换算的价值

## 五、组织与流程（Organization & Workflow）

### 5.1 角色与职责

- [ ] **AI 运营团队（AIOps）设立**：至少明确 1-2 人负责数字员工的日常运维、质量监控、Skill 更新
- [ ] **业务方 AI 联络人**：供应链、财务各指定一名"AI 对接人"，负责业务需求澄清和输出验收
- [ ] **AI 治理委员会**：季度例会，由 VP（你）、IT 负责人、法务/合规代表、业务部门负责人组成，评审重大更新和安全事件

### 5.2 人机协作流程

- [ ] **自动化级别定义**：为每个数字员工定义清晰的自动化等级（参考自动驾驶 SAE 分级思路）：
  - L1：AI 建议，人决策
  - L2：AI 执行，人确认
  - L3：AI 执行，异常转人
  - L4：AI 全自动，定期审计
- [ ] **人工审核节点地图**：为供应链和财务的核心流程绘制人机交互节点图，标注每个节点"谁确认、何时确认、超时怎么办"
- [ ] **变更管理流程**：数字员工的 Skill 更新 → 业务方验收 → 灰度发布 → 全量上线 → 持续监控

### 5.3 培训与文化建设

- [ ] **业务方 AI 素养培训**：针对采购、财务、销售团队的基础 AI 使用培训（至少包含"如何给 AI 提需求""如何判断 AI 输出是否靠谱"）
- [ ] **AI 安全红线培训**：全员级别的 AI 安全须知（不向 AI 输入敏感数据、不盲目信任 AI 输出）
- [ ] **最佳实践沉淀机制**：建立内部 Wiki 或知识库，沉淀各部门使用 AI 的经验、踩坑、模板

## 附录：供应链 vs 财务治理差异速查

| 治理维度 | 供应链数字员工 | 财务数字员工 |
|---------|--------------|------------|
| **最高风险** | 自动下单失误导致库存爆仓/断供 | 账务错误导致报表失真、合规风险 |
| **合规要求** | ISO 28000, 供应商合同约束 | SOX, GAAP/IFRS, 税法 |
| **数据敏感度** | 中（供应商信息、价格、库存） | 高（交易金额、银行账号、客户 PII） |
| **人工介入密度** | 建议类场景可低（预测）、执行类场景需高（下单） | 较高（每笔异常交易需确认） |
| **审计重点** | 决策逻辑是否有偏（如歧视小供应商） | 数字准确性和合规性 |
| **降级策略** | 恢复人工采购计划 | 冻结账务操作，人工介入 |

## 季度自检节奏建议

```
每月一次：成本仪表板 review + Token 消耗分析
每季一次：全面治理评估（逐条过本清单）+ 用户满意度调查
每半年：AI 治理委员会会议 + ROI 复盘 + 下阶段路线图调整
每年：全面 AI 安全审计 + 合规审查 + 治理清单更新
```

> **最后提醒**：治理不是用来"限制"数字员工的，而是用来让数字员工**能放心地跑起来**。没有治理框架的 AI 转型，规模越大风险越大；有了合理的治理，VP 才能从"救火队长"变成"战略掌舵人"。
