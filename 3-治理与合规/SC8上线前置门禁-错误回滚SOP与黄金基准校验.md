> **SC8 session 开工前必读。** SC8（客户订单交期智能承诺）要把"成品交付预期"推给客户——这是对外承诺，错了代价高。本清单是两道闸：**① 切真实库前过"黄金基准校验"；② 推客户前过"L2 人工确认 + 错误/回滚 SOP 就位"。** 没过门禁，SC8 只能出草稿 / 内部看板，**绝不自动外发客户**。

## 1. 错误 / 回滚 SOP（推客户前必须就位）

针对"成品交付预期推给客户后，发现算错"的全流程。

### 1.1 置信度与人工门禁（L2）
- 每条交付预期**带置信度**：有供应商承诺交期 = 高；默认假设/估算（无反馈+30天、委外+10天）= 低。
- 强制人工复核、不自动外发的情形：低置信 / 关键路径物料无反馈 / 预期交付晚于客户目标日。
- L2 人工确认（不可自动执行）：采购金额 > 50 万、新供应商、首次给某客户做交付承诺。

### 1.2 错误识别（怎么发现算错了）
- **触发重算的信号**：供应商交期反馈更新、齐套日变化、委外排期变化、实际到货与预测偏差超阈值。
- **偏差监控**：预测交付日 vs 实际进展，偏差超过 X 天（建议先设 3 天，按业务调）自动告警给 PMC/采购。

### 1.3 推送后发现错误的处置（撤回 / 纠正）
1. 立即用 `crm_notifier` 生成"**交付预期更正通知**"草稿。
2. **经人工确认**后再发给客户（同样走 L2 门禁，不自动外发）。
3. 草稿注明原因：供应商交期变更 / 数据错误 / 齐套延迟 / 委外排期调整。
4. 同步通知相关方：销售、PMC、采购。

### 1.4 IATF 审计记录修订规范
- 原预测记录**不删除**（平台 audit 是 append-only）。
- 新增一条"**更正**"事件，**关联原记录 ID**，写明：原因、触发信号、责任人、时间。
- 保留可追溯链：原预测 → 触发信号 → 更正 → 客户确认。

### 1.5 责任归属
- **AI 出草稿，人工确认外发**：确认人对外发内容负责；AIOps 对系统/算法正确性负责；采购经理对输入数据负责。

## 2. 黄金基准校验（切真实库前必须通过）

仿 supplychain 的 `manual_calculation.md` 黄金基准做法。

### 2.1 取样
- 6/12 全量物料清单到位后，取一小批真实订单（建议 **5-10 张**），覆盖三类：有供应商反馈 / 无反馈（走默认假设） / 含委外加工。

### 2.2 人工核对
- 采购经理 / PMC 对每张单**手工计算**成品交付预期（关键路径齐套日 + 委外 10 天），与 SC8 输出逐项对比。

### 2.3 通过标准
- **确定性逻辑**（关键路径、日期加减）：与手工偏差 = **0**（应完全一致）。
- **启发式假设**（无反馈+30天 / 委外+10天）：与约定一致。
- **置信度标注**：高/低标得对。
- 连续 N 张（建议 ≥5）无重大偏差 → 黄金基准通过。

### 2.4 沉淀
- 把核对过程与结果存为 SC8 黄金基准（如 `4-数字员工/采购部/SC8.../data/golden/`），作为**回归测试基准**——后续改动跑这套基准防退化。

### 2.5 升级到真实推送
- 黄金基准通过 **且** 错误/回滚 SOP 就位 → 才允许开 CRM 自动通报。
- 且**先推内部 / 测试通道**（企微内部群）验证，再切真实客户。

## 4. L2 门禁与回滚 SOP 落地定稿（**已 VP 签字生效 2026-06-11**）

> SC8 真实切换（PR #8）已合 master，下列把第 1 节占位项定稿。**Paul（VP）于 2026-06-11 签字认可 4.1–4.3 全部参数**（见 4.5）。
> 注：本节签字锁定治理参数，**不等于对客上线**——对客仍需第 3 节检查表全勾（含黄金基准校验，待回 LAN/VPN 跑）。

### 4.1 置信度分级与外发规则（与引擎对齐：**2 级**；置信度=分类，非数值阈值）

> 决策（2026-06-11）：引擎输出 2 级置信度，与红线一致——只有**完全**基于真实承诺交期的预测才可外发候选，任何启发式介入即降级不外发。SOP 由原 3 级简化为 2 级**对齐引擎，不改引擎语义**（"中"档不增安全性，反增复杂度）。

| 分级 | 判定 | 外发处置 |
|------|------|----------|
| **高** | 关键路径物料**全部**基于真实 SRM 承诺交期 + 齐套日确定 + 无委外不确定 | 可进入对客确认候选（**仍须人工确认**） |
| **低** | 任何启发式介入（无 SRM 反馈 +30 天 / 委外 +10 天 / 缺数据） | **不外发**，转采购 / PMC 内部跟进 |

> **独立外发拦截（与置信度正交）**：预期交付日**晚于客户目标日** → 无论置信高低，一律**不自动进候选**、强制人工研判（晚于承诺为高敏感事项）。
> 规则锁：系统层只允许"高 **且** 不晚于目标日"进对客草稿队列，队列仍须人工确认。对应已实现的"低置信不外发 + CRM 层无对客自动发送函数 + `CUSTOMER_OUTBOUND_ENABLED=False`"结构性红线。

### 4.2 L2 人工确认流程与授权人

流程：SC8 生成交付预期 → （高置信）生成对客草稿入确认队列 → **确认人**核对（承诺交期 / 齐套 / 客户目标日）→ 确认或驳回 → 确认后系统发送（须先开 `CUSTOMER_OUTBOUND_ENABLED`）。

授权人（VP 已确认 2026-06-11）：
- **常规确认**：供应链计划负责人 / PMC。
- **升 VP 复核**的情形：重点客户（比亚迪 / 上汽 / 理想）、预期**晚于**客户目标日、首次给某客户做交付承诺、关联采购金额 > 50 万。
- 红线：任何对客发送必经人工确认、不可自动；**确认人对外发内容负责**。

### 4.3 偏差阈值与回滚授权

- **偏差阈值**（VP 确认 = 3 天）：预测交付日 vs 实际进展偏差 > 3 天 → 自动告警 + 触发重算（第 1.2 节）。
- **回滚授权**（VP 已确认 2026-06-11）：
  - **常规更正**（生成更正草稿 → 人工确认 → 发客户）：供应链计划负责人 / PMC 可触发。
  - **系统级回滚**（关 `CUSTOMER_OUTBOUND_ENABLED` / 切回 mock / 暂停外发）：AIOps 执行、VP 知会；重点客户重大影响 → **VP 决策**。

### 4.4 与已实现代码的对应（核验用）

- `CUSTOMER_OUTBOUND_ENABLED=False` 当前为关 → 结构性保证不外发；开外发前才接入发送函数。
- 审计按真实端点分标（`U9C_webapi` / `zp_ERP` / `CSV_mock`）；real 模式无真实端点 → `RealEndpointNotReadyError` fail-loud，绝不静默用 mock。
- L2 触发已测（M015 → R1 ≥50 万 待人工审核）。

### 4.6 承诺交期取数口径（2026-06-18 定，Paul 采纳；黄金基准真实跑后修正）

> 背景：6/18 黄金基准全真实跑（3 单/6 行）暴露——**SRM 供应计划看板对各单 BOM 子件只覆盖 15-29%**（17/117、9/90、37/126），多数子件不在看板前瞻窗口 → 全部走"无反馈+30天"启发式 → 三单全低置信🔴。根因是**看板是前瞻计划视图、窗口窄，结构上不适合做"承诺交期"源**。

- **取数口径（决策）**：承诺交期改为**分层取数**——① **主源 `/purchase/answer` 按 PO**（供应商对具体 PO 的答复＝权威承诺交期）；② **辅助：供应计划看板**（补充窗口内子件）；③ **兜底：无反馈 +30 天启发式**（v0 不变）。
- **预期效果**：大幅提子件覆盖、减少"无反馈+30"兜底、产出**高置信样本**（当前一个都没有）。
- **诚实边界（非 bug）**：子件**未下 PO 前本就无承诺交期 → 仍低置信**，这是正确行为；本口径主要救**已下 PO 的在飞订单**；早期新单低置信属正常。
- **CC 待办（LAN）**：实现分层取数 → 重跑 `build_golden_real` → 复核是否出现高置信 / 委外样本（当前真实数据三类只命中"无反馈"一类）→ 黄金基准零漂移回归。改口径前不开对客。
