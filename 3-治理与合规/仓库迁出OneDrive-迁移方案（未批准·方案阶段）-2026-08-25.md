## 一、诉求与判定

**Shao Peishen 2026-08-25 原话**：「目前多数情况下我的 OneDrive 是关闭的，但以后不能经常关闭，我需要把企业AI转型项目目录从 OneDrive 路径移出，以免和 github 冲突。」

**判定：诉求成立，且现行惯例本就是在拿「关掉 OneDrive」当补丁。**

- 根 `CLAUDE.md` §5 现行惯例白纸黑字写着「**平时全关、每周手动开一次作纯离线备份**」——这条惯例的存在本身就是承认：OneDrive 与 git 工作树同处一地是不相容的，只是靠「大部分时间不让它跑」压住了。
- 一旦「以后不能经常关闭」，这个压制条件消失 ⇒ **OneDrive 会开始实时同步 47,578 个文件**，其中包含 `.git/` 的 pack、index、`*.lock`。git 在写 index/lock 期间被同步客户端读写占用，典型症状是 `.git/index.lock` 残留、对象库半写、以及 OneDrive 自作主张产生「-SPSThinkpadWIN」式冲突副本。
- **这不是推测**：本仓库 `.git/` 目录下**已经存在** `config-SPSThinkpadWIN`、`config-SPSThinkpadWIN-2`、`FETCH_HEAD-SPSThinkpadWIN` 三个文件——**这就是 OneDrive 冲突副本命名法在 `.git` 内部留下的实物**。换言之，冲突不是将来时，是已经发生过、只是还没有酿成事故。

**⇒ 结论：迁出 OneDrive 是治本动作，不是优化项。**

### 🔴 冲突发生在哪一层（2026-08-25 补，Shao Peishen 问「git 本身没在 OneDrive 路径里吧」后取证）

**分两层，答案相反**：

| 层 | 位置 | 受不受影响 |
|---|---|---|
| git **程序** | `C:\Program Files\Git\cmd\git.exe` | ✅ 不在 OneDrive，迁移不碰 |
| git **全局配置** | `C:\Users\Paul Shao\.gitconfig` | ✅ 不在 OneDrive，迁移不碰 |
| 仓库的 **`.git` 目录** | `…\OneDrive\Projects\企业AI转型\.git`，**8,251 文件 / 632.5 MB** | 🔴 **就在 OneDrive 里，且它就是问题本身** |

`.git` 占整个仓库 1.26 GB 的**一半**，内容是 pack、index，以及 git 运行期不断创建又删除的 `*.lock`。OneDrive 不认得 git 语义，只看到"一堆文件在高频变动"，于是去读、去上传、去占句柄。

**⇒ 迁移的目标可以更精确地表述为：让 `.git` 这个目录不再有第二个进程去碰它。** 工作树搬走只是顺带的。

**这一节改变了方案的一处做法**：既然要搬的是一个 632 MB 的对象库，S2 的完整性校验必须升级为 `git fsck --full`（见 S3 第 10bis 步），而不是原先写的 `git fsck`。

**已定夺（Shao Peishen 2026-08-25，本会话内答复）**：

| 决策点 | 结论 |
|---|---|
| 目标路径 | **`C:\Dev\zhuopin-ai`**（全英文短路径） |
| 执行方式 | **整树移动 ＋ 逐项修指针**（保真度优先） |

## 四、迁移窗口判据（六条**全部满足**才可开工，缺一即等）

| # | 判据 | 校验方式 |
|:-:|---|---|
| 1 | **§二「待 commit 批次」清零** | 队列 §二 无待处理批次行——否则迁移后 sweep 指向新路径，旧路径里的脏文件**永远不会被提交** |
| 2 | **`ahead = 0`** | `git rev-list --count origin/master..master` ＝ 0；且 `git status --porcelain` 无未提交改动 |
| 3 | **编辑锁空闲** | `工具-共享文档编辑锁.py status` 显示未占用 |
| 4 | **泳道批处理 / 定时班空闲** | 不在 09:00、13:00（拆件巡逻）与周一 10:00（值周巡检）班次内，且无 opener 批处理在跑 |
| 5 | **全部写手已停**（🔴 2026-08-25 扩写，Shao Peishen 答 4(a)） | 三者缺一不可，核验命令见本表下方代码块：① 常驻监听器已停且**进程确已退出** ② **无 claude 进程存活** ③ **无 opener 批处理 runner 在跑** |
| 6 | **OneDrive 已完成同步且已退出** | 迁移期间 OneDrive **进程退出**，避免它一边同步一边被 move 抽走文件 |

**判据 5 核验命令（三条全部应无输出）**：

```powershell
# ① 常驻监听器：任务已停 且 进程确已退出（只看任务状态不算数）
Stop-ScheduledTask -TaskName ZhuopinAibotDevListener
Get-CimInstance Win32_Process -Filter "Name='wscript.exe'" | Where-Object { $_.CommandLine -like '*wecom-aibot-service*' }

# ② 无 claude 进程存活
Get-Process claude -ErrorAction SilentlyContinue

# ③ 无 opener 批处理 runner 在跑
Get-CimInstance Win32_Process -Filter "Name='powershell.exe'" | Where-Object { $_.CommandLine -like '*opener批处理执行*' }
```

🔴 **② 为什么必须单列**：2026-08-25 实测 **16 个 claude 进程自 08-21 存活至今**（最长累计 CPU 361 分钟）。它们不是批处理产生的——那一轮的 headless claude 全部正常退出了——但**它们是活的写手**：随时可能抢编辑锁、写队列、改文件。原判据只点名了 Listener，**这批进程在判据里根本不存在**。

🔴 **判据 2 的反直觉点**：`git status` 在本仓库实测耗时 **61 秒**（47,578 文件 ＋ 云盘占位符）。**不要因为"命令没立刻返回"就以为它挂了而中断**——中断后拿到的是空输出，而空输出看起来正好像"很干净"。（同族＝「工具静默回退：太干净的结果先怀疑它根本没读到」。）

6. 退出 OneDrive 客户端；退出所有 CC / Cowork / 编辑器对该目录的占用。

**S2 · 移动**
6bis. 🔴 **确认无云端占位符**：`Get-ChildItem -Recurse -Force -File | ? { $_.Attributes -band 0x400000 -or $_.Attributes -band 0x1000 }` 应为 **0**（2026-08-25 实测确为 0）。**若非 0 必须先全部 hydrate 再迁**——robocopy 搬占位符会得到一份"看起来文件数对、实际内容是空壳"的副本，**而且不报错**。
7. `robocopy "旧路径" "C:\Dev\zhuopin-ai" /MOVE /E /COPY:DAT /DCOPY:DAT /R:1 /W:1 /NFL /NDL /LOG:…`，**核对返回码 ≤ 7 且日志内 Failed = 0**。
   - 🔴 **不要用 `/COPYALL`**（＝`/COPY:DATSOU`）：它要复制 ACL、属主与**审计信息（SACL）**，需要 `SeSecurityPrivilege`／备份特权，未提权时会产生成片的 ERROR 5，把一次本该干净的搬迁变成一堆需要逐条判读的失败。**`.git` 与源码树不依赖任何自定义 ACL**，`/COPY:DAT`（数据+属性+时间戳）足够。
8. 核文件数：新旧路径两侧各跑一次 `Get-ChildItem -Recurse -Force -File` 计数，**两者应严格相等**。
   - 🔴 **"应等于 47,578"这种写死的期望值不能用**：实测 2026-08-25 09:56 为 47,578、11:30 为 **51,670**，**1.5 小时内涨了 4,092**（CC 会话在跑）。**基线必须在冻结窗口内当场取，不能引用方案里写死的数**。
9. 🔴 **中文完整性抽验**：读回 3 处含中文的深层路径文件，确认无 U+FFFD（编码事故指纹）。
10bis. 🔴 **`.git` 完整性全量校验**：`git fsck --full`（**不是 `--connectivity-only`**）。理由：`.git` 实测 **632.5 MB / 8,251 文件**，其中 pack 文件刚被 robocopy 逐字节搬过一遍——连通性检查只验引用图，验不出 pack 内部的字节损伤。**这一步耗时较长，但它是整次迁移唯一能证明"对象库没搬坏"的动作。**
