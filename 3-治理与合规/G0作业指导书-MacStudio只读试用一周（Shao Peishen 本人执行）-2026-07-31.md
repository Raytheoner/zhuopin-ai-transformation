# G0 作业指导书 · Mac Studio 只读试用一周

## 〇、这一周你在验证什么（只有一个问题）

> **Remote Control 在你真实的 off-LAN 场景下，够不够用？**

**不是**验证"Mac 能不能跑代码"（那肯定能），**是**验证"**你人在外面、只有手机或笔记本浏览器时，能不能舒服地指挥它**"。

这一周结束你只需要给出**一个判断**：够用 / 不够用 / 有条件够用（条件是什么）。

---

## 一、🔴 三条铁律（整周不得违反）

1. **只读。** Mac 上的 clone **不跑任何写盘脚本、不 `commit`、不 `push`、不改任何文件**。
2. **不碰生产。** 不连 `.51`、不连 U9C/SRM、不启动任何服务、不装 `.env`、**不放任何凭据**。
3. **笔记本一切照旧。** 机器人、sweep、拆件巡逻、值周巡检、CC、Cowork **全部原样跑在笔记本**——**Mac 只是个观众**。

> **为什么第 1 条要写死**：Mac 上一旦有 clone，它在结构上就已经是"第二个潜在写手"。整周保持只读，是"这一步零风险"这个断言唯一的依据。

**违反任一条 → 立刻停，本次 G0 作废重来。**

---

## 二、准备（一次性，约 15 分钟）

Claude Code 你已装好。剩下三步：

| # | 动作 | 验收 |
|:--:|---|---|
| 1 | **建一个只读用途的 clone**——放在**独立路径**，🔴 **不放 iCloud Drive / 任何云同步目录**（与"不放 OneDrive"同一条红线）<br>建议：`~/zhuopin-readonly/`（名字里带 readonly，天天提醒自己） | `git log --oneline -3` 能看到最新提交 |
| 2 | **不配 git 身份、不加任何凭据**——只读不需要推送权限 | `cat .git/config` 里没有你的 user.name/email 也无妨 |
| 3 | **启动 Remote Control**：在 Mac 的 Claude Code 里跑 `claude remote-control`（保持这个会话不关） | 在 claude.ai/code 或手机 app 里能看到这个会话 |

> 一个降低误操作的小设置（可选但推荐）：`chmod -R a-w` 掉整个 clone 的写权限，一周后再改回来。**手滑也写不进去。**

---

## 三、这一周每天做什么（每天 5-10 分钟，别多）

**核心原则：用你真实的使用姿势，不要为了测试而测试。**

### 每天至少做一次「远程只读三连」

在你**真实 off-LAN 的时刻**（通勤、外出、客户现场、家里），用手机或笔记本浏览器进 Remote Control，让它做这三件事之一：

| 动作 | 指令示例（直接粘） | 验的是什么 |
|---|---|---|
| **A. 看队列** | `读 1-转型规划/0-全景路线图/跨桌任务队列.md 的 §四，列出需我定夺的项与截止` | 最高频需求：**人在外面想知道有什么在等我** |
| **B. 查状态** | `git log --oneline -10；再告诉我最近一次 sweep 落库是什么时候` | 项目脉搏 |
| **C. 找东西** | `grep 一下 FI2 相关的队列行，告诉我现在卡在哪` | 检索能力 |

**每次记一句话**（记在手机备忘录即可，不必进仓库）：**能不能用？慢不慢？断没断？**

### 每天顺手观察四件事（不用刻意测）

1. **断线重连**：手机切 WiFi/5G、笔记本合盖再打开——会话还在吗？**这是 Remote Control 最关键的卖点**（官方称内置自动重连、客户端睡眠时会话在后台存活），值得亲自验。
2. **通知**：有没有推送提醒？（**官方文档说 2026-03 时通知不是 OS 级**，需主动去看——**验一下现在改了没有**，这直接决定它能不能替代企微私信提醒）
3. **手机端可用度**：小屏幕上读长输出是否可忍受？
4. **延迟**：从发指令到出结果，比坐在电脑前慢多少？

## 四、一周结束时回答这七个问题（这就是评估表）

| # | 问题 | 记什么 |
|:--:|---|---|
| 1 | **一周里你实际用了几次？**（不是"能用几次"，是"真用了几次"） | 次数。**用不到 3 次说明需求没那么强，这本身就是重要结论** |
| 2 | **有没有哪一次，你本来想用但放弃了？为什么？** | 放弃原因是最真实的否决票 |
| 3 | **断线重连真的无缝吗？** | 遇到过几次断、是否需要手动重连 |
| 4 | **通知能不能收到？** | 若不能 → **企微私信提醒（#172）必须保留，不能指望 Remote Control** |
| 5 | **手机端够用还是必须笔记本？** | 决定它能不能覆盖"完全没带电脑"的场景 |
| 6 | **有没有出现过让你不安的事？**（会话丢了、输出串了、权限弹窗） | 任何一次都要记 |
| 7 | **如果明天让你把 CC 建造搬过去，你敢吗？** | 直觉答案。**这题的答案就是 G0 的结论** |

## 五、判定与去向

| 结论 | 含义 | 下一步 |
|---|---|---|
| **够用** | 第 7 题答"敢" | 回来修订实施方案深化件，进 **G1**（Mac 环境搭建）；仍需你逐闸批准 |
| **有条件够用** | 第 7 题答"看情况" | **把条件写下来**（如"必须有通知"/"必须有 Tier-2 通路"），作为 G1 的前置 |
| **不够用** | 第 7 题答"不敢" | **零损失退出**——删掉 Mac 上那个 clone，选项 0（零迁移）成为终局，现环境跑完 Phase 1。**这是完全合法的结局，不是失败** |

## 六、退出（不继续时怎么收干净）

1. 关掉 Mac 上的 Remote Control 会话。
2. `rm -rf ~/zhuopin-readonly/`（因为整周只读，**删掉不会丢任何东西**）。
3. 在队列 #170 行注一句结论即可。**笔记本侧本来就一个字节都没动，无需回滚。**

## 七、这一周**不要**做的事（每条都有具体原因）

| 不要 | 原因 |
|---|---|
| ❌ 在 Mac 上装 `.env` 或任何凭据 | 凭据一旦落第二台机器，就需要走 §五.A 的迁移 SOP 与最小集原则；G0 用不着 |
| ❌ 在 Mac 上跑 `python 工具-*.py` 任何一个 | 它们会写盘（sweep 会 commit、台账会重写），**直接违反只读** |
| ❌ 在 Mac 上开 Cowork | Remote Control **不覆盖 Cowork**；且 Cowork 会改协调类文件，破坏"唯一写手" |
| ❌ 让 Mac 上的 Claude Code 去连 `.51` | 那是生产服务；G0 阶段没有任何理由碰它 |
| ❌ 因为"顺手"就在 Mac 上改一个 .md | 一旦发生就不再是只读试用，评估结论失去意义 |
