# FI9 mock 夹具

🔴 **全部为合成数据**，项目名与员工号均为占位。

**`labor_records.csv` 的 `source` 列写死 `synthetic`、`rate` 列留空，都不是笔误**：
- **工时系统在本项目内无任何既有取数指针，是否存在都未核实**（2026-09-03 实测；`工时`
  二字仅作依赖名出现于 4 份规划文档，代码侧唯一一处是 `shared_tools/models.py:126` 的
  一句注释「用于 SMT 工时查询」，那是 `product_id` 的用途说明、不是连接器）。
- **工时单价口径属判据，未签认**。人工费用归集在这两项解决前一律 fail-loud，
  **不得以任何分摊估算代替**——分摊出来的人工费会原样写进加计扣除备查资料。

**`is_high_tech_scope` 一列全空亦是刻意**：项目是否纳入高新口径须按签认后的政策库判定，
空 ＝ 未判，**不是** ＝ 不纳入。

⚠️ 夹具**不含任何"标准答案"的资本化/费用化判定**。本场景产出是对外申报材料，先造一组
标准答案等于先替财务/研发总监判了一遍，且那些答案会变成回归基准。
