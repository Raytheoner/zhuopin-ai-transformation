## 1. 场景定位

- **场景**：O1 = 运营部第 1 个数字员工，SMT 生产排程。
- **全景编号**：全景规划 §2.1.3 运营部 O1（S1 筑基期场景，排期 2026-09）。
- **自动化等级**：**L1**（Shao Peishen 2026-08-18 拍 design D3）—— 首版产出是纯计算返回的日期，无任何下发/推送/写回动作，无 L2 门禁。
  🔴 **口径分歧未消**：全景规划 §2.1.3 O1 行现写 `L2（AI 生成排程方案，计划员审核调整）`，与本场景实际的 L1 不一致。**回写全景规划或 opener 之一属 Cowork 归口**，已挂账队列 #343，本场景不自行改规划件。全景规划的 L2 定位在场景具备「排程方案下发车间」能力时生效，届时须补人工确认门禁。
- **MVP 范围（档 1）**：完工日推算引擎 + 场景入口 + 审计留痕；mock/CSV 夹具跑通，`real` 模式显式 fail-loud。
- 🔴 **首版是「完工日估算器」，不是「排程优化器」**——收割来的算法是 `max(所有物料到货日) + 工时天数`，无容量约束、无产线/设备分配、无优先级排序、无换线损耗。**与场景名「智能优化」的落差是真实的**，此处如实记录而不修饰；全景规划所载「设备利用率提升 15-20%」属首版不可达指标。
- **底座贡献**：无。O1 是排程引擎的**消费方 #1**，rule-of-three 未触发，引擎留在场景本地（同 O2 当初）。
- **OEM 隔离**：不适用（O1 读内部生产计划/物料到货，不涉 OEM 技术数据），**不强加 OEM 路由**（同 O2）。

## 4. 红线（建造时守住）

- 🔴 **随附工时表 46 行工时值全为占位常数 7，非真实工时**——`fixtures/smt_lead_time.csv` 头部有显式声明块 + 机器可读标记 `@placeholder: true`；返回值与审计均带 `lead_time_is_placeholder`。**禁止用于任何对外承诺、交期答复或产能测算。** 无标记的工时表按占位处理（缺省偏保守）。
- 🔴 **首版是估算器不是优化器**，见 §1。对外描述本场景能力时不得暗示其含产能优化。
- 先 mock/脱敏跑通，再切真实数据；`real` 模式取生产计划**显式 fail-loud，绝不静默回退 mock**。
- 工时列非法的行**跳过并告警**，不得静默视为 0 天——否则会算出一个假完工日（同 O2 B6 精神）。
- 排产决策写平台 `audit`（automation_level=L1，IATF 3 年留存）。
- L1 场景无 L2 人工确认门禁；**若未来升级到「排程方案下发车间」，必须先过门禁评审**并同步改回自动化等级。
- **不新起端口**：首版无 Web 呈现；若后续要呈现，注册到统一门户 `/operations/o1` 路由并预留网关 auth 接入点（根 CLAUDE.md §5 硬约束）。
