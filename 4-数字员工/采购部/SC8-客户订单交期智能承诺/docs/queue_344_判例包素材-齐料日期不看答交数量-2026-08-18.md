## 一、问题一句话

看板上方的**齐料日期**与**瓶颈物料**，取的是该物料**最早的那个答交日期**，
**完全不看那一笔答交了多少**——**连答交数量为 0 的记录也照用**。

## 二、取证（2026-08-18 当日真实取数，非推断）

姚祖怡 2026-08-12 举证：`F02N.0224` 看板显示齐料 **2026-11-18**，她核定正确值 **2026-12-25**，
瓶颈物料 `R01I.0622`。

本次对 `R01I.0622` 实取其逐笔看板承诺：

| 答交日期 | 答交数量 |
|---|---|
| 2026-08-20 | **0** ← **引擎实际采用的就是这一笔** |
| 2026-09-20 | 0 |
| 2026-10-20 | 0 |
| 2026-11-20 | 0 |
| 2026-12-20 | 0 |
| 2027-01-20 | 0 |
| 2027-02-20 | 0 |
| **2027-05-20** | **10000** ← 唯一真正有数量的一笔 |
| 2027-06-20 | 0 |

⚠️ **她举证的日期（11-18 vs 12-25）与本次实测数字（08-20 vs 2027-05-20）不同**，
系预测订单与供应计划看板**月度自然滚动**所致（她举证至今已数日）；
**机制完全一致，且本次复现得更极端**——务必在信里主动交代这一点，
否则她按 11-18/12-25 去核会对不上，重演 #150 那次「找不到那张单」的困惑。

## 三、根因（两处同源，都在"只问日期不问数量"）

1. `sc8/sources.py::load_srm_deliveries`：合并时 `committed = min(auth_dates)` 取最早，
   且构造 `SrmDeliveryOrder(qty_committed=0)` —— **数量在这条链路上根本没被带出来**。
2. `sc8/forecast.py::estimate_material_arrivals`：`srm_index` 同样只留最早日期
   （`committed < srm_index[...]` 即覆盖）。

⇒ 齐料日 `kit_date = max(arrivals)`、瓶颈物料、四色缺口天数**全部**建立在「最早日期」之上。

**为什么她一直感觉「下面的清单是对的、上面的汇总数不对」**：
看板下方 BOM 缺口物料清单走 `_cumulative_confirmed_batches`（**按数量累计至覆盖缺口**，
即她 07-28 亲自定的 #18-a 口径，**是对的**），而上方齐料日期/瓶颈**不走它**。
这是 #262／#296 那一族「汇总数与明细清单口径不一致」的又一处落点。

**与 #266 的分层区别（信里要写清，别让她以为是同一件事又犯了）**：
#266 在 **BOM 展开深度**那一层（只看第一层子件，已于 2026-08-18 修复上线）；
本条在 **答交数量匹配**那一层（看了日期不看数量，**尚未修**）。两者可各自独立复现。

## A-1、问题一句话

你 2026-08-18 给的三条规则里，**规则 1 管「出货日不在三个月内」、规则 2 管「出货日在三个月内」** ——
但**三条规则都没有说过：出货日恰好落在「三个月」那一天时，算哪一边。**

我方程序现在取的是「**含边界**」（边界当天走规则 2）。
**这个取值从来没有人签认过**，当初是我方按「这样更保守」自己定的。

## A-2、🔴 为什么现在必须补签（而不是继续沿用）

当初「含边界」唯一的理由是「**这样算出来的齐料日更晚、更保守**」。
**这个理由在规则 2 按你的原文逐字实现之后就不成立了**：

- **改之前**：边界当天走规则 2 ⇒ 起算点 ＝ **出货日**（更晚）⇒ 确实更保守；
- **改之后（按你原文「此时此刻起往后推 90 天」）**：边界当天走规则 2 ⇒ 起算点 ＝ **今天**（更早）。

⇒ **「含边界更保守」这句话已经反过来了。** 现在这个取值既没有你的签认，
也没有「反正更保守」这层兜底 —— 所以我方不敢再沿用下去，须请你明判。

## A-3、取证（算术，可手算复核；🔴 非生产实测）

以业务日期 **2026-09-02**、无答交件提前期 **90 天**为例，边界当天即 **2026-12-02**：

| 边界当天走哪一支 | 起算点 | 估算到货日（齐料日） | 缺口（齐料日−出货日） | 四色 |
|---|---|---|---:|---|
| **含边界 ⇒ 走规则 2**（我方现行取值） | 今天 2026-09-02 | **2026-12-01** | **−1 天** | **🟢** |
| **不含边界 ⇒ 走规则 1** | 2026-09-20（出货日往前推 3 个自然月的 20 日） | **2026-12-19** | **+17 天** | **🔴** |

⇒ **同一张单，边界当天两种读法相差 18 天，而且四色一个是 🟢、一个是 🔴。**
这不是理论差异，是看板上一行会不会报警的差异。

⚠️ **本表是算术推演，不是生产实测**（我方当前无法连内网取数）；
真实数字须在内网复跑后另出对照表 —— 但**边界该算哪一边是口径问题，不依赖那份数据，可以现在就定。**
