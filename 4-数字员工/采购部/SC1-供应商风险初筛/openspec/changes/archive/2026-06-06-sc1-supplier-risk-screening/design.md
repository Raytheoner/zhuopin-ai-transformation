## Context

SC1 供应商风险初筛是卓品智能采购部的第一个 L2 数字员工。当前采购部供应商评估依赖人工，覆盖率不足 30%。

**现状约束：**
- SRM API（携客云）已接通，可获取交期数据和采购订单历史
- ERP（U9C）接口申请中，IQC 合格率和财务数据暂无法自动拉取
- 评估结果须供采购经理签字确认（L2 自动化，非全自动）
- 所有评估须写入审计日志（IATF 16949 追溯要求）
- 不得向外部 API 传输供应商详细财务数据（红色数据保护）

**目标用户：** 采购经理（非开发人员），需要简单易用的操作入口

## Goals / Non-Goals

**Goals:**
- 四维度加权评分引擎（交付准时率 35%、IQC 合格率 30%、财务稳定性 20%、单源依赖风险 15%）
- 人工数据录入表单，支持 ERP 数据缺失阶段运行完整评估流程
- 标准化 PDF/Markdown 风险报告，供采购经理审批
- IATF 16949 兼容审计日志（JSON Lines 格式，本地持久化）
- SRM API 自动拉取交付和采购历史数据

**Non-Goals:**
- ERP 自动集成（当前阶段跳过，预留接口）
- 外部征信 API（天眼查/企查查）集成（待评估，不在本期范围）
- 供应商自助填报门户
- 全自动决策（L3+），本期固定为 L2

## Decisions

### D1：实现形态选 CLI + Markdown 报告，不选 Web App

**选择**：Python CLI 脚本 + Markdown/HTML 报告文件

**理由**：当前用户仅为采购部内部少数人员，Web App 开发和部署成本不合理。CLI 可在 Windows 本地直接运行，Markdown 报告可用浏览器或 VS Code 查看。ERP 接通后可无缝升级为 Web 服务。

**备选方案**：Streamlit Web App — 开发快但增加部署依赖，暂无必要。

### D2：评分计算用确定性公式，不用 LLM 打分

**选择**：每个维度用预定义的分段评分表（Lookup Table），加权求和得综合分，规则透明可审计。

**理由**：IATF 16949 要求每条评估结论可追溯到具体数据和规则。LLM 评分不可重复，审计时无法复现。LLM 仅用于生成"核心风险描述"和"建议动作"文本（非评分路径）。

**备选方案**：LLM 端到端评分 — 灵活但不可审计，违反 IATF 要求。

### D3：数据录入用交互式 CLI Prompt，不用配置文件

**选择**：运行时交互式输入（`questionary` 或 `input()`），数据立即用于本次评估，不持久化原始录入数据到文件。

**理由**：供应商财务数据为红色数据，不应落盘。评估结果（评分+等级）写入审计日志，原始财务数字不写入。

**备选方案**：Excel/CSV 批量导入 — 方便批量但财务数据落盘存在合规风险。

### D4：审计日志用 JSON Lines 本地文件

**选择**：`audit_log.jsonl`，每条记录一行 JSON，包含时间戳、操作人、供应商名称、各维度评分、综合评分、风险等级、LLM 生成文本摘要哈希、报告文件路径。

**理由**：简单可靠，无需数据库，GREP 可查，满足 IATF 追溯最低要求。后续可迁移到数据库。

**备选方案**：SQLite — 更结构化但增加依赖，当前阶段过度设计。

### D5：模块化设计，预留 ERP 数据适配层

**选择**：数据获取层抽象为 `DataProvider` 接口，当前实现 `SRMProvider`（自动）和 `ManualProvider`（人工录入）。ERP 接通后只需新增 `ERPProvider` 实现。

**理由**：避免 ERP 接通后大规模重构。

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|---------|
| SRM API 数据质量不稳定（字段缺失、历史数据不完整）| 评分引擎对缺失数据降权处理，报告中明确标注"数据不足" |
| 人工录入数据准确性无法验证 | 报告数据来源标注"人工录入"，采购经理签字时承担数据准确性责任 |
| LLM 生成文本出现幻觉（捏造风险点）| LLM 文本仅基于传入的结构化评分数据生成，Prompt 中明确禁止超出输入数据范围的推断 |
| 审计日志文件被误删 | 文档中说明日志文件路径和备份建议；后续升级为数据库时迁移 |

## Migration Plan

1. **阶段一（当前）**：SRM 自动拉取 + 人工录入 IQC/财务数据，CLI 运行
2. **阶段二（ERP 接通后）**：新增 `ERPProvider`，IQC 和财务数据自动拉取，人工录入降级为兜底
3. **阶段三（可选）**：接入天眼查/企查查 API，财务稳定性维度自动化；升级为 Web 服务

回滚：CLI 工具无服务依赖，任意版本直接替换脚本文件即可回滚。

**决定**：Markdown 格式足够，Phase 1 不引入 PDF 依赖。PDF 导出列入 Phase 2。

**决定**：使用 `claude-sonnet-4-6`。报告是正式采购决策文件，质量优先，成本差距可忽略。

**决定**：Phase 1 只支持单次单供应商评估，批量评估列入 Phase 2。
