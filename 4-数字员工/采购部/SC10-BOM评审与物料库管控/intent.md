### 本次完整意图待确认的交付与验收

**目的及使用者**：采购业务人员能逐格核对“BOM 要什么、物料库有什么、还缺什么”，据此准备主数据和专业判例；资料整理人及采购经理是后续业务核对角色，实名与 backup 经正式流程点名。

**输入**：对照包 `SC10-MOCK-B01/r1` 包含 BOM、计划、主数据三份合成资料。现有 fixture 作为事实来源，衍生变体逐项写明移除或改动的字段；每份资料须记录名称、版本、文件 hash 和来源，计划日期单列。此 ID 是文档准备标识，当前接口并未支持或验证它。

**产出**：物料毛需求及成品来源表、主数据对照表、三类缺数清单、四计数摘要、逐格人工算式/预期、差异说明、仍被阻断的建议项及其前置。后续运行产物须能追到输入版本；如何补充审计和版本传递，留在存量 design 中审查，不把外部文档标签冒充已实现的运行追溯。

**人工对照验收线**：每例明确输入、手工依据、观察项与差异归因；用量、成品来源和四计数逐项一致，缺项不得静默补值。基准毛需求为 M-A=80、M-B=10、M-C=20，readiness=3/1/2/0；这是现存 fixture 的数学/静态预期，不是新执行结果。零价仅核对“有值”与“无值”的技术区别，业务有效性留给 SC10-G-05。版本关联不足须列差异，不能凭相同计数宣布同一输入。

**首期能力边界**：复用确定性事实层；外部 API 选型、真实 ERP 接入、优先选用/淘汰/BOM合格判断分别留在其真实前置之后。mock 对照不足以证明真实材料适用性或场景上线；工时和质量收益基线不代填。未来若使用 OEM 技术附件，须先重新判定数据边界。

**路线**：完整 intent 明确确认 → 在原包补 design Decisions/Open Questions 与依赖拆分 → design 审 → 写并审实施计划 → Guardian 隔离建造。输入版本与审计如何绑定是设计前沿；专家五项判据采用案例批改，不转给 Shao Peishen 代定专业值。当前不改原 tasks 勾选或归档状态。
