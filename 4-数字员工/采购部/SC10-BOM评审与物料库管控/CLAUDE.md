## 2. 关键决策记录

| 决策 | 结论 | 依据 |
|------|------|------|
| D1：选用级别口径算不算已有前置 | **单列为第三项前置，不并进「物料属性数据整备」** | 数据整备产出属性值，不产出排序规则；混记会让"属性到位"被误读成"可全量开工" |
| D2：`LifecycleStatus` 要不要混入 `str` | **不混**（与本仓库其余枚举惯例相反） | 带 `str` 时 `ACTIVE < NRND` 静默按字母序成立，一个看似能用、实无业务含义的排序，正是偷偷造判据的入口。测试硬拦 |
| D3：BOM 展开自写还是用底座 | **用底座 `kit_engine.explode_bom`** | O2/SC7/SC8 已共用；`4-数字员工/CLAUDE.md` 第 1 步要求 import 底座不造轮子 |
| D4：共用料怎么识别 | 逐成品单独展开再合并 | `explode_bom` 返回合计毛需求、丢掉"来自哪个成品"，而共用料判定要的正是这条来源信息 |
| D5：外部 API 先接一家还是留 Protocol | **留 Protocol + `UnselectedCatalogSource` 占位** | 先接一家等于替姚祖怡做了选型，而选型结果会改字段口径/配额/缓存策略 |
| D6：物料无价怎么表示 | `unit_price=None`（不是 0.0） | 0 是一个价，None 是"没有这份数据"；前置未到位期间两者必须可区分 |
| D7：`lifecycle` 缺省值 | `UNKNOWN`（不是 `ACTIVE`） | 属性数据整备 2027-01 才启动，库里现无此字段；缺省成 ACTIVE 会让"还没这份数据"消失 |
