## 门禁（实现时守住，已由测试硬拦）

> 调拨清单落 ERP ＋ 外发邮件须 **PMC 经理人工确认后执行，AI 不自动落库、不自动外发**
> ——采购专线 2026-07-06 定，全景规划 §2.1.2 SC11 门禁加固注，根 `CLAUDE.md` §7-4。

两条实现立场：
1. **确认状态的唯一判据是拟稿自身的 `approved_by`**，执行侧函数不接受任何 `force=` 旁路参数（`test_门禁不接受任何旁路参数` 用 `inspect.signature` 硬拦）。
2. **即便已确认，骨架期两个执行动作仍然抛 `NotWiredYet`** ——"确认过了"和"能执行了"是两件事；静默 no-op 会产出一条『落库成功』的 audit 而 ERP 里什么都没有。

## 现在**不能**跑什么

| 卡住的能力 | 前置 | 类型 | 状态（2026-09-03 实读） |
|---|---|---|---|
| 真实需求来源 | 生产计划数据通路 | 数据型 | ⚪ 新增行；窗口 2027-02～03，未到 |
| 真实库存 | 3 委外仓库存实时可见 | 数据型 | ⚪ 新增行；内网通路，off-LAN 期间亦无法验证 |
| 路径择优（真口径） | 四条原则的相对优先级与冲突裁决 | 知识型 | ⚪ 未起；姚祖怡批改会 |
| 「就近」怎么算 | 1 物料仓 + 3 委外仓的距离/时长矩阵及口径 | 混合 | 🔴 **前置总表三项均不产出此矩阵**，本场景据实拆出 |

🔑 **原则正文可转录、冲突裁决不可自拟**：四条原则单独看语义清楚（转录），但"委外仓 A 有现货
但离得远"与"物料仓有货但优先级更高"会指向不同源仓——谁压谁，规划原文没写。故
`rank_candidates` 要求显式传入四条齐全的优先级顺序，少一条即抛，**不替 PMC 决定哪条不重要**。
