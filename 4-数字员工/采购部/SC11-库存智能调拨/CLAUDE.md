## 2. 关键决策记录

| 决策 | 结论 | 依据 |
|------|------|------|
| D1：先做门禁还是先做算法 | **先做 PMC 确认门禁** | 它是四项前置里唯一一条**不依赖任何前置**的实心内容；前置总表 SC11 行备注亦点名「PMC 确认门禁写入 openspec」 |
| D2：门禁能不能被参数关掉 | **不能**，执行侧只接受 `draft` 一个入参；测试用 `inspect.signature` 硬拦 | 一个能被参数关掉的门禁，下一次赶工时就会被关掉 |
| D3：已确认后骨架期怎么处理执行 | **仍抛 `NotWiredYet`**，不静默 no-op | "确认过了"和"能执行了"是两件事；no-op 会产出『落库成功』的 audit 而 ERP 里什么都没有 |
| D4：四条原则算不算自拟判据 | **正文可转录**（规划原文逐字），**冲突裁决不可自拟** | 单条语义清楚；四条互斥时谁压谁规划没写，属「调拨原则口径」知识型前置 |
| D5：优先级顺序给不给默认 | **不给**，`rank_candidates` 要求四条齐全否则抛 | 少给一条＝替 PMC 决定"那条不重要" |
| D6：某原则缺数据时怎么算分 | 返回 `None`，排序时一律靠后 | 折算成 0 会让缺数据的候选冒充最优——本项目记过多次的静默失效形态 |
| D7：距离矩阵内不内置 | **不内置**，由调用方传 | 「就近」按公里/车程/班次算会得出不同路径，本身即口径 |
| D8：计划未给上线仓怎么办 | 抛 `KeyError`，不默认落到任一委外仓 | 默认会静默把料调错地方 |

- 🔴 **PMC 确认门禁**（采购专线 2026-07-06）：调拨清单落 ERP ＋ 外发邮件须 PMC 经理**实名**确认后执行，AI 不自动落库、不自动外发。门禁不得新增旁路参数。
